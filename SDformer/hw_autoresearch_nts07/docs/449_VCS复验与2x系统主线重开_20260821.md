# VCS 复验与 2× 系统主线重开（2026-08-21）

## 决策

`docs/359` 的历史封存数字与 SHA 不修改，但 **Motion-only 不再作为投稿主线**。原因不是
RTL 错误，而是覆盖面错误：新交接包的真实 ep35 profile100 显示 Motion/RQTB attention
只占当前全网络周期 envelope 的 0.5889%，所以 `620868243 -> 620302905 = 1.000911x`。
只继续优化这个 attention 子块不可能形成 2× 系统结果。

新的硬件主线应是：保留 RQTB attention；将 Local5/Q-silent/ident-K 的无损复用思想扩展到
全网络 binary Linear/Conv2d（spiking GeMM）；非二值算子与 ATLIF 走显式旁路；在同一资源、
频率、SRAM/DRAM 与 OP 定义下比较 Fixed、RQTB、Prosperity 和 Phi-like。

当前这仍是架构方向，不是 2× 声明。

## 为什么现有成果看起来弱

弱点是 Amdahl 覆盖，不是 Motion RTL 没有功能收益：

| envelope | 结果 |
|---|---:|
| attention component | 1.182914x |
| fixed attention share | 0.588864% |
| current system | 1.000911x |
| 仅共同增加非 attention 并行度的理论上限 | 1.182914x |
| 2× 系统所需的 proposed non-attention speedup | **2.008217x** |
| 3× 系统所需的 proposed non-attention speedup | **3.027548x** |

真实 operator ledger 有 79 个 Linear/Conv2d；按“输入为严格 0/1 的 spiking GeMM”合同，
57 个结构可映射，覆盖 71.8709% activity-weighted MAC、57.3719% fixed system cycle
envelope。即使这些周期完全免费，系统上限也只有 2.3509×。若保持 RQTB attention，达到
2× 系统需要这 57 个算子的统一引擎达到 **7.6876×**；Local5 的 1.7835× 若被极乐观地
无损推广到全部 57 个算子，也仅对应约 **1.3386× system envelope**，不能写成实测结果。

## Prosperity / Phi 对标结论

Prosperity（HPCA 2025）不是只做一个 attention 微结构。它从 PyTorch 提取多模型逐层
activation，使用 cycle-accurate simulator；核心 SystemVerilog 在商业 28nm 上用 DC，buffer
用 CACTI 7，DRAM 用 DRAMsim3。它在 500MHz/28nm/128 PE 口径下报告 VGG16 的 throughput、
GOP/J、GOP/s/mm2，并在 16 个 model-dataset 点报告 end-to-end speedup/energy。相对 PTB
平均为 7.4×/8.0×，相对 A100 的 spiking-transformer end-to-end speedup 为 1.79×。

Phi（ISCA 2025）同样覆盖 VGG、ResNet、Spikformer、SDT、SpikeBERT、SpikingBERT；用
cycle simulator、SystemVerilog/DC 28nm、CACTI 7、DRAMsim3，并统一规定一 OP 为 binary-one
activation 的一次 accumulation。其 500MHz/28nm 表同时给 area、throughput、GOP/J、
GOP/s/mm2；相对最强 SNN baseline Stellar 报告 3.45× performance 和 4.93× energy，另给
PAFT accuracy、DSE、area/power breakdown 与 activation/weight traffic。

原文：

- Prosperity: <https://arxiv.org/abs/2503.03379>
- Prosperity artifact: <https://github.com/dubcyfor3/Prosperity>
- Phi: <https://arxiv.org/abs/2505.10909>

因此不能把它们的 3–7× 与我们的 1.176× component 直接横比。正确仿照对象是它们的
**实验闭环**：全网络 trace、逐层稀疏映射、统一 simulator、多 ASIC baseline、DC+CACTI+
DRAMsim3、完整 accuracy/performance/energy/area/traffic/DSE，而不是只抄一个倍率。

## 已落地的主线修改

1. full-network ledger 新增 `--profile`，可直接消费接收包且继续锁定四个 profile SHA。
2. DSE 新增 1.2×/1.5×/2×/3× 目标和 proposed-only 非 attention 加速模型。
3. 新增 Prosperity/Phi-like structural adapter：逐 operator 判断 binary spiking-GEMM eligibility，
   禁止导入论文 speedup，未有 ordered trace/cycle/memory 前 fail closed。
4. baseline registry 已从“full operator mapping missing”推进为“structural adapter complete，
   ordered trace/pattern/cycle/memory/PPA missing”。
5. system simulator 单元测试 11/11 PASS；H67 与 Local5 VCS/SVA 回归均 PASS。
