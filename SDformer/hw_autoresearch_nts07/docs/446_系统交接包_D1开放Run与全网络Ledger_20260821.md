## 3. Full-network transaction ledger v0

入口：

```text
system_simulator/scripts/build_h67_ep35_full_network_ledger.py
```

冻结输入为 profile100 的 `operator_runtime.csv`、`activation_records.csv`、
`atlif_activity.csv` 和 `sample_workload.csv`。输出位于：

```text
results/h67_ep35_full_network_ledger_20260821/
```

v0 使用统一 96-lane、activity-weighted MAC 模型；attention slice 使用
sample0 选中窗按 stage 窗数扩展的旧 RTL 校准模型。得到：

| 指标 | v0 模型 |
|---|---:|
| Fixed cycles/frame | 621,349,814 |
| RQTB cycles/frame | 620,661,134 |
| speedup | 1.001110x |
| Fixed attention share | 0.665912% |
| materialize-all activation traffic | 2,779,896,000 bytes/frame |
| unique INT8 weight payload | 46,971,744 bytes |
| ATLIF 16-bit state read+write | 5,844,960,000 bytes/frame |

这是红灯，不是论文结果。它说明之前 30%--50% optimized fraction 没有证据。
同时，统一 96-lane 串行模型也没有反映 patch/FFN/ATLIF 的异构并行、层间
流水、驻留和 DMA overlap，不能据此否决架构。下一版必须完成：

1. 面积公平的 per-category lane allocation；
2. 真实 SRAM residency、bank conflict 和 DMA overlap；
3. CACTI 与 DRAMsim3；
4. Fixed/RQTB/Prosperity/Phi-like 统一 memory/OP 定义；
5. 非 attention operator 的 RTL/DC 校准点。

在这些完成前，状态固定为：

```text

```

## 4. D1/H87 open-run state-file leaf

新增：

```text
rtl_h67/h87_t5_open_run_file.sv
verif_h67/h87_t5_open_run_file_assertions.sv
tb_h67/tb_h87_t5_open_run_file.sv
```

执行对象不是普通 seal-time RLE。输入仍是五个既有 T2 window；每个 spatial
position 只保留当前未闭合 run 的 score、5-bit temporal membership、5-bit
active-K mask 和 generation tag。T5 group 边界位于全局 slot 4/5，禁止跨组
合并。最后一个 T2 window 最多闭合三条 descriptor；接口每拍最多发两条，
第三条进入单项 spill，且保持 raster retirement order。

4-position 定向/混合 trace：

```text
Fixed descriptors = 40
open-run descriptors = 24
equal edges = 16
spill packets = 1
```

Icarus 与 Verilator `--assert` 均 PASS，descriptor score/membership/active mask、
group-last、row-last 和 counter 全部与独立 reference 一致。该结果只证明 leaf
合同与 spill/反压保序，不是 D1 真实 checkpoint population、周期、PPA 或 DATE
新主表。下一门是 D1 ep5 的真实 T5 bit trace miter；GPU 被 D3 训练占用时不抢卡。
