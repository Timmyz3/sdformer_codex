# DATE独立审稿人第五轮：Builder前端后评估

## 1. 审稿设置

本轮由独立subagent按DATE正式审稿口径执行只读评估。审稿人未参与本轮RTL实现，重点阅读：

- `docs/98_H67_GateStack_DATE补强架构签核规格_20260717.md`；
- `docs/111_DATE独立复审与TypedResidency第四轮整改_20260718.md`；
- `docs/112_片上三格式Builder前端与生命周期压力闭环_20260718.md`；
- `results/gatestack_typed_builder_frontend_20260718/report.md`；
- `results/gatestack_typed_builder_policy_20260718/report.md`。

审稿约束明确禁止把Yosys generic cell当作DC PPA、把Builder frontend当作完整serializer，或把单样本首window当作完整workload。

## 2. 总体结论

| 项目 | 独立审稿意见 |
|---|---|
| Overall recommendation | **Weak Reject** |
| 内部成熟度 | **3.3/5** |
| 置信度 | **4/5，高** |
| 相对上一轮 | `3.2/5 -> 3.3/5`，小幅晋级 |
| 是否达到Borderline | **否** |
| 架构创新判断 | 已不是“没有架构创新”，但当前证据只支持中等、增量式组合创新 |
| 工作量判断 | RTL子系统工作量充分，论文实验闭环不足 |

审稿人的核心判断是：

> GateStack已经形成连贯的projection subsystem，并有足够潜力成为DATE架构贡献；但目标PPA、完整片上Builder和代表性真实workload三项仍是直接接收阻塞。

## 3. 审稿人对硬件主张的复述

当前工作准确定位为面向H67 all-binary事件光流网络的`GateStack精确稀疏投影子系统`，不是完整H67 encoder accelerator：

1. 以`{final Q1.7 gate code, K lane}`为精确term合并键，使一次乘积向多个token目的地广播；
2. IPD32W服务常规低/中fanout并支持descriptor residency；
3. FADC24在IPD容量溢出时用list/bitmap救援高fanout head；
4. RAW41为所有异常和容量溢出提供无损回退；
5. typed slot metadata在提交时冻结格式、tag、容量和路由；
6. 三种回放路径共享multicast、product和AccTile后端；
7. 只有IPD允许descriptor residency，tag-qualified release保护跨window生命周期；
8. output-tile-stationary、head-stacked replay用稀疏payload重放换取dense partial sum驻留；
9. 新增Builder前端只完成term元数据累加和容量策略，尚未实现term directory、RAW scratch、三格式serializer和slot commit完整构建链。

## 4. Strengths

1. **架构主线已收敛。** final-gate等价类、三格式表示、typed dispatch、IPD-only residency和共享后端构成连贯数据流，不再是零散RTL模块。
2. **运行时统一格式架构成立。** IPD/FADC/RAW可在同一可综合配置和同一context中交错执行，关闭了早期两个编译配置离线择优的问题。
3. **精确性边界明确。** 不做弱注意力裁剪；容量或metadata异常均回退RAW，保持投影语义。
4. **控制闭环有工程深度。** typed metadata、PLAN/COMMIT、format-qualified residency、tag-qualified release和stale release保护均已实现并验证。
5. **RTL验证工作量较充分。** 四stage真实首窗口、合成mixed context、307个Builder前端head、20030个term和2006次cache压力序列都有双模拟器/SVA证据。
6. **公平基线有所补强。** physically-stripped Direct projection slice和head-major PSUM流量下界已经建立。
7. **证据边界较诚实。** 文档明确区分真实trace、合成mixed用例、结构代理和缺失的目标PPA。

## 5. Weaknesses分级

### 5.1 致命问题

| 问题 | 审稿影响 |
|---|---|
| 无目标`.db`、PVT、SRAM macro、DC/STA、mapped SAIF和mapped-netlist LEC | 无法证明频率、面积、功耗、能量和EDP，DATE硬件主结论缺失 |
| Builder只有metadata accumulator和policy，没有完整三格式serializer和slot commit集成 | 不能声称芯片已经自主生成IPD/FADC/RAW payload |
| 位级真实trace仅`sample0/B0/window0`，profile100没有逐term fanout | 无法证明格式分布、周期和尾延迟代表完整workload |

### 5.2 P0问题

| 问题 | 审稿影响 |
|---|---|
| GateStack projection的候选INT8权重、bias、requant、BN folding和残差scale未完成valid825 | attention/Shiftmax valid825不能替代projection部署闭环 |
| Direct仅有projection slice物理裁剪；head-major只是事务和流量下界 | 公平PPA和完整bit-exact数据流基线不完整 |
| C0/C1 workspace、term directory、bank端口、serializer重叠和真实Builder周期未实现 | 95个generic cell严重低估完整Builder代价 |
| full encoder的attention、ATLIF、skip/residual、权重和外存未闭环 | 现有加速只能标为四窗口projection bundle，不是整网加速 |

### 5.3 P1问题

- 缺功能覆盖率、代码覆盖率、随机reset/abort、多context Builder压力和完整错误矩阵；
- head-major缺descriptor/event buffer和SRAM宏能量；
- 与近期稀疏格式、multicast和adaptive dataflow工作的机制差异仍偏定性。

### 5.4 P2问题

- FADC residency、双workspace重叠、operand isolation和clock gating未做PPA消融；
- DFT、UPF、physical-aware synthesis和布线拥塞尚未评估。

## 6. 架构创新评价

审稿人的明确判断是：

> 方案层面有足够潜力，当前证据层面仍不足。

可以辩护的新意不是IPD、bitmap/list、cache、typed metadata、ping-pong或output-stationary中的任一单点，而是：

> H67 final-gate语义term、低/高fanout异构目的集合、RAW精确回退、typed residency和output-tile-stationary multicast后端的协同数据流。

因此当前不是“没有架构创新”，但只能评为中等、增量式组合创新。是否足够接收，取决于能否证明该组合对H67 workload不可替代，并通过目标PPA/EDP和完整Builder实测建立收益。

## 7. 工作量与验证评价

审稿人认为工程工作量已经达到较完整的研究型RTL子系统，不是玩具设计。运行时三格式、mixed context、生命周期异常和开放LEC体现了实现深度。

验证投入存在明显不均衡：

| 方面 | 评价 |
|---|---|
| 控制、协议、格式切换、生命周期 | 较强 |
| 完整Builder和serializer | 缺失 |
| 真实workload覆盖 | 弱 |
| 部署精度 | 部分完成，GateStack projection未闭环 |
| 目标物理PPA和系统评估 | 缺失 |

总结为：**RTL工作量充分，论文实验闭环不足。**

## 9. 相比上一轮为何只增加0.1分

### 晋级因素

- 格式选择不再完全依赖外部oracle，已有可综合metadata/policy前端；
- fail-safe RAW策略和容量边界进入RTL；
- lifecycle压力从少量定向stale release扩展到2006次shadow-model序列；
- physically-stripped Direct和head-major流量下界增强了基线完整性。

### 未晋级Borderline的原因

- Builder前端不是serializer；
- 新增95个generic cell不能代表完整Builder面积；
- workload仍是单样本首窗口；
- 目标PPA、projection valid825和full encoder仍未关闭。

## 10. 达到Weak Accept的最小交付物

| 交付物 | 可验收门槛 |
|---|---|
| 完整片上Builder | RAW scratch、term directory、IPD/FADC/RAW 64-bit serializer和atomic commit全部接通；逐word对照Python金参考零失配 |
| 扩展真实trace | 至少100个valid frame，覆盖12个attention block和全部window；报告格式分布、fallback和周期p50/p95/p99/worst |
| 部署精度 | 冻结projection BN/bias/requant/residual合同；valid825 AEE相对H67部署基线退化不超过`0.02` |
| 公平目标PPA | Direct、IPD、FADC、Typed、Typed+Residency使用相同库/PVT/SDC/SRAM；WNS≥0、TNS=0、SAIF注释率≥95%、netlist LEC全部通过 |
| 能效 | 相对最佳公平exact基线，GateStack projection EDP至少改善15%；分账logic、memory、clock和leakage |
| 系统闭环 | 给出attention、GateStack、ATLIF、skip和外存的Amdahl/带宽/周期；达不到30 FPS则删除实时claim并报告Pareto |
| 验证闭环 | 功能需求覆盖100%，代码行覆盖≥95%；覆盖mixed格式、容量边界、reset/abort、长反压、stale tag和多context |

## 11. 可以写入论文的贡献

- 提出面向H67 final-gate等价类的精确稀疏投影数据流；
- 实现运行时typed slot，在IPD32W、FADC24和RAW41之间执行格式限定分派；
- IPD用于常规低/中fanout，FADC用于IPD容量溢出的高fanout救援，RAW提供无损回退；
- 三种表示共享term/event、multicast、product和AccTile后端；
- tag-qualified IPD-only residency防止旧release破坏新tag cache line；
- metadata/policy前端在307个测试head、20030个term上通过双模拟器/SVA；
- head-major在当前H67维度下具有显著PSUM流量下界，但必须明确是理论下界；
- 四个被测真实首窗口中统一Typed配置相对既有GateStack周期bundle改善，但必须标明trace范围。

## 12. 绝对不能写的主张

- Builder frontend已经完成三格式payload serializer；
- 芯片已经完成完整自主在线三格式编码；
- 单样本首window代表完整H67 workload；
- Yosys generic cell等同于DC面积或PPA；
- 已达到500 MHz、30 FPS或实现能量/EDP改善；
- `1.418x`是整encoder、每帧或系统吞吐加速；
- head-major能量优劣已经由PPA证明；
- 完整H67 encoder RTL或ASIC已经签核；
- GateStack projection候选INT8已经通过valid825；
- FADC在所有stage和样本上普遍优于IPD；
- list/bitmap、typed metadata、residency或output-stationary是首次提出；
- 95个generic cell代表完整Builder的低面积成本。

## 13. 本轮行动结论

当前不应继续扩充微小控制功能或用更多Yosys结构数字包装成熟度。最短晋级路径是：

1. 完成三格式payload serializer和atomic commit；
2. 扩大逐位真实trace；
3. 完成projection valid825部署合同；
4. 在统一目标库边界下完成公平PPA；
5. 最后补full encoder Amdahl和带宽闭环。

完成第1项可以解决“芯片不能自主编码”的结构性缺口；第2至第4项决定论文能否从Weak Reject进入Weak Accept。
