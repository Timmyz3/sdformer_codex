## 2. P0-1：逐候选资源与生命周期

| 候选 | Acc context | epoch slot | FIFO2 | stripe | 生命周期 |
|---|---:|---:|---:|---:|---|
| C0 Direct-serial | 1 | 0 | 1 | 1 | prepare -> H heads -> drain -> free |
| C1 reuse-only-S2 | 2 | 1x1RW | 1 | 2 | fill/seal -> 两 tile 顺序消费 -> drain |
| C2 overlap-only | 1 | 2x1RW | 1 | 1 | slot i 在 task i-2 退休后才复用 |
| C3 EREP-S2 | 2 | 2x1RW | 1 | 2 | 双 slot 重叠 + 双 Acc context + 串行公共 drain |

公共单元为一个 Local5 relation transpose/frontier workspace、一个 source-major
FIFO2 builder、一条 Direct 合法 1RW 五 bank execution lane 和一个公共向量
drain/serializer。

数据状态增量：

| 候选 | 相对 C0 新增 bit |
|---|---:|
| C1 | 511,200 |
| C2 | 100,800 |
| C3 | 561,600 (`68.5547 KiB`) |

tag、valid、FIFO、控制、clock tree 和布线仍必须在 PPA 中计入。

## 3. P0-2：从全局序号改为逻辑事务身份

v2 不再要求四候选的全局 weight 请求顺序一致。公平性改为：

```text
delay = uint64_be(
  SHA256("local5_erep_identity_service_v2|20260810|" + kind + identity)[0:8]
) mod 4
```

identity 使用 sorted-key compact JSON，并按 transaction kind 显式包含：

- relation：`sample/stage/block/window/input_head/source_id`；
- epoch read：再加 `stripe/output_tile`；
- weight：`input_head/output_tile/lane/out`；
- final：`output_tile/source_id/out`。

所有候选共同的逻辑事务必须产生逐字节一致的 `{identity,delay}` map。
候选依赖的全局 transaction index 被禁止。

## 4. P0-3：显式生命周期离散事件模型

v2 参考器的输入不再是每 head 单个 `E*stripe_width`，而是：

```text
HeadWork {
  epoch_records,
  epoch_fill_cycles,
  direct_cycles_by_tile[O],
  execute_cycles_by_tile[O]
}
WindowWork {
  heads[H],
  prepare_cycles_by_tile[O],
  drain_cycles_by_tile[O]
}
```

模型输出半开区间 `[start,end)` ledger，显式记录：

- epoch slot 的 fill/atomic-seal/hold/consume；
- Direct 1RW execution lane；
- 每个 Acc context 的 prepare/accumulate/drain；
- epoch record 1RW read/write 事务数；
- S2 尾部宽度 1 的重建和 drain。

同一 slot/context/lane 的任意时间区间都不得重叠。当前 `5/5 PASS`只
证明离散事件和资源互斥算术，不是 EREP RTL。

G0 所用的周期不允许来自旧 Python stall predictor，必须来自仪器化
RTL phase trace：

1. Direct 每 `{window,head,tile}` 周期；
2. relation workspace 到 active-record slot write 与 atomic seal；
3. sealed slot 经 FIFO2、Direct 1RW backend 到 per-head flush；
4. context prepare 与公共向量 drain；
5. 每笔 relation/slot/FIFO/five-bank/drain command ledger。

参考器本身不伪造 record-level 握手时间；它消费并审计后续
`[​rtl calibration]` 产生的 phase/command trace。因此 G0 结果必须标为
`[rtl calibration]+[模型]`，不是 EREP `[rtl]`。

## 5. P0-4：唯一统计量

主统计量冻结为：

```text
R_x = sum_j(w_j * C0_j) / sum_j(w_j * Cx_j)
```

`j` 是 1200 个 sampled joint window，`w_j=stage_windows`，每个 joint window 只加
一次权。禁止使用 per-window speedup 的加权平均替代比率的汇总。

cluster bootstrap 冻结为：

- cluster ID：真实 cohort `sequence_key`，预期 18 个 cluster；
- paired nonparametric cluster bootstrap；
- 20,000 次，seed `20260810`；
- 主 CI：双侧 percentile 95%；
- stage p95：四个单侧检验，Bonferroni `alpha=0.0125`，分别使用
  98.75% upper bound；
- p95 不回退：`upper_bound(p95_C3-p95_C0) <= 0`。

## 6. 新增强架构基线

v2 新增两个不许省略的 exact-reuse 基线：

| 基线 | 资源 | 用途 |
|---|---:|---|
| C4 capacity-matched relation memo | 561,600 bit 数据状态 | 同 C3 增量 bit 预算的 cache-only 上界 |
| C5 full relation memo | stage3 最坏 1,209,600 bit | 更大面积 exact-reuse 上界 |

C4 在 G0 同时报告 offline optimal 0/1 knapsack 上界与后续可实现策略，
不把 oracle 写成硬件结果。C5 不是面积公平基线。

stripe `{1,2,3,4,6,8,12,24}` 只作 sensitivity；正式主候选仍固定 S2。
看到结果后不允许用其他 stripe 替换 S2，除非更换新 hold-out cohort。

## 7. 分阶段门槛

### G0：profile + RTL calibration + model

1. C0/C3 主比率 `>=1.25x`，即周期下降至少 20%；
2. 主比率 cluster-bootstrap 95% 下界 `>1.0`；
3. 四 stage 的 p95 Bonferroni upper bound 全部不回退；
4. C3 相对 C1/C2 更快者 `>=1.05x`，且 cluster CI 下界 `>1.0`；
5. C3 相对 C4 cache-only 同 bit 上界 `>=1.05x`，且 CI 下界 `>1.0`。

G0 失败则停止 Local5 新架构 RTL，回到 Motion 多样本证据。

### G1：RTL

G0 通过后才实现 C0--C4 最小同边界 RTL，必须 Acc32 零失配，并覆盖
S2/remainder、empty/dense、slot/context/drain 长反压、epoch invalidation 和跨
block/window 切换。

### G2：物理

主指标预选为 **memory-inclusive EDP**，不允许事后在 EDP 和面积归一
吞吐中择优：

- C3 相对 C0 EDP 下降 `>=20%`；
- C3 相对 C4 EDP 改善 `>=5%`；
- 同 process/voltage/SDC/SRAM macro/activity/floorplan policy；
- OpenROAD 只是 `[开放物理代理]`；
- 最终 ASIC 主张需 DC/STA/SAIF/PTPX。
