## 2. 新发现的仲裁互锁

上一版中：

```text
source_ready      依赖 !group_close_valid
group_close_ready 依赖 !source_valid
```

两个独立 valid 同时为 1 时，两个 ready 同时为 0，形成新死锁。

## 3. 修复后的确定性仲裁

新合同为：

1. `source_valid` 与 `group_close_valid` 同时出现时，source 优先。
2. 若 source 不是 final，先接收 source；close 保持 valid，并在下一可用周期提交。
3. 若 source 是 final，且 close tag 与 source group tag 相同，则 source 与 close 可同拍完成。
4. 容量满时仍先 drain-and-resume；close 不得越过尚未接受的 source。

新增定向 group 同时拉高 source 与 close，验证 source 先握手、close 后握手、group 正常完成且 accumulator 零失配。

当前总回归计数：

```text
source=12
typed term=9
partial drain=2
fallback=2
group=4
stalled command cycles=3
accumulator mismatch=0
```

## 4. 跨 drain duplicate 的证据边界

ET3 只能检查当前 chunk 内的重复 `{key,destination}`。partial drain 后目录被释放，因此不保存 whole-group seen set。

这不再被写成 ET3 自身的 whole-group validation。正式输入合同是：

> 上游 Motion NMF 或 Local5 MFEP 必须保证一个 group 内每个 `{gate,lane,multiplicity,destination}` 至多出现一次；ET3 保证每个已接受 item exactly-once 发射，不负责重新证明上游唯一性。

真实 ordered trace 导出必须同时统计该唯一性合同；任何 duplicate 都使 trace/软件前端不合格。

## 5. 新增 SVA

新增：

- `verif_et3/et3_native_slice_assertions.sv`

Verilator `--assert` 现在实际加载九条 property，而不再只是空开关：

1. source stalled 时 valid 与 payload 稳定。
2. command stalled 时 valid 与 payload 稳定。
3. Motion source 的 multiplicity 必须为 1。
4. Motion command 的 multiplicity 必须为 1。
5. `head_last` 必须同时是 `term_last`。
6. `group_done` 时 epoch 必须 inactive。
7. inactive epoch 不得接收 source/close。
8. 已发射 destination 数不得超过已接受 source 数。
9. matching final source 与 close 同时到达时必须可共同 retire。

SVA、Icarus、Verilator、Yosys 与 Python evidence tests 全部通过。当前 Verilator 功能回归无 warning。

## 6. 创新性结论不变

这轮工作关闭了生存性和验证缺口，但仍属于正确性整改：

- 不构成新的 DATE 贡献。
- ET3 当前仍是 typed aggregation/execution prototype。
- 未连接 normalization-to-term，不能声称完成避免 gated-K 物化的端到端架构。
- 无 ordered post-G0/full-resolution 在线收益与目标工艺 PPA。

主线仍为 Motion；Local5 继续 shadow。

## 7. 下一阶段

GPU 训练占用期间只做同一决定性切片的前置工作：

1. 冻结 ordered trace schema。
2. 实现普通 per-destination native-m queue CPU/RTL 基线。
3. 实现 native-m queue 与 ET3 的同边界 CPU replay。
4. schema 必须含 group open/close、empty group、原始 item 顺序、tag、gate/lane/m/destination、金参考 hash 与上游唯一性审计。
5. synthetic trace 只用于协议回归，不进入性能表。
