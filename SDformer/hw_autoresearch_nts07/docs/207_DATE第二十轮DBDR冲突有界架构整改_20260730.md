# DATE 第二十轮 DBDR 冲突有界架构整改

## 1. 为什么必须再改一次架构

第十九轮 XBF-QFSA 使用：

```text
bank = lane[1:0] XOR direction[1:0]
```

把全局 `128->4` tagged compactor 缩成四个局部选择器，但原 T8 路由只看
每个方向的总 delta 数：

```text
delta_count(direction) > 8 -> direct32
否则                         -> XOR-bank residual
```

DATE 与 ASIC 两位独立审稿人共同给出一个合法反例：

- N 方向取 `lane_low2=0` 的 8 项；
- S 方向取 `lane_low2=1` 的 8 项；
- E 方向取 `lane_low2=2` 的 8 项；
- W 方向取 `lane_low2=3` 的 8 项。

由于 `bank=lane_low2 XOR direction`，32 项全部落到 bank0。每方向总数都等于
8，T8 不会触发 direct：

- 4xW1 最多 8 个 residual service 拍；
- XBF-T8 需要 32 个 residual wave；
- 当前 selector metadata pipeline 还需要 1 个 drain 拍；
- 实际 RTL 计数为 33 拍。

这证明“XOR 映射通常能分散”不是架构保证。若只等真实 workload 证明反例少见，
架构仍缺少可解释的尾延迟边界。

## 2. DBDR：方向密度与 bank 压力双上界

本轮新增：

**DBDR（Dual-Bound Density Routing，双上界密度路由）**

对每个方向 `d` 同时计算：

```text
direction_total[d] = sum_b bank_count[d][b]
direction_peak[d]  = max_b bank_count[d][b]
```

T8Bk 的 exact 路由为：

```text
direct[d] =
    direction_total[d] > 8
    OR direction_peak[d] > k
```

其余方向进入 XBF residual。两条路径计算完全相同的 raw score，最终进入同一个
13-bit accumulator，并只进行一次 RNE 和同一个 Shiftmax，因此 DBDR 不删事件、
不近似、不改变 score/gate。

### 2.1 解析边界

若一个方向保留在 residual 路径，则它对任一 bank 的贡献不超过 `k`。一共四个
方向，所以：

```text
residual_waves <= 4k
pipeline_service <= 4k + 1
direct_service <= 4
total_service <= max(4, 4k + 1)
```

因此：

| 配置 | residual+drain 解析上界 | 用途 |
|---|---:|---|
| T8B1 | 5 | 强尾延迟保护，可能增加 direct 活动 |
| T8B2 | 9 | 当前 RTL 默认候选 |
| T8B3 | 13 | 更偏向 residual pooling |
| 原 T8 | 33 | 无 bank-pressure 保护 |

这些是当前单 destination FSM 的 service 上界，不包括 ROUTE/RNE/OUT 与下游
反压，也不是端到端窗口延迟。

### 2.2 本土化新意

DBDR 的启发边界为：

- Bishop：按 workload density 分流；
- 复旦 ISSCC 2023 butterfly zero skipper：用规则交换网络分散有效项；
- FireFly 类设计：每拍多事件抽取。

本项目的实质修改不是换名字：

1. 路由对象是 Local5 固定 incidence 的 exact XOR residual，不是剪枝权重；
2. direction tag 直接参与 bank 映射；
3. stratifier 同时观察算术密度和目标 bank 压力；
4. direct/residual 只改变执行位置，不改变网络语义；
5. 给出参数化最坏 service 上界，而非只依赖平均稀疏度；
6. 与 FCSR 使用同一方向、坐标和边界微程序，归入 QFIT 双向关联数据流。

单独的阈值比较器、XOR hash 和四个 priority selector 均不是创新。可以争取的
架构主张是：

> 面向固定关联图的冲突有界 exact 双路径 score fabric：将方向语义编译进
> bank 置换，并以方向密度和 bank 压力双上界调度 direct/residual 执行。

## 3. RTL 整改

### 3.1 参数

`rtl_qfit/qfit_local5_score_leaf.sv` 新增：

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `USE_BANK_PRESSURE_ROUTE` | 0/1 | 是否启用第二上界 |
| `BANK_PRESSURE_THRESHOLD` | 2 | 单方向单 bank 压力上界 |

原有 T8 仍保留为消融，不覆盖或删除负结果。

### 3.2 修复 pipeline route cost

第十九轮 16-mask 路由目标为：

```text
max(direct_cycles, residual_cycles)
```

当 `PIPE_COMPACTOR=1` 且 residual 非空时，真实执行还需一个提交拍。现已修为：

```text
residual_effective = residual_cycles + 1
cost = max(direct_cycles, residual_effective)
```

这只修正 mask 选择，不改变整数结果。

### 3.3 对抗验证

testbench 新增第五个并行 DUT：XBF-DBDR-T8B2，并加入 32 项同 bank 对抗向量。

RTL 结果：

| 变体 | direct mask | service cycles | score/gate |
|---|---:|---:|---|
| XBF-T8 | `0x0` | 33 | 与 direct golden 一致 |
| XBF-DBDR-T8B2 | `0xf` | 4 | 与 direct golden 一致 |

验证范围现为：

- 300 个随机向量；
- 16 个 route-mask 定向向量；
- 1 个均衡跨方向 pooling 向量；
- 1 个 32 项同 bank 对抗向量；
- 五个 DUT 的逐 valid score 与全部 Shiftmax gate；
- 随机输出反压稳定性；
- W1、global-QFSA-pipe、XBF-T8、XBF-DBDR 四个参数组合独立 Verilator lint；
- 69 项相关 Python CPU 回归通过。

## 5. post-G0 profile 合同补齐

Local5 fullres follower 将额外输出：

- T8 的逐 destination 四 bank load；
- `max(bank)-min(bank)` imbalance；
- T8B1/T8B2/T8B3 的 score cycles；
- direct mask、direct cycles、residual waves；
- 4xW1、global QFSA、XBF-T8 的对应 ordered cycles。

选择规则：

1. B1/B2/B3 先按四 stage 加权 mean、p95、p99 选点；
2. 若 DBDR 只改善人工反例、不改善真实 p99，降为鲁棒性消融；
3. 若 XBF-DBDR 相对 4xW1 周期改善不足 `8%`，淘汰；
4. `8%~12%` 只作消融；
5. 周期至少改善 `12%` 后，才支付 DC/STA/SAIF 成本；
6. 最终仍要求 score leaf EDP 至少改善 `15%`。

## 7. 当前 DATE 主张冻结

当前最多保留两项架构候选：

1. **QFIT 行侧：固定关联图编译的冲突有界 exact score fabric**
   （anchor/residual、XOR-bank、DBDR）。
2. **QFIT 列侧：固定最后消费者的在线关系转置**
   （FCSR，对 Dynamic Frontier 和 Nonblocking Stripe）。

QFIT 是把两侧统一起来的架构名称，不作为第三项重复贡献。SCS-Shiftmax、term、
DCTF、TTB、PPDI、双 context 和 FIFO 均降为内部算子、数据表示或消融机制。

当前还不能宣称达到 DATE accept：

- DBDR 只有对抗收益和 generic 面积代价；
- Local5 fullres exact 与 post-G0 尚未结束；
- FCSR 同合同 RTL 尚未完成；
- 无目标工艺 PPA；
- 无联合 tile 端到端 EDP。

下一步只做会改变评分的工作：真实 trace 选择 B1/B2/B3，然后实现 FCSR 与强
基线的同合同关系转置 RTL，最后接成最小 QFIT tile。

## 8. 第二十轮复审后周期口径修正

DATE 审稿人指出，RTL 的 16-mask cost 已加入 residual pipeline drain，但软件
profile 的 `xorbank_stencil_route()` 仍返回未流水的 `max(D,R)`。现已增加显式
`pipeline_drain` 参数，并在所有部署 profile 调用中冻结为：

```text
R_effective = R + (R > 0 ? 1 : 0)
service = max(D, R_effective)
score cycles = anchor + service
```

新增混合定向测试覆盖 `D=1、R=1`：旧口径为 1，修正后为 2；32 项 hot-bank
的软件 oracle 同样得到 33，与 RTL service counter 一致。基础数学 helper 仍可
显式使用 `pipeline_drain=False`，避免把物理流水成本混入无流水解析比较。
