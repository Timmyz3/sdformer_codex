# 第八轮 DATE 独立评审：Local5 DS-GASR 五 Bank 在线架构

## 1. 评审范围与证据纪律

本评审只使用当前机器可审计的 RTL、脚本、日志和报告，不采用任何外部机器或 Claude 结果。重点证据包括：

- `docs/243_Local5_QGASR2C五Bank在线RTL与第八轮送审_20260804.md`；
- `results/local5_gasr2c_fivebank_postg0_rtl_20260804/` 中的 blind-geometry 日志与报告；
- `results/local5_qgasr2c_fivebank_postg0_rtl_20260804/` 中的 descriptor-synchronized 日志与报告；
- `results/local5_descriptor_geometry_qualification_20260804/report.json`；
- 五 bank 在线顶层、backend、color map、FIFO2 builder、GASR bank、SVA和一键脚本。

评估边界是 Local5 full-resolution `15x15x2=T450` 的 post-G0 稀疏投影子系统，不是完整 encoder、完整光流网络或芯片实现。

证据分级如下：

- `[rtl]`：由当前本机 RTL 日志直接支持；
- `[模型]`：由日志上的离线分析或选择模型支持；
- `[未证]`：尚无同约束物理、功耗或端到端证据。

## 2. 总体推荐

**推荐等级：Weak Reject，2.5/5。**

工程晋级结论：五 bank 在线数据流和source-resident accumulator机制已经达到可信的 RTL 原型水平，但当前不能作为独立 DATE 架构主张完成接收闭环。

本轮最重要的更正是：原“mask-qualified geometry 删除无效 bank prepare”的因果解释不成立。因此建议停止使用 QGASR 命名，改称：

> **DS-GASR：Descriptor-Synchronized Geometry-Aware Source Residency**，即“描述符同步的几何感知源驻留”。

DS-GASR 的候选贡献不是 mask pruning，而是把 GASR 的 prepare/activate 同步点从 relation-read issue 路径移到完整 descriptor 的原子提交边界，使 relation-read 请求与 backend prepare 解耦。

## 3. 关键证据更正

新增统计按 RTL 邻接映射重建了 profile100 的全部 active source：

| 指标 | 数值 | 证据等级 |
|---|---:|---|
| active sources | 9,427 | `[模型/向量重建]`，与 RTL descriptor 数一致 |
| boundary geometry roles | 44,661 | `[模型/向量重建]` |
| descriptor-valid roles | 44,661 | `[模型/向量重建]` |
| descriptor mask 删除的 roles | 0 | `[模型/向量重建]` |
| mask 不同的 sources | 0 | `[模型/向量重建]` |

因此：

1. `docs/243` 中“blind geometry 对所有边界内邻居 prepare，而 mask-qualified 只对真实active role prepare”的解释失效；
2. `report.md` 中“mask-qualified geometry 避免无效 bank 预取”的因果表述失效；
3. `mask_qualified` 仍可作为当前日志的工程 variant 名，但不能作为论文创新名称；
4. blind 与新版本均为60,510次SRAM事务，也与“没有删除任何role”的更正一致；
5. 当前周期变化不能归因于mask pruning。

该统计是由真实输入向量按 RTL 映射重建，能够否定mask-pruning解释；它本身不是周期、面积或功耗证据。

## 4. 数字审计

### 4.1 当前 DS-GASR 与 direct

对原始100组逐组日志重新求和，可得到：

| 指标 | direct-1RW | DS-GASR | 结论 |
|---|---:|---:|---|
| 周期 | 121,501 | 119,348 | `[rtl]` 1.018x，周期缩短1.77% |
| term stall | 13,055 | 10,965 | `[rtl]` 下降16.01% |
| SRAM reads | 152,894 | 23,662 | `[rtl]` |
| SRAM writes | 166,080 | 36,848 | `[rtl]` |
| SRAM总事务 | 318,974 | 60,510 | `[rtl]` 下降81.03% |
| descriptors | 9,427 | 9,427 | `[rtl]` 相同 |
| terms | 53,085 | 53,085 | `[rtl]` 相同 |
| updates | 166,080 | 166,080 | `[rtl]` 相同 |

报告数字均能由日志支持，没有发现汇总算术错误。

但固定DS-GASR的逐组表现为 `17/45/38` 个win/equal/loss，p50为1.000x，最差为0.756x。因此1.018x只能描述该profile100上的加权聚合周期结果，不能写成每窗口加速、端到端网络加速或稳定吞吐提升。

### 4.2 blind issue-side GASR 负结果

blind日志支持：

- direct：121,501周期；
- issue-side GASR：122,360周期，即0.993x；
- SRAM事务仍为60,510；
- Acc32为100/100组PASS。

当前DS-GASR相对blind版本为 `122360/119348=1.025x`。按stage汇总，DS版本相对blind版本四个stage均改善，约为1.020x、1.009x、1.027x和1.032x。

这些现象与“把prepare从relation-read issue路径移出，改到descriptor提交点”一致，但严格因果仍未完全锁定：blind结果目录没有冻结对应源码哈希，当前一键脚本也没有同一源码下的issue-side/descriptor-side编译开关。因此blind日志可作为负结果和设计动机，暂不能作为单变量消融的最终证据。

### 4.3 留出选择模型

`terms/active >= 4.7241379` 的选择规则得到：

- 前50组训练：1.047x；
- 后50组留出：1.052x；
- 留出oracle：1.058x；
- 全100组模型：1.050x。

这些数字由汇总脚本正确计算，但只能标为 `[模型]`。还需注意：前50组恰好是stage 0和stage 1，后50组恰好是stage 2和stage 3。这是无数值泄漏的跨stage测试，不是各stage内随机、独立同分布的样本留出。

此外，`terms/active` 在当前执行流中并非窗口开始时天然可得。若不增加预扫描、全窗口缓冲或预测器，不能直接用它选择同一窗口的运行模式。因此1.052x不能称为runtime结果。

## 5. DS-GASR 的架构新颖性判断

### 5.1 可以成立的架构部分

以下组合达到“领域专用架构候选”而不是单纯代码优化的程度：

1. **五着色无冲突映射**：`bank(x,y)=(x+2y) mod 5` 使Local5五个空间角色在每个source上落入不同bank；
2. **source-major partial-sum residency**：同一source的term连续，使每term单端口RMW可改为source切换级write-back/prefetch；
3. **descriptor-synchronized atomic fork**：完整descriptor在builder FIFO与五bank backend同时ready时原子提交，避免backend prepare阻塞relation-read issue；
4. **双上下文重叠**：当前source在寄存器槽累加，下一source通过同一1RW backing memory准备。

这套组合改变了数据的驻留位置、bank组织、跨级同步点和存储访问频率，具备微架构实质。

### 5.2 不能单独成立的创新

以下机制单独看仍是常规工程：

- 两项FIFO、ping-pong和dirty write-back；
- ready/valid原子fork；
- 把ready路径从一个流水级移动到另一个流水级；
- descriptor mask过滤；
- 单纯五bank划分。

特别是“descriptor同步”本身属于流水解耦和反压路径重构。只有与Local5五着色source residency绑定，并由同版本单变量消融证明其消除了relation-read/prepare耦合后，才适合作为DS-GASR整体机制的一部分，而不能单列为DATE核心贡献。

### 5.3 最终新颖性结论

**DS-GASR是中等新颖性的领域专用数据流/存储微架构，不是高冲击力的新通用架构原则。**

mask-pruning解释被推翻后，新颖性应从原先可能的3.0/5下调到2.5/5。五着色source residency仍有可辩护内容，但descriptor同步更接近本土化流水优化。要进入DATE主贡献，需要物理收益和严格因果消融共同支撑。

## 6. 实现与验证审查

### 6.1 已完成

- `[rtl]` word-skipper、同步relation frontier、FIFO2 builder、五bank backend已在线集成；
- `[rtl]` direct与DS-GASR均完成100组T450回放和逐元素Acc32零失配；
- `[rtl]` 随机输入/读回空泡与SVA回归PASS；
- `[rtl]` descriptor阻塞稳定、builder/backend原子提交、source context匹配和close排空边界有断言；
- `[rtl]` memory-preserving Yosys `check` 对direct和DS-GASR均报告0 problems。

### 6.2 限制与口径问题

1. testbench使用`OUT_DIM=2`和合成权重，不是部署级`OUT_DIM=32`真实权重。周期控制趋势可参考，但寄存器面积、宽加法器时序、SRAM宽度和活动功耗不能外推；
2. accumulator memory仍是固定一周期、无请求反压的逻辑1RW合同，不是已绑定的真实SRAM宏；
3. 随机测试只加入上游输入和结果读回空泡，没有覆盖可变SRAM延迟；
4. Verilator日志无error但有31类/处warning，lint应写成“无error”，不能写成warning-clean；
5. 结果目录中的memory-preserving Yosys检查可以证明结构可读性，但不是DC、STA或面积签核；
6. 同目录另有非一键流程生成的展开Yosys日志，出现大量无驱动问题。它们不属于当前一键签核入口，必须从论文证据清单排除并避免与memory-preserving结果混用；
7. blind负结果缺少对应源码哈希和当前版本复现开关，实验追踪性弱于DS结果。

## 7. 公平性判断

周期A/B在逻辑层面基本公平：

- 两者使用相同word-skipper、relation frontier、FIFO2 builder、权重、输入向量和结果检查；
- 两者均为五个相同深度、相同位宽、相同单端口1RW逻辑合同的bank；
- 周期边界均为`projection_start`到五bank flush完成；
- SRAM事务均不含结果读回；
- descriptor、term和update工作量完全相同。

但它还不是PPA公平：DS-GASR增加双槽payload、tag、dirty位和控制逻辑。Yosys memory-preserving统计中的2,539与4,135个抽象cell、21与41个`$mem_v2`只能提示结构成本风险，不能转换成面积、功耗或EDP。

## 9. 三个数字分别能宣称什么

### 固定1.018x

允许宣称：

> `[rtl]` 在相同逻辑1RW合同和相同在线五bank前端下，DS-GASR在该T450 profile100上将投影子系统聚合周期缩短1.77%。

禁止宣称：稳定逐窗口加速、完整网络FPS提升、频率提升或芯片吞吐提升。

### 81.03% SRAM事务下降

允许宣称：

> `[rtl]` 执行期发往逻辑backing SRAM的read/write命令数下降81.03%。

禁止宣称：SRAM功耗下降81.03%、总功耗下降81.03%、能量或EDP下降81.03%。驻留寄存器、宽加法器、tag/control、时钟树和真实宏每访问能量均未计入。

### 留出模型1.052x

允许宣称：

> `[模型]` 用stage 0/1选择阈值后，在stage 2/3留出组上，离线window级选择模型相对direct估算为1.052x，oracle为1.058x。

禁止宣称：runtime RTL加速、无开销在线选择、独立数据集泛化或完整系统加速。

## 10. Runtime双模式决策

**当前BLOCK runtime双模式作为下一项实现。**

原因如下：

1. 选择特征`terms/active`尚不能在当前窗口执行前无额外扫描获得；
2. 留出oracle仅1.058x，runtime逻辑、模式切换和共享SRAM仲裁很容易吃掉剩余收益；
3. 固定DS-GASR的核心价值更可能是能量而不是周期，但目前没有物理或活动功耗证据；
4. 新增mask统计已经推翻了一次错误因果解释，必须先锁定descriptor同步的单变量因果。

这不是永久否定runtime。只有DS同步点消融成立，且后续PPA显示固定DS-GASR具有净能效收益但尾延迟退化不可接受时，runtime模式才值得恢复。

## 11. 下一轮唯一最高优先级与晋级门槛

### 唯一动作

在**同一份当前RTL**中加入仅改变prepare发射同步点的编译期消融开关，完成：

> issue-side prepare GASR vs descriptor-synchronized DS-GASR 的单变量profile100 A/B。

两边必须保持完全相同的geometry/descriptor role集合、FIFO深度、五bank GASR、SRAM合同、权重、向量、SVA和周期边界，并记录源码哈希。不得同时修改builder、bank控制或其他ready路径。

### 明确晋级门槛

只有同时满足以下条件，DS同步才允许写入DATE贡献并进入macro-aware PPA：

1. 两模式Acc32、descriptor、term、update全部bit-exact且工作量相同；
2. SRAM事务完全相同，证明收益不是来自访问集合变化；
3. DS-GASR相对issue-side GASR聚合周期改善不少于2%；
4. 四个stage均不退化；
5. 随机空泡与SVA均PASS；
6. 一键脚本、工具版本、RTL和向量哈希全部落盘。

若不能通过，应删除“descriptor-synchronized架构贡献”，只保留五着色source residency作为存储活动优化候选；若通过，下一阶段再做部署`OUT_DIM=32`、同SRAM宏、同SDC、同活动向量下的OpenROAD物理代理和后续DC/STA/SAIF。OpenROAD只能标作物理代理，DC/PrimeTime/PrimePower结果仍需后续服务器补齐。

## 12. 最终审稿意见

本轮完成了从离线单bank到在线五bank的实质性进展，且blind负结果体现了较好的研究纪律。但新统计证明mask qualification没有减少任何role，原QGASR故事必须撤回。

DS-GASR仍保留中等架构价值：它把Local5五着色source residency与descriptor边界的原子调度结合，解决了issue-side prepare对relation-read路径的耦合。不过当前证据只能说明现象一致，尚缺同版本单变量消融；1.018x周期也不足以掩盖没有PPA/EDP的缺口。

因此本轮结论为：**允许保留并验证DS-GASR，暂不允许实现runtime双模式，不允许按DATE可接收状态收口。**
