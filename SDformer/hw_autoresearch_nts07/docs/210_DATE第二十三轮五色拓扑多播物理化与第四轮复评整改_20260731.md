# DATE 第二十三轮：五色拓扑多播物理化与第四轮复评整改

> 本文件是同步 1R1W 端口合同与 bank/replay Pareto 补齐前的阶段记录。
> 最新裁决见 `docs/211_DATE第二十四轮源商化执行架构与第五轮复评整改_20260731.md`。

## 1. 本轮裁决

Local5 硬件线已从“关系转置加行为级投影”推进为一条可验证的完整架构切片：

```text
XBF-DBDR exact score fabric
  -> FCSR-RX bounded-lifetime relation transpose
  -> source gate-equivalence quotient
  -> K-bitmap next-event iterator
  -> OUT_DIM-wide shared product vector
  -> TCFM-5 topology-colored multicast
  -> five packed synchronous RMW Acc banks
```

本轮最重要的变化不是增加模块数，而是关闭了此前无法进入物理实现的三个
合同：

1. 五个 Acc bank 不再是多端口三维行为数组；
2. `gate×W` 不再写在 bank 循环内，而是 bank 外计算一次后广播；
3. close 不再是无握手脉冲，而是 `close_ready/close_fire -> drain -> done`。

当前裁决：

- 架构创新：Local5 继续作为优先主候选；
- RTL：可进入同约束基线和 SRAM macro 映射前的复评；
- DATE：仍不能宣布可投，真实 Local5 trace、强基线 RTL 和目标工艺 PPA
  尚未完成。

### 2.1 DATE 架构审稿

| 指标 | 分数 |
|---|---:|

| 架构完整性 | 3.6/5 |

推荐为 **Weak Reject**。审稿人认可的最强贡献不是五色公式本身，而是：

> FCSR-RX 把 destination-major relation 转为 source descriptor，source
> 内按 gate 等价类共享 `gate×W` product，再由拓扑导出的五色 banking
> 无冲突多播到最多五个 destination。

审稿人明确指出：

- 模 5 着色和 K5 下界单独看属于可预期的 stencil graph coloring；
- 只有与在线关系转置、source quotient、共享 product 和物理 Acc
  数据流绑定，才可能形成 DATE 贡献；
- 定向向量 `863 vs 960` 不能替代部署 trace 和公平 RTL/PPA。

### 2.2 ASIC/RTL 审稿

旧版评分：

| 指标 | 分数 |
|---|---:|

## 3. P0 整改

### 3.1 五个 packed Acc bank

新增：

- `rtl_qfit/qfit_tcfm5_acc_bank.sv`

每个 bank 的逻辑 word 为：

```text
OUT_DIM × ACC_W = 4 × 32 = 128 bit
```

一个 term 对同一颜色最多命中一个 destination，因此每 bank 每拍最多一个
128-bit RMW。展平后的 TCFM-5 开放结构现在包含：

| memory | 数量 |
|---|---:|
| weight memory | 1 |
| packed Acc memory | 5 |
| 合计 `$mem_v2` | 6 |

这仍不是目标 SRAM macro 证明，但已经从“一个多端口行为数组”变成五个
显式 bank 实例。

### 3.2 同步 RMW 与 RAW forwarding

每个 Acc bank 使用：

```text
cycle n   : 接收 update address/delta，读取 base
cycle n+1 : packed vector add + writeback
```

连续 term 命中同一 `(bank,address)` 时：

```text
read base = pending write value
```

而不是再次读取旧 SRAM 值。`ST_DRAIN` 等待五个 bank 的 pending update
全部写回后才进入 `ST_DONE`。

定向测试刻意让同一 source 的连续 term 重复更新相同 destination，最终
Acc 仍逐项 exact。新增 SVA 检查：

- clear/update/read 相序互斥；
- 地址不越界；
- read 一拍响应；
- 连续同址更新采用 pending-write forwarding。

### 3.3 product 只计算一次

TCFM-5 在 bank 外形成：

```text
product_vector[out] = gate × W[lane,out]
```

Yosys 结构中动态 `$mul` 数量为 `OUT_DIM=4`，而不是
`5 banks × OUT_DIM=20`。随后同一个 128-bit product vector 广播到五个
bank。

地址生成的变量乘法也已改为编译期展开 LUT，TCFM 顶层不再把地址乘法与
数值乘法混在一起。

### 3.4 close 握手

新增：

```text
projection_close_ready
window_close_ready
window_close_fire
```

合法关闭：

```text
upstream stream idle
  -> close_fire
  -> ST_DRAIN
  -> five banks idle
  -> ST_DONE
```

提前 close 不再静默截断，而是置 sticky `protocol_error`。定向 TB 先注入
一次非法 close，确认报错，再由新 transaction 的 `projection_start`
清除错误并完成正常运行。

### 3.5 plane 与 term 身份合同

- `plane_start_ready` 只对 `plane_id < TIME_PLANES` 为真；
- relation 只接收真实 `plane_start_fire`；
- 新增 SVA：

```text
source_id
= plane × HEIGHT × WIDTH
 + y × WIDTH
 + x
```

## 4. TCFM-5 最小 bank 证明

对任一内点 source，其五个 destination 为：

```text
self, north, south, west, east
```

若一个 source gate-equivalence term 需要在单拍完成所有选中写入，则这
五个 destination 在同时写冲突图中形成五节点团 K5。因此，在“每 bank
单写、无 replay、无复制归约”的合同下，至少需要五个 bank。

着色：

```text
bank(x,y) = (x + 2y) mod 5
```

使五个角色的颜色分别为：

```text
c, c-2, c+2, c-1, c+1 mod 5
```

恰好覆盖五个不同颜色，因此达到该端口合同的 5-bank 下界。

穷举结果：

- 部署窗口：`T=2×15×15`，450 token；
- 全部 `(bank,local_address)` 单射；
- 全部有效五点邻域无 bank conflict；
- 338 个内点 K5 见证；
- 15 列恰为 5 的倍数，bank 槽利用率 100%。

普通 raster-id `%5` 的同端口映射：

| 邻域所需 replay 周期 | source 数 |
|---:|---:|
| 2 | 60 |
| 3 | 390 |

该结果只证明拓扑冲突，不代表 gate/K 稀疏后的真实 term 周期。

## 6. K-bitmap next-event iterator

旧 builder 对每个 descriptor 扫描全部 32 lane，即使 `K[lane]=0` 也耗费
扫描周期。整改后：

```text
remaining_K bitmap
  -> priority next-set-bit
  -> emit all unique gate terms for this lane
  -> clear bit
  -> next active lane
```

同一 `W=6` 定向向量：

| builder | relation producer stall |
|---|---:|
| 全 lane 顺序扫描 | 691 |
| K-bitmap next-event | 347 |

stall 减少 49.78%，product term 和最终 Acc 不变。

该机制借鉴 FireFly 类事件抽取与 Prosperity 的 exact-skip 思路，但只是
供给侧支撑机制，不单列为论文核心创新。

## 7. 架构创新应如何写

建议只列三项主贡献：

### C1：XBF-DBDR

把 Local5 固定方向 incidence 编译进 residual 交换与有界冲突服务，而不是
运行时做通用 128-to-4 compaction。

### C2：FCSR-RX

利用五点 stencil 的闭式最后消费者 frontier，在三行关系状态内完成
destination-major 到 source-major 的在线转置。

### C3：Source-Quotient TCFM

先按 source 内 gate 等价类商化 product work，再用达到 K5 下界的拓扑五色
banking 做无 replay multicast；一个 `OUT_DIM` product vector 只计算一次。

以下不能单列创新：

- 模 5 着色公式；
- 五 bank；
- 同步 RMW 和 forwarding；
- priority iterator；
- FIFO、双缓冲、descriptor；
- 定点化或 Shiftmax 本身。

它们是 C1-C3 的必要实现机制或证据。

## 8. 外部工作借鉴与本土化

| 工作 | 借鉴 | 本土化差异 |
|---|---|---|
| Prosperity | exact product/relation reuse | relation 和 gate 等价类由网络语义直接给出，不做通用在线 matcher |
| Phi | pattern/residual 分层 | pattern 是固定五点 incidence，residual 是 exact XOR event，不是 learned codebook |
| Bishop | TTB metadata-first、density 思维 | frontier-complete source descriptor；不做 ECP 或异构密疏双核 |
| FireFly-T | 多事件抽取 | K-bitmap next-event 只供给 source quotient，不声称原创 decoder |
| stencil/graph coloring | conflict-free banking | 着色与 source gate-equivalence product multicast、在线关系转置联合 |

这些工作提供设计范式，不应写成“我们首次提出 TTB、pattern/residual 或
event decoder”。

## 9. Motion 与 Local5

### Local5

固定五点关联图同时支持：

- 编译期 incidence；
- 闭式 relation lifetime；
- 三行在线转置；
- K5 下界的五色无冲突 banking。

因此 Local5 当前拥有更清晰的架构创新链。

### Motion

Motion 的 full attention 关系图接近全连接，不能用常数五色把任一 source
的全部 destination 无冲突映射到五个 bank。Motion 仍保留：

- TTB/STT temporal-pair；
- Motion-XOR；
- exact SCS-Shiftmax；
- gate-code term；
- DCTF 通用 bank-local projection。

Motion 适合作为通用 all-binary attention 对照和算法后备线，但不再与
Local5 并列宣称同强度架构创新。

正式主线选择仍需满足：

```text
Local5 fullres accuracy guardrail
AND post-G0 trace 支持 C1-C3
AND 同约束 EDP 为正
```

1. Local5 fullres exact 后的 post-G0 多样本 trace；
2. 每 stage 的 gate cardinality、term fanout、K density、全五角色 term
   比例、Linear-4/5 replay；

   同接口 RTL；
4. 同一 SRAM macro、同一 SDC 的 DC/STA/SAIF/EDP。

### P1

1. 真实 SRAM compiler wrapper 和 read-during-write 合同；
2. `TIME_PLANES=3`、更长随机反压和 Acc 溢出边界；
3. clear、readback、weight load、score/FCSR/builder/delivery 的完整周期
   分账；
4. full encoder FPS/带宽模型只在上述数据后更新。
