# Local5双向五色关系前沿到TCFM5真实回放闭环

日期：2026-08-03

## 1. 本轮结论

本轮把此前彼此分离的三个叶级机制接成一个统一、可回放的post-score架构slice：

1. `word-level五色zero skipper`在destination-major关系写入时建立active-source集合；
2. `relation frontier`只读取active source，并恢复精确的五方向consumer关系；
3. `source multicast term builder`按相同gate合并角色并按active K lane生成term；
4. `TCFM5`用`bank(x,y)=(x+2y) mod5`将一个Local5五点邻域的五个destination映射到五个不同单写bank。

同一套五色映射第一次同时承担两种职责：前端将稀疏source按颜色组织成可跳零的关系前沿，后端将同一source的五个consumer无冲突写入Acc。这不是两个独立的“五bank技巧”，而是一份贯穿关系倒置与投影累加的拓扑合同。

在本机qualified post-G0 trace中固定抽取100个T450 group后：

| 指标 | TCFM5 | Linear5强基线 |
|---|---:|---:|
| 总busy周期 | 108,012 | 158,342 |
| mean | 1,080.12 | 1,583.42 |
| p95 | 3,294.7 | 5,656.7 |
| p99 | 4,999.3 | 9,353.0 |
| max | 5,132 | 9,453 |
| 扁平Yosys generic cell | 2,262 | 2,745 |

在相同前端、相同term、相同五个单写Acc bank和相同输出下，TCFM5的RTL总周期加速为`1.466x`。每个后端分别通过90,000个、合计180,000个32-bit Acc逐值比较。Yosys generic cell少约`17.6%`，但该值不是工艺面积。

证据等级为 **[rtl]+[qualified-post-G0]+[open-logic-proxy]**。当前仍没有目标工艺PPA。

## 2. 为什么这次比叶模块更像架构贡献

### 2.1 原来的缺口

此前证据只说明：

- active source可以减少固定450-source扫描；
- 五色bank映射在端口模型中没有局部写冲突；
- word-level skipper比450-bit深优先编码器更容易实现。

这些结论没有证明三者接在一起仍精确，也没有证明相同五bank强基线下有RTL周期收益。

### 2.2 当前统一数据流

```text
destination-major post-score relation
  {plane,y,x,Kself,valid[5],active[5],gate[5]}
                    |
                    v
       dual-color relation frontier
       +---------------------------+
       | relation store            |
       | five-color active words   |
       | 15-word nonzero frontier  |
       +---------------------------+
                    |
          only active source
                    v
  {source,K,incoming gate[5],valid[5]}
                    |
                    v
       gate-equivalence term builder
    {source,lane,gate,destination mask}
                    |
          same narrow term stream
          /                     \
         v                       v
 TCFM5: (x+2y) mod5       Linear5: raster-id mod5
 conflict-free issue       exact replay on conflict
         \                       /
          +---- same 5x1W Acc ---+
```

该对照消除了以下混杂变量：

- source压缩率；
- term数量与顺序；
- 权重与乘法位宽；
- Acc容量与端口数；
- 关系写入、Acc清零和drain开销。

唯一架构变量是destination到bank的映射，以及由该映射决定的冲突/replay控制。

## 3. 真实工作负载合同

输入来自：

`results/local5_fullres_postg0_qfsa_profile100_20260730/ordered_term_manifest.json`

该manifest标记为qualified，包含100个样本、12个attention module、4,800个group和T450形状。RTL回放不是直接读取模型统计，而是执行以下可逆变换：

1. 从source descriptor的五个consumer角色反推destination/candidate位置；
2. 生成450个destination-major关系写入；
3. 用同一逆映射重新构造source descriptor并逐角色检查；
4. 根据K bitmap、gate和权重生成32-bit Acc金参考。

固定抽样规则为每个stage等距选25组，共100组。向量manifest保存源文件SHA256、选择索引和各组active/term/update总量。

本次100组累计：

| 指标 | 数量 |
|---|---:|
| 全source槽位 | 45,000 |
| active source | 9,427 |
| gate-lane term | 53,085 |
| destination update | 166,080 |
| 完全空group | 45 |

45个完全空group很重要：它们使平均加速只有`1.209x`，低于非空重组的收益，并证明报告没有删除不利样本。

## 6. Yosys结构代理的正确解读

扁平结构统计为：

| 指标 | TCFM5 | Linear5 | 变化 |
|---|---:|---:|---:|
| generic cell | 2,262 | 2,745 | -17.6% |
| wire bits | 35,086 | 36,228 | -3.2% |
| mux | 1,024 | 1,255 | -18.4% |

TCFM5不仅周期更少，控制结构也更简单，主要少了linear5的角色冲突选择、remaining-mask和replay状态。但是：

- `$mem_v2`没有映射到真实SRAM macro；
- `$mul/$mod/$div`仍是generic operator，常数优化结果依赖后续综合；
- generic cell数量不能转写为面积、功耗或EDP。

因此这些数字只能支持“没有用显著更多开放逻辑换周期”，不能支持PPA结论。

## 7. 可写入DATE的贡献表述

当前Local5硬件贡献可以收敛为一条主贡献和两个机制，而不是把普通buffer逐项列成创新：

**主贡献：双向拓扑着色关系数据流。** 对Local5五点候选图使用同一五色合同，同时构造前端active-source关系前沿和后端无冲突Acc映射，将destination-major score输出无损变换为source-major复用term，并避免固定source扫描与投影写冲突。

**机制一：word-level topology frontier。** 五个颜色bank各自维护少量word-nonzero元数据，仅对活动source做关系读出；T450下不使用450-bit深优先编码器。

**机制二：topology-preserving term multicast。** gate-equivalent term保留Local5角色掩码，后端不展开为五条独立命令；五个consumer在一个周期写入五个互异bank。

与Prosperity/FireFly-T/Bishop等工作的关系必须克制表述：

- 借鉴Prosperity的exact sparse execution和trace驱动评估方法，但本工作复用的是`(source,gate,lane)`而非ANN binary partial product；
- 借鉴FireFly-T的时空驻留思路，但本工作将Local5图着色作为跨关系前沿与Acc的统一合同；
- 借鉴Bishop的metadata-first思想，但不使用异构双核或近似ECP；
- 与复旦ISSCC蝶形zero skipper相同的是word级“先判空再定位”，不同的是本工作按Local5拓扑颜色组织source，并直接连接无冲突consumer写入。

## 8. 尚不能宣称的内容

1. 不能说已完成Local5全加速器；当前slice从post-score开始。
2. 不能说已完成SRAM实现；关系存储和bitmap仍是RTL数组。
3. 不能说已获得面积、频率、功耗或EDP；Yosys不是DC/PTPX。
4. 不能说100组代表完整部署帧；它是qualified trace的固定分层抽样。
5. 不能把远端Claude或其他机器的结果并入本机证据。

## 9. 下一轮优先级

1. 将关系存储改为显式同步1R1W SRAM合同，加入1-cycle/2-cycle读延迟和bank backpressure；
2. 在同一100组向量上比较理想数组与同步SRAM版本，确认`1.466x`是否保持；
3. 为统一slice跑OpenROAD或至少ABC同库映射，报告WNS、cell area、拥塞代理；
4. 增加固定seed随机关系逆变换、输出反压和多轮连续window覆盖；
5. Local5 score/Shiftmax与本slice的边界只做接口闭环，不急于扩成full encoder；
6. Motion线下一轮补T450 TARE增量score与weighted-SCS到gated-K链，不能用本轮Local5结果替代。
