## 3. 两个 fail-closed 负例

### 3.1 release source-tree 污染

首批目录 `results/local5_numeric_samples3_6_batch_v1_20260812/` 在仿真前失败。
原因是 sealed release 的 source tree 中出现额外 Python `__pycache__/.pyc`，与冻结的
source SHA 清单不一致。四路均在约 2.4 秒内退出，没有产生伪 PASS。清理生成缓存并
重新执行 release verifier 后才允许运行真实回放。

这个负例证明 release 校验是 fail-closed；删除对象仅为 Python 生成缓存，不是 RTL、
脚本源码或用户数据。

### 3.2 聚合器保守假阴性

真实回放完成后，`results/local5_numeric_samples3_6_batch_v2_20260812/` 返回 FAIL。
四个 shard 自身均为 12/12 窗口、零失配；失败来自新增聚合器把
`complete.release_binding_sha256` 的“binding 文件哈希”错误解释为“release manifest
哈希”。这是聚合器合同错误，不是数值或 RTL 失败。

该错误没有放宽为 PASS，而是修正字段语义后只读重验已经 sealed 的四个 shard。
v2 保留为保守假阴性证据。

## 4. 最终独立只读聚合

最终脚本：

```text
scripts/run_local5_numeric_sample_batch_v1.py
scripts/test_run_local5_numeric_sample_batch_v1.py
```

v5 聚合器不只读取 merge 报告中的 `mismatch=0`，还独立执行以下检查：

1. 分别绑定 release-binding 文件、release manifest、release complete 和三层 SHA 清单；
2. 限制所有 shard 路径不得跳出各自目录；
3. 直接以 `allow_pickle=False` 打开 Acc32 NPZ；
4. 强制 `schema_version=4`、全部 metadata 的 dtype/shape 和有序 12-block 拓扑；
5. 逐窗检查 token、weight、head 与 report 顺序一致；
6. 强制每段 offset 长度为 `heads x 450 x 32`；
7. 独立逐元素比较 `expected_acc32` 和 `actual_acc32`。

篡改单测直接修改 `actual_acc32[17]` 并调用 archive miter，不经过外围 SHA，因此明确
验证逐元素比较本身会拒绝错误。3/3 单元测试和 `py_compile` 均通过。

v5 是对 v2 已执行 RTL shard 的只读独立聚合复验，不是第二次 RTL 仿真。最终结果为：

```text

samples_passed = [3,4,5,6]

```

## 5. 独立 DATE 复审

首轮复审为 `4.1/5 Conditional Accept`、P0=0、P1=2、P2=2。两个 P1 分别是：

- 篡改单测可能先被 archive SHA 拒绝，未单独证明逐元素 miter；
- NPZ 的版本、dtype、顺序和分段 offset 合同不够严格。

修复后最终针对性复审为：

```text
4.5/5 Accept（仅针对 numeric 证据包）
P0 = 0
P1 = 0
P2 = 1
```

唯一 P2 是所有源码、收据和 SHA 仍在同一个可修改存储域，没有外部不可变 trust root。
它不阻止本机证据采用，但投稿归档时仍应将最终 manifest 放入独立只读存储或版本化
制品库。

## 6. 证据边界

允许表述：

> Local5 numeric Acc32 shard coverage 达到 7/100 `[rtl]`；其中 sample3-6 以同一
> sealed v5 RTL release 覆盖 48 个 block-window、7,948,800 个 int32 Acc32，软件整数
> 金参考与 RTL 输出逐元素一致，零失配。

禁止表述：

- 7/100 等于 100-sample formal G0；
- 每个 sample 的 12 个窗口等于全部空间窗口或 full encoder；
- regression cycle 是部署性能；
- 本批提供 DC/STA/SAIF、ASIC PPA 或系统 FPS；
- 数值验证基础设施本身是 DATE 架构创新。
