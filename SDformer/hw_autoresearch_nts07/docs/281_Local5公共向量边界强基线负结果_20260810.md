# Local5 公共向量边界强基线负结果

> 日期：2026-08-10  
> 前序：`docs/280_Local5合法1RW_TCFM5跨头驻留闭环_20260810.md`  
> 本轮唯一问题：消除 scalar-B0 的 32 次重复行读取后，TCFM5 跨头驻留相对
> 合法向量物化强基线是否仍达到每个 seed 至少 `1.20x` 的事前周期门槛。

## 1. 结论

本轮新增公共向量边界：

```text
B0v materialize:
  per-head TCFM5 5x(90x1024-bit 1RW)
    -> 450x1024-bit vector stream
    -> second 5x(90x1024-bit 1RW) cross-head Acc
    -> shared vector serializer

B2v resident:
  cross-head-resident TCFM5 5x(90x1024-bit 1RW)
    -> 450x1024-bit vector stream
    -> shared vector serializer
```

`[rtl]` B0v 与 B2v 都只读取每个 Acc 向量行一次，且最终进入完全相同的 32 路
serializer。三 seed 正式结果为：

| 候选 | mean 周期 | Acc32 | 逐事务服务 digest |
|---|---:|---|---|
| B0v 向量物化 | 311118 | 零失配 | 与 B2v 相同 |
| B2v 跨头驻留 | 294699 | 零失配 | 与 B0v 相同 |

B2v/B0v 三个 seed 分别为 `1.055710x / 1.055748x / 1.055686x`，最差
`1.055686x < 1.20x`。因此本轮结论是：

1. 旧 scalar-B0 下的约 `1.94x` 主要来自重复标量行读取，不是可作为 DATE
   强基线的跨头驻留收益；
2. TCFM5 跨头驻留在公共向量边界下仍有正周期收益，但当前量级不足以单列为正文贡献；
3. 按事前门槛停止该机制的 memory-inclusive OpenROAD 晋级，不事后降低阈值；
4. 保留跨头驻留作为 Local5 数据流的实现选项，而不是论文主创新。

旧 scalar 路径也用当前代码复跑 seed `17717`：B0=`818492`、B2=`422972`，证明新增
向量口没有破坏旧路径；但这组约 `1.94x` 仍只属于弱 scalar-materialize ablation。

## 2. 为什么 B0v 是更强且公平的基线

旧 B0 在每个 `(plane,y,x,out)` 上发起独立读请求。底层 1RW bank 实际存储
`1024-bit` Acc 向量，因此同一行被读取 32 次，随后每个 32-bit 标量又写入
`14400x32` cross-head memory。这把“向量服务粒度”与“是否跨头驻留”两个变量混在
一起。

B0v 把每个 head 的完整行只读一次，并在五个合法 1RW 向量 bank 内做跨头 RMW：

- 每个向量包含同一 token 的 32 个 Acc32；
- 地址布局与 TCFM5 的五色 bank 完全一致；
- head0 首次触达直接写，head1/head2 对同一向量执行合法 1RW RMW；
- 最终向量与 B2v 共用同一个 serializer，外部仍观察完全相同的 scalar Acc32 顺序。

所以 B0v/B2v 只保留一个核心差异：是否在原 TCFM5 Acc 内跨 head 保留状态。

## 3. 公平服务合同

TB 不再只比较请求总数和 delay sum，而为每类事务累计
64-bit 顺序相关的 identity digest：

```text
token : {tag, head, token_id, transaction_index, delay}
weight: {tag, head, output_tile, lane, out, transaction_index, delay}
result: {tag, output_tile, plane, y, x, out, transaction_index, delay}
```

`[rtl]` seed `17717` 的三类 hash 分别为：

| 事务 | digest |
|---|---|
| token | `c43a1e3a83ab6041` |
| weight | `a07c1812f23faf25` |
| result | `04849bdf2549c2e5` |

B0v/B2v 三项逐一相同，不是由总和相等推断。它们是序列审计
digest，不是 SHA-256，也不代替 Acc32 oracle 的逐项比对。最终 result 仍经历
transaction-indexed 随机反压，两个候选共用相同第 n 次服务合同。

## 4. RTL 结构

新增两个结构单元：

- `qfit_local5_vector_cross_head_acc`：五色 `90x1024-bit` 合法 1RW 向量跨头 Acc；
- `qfit_acc32_vector_serializer`：一次锁存完整向量，随后在反压下稳定发出 32 个
  Acc32，不再回读 SRAM。

TCFM5 新增可关闭的向量读口。默认 `ENABLE_VECTOR_READ=0`，旧 scalar 接口和旧 TB
保持原行为；B0v/B2v 才显式启用。scalar 与 vector 请求互斥，权重 context 只能在
两类读响应都清空后释放。

正式报告验证 45 个源码/脚本/SVA/oracle SHA 项并绑定 24 份日志。当前 oracle 的三头
term 数为 `7/21920/10`，中间 head 占约 `99.92%`；它仍是定向状态测试，
不代表真实 fullres 分布。即便三 seed 完全一致，也不能把 `1.0557x`
外推到全部 stage/block/head。本轮只做 Yosys 结构可读检查，没有宏绑定、SDC、
STA、布局布线、功耗或 EDP 证据。

另外，当前 job engine 的 vector `valid` 是在 `ready` 已经为高时发出的单周期
pulse，不是通用 decoupled ready/valid 协议。当前直连组合下可用；未来接入
SRAM wrapper 或额外反压级时，必须先改成 `valid` 独立保持到 handshake
完成的标准合同。

## 6. DATE 贡献裁决

本轮是一次必要的强基线否决，不是新贡献的晋级：

- **不能再写**：“跨头驻留相对合法基线加速约 `1.94x`”；
- **可以写入方法/消融**：公共向量边界证明 scalar 物化接口会夸大驻留收益；
- **可以保留实现**：B2v 少五个跨头向量 SRAM bank，后续若有 DC/PTPX，可作为
  memory-capacity 消融，而不是当前周期主结果；
- **不能进入摘要贡献**：TCFM5 跨头驻留、lazy-zero、向量 serializer。

Local5 的架构主张应继续集中于 relation-driven source-major term 与五色拓扑冲突
消除，而不是依赖跨头驻留放大收益。

## 7. 独立 DATE 评审

### 7.1 评审结论

2026-08-10 已完成独立只读 DATE 评审：

| 范围 | 评分 | 结论 |
|---|---:|---|
| 当前证据包 | `3.9/5` | 公平、诚实且可复现的负结果 |
| Local5 整体 | `3.3/5` | RTL 深度足，真实 workload 与 PPA 未闭合 |
| 架构创新 | `2.5/5` | TCFM5 有领域特异性，跨头驻留本身常规 |
| DATE 就绪度 | `2.8/5` | Weak Reject / Major Revision |

评审认可 B0v/B2v 共享 `450x1024-bit` 最终向量边界和同一 serializer，
也认可合法 1RW 合同与组合环修复。无 P0。主要 P1 是真实 workload 外部
有效性、`USE_MEMO=1` 组合未覆盖和无物理证据。

裁决：

1. TCFM5 跨头驻留从正文贡献列表移除；
2. 公共向量边界与 serializer 归入验证方法或附录；
3. `1.0557x` 只作为定向 RTL 消融负结果；
4. `REJECT_VECTOR_RESIDENCY` 阻止该机制单独进入 OpenROAD，但不阻止 Local5
   整体架构以后做 OpenROAD/DC。

### 7.2 下一轮预注册门槛

下一轮唯一优先项为真实 joint-head fullres profile，不在当前偏斜 oracle
上继续扩 Local5 微机制。profile 必须：

1. 固定 checkpoint/config/cohort SHA，覆盖不少于 100 个 sample-window、12 个
   attention block、全部 head 和真实 valid mask；
2. 输出 term/head、跨头 relation overlap、gate cardinality、五 bank 冲突、
   1RW RMW、向量物化流量与周期的 mean/p50/p95/p99；
3. 新 Local5 候选在同一合法 1RW 模型下的加权平均预测改善必须
   `>=20%`，p95 不退化，且后续 Acc32 bit-exact，才允许新增 RTL；
4. 若无候选过 `20%` 门槛，暂停 Local5 微机制扩展，下一轮转向
   Motion 多样本证据。
