# M275r2：Conv 树 materializer 单端口/单累加器合同修复

M275r2 已按 M279 的 P0/P1/P2 意见收紧，结论为：**端口和 valid 生命周期在保守模型下可行，但树 materializer 自身几乎不加速。**

## 修复内容

1. 当前计算 bank 显式计入 96B weight read 和 144B selected-child PWP read。
2. next PWP bank 固定为一个同步 144B read-or-write port；非 root、非 accumulator resident 的 parent 先独占一拍读取，child 在最后一个 flip update 拍写回，二者不得同拍。
3. next weight bank 的 32B fill 与 96B generator read 串行；pattern 32B、descriptor 64B 与 weight 共用 32B/cycle DRAM fill link。
4. generator 只有一个 96-lane signed12 accumulator。每次 child 写回后只保留该 child；冻结 Prim 顺序下重取 parent 的 edge 数为每 catalog 5,041。
5. next weight/metadata/PWP 的 valid 分别在完整 fill、完整 fill、最后一次 child write 后置位；role switch 只有在三者 valid 且 generator idle 后才允许。
6. 绑定 M251r2：16 项 signed-INT8 PWP 的正确范围为 `[-2048, 2032]`，signed12 仍安全，cycle 不变。

| materializer-only ratio | 1.0000071807x | 不能作为 headline |
| vs bit-sparse | 1.5405684725x | 完整 modeled PWP Conv ratio |
| vs dense | 18.8332234608x | 完整 modeled PWP Conv ratio |

与旧 M275 相比，parent 144B read 使 cold start 从 675 增至 707、总 cycle 增加 320、reduction 从 2,850 降到 2,530；但冻结 10-sample trace 内仍无 transition stall 暴露。

## 不能写成什么

- 1.54x/18.83x 不是树 materializer 的贡献，而是完整 PWP Conv 模型相对 bit-sparse/dense 的比值。
- 61,776B 只是 weight/PWP/metadata/accumulator 的容量下界，不含控制、队列和物理 macro overhead。
- 本里程碑没有 RTL/VCS、SRAM macro、DC/PT、energy、完整 Conv RTL 或 system speedup 证据。
- PWP 的 DRAM payload 被树描述符替代不等于 on-chip PWP bank 被消除。

## 下一轮独立打铁重点

独立评审应从冻结 payload/catalog 重建而不是导入本分析器，并重点核查：

1. 5,041 个 nonresident parent edge 的 residency 判定及乘 8 output block 后的 403,280 个 144B read；
2. child write 与最后一个 weight update 重叠是否合法，同时 parent read/write 在单 PWP port 上始终互斥；
3. external bank-valid 与内部 per-entry-valid 的区分，确认没有 parent use-before-write 或 early role switch；
4. 707/827/333/0 与总周期 352,332,590 的独立复算；
5. 61,776B 容量求和及 1.000007x 与 1.54x/18.83x 的归因分栏。
