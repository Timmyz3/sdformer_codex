# Local5 EREP G2 物理评估预实现合同

## 1. 本轮结论

本轮只冻结 Local5 EREP v4 的 G2 预实现评估合同，不实现 EREP RTL，
不修改核心 RTL，也不修改现有 OpenROAD 配置、runner 或 SDC。合同覆盖
`C0--C5` 同一 relation-to-projection 功能边界，并把开放物理代理与目标
ASIC 评估严格分开：

- `G2a`：Nangate45 + OpenROAD 的 `[开放物理代理]`；
- `G2b`：目标服务器上的 DC/STA/SAIF/PTPX，当前全部为 `[待验证]`。

G2a 只能说明在冻结的开放工具、开放库和代理 SRAM 下的相对趋势，
**不能写成 ASIC PPA**、目标工艺功耗、STA signoff 或可流片结果。

机器可检查合同为：

`contracts/local5_erep_g2_preimplementation_contract_v1_20260810.json`。

## 2. 为什么现在必须先冻结合同

EREP 的核心比较不只是周期。C1--C5 会增加 relation epoch slot、Acc
context、memo payload、tag/valid metadata 和控制状态。如果只比较计算周期，
或者把这些状态当成免费存储，会系统性偏袒复杂候选。因此 G2 必须在实现前
冻结以下规则：

1. C0--C5 输入、输出、数值和 workload 完全相同；
2. 所有候选使用同一频率、同一物理边界、同一 activity 和 idle 口径；
3. 动态能量、时钟能量、存储能量和按延迟积分的漏电能量全部计入；
4. C4 first-fit 的控制、metadata 和存储都计入；
5. 任何候选不能通过私下降频、换 SRAM 宏或裁剪 activity 窗口过关；
6. 时序失败直接淘汰，不给失败候选另设低频结果作为主表数字。

## 3. C0--C5 的同一功能边界

### 3.1 边界定义

固定边界 ID 为 `local5_erep_relation_to_acc32_v1`。

输入边界：已经 sealed 的 Local5 relation workspace，以及相同的 weight、
bias、context、source-major term 和 output-tile stimulus。

输出边界：每个 output tile 的完整 `OUT_DIM=32` Acc32 状态与公共
drain/readback。

边界内必须计入：

- relation workspace 读；
- relation epoch 的 fill/read；
- FIFO2 term delivery；
- 五 bank Acc32 更新；
- context prepare；
- common drain/readback；
- 候选新增的全部控制、metadata 和存储。

边界外包括 voxel、sealed relation 之前的 score/Shiftmax5、完整 encoder
ATLIF/skip 调度和片外 SoC 集成。本合同因此是 projection subsystem 的公平
物理评估合同，不冒充 full-encoder ASIC。

所有候选必须消费同一组逻辑事务并产生逐元素 bit-identical Acc32 结果。
禁止通过剪枝、近似、改变数值顺序语义或候选专属 workload 获得收益。

### 3.2 候选冻结表

| 候选 | 机制 | Stripe | Epoch slot | Acc context | 物理角色 |
|---|---|---:|---:|---:|---|
| C0 | Direct serial | 1 | 0 | 1 | 主精确基线 |
| C1 | reuse-only S2 | 2 | 1 | 2 | 仅 relation 复用消融 |
| C2 | overlap-only | 1 | 2 | 1 | 仅 producer/execute 重叠消融 |
| C3 | EREP S2 | 2 | 2 | 2 | 复用与重叠组合候选 |
| C4 | capacity-matched first-fit memo | 1 | 0 | 1 | 可实现的同容量 memo 基线 |
| C5 | full relation memo | 1 | 0 | 1 | 更大容量精确复用上界，不面积公平 |

C4 只允许固定、在线可实现且不看事后收益的策略：按 input-head 顺序无条件
first-fit；只要下一条完整非空 relation 能整体放入就接纳，否则走 Direct。
禁止 saved-cycle oracle、预测、replacement 和重新考虑。其 payload 容量为
`561,600 bit`，即 `5,014 x 112 bit + 32` 个静态不可用 bit。目录固定为
24 项，每项含 32-bit tag、1-bit valid、13-bit base 和 9-bit length，共
`1,320 bit`；24 路精确 tag 比较、最低索引优先、payload 端口和 fallback
控制必须全部计入面积、功耗和能量。

C5 payload 为 `1,209,600 bit = 10,800 x 112 bit`，用于无 capacity miss 的
较强精确复用参考；由于容量更大，它不能冒充同面积基线。

## 4. G2a：Nangate45 开放物理代理

### 4.1 固定物理口径

| 项 | 冻结值 |
|---|---|
| 平台 | Nangate45 open proxy |
| 周期/频率 | 5 ns / 200 MHz |
| OUT_DIM | 32 |
| Die | `0 0 2000 1600` um |
| Core | `20 20 1980 1580` um |
| Pin seed | 42 |
| IO layer | horizontal metal5 / vertical metal6 |
| 基础 SRAM 宏 | 32 个 |

32 个基础宏的实物分布为：

- `fakeram45_128x256`：20 个；
- `fakeram45_256x16`：10 个；
- `fakeram45_256x32`：2 个。

“固定 32 个 SRAM 宏”表示 C0--C5 都必须保留同一套 relation/Acc 基础宏，
不能用候选新增存储替换或隐藏这 32 个宏。增量映射在看到结果前固定为：

| 存储类 | 逻辑容量/端口 | G2a 固定映射 |
|---|---|---|
| 额外 Acc context | `460,800 bit`，五个独立 1RW bank，读延迟 1 | 20 个 `128x256` |
| 一个 epoch slot | `50,400 bit = 450x112`，单端口 1RW，读延迟 1 | 10 个 `256x16` + 2 个 `256x32` |
| C4 payload | `561,600 bit`，单端口 1RW | 40 个 `128x256`，另计固定 1,320-bit 目录 |
| C5 payload | `1,209,600 bit`，单端口 1RW | 85 个 `128x256`，另计固定 1,320-bit 目录 |

因此 C0--C5 的总宏数依次为 `32/64/56/76/72/117`。固定 outline 放不下、
宏目录不具备或无法布通时，候选直接失败；不能在结果出来后改用另一种宏、
标准单元存储或单独扩 floorplan。这一保守映射会暴露容量浪费，但比给新增
存储“免费面积”更可辩护。

### 4.4 当前 config/runner 的真实边界

现有 runner 只暴露 `direct/issue/ds` 三个旧模式，并不能直接执行新的
C0--C5 EREP 物理候选。它在本合同中是物理政策锚点，不是“C0--C5 已完成
物理实现”的证据。

未来 C0--C5 wrapper、filelist 和参数 manifest 必须单独生成 SHA receipt，
且不得放松本合同的 5 ns、outline、pin seed、SDC、宏 catalog 和计量规则。

### 4.5 Activity、idle 与 clock-gating

所有候选必须使用同一个 formal workload/stimulus bundle。共同 stimulus SHA
当前为空并标为 `[待验证]`；每个候选还必须记录由该共同 stimulus 生成的
SAIF SHA。

统一测量窗口：

- 起点：相同 reset/preload 后的第一笔 accepted transaction；
- 终点：相同逻辑 workload 的最后一次 common drain/readback fire；
- 中间的 bubble、backpressure 和 tail latency 全部保留；
- core clock 始终为 200 MHz；
- G2a 禁止 automatic ICG，也禁止候选专属 ideal clock gating；
- 只允许共同可用、由相同 trace 驱动的显式 RTL enable；
- 禁止针对候选裁短 activity window。

### 4.6 时序与布线淘汰条件

G2a 每个候选必须在共同 5 ns 下同时满足：

- post-route setup violation = 0；
- post-route hold violation = 0；
- detailed-route DRC = 0；
- unconstrained functional endpoint = 0。

任何一项失败都执行 `ELIMINATE_CANDIDATE`。现有 Direct 报告仍有一个 hold
违例，因此只能作为历史开放物理基线，不能自动视为通过本 G2a 合同。

## 5. Memory-inclusive EDP 口径

### 5.1 单 trace 口径

延迟：

```text
latency_j = cycles_j / 200000000
```

总能量：

```text
energy_j = E_logic_nonclock_dynamic
         + E_clock_dynamic
         + E_memory_dynamic
         + (P_logic_leakage + P_memory_leakage) * latency_j
```

这里的 memory 包括固定 32 个基础 SRAM 宏，以及候选新增的 epoch slot、
memo、tag/valid 和其他状态实现。漏电不是一个瞬时功率数字，而是必须按每个
候选的真实延迟积分成漏电能量。

### 5.2 加权与主比较

对共同 workload 中的 trace `j` 使用同一预注册权重 `w_j`。权重实物固定为
`joint_window_selection_plan.json`，SHA-256 为
`4e8732210a64cfcb553e7f4eee3657be70cc975a38839527e4792668d6deaf6b`。
必须对 1,200 个 joint-window row 分别生成有界 activity/energy 记录后再加权；
一个没有逐 trace 分账的整段 SAIF 不能替代该口径：

```text
weighted_energy  = sum(w_j * energy_j)  / sum(w_j)
weighted_latency = sum(w_j * latency_j) / sum(w_j)
candidate_EDP    = weighted_energy * weighted_latency
```

主指标为：

```text
EDP_ratio(Cx) = C0_memory_inclusive_EDP / Cx_memory_inclusive_EDP
```

即分子始终是同条件 C0，分母是候选 Cx。C3 的两个冻结门槛为：

```text
4*EDP_C0 >= 5*EDP_C3       # 相对 C0 至少降低 20%
19*EDP_C4 >= 20*EDP_C3     # 相对可实现 C4 至少降低 5%
```

唯一计算器是 `scripts/local5_erep_g2_contract_v1.py`，输入必须为正的十进制
字符串，门槛用整数交叉乘法判断。任一门槛失败，C3 的 G2 失败。主表还必须
分别报告 std-cell、基础 SRAM、增量存储、metadata/control 面积和总利用率，
禁止只报 memory-excluded EDP 或只报 cell area。

## 6. G2b：目标 ASIC 运行前 receipt

G2b 当前不能运行。必须在目标服务器开始任何一个候选前，先生成一个适用于
全部 C0--C5 的共同 receipt。receipt 的所有 required field 均不得为空，至少
覆盖：

1. 目标工艺库名称、node、`.lib/.db` SHA、PVT、operating condition、V/T；
2. DC、STA、SAIF 生成工具、PTPX 的版本与命令 SHA；
3. 同一 SDC 的路径与 SHA；
4. SRAM macro `.lib/.db`、LEF/面积模型、动态功耗模型、漏电模型和端口延迟合同 SHA；
5. RTL manifest、filelist、参数 manifest SHA；
6. 共同 activity stimulus、各候选 SAIF manifest SHA；
7. 统一 idle/clock-gating policy SHA；
8. wireload 或 physical-aware policy、物理参考文件和完整命令 manifest SHA。

运行前必须执行：

```bash
python scripts/local5_erep_g2_contract_v1.py preflight RECEIPT.json
```

preflight 严格检查字段集合、非空值、SHA 格式与实物、SDC 路径，以及 C0--C5
的 boundary、5 ns、PVT、SDC、宏端口合同、共同 activity、idle/gating policy。
空字符串、伪 SHA、缺文件或候选专属例外均 fail closed。未来 C0--C5 物理
runner 仍必须显式调用该 preflight；当前 runner 尚未实现，继续标 `[待验证]`。

G2b 禁止候选分别降频或换宏。一个候选在共同 target clock/PVT 下 timing fail，
就直接淘汰；不能把该候选降频后的数字混入同频主表。Activity annotation
coverage 必须至少 95%，unknown toggle 必须为 0，并单独审计 SRAM pin activity。

## 8. 运行与失效规则

严格单测入口：

```bash
python -m unittest \
  tests.test_local5_erep_g2_contract_v1 \
  tests.test_local5_erep_g2_contract_runtime_v1 -v
```

单测检查 C0--C5 边界、C4 无条件 first-fit、增量 bit/端口/宏映射、
5 ns/OUT_DIM32/32 基础宏、EDP 精确门槛和 G2b fail-closed preflight，并重新
计算所有已冻结文件、ORFS dirty patch、工具 binary 与唯一计算器 SHA。

以下任一事件发生时 v1 自动失效，必须重发合同：

- 任何冻结文件或工具 SHA 改变；
- ORFS dirty patch/status 改变；
- 修改共同频率、outline、pin seed、宏映射或 activity/idle 政策；
- C0--C5 功能边界或 C4 first-fit 策略改变；
- 目标服务器 receipt 允许空 required field 或候选专属例外。

## 10. 第一次独立 DATE 评审与整改

第一次独立评审给出 `2/5，DENY`。第一轮只完成了合同字段整改，不能写成
证据链已闭合：

1. C4 删除“positive saved cycle”事后判据，改为无条件顺序 first-fit；
2. C1--C5 冻结逻辑容量、端口、读延迟、G2a 宏数量和固定 metadata；
3. 新增 G2b preflight，当前只闭合 shared artifact；候选私有 RTL/filelist/
   parameter 实物绑定仍未闭合；
4. 冻结 `C0/C3 >= 5/4` 与 `C4/C3 >= 20/19`，由唯一 Decimal 计算器执行。

第二次独立评审给出 `3/5，Major Revision，DENY`，并复现三项残余 P0：

1. C4 代码仍含 `saved_cycles>0`，与无条件 first-fit 合同冲突；该项现已修复，
   负收益 fixture 下仍接纳全部可容纳的非空 head，`8/8 PASS`；
2. 候选私有 SHA 仍可只填合法字符串而不绑定实物；未关闭；
3. EDP evaluator 仍可读取六行聚合自报数，不读取 1200-row energy ledger、
   timing/DRC、SAIF、SRAM pin、宏实例和 Acc32 收据；未关闭。

因此本合同当前仍是 `[合同草案]+[单测]`，不是可启动 G2 的执行闭环。它没有
生成 G2a/G2b 结果，也没有关闭 activity SHA、候选 runner、目标库/PVT、绝对
面积/功耗预算等阻塞。
