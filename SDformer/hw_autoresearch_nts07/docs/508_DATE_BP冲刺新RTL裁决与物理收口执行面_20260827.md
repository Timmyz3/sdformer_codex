# DATE/BP 冲刺：新 RTL 裁决与物理收口执行面

日期：2026-08-27

## 结论

当前不再开发第四种通用 sparse matcher、event router、delta cache 或
attention prune RTL。独立审计的当前分数约为 **3.2/5（Borderline Reject）**，
BP readiness 约 **1.9/5**。但 2026-08-27 的 M510 覆盖审计发现，旧 profiler
漏 hook H67 的四层 `ConvTranspose2d` decoder；因此 `620,302,905` 从现在起
只能称 **included-scope envelope**，不能再称严格全网。该缺口形成一个新的
trace-first 条件 RTL 候选，而不是授权泛化扩线。

允许继续开发/修改的硬件只有三类：

1. **FC2 matched shared-state bank-coissue**：现有 M495/M496/M499 继续物理
   收口；这是唯一无条件优先的 RTL。
2. **dynamic-BN 16/24-bit raw replay**：只有 exact integer/raw/address trace
   通过全部门后才允许写 RTL；当前仍是条件候选。
3. **Event-Polyphase Decoder（EPD）**：只允许先抓四层反卷积 exact binary
   index trace，再做同 96-lane、同 SRAM/bank 的 A0/A1 周期快杀；未过门不得
   写 RTL。详细纠正与门槛见 `docs/510_H67反卷积覆盖缺口与EPD立项裁决_20260827.md`。

ATLIF remaining-budget early-stop 已由真实 issue reduction `0.06761%` 否决；
Conv M479/M498、单口 scratch M504/M505、FC1 扩宽、patch 空 tile、PAFT
near-match 和 attention 有损主线均不再扩 RTL。`docs/359` 保持 SHA256
`dedde7ce44c3e595098f25ce6550dc0f6dfd66ce7227bcffd3dab0426a7bdfc4`。

## 1. 当前唯一首选 RTL：FC2 shared-state bank-coissue

### 1.1 已证明与未证明

| 证据 | 当前状态 | 合法含义 |
|---|---|---|
| H67 120-record frontend replay | K8/K1 `4.764209x` | 同 scope、低带宽 K1 分母的局部 frontend 周期比 |
| equal-bandwidth directed VCS | K8/K1x8 `1.000x` | 同八 bank 峰值下吞吐持平；不能卖正周期倍率 |
| K1/K8/K1x8 RTL | exact VCS 分别通过；M495 同 top 已冻结 | 可进入同 top、同 SDC、同 pins 的物理比较 |
| M496 r3 runner | 静态打铁 `95/100` | 仅在 64 GiB commit headroom 等资源门全过后允许一次 DC replay |
| 当前共享机 | `simv` 活跃且 commit headroom 低于门槛 | 不能启动；不是设计失败 |
| Formality/PTPX/宏 | 未完成 | 不能称 paper PPA 或 energy/token |

FC2 在旧 included-scope `620,302,905` opportunity envelope 中占约 `6.6764%`。
该分子仍成立，但分母须在 M510 exact decoder trace 后重建。即使暂按旧分母把
低带宽 K1 的 `4.764209x` 全替换进去，理想 Amdahl sensitivity 也只有约
`1.05569x`；FC2 无限快的上限约 `1.07154x`。因此论文的主指标必须是：

- equal-throughput `area` 与 `sequential cells`；
- `throughput/mm²`；
- `energy/completed token`；
- shared Acc24 state 相对 K1x8 replicated state 的 bit/macro 成本。

严禁把 `4.764209x` 写成 equal-resource 或 full-network speedup。

### 1.2 物理准入门

M496 三点必须全部达到：

- 3 ns setup/hold 与五类约束 clean；
- identical reported port count；
- K8/K1 area `<=1.25x`，冻结局部周期 `>=3.0x`，throughput/area
  `>=2.4x`；
- K8/K1x8 equal-bandwidth throughput `>=0.98x`；
- K8/K1x8 area 与 sequential cells 均 `<=0.50x`，throughput/area
  `>=2.0x`。

过门后才做三个 elaboration point 的 Formality、matched SAIF/PTPX，以及
八个公共 weight bank 与 Acc24 state 的宏收费。PTPX 目标是 annotation
`>=95%`，K8 energy/token `<=0.70x K1x8`。

### 1.3 对顶会开源 artifact 的实际借鉴

- [FEATHER](https://github.com/maeri-project/FEATHER) 的可迁移做法不是再造
  reorder 网络，而是“两级验证”：功能/周期 reference miter 与同一 top 的
  多配置 ASIC 报告分开。M495/M496 正按这个方式组织 K1/K8/K1x8。
- [Prosperity](https://github.com/dubcyfor3/Prosperity) 的可迁移做法是把
  full-workload cycle、bit-vs-product ablation、CACTI buffer 与 DRAM energy
  放在同一框架。M472 的 `2.459487x` 只保留为官方 simulator 的
  product-vs-bit 外部对标，不冒充本项目 RTL。
- [SNE](https://github.com/pulp-platform/sne) 的可迁移做法是 standalone RTL
  与高层稀疏卷积模型成对交付。项目现有 C2/FC2 也应维持 full-trace simulator
  与定向 VCS 分层，而不是在 VCS 中强跑数亿周期后把 simulator 口径混掉。

这些借鉴强化的是证据方法，不授权重复已有 prior art 的第四个 engine。

## 2. 条件候选：dynamic-BN 16/24-bit raw replay

M502 的 analytic opportunity 有足够大的流量窗，但还不是性能：

| 指标 | Q24 strong fused | 16/24 candidate | 当前身份 |
|---|---:|---:|---|
| useful raw write+read traffic | 2.62656 GB | 约 1.815 GB | analytic，未计 padding/metadata |
| traffic opportunity | — | `1.446701x` | analytic |
| 512-bit、32-lane local schedule | — | `1.446835x` | analytic，consumer 未物理化 |
| envelope sensitivity | — | 约 `1.0209x` | Amdahl replacement，不是系统仿真 |

第一版若获准只能是 per-phase 静态 `{16,24}` mode、固定 512-bit bus、32-lane
signed replay、cross-beat carry、tail valid mask 与任意 backpressure；禁止通用
14--18-bit runtime barrel packer。

RTL 前硬门保持不变：冻结 activation/weight scale、binary point、bias、RNE/
saturation；24 phase analytic fit 且 overflow=0；生成 address-timed 1R1W/DRAM
trace；16/24 traffic `>=1.35x`、local schedule `>=1.20x`。RTL 后还需 VCS
0 mismatch、3 ns pack/unpack/control `<=15,000 um²`、matched logic+memory
净 raw-path energy 降低 `>=20%`。

它只能作为 dynamic-BN memory 支撑机制；CICC BWAC、Stripes、Loom 和 Bit
Fusion 已覆盖位宽压缩的大部分独立新颖性空间。

## 4. 为什么当前不做全 120-record VCS

M216 的 120-record full trace 含 `5.58M` token、`143.895M` event，K1/K8
frontend 模型分别约 `429.7M/90.2M` cycles。把数亿周期硬塞进 RTL 仿真并不能
替代高层全 workload cycle model，且会挤占 VCS/DC 收口窗口。

采用两级证据：

1. full trace 在 exact payload-bound cycle simulator 中统计全部事件、控制和
   aggregate；
2. RTL 用 directed、tail、stall、reset、protocol attack、request/response multiset
   与 recurrence calibration 证明模型语义；
3. M495 三个 elaboration point 再用 DC/Formality/PTPX 证明物理实现。

论文必须明确两级边界，不能把 simulator 叫 RTL cycle，也不能把 directed VCS
叫 full trace replay。

## 5. 收口关键路径

1. 远端 A800 当前训练结束后，先抓 M510 四层 `ConvTranspose2d` exact binary
   index trace，重建完整 envelope，并对 EPD 做 A0/A1 同资源 fast-kill。
2. 共享机资源门清空后，执行 M507 一次快杀；完成后立即独立 receipt hammer。
3. 在满足更严格的 M496 64/128/32 GiB 三样本门后，执行唯一一次三点 DC；不得
   降门槛、换目录或混用旧点。
4. M496 过门则依次做 Formality、matched SAIF/PTPX、公共 SRAM/macro；失败则
   FC2 只保留已有局部 RTL，不进入主物理贡献。
5. 同一 GPU 空窗执行 BN exact integer/raw/address capture；未过门不写
   M502 RTL。
6. C1/C2/C3/A1 收到同一 28 nm、3 ns、公共 SRAM/DRAM 能量和 H67 population；
   补至少三条 held-out DSEC sequence。
7. 最后只保留 2--3 个论文贡献，并进行 receipt-blind DATE/BP 评审。BP 目标要求
   novelty、validation、reproducibility 同时 strong accept；不能靠贡献数量达成。

## 6. 当前可诚实对外的状态

- 硬件创新可以组织成 DATE 投稿，但当前证据仍是 Borderline Reject，不是 BP-ready。
- 正向核心是 C2/FC2 的 signed-source shared-state execution；C1/C3/A1 是层级
  协同和支撑机制，不应各自包装成独立 headline。
- 当前最大的口径 P0 是补齐四层 decoder；在这之后才是 energy/token、
  throughput/mm²、宏收费和多序列。新的局部 2--5x opportunity 数字仍不能冒充
  系统或 RTL 结果。
