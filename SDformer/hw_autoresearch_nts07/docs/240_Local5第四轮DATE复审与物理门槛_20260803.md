# Local5第四轮DATE复审与物理门槛

日期：2026-08-03

## 1. 复审结论

第四轮独立审稿子代理只检查本机同步存储RTL、SVA、真实100组日志和中文报告，不引用远端Claude。评分为：

| 维度 | 评分 |
|---|---:|
| 新颖性 | 3.3 / 5 |
| 完整度 | 3.8 / 5 |
| 验证可信度 | 4.3 / 5 |
| 实验充分性 | 3.8 / 5 |
| 公平性 | 4.2 / 5 |
| 总体 | 3.6 / 5，Borderline / Weak Accept边缘 |

审稿结论是：第三轮最高优先级已在RTL memory-contract范围内补齐，但未补齐foundry SRAM宏与物理PPA。`1.449x/1.419x`在当前post-score aggregate周期口径下公平，不能写成典型window加速。

## 2. 审稿人认可的证据

1. 四配置共享relation frontier、word skipper、term builder、权重和五个Acc bank；
2. 同一延迟下memory-wait完全相同，主要变量只有Acc bank映射与Linear5 replay；
3. 同步SRAM L1/L2、真实T450、尾延迟和36万次Acc32比较均通过；
4. 第三轮预设的`>=1.3x`aggregate门槛在L1/L2下均满足。

## 3. 审稿修正

### 3.1 存储端口命名

RTL具有逻辑写地址/数据和逻辑读地址/数据通道，但SVA禁止同拍读写，build/read相序互斥。因此准确说法是：

> 目标映射单端口1RW宏的相序互斥逻辑双通道合同。

不能声称已经自动绑定真1R1W双端口宏，也不能声称Yosys `$mem_v2`等价于目标SRAM。

### 3.2 延迟命名

`READ_LATENCY=1/2`描述SRAM请求到数据有效的延迟；六路数据之后还经过一拍descriptor保持寄存器，所以下游可见延迟为`L+1`拍。日志中的memory-wait正好为：

- L1：`18,854 = 9,427 x 2`；
- L2：`28,281 = 9,427 x 3`。

### 3.3 Aggregate与典型group

| 延迟 | aggregate | per-group mean | p50 | p95 | p99 |
|---:|---:|---:|---:|---:|---:|
| L1 | 1.449x | 1.197x | 1.004x | 1.755x | 1.840x |
| L2 | 1.419x | 1.178x | 1.004x | 1.714x | 1.835x |

aggregate适合表示整批workload吞吐；p50接近1是45个空group导致。论文必须同时报告两套口径。

## 4. 当前最严重问题

六个关系bank、五个Acc bank和权重存储尚未绑定目标SRAM宏，真实面积、频率、布线、功耗与EDP未知。真实回放只使用`OUT_DIM=2`，不能外推部署输出通道的乘法器与Acc宏压力。

## 5. 唯一最高优先级

完成宏绑定、等约束的TCFM5/Linear5物理对照：

1. 相同PDK、SDC和floorplan；
2. 同规格1RW relation/Acc/weight macro wrapper；
3. 相同真实活动文件；
4. 报告面积、Fmax、动态/漏电功耗、吞吐/mm2和EDP；
5. 在物理结果仍为正后，才把Local5提升为独立DATE硬件主线。

本机暂时没有目标SRAM compiler和DC/PTPX，因此先做Nangate45标准单元映射的OpenROAD可路由性代理。该代理只用于暴露地址网、取模、扇出和拥塞问题，不能替代上述最高优先级。
