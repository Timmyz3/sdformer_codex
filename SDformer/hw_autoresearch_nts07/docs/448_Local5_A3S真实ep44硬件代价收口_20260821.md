A3S 还新增每组 225 pixel 的 2-bit direction field，即 450 bit/group。本审计未计入方向场生成逻辑、存储访问和控制，因此表中代价仍偏向 A3S。

## 5. 为什么 destination update 不变而 product 增加

A3S 对四个方向 lane 施加 `+delta/-delta`。它不删除 relation，也不改变 K；因此非零 destination delivery 数没有下降。相反，同一 source 原先可共享的 gate code 被拆成更多类，source-owned 后端必须为新增 gate class 生成额外 product。该结果直接作用于现行 `source-owned -> TCFM5` 执行对象，不是对弱 destination-local 实现的比较。

## 6. 后续边界

1. 让冻结的五轮训练自然完成，不中止、不改超参。
2. 只在最终 checkpoint 上跑 valid825，判断准确率是否恢复；首轮 validation loss `1.605619` 已明显弱于父 Local5 后期约 `0.96-1.08`，目前无晋级信号。
3. 即使准确率提高，也不把 A3S 写成加速机制；需要同时披露 `+31.1%` 到 `+51.3%` product term 和 450 bit/group 新状态。
4. 不实现 A3S RTL，不修改 Local5 封存 `1.6957x/1.770x`，不把本报告数字写进 `docs/359` 主表。

该负结果使 Local5 主线继续保持为一条数据流：Query-Silent、inverse-stencil/FCSR、source-owned gate quotient 与 TCFM5；A3S 不构成第五个模块名或新的 DATE 贡献。
