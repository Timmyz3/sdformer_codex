# DATE 第二十六轮：联合反压实测与双商架构收敛

> **第八轮复评纠错：** 本文初版把 `(source,lane,gate)` 误写为 product
> 计算下界。`source` 不影响 `gate×W[lane,:]` 的数值；真正的 value key 是
> `(lane,gate,weight_epoch)`。下文已撤销“product下界”和“双下界”主张，
> 改为 value quotient 与 destination quotient 两级精确数据流。

## 1. 本轮回答的问题

第七轮独立 DATE 审稿给出：

| 维度 | 分数 |
|---|---:|
| 创新性 | 3.3/5 |
| 架构完整性 | 4.0/5 |
| 证据充分性 | 3.5/5 |
| 总分 | 3.5/5 |

推荐仍为 **Weak Reject**。核心批评是：

1. SQEF 仍可能被看作 relation transpose、CSE/multicast 和 graph banking 的
   工程组合；
2. Affine/Linear 周期来自 TB 分析计数，不是实际后端反压；
3. Role-Sharded 仍是模型；
4. 没有证明联合架构产生超出局部数字相加的约束。

本轮针对第 2、3、4 项做了实质整改。

## 2. 四后端共享同一完整 producer

`qfit_local5_projection_tile` 现在支持四个参数化后端：

```text
BACKEND_KIND=0  TCFM-5
BACKEND_KIND=1  Affine-4 exact replay
BACKEND_KIND=2  Linear-5 exact replay
BACKEND_KIND=3  Role-Sharded partial Acc
```

四次运行完全复用：

```text
Local5 integer score/Shiftmax
-> FCSR-RX relation transpose
-> source multicast term builder
-> selected projection backend
```

输入 Q/K、invalid-candidate mask、权重、term 顺序和最终整数金参考相同。
所有后端均完成：

- 36 个 source-complete descriptor；
- 1494 个 source-quotient product term；
- 2335 次 destination update；
- 全部 `plane/y/x/out` Acc 逐项一致；
- projection close、RMW drain 和最终 readback。

这不再是离线周期公式，而是四个实际 RTL 后端分别对上游施加 ready/valid
反压后的端到端架构切片。

## 3. 全 tile 联合结果

### 3.1 实际反压周期

`projection_busy` 包含 Acc clear、producer 反压、term delivery 和 close/drain，
不包含最终 readback。

| 后端 | tile周期 | relation stall | 相对TCFM | Acc槽 | 最终归约 |
|---|---:|---:|---:|---:|---|
| TCFM-5 | 1603 | 347 | 1.000x | 450 | 无 |
| Role-Sharded | 1603 | 347 | 1.000x | 2250 | 五路partial |
| Affine-4 | 1687 | 363 | 1.052x | 480 | 无 |
| Linear-5 | 1702 | 431 | 1.062x | 450 | 无 |

该表揭示了联合数据流效应：

- Affine-4 的 replay 不只增加 projection 周期，也将 relation stall 从
  347 增至 363；
- Linear-5 的动态冲突使 relation stall 增至 431；
- TCFM-5 与 Role-Sharded 都不向 producer 注入冲突 replay；
- Role-Sharded 以五倍 Acc 状态和最终五路归约换取与 TCFM-5 相同的前向
  吞吐；
- TCFM-5 用拓扑编译在不复制 destination state 的前提下达到同样吞吐。

因此 C3 的价值不应再写成“相对 Linear-5 快 6%”，而应写成：

> 在 source-quotient multicast 产生多目的同拍提交之后，TCFM-5 同时避免
> 动态 replay 的前向反压和 Role-Sharded 的 partial-state 复制/最终归约。

### 3.2 统一开放结构审计

四者使用同一 Yosys 展平流程。经过两轮公平性修复，四个后端均只有 4 个
product 乘法器，且无运行时 `$div/$mod`。

| 后端 | cells | wire bits | memory | mul | mux |
|---|---:|---:|---:|---:|---:|
| TCFM-5 | 811 | 15355 | 6 | 4 | 318 |
| Affine-4 | 680 | 13989 | 5 | 4 | 248 |
| Linear-5 | 1292 | 16499 | 6 | 4 | 551 |
| Role-Sharded | 443 | 14328 | 6 | 4 | 151 |

Role-Sharded cells 较少不代表面积更小。Yosys 的 memory cell 数不体现深度：

```text
TCFM-5:      5 × 90 × 128-bit Acc
Role-Sharded:5 × 450 × 128-bit partial Acc
```

Role-Sharded 的 Acc 数据位为 288000 bit，是 TCFM-5 的 57600 bit 的 5 倍。
这也是为什么开放 cells 绝不能替代目标 SRAM PPA。

## 4. 两次公平性修复

### 4.1 周期 provenance

旧统一报告在 Python 中硬编码 1494/1579/1598。现在：

1. 四个后端的实际日志由同一个端到端 runner 生成；
2. `report_qfit_local5_projection_tile.py` 解析四份日志；
3. 生成 `cycle_evidence.json`；
4. 结构比较脚本只读取该 JSON，不再包含周期常数。

旧的 product-delivery 分析计数仍保留用于分账，但不再冒充后端 RTL 实测。

### 4.2 Role-Sharded 乘法器公平性

代理初版的 lane 选择循环被 Yosys 展开成 136 个乘法器。第一次修复为动态
权重索引后仍有 12 个，其中 8 个来自运行时坐标乘法。

最终版本：

- `weight_q[term_lane][out]` 只保留 4 个 product 乘法器；
- plane/row 地址改成编译期常量基址 LUT；
- 展平网表为 4 个乘法器、零 `$div/$mod`。

该过程说明开放结构审计的用途是发现不公平 RTL，不是生成论文面积数字。

## 5. TCFM非法term副作用整改

ASIC 独立审阅发现：旧 TCFM-5 对非法 term 会在同拍先发 Acc update，再在
时序块中置 `protocol_error`。Affine/Linear 则会门控更新，协议不一致。

当前 TCFM-5 显式定义：

```text
term_fire
term_contract_valid
term_boundary_error
term_commit = term_fire
            && term_contract_valid
            && !term_boundary_error
```

所有 Acc `update_valid` 只由 `term_commit` 触发。新增 SVA：

- 非法 term 同拍不得产生任何 bank update；
- 下一拍必须报告 protocol error；
- product/update 计数必须保持；
- DONE 必须满足所有 bank idle。

修复后 source multicast/TCFM 全回归通过。

## 6. 架构主张进一步收敛：双商精确执行

第八轮复评指出，初版所谓 product 下界不成立。若两个 term 的 source 不同，
但 lane、gate 和 weight epoch 相同，则其 product 对任意权重都相同。因此
架构必须分离两个不同的等价关系：

```text
value quotient key:
  (lane, gate, weight_epoch)
  -> 决定 gate × W 的数值，可跨 source 复用

destination quotient key:
  (source, lane, gate)
  -> 决定 destination set、生命周期和提交顺序
```

### 6.1 Value quotient：跨source product复用

现有 Source-Quotient 已经按 destination quotient 生成 term，但每个 source
term 仍计算一次 product。严格强基线应增加精确 gate-product dictionary：

```text
lookup (lane, gate, weight_epoch)
  hit: 复用已有 product vector
  miss: 计算 gate × W，并写入dictionary
```

该 dictionary 不改变 destination schedule，不允许近似匹配；权重切换必须
更新 epoch 或清空目录。它与 Prosperity 的 exact reuse 思想相关，但 key 和
生命周期来自 Shiftmax gate 与 layer weight epoch。

初版以下说法全部撤销：

- “每个 `(source,lane,gate)` 至少计算一次”；
- “1494 是全局最少 product 数”；
- “SQEF 达到 product 计算下界”。

1494 只能解释为 destination quotient term 数；它相对 2335 条 edge delivery
减少了命令与 source-local 重复计算，但还可以被跨 source value memo 继续
减少。

### 6.2 Bank下界

一个内点 source 的五个 destination 在同一 quotient term 中可能同时有效，
形成 K5 写冲突团。若要求：

- 每 bank 每拍最多一个 update；
- 不 replay；
- 不复制 partial state 后归约；

则至少需要五个 bank。TCFM-5 使用五色仿射映射达到该下界。

### 6.3 联合点

双商架构把“product 数值复用”和“destination 多播调度”分开：

```text
gate-product value quotient
  -> 跨source减少product计算/乘法活动
source/destination quotient
  -> 将同source同gate edge合并为destination set
  -> 产生多destination同拍提交压力
topology-compiled exact commit
  -> 不 replay、不复制状态地吸收该压力
```

FCSR-RX 则保证 query-major gate 流在有限状态中转成 source-complete term，
不物化完整 CSR，也不恢复逐 edge 中间表示。

论文应写成 **一个联合架构贡献、value/schedule 两级等价关系、一个受限
bank 下界**，而不是三项“首次”或两个无条件下界。

## 7. 仍未解决的拒稿风险

1. W6 仍是 `3×6×2` 定向向量，不是 full-resolution post-G0；
2. `(lane,gate)` gate-product dictionary 尚未完成容量/hit/PPA评估；
3. bank 下界允许 replay 或复制归约后不成立；
4. Role-Sharded 的 readback 归约能量尚未进入 SAIF；
5. Affine-4 可能在目标 SRAM compiler 下取得更优 EDP；
6. 当前机器没有 DC，不能将 Yosys 数字写成 ASIC PPA；
7. full encoder 与 Motion 统一仍是系统边界，不是本轮已验证贡献。

## 9. 本轮判断

本轮没有把 DATE 评分“包装”到 accept，但关闭了三个可被直接拒稿的证据
问题：

- 强基线周期由真实后端反压产生，不再硬编码；
- Role-Sharded 从模型升级为同 producer、同算术 RTL；
- 四后端计算资源和地址生成已统一到 4 个乘法器、零除法/取模。

最有价值的新结论是：

> TCFM-5 的优势不是单纯比 Linear-5 少 99 个周期，而是在与
> Role-Sharded 相同吞吐下只保存一份 destination state，同时又不像
> Affine/Linear 那样把 replay 反压传播回 FCSR producer。

这使 SQEF 更接近可辩护的架构工作，但是否达到 DATE accept 仍由 post-G0
真实负载与同 SRAM PPA 决定。
