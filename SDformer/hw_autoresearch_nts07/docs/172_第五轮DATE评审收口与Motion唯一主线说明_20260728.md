# 第五轮 DATE 评审收口与 Motion 唯一主线说明

## 1. 本轮结论

第五轮独立 DATE 审稿结论仍为：

| 项目 | 结果 |
|---|---:|
| Recommendation | Reject |
| 完整度 | 3/5 |
| 创新性 | 2/5 |
| 证据完整度 | 2/5 |
| 目标潜力 | 3/5 |

因此，当前不能宣称硬件部分已经达到 DATE 接收标准，也不能宣称 ET3 已经带来性能收益。

本轮可以冻结的判断是：

1. Motion/H67 是当前唯一可以继续作为硬件论文主线的候选。
2. Local5 只能保留为影子线，等待 post-G0、全分辨率、RTL-exact ordered trace 的真实 kill test。
3. ET3 已经从概念变成可综合读取、带有限资源和 exact fallback 的 RTL 原型，但 synthetic 对照是负结果，尚不能列为论文主贡献。
4. 第五轮仍发现两个证据链 P0，下一轮必须先关闭，不能直接使用 GPU 生成“看似 post-G0”的结果。

这里的“Motion 唯一主线”表示当前证据成熟度排序，不表示 Motion 硬件已经可以投稿或可以直接据此做最终 DC 主表。

这五轮说明：

- RTL 协议完整度确实提高，已不再是只处理理想输入的玩具目录。

- 当前主要短板已经从“RTL 会不会错”转移到“workload 证据是否真实”和“架构是否在公平基线下有净收益”。

## 3. 本阶段真正完成的硬件工作

### 3.1 ET3 exact SET/MULTISET 切片

当前 ET3 数据流为：

```text
Motion SET / Local5 MULTISET source
        |
        v
有限 typed-key directory
        |
        +-- 命中且 segment 未满：追加 destination
        +-- 命中但 segment 已满：分配新 segment
        +-- directory 满：进入 exact fallback FIFO
        +-- directory 与 fallback 均满：partial drain 后恢复
        v
segmented typed term stream
        v
原生 multiplicity executor
        v
整数 accumulator
```

typed key 为：

```text
{mode, group_tag, gate_code, lane_id, multiplicity}
```

- Motion 为严格 SET：`multiplicity=1`。
- Local5 为有界 MULTISET：`multiplicity=1..5`。
- `group_tag` 禁止跨窗口/head 合并。
- fallback 只损失复用机会，不改变整数结果。

### 3.2 公平 native-m 基线

已实现不做跨 destination 聚合的 native-m queue：

- 与 ET3 共用同一个 multiplicity executor。
- Local5 不被错误展开成 SET。
- 每个 destination item 独立读取一次 weight、计算一次 product。
- FIFO 满且同拍 pop 时允许 push，避免人为插入 bubble。
- baseline 已接入动态 SVA 和 Verilator functional runner。

## 4. 第五轮前已修正的周期模型

旧模型错误地对同一 chunk 使用：

```text
max(collect(chunk_i), emit(chunk_i))
```

这允许 chunk 尚未收集完成就发射自身。新模型只允许：

```text
emit(chunk_i) || collect(chunk_i+1)
```

并显式计算两个 context 的占用、首块填充和末块排空。

同一 synthetic ordered trace 的修正结果为：

| 指标 | 结果 | 证据等级 |
|---|---:|---|
| source item | 11 | [synthetic] |
| unlimited ideal term | 6 | [synthetic] |
| online finite ET3 term | 8 | [synthetic] |
| online reuse retention | 60% | [模型] |
| native-m 周期 | 16 | [参数化因果模型] |
| ET3 single-context 周期 | 31 | [参数化因果模型] |
| ET3 dual-context 周期 | 29 | [参数化因果模型] |

这是一个明确的负结果：

```text
ET3 dual-context 29 cycles > native-m 16 cycles
```

它证明 product/weight-read 数量下降不能直接推导周期加速。该结果不是 Local5 workload 结果，也不是 RTL 实测 cycle；但在真实 ordered trace 证明相反结果前，ET3 不能晋级主贡献。

## 5. 第五轮新发现的两个 P0

### 5.1 P0-A：Provenance 可以被伪造

当前 replay 会检查：

- `config_sha256`、`checkpoint_sha256`、`cohort_sha256` 是否长得像 64 位十六进制。
- manifest 自报的 full-resolution、sampling 和 software contract。
- payload 与 group item hash。

但它没有：

1. 重新读取实际 config 文件并计算 hash。
2. 重新读取 checkpoint 并计算 hash。
3. 重新读取 cohort manifest 并计算 hash。
4. 从实际 config 重新推导 software contract。

第五轮审稿人复制 synthetic payload，只修改标签、填入任意合法格式伪 hash，并自报 full-resolution/Local5 contract，`load_trace()` 仍接受为 `post_g0`。

所以当前门禁只能防止字段缺失，不能防止“改标签升级证据”。在修复前，任何 post-G0 性能主张均不允许进入论文主表。

### 5.2 P0-B：Ordered sink 不是 producer handshake trace

当前 sink 在完整 tensor 计算结束后，按：

```text
destination -> candidate -> lane
```

使用 `torch.nonzero` 重建一个确定性的 canonical 顺序。

这能证明导出可重复，但不能证明它等于未来硬件 producer 的真实 source handshake 顺序。有限目录的 retention、fallback 和 partial drain 都与顺序有关，因此 canonical tensor traversal 不能自动被称为真实 ordered trace。

必须冻结 producer 调度合同，并逐 item 证明：

```text
software sink sequence == producer valid/ready accepted sequence
```

### 5.3 P1：满队列同拍 pop/push 缺显式覆盖

baseline 的组合逻辑支持：

```text
fifo_full && pop && push
```

但现有 TB 的 source task 含空拍，没有明确证明该路径实际命中。需要增加定向 cover/assert；这不是已发现的功能错误，但属于覆盖缺口。

## 6. 为什么 Motion 是当前唯一硬件主线

### 6.1 软件算法已经形成冻结候选

H67 Motion 的 full30 + valid825 已完成：

| 指标 | H67 epoch19 |
|---|---:|
| AEE | 1.4671 |
| AAE | 9.4155 |
| total spikes | 26.3898G |

相对 NB0：

- AEE 改善约 1.35%。
- spikes 下降约 40.1%。

H67 epoch4 还提供 AEE 1.4896、spikes 24.2416G 的效率 Pareto 点。

这使 Motion 同时具备精度、稀疏性和已冻结 checkpoint 候选。Local5 即使算法精度有竞争力，当前还没有与硬件合同一致的全分辨率部署证据。

### 6.2 Motion 有真实 ordered workload 证据

H67 profile100 已给出：

| 指标 | 数值 | 等级 |
|---|---:|---|
| token K-zero | 约 88.7% | [prof] |
| pair empty | 约 74% | [prof] |
| final-gate product work 减少 | 约 82.5% | [prof] |
| S=4 overflow | 约 0.014% | [prof] |

Motion 还已有 ordered profile、DCTF trace、四 stage replay 和等 lane 周期对照。虽然尚缺目标工艺 PPA，但这些数据已经能够驱动真实有限容量设计。

Local5 当前只有：

- pre-G0 离线全局 unique 上界。
- synthetic ordered 协议向量。
- 尚未标定的参数化周期模型。

两者不是同一证据等级。

### 6.3 Motion 的 RTL 链路成熟度更高

Motion 已覆盖的硬件链路包括：

```text
H67 score / Motion-XOR
    -> SCS-Shiftmax
    -> gate/term 表示
    -> NMF/DCTF projection
    -> 真实 H67 stage trace/replay
```

Local5 当前已补出 MULTISET executor 和 ET3 原型，但硬件输入仍从 MFEP 后开始。Local5 的：

```text
local stencil score
    -> multiplicity formation
    -> Shiftmax/gate code
    -> ordered producer
    -> ET3
```

尚未形成同一条端到端 RTL/trace 合同。

### 6.4 Local5 的全分辨率配置尚非 RTL-exact

当前检查到的全分辨率 Local5 ft30 配置中：

```text
hardware_quant_enabled = false
```

因此它不能直接生成可用于 RTL bit-exact 性能主张的 post-G0 trace。仓库中虽有启用硬件量化和 RTL Shiftmax 的 deploy 配置，但还需要把：

- full-resolution 配置；
- 冻结 checkpoint；
- cohort；
- dyadic/RTL Shiftmax 数值合同；
- producer 顺序合同；

绑定成同一可重放证据包。

### 6.5 Local5/ET3 当前没有性能胜证

Local5 pre-G0 离线上界很大：

| 指标 | 数值 |
|---|---:|
| exact-or-LIST4 coverage | 94.6010% |
| ideal MPET term | 13,732,741 |
| per-destination term | 153,748,435 |
| fanout mean/p95/max | 11.20 / 45 / 110 |
| native multiplicity command 上界减少 | 18.3810% |
| ideal product compute 上界减少 | 92.7098% |

但这些是全局离线 unique 或 pre-G0 上界。真实有限目录会受到 source 顺序、容量、segment、fallback、SRAM latency 和 backpressure 影响。

当前唯一同 trace 的因果周期结果还是：

```text
native-m 16 < ET3 dual-context 29
```

所以 Local5 目前是“复用潜力更大”，不是“硬件已经更快”。

### 6.6 双主线会污染论文证据边界

若现在把 Motion 与 Local5 同时称为主线，会出现：

1. Motion 使用 post-profile ordered trace，Local5 使用 pre-G0/global-unique 上界。
2. Motion 有较完整 RTL 链，Local5 只有后半段 ET3 切片。
3. 两条线的软件部署量化合同不一致。
4. 同一张 PPA/周期表混入不同证据等级。

这会使审稿人无法判断收益来自架构、算法，还是统计口径。现阶段只保留 Motion 为主线，是证据纪律要求，不是因为 Local5 永久不适合硬件。

## 7. Motion 主线也还没有达到 DATE 接收标准

Motion 当前仍缺：

1. 同 SDC、同 SRAM macro 规则下的 Central、Independent、DCTF 公平 DC/STA。
2. 真实 trace 驱动的 SAIF 功耗和 EDP。
3. 多 sample、多 window 的 mean/p95/p99 cycle、stall 和 bandwidth。
4. SRAM latency、final backpressure 和片上存储层次闭环。
5. full encoder 边界下 attention/projection 占比及 Amdahl 结果。
6. 与 Bishop、Prosperity、Phi、FireFly-T、FLAT/LoAS 等工作的同口径机制差分。
7. 能将创新性从 2/5 提高到至少 3/5 的架构主张和对应消融。

因此准确表述应为：

> Motion 是唯一具备继续完成 DATE 级证据闭环条件的硬件主线，但当前硬件稿仍是 Reject。

## 8. Local5 何时可以挑战主线

Local5 只有同时满足以下条件，才允许重新讨论切换主线：

1. 生成不可伪造 provenance 的 post-G0、full-resolution、RTL-exact trace。
2. sink 顺序与冻结 producer handshake 顺序逐 item 等价。
3. 在线有限目录 reuse retention 不低于 70%。
4. 相对公平 native-m，在同存储 bit budget 下净周期或 key traffic 改善不低于 15%。
5. 随机反压、SRAM latency 和真实尺寸下保持 bit-exact。
6. DC/STA/SAIF 后 EDP 仍有净收益，而不是只减少 product count。

若任一核心门槛失败：

- 淘汰 ET3 聚合路径；
- Local5 可保留原生 native-m executor；
- 论文硬件主线继续使用 Motion。

## 9. 下一阶段唯一正确顺序

第五轮后不应继续堆新模块。下一轮顺序应为：

1. 关闭 provenance 伪造 P0：读取实际文件、重算 hash、由 config 推导合同。
2. 冻结 producer source-item 调度合同，并证明 sink/handshake 逐项一致。
3. 补 baseline 满队列同拍 pop/push 定向覆盖。
4. GPU 空闲后再生成 Local5 post-G0 full-resolution trace。
5. 执行 Local5 kill test；不达门槛立即淘汰 ET3。
6. 无论 Local5 是否晋级，Motion 主线进入同约束 DC/STA/SAIF。

在第 1、2 项完成前，占用 GPU 导出 Local5 trace 没有论文价值，因为证据仍可被第五轮审稿意见直接否决。
