# ISCAS 2027 C1/C2/C3 统一叙事与准入表（2026-09-01）

本文档冻结投稿叙事，不修改 `docs/359`，也不把组件结果扩张为全系统结果。主稿采用两个架构贡献（C1、C2+TSBG）与一个服务覆盖闭环（C3）；TSBG 只能嵌入 C2，C3、decoder/RQTB 不另立同等级性能贡献。

## 一句话主线

面向 binary-event optical-flow workload 与 polarity-bearing typed-source/Acc24 下游协议，设计一套共享执行底座，并分别解决容量受限卷积中的 product capture、FC 中的并发与权重交付、以及 Fixed-T10 ATLIF 的精确时序服务；所有性能、面积和能量数字均按组件边界、同资源基线和证据类型分列。

四页正文采用 `execution islands` 而不是已集成 `system accelerator` 的措辞。算法侧不另立贡献，只提供三条硬件可消费的不变量：有限驻留期内的重复卷积乘积映射到 C1；跨 token 相同 weight-row identity 但独立 sign/destination/Acc24 context 映射到 C2+TSBG；固定 T10 的 state/commit order 映射到 C3。Attention、decoder 和已判弱的稀疏线仅维持 workload/coverage 身份，不增加贡献 bullet。

## 两个架构贡献与一个覆盖闭环

### C1：capacity-constrained exact product capture

- 对象差：在 240 KiB、单口 parent scratch、signed residual 和 dead-write 约束下捕获 product reuse，不把官方 Prosperity 的理想机会冒充本项目实现。
- final ep34 十样本、四层 bottleneck Conv3x3、51.84 M source-row 的同账本结果：`382,848,700` vs strongest-zero `648,741,051` cycles，即 **1.694510x**，modeled time **-40.99%**；相对 same-coordinate bit 为 **1.688968x**。
- 理想 concurrent-1R1W ceiling 仅作机会：`341,057,992` cycles；可落地单口点相对该不可物理化 ceiling 的 cycle tax 为 **12.2533%**。该税值定义为 `382,848,700 / 341,057,992 - 1`，不另造“理想收益保留率”。
- 物理锚点：28 nm、3.0 ns、9 个 128x128 1RW SRAM、面积 **166,514.312 um2**。M1740/M1742 已正式准入：Formality 为 16,549/16,549 compare points PASS；PrimeTime setup **+0.027871 ns**、hold **+0.001827 ns**、TNS 0、violating paths 0。该结果仍是 pre-layout、ideal-clock、ZeroWireload 组件证据。
- 能量锚点：M1789 独立打铁 `99/100, P0/P1/P2=0/0/0`。完整 mapped C1 top（含 9 个 SRAM Liberty leaf）在 ep34-density-conditioned 定向 `64-row / 253-cycle / 759 ns` 窗口下为 **29.0763016 mW**、**22.0689129144 nJ/window**；internal/switching/leakage 为 `26.660183/1.74465036/0.671468437 mW`。`u_parent_scratch` 层次为 **10.5071545 mW / 36.1%**。该点为 stdcell `TT 0.9 V 25 C` + SRAM `SSG 0.9 V 125 C` 的 mixed-corner 组件估计，ideal clock、ZeroWireload、无 SPEF；不是 energy/frame、system energy、single-corner signoff 或 silicon measurement。
- 边界：1.694510x 是 local same-ledger cycle model，不是 RTL cycle、full network 或 system speedup；pre-layout timing 不是 post-layout signoff。
- 模型到 RTL 校准：M2037 successor VCS 经 M2038 独立复核为 **100/100，P0/P1/P2=0/0/0**。它在 M1590 ledger 的首个真实 ep34 64-row support-mask tile 上逐项对齐 `issue=196`、`parent_edges=58`、`dead_write=31`、`macro_read/write=54/33`、`forward=4`、`deadline_hold=6`、`stall=14`、`commit/completion=64/64`；96-lane 数值 payload 为确定性 synthetic signed12 且 prior psum 为零。该证据校准 event-count/功能，不把 1.694510x 升为 RTL speedup。
- 正文已明确微架构对象：64 行双缓冲 mask directory 只允许选择更早的 exact-subset parent，发行 XOR residual 后重构 96-lane signed product row；population-count 稳定次序、live-parent bitmap、最早父边 lookahead、两个 reserved response slot、forwarding 和 atomic psum/row completion 共同使得 single-1RW 限制成为可执行合同，而非普通 cache 换名。

### C2：typed-signed K8 shared execution fabric with TSBG delivery

- 基础织物：K8 对等带宽 K1x8 为 `1913/1945` cycles，即 **1.016728x**。注册公共故障修复后的 M1811/M1830 fresh matched DC 为 `130,822.775/585,534.972 um2`，即 **-77.6576%**；结合冻结周期，throughput/mm2 为 **4.550657x**。两轴 setup 最小 slack 为 `+0.0018/+0.0014 ns`；diagnostic hold 为 `-0.0190/-0.0177 ns`，因此 hold 尚未闭合。
- 正确写法必须把周期和面积效率放在同一句；禁止把 K8 对单 K1 的倍率写成稀疏收益。
- TSBG 定位：只复用 weight-row fetch，不误复用 typed-signed product；B4/B8 在多个独立 Acc24 context 前做 bundle broadcast。它是 C2 的 weight-delivery specialization，不是第四个贡献。
- TSBG 准入门：相对 ordinary persistent same-capacity row buffer，局部周期至少 **1.15x**；或者周期退化不超过 5% 且 weight bytes 至少降低 30%。B4/B8 的 Acc24/context/FIFO 显式下界分别为 1,216 B 和 2,432 B；matched logic-only ablation 已计 control/tag/stdcell state，但 SRAM 宏、能量和可执行生产周期未计价，仍不得称 full-design same-area speedup。
- 当前状态：ep34 40-sample capture 已生成并封存 11,040/11,040 FC frames，872,855,874 个非零 FC code 均为 `+/-1`。M1866 的同 I/O、同 cache-capacity CPU premodel 中，B4 相对 ordinary persistent LRU4 为 **2.533808x modeled cycles**，weight traffic 下降 **65.1978%**；这不是 RTL、mapped、同面积或系统倍率。M2018 公平 scheduler 已通过 source hammer；M2025 directed VCS 已由 M2026 独立复核为 **99/100，P0/P1/P2=0/0/0**，其 576->144 weight bundle 与 4608->1152 scalar-bank request 可作为 directed RTL 功能/请求削减证据。M2029 matched logic-only DC 经 M2030 独立复核为 **99/100，P0/P1/P2=0/0/0**：ordinary/TSBG 面积为 **249,710.452/249,739.810 um2**，TSBG 增量仅 **29.358 um2 / 0.0117568%**，两轴 3 ns setup 分别为 **+0.0264/+0.0688 ns**；两轴 diagnostic hold 均为 **-0.0164 ns**。production G48、精确 RTL 周期、SRAM macro、hold、power/energy 仍未闭合。
- B4 跨序列稳健性已收进正文的小表：`interlaken_01_a / thun_01_b / zurich_city_09_a / zurich_city_12_a` 的 CPU-modeled ratio 分别为 `2.544029x / 2.549910x / 2.525227x / 2.517177x`，weight-byte reduction 为 `65.4047% / 65.5268% / 65.0036% / 64.8738%`。该表只证明 CPU scheduling result 不由单一 sequence 驱动，不改变其非 RTL 边界。

### C3：exact Fixed-T10 ATLIF temporal-service coverage

- 作用：证明统一底座不只覆盖 Conv/FC，并提供网络需要的 Fixed-T10 ATLIF 精确时序服务。ep34 capture 中 ATLIF 输出均为 binary，不能据此宣称 analog-output workload。
- 现有物理锚点：**63,756.126 um2**；DC setup/hold **+0.000300/+0.034585 ns**；PT setup/hold **+0.000299/+0.030474 ns**；11,180 mapped compare points PASS；17 cycles/tile。
- 边界：当前无公平 speedup，不在摘要中制造倍率，也不与 C1/C2 并列为第三条性能创新；作用是 exact service、协议闭合和算子覆盖。

### ep34 部署算术的 valid825 精度绑定

- M2045 唯一 GPU successor 已以 canonical 目录原子发布，远端与本机双封均通过。独立 result hammer 为 **25/25 PASS，95/100，P0/P1/P2=0/2/3**；manifest SHA256 为 `bbe94c7b3079b10c298d56f9c8b8f25b3dd1e456922805603a582647d6c51a27`。
- 候选部署范围严格限于 12 个 block 的 hardware-order attention，以及 4 个 C1 Conv3x3 + 4 个 decoder ConvTranspose 权重的 dyadic-INT8 QDQ；其余算子保持 checkpoint precision。这不是 full-network INT8、SystemVerilog 等价、cycle/speedup/power/energy/PPA 证据。
- 同一 valid825 人口与聚合口径为 **825 frames / 18 sequences / 48,152,523 valid pixels**。AEE 为 `1.1995140134 -> 1.1973673040`，相对冻结 baseline 的 `delta=-0.0021467094`，通过 `candidate-baseline <= +0.02` 门。AAE / AAE-Benchmark / DSEC-Fl 变化为 `+0.0121673 / +0.0152556 / +0.0154745`。
- 历史 baseline 开启 TF32/cuDNN benchmark，candidate 禁用两者；因此只能写 **frozen-baseline-referenced accuracy-gate compatibility**，不得把负 AEE delta 归因为量化改善精度。

## 兼容性证据

- Decoder：作为 typed-source/Acc24 覆盖对象；D0 actual prefix 只报 diagnostic cycle model，8700-shard 完整 replay 未完成前不写 decoder-complete。
- RQTB/attention：attention 仅约 0.59% 旧 envelope，放在兼容性或能量消融，不当系统性能贡献。
- S2/CCBS16：本轮主稿默认排除。只有 paired 40-sample `delta AEE <= 0.02`、逐序列 `<= 0.03`、metadata `<= 2%`、同资源局部周期 `>= 1.15x` 且基线包含已准入 TSBG 时，才允许作为 C2 optional lossy mode；不得新增第四个 bullet。

## 收口顺序

1. C1 Formality + PT + public-port mapped VCS/SAIF/PTPX 已闭合；M2037/M2038 又闭合了首个真实 ep34 64-row tile 的模型到 RTL 事件校准。M1789 准入的能量只进 component table。SRAM datasheet 仍只作独立 alternative/sensitivity，不做 top-minus-macro，不得称 whole-chip 或 energy/frame。
2. TSBG 已完成 B2/B4/B8 真数据 screening、B4 无除法/取模公平 scheduler、directed VCS 与 ordinary-LRU4/B4 matched logic-only DC；M2030 已准入其 **0.0117568%** 逻辑面积税与两轴 setup PASS。它作为 C2 的 weight-delivery specialization 保留，CPU 2.533808x 仍只进模型消融。
3. M2045 valid825 精度绑定已通过独立审计并进入四页稿；decoder 长 replay 继续后台，不阻塞组件稿。
4. TSBG 过门才进入 C2；未过门则冻结 C1/C2/C3，不再开新机制。

## 禁止表述

- “全网/系统 1.69x”或“RTL 实测 1.69x”。
- “K8 稀疏加速 4.55x”；4.55x 是等带宽 throughput/mm2。
- “TSBG production RTL speedup”或“代表性功耗”；现阶段 production trace 只进入 CPU premodel，RTL 只覆盖 directed request/protocol，DC 只覆盖 matched logic schedule ablation。
- 将官方 Prosperity、理想 ceiling、组件周期或面积效率相乘。
- 将 pre-layout/ideal-clock/ZeroWireload 结果写成 post-layout、silicon 或 paper-PPA-ready。
- 将 M2045 的 `-0.002147` AEE 写成“量化导致精度提升”；历史 baseline 与 deterministic candidate 的 GPU backend flags 不同。
