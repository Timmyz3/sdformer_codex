# Local5 TCFM5 原位跨头驻留累加四方闭环

> 后续证据优先级：`docs/280_Local5合法1RW_TCFM5跨头驻留闭环_20260810.md`
> 修正了非法持续 1R1W 合同；`docs/281_Local5公共向量边界强基线负结果_20260810.md`
> 又消除了 scalar-B0 的重复行读。最终公平周期收益仅 `1.0557x`，本文早期较大收益
> 不得作为 DATE 强基线结论。

日期：2026-08-09

## 1. 本轮结论

本轮只推进 `docs/276` 经 DATE 评审冻结的最高优先级：不再把每个 input head 的
`450xOUT32` 结果标量化到独立跨头 Acc，而是在现有五个 TCFM5 向量 Acc bank 内按
head 顺序连续累加，仅在最后一个 head 后读出最终 Acc32。

- `[rtl]` 原位 recompute B2 相对标量 recompute B0 平均加速 `2.2636x`；
- `[rtl]` 原位 memo B3 相对标量 recompute B0 平均加速 `2.3407x`；
- `[rtl]` memo 在原位路径上的独立增量为 `1.0340x`，仍是次要机制；
- `[rtl]` 删除 `129600` 个跨头 partial、`129600` 次额外标量读和 `129600` 次额外
  标量写，最终结果仍为 `43200` 个 Acc32；
- `[rtl合同]` 删除独立 `460800-bit` 跨头 Acc，TCFM5 公共 Acc 状态不增加；
- `[模型]` 在统一宏组织假设下，逻辑 Acc bit 减少 `50.00%`，向上取整后的分配 bit
  减少 `41.61%`；
- `[待验证]` 本机只有 1RW 开放宽宏，不能直接实现 TCFM5 的持续 1R1W 更新合同，
  因而本轮没有虚构 OpenROAD 宏 PPA。

这是一项显著的数据流收益，但其原理仍接近 output-stationary/in-place reduction。
当前应把它定位为 **Local5 五色拓扑投影的跨头物化消除机制**，而不是声称发明了通用
原位累加。是否足以成为 DATE 正文独立贡献，必须结合本轮评审、fullres trace 和目标宏
PPA 再决定。

## 2. 被消除的旧物化边界

旧 B0/B1 数据流为：

```text
每个 output tile：
  head 0 -> score/Shiftmax5 -> relation/term -> TCFM5 vector Acc
         -> 14400 个 scalar partial -> 独立 cross-head Acc 首写
  head 1 -> 同上 -> 14400 个 scalar partial -> cross-head 1RW RMW
  head 2 -> 同上 -> 14400 个 scalar partial -> cross-head 1RW RMW
  独立 cross-head Acc -> 43200 个 scalar final drain
```

这条路径先在 TCFM5 内形成完整 `OUT32` 向量，再把它按 out 维标量化，搬到另一份
`14400x32b` 存储做相同的整数加法。`docs/276` 的分账证明，relation memo 虽减少
44.44% Q/K Token 请求，却无法跨越这个物化边界，因此仅有 `1.0145x` 周期收益。

## 3. 原位跨头驻留数据流

新 B2/B3 数据流为：

```text
output tile scheduler
  -> head 0: load W0 -> clear five TCFM5 Acc banks
             -> relation/term -> Acc += gate*W0
             -> 不读出、不物化 partial
  -> head 1: load W1 -> 保留同一组 TCFM5 Acc
             -> relation/term -> Acc += gate*W1
             -> 不读出、不物化 partial
  -> head 2: load W2 -> 保留同一组 TCFM5 Acc
             -> relation/term -> Acc += gate*W2
             -> 仅此时读出 43200 个 final Acc32
```

`qfit_tcfm5_projection_top` 新增 `run_accumulate` 和初始化状态：首 head 走 clear，后续
head 跳过 clear 并在原 Acc 字上更新；未初始化就请求 accumulate 会粘滞
`protocol_error`，直到下一次合法 run 显式重启该叶；外层 executor 的错误状态保持到
reset。权重 context 仍按 input-head/output-tile 作业释放，Acc context 则在
同一 output tile 的全部 input head 完成前驻留。两者生命周期被显式分离。

`qfit_local5_cross_head_tile_executor` 只给非首 head 置 `job_accumulate`，只给末 head 置
`job_emit_results`。原位模式通过 generate 删除独立 `qfit_single_port_acc_memory`，末头
结果直接连接 scheduler-facing `tile_result`；非末 head 若异常产生结果，会因身份合同
不匹配进入 fail-closed，而不是被静默接受。

## 4. 为什么整数结果保持 exact

对于同一目标位置和输出通道，旧路径计算：

```text
P_h = sum(term in head h) gate(term) * W_h(term)
Y   = ((P_0 + P_1) + P_2) mod 2^32
```

新路径在同一 TCFM5 Acc 地址上按相同 head 顺序计算：

```text
Acc = 0
Acc += head 0 的全部 term
Acc += head 1 的全部 term
Acc += head 2 的全部 term
Y = Acc mod 2^32
```

每个 head 内的 term 顺序、Q7 score、Q1.7 gate、signed weight 和 32-bit 二补码加法均未
改变；head 顺序仍是 0、1、2。因此它不是近似重排，也没有改变溢出语义。本轮独立
Python oracle 对三个 output tile 的每个 Acc32 做逐项比较，四候选均为零失配。

## 5. 四方公平消融

统一测试条件：三 input head、三 output tile、T450、OUT32、相同定向 Q/K/weight、相同
外部服务模型、三个随机反压 seed，并由 Icarus 和 Verilator/SVA 两套模拟器复核。

| 候选 | Relation | 跨头归约 | mean 周期 | 相对 B0 |
|---|---|---|---:|---:|
| B0 scalar recompute | 每 tile 重算 | 独立 1RW scalar Acc | 696609.0 | 1.0000x |
| B1 scalar memo | hit/replay/fallback | 独立 1RW scalar Acc | 686677.3 | 1.0145x |
| B2 in-place recompute | 每 tile 重算 | TCFM5 原位驻留 | 307738.3 | 2.2636x |
| B3 in-place memo | hit/replay/fallback | TCFM5 原位驻留 | 297610.0 | 2.3407x |

关键增量：

| 对照 | 加速 | 归因 |
|---|---:|---|
| B2 / B0 | 2.2636x | 只改变原位跨头累加 |
| B3 / B1 | 2.3073x | memo 条件下只改变原位累加 |
| B1 / B0 | 1.0145x | 标量路径只加入 memo |
| B3 / B2 | 1.0340x | 原位路径只加入 memo |
| B3 / B0 | 2.3407x | 两机制联合，不用于单项归因 |

因此本轮主收益来自取消中间物化，不来自 memo。FCSR 继续保留为 exact 前端流量机制或
附录消融，不能仅因与 B3 联合就恢复成主性能贡献。

| B3 | 51642.7 | 73148.0 | 172773.3 | 18.0 | 0 | 0 | 18.0 |

`cross RMW` 是 `child readout` 中的诊断子集，不能再次加入总周期。B3 完成后，末头
scalar readout 约占总周期 58%，成为新的第一瓶颈；frontend 约 24.6%，weight 服务约
17.4%。本轮不继续修改 final readout，以维持单机制收益归因。下一轮是否做向量行缓存、
BN/requant/ATLIF 融合消费或 vector result 接口，应由 DATE 评审和系统边界共同决定。

## 7. 存储、端口与物理公平性

局部存储合同：

| 路径 | 逻辑组织 | 端口 | 逻辑 bit |
|---|---|---|---:|
| 公共 TCFM5 Acc | 5x90x1024 | 持续更新需 1R1W | 460800 |
| B0/B1 额外跨头 Acc | 14400x32 | 1RW | 460800 |
| B2/B3 额外跨头 Acc | 无 | 无 | 0 |

`scripts/model_local5_inplace_acc_sram.py` 按每个逻辑 bank 独立映射、禁止跨 bank 偷合并
端口：

| 数组 | 统一宏组织 | 宏数 | 分配 bit | 浪费率 |
|---|---|---:|---:|---:|
| TCFM5 | 20 个 128x256 1R1W 分片 | 20 | 655360 | 29.69% |
| 旧跨头 Acc | 57 个 256x32 1RW 分片 | 57 | 466944 | 1.32% |

由此 B0/B1 的局部 Acc 分配为 1122304 bit，B2/B3 为 655360 bit，下降 41.61%
`[模型]`。宏数不能直接相加比较面积，因为 128x256 与 256x32 的外围和版图不同。

更重要的是：本机 `fakeram45_128x256` 是 1RW，而当前 TCFM5 bank 每拍读旧值并写回
前一项，需要 1R1W。把它直接接到 OpenROAD 会改变吞吐或语义，所以本轮明确报告
“本机不支持该等吞吐宏映射”。后续必须二选一：

1. 在 DC 服务器使用目标工艺 1R1W compiler 宏，四候选同 SDC、同外围规则综合；
2. 实现 1RW 降吞吐 TCFM5 公平基线，重新测周期和 PPA，不能沿用当前 2.34x。

## 9. DATE 创新性边界

本轮可以辩护的系统性表述是：

> Local5 的 relation/term 流已经按五色拓扑把 32-lane product 直接路由到空间 bank；
> 跨 input-head 的归约不应再次离开这些 bank。原位驻留把 head 维归约吸收到相同的
> topology-colored output-stationary 状态中，取消 attention-to-projection 的标量物化边界。

它相对“加一个跨头 Acc”具有明确的周期、事务和存储收益，但以下内容不能单列贡献：

- 仅仅使用 output-stationary 或向量 Acc；
- ping-pong、banking、FIFO、初始化标志和 fail-closed；
- 把 1024-bit 行为 word 当作免费并行总线；
- 把 Yosys cell 或分配 bit 称为 ASIC PPA；
- 在 fullres Local5 exact 结果未完成时称为最终部署架构。

若要进入 DATE 主贡献，下一阶段需把它与本网络特有的五色 relation、确定性 head 顺序、
末端 ATLIF 事件生成和真实 fullres workload 绑定，并用同宏 PPA 证明收益不被 1R1W 宏
面积和宽读能量抵消。

## 10. 当前完成度与下一步候选

Local5 已闭合的主链是：

```text
12-block 时间复用调度
 -> tagged T450 score/Shiftmax5
 -> relation transpose
 -> source-major term
 -> TCFM5 five-bank projection
 -> 三 input-head 原位 Acc32
 -> 末头 final result
```

仍缺：fullres Local5 Q7/Q1.7 hardware-order 精度结果、真实多 sample relation/term 分布、
bias/no-running BN/requant/residual/ATLIF 输出、目标 1R1W SRAM、DC/STA/SAIF/PTPX 和整帧
带宽/FPS。Voxel 前端仍不在硬件 scope。

本轮完成后必须做独立 DATE 评审，再决定 Local5 的下一单项；Motion 不停止。Motion
随后恢复 `TARE-RQTB/ZKQI` 的真实 ordered-profile 去重分析，并允许选择或否决新机制，
而不是只维护旧 RTL。

## 11. 独立 DATE 评审与整改

独立只读审稿人检查本文、正式结果、关键 RTL、TB 和 SVA，未修改仓库。评分为：

| 范围 | 评分 | Recommendation |
|---|---:|---|
| 本轮证据包 | 3.8/5 | 高质量 RTL 原型；论文仍需 Major Revision |
| 整个 Local5 硬件线 | 3.2/5 | Weak Reject / Borderline 前 |
| 架构创新性 | 2.4/5 | Weak Reject |
| 当前 DATE 投稿准备度 | 2.8/5 | Weak Reject |

评审认可四方周期、逐 Acc32 等价、事务账本和 50.00%/41.61% 两种存储口径，但没有
因 `2.3407x` 抬高总体 recommendation，理由是：

1. B0 把本已形成的 OUT32 向量标量化三遍再做第二次归约，容易被视为 strawman；
2. 保持 reduction state output-stationary 是常见做法，五色 bank 不自动产生新原理；
3. 本机宽宏只有 1RW，当前 1R1W 周期尚不是合法宏实现结果；
4. 三 head/三 tile 定向测试不能代表 fullres 各 stage/head-count；
5. 局部 Acc 状态减少不能外推为全芯片存储、面积或能量减半。

评审还指出四项实验/验证问题：

- 同一 LFSR seed 按 wall-clock 自由运行，候选周期不同后并非 transaction-indexed
  完全相同服务 trace；正式公平基线必须录制/回放同一事务延迟序列；
- `readout_cycles` 包含子引擎状态、握手和反压，不是纯 SRAM 读延迟；
- 当前 final scalar 接口会对同一 1024-bit 行重复请求 32 次，需补宏激活与切换账本；
- 尚缺 head-count 1/最大值、同址长 burst、尾部反压、异常中间结果和 wrap stress。

评审发现子引擎 `protocol_error` 后外层仅关闭服务、未退出 `TX_RUN_HEAD` 的潜在永久
等待。本轮已整改为直接进入 terminal `TX_ERROR`，新增 SVA 和定向故障模式 4；该修复
属于 correctness，不计性能或创新。

Local5 下一轮唯一优先级冻结为 **合法 1RW TCFM5 强基线**：四候选必须都用本机可
实现 1RW 调度和 transaction-indexed 相同服务 trace。晋级门槛是 B2/B0 仍有至少
`1.5x` RTL 周期收益，且后续同宏 EDP 或面积归一吞吐至少改善 20%；否则本机制降为
工程优化或附录。final BN/requant/ATLIF 融合在该门槛前不扩 RTL。

建议克制命名为 **Topology-Colored Cross-Head Accumulator Residency**，中文为
“五色拓扑 Acc 跨头驻留/跨头中间物化消除”。不使用“通用新型原位架构”等表述。

Motion 下一轮继续允许新机制，但先做 profile/淘汰：扣除 zero-K、RQTB 和 ZKQI 重叠
后，独立 cycle/work 增量不足 10% 就停止，不直接扩 RTL。
