## 0. 结论先行

### 0.1 是否立即把硬件主线从 H67 切到 Local5

**不立即全量切换，但 Local5 应升为优先硬件候选，并进入一次有明确淘汰门槛的 profile。**

理由不是 Local5 “局部注意力天然便宜”，而是：

1. `[算法]` 当前 Python RTL-like 部署模型中，Local5 的精度优于 H67：

   | 候选 | Python RTL-like AEE | AAE | spikes(G) | spike energy proxy(uJ) |
   |---|---:|---:|---:|---:|
   | H67 Motion-XOR | 1.4627 | 9.4040 | 26.3544 | 23362.23 |
   | H66d Local-5 | **1.4486** | 9.4210 | 26.5340 | 23535.19 |

   Local5 的 AEE 相对改善约 `0.964%`，但这个 `1.4486` **不是已经由
   Local5 SV 逐拍验证的 RTL-exact 结果**。独立语义审阅发现现有软件部署、
   Python 参考和 SV 存在第 0.3 节所列三个 P0。修复并重跑 valid825 以前，
   该数字只能作为候选精度证据。与此同时，spikes 和当前 proxy 分别增加约
   `0.681%` 和 `0.740%`。该 proxy 不包含 Local5 的五邻域搬运、738 条边和
   162 次 Shiftmax5 控制，因此不能据此断言硬件能耗更低。

2. Local5 的规则五邻域第一次提供了两个 H67 不具备、且可以做成真实 RTL
   机制的机会：

   - **Remainder-Carried Stencil Delta，RCSD**：利用 self-K 天然锚点和
     `K_self XOR K_neighbor` 的有向翻转集合，精确恢复邻居 Q7 score；保留
     舍入余数，避免“从已舍入 self score 做差”导致误差。
   - **Multiplicity-Folded Edge Projection，MFEP**：把 Local5 的
     `attention -> projection` 重排为边项直接累加，并把同一输出 token、
     channel、gate 的 1 至 5 次重复贡献折叠为带小重数的 term。

3. Local5 不是 H67 score 前端的小替换。H67 每个 162-token 窗口产生 162 个
   token score 和一次长度 162 的归一化；Local5 每个窗口产生 738 条有效邻边、
   162 次长度 3/4/5 的归一化，平均每个输出 token 有 `4.5556` 个候选。
   Local5 的归一化和地址规则更简单，但原始 score/edge 数约为 H67 的
   `4.56x`。

因此当前策略是：

```text
H67：冻结为已实现、已验证的硬件基线，不继续用包装抬高创新性
Local5：先做真实 ordered profile 和数学/定点合同，再决定是否重写前端
通过门槛：Local5 成为论文主线，H67 成为消融和负结果
未通过门槛：保留 H67 硬件主线，Local5 只作为精度上界
```

### 0.2 Local5 当前存在的三个数值 P0

#### P0-A：边界 mask 存在三种不同合同

当前软件把无效候选 score 写成 `-2.0`，但仍让其进入 Shiftmax 分母；通用
Python RTL-like Shiftmax 会给它非零 gate，随后 clamp 后的边界 K 仍参与
加权。现有参考向量也保留该非零 gate。

当前 Local5 SV 同样把 `-2.0` 放入分母，但最后强制无效候选 gate 为零。
真正的 masked Shiftmax 则应把无效候选同时排除出 max、分母和输出。

| 合同 | 分母 | 无效边输出 |
|---|---|---|
| 当前软件/Python 参考 | 包含 score=-2 | 非零，乘 clamp 后 K |
| 当前 Local5 SV | 包含 score=-2 | 最终强制为零 |
| 真正 masked Shiftmax | 不包含无效边 | 零 |

必须先选定一种合同并重新跑 valid825。若选择真正 masked Shiftmax，当前
`AEE=1.4486` 可能因消除边界泄漏而变化。

#### P0-B：Shiftmax5 SV 的 gate 缩放多一倍

冻结 Python 模型为：

```text
gate_q17 = RNE(exp_q8 * 128 / pow2ceil(row_sum_q8))
```

现有 `local5_shiftmax5_q17.sv` 在 `scaled` 低位拼接 8 个零，实际乘
`256`，而注释写的是乘 `128`。五个相等 score 时，Python gate code 约为
`16`，当前 SV 会得到约 `32`。因此现有 SV 与 Python reference 不等价。

#### P0-C：score SV 使用 half-up，不是 ties-to-even

软件 `torch.round` 是 RNE/ties-to-even。现有 score SV 使用“加半后右移”，
是正数 half-up。可达反例：

```text
q1=0, k1=24, n11=0, same_zero=8
A = 65*n11 + 32 - q1 - k1 = 8
RNE(A/16)     = 0
half-up(A/16) = 1
```

因此切 Local5 硬件主线前，必须先完成：

```text
G0：冻结边界 mask 语义并重跑 valid825
G1：修正 score RNE 与 Shiftmax x2，SV 对 Python 全向量零失配
```

在 G0/G1 完成以前，Local5 是“精度领先的软件候选”，H67 仍是“已验证硬件
基线”。

### 0.3 当前真正值得做的贡献

按优先级排序：

1. **RCSD：余数携带的精确 stencil 差分 score engine**；
2. **MFEP：带重数折叠的 Local5 边项直接投影数据流**；
3. **同一 reduction substrate 上的 direct/delta 密度自适应模式**，仅在
   邻域 XOR 密度 profile 支持时晋级；
4. **Stencil-Time Tile，STT**，作为 Bishop TTB 的 Local5 定制容器和存储
   基础设施，不作为单独原创贡献。

SCS-Shiftmax、GateStack、DCTF-2C、PPDI 和 H67 term stream 仍有工程价值，
但不再承担论文的主要架构新颖性。

## 1. H67 与 Local5 的真实语义差异

### 1.1 H67

H67 的主干是：

```text
每个 token 的 ternary alpha-XNOR score
  + 同空间位置跨 T=2 的 K Motion-XOR bias
  -> 162-token Shiftmax
  -> pointwise gate * K
  -> projection
```

冻结 H67 trace 已有以下 `[prof]` 动机：

- token K-zero 约 `88.7%`；
- temporal pair empty 约 `74%`；
- final-gate product work 相对稠密执行减少约 `82.5%`；
- H67 G1 trace 上每行活跃 gate class 的 `p50/p95/p99/max = 1/3/3/6`。

最后一项只是特定 H67 trace 的经验分位数，不是“gate cardinality theorem”，
也不能迁移到 Local5。

### 1.2 Local5

Local5 对每个 `T x 9 x 9` 窗口中的输出 token，选择：

```text
self + north + south + west + east
```

设计意图是对边界候选做 mask；当前软件/Python/SV 的实际 mask 合同尚未
统一，见第 0.2 节。每个候选独立做 binary alpha-XNOR score；随后在候选维
做 Shiftmax5：

```text
a[i,d] = sum_{j in N(i)} gate[i,j] * K[j,d]
```

两帧、每帧 9x9 的有效有向边数为：

```text
self:            2 * 81      = 162
N/S/E/W:         2 * 4 * 72  = 576
total:                         738
average degree: 738 / 162    = 4.5556
```

因此 Local5 同时具有两面性：

| 维度 | Local5 优势 | Local5 风险 |
|---|---|---|
| 拓扑 | 固定邻域，无动态 top-k、无通用路由 | 边界需要 3/4/5 候选合同 |
| 归一化 | 只做 Shiftmax5，状态极小 | 每窗口要做 162 次 |
| 存储 | 三行缓冲即可服务空间邻域 | naïve query-major 会重复读 K |
| score | binary alpha-XNOR，算术简单 | 有效 score 为 738 个，不是 162 个 |
| 投影 | 可把邻边直接转成投影 term | term 是多重集，不再是 H67 的 0/1 set |
| 论文 | 可讲规则 stencil 专属数据流 | 不能把普通 local attention 或 line buffer 当创新 |

## 2. 对现有“重新包装”建议的严格判定

| 建议名称 | 判定 | 可保留部分 | 必须删除或改写的部分 |
|---|---|---|---|
| ZUI Exact Computing | 定位词 | 用 `bit-exact` 作为评价轴 | exact 本身不是架构；不能说既有稀疏 attention 都近似 |
| Gate-Code Superscalar | 类比过度 | 可描述一条 term 向多个 bank 发射 | 当前没有 superscalar issue/rename/dependency 机制 |
| ISD / Hardware Type System | 证据不足 | descriptor 可定义严格 schema | 没有类型规则、兼容性检查和组合语义，不能叫类型系统 |
| WAL | 不恰当类比 | whole-term 原子可见性是正确性合同 | 没有持久日志、恢复和 rollback，不应写 WAL |
| SSA | 普通不变量 | term 内 gate/product 不变可用于复用 | 不是 SSA 架构贡献 |
| Virtual Channel | 不严谨类比 | per-reader progress 和 ordered retire 可描述协议 | consume mask 不是 VC credit |
| Algebraic Closure | 当前不成立 | 可证明具体有限多重集变换 | score histogram 与 destination directory 不是同一代数结构 |
| Gate-Stationary | 可做数据流消融 | 明确 loop nest、驻留对象和搬运公式 | Sanger 等已有 stationary dataflow，不能单独称首次 |
| Precision Stratification | 常规重构 | 若同一物理 lane 真正复用可报告 PPA | 仅配置不同不构成贡献 |

论文可以使用“精确”“确定性”“无需预测”等性质，但贡献标题必须落在可画出
状态、端口、循环和存储层次的机制上。

## 3. 为什么以前没有直接采用 Bishop、Prosperity、Phi 和蝶形网络

这不是完全漏看。`docs/47` 已对 Bishop/TTB、Prosperity、LoAS、Sparseloop
做过机制映射；`docs/66` 已对复旦 ISSCC 2023 蝶形 zero skipper 和局部注意力
复用做过淘汰审计。

### 3.1 Bishop 与 TTB

Bishop 的核心是 Token-Time Bundle、density stratifier、dense/sparse 异构核、
BSA 训练和 ECP 近似剪枝。

H67 的 TTB profile 确实有大量 empty bundle，但没有证明双核在加入：

- stratifier；
- 双 FIFO；
- idle core；
- 稀疏 metadata；
- SRAM 和路由；

以后仍有净 EDP 收益。因此此前保留 TTB 表示，未直接复制双核是正确决策。

Local5 下可以迁移的是 **bundle 思想**，但更合理的容器不是通用 token-time
bundle，而是包含空间 halo 和有向差分密度的 STT：

```text
STT descriptor
  time id / row id / x span
  valid-boundary mask
  self-K occupancy
  N/S/E/W directional XOR density
  active-K bitmap
  optional delta/direct issue hint
```

TTB/STT 是基础设施。除非证明该容器能跨 score、Shiftmax 和 projection 原地
演化并减少真实 SRAM/NoC 流量，否则不能作为主创新。

### 3.2 Prosperity

Prosperity 利用二值行之间的 exact/partial subset 关系复用内积，并承担在线
detector、TCAM/compare、排序、dispatcher 和结果表成本。

H67 的 temporal K0/K1 精确复用只有约 `10%`，不值得先上通用关系检测器。
Local5 则不同：self 和四邻居关系由 stencil 拓扑免费给出，天然存在锚点，
无需 TCAM 查“谁和谁相似”。RCSD 借用的是 Prosperity 的 **exact residual
reuse 原则**，差异是：

- 关系由拓扑静态给出；
- anchor 固定为 self K；
- residual 是有向 `0->1`/`1->0` 翻转；
- Q7 舍入余数随 anchor 携带；
- delta 太密时回到同一 reduction tree 的 direct 模式。

因此不能宣称“首次 exact product reuse”，但可以研究“无需在线关系发现的
拓扑锚定精确增量 score”。

### 3.3 Phi

Phi 把 activation 表示为预定义 pattern 加稀疏 residual，并对 pattern 部分做
预计算；PAFT 是另一个算法协同维度。

Local5 可以建立一个 Phi-like 对照：

```text
K = codebook_pattern[id] XOR residual
```

但该方向只有在真实 Local5 Q/K chunk 满足以下条件时才值得做：

- 小 codebook 覆盖率高；
- residual 的 mean/p95 都低；
- pattern lookup + residual engine 的能量低于 RCSD；
- 不做 PAFT 时保持完全精确。

否则 Phi 路线会把固定五邻域的简单问题重新变成 codebook 检测和索引问题。
本轮将其保留为强基线，不列为主方案。

### 3.4 FireFly-T

FireFly-T 可迁移的机制包括：

- 多 lane 稀疏 decoder；
- weight dispatch 和 bank-conflict-aware 调度；
- binary attention engine；
- 多维数据流重排。

不能直接迁移的是 FPGA LUT6 AND-popcount 的 PPA结论和 dual-engine overlay
结果。Local5 的四个方向固定，通常不需要通用稀疏 decoder；若 XOR residual
足够稀疏，可把 FireFly-T 的“每拍抽取多个非零”思想改成 **每拍抽取多个有向
delta bit**，作为 RCSD 的电路实现对照。

### 3.5 复旦 ISSCC 2023 蝶形网络

该工作已经提出：

- 面向非结构剪枝权重的 in-memory butterfly zero skipper；
- CIM-based local-attention-reusable engine；
- Q/K sharing。

H67 的动态 K-event 复用不足，直接采用蝶形网络没有数据支撑。Local5 虽是
局部注意力，但它只有固定十字五路：

```text
line buffer + 固定方向 tap + boundary mask
```

通常比可编程蝶形网络更小、更低功耗。可借鉴的是“局部注意力应把重用放到
存储和数据搬运层”的原则，而不是把 butterfly 本身重新包装成创新。

只有未来 Local5 扩展为可变 span、AX17、DE9 或多尺度稀疏邻域时，蝶形或
Benes 类网络才值得作为互连 DSE 候选。

## 4. 主候选一：RCSD 余数携带的精确 stencil 差分

### 4.1 冻结算术

Local5 部署配置为：

- binary Q/K；
- `HEAD_DIM=32`；
- `alpha0=1/64`；
- score 先除以 32，再量化到 Q7；
- 每个候选独立舍入，然后进入 RTL Shiftmax5。

对 32-bit Q、K，定义：

```text
q1  = popcount(Q)
k1  = popcount(K)
n11 = popcount(Q & K)
n00 = 32 - q1 - k1 + n11
```

Q7 整数 score code 为：

```text
S7(Q,K) = RNE((256*n11 + 4*n00) / 64)
        = RNE((65*n11 + 32 - q1 - k1) / 16)
```

### 4.2 有向差分恒等式

以 self K 为 `K0`，邻居为 `Kr`：

```text
U = (~K0) & Kr    // 0 -> 1
D = K0 & (~Kr)    // 1 -> 0
```

则：

```text
n11_r - n11_0 = popcount(Q & U) - popcount(Q & D)
k1_r  - k1_0  = popcount(U)     - popcount(D)
```

令 self 的舍入前整数 numerator：

```text
A0 = 65*n11_0 + 32 - q1 - k1_0
```

邻居增量为：

```text
Delta_r =
    65 * (popcount(Q & U) - popcount(Q & D))
  -      (popcount(U)     - popcount(D))
```

因此：

```text
S7(Q,Kr) = RNE((A0 + Delta_r) / 16)
```

RNE 的整数实现必须保留：

```text
q = floor((A0 + Delta_r) / 16)
r = (A0 + Delta_r) mod 16
inc = (r > 8) or ((r == 8) and q[0] == 1)
S7 = q + inc
```

**关键点**：不能从已经舍入的 `S7(Q,K0)` 继续累加 `RNE(Delta/16)`。
RCSD 保存 `A0` 的 quotient/remainder，邻居只在最后统一舍入，因此与五套
direct score 在整数上完全一致。

本文已做 `[推导]` 随机参考检查：

```text
500000 个随机 32-bit (Q, K0, Kr)
direct Q7-RNE 与 remainder-carried delta Q7-RNE
结果：PASS，零失配
```

该检查证明公式实现方向正确，不代替 valid825 全 trace 和 RTL bit-exact。

### 4.3 微架构

```text
Q register ------------------------------+
                                          |
self K -> q1/k1/n11 reduction -> A0(q,r) |
                                          v
neighbor K -> U/D directional masks -> delta extractor
                                   -> popc(Q&U), popc(Q&D)
                                   -> popc(U), popc(D)
                                   -> Delta add to A0 remainder
                                   -> exact Q7 score
five exact Q7 scores -> Shiftmax5
```

推荐的物理实现不是“五个 delta engine”，而是一棵时间复用的 reduction
substrate：

```text
direct mode: 32-bit bit-parallel popcount
delta mode:  2/4-lane set-bit extractor + signed small-count accumulator
```

每个邻居根据 delta density 选择模式。该选择只改变执行方法，不改变结果。

### 4.4 RCSD 的真实创新边界

可辩护：

- 固定 stencil 提供零检测成本的 anchor 关系；
- 有向 residual 精确恢复 alpha-XNOR；
- remainder-carry 保持逐候选 Q7 舍入；
- direct/delta 复用同一 reduction substrate；
- 可用真实方向 delta density 做调度。

不可宣称：

- 首次 product reuse；
- 首次 pattern-residual；
- 只做 XOR 就能恢复 score；
- delta 一定比 direct 省面积/能量。

### 4.5 RCSD 晋级门槛

在写 RTL 前必须满足：

1. 四方向 `popcount(K0 XOR Kr)` 的 mean/p50/p95/p99 必须分 stage/head/window
   统计；
2. 方向翻转 `|U|`、`|D|` 和 Q-conditioned `|Q&U|`、`|Q&D|` 必须分别统计；
3. 预注册筛选：delta engine 的 trace work ratio 相对四个完整邻居
   32-bit score 不高于 `0.50`，且 p95 不高于 `0.75`；
4. 后续同吞吐、同寄存边界、共享 q-count 的公平 RTL 对照中：
   `EDP_RCSD <= 0.85 * EDP_direct5`；
5. 所有候选 score 和 gate 对冻结软件逐整数零失配。

第 3、4 条是工程筛选门槛，不是现有结果。

## 5. 主候选二：MFEP 带重数折叠的边项直接投影

### 5.1 精确循环重排

Local5 注意力输出：

```text
A[i,c] = sum_{j in N(i)} g[i,j] * K[j,c]
```

后续 affine projection：

```text
Y[i,o] = b[o] + sum_c A[i,c] * W[c,o]
```

在宽整数累加且只在最终边界做一次 requant/saturation 时，可重排为：

```text
Y[i,o] =
  b[o] + sum_{j in N(i)} sum_c
         g[i,j] * K[j,c] * W[c,o]
```

本文已做 `[推导]` 参考检查：

```text
100 个随机 162-token、32-channel、12-output 整数窗口
materialized Local5 -> projection
对比 edge-term direct projection
结果：PASS，零失配；每窗口有效边为 738
```

该恒等式不自动证明当前部署图 bit-exact。BN 折叠、bias、Acc 位宽、
requant/saturation 和 `attn_sn` 状态边界必须先冻结。

### 5.2 为什么 H67 的 destination bitmap 不能直接套用

H67 中，一个输出 token 的某个 input lane 至多产生一次 `(gate,lane)`
贡献，因此 destination bitmap 是集合。

Local5 中，一个输出 token 的同一 lane 可能从多个邻居收到相同 gate：

```text
g[i,self] * K[self,c]
+ g[i,N] * K[N,c]
+ ...
```

若多个有效边的 `(gate,c)` 相同，贡献有 2 至 5 次。单个 bitmap 只能表示
“出现/未出现”，直接合并会丢失 multiplicity。

这不是一个边角协议问题，而是 Local5 相对 H67 的核心 term 语义变化：

```text
H67 term:   set multicast
Local5 term: bounded multiset reduction
```

### 5.3 重数折叠

对每个 destination `i` 和 input lane `c`，仅保留 `K[j,c]=1` 的邻边，并按
gate code 建立最多五项的小直方图：

```text
m[i,c,g] = count{j in N(i) | K[j,c]=1 and gate[i,j]=g}
```

于是：

```text
Y[i,o] =
  b[o] + sum_c sum_g m[i,c,g] * g * W[c,o]
```

其中 `m` 只取 `1..5`。硬件可按 multiplicity 分成五个 destination plane：

```text
term = {lane, gate, multiplicity, destination_bitmap}
```

每个 plane 内仍是 0/1 bitmap，因而可以继续使用 DCTF 的：

- bank-local weight/Acc；
- ordered multicast；
- output tile 生命周期；
- bias/final；
- flush/epoch 保护。

executor 新增一个 `x1..x5` 小常数缩放：

```text
x1 = p
x2 = p << 1
x3 = (p << 1) + p
x4 = p << 2
x5 = (p << 2) + p
```

这比“给每个 destination 加 3-bit count SRAM”更容易复用现有 set fabric，
但不是“DCTF 原样复用”：term schema、adapter、fabric payload 和 executor
都要加入 multiplicity，Acc 位宽也要重审。是否节省 term 数和能量必须由
Local5 trace 决定。

必须同时实现一个低风险基线：

```text
offset-separated term
  key = {direction, lane, gate}
```

该基线按 self/N/S/E/W 分开，天然不会把不同邻边错误 OR 到同一 destination
bitmap，能够较多复用现有 DCTF；代价是 term 数增加、跨方向 gate 复用丢失。
MFEP 必须在同一 trace 上胜过该基线，不能只和 materialized naïve 路径比较。

### 5.4 source-centric 数据流

MFEP 推荐从 naïve query-major gather 改为 source-centric multicast：

```text
三行 K/Q buffer
  -> 固定五方向 edge score/gate
  -> active source-K lane
  -> 对最多五个 destination 的 gate 做小直方图
  -> {lane, gate, multiplicity, destination bitmap}
  -> DCTF bank-local projection
```

这样：

- 不物化 `A[162,32]`；
- K source 从 line buffer 读一次，可服务最多五个 destination；
- `W[c,:]` 对相同 lane/gate/multiplicity term 只取一次；
- 边界由固定 valid mask 处理；
- gate=0 仍需按冻结语义决定是零旁路还是保留归一化状态。

这比单纯“gate-stationary”更具体：它同时定义了 loop transposition、term
多重集、存储驻留和投影提交语义。

### 5.5 MFEP 的 P0 正确性合同

1. BN 必须先折叠为 affine projection，或明确不能跨 BN 重排；
2. bias 对每个 destination 只提交一次；
3. Acc 位宽必须覆盖 5 邻边、32 input lane 和 output tile 的最坏范围；
4. 只允许在冻结部署边界做最终 requant/saturation；
5. boundary mask 和 invalid score 不得生成伪 term；
6. gate=0、K=0、empty token 必须保持软件语义；
7. `attn_sn(x)` 的状态和返回值必须确认是否为部署可观察状态；
8. 同一 destination 的重复 `(gate,lane)` 必须由 multiplicity 或重复 event
   完整表达，禁止用普通 bitmap 静默去重；
9. 多 head term key 必须包含 `head_input_channel_base + lane`，禁止跨 head
   按局部 lane 合并；
10. term 顺序改变只能发生在整数加法可交换且无中间饱和的边界内；
11. final-valid 前必须完成所有 multiplicity plane。

### 5.6 MFEP 晋级门槛

1. Local5 全 ordered trace 上统计：
   gate=0、gate cardinality、`m=1..5` 分布、term fanout、重复率；
2. `unique (lane,gate,m,destination)` term work 不高于 naïve 738-edge
   projection 的 `60%`；
3. Local5 MFEP term/product work 不高于 H67 GateStack 的 `1.25x`；
4. 目标格式 overflow/fallback 低于 `0.1%`；
5. source-K SRAM transaction 相对 query-major 至少降低 `50%`；
6. 多 trace p99 queue/fabric latency 不比 naïve Local5 退化超过 `5%`；
7. attention-projection 子系统目标工艺 EDP 至少改善 `15%`；
8. full-encoder Amdahl 后端到端收益至少 `8%`，否则降为算子级贡献。

以上均为预注册门槛，不是现有结果。

## 6. 次级候选与淘汰规则

### 6.1 STT：Stencil-Time Tile

用途：

- 两帧、行段和 halo 连续存储；
- 携带边界、K occupancy、方向 delta density；
- 为 RCSD direct/delta issue 提供 metadata-first 判定；
- score 完成后原位演化为 edge-term header。

它借鉴 Bishop TTB 和 LoAS temporal packing。只有当“同一 resident tile 跨
score 到 projection 原地演化”显著减少 decode/repack 和 SRAM traffic 时，
才可作为系统贡献的一部分。

### 6.2 Phi-like exact pattern + residual

作为强基线：

- 小 codebook pattern；
- exact XOR residual；
- 不启用 PAFT；
- 与 RCSD 比 detector、表、残差 work、SRAM 和 EDP。

若 codebook 命中率或 residual p95 不够好，立即淘汰。

### 6.3 direct/delta 单阵列双模式

这不是 Bishop 式 dense/sparse 双核。建议同一 reduction tree 支持：

```text
dense/direct: 32-bit 并行 popcount
sparse/delta: 多 lane set-bit extraction
```

优点是避免复制两个 core；缺点是 mux、控制和低利用率可能抵消收益。必须与
DenSparSA 的“稀疏支持低额外开销”原则对齐，报告 dense 模式的面积/功耗
惩罚。

### 6.4 蝶形路由

固定 Local5 首版淘汰。未来满足任一条件才重开：

- 邻域从 5 扩展为可变 span；
- 多尺度窗口动态选择；
- line buffer + crossbar 的 routing/energy 已成为主瓶颈；
- 同约束 DSE 证明 butterfly/Benes 的 EDP 优于固定 tap。

## 7. Local5 切线时可复用与必须重写的硬件

| 子系统 | 复用级别 | 说明 |
|---|---|---|
| encoder descriptor/stage/block scheduler | 高 | stage/block 数和统一 all-binary encoder 骨架不变 |
| ATLIF cluster | 高 | 神经元传播主线不变 |
| skip S0/S1/S2 端口 | 高 | Local5 不改变 skip 拓扑 |
| projection weight banks | 高 | `W[c,o]` 语义不变 |
| bank-local Acc、bias、final | 高/中 | 需扩 multiplicity 与位宽合同 |
| DCTF ordered multicast | 中 | set fabric 可复用，term schema 需扩展 |
| typed serializer/fallback | 中 | 需重新 profile Local5 term 分布 |
| Q/K SRAM | 中 | 容量可复用，布局改为三行/halo |
| Shiftmax LUT/reciprocal primitives | 中 | 算术可复用，row-162 控制改为 162 个 Shiftmax5 |
| H67 Motion-XOR scorer | 低 | Local5 主线不使用 |
| H67 SCS 35-class row engine | 低 | Local5 每 token 是 3/4/5 候选，不能直接复用 |
| H67 temporal-pair adapter | 低 | 需改为 stencil edge builder |
| H67 profile/TTB 统计 | 不可作证据 | 只能作硬件基线，不能外推到 Local5 |

切换规模应定义为 **中到大**：

- attention 前端、存储访问和 term builder 基本重写；
- projection 后端、encoder 调度、ATLIF/skip 骨架可继续复用；
- 不能称“只改新增部分”，也不需要推倒整个加速器。

## 8. 必须补的最小 Local5 profiling

### 8.1 score 与邻域差分

- sample/stage/block/head/window/row 的 ordered trace；
- self/N/S/E/W 的 K-one density；
- 四方向 `Kself XOR Kneighbor` density；
- `0->1` 与 `1->0` 分开统计；
- `Q&U`、`Q&D` 条件 delta；
- zero-delta、exact-K-match 和 subset-match；
- reuse distance；
- direct 与 delta 的估计 cycles/toggles。

### 8.2 Shiftmax5 与 gate

- 边界 degree=3/4/5 的占比；
- Q7 score tuple 的唯一数；
- gate=0 比例；
- 每 token gate-code cardinality；
- 同一 source 的五个 outgoing gate 重复率；
- gate 的 CSD digit 数；
- Shiftmax5 denominator、LUT 和 saturation 分布。

### 8.3 edge term 与重数

- 738 边中 source-K active 比例；
- 每个 `(destination,lane,gate)` 的 multiplicity `0..5`；
- 每个 `(lane,gate,m)` 的 destination fanout；
- naïve edge event、unique multiset term、PPDI command 数；
- typed format bytes、overflow、fallback；
- builder/FIFO depth 的 mean/p95/p99/max；
- bank conflict、stall、oldest-retire wait。

### 8.4 存储与系统

- query-major K reads；
- line-buffer/source-centric K reads；
- Q/K line-buffer 容量和端口；
- gate/score/materialized-A/term buffer bytes；
- SRAM read/write bytes/frame；
- projection weight row fetch；
- attention、projection、ATLIF、skip 的 cycle Amdahl；
- 30 FPS 目标下所需 Fmax、带宽和多窗口并发。

### 8.5 部署合同

- BN fold；
- projection weight/bias quant；
- Acc 最坏范围；
- requant/saturation 位置；
- `attn_sn` 可观察状态；
- full valid825 的 dense、RCSD、MFEP 逐整数一致；
- AEE/AAE/spikes 重新报告，硬件能量与 spike proxy 分账。

## 9. 公平基线

Local5 不能只和当前“五套完全复制 score RTL”比较，因为该 RTL 重复计算
q-count，基线过弱。至少需要：

1. **Direct5-naïve**：现有五套 score；
2. **Direct5-CSE**：共享 q-count、公共常量和寄存边界；
3. **RCSD-fixed**：固定 delta；
4. **RCSD-adaptive**：同一 substrate direct/delta；
5. **Phi-like exact pattern-residual**；
6. **Materialized projection**；
7. **Edge-term without multiplicity folding**；
8. **Offset-separated edge term**；
9. **MFEP**；
10. **H67 GateStack/DCTF**：同 scope、同 lane、同 SRAM 规则。

所有候选必须使用相同：

- SDC、PVT、目标库；
- SRAM macro 或同等 memory compiler 规则；
- ingress/egress 带宽；
- lane 数和寄存边界；
- backpressure；
- valid825 trace 集；
- DC/STA/SAIF 和功耗口径。

## 10. 论文故事的推荐收敛

若 Local5 通过门槛，论文不再以“7 个小创新”展开，而是：

### C1：算法-硬件协同的规则 Local5 全二值光流注意力

Local5 在当前 Python RTL-like 部署模型下达到 `AEE=1.4486`，并把动态全局
token 归一化变为固定 3/4/5 候选。只有 G0/G1 修复后 valid825 仍领先 H67，
该结果才可进入论文主表。该贡献属于协同工作，不单独冒充硬件架构。

### C2：RCSD 精确邻域差分 score engine

固定拓扑 self anchor、有向 residual、余数携带和 density-adaptive 单 substrate，
在保持逐候选 Q7 完全一致时减少 score work。

### C3：MFEP 多重集边项投影

将 Local5 attention 与 projection 做精确循环重排，不物化 attention tensor；
利用邻域度上界 5，把重复 edge contribution 折为小重数 term，并映射到
bank-local projection。

### C4：统一 encoder 执行骨架

STT/descriptor、RCSD、Shiftmax5、MFEP、ATLIF 和 skip 在一个共享 encoder
调度与存储层次中执行。DCTF、PPDI、TTB 作为支撑机制和消融，不重复计数为
原创贡献。

推荐暂用系统名：

```text
STEER-Flow
Stencil-Temporal Exact Event-Reduction Accelerator for Optical Flow
```

名称只是占位。最终标题必须等 RCSD/MFEP 的真实 profile 和 PPA 后确定。

## 11. 执行顺序

```text
G0  冻结边界 mask 与完整部署数值合同，重跑 valid825
G1  修正 score RNE/Shiftmax 缩放，SV 对 Python 零失配
G2  G0/G1 后重跑 Local5 ordered profile100/valid825 统计
G3  用 profile 判 RCSD、MFEP 是否过预注册门槛
G4  先做 Python/整数 reference 与 trace replay
G5  做公平 Direct5-CSE、RCSD 叶 RTL
G6  做 materialized、edge-term、MFEP 投影 RTL
G7  多 trace + backpressure + SRAM latency 回归
G8  同约束 DC/STA/SAIF
G9  full encoder Amdahl 和 30 FPS 系统预算
G10 独立 DATE 审稿；不过门槛则回退 H67
```

本轮已经旁路完成一次 pre-G0 探索 profile，只用于判断 RCSD/DSE 是否值得
继续，不等价于 G2。当前仍只允许推进 G0/G1；完成后必须以同 cohort 重跑
G2。没有数值合同和 post-G0 Local5 workload 数据前，不应继续扩 DCTF
包装，也不应直接写 RCSD/MFEP 大顶层。

## 13. 当前冻结判断

1. **当前 Python 部署模型中 Local5 领先，但存在三个 P0；硬件上尚未胜出。**
2. **H67 继续作为成熟 RTL 基线，不再继续堆叠包装型创新。**
3. **Local5 最强机会不是普通 local attention、TTB 或蝶形，而是 RCSD 和
   MFEP。**
4. **DCTF 可以作为 MFEP 的后端，但必须从 set multicast 扩展到 bounded
   multiset reduction。**
5. **下一步唯一合理动作是补 Local5 ordered workload profile 与部署合同。**
