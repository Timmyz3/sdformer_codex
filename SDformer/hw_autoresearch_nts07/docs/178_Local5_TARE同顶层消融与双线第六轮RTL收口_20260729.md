# Local5 TARE 同顶层消融与双线第六轮 RTL 收口

## 1. 结论先行

本轮完成了 Local5 `Direct/TARE` 在同一
`score -> Shiftmax5 -> MFEP -> projection` 顶层下的公平消融。

结论不是“TARE 晋级”，而是：

> **Local5 默认吞吐路径冻结为 Direct；TARE 仅保留为待真实活动率和
> SAIF/DC 证明的精确低功耗候选。**

Motion 线继续冻结为：

```text
temporal-pair TARE
-> SCS/SET-term
-> fixed64/M4 exact multicast
```

Local5 线继续冻结为：

```text
self-K stationary Direct
-> Shiftmax5
-> multiplicity-preserving MFEP
-> conservative destination stream
```

两线仍共享 `tare4_residual_composite_core`，但不强迫 Local5 默认使用它。

## 2. 本轮修复与新增

### 2.1 同顶层双模式

以下三级顶层新增参数 `USE_TARE`：

- `local5_score_gate_term_top`
- `local5_window_attention_top`
- `local5_linebuf_window_top`

同一 MFEP、bridge 和 projection 后端仅切换 row score engine，避免把后端差异
误算成 TARE 收益。TARE 的 `ZERO/SPARSE/DENSE` 计数已导出到顶层。

由于实测 TARE 周期回退，发布默认值设为：

```systemverilog
USE_TARE = 1'b0
```

TARE 必须显式启用。

### 2.2 空 mask 正确性

旧 TARE row 在 `valid_mask=0` 时仍可能发一笔 self score。修复后空候选集合直接
进入 `DONE`，不产生 TARE issue、edge、term 或 destination。

### 2.3 全 32 种候选 mask

`tb_local5_row_context_tare` 已遍历五候选的全部 `2^5=32` 种 mask，包括：

- self 有效/无效；
- 任意方向组合；
- 全空；
- ZERO、SPARSE、DENSE 三类 residual。

结果：

```text
edges=80
tare_issues=80
zero=38
sparse=22
dense=20
```

issue 与分类、有效 edge 严格守恒。

score-to-term 顶层另加入全空 mask 向量，Direct/TARE 两种模式均在不产生 command
的情况下完成 `stencil_done`。零 K 但候选有效的 window 用例也分别运行
Direct/TARE，覆盖“有 score、无 term”的另一条零工作路径。

### 2.4 fullres T=450 地址边界

`score_gate_term` 新增 `DEST_W=9` elaboration，并实际使用 destination `449`。
该测试不是只证明“能编译 9 bit”，而是覆盖 T=450 最大合法地址。

### 2.5 反压与 SVA

score-to-term TB 使用确定性约 75% ready 的 sink。新增绑定断言检查：

1. anchor 在反压期间 payload 稳定；
2. command 在反压期间 payload 稳定；
3. 分类完成数不超过 issue 数；
4. stencil 完成时分类计数守恒。

TARE 与 Direct 两种 elaboration 均通过 `Verilator --assert`。

### 2.6 综合可移植性

为支持仓库中的旧 Yosys 前端：

- Shiftmax 的 unpacked 数组端口改为一维扁平向量；
- function 使用函数名赋值，不使用 `return`；
- MFEP 动态循环上界改为常数上界加条件屏蔽；
- destination 地址宽度保持参数化。

256 个数值向量、row、window 和 projection 回归均用于证明改写前后语义不变。

### 2.7 完成反压生命周期修复

独立 RTL 审阅发现：旧控制器进入 `ST_FINISH` 后，row engine 已回到空闲。
若 `stencil_done_ready=0`，下一笔 anchor 可能被 row engine 提前接收并覆盖完成
事务的 tag。

修复包括：

1. 对外 `anchor_ready` 和对内 `row_anchor_valid` 同时受
   `ctrl_q == ST_WAIT_EDGE` 门控；
2. row done 握手时把 tag 锁存到独立 `done_tag_q`；
3. `stencil_done` 反压期间保持 valid/tag 稳定；
4. SVA 检查完成事务退休前 `anchor_ready=0` 且
   `row_anchor_valid=0`；
5. score-to-term TB 对每个向量施加 1 至 3 拍完成反压。

该修复关闭的是 Direct/TARE 共用的 ready/valid 正确性问题，不增加架构性能。

### 2.8 T450 计数器位宽与动态边界

T450 最坏 naive product 数为：

```text
450 destinations * 32 lanes * 5 candidates = 72000
```

原 16-bit 计数器会回绕。score-to-term 的 edge/term/naive 计数已参数化为
`PERF_W=32`，并贯穿 MFEP 和两个窗口顶层。TARE issue 分类仍为 16 bit，
其 T450 上界约为 2250。

新增动态边界 TB 实际执行 450 个 destination、每个 5 个候选、每候选 32 个
有效 lane，得到：

```text
edges=2250
terms=72000
naive=72000
```

该测试关闭单次和现实多窗口计数回绕风险，但性能计数器仍属于自 reset 起累计，
不作为功能数据。

## 3. 同顶层周期结果

结果文件：

```text
results/local5_tare_direct_fullflow_20260729.log
results/local5_tare_direct_arch_eval_20260729/report.json
results/local5_tare_direct_arch_eval_20260729/report.md
```

| 层级 | Direct | TARE | TARE 周期开销 |
|---|---:|---:|---:|
| window4 | 420 | 471 | +12.14% |
| window16 | 1662 | 1896 | +14.08% |
| linebuf8x3 mean | 1118 | 1232 | +10.20% |

三组测试的 command 数完全相同，因此周期差来自 row score 相序，而不是 MFEP
工作量变化。

解释：

- Direct 同时计算五个候选 score；
- 当前 TARE 先驻留 anchor，再顺序发 self/neighbor transaction；
- residual lane work 可能减少，但 transaction、commit 和状态切换没有重叠；
- 因此当前 TARE 是“算术活动减少候选”，不是吞吐优化。

## 4. 开放映射结果

可复现入口：

```text
sim_local5/run_local5_tare_yosys_matrix.sh
```

四点均使用同一 Yosys `abc -fast` 流程。

| 配置 | DEST_W=8 | DEST_W=9 | 9-bit 变化 |
|---|---:|---:|---:|
| Direct | 35918 | 35919 | 约 0% |
| TARE | 35433 | 35436 | +0.01% |

TARE 只减少约 1.35% 通用单元。把不同门等权处理得到的面积归一吞吐代理为：

| 层级 | TARE / Direct |
|---|---:|
| window4 | 0.904x |
| window16 | 0.889x |
| linebuf8x3 | 0.920x |

证据边界：

- 这是 `[开放映射]`，不是目标工艺面积；
- 没有 SRAM macro、SDC、STA、SAIF、时钟树和泄漏功耗；
- 只能用于候选淘汰，不能进入论文主 PPA 表。

当前代理不支持 Local5 默认 TARE。

## 5. 双线架构创新状态

### 5.1 可以继续发展的共同架构原则

**Topology-Declared Exact Residual Execution（TDRE）**

算法/编译侧提前给出 temporal pair 或 spatial stencil，硬件执行
anchor/residual/fallback，不运行 matcher、不预测关系、不引入近似。

当前已有的硬件事实：

- Motion wrapper 与 Local5 wrapper 共享同一 residual composite core；
- ZERO/SPARSE/DENSE 具有 exact fallback；
- Local5 全 mask 与 Motion 时序参考均已回归；
- 两线后端允许按真实 destination 分布专化。

仍缺：

- 统一 descriptor/lowering ISA 的 RTL；
- Motion 与 Local5 同物理核的切换顶层和周期消融；
- fullres T450 真实 trace；
- 同工艺 PPA。

所以 TDRE 当前是“可晋级的架构主张”，还不是完成的 DATE 贡献。

### 5.2 Local5 当前可保留机制

1. self-K stationary 五点 score；
2. multiplicity-preserving MFEP；
3. Direct/TARE exact mode；
4. T=450 参数化 destination；
5. 保守 destination stream。

ISHD 仍等待 post-gate0 的逐 term destination delta/escape profile，不能先实现后
找收益。

### 5.3 Motion 当前可保留机制

1. temporal-pair TARE；
2. SCS/SET-term；
3. fixed64/M4 exact multicast；
4. 展平 token parity；
5. stage-conditioned Prosperity bypass。

Motion 单 destination ISHD 已淘汰。PPDI 等待修正后的 fullres profile。

## 6. 验证签核

### 已通过

- Verilator 256 数值向量；
- Direct row；
- TARE row，全部 32 种 mask；
- MFEP/bridge 协议；
- TARE/Direct score-to-term，随机反压；
- 每个 stencil 完成端 1 至 3 拍反压，done tag 稳定且下一 anchor 被阻断；
- `DEST_W=9`、destination 449；
- window4、window16、三窗口 line buffer；
- TARE/Direct SVA；
- Icarus TARE row 与 score-to-term；
- Yosys 四点结构映射；
- Motion/TARE/Prosperity/双线软件模型共 33 项 CPU 单测。

### 尚未签核

- fullres T450 hardware-order 真实 trace；
- 随机 SRAM latency；
- accumulator 深度 450；
- DC/STA/SAIF；
- target-library LEC；
- full encoder Amdahl/FPS。

本轮 clean rebuild 的 Verilator 主回归共有 21 个 PASS 记录；Direct/TARE
`Verilator --assert`、Icarus score-to-term 交叉仿真和两种 elaboration lint
均通过。

Erie 独立 lint 对新增 SVA 和顶层接口为 PASS；旧 row/Shiftmax RTL 因其规则禁止
function 和参数化 for-loop 仍报错。Verilator 与 Yosys 均可处理这些结构，但在
正式 RTL sign-off 前仍需决定：重写为完全展开逻辑，或把该规则登记为经过审阅的
项目级 waiver。

## 7. 下一步门槛

### Local5

1. 等 fullres exact follower 产生 post-gate0 trace；
2. 统计 ZERO/SPARSE/DENSE、gate cardinality、destination delta、escape；
3. 只有 TARE 的 SAIF/DC EDP 改善 `>=15%` 才重新晋级；
4. 只有 ISHD 含 fallback 后 fabric bits 降低 `>=50%`、escape `<=1%` 才实现。

### Motion

1. 完成 T450 control/address/storage RTL 回归；
2. 用修正 parity/gate0 后的 profile 重算 M4/PPDI；
3. PPDI command 降低 `>=15%` 且 EDP 改善 `>=10%` 才替换 M4；
4. 保持 fixed64/M4 为当前唯一主路径。

### DATE

本轮证据提高了正确性和负结果可信度，但没有解决目标工艺 PPA 与 fullres 外推。
在这些缺口关闭前，论文状态仍应按 `Weak Reject` 管理，不能靠重新命名提升评分。
