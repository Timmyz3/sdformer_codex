# DATE第十二轮强基线复审整改与G0冻结

## 1. 第一轮独立结论

本轮同时启动DATE架构审稿与数字ASIC审阅。

DATE初评：

- 评分：2.6/5；
- 推荐：Weak Reject；
- lane-local LRU只能算RTL骨架，不是强基线；
- GS-TTB仍有跨阶段数据流潜力，PF-GS-TTB存在严重同trace数据泄漏。

ASIC初评：

- 功能bring-up：GO；
- GS/PF同约束PPA基线：NO-GO；
- P0：无；
- P1集中在product位宽、乘法活动、weight/epoch合同、1RW宏口径、
  真实trace和LRU断言。

## 2. 第一轮发现的关键错误

### 2.1 128-bit不是缓存下界

输入为9-bit无符号gate和8-bit有符号weight：

```text
gate ∈ [0, 511]
weight ∈ [-128, 127]
product ∈ [-65408, 64897]
```

每路17-bit有符号数足够精确保存，因此4路内部product只需68 bit。128 bit只是
向32-bit Acc接口符号扩展后的传输格式。

### 2.2 计数器不等于真实活动

旧RTL在hit时仍组合计算`gate × weight`，虽然`perf_product_starts`不增加，
乘法器输入仍可能翻转。因此“减少product start”不能直接解释为乘法动态功耗。

### 2.3 1R1W不是公平物理合同

一次term只会hit读或miss写，不需要同时读写。强基线应使用同步单端口1RW，
否则可能人为放大LRU宏成本。

## 3. 已完成整改

| 整改 | 结果 |
|---|---|
| 内部product | `4×17=68 bit`，输出符号扩展到`4×32` |
| 乘法器 | 4个signed `10×8→17`，不随way复制 |
| operand isolation | 仅合法miss使能gate和weight操作数 |
| product bank | 每way一个`68×32`同步1RW |
| weight加载 | 强制lane-major/out-minor完整顺序 |
| `weight_last` | 仅最后一项合法，提前到达会阻止epoch |
| epoch | 定义为weight-product epoch，可覆盖多个window |
| 真实trace | 1494 term、32 lane、4 output，W4/W6/W8逐项PASS |
| 多window | 同一epoch内设置6个`window_last`，cache不失效 |
| Verilator+SVA | W4/W6/W8 directed及W6真实trace PASS |
| 存储敏感性 | 分开报告68-bit、72-bit假设对齐和128-bit未压缩 |
| 证据哈希 | 纳入RTL、TB、SVA、runner、结构检查器和trace CSV |

新增SVA包括：

- hit/miss活动计数分账；
- hit恰读一个bank；
- miss恰写一个bank；
- 合法输入下一周期产生输出；
- closing后不再接收输入；
- 原有输出stall稳定、同步读完成、done清空和hit/miss总账。

## 5. 第二轮复审

DATE复评：

- 证据可信度：4.0/5；
- 强基线程度：3.8/5；
- 总体：3.4/5，Borderline/Weak Reject；
- 动态GS-TTB：Conditional GO，可进入候选叶RTL；
- PF-GS-TTB：NO-GO，必须等待sample-held-out。

ASIC复评：

- 功能等价基线：GO；
- 逻辑周期同约束基线：GO；
- ASIC PPA基线：NO-GO；
- DATE面积、功耗、频率和EDP主表：NO-GO。

## 6. 仍未解除的物理问题

1. 单周期miss包含tag/LRU查找、weight选择、窄乘法和SRAM写数据生成，未经STA；
2. tag/valid/LRU/weight仍是寄存器/CAM式逻辑口径，没有目标工艺物理映射；
3. 没有完整LRU状态不变量formal或constrained-random覆盖；
4. 尚未与同一producer、FIFO和TCFM-5组成公平端到端对照；
5. 没有DC、STA、门级回标、真实weight SAIF和多sample统计。

## 7. G0冻结判定

G0在**功能与逻辑周期层面冻结为GO**，不继续用叶模块工程细节冒充架构创新。

后续候选必须共享：

```text
4个10×8→17乘法器
68-bit内部product
同步1RW product bank
相同weight-product epoch
相同producer/FIFO/TCFM反压
```

PPA前仍必须回到统一目标库和SRAM宏，不能引用Yosys cell作为面积。
