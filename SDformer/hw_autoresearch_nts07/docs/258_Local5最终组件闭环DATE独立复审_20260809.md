# Local5 最终组件闭环 DATE 独立复审

## 1. 评审结论

独立审稿代理按 DATE 硬件/软硬件协同标准给出：**2/5，Reject**。

工程验证纪律得到认可，但当前证据仍是“算法候选 + 三个组件 RTL + 架构模型”，没有形成可用于 DATE 主结果的部署精度、单顶层周期和 PPA 闭环。

| 分项 | 评分 | 主要原因 |
|---|---:|---|
| 新颖性 | 2.0/5 | exact relation replay 有候选价值，但 exposure-aware admission 相对 first-fit 的增益较小，尚不足以单独构成强贡献 |
| 系统完整度 | 1.5/5 | 缺 score→relation→term→projection 单顶层、跨 head 求和、动态 BN/requant/residual 和 12-block 调度 |
| 验证可信度 | 2.5/5 | 组件 miter、双仿真器、SVA 和哈希绑定扎实，但 ATLIF 仅覆盖 sample0 的 81 条命令，不能上推全系统 |
| 实验完整度 | 1.5/5 | 缺部署量化 valid825、真实联合 head trace、RTL 周期、SRAM macro、STA、功耗和 EDP |

## 2. 审稿人确认的负边界

1. GASR 公平 RTL 周期为 0.995x，不能写 latency 或 throughput 加速；80.03% SRAM 事务下降只能作为流量观测。
2. ATLIF 的 4.5409% fixed-vs-float event flip 不是 4.54% AEE 下降，但足以否定浮点等价和部署精度签核。
3. Relation Memo 的 1.342x 来自模型，不是 RTL；当前 bootstrap 独立抽取同 stage group，既破坏同 window 相关性，也没有保持 head 条件分布。
4. 抽查显示 S0 不同 head 的平均 service 约为 115、312 和 549 cycles，说明把所有 head 当成可交换样本会产生系统偏差。

因此，当前 1.342x 只能用于决定是否继续，不得进入摘要、主结果表或 headline speedup。

## 3. 唯一下一轮门槛

取得最终 epoch29、同一 `sample/block/window` 的完整 all-head 联合 trace，并在该 trace 上用相同端口、相同反压、相同周期边界完成 7 KiB Relation Memo 的 recompute 与 pack/replay/fallback 对照。

晋级条件同时满足：

- Acc32 逐项零失配。
- 按 sample 聚类得到的全帧 speedup 95% 置信下界不低于 1.15x。

未过门槛时，Relation Memo 降级为待物理能耗验证的存储候选，不继续扩大 RTL。

## 4. 当前不得写成贡献

- GASR 周期加速、功耗或 EDP 改善。
- ATLIF 浮点等价、量化精度签核或完整网络精度保持。
- Relation Memo 的 1.342x RTL/ASIC 加速、PPA、能效或吞吐面积比。
- 三个独立组件 bit-exact 等同于端到端 accelerator correctness。
- testbench 竞态修复、仿真器通过、哈希绑定或测试数量。
- SRAM、ping-pong、缓存和通用 memoization 本身。
- 把浮点 valid825 与未签核整数 RTL 组合成同一个软硬件 Pareto 点。

## 5. 本轮决策

接受评审意见，不再基于现有 bootstrap 扩 Relation Memo RTL。下一轮只修改 profile/qualification/模型输入，使 same-window all-head 联合分布成为可审计的正式证据，然后再决定是否晋级单顶层 RTL。

Motion 线继续并行。H67 fullres T450 profile 与 RQTB follower 的结论将单独复审，Local5 的 Reject 不构成暂停 Motion 架构迭代的理由。
