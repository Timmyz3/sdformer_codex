## 2. P0 整改

| 二次复审问题 | 整改 | 本地证据 |
|---|---|---|
| `resource/kind/phase/scope` 可伪造 | 每个 candidate/event 固定语义，bank 与 resource 绑定 | 对抗变异拒绝 |
| terminal 可提前 | 必须为 trace→唯一 PASS→唯一 `$finish`，finish 后无输出 | 对抗变异拒绝 |
| 可插入未知 boundary | boundary 集合、phase、`relation_records` 位置必须精确 | 对抗变异拒绝 |
| relation/FIFO 与 term 断链 | 从 K、5 路 gate、mask 按 builder 规则重建 20 条 term | mismatch=0 |
| TCFM5 `commit=0` 仍接受 | accepted term 必须 `commit=1`，last 唯一 | 对抗变异拒绝 |
| C0 被称为独立预测 | 改名为 measured-execute-tail rule reconstruction | 证据边界修正 |

Direct 重建规则与 RTL 一致：gate 按 role 首现顺序去重，相同 gate 合并
destination mask；K lane 升序，每个 lane 遍历全部唯一 gate。重建结果逐项比较
source、坐标、lane、gate、mask、term last 和 source last。

## 3. Backpressure 整改

固定 fixture 的 stall 数必须精确为 `4/1/18`，删除任一行即失败。每个 stall run
必须在下一拍由相同 payload 的事务接受；TCFM5 term 额外检查 stall 时
`commit=0`、接受时 `commit=1`。serializer 有 9 个连续双拍 run，能触发 monitor
的跨拍稳定性检查；Direct/TCFM5 term 仅为单拍 stall，不再过度声称连续稳定性
覆盖。

未受支持的 `QFIT_EREP_LEGACY_BIND_V4` 代码已删除；唯一受支持接入方式仍是
校准 TB 显式实例化三个 monitor。
