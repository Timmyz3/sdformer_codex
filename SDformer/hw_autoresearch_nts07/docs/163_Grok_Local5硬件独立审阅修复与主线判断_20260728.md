# Grok Local5 硬件独立审阅、修复与主线判断

**日期**：2026-07-28
**范围**：独立审阅 `docs/158`–`docs/162`、`rtl_local5/`、`tb_local5/` 与统一回归。
**结论等级**：当前是可验证的 Local5 投影子系统原型，不是可直接 DC/投稿的完整加速器。
**复现入口**：`./sim_local5/run_local5_parity_checks.sh`

---

## 1. 审阅结论

Grok 补齐的工作有实际价值：Local5 已具备

```text
行/窗口取数 -> 5 候选 score -> Shiftmax -> MFEP 多重集 term
           -> 命令桥 -> 投影累加 -> 窗口完成
```

但原回归和文档存在三个系统性问题：

1. 部分 golden 复用被测 RTL 叶模块，不能独立发现数值错误；
2. 顶层 `valid/ready`、`last` 和 `done` 边界存在会丢数据或提前完成的 P0 缺陷；
3. 当前“3-bank”只是单发射 banked accumulator 模型，不等于 DCTF 三 bank 并行架构。

修复后，Local5 RTL 的控制可信度明显提高，但软件/RTL 的边界 mask 语义尚未冻结，
因此 `H66d RTL-exact AEE=1.4486` 还不能直接作为本版 RTL 的部署精度。

## 2. 已发现并修复的问题

| 严重度 | 问题 | 后果 | 修复 |
|---|---|---|---|
| P0 | alpha-XNOR score 使用正半向上舍入 | ties 情况相差 1 LSB | 改为显式 ties-to-even RNE |
| P0 | Shiftmax gate 缩放使用 `×256` | Q1.7 gate 整体放大 2 倍 | 改为 `×128` |
| P0 | invalid candidate 进入分母 | 边界 token 的有效 gate 被错误压低 | RTL 改为真正 masked Shiftmax |
| P0 | `probe_valid` 寄存后仅凭 `ready` 提前推进 | 首个 probe 被跳过，整行无 edge | 改为状态组合 `valid`，只在真实握手推进 |
| P0 | 重复 probe / early-last 仍进入计算 | malformed row 可产生部分结果 | 异常行原子丢弃，不发 edge |
| P0 | `term_last` 绑定物理 lane31 扫描尾 | 稀疏尾部没有 last，窗口无法关闭 | 预数实际非零 term，最后一个真实 term 标 last |
| P0 | `run_done` 不等待投影完成 | 上层可能读取尚未提交的 Acc | 增加 `WAIT_PROJ`，以 `proj_done` 为完成条件 |
| P0 | 零 term 窗口没有结束命令 | 投影状态机永久停在 RUN | 增加有序 command-less close |
| P1 | 子模块错误非粘滞 | 早期错误在下一 destination 被清掉 | 顶层跨窗口执行粘滞保存 |
| P1 | explode 计数重复累加 | 性能账本夸大展开命令 | 删除逐拍重复计数 |
| P1 | 数组索引宽度告警 | DC/仿真工具行为边界不清 | 显式转换为整数索引 |

## 4. 仍然存在的关键缺口

### 4.1 P0：软件和本版 RTL 的 invalid-mask 语义不一致

当前软件先把 invalid score 填为最小值，再调用一个不接收 `valid` 的
`_rtl_shiftmax_gate_q17`。因此 invalid lane：

1. 仍进入 Shiftmax 分母；
2. 仍产生非零 gate；
3. 仍乘以 clamp 后的边界 K。

本版 RTL 实现的是真正 masked 语义：invalid lane 的 `exp=0、gate=0`。

在 `T=2, 9×9, 5-candidate` 中，每窗口有 72 个越界方向项，占 810 个候选的
8.89%，不能假设精度影响为零。必须做一次软件 G0：

```text
legacy min-fill/leakage
vs
true masked Shiftmax
```

在 valid825 上比较 AEE/AAE/spikes，并重新导出 RTL-exact trace。完成前，
本版 RTL 只能称“符合注释和标准 mask 语义”，不能称“符合当前 H66d checkpoint
已发表的 RTL-exact 数值”。

### 4.2 P0：现有窗口不是完整真实 `T=2×9×9`

当前 direct TB 使用 4/16 个合成 destination；line-buffer TB 使用 8-token 行。
尚未验证：

- 两个 timestep 独立的 9×9 stencil；
- `x=8` 到下一时间片 `x=0` 不得成为空间邻居；
- 12 个 attention module / 四个 stage 的真实边界 mask；
- 真实 ordered trace 下的 backpressure 与窗口切换。

### 4.3 “3-bank”不是架构贡献

`local5_multibank_projection_top` 当前是：

```text
单 cmd 输入 -> dest%3 -> 单个 Acc 更新
最大 1 IPC，并对同 bank 连续命令人为停 1 拍
```

它没有三个独立命令 reader、没有三路并行 weight read、没有三个同时提交的
bank executor。现有 conflict 数只是该模型的 stall 计数，不能证明 3-bank
提高吞吐，也不能写成 DCTF 并行架构。

建议在论文和代码说明中暂称：

> single-issue bank-conflict model

若 Local5 晋级主线，再实现真正的 3-reader/3-bank 或证明单 bank 已足够；
不能为了“看起来像架构”保留无收益的多 bank。

### 4.4 TARE 仍未进入默认窗口路径

TARE 行 TB 现已覆盖三种分类并逐项检查 gate，但 direct/window/linebuf 顶层仍实例化
直算 `local5_row_context_engine`。此外，定向 TB 的 SPARSE 命中不能替代真实 profile。
必须统计真实 `popcount(Kself xor Kneighbor)` 的 mean/p50/p90/p95/p99 和
`0/1–4/>4` 比例，才能决定 TARE 是否值得占面积。

### 4.5 STT 只是观测侧带

当前 STT 没有驱动取数、调度或资源分配，live 字段也未被消费。
它可以用于 assertion/trace，但暂时不能作为控制平面创新。

## 5. 六类论文机制的真实落地状态

| 来源 | Motion | Local5 当前 | 本土化方向 |
|---|---|---|---|
| Prosperity | 时间 residual | 拓扑 TARE 已有叶/行 TB | 静态 self-anchor 免在线匹配 |
| Bishop | TTB/density | ZERO/SPARSE/DENSE classifier | 改为 9-wide Stencil-Tile Bundle，而非照搬双核 |
| FireFly-T | bounded lane update | LIST4 residual | 复用 4-lane delta extractor |
| FLAT/FuseMax | score→SCS→projection 融合 | score→Shiftmax→MFEP→Acc 已串接 | 不物化 attention matrix |
| LoAS | 时间维驻留 | 3-row line-buffer 原型 | `T2×3-row×9-col` source-stationary 布局 |
| SpAtten | 级联 skip | invalid/zero-gate/zero-K exact skip | 做 exact issue 层次，不做有损 pruning |
| Phi | pattern+residual | 未实现 | 仅在真实边界/多重数模式低基数后再做 codebook |

结论：六类机制并非都已成为“贡献”。已进入 RTL 的是 TARE、融合链、line-buffer
和 exact skip；Bishop TTB 与 Phi pattern 目前仍只是设计候选。

## 6. Local5 与 Motion 的主线判断

| 维度 | Motion H67 | Local5 H66d |
|---|---|---|
| 当前 dyadic/RTL 精度 | H67 dyadic 约 1.4626 | dyadic 1.4475，旧 RTL-exact 1.4486 |
| score 邻域 | 全窗口/时间语义，控制较重 | 每 token 最多 5 候选，确定 stencil |
| 存储 | 大窗口 K/score/class 状态 | 3 行 K 驻留即可 |
| 现有硬件证据 | 更成熟，equal96/DCTF 较深 | 子系统刚闭环，真实 trace/PPA 弱 |
| 架构潜力 | GateStack/SCS/DCTF 故事完整 | 拓扑驻留+multiset 更应用专用、更可能低成本 |
| 当前风险 | 收益增量偏小 | mask 软件语义未冻结，TARE 命中未知 |

**判断**：

- 硬件潜力上，Local5 比 Motion 更适合作为最终主线；
- 证据成熟度上，Motion 仍是当前 fallback；
- 只有 true-mask valid825 保持优势且真实 TARE/MFEP profile 有利时，才正式换主线。

## 7. 建议收敛的架构主张

不要把 3-bank、双缓冲、STT 分别包装成贡献。建议收敛为一个主抽象和三个机制：

### 主抽象：Topology-Stationary Multiset Tileflow

固定 5-point 光流 stencil 使 K 在三行缓冲中驻留，score/gate 不形成稠密矩阵，
而直接变换为保留重数的投影 term。

### 机制一：Semantic-Anchor Exact Residual

self K 是确定拓扑锚点；按 `0/1–4/>4` 选择复用、LIST4 residual 或 exact replay。
是否主打取决于真实 SPARSE 命中率和 PPA。

### 机制二：Bounded-Multiset Gate-Stationary Projection

Local5 的同一 `(gate,lane,destination)` 可出现 1–5 次，必须保留 multiplicity。
以低基数 gate 为驻留键，weight/product 跨重数复用。这个性质比普通 set bitmap
更有 Local5 区分度。

### 机制三：Boundary-Aware Stencil-Tile Bundle

每个 9-token row bundle 携带：

```text
time_id、row_id、有效方向 mask、TARE class count、
gate-cardinality、MFEP term count、bank destination summary
```

它借鉴 Bishop 的 bundle-first 调度，但利用的是固定 9×9 边界和精确多重集语义，
不需要复制 dense/sparse 双核。是否加入硬件由 ordered profile 决定。

## 8. 下一阶段最小闭环

1. **软件 G0**：legacy leakage 与 true mask 的 valid825 A/B，冻结唯一语义。
2. **真实 profile G1**：导出 12 module 的 `T2×9×9` ordered trace，统计：
   boundary、TARE delta、gate cardinality、multiplicity、term、bank 序列、FIFO 峰值。
3. **架构 DSE G2**：同 trace 比较 Direct5、TARE、融合 MFEP、bundle 调度和真实
   1/3-bank reader，报告 mean/p95/p99 cycle、SRAM read、toggle 代理。
4. **RTL G3**：只实现 DSE 赢的结构；TARE 参数化接入默认窗口；补真实 162-token
   trace、随机反压和 SRAM 1/2-cycle latency。
5. **物理 G4**：packed-port wrapper、DC/STA/SAIF，同 SDC/SRAM macro 对齐
   Motion 和 Local5。

在 G0/G1 完成前，不继续扩展更多“架构名”；在 G2 证明三 bank 无净收益时，
直接删除论文中的三 bank 主张。

## 9. DATE 状态

当前硬件部分仍约为 **2.5–3.0/5，Borderline Reject**：

- 加分：真实算法优势、完整子系统 RTL、独立数值参考、协议边界修复；
- 拒稿风险：软件语义未闭环、无真实 Local5 trace、无同约束 PPA、
  多 bank 没有真实并行、默认窗口未接 TARE。

完成 G0/G1/G2 后若能证明：

```text
精度保持
+ 真实 trace 上 score/term/memory work 显著下降
+ Topology-Stationary Multiset Tileflow 的同约束 EDP 优于 Direct5/Motion
```

才具备把 Local5 抬为 DATE 主硬件线的条件。
