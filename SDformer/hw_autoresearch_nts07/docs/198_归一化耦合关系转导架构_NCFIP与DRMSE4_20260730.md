# 归一化耦合关系转导架构：NC-FIP 与 DRMS-E4

> **2026-07-30 第十四轮复审纠错：本文件中的 `fused` 数字只是不成立的
> 零转导周期上界。** final gate 依赖完整 denominator，不能在第一次求和
> scan 中产生。本路线已由 `docs/200_*ACRT*` 的两遍 all-class relation
> transduction 取代。原 FCIP 已淘汰，DRMS-E4 不单列论文贡献。

## 1. 本轮回答的问题

本轮不新增 RTL，先回答：

1. 原 FCIP 在与 B1 同带宽后是否仍有性能收益；
2. H67 的 SCS-Shiftmax 与 projection 能否形成跨算子架构创新；
3. 是否能在不复制异构双核的前提下消除极稀疏行尾延迟；
4. 哪些数字可以进入下一阶段，哪些必须冻结为负结果。

## 3. 原 FCIP 的负结果

公平模型统一：

- B1-Wx 与 FCIP-Wx 使用相同 x-token ingress；
- 单外部 term sink；
- 2/4 个完整 T-bit term context；
- 1-cycle relation read latency；
- 100%、90%、75% 三种 sink ready；
- 配对逐行 tail；
- S16 overflow 支付 abort 与 B1 replay；
- FCIP 不使用 class-lane occupancy oracle。

W4、ready100：

| 架构 | mean cycle/row | 相对 B1 |
|---|---:|---:|
| B1-W4 | 23.00 | 1.000x |
| B2-W4 联合关系平面 | 27.09 | 0.849x |
| 原 FCIP-W4 | 27.42 | 0.839x |

结论：

> **原 FCIP 性能主张被证伪，停止作为独立性能架构进入 RTL。**

它只保留容量观察：T162 关系 payload 中，B1 G4 目录为 20,736 bit，
B2 S16 联合平面为 82,944 bit，FCIP 含四个 context 为 8,586 bit。该数字
不是面积。

## 4. NC-FIP：归一化耦合因子交集平面

### 4.1 核心架构观察

SCS 已按 occupied score class 扫描并生成 final gate。若等到 projection
阶段再 replay token 或重新 union class，等于丢弃了这一确定性时刻。

NC-FIP 在该边界执行关系转导：

```text
score/classify
  ├─ C[score_class][destination]     S16 x T
  ├─ K[lane][destination]            32 x T
  └─ class histogram/count
            |
            v
SCS occupied-class scan
  class -> Q1.7 final gate
  C[class] --OR--> G[final_gate_slot][destination]   G4 x T
            |
            v
projection
  G[gate][segment] AND K[lane][segment]
  -> 2/4 bounded T-bit assembler contexts
  -> single term ready/valid sink
  -> shared DCTF projection backend
```

### 4.2 为什么是架构而不只是包装

NC-FIP 改变了三个系统边界：

1. **跨算子生产者/消费者合同**：SCS 不只输出数值 gate，还输出 projection
   所需的 destination relation；
2. **存储层次**：从 `G×L×T` 或 `C×L×T` 联合关系改为
   `C×T -> G×T` 与 `L×T` 因子平面；
3. **调度时刻**：稀疏关系在 normalization 中确定，不在 projection 中
   预测、搜索或 replay。

可用名称：

> **Normalization-Coupled Relation Transduction (NCRT)** 是总原则，
> **NC-FIP** 是其 projection 微架构。

### 4.3 explicit 与 fused 两个证据边界

- `explicit`：class fragment 转导周期完全串行支付；
- `fused`：class fragment 读与现有 SCS occupied-class scan 完全重叠。

W4、ready100：

| 实现边界 | mean cycle/row | aggregate speedup vs B1 |
|---|---:|---:|
| NC-FIP explicit | 21.36 | 1.077x |
| NC-FIP fused | 19.29 | 1.192x |

因此，收益是否达到 DATE 门槛完全取决于 SCS 转导能否在同一 class scan 内
完成。该重叠必须由 RTL 和综合证明，不能直接把 fused 数字写成结果。

## 5. DRMS-E4：无双核的精确关系模式切换

### 5.1 为什么放弃 DRMS-T16

早期 T16 方案隐含 B1 的 `G4×L32×T` 目录。如果保留该目录，NC-FIP 的容量
优势失效。因此 T16 不进入架构。

### 5.2 E4 模式

行开始前，K metadata 已精确给出 active-token count：

```text
active_token <= 4:
    从4-entry {class, token, K-mask}寄存器枚举非零lane
    每个lane event生成一个singleton destination-bitmap term
else:
    使用NC-FIP gate×K factor intersection
```

两种模式共享：

- class-to-gate 映射；
- K 数据；
- term ready/valid 接口；
- DCTF projection backend；
- Acc 和顺序合同。

它不是 Bishop 式 dense/sparse 双核，也不是 oracle：

- 判据只依赖投影前已经存在的 active-token count；
- singleton term 与 grouped term 在整数累加下精确等价；
- 不需要第二个 G4 directory；
- 模式选择不删除 token，不改变 Shiftmax denominator。

可用名称：

> **Deterministic Relation-Mode Switching (DRMS-E4)**。

### 5.3 初步结果

W4：

| sink ready | explicit speedup | explicit p99 slowdown | fused speedup | fused p99 slowdown |
|---:|---:|---:|---:|---:|
| 100% | 1.091x | 1.138x | 1.201x | 1.051x |
| 90% | 1.095x | 1.134x | 1.198x | 1.049x |
| 75% | 1.083x | 1.114x | 1.169x | 1.041x |

fused 边界达到“收益超过 15%、p99 低于 10%退化”的模型门槛；explicit
边界没有达到 15%。所以当前状态是：

> **允许进入最小 RTL 可行性验证，不允许宣称已获得 1.20x。**

## 6. 与既有工作的差分

| 工作/原则 | 借鉴 | 本土化差分 |
|---|---|---|
| Bishop/TTB stratifier | 用已知稀疏 metadata 选择执行形态 | 单共享 datapath；singleton/grouped relation 两种精确表示；无 ECP、无双核 |
| Sanger score-stationary | 稀疏关系驻留 | 驻留对象是 final-gate destination relation，且由 SCS 归一化直接产生 |
| FLAT/STAR 跨阶段 dataflow | 跨算子减少中间搬运 | class bitmap 在 normalization 边界转导为 projection relation |
| Prosperity exact reuse | 利用精确重复项 | gate-lane term 的重复由确定性 class-to-gate alias 产生，不做近似匹配 |
| PHI 类 metadata-first | 先处理稀疏 metadata | metadata 同时决定 relation mode 和 segment read，不改变网络语义 |
| StreamTensor/Canon | 描述符与数据流解耦 | descriptor 携带 stage、T、S、G、E4阈值；不把普通复用单列为贡献 |

不能声称发明 TTB、stationary dataflow、stratifier 或 descriptor。可声称的是
上述机制在 H67 的离散 class/gate 代数与 SCS 时序下形成的 NCRT 组合。

## 7. 最小 RTL 边界

只实现以下模块，不扩 full encoder 顶控：

1. `ncrt_class_segment_bank`：S16、3×64-bit segment；
2. `ncrt_gate_alias_fold`：class-to-gate、G4 slot、segment OR；
3. `ncfip_k_segment_bank`：32 lane、3 segment；
4. `ncfip_intersection_scheduler`：4-way 64-bit AND；
5. `ncfip_term_context4`：四个 T-bit bounded context；
6. `drms_e4_router`：4-entry token/K-mask 与 singleton term；
7. `ncrt_projection_top`：单 term sink、fallback、epoch 和回压；
8. 与现有 DCTF term backend 的 adapter。

必须有两个实现：

- `explicit`：class fold 单独占周期；
- `fused`：和真实 SCS class scan 同拍。

如果 fused 需要复制 SCS 读端口、形成长 OR 路径或降低频率超过收益，则该
创新淘汰。

---

## 8. 晋级与停止条件

进入 DATE 主贡献必须同时满足：

1. 多样本 T162 与 T450 real trace；
2. bit-exact：class count、gate、term、delivery、Acc 全部零失配；
3. random backpressure、overflow、abort/replay、跨 row epoch；
4. 同一 SDC、同一 memory rule 的 B1-W4/B2-W4/NC-FIP/DRMS；
5. DC/STA/SAIF 后 EDP 至少改善 15%；
6. 面积不增加，或面积增量由更大的能耗/吞吐收益覆盖；
7. 配对 p99 slowdown 低于 10%；
8. fused class fold 不降低目标频率。

任一情况发生则停止：

- fullres profile 的 final-gate cardinality 或 S16 overflow 明显恶化；
- fused RTL 不能隐藏 class fold；
- 同约束 EDP 改善低于 15%；
- 为 E4 引入完整 B1 directory；
- 为跳过 fragment 引入接近 B2 大小的 class-lane occupancy oracle。
