# DQFS 分段叶模块 RTL 证明与阶段签核

## 1. 本轮目的

第 215 号文档冻结了 DQFS 的无死锁接口合同。本轮回答三个实现问题：

1. 有限 context、有限 term 容量和有限 lane-way 下是否会死锁；
2. 一个 row 被拆成多个 segment 后，`row_last` 是否可能越过旧 segment；
3. 窄 term 目录是否能以综合友好的单写 reverse-link 结构实现。

## 2. 关键修正

### 2.1 资源 seal 不吞触发 term

capacity/way 满时，`in_ready=0`。旧 context 先封存，触发 term 保持在输入端，待空闲 context 出现后重新匹配并接受。资源不足因此只改变分段边界，不改变 term 集合。

### 2.2 年龄有序的 context drain

每次封存 context 时写入单调 `seal_seq`。排出端采用：

1. 非 `window_last` context 优先；
2. 同类 context 中 `seal_seq` 最小者优先；
3. 仅当没有普通 sealed context 时，才选择最终 window context。

测试台为每个输入 term 记录 `row_id`。当 DUT 发出 `member_row_last` 时，scoreboard 检查该 row 是否还有未发出 term。该检查在容量 seal、way seal、行交错和输出反压场景下通过。

### 2.3 单写 reverse linked list

目录保存每个 `(lane, gate)` group 的 tail。加入新 member 时，新 term 的 `prev` 指向旧 tail，目录 tail 更新为新地址，payload SRAM 只发生一次 term 写入。

输出顺序在 group 内反转，但最终整数累加允许交换律重排。本轮只证明输入项集合、结束标记层级与事务计数守恒，不声称逐周期 hardware-order 相同。

## 4. DATE 创新证据的正确位置

DQFS 的潜在架构价值不是“双缓冲”本身，而是把 Local5 的两个不同商结构放在同一个 framed execution contract 中：

- schedule quotient：相同源/目的关系的 destination work；
- value quotient：相同 `(lane, gate, epoch)` 的 product work。

本轮只证明 value-quotient framing 可以用有限资源无损实现。DATE 主张仍需由以下证据闭环：

1. 相同 producer 与相同 SRAM 规则下，对比 token stream、term-only、product cache、DQFS；
2. 真实 trace 上同时报告 product compute、term SRAM、stall、overflow 和 final Acc；
3. DQFS 与 TCFM 集成后证明 product 只生成一次并被多 destination 精确消费；
4. DC/STA/SAIF 证明窄 term SRAM 与额外控制逻辑的净 PPA 收益。

## 5. 阶段结论

> **DQFS 最小叶模块 RTL proof：GO；DQFS+product+TCFM 集成：NO-GO；论文性能主张：NO-GO。**

独立评审与真实128-bit product Pareto表明，16/16个DQFS配置被更简单
候选支配。下一阶段转向lane-local LRU与跨阶段无替换gate-slot表，不再
准备DQFS product/TCFM接口，也不用叶模块的generic cell数替代PPA。
