# H67 系统建模与服务器数据交接（2026-08-21）

## 1. 当前裁决

H67 ep35 的 checkpoint、100-sample attention NPZ 和全 1200 窗索引已经封成一个可验证交接包。普通 GitHub Git 不适合承载该包：checkpoint 和归档均超过普通 Git 单文件限制，而且 NPZ/权重不应混入源码提交历史。源码与小型合同走 Git；大数据用 `rsync`/`scp` 直传服务器并在服务器执行 SHA 校验。

建议传输：

```bash
rsync -ah --partial --append-verify \
  hw_autoresearch_nts07/system_handoff/packs/h67_ep35_system_trace_handoff_20260821.tar.zst \
  <server>:<destination>/
rsync -ah \
  hw_autoresearch_nts07/system_handoff/packs/h67_ep35_system_trace_handoff_20260821.tar.zst.sha256 \
  <server>:<destination>/
```

服务器端必须先执行 `sha256sum -c`，再按 `system_handoff/README.md` 的 `--verify-only` 合同核对归档内 manifest。该包是 attention trace complete，不是 full-network address-timed trace。

## 2. 全网络账本 v0

新增 `system_simulator`，从冻结 H67 ep35 100-sample profile 重建 79 个 Linear/Conv 类算子、93 条 ATLIF 记录、34 个激活对象，并绑定原有 attention RTL 校准锚点。

当前结果：

```text
status = PASS_TRANSACTION_LEDGER_MODEL_NOT_CYCLE_ACCURATE
Fixed cycles/frame envelope = 621,349,814
RQTB cycles/frame envelope = 620,661,134
speedup envelope = 1.001110x
Fixed attention share = 0.6659%
```

这些数字不能进论文主表。非 attention 算子仍是 96-lane activity-weighted 模型；attention 是 sample0 选中窗按 stage 克隆；二者还没有统一成面积公平、带 SRAM stall 的 cycle simulator。它们的价值是揭示：若非 attention 后端没有大幅并行化，RQTB 的局部 1.1865x 会被系统 Amdahl 稀释。

ATLIF 口径已纠正：它是 `T x T` 时间矩阵算子，MAC 数为 `output elements x T`。存储报告分别给出整段时间输出全部落地的上界与一行输出流式累加的最小驻留对象，不再将其写成膜电位 state，也不将 payload 冒充 SRAM 读写流量。

## 3. DSE 与存储边界 v1

```text
status = PASS_SYSTEM_DSE_ENVELOPE_NOT_CYCLE_ACCURATE
attention-only speedup limit = 1.199678x
non-attention scale for 1.01x system target = 9.43x
non-attention scale for 1.05x system target = 59.78x
non-attention scale for 1.10x system target = 179.53x
```

存储事实：

- INT8 unique weights 为 46,971,744 bytes；理想跨帧 64 MiB weight SRAM 可以全驻留。
- 最大激活对象为 73,728,000 bytes；64 MiB 仍无法单对象容纳。
- 最大 ATLIF 单输出行流式累加对象为 29,491,200 bytes；64 MiB 可逐个容纳所有该类对象。
- full-temporal-output buffer 是更保守的落地上界，不代表实现必须这样调度。
- CACTI 请求已生成；DRAMsim3 继续 fail-closed，直到存在带地址和时间戳的 trace。

## 4. 公平基线接口

`build_h67_baseline_registry.py` 只让 Fixed2S 与 RQTB2S 读取同一个本地账本。Prosperity 与 Phi-like 的行保持 `BLOCKED_MATCHED_ADAPTER_MISSING`，在以下合同统一之前没有 cycle/energy 数字：

- 全算子映射；
- lane 与频率；
- SRAM/DRAM 层次；
- INT8、binary 与 accumulate 的 OP 定义。

该 fail-closed 注册表用于防止把外部论文数字直接拼入本项目主表。

## 6. 尚未闭合

1. 将算子账本变成有资源占用、依赖、bank conflict 和 DMA overlap 的 cycle simulator。
2. 从调度器生成 address-timed SRAM/DRAM trace，接 DRAMsim3。
3. 在服务器运行 CACTI，并把实际宏参数回填到同一 baseline contract。
4. 为 Prosperity/Phi-like 实现 matched adapters，而不是引用外部加速比。
5. 增加跨 DSEC sequence、density/equal-rate 分层窗口。
6. 在新思服务器对关键 RTL 运行 DC/STA/SAIF/PTPX；该工作与系统 simulator 并行，不互相替代。

结论：当前已经消除“服务器缺 checkpoint/attention NPZ”的数据交接阻塞，并形成可重跑的全网络事务骨架；尚未达到论文级全网络 cycle/energy 表。
