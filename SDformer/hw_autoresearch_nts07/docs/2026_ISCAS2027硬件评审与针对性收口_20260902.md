## 论文身份：两个架构贡献与一个覆盖闭环

- 工作负载固定为 Motion C12 ep34：DSEC valid825 AEE 1.199514，全局 firing rate 5.6709%，checkpoint SHA 前缀 `4bbaf7fc`。
- 正确语义是“binary-event optical-flow workload with a typed-signed downstream execution protocol”。105 个配置 ATLIF wrapper 中，12 个 `sn2_q` 被 runtime bypass、调用数为 0，故 capture 调用 93 个（T2=48，T10=45）；这 93 个被调用点中另有 12 个 `attn_sn` 返回值在 fixed normal-inference call graph 下无消费者，故 graph-live service 为 81（T2=36，T10=45）。两组 12 不能混写。capture 中 93 个 ATLIF 输出均为 binary；81 不能扩张成“已物理删除且端到端等价”。
- 冻结 ep34 配置的 `hardware_quant_enabled=false`，同时保留 `binary_motion_xor_alpha=0.125`，H60 以 K 作为 value carrier。Q7 score、next-power-of-two integer row-sum Shiftmax 与 Q1.7 gate 只属于 M2045 部署候选，不能写成冻结 baseline 本身。
- C1：240 KiB 级容量、单口 parent、dead-write 约束下的 exact product capture。ep34 十样本同账本 1.694510x；九宏 28 nm 组件 166,514.312 um2，3 ns PT setup/hold 和 Formality 均闭合。
- C2：typed-signed K8 共享 Acc24 与端点。相对等带宽 K1x8 为 1.016728x cycles、4.550657x throughput/mm2、逻辑面积下降 77.6576%。TSBG 只能嵌入 C2，不能成为第四个并列贡献。
- C3：exact Fixed-T10 temporal service，承担算子覆盖与完整性。63,756.126 um2，DC/PT setup+hold 闭合；11,180 Formality 点仅为 M917 mapped 到 hold-repaired M1454 mapped 的 gate-to-gate 对照，并非 direct RTL-to-M1454 proof。没有公平 speedup，不在摘要单独造倍率。

## 对 Opus 审阅的采纳与否决

### 采纳

1. ep34 必须成为 ISCAS 唯一 workload/checkpoint 身份；旧 ep35 `docs/359` 是历史冻结物，不修改，也不与 ep34 数字混用。
2. 组件结果应采用 Prosperity/Phi 式证据三角：周期级模拟器给完整 trace，VCS 给协议/算术，DC/PT/Formality 给物理锚点；三类证据分列。
3. TSBG 的 2.533808x 和 29.41G/11.61G 都是 CPU premodel，不是 RTL、映射、同面积或系统倍率。VCS 目前只允许陈述 576->144 bundle 与 4608->1152 scalar request（-75%）。
4. M2029/M2030 只准入 matched logic-only scheduler ablation：ordinary/TSBG 为 249,710.452/249,739.810 um2，面积税 0.0117568%，两轴 3 ns setup 均过；hold 均为 -0.0164 ns。该物理点不能把 CPU 2.533808x 升成 RTL 倍率。

### 否决或降级

1. “Shiftmax 商天然都是 2 的整数幂，因此只需移位”不成立。部署分数是 Q7，`ttx_exp2_lut_q8` 对小数指数使用 16-entry LUT（例如 245、234、224），最终 Q1.7 gate 并非一般意义上的 2 幂。现有门控乘积仍包含 gate×weight。基础 Shiftmax/整数 exp2 也不是本项目首次提出。
2. 若把低指数 gate 直接清零，这是有损剪枝，必须给独立的 AEE Pareto；现有 profile 还显示 gate 接近均匀。attention 旧 envelope 仅约 0.59%，不适合占 ISCAS 主线。该想法最多保留为 future/附录筛选。
3. “8 个指数档只需 1--2 bit”在编码上也不成立；8 个状态至少需要 3 bit，且当前 fractional LUT 的码值远多于 8 个。
4. Motion-XOR 空窗预检只有在证明它超出既有 pair-empty/K-zero skip 的增量时才有意义；否则只是已有 exact skip 的重述。attention Amdahl 很小，不开新 RTL。
5. Acc24 缩位、序列哈希和 decoder 通道 skip 都缺当前 checkpoint 的全路径范围/非零分布证明；本轮不作为 P0。

## 合法的“论文 trick”

Prosperity/Phi 的高倍率来自明确的测量层级：cycle-accurate simulator 覆盖支持的 workload，RTL/DC/CACTI/DRAMsim3提供物理锚点，再选择公开且对其机制不利或有代表性的 baseline。可借鉴的是这种证据组织，不是模糊分母。

ISCAS 主表按以下列组织：Mechanism；workload/trace；baseline；cycle-model；VCS fact；logic/macro area；STA/Formality；power/energy；claim boundary。C1 的 1.6945x、C2 的 4.5507x、TSBG 的 2.5338x必须处在不同 metric/type 列，禁止相乘。外部 Prosperity artifact 的 2.46x/3.09x 只放 related-work/iso-workload 行并标 `not ours`。

## ep34 attention 只读快筛（不升主线）

为核对“二次幂分数跳表”是否存在无损 skip 空间，对 M1458 的全部 480 个 attention NPZ 做了逐文件只读统计；输入 `attention_qk/manifest.json` SHA256 为 `1543ea8a753992d46f36233016e73f7b2d2d363b126baa4cdbea9aa25ec3c3c9`。

- 共统计 79,920,000 个 Q1.7 gate，码值范围 85--112、共 28 个不同值，精确零 gate 为 0。70.54% 的 gate 等于 112；若按 `<112` 清零，已经是会删除 29.46% pair 的有损方案，而不是移位编码优化。
- Q/K 的 32-bit source 向量精确空率分别为 92.26%/83.49%，但这部分已属于既有 empty-Q/K-zero descriptor skip 的对象，不能二次计功。
- 相邻两个 timestep 的 Q/K 32-bit source 向量完全相等率分别为 88.20%/78.27%。这可作为 exact temporal reuse 的 workload 事实，但 attention 低 Amdahl 且与既有 T=2/RQTB 路径重叠，本轮不新开 RTL。

结论：该统计进一步否决“当前 gate 天然是少量二次幂码、可无损大量跳过”的说法。任何 gate threshold 必须单列有损 AEE Pareto；不进入 ISCAS P0，也不进入摘要或主表。
