# VL-GS-TTB 双线词表生命周期架构与最小 RTL 复评

> 日期：2026-07-31  
> 证据边界：本文包含 `[prof-ordered]`、`[exact-model]`、`[rtl]` 和
> `[open-synth]`；不包含 DC、STA、SAIF 或目标工艺 PPA。

## 1. 本轮结论

本轮没有把“字典压缩”直接冻结为 DATE 创新，而是完成了三项可证伪工作：

1. 在 Motion 真实 profile100 上建立 eager vocabulary/header 位数模型；
2. 在左右角色修正后的同一 1498-term Local5 producer 上重签 W4/W6/W8
   lane-local LRU 强基线；
3. 实现一个公共 slot decoder，以及 Motion eager encoder、Local5
   lane-local first-bind allocator 两个不同前端，并在独立反压下逐项恢复
   原始 9-bit gate。

阶段判定：

- Motion S4 最小协议 RTL：**GO**；
- Local5：S4/S6 都保留，**禁止预先冻结 S4**；
- “两条算法线共用同一前端”：**否**；
- “两条算法线共享同一消费端协议和参数化 decoder”：**已形成 RTL 证据**；
- VL-GS-TTB 作为 DATE 主贡献：**尚未晋级**，需真实 trace 集成周期、物理成本
  和多样本统计。

## 2. 为什么旧强基线必须作废重签

左右角色合同修正后，Local5 定向 trace 从 1494 项变为 1498 项。旧 LRU
报告仍绑定 1494 项及硬编码窗口边界，因此虽然日志显示 PASS，证据已经过期。

本轮将 trace schema 改为：

```text
seq,plane,y,x,lane,gate,mask,window_last
```

当前 projection slice 的 term backend 使用显式 `projection_close`，逐 term
`window_last` 实际为 0；TB 现在从 CSV 读取真实字段，不再伪造六个边界。
term 总数动态读取，LRU 期望 miss 由同一 CSV 上的独立 Python 模型计算后注入。

重新签核结果：

| 配置 | term | hit | miss/product start | product 减少 | tag compare |
|---|---:|---:|---:|---:|---:|
| W4 LRU | 1498 | 1036 | 462 | 69.16% | 5992 |
| W6 LRU | 1498 | 1345 | 153 | 89.79% | 8988 |
| W8 LRU | 1498 | 1345 | 153 | 89.79% | 11984 |

W6 已达到 W8 相同 miss，因此 W8 在该 trace 上被支配。完整 Icarus、
Verilator、SVA、lint、Yosys 和结构合同均重新 PASS。

旧文档 219/220 中的 1494-term 表只保留为历史快照，不能继续用于新方案公平
比较；本节和
`results/qfit_lane_product_cache_20260731/report.md`为当前口径。

## 3. 统一抽象不是“统一前端”

### 3.1 公共架构对象

VL-GS-TTB 把 gate vocabulary 从每条 term 携带的 9-bit 立即数，提升为有
建立、使用、异常旁路和失效时刻的架构对象：

```text
算法专用 producer
      |
      +-- update:   {set, slot, raw_gate}
      +-- primary:  {set, slot, use_exception, payload}
      +-- exception:{raw_gate}
      v
公共 slot decoder
      |
      +-- 直接索引 slot table
      +-- primary/exception exact join
      v
原始 gate + 原 payload，送入既有 projection
```

公共不变量：

1. update 必须先于引用该 slot 的 primary；
2. 一个生命周期内 slot 不允许被不同 gate 覆盖；
3. exception 只携带原始 gate，不能近似、剪枝或默认置零；
4. primary 与 exception 均通过 ready-valid，输出反压时 payload 稳定；
5. lifecycle end 前不得遗留 primary 或 exception。

### 3.2 Motion 前端

```text
SCS class enumeration
  -> context是否超过S
  -> fast: eager slot->gate header + slot body
  -> raw:  whole-context raw-gate body
  -> common decoder
```

SCS 完成一个 context 后已经知道完整 gate class 集合，因此可以先发布 header。
这不是在线 cache。当前 RTL 还允许未命中 term 走精确 exception，便于协议
容错；论文主模式仍应使用“整 context fast/raw 原子选择”。

### 3.3 Local5 前端

```text
FCSR ordered term(raw gate, lane)
  -> lane-local first-bind lookup
     -> hit: slot primary
     -> empty: update，再发slot primary
     -> full: raw exception
  -> common decoder(set=lane)
```

Local5 vocabulary 是流式发现的，生命周期为 weight-product epoch，而不是
Motion 的 SCS context。因此两个前端不能被写成同一个硬件过程。真正共享的是
下游协议、slot table 语义和 decoder 数据通路。

## 4. 真实数据驱动的参数结论

### 4.1 Motion profile100

输入为 H67 ordered profile100：

- 总 context：672000；
- active context：339689；
- gate-class/channel term：7101034；
- 原 9-bit gate key：63909306 bit。

| slots | fallback active-context | fallback term | gate-key 减少 |
|---:|---:|---:|---:|
| S2 | 12.0911% | 32.9798% | 51.3947% |
| S4 | 0.0280% | 0.1375% | **67.0931%** |
| S6 | 0 | 0 | 56.0817% |
| S8 | 0 | 0 | 55.5502% |

S4 优于 S6/S8 的原因不是 fallback 更少，而是 slot 编号仍为 2 bit；S6/S8
需要 3 bit。Motion S4 是当前 bit-model Pareto 点，但只代表 gate-key/control
流量，不代表总线 SAIF、乘法减少或端到端加速。

### 4.2 Local5 定向 W6 trace

| 配置 | product start | product 减少 | bypass | gate-key 减少 |
|---:|---:|---:|---:|---:|
| first-bind S4 | 384 | 74.37% | 288 | 29.92% |
| first-bind S6 | 153 | **89.79%** | 9 | **34.23%** |
| first-bind S8 | 153 | 89.79% | 0 | 34.23% |

S6 在当前 gate-key 和 product-start 两项上都优于 S4。S4 只有在 tag、slot
product、FIFO 和控制面积显著更小时才可能保留 Pareto 地位，因此必须通过
同约束综合判断。

同时，first-bind S6 与 LRU W6 都是 153 次 product start。当前可研究的差异
不是“额外减少乘法”，而是：

- LRU：每 term 做 6-way tag compare，并维护替换年龄；
- first-bind：上游 allocator 仍需查找 gate，但不写 LRU，term 链路只发送
  slot，decoder 直接索引；
- first-bind 的潜在收益来自跨阶段元数据前移、窄链路和稳定 product 生命周期，
  不能只凭 miss 数声称更快。

## 5. RTL 实现与验证

新增 RTL：

- `rtl_qfit/qfit_vl_gs_ttb_slot_decoder.sv`
- `rtl_qfit/qfit_vl_gs_ttb_motion_encoder.sv`
- `rtl_qfit/qfit_vl_gs_ttb_local_allocator.sv`

新增验证：

- `tb_qfit/tb_qfit_vl_gs_ttb_motion.sv`
- `tb_qfit/tb_qfit_vl_gs_ttb_local.sv`
- `sim_qfit/run_vl_gs_ttb_dual_line_checks.sh`

结果：

| 项目 | 结果 |
|---|---|
| Icarus Motion exact reconstruction | PASS |
| Icarus Local5 fill/hit/bypass reconstruction | PASS |
| Verilator assertions + 独立通道阻塞 | PASS |
| 三个叶模块 Verilator lint | PASS，无 DUT warning |
| 三个叶模块 Yosys synth-readable | PASS |

定向计数：

- Motion fast context：2 update、2 slot term、0 raw exception；
- Motion whole-context raw：0 update、0 slot term、2 raw exception、2 个输出
  stall；
- Local5：3 fill、1 hit、1 bypass、2 个输出 stall。

TB 额外强制覆盖两个相反次序：Motion raw context 的 exception 先于对应
primary 到达，
Local5 的 primary 先于对应 exception 到达。两个前端分别持有 pending 状态，
不再令任一通道的 `valid` 组合依赖另一通道的 `ready`；公共 decoder 按有序
exception 流完成无 sequence-tag join。

默认参数开放综合统计仅用于发现结构异常：

| 叶模块 | 默认参数 | Yosys cell |
|---|---|---:|
| slot decoder | SETS=32, SLOTS=6 | 130 |
| Motion encoder | SLOTS=4 | 73 |
| Local allocator | SETS=32, SLOTS=6 | 178 |

这些 cell 数不能当面积，不包含目标 SRAM macro、布线、时钟树和时序约束。

## 6. 与已有工作的差分边界

- **Bishop**：借 TTB header/body 纪律；不使用 ECP，改为 gate vocabulary
  生命周期与 exact fallback。
- **Prosperity**：借 exact reuse 原则；不做通用在线 product matcher，
  Local5 的键固定为 `(lane, gate)`。
- **Phi**：借 primary/residual 分层传输；exception 是原 gate 的精确旁路，
  不是 learned pattern 或近似 residual。
- **Sanger**：借 stationary 数据流分析；Local5 驻留 gate/product，
  Motion 当前只驻留 gate 映射，不夸大为 product stationary。
- **Bishop/LoAS 类 TTB**：本工作不是重新发明 token bundle，而是把 bundle
  的 header 语义改成本网络的有限 gate vocabulary，并给出 eager/incremental
  两种生命周期。

因此当前贡献应写成“借鉴后针对 all-binary gate vocabulary 的无损本土化”，
不能写成上述机制均由本工作首创。

## 7. 本轮独立 DATE 评审

RTL 实现前的独立评审为：

- 总体：2.7/5，Weak Reject；
- 架构创新：2.8/5；
- Motion S4 协议探针：GO；
- Local5 S4 冻结：NO-GO；
- 双线统一前端：NO-GO。

评审 P0 中“1498-term 强基线失配”已修复；“只有概念共享、没有物理公共
decoder”已通过参数化 decoder RTL 部分修复；但以下问题仍成立：

1. Local5 缺 post-G0 fullres 多样本；
2. 没有 depth-2/4/8 FIFO、异常流长距离领先和 flush 压力测试；
3. 没有与 raw-gate、LRU、pinned codebook 的同 producer 集成周期；
4. 没有目标工艺 DC/STA/SAIF；
5. 尚未证明公共 decoder 比两个专用消费端在 EDP 上更优。

本轮 RTL 完成后的第二次独立只读复评仍为总分 `2.7/5`、创新性 `2.8/5`、
Weak Reject。评审确认公共 decoder 和双向到达次序是实质进展，同时指出：

1. Motion fast context 逐 term miss fallback 与模型的 whole-context raw 合同冲突；
2. producer 在 lifecycle start 同周期仍可能对外给出 `ready`；
3. Local5 尚未接入与 LRU 相同的 product SRAM/乘法/Acc 边界。

前两项已经整改：Motion fast 未命中现在 fail-close，raw fallback 只能由
`lifecycle_raw_mode` 在 context 开始时整体选择；Motion TB 已分别覆盖完整 fast
与完整 raw context。两个 producer 均新增 active/end 状态，start/end 周期关闭
输入 ready，生命周期未清空时 end 会报错。第三项是下一阶段 P0，尚未完成。

## 8. 下一轮最小可证伪实验

优先级顺序：

1. 将 decoder 的单项 buffer 扩展为参数化 depth-2/4/8 primary/exception
   FIFO，并覆盖 exception 提前、primary 提前、flush 和 lifecycle end；
2. 对 Local5 S4/S6 与 LRU W4/W6 使用同一 1498-term producer、同一乘法器和
   同一同步 SRAM latency，统计总周期、FIFO p95/p99、compare、metadata write；
3. 对 Motion S4 回放 profile100 的 context 长度与 fallback 序列，统计 header
   周期能否与 SCS/上一 context body 重叠；
4. post-G0 到达后报告 Local5 多样本 mean/p95/p99，若 S6 first-bind 对 LRU
   没有 cycle/energy 优势，则淘汰 Local5 VL-GS-TTB；
5. 获得工艺库后统一 DC/STA/SAIF；在此之前只允许报告 RTL 和模型证据。

## 9. 当前论文贡献候选

可以继续验证但尚未冻结的架构贡献是：

> 一种面向 all-binary 事件注意力的 Vocabulary-Lifecycle TTB：它把有限
> gate vocabulary 作为跨 attention-projection 的一等架构对象，用算法相关的
> eager 或 incremental producer 建立词表，并由公共 exact slot/exception
> consumer 在不改变整数结果的条件下缩窄 term 控制流。

它比“做了一个 LRU cache”更具体，但是否足以成为 DATE 独立贡献，最终取决于
强基线下的周期、EDP 和多样本外推，而不是命名。
