## 2. 已确认并修复的 P0 统计错误

### 2.1 Local5：唯一 term 与 destination delivery 混用

原始 profile 对两个统计量有明确区分：

```text
mfep_multicast_terms          = 13,732,741
destination_gate_lane_groups = 153,748,435
```

前者表示跨 destination 去重后的 `{gate,lane,multiplicity}` product identity；后者表示必须实际送达 accumulator 的 destination group。

旧模型错误地令：

```text
exact_projection_terms = mfep_multicast_terms
exact_destination_beats = mfep_multicast_terms
```

等价于免费消掉约 `153,748,435 / 13,732,741 ≈ 11.2×` 的 destination fanout。随后 ISHD 又按假设 fanout 缩减一次 weight fetch，构成重复获益。

修复后：

```text
weight/product work = mfep_multicast_terms
delivery work       = destination_gate_lane_groups
```

并删除 `local5_hierdesc_fanout_assumption` 设计参数。

### 2.2 Motion：M4 delivery 与 PPDI 重复计益

Motion profile100 已使用：

```text
projection_gate_multicast_delivery_m4
```

旧模型又乘以 `1-30.27%`。但 `30.27%` 只来自 sample0/window0 的标量 destination 命令，不是 profile100 M4 命令，也不是 RTL 周期。

修复后：

- profile100 直接使用 M4 delivery；
- 删除全局 `motion_ppdi_command_reduction`；
- 在逐 term、逐 parity、profile100 ordered 统计完成前，Motion 和 Local5 均不叠加 PPDI。

### 2.3 T162 证据标签

旧代码对 T162 也调用比例外推函数，使实测 profile 被标成 `[外推-25/9]`。

修复后：

- `target_tokens == source tokens` 时原样返回；
- T162 保留 `[prof-preG0]` 或 `[prof-ordered]`；
- 只有 T450 使用 `[外推-25/9]`。

## 4. 修正后的双线结果

默认硬件资源：

```text
Direct score: 32 lane
Static anchor score: 32 lane + W4 residual lane
Projection: 3 bank × 256 bit/cycle
Activation SRAM: 128 bit/cycle
```

score-lane 归一代理定义为：

```text
lane-normalized proxy = raw speedup × 32 / (32 + W)
```

它只用于在没有 DC 面积时阻止“免费增加 W lane”，不能当作真实面积归一吞吐。

| 主线 | raw 模型加速 | lane 归一代理 | fabric metadata | tail 证据 |
|---|---:|---:|---:|---|
| Local5 T162 | 1.583× | 1.407× | 11.96% | histogram 下界，非 ordered FIFO |
| Motion T162 | 1.795× | 1.595× | 6.02% | 真实 ordered delta trace |

判定：

- Motion：模型门槛通过，但尚未得到 profile100 projection cycle-accurate RTL 和 PPA；
- Local5：周期模型有潜力，但 metadata 超过 10%，且没有 ordered tail，暂不晋级；
- T450 两线结果仍是 `25/9` 线性外推，不是 fullres 性能证据。

因此当前表中必须写：

> `online-matcher oracle`，不是 `Prosperity baseline`。

下一阶段需要：

1. 真实运行官方 reference workload，确认环境和输出字段；
2. 增加 H67/Local5 二值矩阵导出格式；
3. 写 Prosperity FC/attention adapter；
4. 在相同输入矩阵上报告 official Prosperity cycles、reads/writes、preprocess stall；
5. 单列算法语义不匹配项，不能把普通 FC product sparsity 直接冒充 H60/Local5 attention。

## 6. 创新点重新分级

| 候选 | 当前等级 | 是否单列 DATE 贡献 | 晋级条件 |
|---|---|---|---|
| 静态拓扑锚定 exact residual execution | 架构候选 | 有潜力 | 双线真实 ordered、RTL 校准、PPA |
| ISHD header/continuation | 编码优化 | 否 | 独立 RTL、escape、EDP ≥15% |
| TTB/STT | 调度支撑 | 否 | 与 C1 形成不可分的 exact issue 数据流 |
| SCS→term handoff | 融合数据流 | 不能单列 | 证明零物化流量和 PPA |
| PPDI | 条件候选 | 否 | profile100 逐 term parity 统计和 RTL |

当前最有可能形成主贡献的是：

> **基于固定时空拓扑的 exact anchor/residual execution：Motion 使用时间对锚点，Local5 使用 self/neighbor stencil 锚点；两线共享 TARE 叶模块，但采用不同 descriptor 和 score 语义。**

这比单独包装 DCTF、双 context 或 ISHD 更可辩护，因为创新源来自本网络可验证的时空结构，而不是常规缓冲与编码机制。

4. DC/STA/SAIF 使用同 SRAM macro 规则、同 SDC、同 PVT；
5. 最后做 full-encoder Amdahl、FPS 和 energy/frame。
