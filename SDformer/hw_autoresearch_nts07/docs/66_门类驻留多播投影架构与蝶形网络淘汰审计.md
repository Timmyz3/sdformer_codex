# 门类驻留多播投影架构与蝶形网络淘汰审计

> 2026-07-13语义修正：本文早期使用“score class”描述投影复用键。该说法只在同一
> Shiftmax row内成立；跨row或跨window时，分母不同会使相同score得到不同gate。当前实现与
> 后续RTL一律以RTL Shiftmax最终输出的9-bit无符号Q1.7 `gate_code`为复用键。文中的历史
> score-class统计只保留为前端/SCS对照，不再用于冻结跨窗口投影架构。

**日期**：2026-07-13  
**对象**：H67 主线、H68/TTX 部署兼容模式  
**结论状态**：架构候选已形成，整数语义已验证；真实 profile100、RTL、DC、SAIF 尚未签核

## 1. 先给结论

1. 不再把“异构双核”预设为主创新。H67/H68 的全网 workload 分布接近，但同一模型内部 12 个 block 的稀疏度差异很大，更适合统一同构核加 descriptor 配置，而不是复制 dense/sparse 两套算术核。
2. 不把通用蝶形 zero skipper 作为主创新。复旦 ISSCC 2023 已经把蝶形数据分配网络用于局部细粒度、全局粗粒度稀疏权重的特征抽取，并做了存内传输门实现。直接照搬既不新，也未必适合当前动态 K-event 数据流。
3. 时间维 K0/K1 完全相同事件的真实复用率目前只有约 10%，不足以支撑全局 butterfly 或复杂时间复用网络。H67 恢复值为 9.98%，H68 为 10.58%；S0 约 13%，后续 stage 约 1% 到 2%。
4. 当前更强的候选是 **GCM-P（Gate-Class Multicast Projection，门码类驻留多播投影）**：直接使用Shiftmax最终Q1.7 gate code，对同一 `(final gate code, input channel)` 只生成一次 `gate×weight` 向量，再按K-event bitmap多播到不同token累加器。
5. GCM-P 保持每个 token 的独立输出，不把 token 结果错误相加。它减少的是乘积生成和权重读取，活动 token 的累加写与多播目的数仍然存在，必须单独计费。
6. GCM-P 是否进入 RTL 由正在排队的真实 ordered profile 决定。若乘积项减少不足、class-slot 溢出频繁或多播事务成为瓶颈，则退回现有 CCSP/FGP 稀疏投影，不为论文强行保留。

## 3. 精确数学重排

H67 部署路径为token-wise selector：

```text
score_n -> RTL Shiftmax -> final_gate_code_n
attn[n,d] = K[n,d] * gate_n
y[n,o] = sum_d attn[n,d] * W[d,o]
```

令`g(n)`为token `n`的最终Q1.7 gate code：

```text
y[n,o] = sum_d K[n,d] * (g(n)/128 * W[d,o])
```

统计和硬件中的一条row对应`(window, head)`。对每个row内的`(g,d)`，或对同一
`(block, head)`的一组window内的`(g,d)`：

1. 只计算一次向量`P[g,d,:] = g * W[d,:]`；
2. 查询`D[g,d] = {n | g(n)=g且K[n,d]=1}`；
3. 将`P[g,d,:]`多播并累加到所有`n in D[g,d]`；多个head的输入通道区间互不重叠，最终仍按原projection权重累加到同一token输出。

这里的`d`必须映射为拼接head后的全局input channel，或在地址中显式携带head。不同head
不能只凭相同gate code和局部lane编号合并。跨window分组只允许同一block/head、同一折叠权重
版本；不同block的权重不同，严禁合并。

该重排不交换非结合浮点运算。部署合同使用整数 gate、整数 weight 和足够宽的整数累加器；最终截位、饱和和 bias 顺序必须与软件定点参考一致。若软件在每次加法后截位，则不能采用先累加后统一截位，必须按 reference 冻结顺序。

## 4. GCM-P 微架构

### 4.1 总数据流

```text
128-bit temporal-pair input
        |
        v
PESF/score engine -- Motion-XOR(H67 only)
        |
        +--> PCCC + class histogram + occupied bitmap
        |                         |
        |                         v
        |                    SCS/Shiftmax
        |                         |
        v                         v
active K replay ----------> gate-class directory
        |                         |
        +--> class-channel destination bitmap
                                  |
                                  v
weight-column stationary product generator
                                  |
                                  v
segmented bitmap multicast network
                                  |
                                  v
banked token-output accumulators -> projection quant/bias -> RPI
```

### 4.2 核心模块

| 模块 | 功能 | 是否新增 |
|---|---|---|
| score/class frontend | 生成 H67/TTX score class | 复用 TESSA/PESF |
| class directory | 保存 class ID、gate、32-bit occupied-channel bitmap | 新增 |
| destination bitmap SRAM | 保存每个 class/channel 的 162-bit token 目的 mask | 新增 |
| product generator | 一次读取 `W[d,:]` 并计算 `gate[c]×W[d,:]` | 新增 |
| segmented multicast | 每拍向 M 个 token accumulator 投递 | 新增 |
| token accumulator banks | 保持每个 token 输出独立 | 改造 FGP |
| direct fallback | class overflow 或关闭 GCM-P 时逐 active-entry 投影 | 必须保留 |

### 4.3 存储组织

设 class slot 数为 `S`，head dim 为 32，窗口 token 数为 162：

```text
destination bitmap = S * 32 * 162 bit
S=4: 20,736 bit = 2.53 KiB/context
S=8: 41,472 bit = 5.06 KiB/context
```

class directory 每 slot 约为：

```text
class_id(8) + gate_q17(8) + occupied_channel_bitmap(32) + valid/metadata
```

输出累加器不保存全部 `162×Cout`。按 16 token × 16 output-channel 分块，产品向量寄存器在 11 个 token mask segment 间保持，随后切换 output-channel tile。该分块降低 accumulator SRAM 端口和寄存器面积，但不会丢失跨 162 token 的产品复用。

`S=4/8` 目前只是参数，不是冻结值。最终选择取决于真实 `active_projection_classes` 的 p99 和 overflow 比例。

### 4.4 为什么首版不需要完整蝶形网络

多播目的集合已经是 162-bit bitmap，不需要先把动态事件重排成连续向量。首版采用：

```text
bitmap -> 16-bit segment -> priority/select M destinations -> bank conflict check
```

只有当以下条件同时成立时，才比较 butterfly/Benes 版本：

- M=4/8 的分段扫描使 product generator 空闲超过 20%；
- bank-aware 简单 selector 无法把冲突周期降到理论下界的 1.15 倍以内；
- butterfly 版在同工艺、同频率、同 SRAM 下带来至少 15% 子系统 EDP 改善；
- 布线与时序开销没有使 Fmax 下降超过 5%。

因此蝶形网络是一个可淘汰互连实现，不是论文预设贡献。

## 6. HIT-Flow 的系统级架构位置

GCM-P 不是独立小核，而是 HIT-Flow 全 encoder 的 attention-to-projection 后端：

```text
descriptor scheduler
  |
  +--> DP-TME cluster: 45个T10、36个T2 ATLIF点时间复用
  |
  +--> LR-HTT: single/fanout/pair生命周期事件路由
  |
  +--> TESSA/PCCC/SCS: 12个attention block时间复用
  |         |
  |         +--> GCM-P: class-gated product + token multicast
  |
  +--> RPI: ADD、S0/S1/S2 skip、多位残差精度岛
```

硬件不会按 PyTorch module 数实例化 105 个 ATLIF 或 12 个 Shiftmax：

- 105 是安装模块数；固定部署正常路径只有 81 个活跃结果；
- DP-TME 阵列由 descriptor 顺序执行 45 个 T10 和 36 个 T2；
- TESSA/SCS/GCM-P 是共享 attention 后端，12 个 block 只加载不同 descriptor、shape 和量化参数；
- row context 是隐藏延迟的状态槽，不是复制完整算术核；
- H68/TTX 通过编译期关闭 Motion-XOR、缩减 class range，不实例化另一套核。

## 7. 论文可写的架构贡献

只有完成真实 profile、RTL 和同约束 DC 后，才可使用以下表述：

1. **软硬件协同贡献**：把 all-binary 事件注意力的量化 score 显式冻结为 gate equivalence class，使 Shiftmax normalization metadata 同时成为后续 projection 的精确计算复用码，而不是只用于 softmax 加速。
2. **数据流架构贡献**：提出 GCM-P，将 class-stationary normalization、K-event bitmap 和 weight-column stationary projection 融合，避免物化 gated-K，并将每个类通道乘积精确多播到独立 token accumulator。
3. **全 encoder 架构贡献**：提出 HIT-Flow 的 descriptor 驱动共享执行体系，用 DP-TME、生命周期路由、GCM-P 和残差精度岛统一执行 T10/T2 ATLIF、12 个 H67/H68 attention block 和三条长 skip。
4. **可证伪设计方法**：以真实 ordered trace 联合选择 class slots、多播宽度、row contexts 和 fallback，不把稀疏率直接等同于 speedup，并用同 RTL 的 direct/GCM/butterfly 模式做消融。

不能写成贡献：

- 发明 butterfly、multicast、product sparsity、Shiftmax 或 operator fusion；
- 仅凭随机参考的 79.15% 声称 H67 乘法减少；
- 将 Yosys generic cell 数当作 DC PPA；
- 把 105 个 PyTorch module 写成 105 套硬件实例；
- 忽略多播累加与目的 bitmap SRAM，只报告乘法减少。

## 9. 同约束基线与评价口径

必须比较：

| 基线 | 用途 |
|---|---|
| B0 dense gated-K + projection | 不利用 K-zero 和 class reuse |
| B1 active-entry sparse projection | 只利用 K-zero |
| B2 temporal-union projection | 只利用 K0/K1 exact reuse |
| B3 GCM-P direct fallback | 同存储、同累加器，不启用 class multicast |
| B4 GCM-P segmented bitmap | 主候选 |
| B5 butterfly/Benes compaction | 复旦/SIGMA 类互连消融，不默认胜出 |

统一口径：

- 面积：标准单元、SRAM macro、clock tree 估计分别报告；
- 功耗：真实 trace 产生 SAIF/VCD，分 score、class、weight SRAM、product、multicast、accumulator、clock；
- 吞吐：每帧周期、attention row p50/p95/p99、30 FPS 约束；
- 存储：bit 数、bank 数、端口数、读写事务，不只报 tensor 容量；
- 控制：descriptor 数、FSM 状态、fallback/overflow、FIFO p99、stall 原因；
- 正确性：软件定点参考、RTL、门级仿真和 LEC 分层签核；
- PPA：同工艺、同电压、同频率目标、同 SRAM 假设，不跨论文直接比较绝对 TOPS/W。
