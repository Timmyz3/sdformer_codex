# NTS11 深度文献调研与可迁移设计范式

**版本**：2026-06-15  
**目标**：为 NTS11 统一 H60 硬件设计寻找可迁移的设计范式、模块结构和论文叙事。  
**原则**：优先一手论文、会议页面、arXiv、作者主页；二手综述只作检索线索。

---

## 1. 本轮调研结论

现有论文已经足够支撑 NTS11 第一版硬件设计，但还不足以直接写最终 DATE related work。  
建议把文献分成四条线：

1. **Spiking Transformer 专用加速器**：直接迁移数据流和核心结构。
2. **Spiking Transformer token / temporal sparsity**：迁移 token-time bundle、token pruning、temporal early exit。
3. **事件光流与 neuromorphic optical flow**：迁移任务叙事、端到端低功耗评测口径。
4. **通用稀疏 / 事件驱动硬件范式**：迁移 sparse/dense stratifier、SRAM 布局、zero-skipping。

对 NTS11 最关键的三条设计范式：

| 范式 | 来源 | 迁移到 NTS11 |
|------|------|--------------|
| Token-Time Bundle | Bishop | window × timestep bundle 调度 |
| sparse/dense stratifier | Bishop / FireFly-T | 低密 bundle 走 sparse，高密 bundle 走 dense |
| byte/bit packed event SRAM | FireFly-T / SNN accelerator | 1-bit binary、2-bit ternary Q/K、gate buffer |

## 2. 第一梯队：必须精读

### 2.1 Bishop：Sparsified Bundling Spiking Transformers on Heterogeneous Cores with Error-Constrained Pruning

链接：

- https://arxiv.org/abs/2505.12281
- https://dl.acm.org/doi/10.1145/3695053.3731063

核心思想：

| 机制 | 说明 |
|------|------|
| Token-Time Bundle | 把多个 token 和多个 timestep 打包成调度单元 |
| heterogeneous cores | dense core 与 sparse core 同时存在 |
| stratifier | 根据 bundle 稀疏度分流到不同 core |
| Bundle Sparsity-Aware training | 训练时鼓励 bundle 级结构稀疏 |
| Error-Constrained Pruning | 在注意力前后裁剪 Q/K/V 活动，并控制误差 |
| TTB attention core | 用简化 AND / accumulate 支持 spiking attention |

对 NTS11 的直接迁移：

1. 把 NTS11 的 H60 window 按 `window × timestep` 打包。
2. 对每个 bundle 统计 density。
3. 空 bundle 直接 skip。
4. 低密 bundle 走 sparse event engine。
5. 高密 bundle 走 dense/vector event engine。
6. 把 TTB-2 作为第一版硬件 scheduler，而不是一开始做复杂动态 token pruning。

NTS11 需要补的数据：

```text
profile_bundle_density.py
```

要证明：

```text
TTB-2 下 empty/low-density bundle 足够多，值得硬件支持。
```

论文可讲法：

> Bishop 证明 spiking transformer 的稀疏不能只看单个 spike，而要看 token-time 结构。NTS11 采用统一 H60 后，所有 encoder attention 都具有相同 window/timestep 结构，因此比 mixed datapath 更适合 TTB 调度。

### 2.2 FireFly-T：High-Throughput Sparsity Exploitation for Spiking Transformer Acceleration with Dual-Engine Overlay Architecture

链接：

- https://arxiv.org/html/2505.12771v1
- https://www.semanticscholar.org/paper/6c68ab897b7dce8065366d5478cc0c0113048335

核心思想：

| 机制 | 说明 |
|------|------|
| dual-engine overlay | sparse engine + binary attention engine |
| sparse decoder | 同时抽取多个非零 spike |
| binary attention engine | 针对 spiking attention 的 AND-PopCount 类计算 |
| SRAM byte-level write | 减少 3D 数据流转置 buffer |
| orchestrator | 统一调度两个 engine |

对 NTS11 的直接迁移：

1. NTS11 不应把所有东西塞进一个大 PE 阵列。
2. 应拆成：
   ```text
   Sparse/Event MAC engine
   H60 attention engine
   Dense decoder engine
   ```
3. H60 attention engine 内部用 ternary compare-popcount 替代 binary AND-PopCount。
4. Q/K event SRAM 要用 packed layout，避免 H60 前后频繁转置。

论文可讲法：

> FireFly-T 的 binary attention engine 说明 spiking attention 值得单独做硬件核。NTS11 的差异是 Q/K 为 ternary events，score 由 TX/SC consensus 产生，并通过 single Shiftmax gate 输出 gated-K。

### 2.3 Spiking Transformer Hardware Accelerators in 3D Integration

链接：

- https://dl.acm.org/doi/10.1145/3676536.3676826
- https://gtcad.gatech.edu/www/papers/iccad24-boxun.pdf

核心思想：

| 机制 | 说明 |
|------|------|
| 3D integration | memory-on-logic / logic-on-logic 降低数据搬运 |
| spiking transformer mapping | 针对 attention / MLP 数据流做物理设计 |
| activation movement | 强调数据搬运是主要瓶颈 |

对 NTS11 的直接迁移：

1. NTS11 不能只报 popcount 省电。
2. 必须单独建模：
   ```text
   Q/K event SRAM traffic
   score buffer traffic
   gate buffer traffic
   downsample event traffic
   decoder dense traffic
   ```
3. 架构图里要把 SRAM bank 和 data movement 画出来。

论文可讲法：

> 3D Spiking Transformer 工作提醒我们，spiking transformer 的瓶颈常常是数据移动。NTS11 的贡献不是只减少 arithmetic，而是把 mixed encoder datapath 收敛成统一 H60 event dataflow，降低控制和缓冲复杂度。

### 2.4 Hardware Efficient Accelerator for Spiking Transformer With Reconfigurable Parallel Time-Step Computing

链接：

- https://papers.cool/arxiv/2503.19643

核心思想：

| 机制 | 说明 |
|------|------|
| parallel timestep | 并行处理多个 timestep |
| reconfigurable neuron | 降低多 timestep 延迟和状态存储 |
| vectorized processing | 支持卷积和矩阵类操作 |

对 NTS11 的直接迁移：

1. 不要默认 T=10 完全串行。
2. 可以先做 TTB-2：两个 timestep 一组。
3. 对 ATLIF wrapper 共享 threshold，但 bundle 内并行比较。
4. 对 H60 score engine 复用 Q/K event tile。

论文可讲法：

> NTS11 的 T=10 spiking encoder 可以通过 bundle 化缓解逐 timestep 重复读权重的问题。第一版不追求全 T 并行，而采用 TTB-2 作为面积/控制折中。

## 3. 第二梯队：token sparsity 与 attention 稀疏

### 3.1 STATA：Towards Efficient Spiking Transformer: a Token Sparsification Framework

链接：

- https://proceedings.mlr.press/v235/zhuge24b.html
- https://raw.githubusercontent.com/mlresearch/v235/main/assets/zhuge24b/zhuge24b.pdf

核心思想：

| 机制 | 说明 |
|------|------|
| timestep-wise anchor token | 跨 timestep 标准化选择重要 token |
| dual alignments | 减少 token sparsification 造成的性能退化 |
| training/inference acceleration | 同时服务训练和推理 |

对 NTS11 的迁移：

1. 不直接照搬训练框架。
2. 借鉴“跨 timestep 选择标准要一致”。
3. 在 H60 gate stats 中统计不同 timestep 的 token 重要性稳定性。

可落地动作：

```text
gate_topk_overlap(t, t+1)
anchor_token_stability
```

### 3.2 SPARTA：Spike-Timing-Based Prioritization

链接：

- https://arxiv.org/abs/2508.01646
- https://arxiv.org/html/2508.01646v1

核心思想：

| 机制 | 说明 |
|------|------|
| spike timing cue | 使用 firing pattern、spike timing、inter-spike interval |
| competitive gating | 选择重要 token |
| sparse attention | 降低 attention token 数 |

对 NTS11 的迁移：

1. NTS11 当前没有 spike timing priority。
2. 可作为后续 P1/P2 扩展：用 ATLIF firing timing 辅助 gate skip。
3. 现阶段只做 profiling，不引入新模型机制。

### 3.3 ADAPT：Training-Free Adaptive Token Pruning and Hierarchical Sparsity

链接：

- https://63dac.conference-program.com/presentation/?id=RESEARCH1480&sess=sess120

核心思想：

| 机制 | 说明 |
|------|------|
| training-free adaptive token pruning | 不重训，根据 token diversity 与 spike activity 剪 token |
| hierarchical sparsity | 不只看 bit-level，也看 token/block 级稀疏 |
| algorithm-hardware co-design | 算法剪枝与硬件调度一起设计 |

对 NTS11 的迁移：

1. 当前最适合做 training-free profiling，而不是马上改训练。
2. 对 H60 gate 做 token diversity / activity 统计。
3. 若 token 多数低贡献，可引入 runtime token skip。

### 3.4 C-STEP：Temporal Early Exit

链接：

- https://www.date-conference.com/proceedings-archive/2026/DATA/1559.pdf

核心思想：

| 机制 | 说明 |
|------|------|
| temporal early exit | 部分 timestep 足够时提前停止 |
| early time-step skipping | 跳过贡献小的时间步 |
| spatio-temporal reduction | 从时间维减少计算 |

对 NTS11 的迁移：

1. T=10 是 NTS11 的固定成本之一。
2. 可以统计每个 timestep 对 H60 gate / output 的贡献。
3. 若后续 timestep gate 变化小，可考虑 temporal early exit。

当前不建议马上做 early exit，因为会影响精度，需要额外训练或校准。

## 4. 第三梯队：事件光流与 neuromorphic optical flow

### 4.1 Spike-FlowNet

链接：

- https://www.ecva.net/papers/eccv_2020/papers_ECCV/papers/123740358.pdf
- https://github.com/chan8972/Spike-FlowNet

核心思想：

| 机制 | 说明 |
|------|------|
| hybrid SNN/ANN optical flow | 前段利用 spike 稀疏，后段保留 ANN 表达 |
| event-based optical flow | 面向 MVSEC 等事件数据 |
| energy-efficient network | 以事件稀疏和混合结构换能效 |

对 NTS11 的迁移：

1. 相关工作中可用来说明事件光流 + SNN 的任务背景。
2. 也提醒我们：decoder 保留 dense 路径并不丢人，关键是整体能效。

### 4.2 OF_EV_SNN：Optical flow estimation from event-based cameras and spiking neural networks

链接：

- https://www.frontiersin.org/journals/neuroscience/articles/10.3389/fnins.2023.1160034/full

核心思想：

| 机制 | 说明 |
|------|------|
| DSEC + SNN optical flow | 与我们任务最接近 |
| U-Net-like SNN | 事件光流网络结构 |
| low-power motivation | 事件相机 + SNN 的硬件动机 |

对 NTS11 的迁移：

1. 用于 related work 的任务线。
2. 对比我们从 U-Net SNN 扩展到 spiking transformer + H60 attention。

### 4.3 ASNA-Flow

链接：

- https://www.researchgate.net/publication/394992601_ASNA-Flow_An_Efficient_Asynchronous_Neuromorphic_Accelerator_for_Real-Time_Event-Based_Optical_Flow

核心思想：

| 机制 | 说明 |
|------|------|
| asynchronous neuromorphic accelerator | 面向实时事件光流 |
| 28 nm CMOS | 可作为工艺/功耗对标 |
| 104 FPS / 7.9 mW | 极低功耗事件光流参考点 |

对 NTS11 的迁移：

1. 作为事件光流硬件对标。
2. 但 ASNA-Flow 与 transformer attention 不是同一复杂度，不应直接宣称击败。
3. 可强调 NTS11 面向更复杂 SDformerFlow 类模型。

### 4.4 SENECA 上的 ANN vs SNN optical flow

链接：

- https://arxiv.org/abs/2407.20421
- https://research.utwente.nl/en/publications/event-based-optical-flow-on-neuromorphic-processor-ann-vs-snn-com-2/

核心思想：

| 机制 | 说明 |
|------|------|
| hardware-in-loop | 实测时间和能耗 |
| activation sparsification | ANN/SNN 公平比较 |
| SNN lower pixel-wise spike density | SNN 能效来自更少状态访问 |

对 NTS11 的迁移：

1. 能效评测要公平，不能只用 theoretical SOPs。
2. 需要把 memory access 纳入 NTS11 energy model。

## 5. 可迁移到 NTS11 的硬件结构

### 5.1 UniH60-Bundle scheduler

来源：Bishop + parallel timestep accelerator。

结构：

```text
window/timestep descriptor
→ bundle density detector
→ empty skip / sparse lane / dense lane
→ H60 score engine
```

需要 profiling 支撑：

```text
empty_bundle_ratio
low_density_bundle_ratio
high_density_bundle_ratio
```

### 5.2 Ternary consensus score engine

来源：FireFly-T binary attention engine + NTS11 H60。

结构：

```text
Q/K 2-bit event
→ ternary classify masks
→ popcount
→ TX score
→ SC score
→ fused score
```

相比 binary attention 的差异：

| binary attention | NTS11 H60 |
|------------------|-----------|
| AND / popcount | ternary compare / classified popcount |
| binary Q/K | ternary Q/K |
| attention map | single Shiftmax gate |
| dense V 或 binary V | gated-K event output |

### 5.3 Shared ATLIF event encoder

来源：SNN accelerator + 本工作统一 ATLIF。

结构：

```text
activation tile
→ threshold/center SRAM
→ comparator lanes
→ binary/ternary packer
→ event SRAM
```

关键设计：

```text
logical ATLIF site != physical hardware instance
```

NTS11 的 105 个 ATLIF site 通过 descriptor 复用同一组 encode lanes。

### 5.4 Byte/bit packed SRAM

来源：FireFly-T SRAM 数据流思想。

NTS11 建议：

| buffer | 格式 |
|--------|------|
| binary event SRAM | 1-bit packed |
| ternary Q/K SRAM | 2-bit packed |
| score SRAM | INT score |
| gate SRAM | INT gate |
| descriptor SRAM | layer/block/window 参数 |

### 5.5 downsample hotspot path

来源：本地 profiling。

NTS11 的 downsample event 明显偏高：

```text
NTS11bd ep19: 4.416G
NTS11bj ep2 : 4.102G
```

建议硬件上暂时不要为 downsample 单独做复杂核，但要：

1. 在 energy model 单独列 downsample traffic；
2. 在 bundle density profiling 中单独输出 downsample；
3. 后续考虑 downsample binary 或 skip。

## 6. 不建议迁移或暂缓迁移的点

| 机制 | 暂缓原因 |
|------|----------|
| 3D integration | DATE 第一版硬件设计成本过高，可作为未来工作 |
| dynamic head pruning | 需要改模型或训练，当前主线先稳定 UniH60 |
| temporal early exit | 可能影响光流精度和时序一致性 |
| training-free token pruning | 需要 gate/token stability 证据后再做 |
| analog sparse transformer | 与当前数字 event datapath 不一致 |


- STATA

```text

```

## 9. 当前推荐的 NTS11 硬件设计方向

推荐主线：

```text
UniH60-Bundle
```

组成：

1. 全 encoder H60 attention ISA；
2. ternary Q/K event coding；
3. TX/SC consensus score engine；
4. single Shiftmax token gate；
5. gated-K event output；
6. shared binary/ternary ATLIF event encoder；
7. TTB-2 bundle scheduler；
8. sparse/dense event stratifier；
9. packed event SRAM；
10. descriptor-driven controller。

一句话叙事：

> NTS11 把 mixed spiking transformer encoder 收敛成统一 H60 event-attention dataflow，并用 token-time bundle 调度把 ternary event sparsity 变成硬件可利用的结构化跳过。
