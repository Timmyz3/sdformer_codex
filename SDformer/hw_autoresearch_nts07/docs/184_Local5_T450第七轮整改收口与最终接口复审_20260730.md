# Local5 T450 第七轮整改收口与最终接口复审（2026-07-30）

## 1. 最终结论

本轮关闭了 Local5 T450 研究原型中的以下实现与接口风险：

1. `MAX_DEST=450/DEST_W=9` 最高合法地址449全链累加与读回；
2. 单周期全阵列清零改为逐行 `ST_CLEAR`；
3. 独立 Python 整数 golden，移除与 DUT 共用 score/Shiftmax RTL 的参考依赖；
4. 连续两窗口运行，逐窗检查全部 `450x4` Acc，共3600项；
5. 顶层读口只在 `ST_FINISH/run_done` 阶段开放；
6. 非法 Acc 地址不握手、不返回数据并置协议错误；
7. 权重未装完时的 `run_start` 被拒绝并置错，不进入永久反压；
8. 当前完整编译依赖、向量和脚本共27项 SHA256 已固化。

最终独立 DATE 复审结论：

- 上述三项最后接口风险均 `Closed`；
- 当前参数范围内未发现新的 P0/P1 RTL bug；
- DATE 评分仍为 `2.3/5`；
- Recommendation 仍为 `Weak Reject`；
- 原因是本轮提升了正确性，不增加架构创新、真实 workload、PPA 或系统收益证据。

## 2. 独立 workload 与 golden

新增 `scripts/generate_local5_t450_window_vectors.py`，独立实现：

- alpha-XNOR Q7 score；
- masked Shiftmax5 Q1.7 gate；
- K-bit、gate、weight 的整数投影；
- 目的 token 累加。

两窗口刺激包含：

- 6+3 次目的输入；
- 目的0、1、17、225、448、449；
- 重复目的449；
- 随机与定向 Q/K；
- 多种 invalid mask；
- 正负权重；
- multiplicity 1、2、3；
- 第二窗口对第一窗口全部旧 Acc 的清除检查。

当前仍缺 multiplicity 4/5、溢出边界、真实 ordered trace 和随机流级反压。

## 4. 协议整改

### 4.1 顶层完成与读口同相

projection 的读口先接入内部 `proj_acc_*` 信号；wrapper 只有在 `ST_FINISH` 时才向外转发 `acc_read_ready` 和 `acc_data_valid`。因此顶层满足：

`acc_read_ready -> run_done`

### 4.2 非法读 fail-closed

projection 同时检查目的地址和输出地址范围：

- 非法读不产生 ready；
- 非法读不产生 data_valid；
- 非法读置 `protocol_error`；
- TB 定向访问目的500并检查 fail-closed。

### 4.3 未装权重启动 fail-closed

wrapper 只在合法 `w_load_last` 握手后置 `weights_loaded_q`。此前收到 `run_start` 时：

- 保持 `ST_IDLE`；
- `run_busy=0`；
- 不发 `proj_start`；
- 置 `glue_err_q`。

## 5. 证据分级

本轮关闭的是 RTL 正确性和实现可扩展性 P1，不是 DATE 真实 workload P0。

| 声明 | 等级 |
|---|---|
| T450 地址、双窗口、3600项 Acc 零失配 | `[rtl]` |
| 清零与读口控制属性 | `[rtl-sva]` |
| bank-local 参数化开放综合可读性 | `[open-synth]` |
| Local5 fullres/post-G0 ordered workload | 无 |
| 同步 SRAM/RMW/bank hazard | 无 |
| DC/STA/SAIF/LEC/EDP | 无 |
| full encoder FPS/带宽 | 无 |

## 6. 为什么评分仍不提高

逐行 scrub、独立 golden 和 fail-closed 接口属于必要工程质量，不是新的架构原则。DATE 主张仍缺：

1. 真实 fullres post-G0 ordered trace；
2. 全部450 destination 与真实 invalid mask；
3. 同步 SRAM、read-modify-write、RAW hazard 和 bank conflict；
4. MFEP on/off 同顶层公平消融；
5. 相同 SRAM/SDC/PVT 下的 DC、STA、SAIF、LEC 和 EDP；
6. Motion 与 Local5 双线在相同边界下的系统比较。

## 7. 下一步唯一 P0

下一步不应继续扩展定向 RTL 功能，而应优先回放真实 full-resolution post-G0 ordered trace：

- 真实 T450 destination 顺序；
- 真实 invalid mask；
- 多样本、多窗口；
- 独立整数 golden 全输出零失配；
- 报告 mean/p95/p99 周期、term 数、multiplicity、队列占用、目的 fanout 和清零占比。

只有该 P0 关闭后，才能决定 Local5 的 MFEP、epoch-tag/lazy-clear、同步 SRAM banking 是否值得进入目标工艺 PPA。
