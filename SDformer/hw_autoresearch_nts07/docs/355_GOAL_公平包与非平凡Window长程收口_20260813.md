## 一句话

Motion 把空行跳过并进共享后端，并补上与 1.1865× 同口径的 LFSR 公平对照；Local5 把 Q-silent Acc32 从「全空 Q 的 S0 三头」推进到 **Q≠0 占两成的完整 S3 window（24 头）**；若 S3 数据支持，再加一条仍 bit-exact 的 residual 快路径。

## 为什么够长、且两边都要做

- 完整性：共享后端还停在 ready=1；DATE 主表必须能和 Fixed2S/RQTB2S 的 LFSR 包同台。S0 window 全是 Q==0，审稿会说你只优化了空 query。  
- 创新：空行并入共享后端是 occupancy cascade；S3 的 Q≠0 才能决定下一条 exact 机制（相同 K 广播或拒绝）。  
- 工作量：S3 24×450 dest × 两模式 Acc32 + 共享后端改顶层 + LFSR 三方对照，是小时级而不是再写一篇文档。

## 验收

### M1 共享后端 + 空行跳过 `[rtl]`

`h67_laws_shared_backend_2s_top` 增加 `row_k_present`。空行 2 拍结束，不进 226 拍 scan。138 行 ready=1 wall 相对 85912 报告；空行 33 行必须走 skip。

### M2 LFSR 公平对照 `[rtl]`

同一 LFSR（与 sealed 2S TB 相同多项式/初值）下：

- Fixed2S  
- RQTB2S  
- SharedBackend+Skip（可顺序一行一行，以便和 1.1865× 同口径）

报告三方 cycle。Shared 不得替换 1.1865× 主锚点，除非数字在同口径下仍成立。

### L1 S3 完整 window Acc32 `[rtl]`

sample0 / S3 / B0 / 该 profile window 的 **24 头**。residual vs Q-silent，Acc32 0 mismatch。必须报告 Q==0 / Q≠0 比例。

### I1 数据驱动的下一条 exact 机制

先在 S3 window 上统计 Q≠0 行的 identical-K / equal-score。  
- 有结构性收益且能 bit-exact → 最小 RTL + 与 sealed leaf miter  
- 否则书面否决，不进贡献列表
