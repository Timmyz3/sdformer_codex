## 2. 最终流合同

Direct online 新增以下精确检查：

1. drain accept 与 response 均严格按 source-major/out-major 排列；
2. 每个 response 与对应 accept 的 `(source,out)` 完全相同；
3. response cycle 固定为 accept cycle 加 2；
4. accept 的 `(plane,y,x)` 必须由 source ID 唯一重建；
5. Direct 接口没有 `last`，证据明确记录 `last=null/not-applicable`。

TCFM5 新增以下精确检查：

1. vector accept、vector response 与 serializer input 的 source 顺序均为 `0..8`；
2. vector accept 与 response 身份逐项配对；
3. serializer output 严格按 source-major/out-major 输出 18 个标量；
4. serializer input 只允许第 9 项 `last=1`，output 只允许第 18 项 `last=1`；
5. source、坐标、vector data、serializer input 与最终标量保持同一身份链。

因此“交换两个完整 payload，但保持最终 `(source,out)->value` 集合不变”的攻击
现在会因流顺序或 accept-response 身份不一致而失败。

## 3. Snapshot 状态合同

每个 `cycle_snapshot` 先检查 packed `fire == valid & ready`，再逐 cycle 检查：

| 候选 | 冻结状态 |
|---|---|
| Direct | phase、projection busy/done、relation active/done |
| TCFM5 | phase、FSM state、run busy/done |

Direct relation 前端在最后一次 1RW relation read 后经过同步响应、descriptor 捕获、
FIFO enqueue 与 idle 可见四拍尾延迟；`projection_done` 在 compute-done cycle 生效，
phase 标签下一拍进入 done。第五次复审证明本版的 boundary 仍由同一 monitor 状态
生成，因此这里原称“不从状态位反推”并不成立，不能再引用为独立状态证据。

## 4. 负测与结果
