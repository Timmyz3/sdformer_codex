# DATE 第八轮架构整改与主线收窄

## 1. 整改结论

第八轮复审的 P0/P1 基本成立。本轮没有为提高分数继续改名，而是删除了不可靠
代理并执行一次负结果淘汰：

> **Motion W4 进入完整边界 RTL 校准；Local5 W4 是等待 ordered trace 的
> fission 架构创新候选。**

新增同 lane monolithic16 后，Motion fused 服务与 monolithic 完全相同，不能
作为 fission/fusion 创新。Local5 W4 split 相对 monolithic16 的服务量下界为
1.138x，但等待 post-G0 ordered trace；TRCF 在 Motion 上已淘汰，在 Local5
上仍被逐 term trace 阻断。

## 2. 问题闭环

| 复审问题 | 整改 |
|---|---|
| lane 数冒充面积 | 改称 nominal lane，只作结构筛选；面积/功耗必须由同 SDC 综合 |
| residual service 冒充吞吐 | 改称服务下界；状态改为“进入完整边界 RTL 原型” |
| backlog 冒充 FIFO | 改称最大待服务周期；FIFO entry 只由 RTL replay 统计 |
| sample p99 冒充 transaction tail | 报告中明确降级；后续 RTL 逐事务统计 |
| projection 重复记账 | 删除 cross-stage work proxy；unique product 与 Acc RMW 分账 |
| TRCF destination `/3` | 纠正：3-bank 是 output-channel banking，保持公平 M4 端口 |
| T450 8-bit destination | 改为 9-bit destination + 2-bit flag |
| 双线共享已成立 | 改为待证假设；必须比较可重构核与两个专用核 PPA |
| TRCF 已可晋级 | Motion 计入 11-bit local list 后总流量只降 11.23%，低于门槛，淘汰 |

## 3. 修正后的模型结果

### 3.1 Motion TQ-FFE

| 配置 | nominal lane | residual 服务保持 | nominal lane 指数 | 最大待服务周期 | 决策 |
|---|---:|---:|---:|---:|---|
| 4x2 fused | 40 | 0.99995x | 1.600x | 2080 | 淘汰 |
| 4x4 fused | 48 | 1.00000x | 1.333x | 179 | 完整边界 RTL 原型 |
| 4x8 fused | 64 | 1.00000x | 1.000x | 0 | 淘汰 |

注意：

- `1.00000x` 不包含 normalizer/term/projection；
- `1.333x` 不是面积归一吞吐；
- `179` 不是 FIFO entry。

### 3.2 Local5 TQ-FFE

| 配置 | nominal lane | residual 服务保持 | 状态 |
|---|---:|---:|---|
| 4x2 split | 40 | 0.946x | 淘汰 |
| 4x4 split | 48 | 0.999x | 缺 post-G0 ordered trace |
| 4x8 split | 64 | 1.000x | 保守备选 |

### 3.3 TRCF

公平口径改为：

- 3 个 output-channel bank；
- source 和 TRCF 都最多 M4 destination/cycle；
- Motion 允许同一 row 内跨 term 理想尾部合并；
- local destination entry 为 `9-bit id + 2-bit flag`。

| 主线 | global bits 减少 | global+local bits 减少 | 理想服务上界 | 决策 |
|---|---:|---:|---:|---|
| Motion | 61.56% | 11.23% | 1.177x | **淘汰** |
| Local5 | 93.30% | 76.11% | 4.000x | 缺 post-G0 逐 term trace |

Motion 虽有 global fabric bit 收益，但计入本地 list 后未过 15% 门槛，不能再
列入 Motion 贡献。

## 4. 当前真正可讲的架构创新

### 4.1 主候选：Topology-Quotient Fission-Fusion Engine

与 Prosperity/Phi 的差异不写成“我们也做 anchor+residual”，而是：

1. relation 由 temporal/stencil 拓扑静态声明，不使用 matcher/codebook；
2. 四个物理 residual slice 在 temporal mode 融合，在 stencil mode 裂分；
3. exact identity 不发重复 candidate，改为 multiplicity-carrying quotient；
4. weighted normalizer 和整数 projection 保持原 hardware-order。

其中第 2 项是最核心的硬件架构假设，第 1/3/4 项共同保证它不是有损稀疏核。

### 4.2 条件候选：Local5 TRCF

只有以下全部成立才允许晋级：

1. destination list 可在 projection bank 本地生成；
2. 至少两个 product context 可同时驻留；
3. 逐 term destination/port-class replay 证明 M4 尾部可合并；
4. 计入 list SRAM、context、walker 后 EDP 改善至少 15%。

## 5. 当前不能写成贡献的内容

- nominal lane 比；
- residual service `1.0x`；
- sample-total p99；
- Motion TRCF；
- Local5 pre-G0 4.0x；
- butterfly；
- DCTF/3-bank/双 context；
- “双线共享核已经成立”；
- unique product reduction 等于 projection 加速。

TRCF RTL，也不把 Local5 W4 预筛写成 DATE 结果。
