## 2. 四项 additive 修复

### 2.1 overlap 必须 bank-distinct

M938 supplemental SVA 新增：

```systemverilog
match_g_valid && exec_active |-> match_g_bank != exec_bank
```

cover 和 TB counter 也只接受 `match_g_bank != exec_bank`；若同一 bank 同时 match/execute，TB 直接记错。

### 2.2 row63 READY 绑定同一 bank

删除原来可被任意 `exec_active` 满足的逃生条件。G-row63 后一拍必须满足：

1. `match_g_bank` 与前一拍相同；
2. 动态绑定的该 match bank state 为 `BANK_READY`；
3. `match_active=0`。

当前 RTL 的 NBA schedule 不允许目标 bank 在这一 sample 已经进入 EXEC；execution ownership 只能在随后 edge 转移。

### 2.3 F/G/R63 三个动态 reset

新增三项 directed case：

| case | reset 点 | 未提交目标 |
|---|---|---|
| F | F row0 valid、G empty | row0 |
| G | G row0 local winner valid、R write pending | row0 |
| R63 | G row63 valid、terminal R write/READY pending | row63 |

reset corpus 使 row0、row63 的最终 directory 必然不同于 prep seed，因此 stale R write 可观察。每项均检查：

- `match_active/match_issue_done/F valid/G valid/exec_active` 清零；
- 两个 bank state 都回 `BANK_FREE`；
- reset low 与 release 后均无 stale directory write、READY、execute 或 task_done；
- fresh empty recovery task 能重新完成。

这些只是尚待 VCS 执行的动态用例源，不是已通过的仿真结果。

### 2.4 bank/epoch oracle 外部所有权

外部模型只消费 public accepted-prep 和 task-done handshake，维护：

- 两个 bank 的 ownership/epoch；
- 当前 prep bank；
- 下一 match 的 expected bank/epoch。

逐 row oracle 使用 `external_match_expected_epoch_q` 选择 reference，并独立比较 F/G bank tag。`dut.bank_epoch_q` 只作 observation/comparison，不再选择自己的 reference slot。

并发 pair 也从相同 directed masks 改为：

- epoch1：directed masks；
- epoch2：`make_random_masks(32'h9380_0002)`。

因此 bank/epoch 交换无法再靠相同 directory 蒙混通过。
