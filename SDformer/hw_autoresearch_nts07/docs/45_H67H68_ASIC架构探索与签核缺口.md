## 0. 执行结论

1. **算法精度主线应继续采用 H67 epoch19。** H67 dyadic valid825 为 AEE `1.4626`、AAE `9.3949`、spikes `26.3948G`；H68 dyadic 为 AEE `1.4715`、AAE `9.4517`、spikes `26.4311G`。H67 在三项上均优于 H68，但 AEE 优势只有约 `0.60%`，最终硬件选择仍需同约束 DC 与真实活动功耗决定。
2. **H68 不需要、也不应新增一套推理 RTL。** H68 的 binary alpha-XNOR full-matrix Castling 分支只在训练态工作，权重从 `0.5` 线性退火到零；`eval` 时函数直接返回零，部署配置也显式关闭它。H68 的推理硬件就是 TTX。这是“训练期富分支、部署期零附加算子”的软硬件协同点，不是第二条矩阵注意力硬件路径。
3. **推荐的物理架构是单实例、可配置的 TTX/H67 统一 row engine。** 共享 descriptor scheduler、active-entry buffer、Shiftmax、gated-K 和下游 ATLIF；只在 score 前端选择基础 TTX 或 H67 Motion-XOR，并采用能覆盖两种模式的 score-class folding。12 个 attention block 和 105 次 ATLIF 调用均按时间复用，不按 PyTorch module 数量复制实例。
4. **当前资产不能直接作为论文 PPA top 送 DC。** 它们可以用于结构性探索综合，但尚有两个数值 P0 阻塞：H68 软件部署 `alpha0=1/64`，当前 TTX top 默认却是 `ALPHA0_Q8=5`；软件执行 `center -> quant`，RTL 执行 raw-score quant 后利用 Shiftmax 平移不变性省略 center，半格点存在已知反例。
5. **当前 RTL 还不是完整加速器边界。** top 只输出 `{token_idx,K,gate,threshold}`，未实例化 `ttx_late_gate_accum`，也没有 projection、ATLIF、SRAM macro wrapper、AXI/APB、DMA、SDC、DFT、CDC 或功耗活动闭环。Yosys 的 `memories=0` 和 generic cell 数不能用于论文面积。
6. **架构签核结论为 `NO-GO`，推荐架构为“有条件通过”。** 完成第 12 节 P0 门槛后，可进入同工艺 DC 差分；在 PDK、频率/面积/功耗预算、SRAM 宏和逐行 bit-exact 未冻结前，不得宣布 architecture sign-off。

## 3. 软件到硬件的真实映射

### 3.1 H68：训练期 Castling，部署期 TTX

```text
训练：Y = (1-lambda(step))*Y_TTX + lambda(step)*Y_full_matrix
      lambda: 0.5 -> 0 before epoch20

推理：lambda = 0
      Y = Y_TTX
```

`_castling_aux_weight()` 在 `not module.training` 时返回 `0.0`，部署 YAML 也设置：

```text
binary_motion_xor_alpha = 0
castling_matrix_aux_weight = 0
castling_matrix_aux_end_step = 0
alpha0 = 1/64
score/gate step = 1/128
```

因此 H68 的硬件贡献边界只能写成：利用训练期 richer full-matrix guidance 改善固定 TTX 部署核的 checkpoint，推理芯片不增加矩阵 score SRAM、矩阵 Shiftmax 或动态 `weights@K`。不能画一条长期存在的 Castling matrix hardware branch。

### 3.2 H67：TTX 加时间 K 运动证据

冻结部署公式为：

```text
overlap  = popcount(Q & K_current)
same0    = popcount(~Q & ~K_current)
motion   = popcount(K_current XOR K_peer)
score_q7 = RNE(4*overlap + motion + same0/16)
```

`T=2,D=32` 时，Motion-XOR 在 Q7 域直接加 `motion`。零 K token 的 score 仍依赖 peer K，不能继续只按 `q_active` 合并；H67 使用最终 score `0..34` 的 35 类 TPSF。

### 3.3 共享后端

```text
descriptor
  -> Q/K event stream
  -> [TTX score | H67 Motion-XOR score]
  -> row max
  -> exp2 LUT
  -> zero-K score-class denominator folding
  -> power-of-two denominator / gate_q8
  -> sparse {token_idx, K, gate, threshold}
  -> gated-K / projection / binary ATLIF
```

当前仓库只实现到 sparse `{token_idx,K,gate,threshold}` 输出。`ttx_late_gate_accum` 是独立模块，但未接入 attention top；projection 和 ATLIF 不在本次 H67/TTX top 中。

### 4.1 可复用资产

| 资产 | 作用 | 审阅结论 |
|---|---|---|
| `ttx_descriptor_scheduler` | 4 stages、12 blocks、6720 rows/frame | 可复用；形状硬编码 |
| `ttx_tx_score_q7` | TTX overlap/silence score | 结构可用；部署常数和舍入待冻结 |
| `ttx_row_engine` | 33 类 ZAF、Shiftmax、稀疏输出 | 功能原型；hist reset 不利 SRAM 映射 |
| `h67_temporal_pair_adapter` | `{K1,K0}` current/peer 选择 | 可复用 |
| `h67_motionxor_score_q7` | H67 dyadic RNE score | 局部参考验证充分 |
| `h67_score_class_row_engine` | 35 类 TPSF | 可复用；逐 row golden 未关闭 |
| `ttx_exp2_lut_q8` | Shiftmax 指数 LUT | 需与软件 gate 逐行对齐 |
| `ttx_ceil_log2_u32` | 幂二分母 | 是近似规范的一部分，需冻结 |
| `ttx_late_gate_accum` | late gate 后有符号权重累加 | 未接 top，不能算完整 datapath |

### 4.2 已确认的结构问题

1. `ttx_attention_top` 未把 `ALPHA0_Q8` 暴露到顶层，`ttx_row_engine` 默认值为 `5`；H68 dyadic 软件是 `1/64=4/256`。
2. TTX score 使用加半 LSB 的 round-half-up；H67 使用明确 RNE。软件 `torch.round` 是 ties-to-even，模式间舍入规范尚未统一。
3. TTX 在 `ST_IDLE` 用 `for` 循环一拍清 64 项 histogram。综合成寄存器可工作，但通常不能直接映射单端口 SRAM；H67 的顺序初始化和 scan-clear 更接近宏实现。
4. active score、K、token 三个数组在 Yosys 中全部映成寄存器，`Number of memories: 0`。当前 generic cell 数掩盖了真实宏面积、端口和延迟。
5. row engine 只支持一个 in-flight row。scheduler 在 `ST_WAIT` 阻塞，吞吐不能靠多 row overlap 隐式提高。
6. reset 是单时钟同步低有效语义；没有 clock-domain、CDC、scan、MBIST 或 isolation 定义。

## 5. 接口审阅与建议契约

### 5.1 当前 TTX 局部接口

| 方向 | 信号 | 每拍 payload | 语义 |
|---|---|---:|---|
| descriptor out | stage/block/head/window/n_tokens | 28 bit | 请求一个 162-token row |
| row input | Q + K | 64 bit | `valid/ready/last`，每拍一 token |
| sparse output | token_idx + K + gate + threshold | 56 bit | 只输出未折叠 K token |
| control | start/busy/done/config | 约 12 bit | 单 frame、单 engine |

### 5.2 当前 H67 局部接口

| 方向 | 信号 | 每拍 payload | 语义 |
|---|---|---:|---|
| row input | time_sel + Q + `{K1,K0}` | 97 bit | peer K 与 current K 同拍提供 |
| sparse output | 与 TTX 相同 | 56 bit | 保持 token index |

直接接口每 frame 有 `6720*162=1,088,640` 个 input beats。TTX payload 约 `69.67Mbit/frame`；H67 现有 97-bit 直接接口约 `105.60Mbit/frame`。后者不是逻辑数据量必然增加，而是同一个 K pair 可能在两个 timestep token 上重复呈现。正式 memory architecture 应让 81 个空间位置各存一次 64-bit K pair，由地址生成器本地选择 `time_sel`。

### 5.3 DC 前必须补全的系统接口

- 控制：APB/CSR 或冻结的配置 bundle，至少包含 mode、alpha0、preserve_mean、fold enable、threshold、frame shape。
- 数据：定义 SRAM request/response 或 AXI-stream，明确 latency、backpressure、row abort 和 error 语义。
- descriptor：当前 stage/head/window 表硬编码，可保留为 ROM，但必须把输入 tensor layout 和地址公式写成规范。
- 输出：明确 sparse gated-K 是送 projection accumulator、event SRAM 还是 DMA；不能只停在 testbench 端口。
- 错误：score range error、unexpected last、token count mismatch、FIFO overflow 必须有 sticky status。

## 6. 存储与端口模型

### 6.1 当前 row-local 逻辑容量

按 `MAX_TOKENS=162` 导致的 256-depth 物理数组估算：

| 存储 | 深度 x 位宽 | bit |
|---|---:|---:|
| active score | `256 x 16` | 4096 |
| active K | `256 x 32` | 8192 |
| active token index | `256 x 8` | 2048 |
| score histogram | `64 x 8` | 512 |
| **合计** |  | **14848 bit，约 1.81KiB** |

TTX 与 H67 row-local 容量相同；区别是 histogram 合法类 33 对 35。Yosys 尚未保留这些 memory。

### 6.2 temporal-pair 容量

| 项 | 逻辑容量 |
|---|---:|
| 一个 window/head 的 K pair | `81 x 64 = 5184 bit` |
| Q 与 K 都按 temporal pair 保存 | `2 x 81 x 64 = 10368 bit` |

H67 至少需要 K pair 可同拍读取；未来 Exact Delta 还需要 previous Q/K 或等价 contribution state。pair packing 可减少地址事务，但不减少信息论容量。论文存储表必须分列 payload、bank padding、valid/tag/ECC 和 macro peripheral。

### 6.3 推荐端口

- active score：1RW，load 写、sum/emit 读，状态互斥。
- active K：1RW，load 写、emit 读。
- token index：1RW，load 写、emit 读。
- histogram：若用 64x8 flop bank，可单周期 RMW；若用 SRAM，需要 read-modify-write 两拍或旁路累加器。
- temporal pair：至少 64-bit read/cycle；若 Q 和 K 同 bank，需 128-bit word 或双 bank，避免每 token 两次读。

小数组是否用 SRAM 必须由目标工艺 compiler 的最小宏和外围成本决定。不能预设“SRAM 一定更小”；35/64 项 histogram 很可能适合寄存器，而 256x32 active K 更值得宏化。

## 7. 吞吐模型

### 7.1 workload

硬编码 scheduler 每 frame 发出：

```text
S0: 2 blocks * 3 heads  * 440 windows = 2640 rows
S1: 2 blocks * 6 heads  * 120 windows = 1440 rows
S2: 6 blocks * 12 heads * 30 windows  = 2160 rows
S3: 2 blocks * 24 heads * 10 windows  = 480 rows
total = 6720 rows/frame
```

TTX 100-sample profile 按真实 row 权重折算的 active entries 约 `19.15/row`。该值来自 TTX checkpoint，不是 H67 实测，移用于 H67 只作为低置信度估算。

### 7.2 单 row 周期

在输入连续、`out_ready=1`、有 K-zero folding、忽略 SRAM wait 的假设下：

```text
TTX/H68 cycles/row ~= 162 load + A sum + 33 class scan + A emit + 3 control
H67     cycles/row ~= 162 load + A sum + 35 class scan + A emit + 3 control
```

| 情形 | A | TTX/H68 cycles/row | H67 cycles/row |
|---|---:|---:|---:|
| 理想全折叠 | 0 | 198 | 200 |
| TTX profile 暂估 | 19.15 | 236.3 | 238.3 |
| 最坏无折叠 | 162 | 522 | 524 |

### 7.3 attention-only 吞吐敏感性

| 情形 | 250MHz TTX/H68 | 250MHz H67 | 500MHz TTX/H68 | 500MHz H67 |
|---|---:|---:|---:|---:|
| profile 暂估 FPS | 157.4 | 156.1 | 314.9 | 312.2 |
| 最坏 FPS | 71.3 | 71.0 | 142.5 | 142.0 |

这些数值只代表一个无外部 stall 的 attention engine，不是 SDformer 端到端 FPS。H67 固定多扫 2 类，profile 暂估周期增量约 `0.85%`；真正风险来自 97-bit 供数、pair SRAM 和 XOR/popcount 的时序/动态功耗，而非 class scan。

## 8. 候选架构探索

### 8.1 候选 A：H68 Castled-TTX 最小核（保守）

```text
Q/K stream -> TTX score -> 33-class ZAF -> Shiftmax -> gated-K
```

- H68 full-matrix 仅训练期存在，芯片不实现。
- 64-bit 输入，row-local 14848 bit。
- 算法结果：AEE `1.4715`、AAE `9.4517`、spikes `26.4311G`。
- 优点：接口最窄、无 peer-K SRAM、验证空间最小。
- 缺点：精度被 H67 小幅支配；当前 alpha0/舍入不匹配阻塞部署。

### 8.2 候选 B：H67 Motion-XOR + TPSF（精度型）

```text
Q + {K1,K0} -> pair select + XOR/popcount
              -> H67 Q7 score -> 35-class TPSF -> shared Shiftmax/gated-K
```

- 复用 scheduler、exp LUT、denominator、稀疏输出。
- row-local 仍为 14848 bit；本地 K-pair 另需 5184 bit/window/head 或等价上游供数。
- 算法结果：AEE `1.4626`、AAE `9.3949`、spikes `26.3948G`。
- 优点：当前精度/AAE/spikes 三项均胜 H68；class scan 只多 2 cycles。
- 缺点：pair SRAM/带宽和 Motion-XOR 动态功耗未测；software/RTL row bit-exact 未关闭。

### 8.3 候选 C：统一可配置 Score-Class Engine（平衡，推荐）

```text
temporal-pair buffer
  -> shared Q/K event fetch
  -> shared overlap/silence counters
  -> mode mux: TTX | +Motion-XOR
  -> canonical final-score class key
  -> one row max / exp / denominator / gated-K backend
```

- 物理只保留一个 engine，通过 frame/block 级 mode 选择 H68/TTX 或 H67。
- 采用 canonical final-score class，而不是同时保留 TTX q-active histogram 和 H67 score histogram；TTX 可映入其合法子集。
- H68 mode 可关闭 pair peer read、XOR tree 和 H67 class range，形成独立 clock-gating 域。
- 优点：同一芯片支持 accuracy 主线和零增量训练协同回退；论文消融保持同后端、同 SRAM、同约束，比较更公平。
- 缺点：当前没有 unified RTL；mode mux、规范统一和 clock gating 需要新增验证。若产品永远只部署 H67，双 mode 的面积价值有限。

### 8.4 候选 D：TTB Exact-Delta 异构前端（激进）

```text
Q/K temporal pair -> toggle mask / density stratifier
  -> zero-update reuse
  -> sparse delta lane engine | dense recompute engine
  -> shared score-class/Shiftmax/gated-K
```

- 现有 TTX profile 的 Q-or-K temporal update density 为 `2.7832%`，全 T=2 compare reduction 理想上限 `48.61%`。
- 优点：可能显著降低 t1 compare switching；K-toggle 可与 H67 Motion-XOR 共享。
- 缺点：缺 locality-v2 分布、queue/cycle trace、双路径 RTL、SRAM bank conflict 和 post-synth crossover；当前不具备准入证据。

### 8.5 取舍矩阵

| 候选 | 算法质量 | 输入/状态 | 周期 | 控制 | PPA置信度 | 技术风险 |
|---|---|---|---|---|---|---|
| A H68/TTX | 次优，AEE 1.4715 | 64-bit；无 peer K | 最低 | 低 | 中低 | 中 |
| B H67/TPSF | 最优，AEE 1.4626 | 97-bit direct；需 K pair | 比A约+0.85%暂估 | 低中 | 中低 | 中高 |
| C unified | 覆盖A/B | pair buffer + mode | mode相关 | 中 | 低 | 中高 |
| D TTB/Delta | 算法应等价 | Q/K state + queues | 潜在最低 | 高 | 很低 | 高 |

| TTX score | 131 |
| H67 score | 198 |
| TTX row hierarchy | 3016 |
| H67 row hierarchy | 2990 |
| TTX attention top | 3096 |
| H67 attention top | 3070 |

H67 score 代理比 TTX score 多 67 cells，但完整 top 反而略少，原因是 H67 用最终 score class 简化了 class-score 生成。所有数组均被打散，故这些数字只能说明“score 增量相对小于 row backend”，不能说明 H67 芯片面积更小。

在没有 DC 前，只允许使用以下规划区间：

| 候选 | 归一化逻辑面积先验 | 附加存储 | attention动态功耗先验 |
|---|---:|---:|---:|
| A H68/TTX | 1.00 | row-local 14848 bit | 1.00 |
| B H67 | 1.00--1.08 | +5184 bit K pair（若本地） | 1.02--1.10 |
| C unified | 1.03--1.12 | +5184 bit K pair | 1.02--1.12，按mode gating |
| D Delta | 1.25--1.60 | +Q/K state、FIFO、bitmap | 需真实trace，不能预判 |

这些区间是架构 guardband，不是测量结果，不得进入论文 PPA 表。

### 9.3 正式 PPA 口径

- **面积**：DC standard-cell area、SRAM compiler area、clock tree/DFT 预留分别报告；禁止把 generic cells 换算成 mm²。
- **频率**：同一 library、PVT、wireload/physical guidance、SDC，报告 WNS/TNS 和关键路径。
- **动态功耗**：H67/H68 真实 valid workload 产生 VCD/SAIF，分别报告 pair buffer、score、hist、Shiftmax、output、projection、ATLIF、clock。
- **漏电**：同一 PVT，与动态分列；检查是否超过总功耗 15%。
- **吞吐**：`6720 rows/frame * 实测 cycles/row`，加入 SRAM wait、backpressure、projection 和 ATLIF；同时报告 attention-only 与 end-to-end。
- **能效**：芯片 `mJ/frame`、`frames/J`，不能使用 spike proxy 替代。
- **对比**：A/B/C 使用同 SRAM macro、同频率目标、同接口、同激励和同综合选项。

### 9.4 Clock gating 预算

尚无 RTL SAIF，以下只给架构分类：

| 域 | 预期活动 | gating class | 要求 |
|---|---|---|---|
| descriptor/control | 每 row 活动 | moderate | row wait 时门控计数器 |
| pair/XOR | H67 mode 活动；H68关闭 | high opportunity | mode级 ICG 必须有 |
| active-entry SRAM | load/sum/emit 分相 | moderate | 按 state 控制 enable |
| histogram | load/scan 活动 | moderate | 空类不切 exp datapath |
| exp/denominator | K-zero 折叠后大幅减少 transaction | high opportunity | valid 驱动 operand isolation |
| projection/ATLIF | 仅有效 K 输出 | high opportunity | token-valid 级 enable |

正式签核要求以 SAIF 得到 activity factor，并对高机会域至少覆盖 60% 寄存器位的 ICG 规划。

## 11. 推荐架构与决策记录

### 11.1 推荐

**推荐候选 C：统一可配置 Score-Class Engine，但按两阶段实现。**

第一阶段先把候选 A 和 B 在同一数值规范、同一 SRAM wrapper、同一 SDC 下完成 DC 差分。若 H67 的总 attention 能耗/面积增量在预算内，则产品默认 mode 固定 H67；H68/TTX 作为同硬件回退和消融模式。第二阶段才合并为 canonical score-class engine，避免在数值规范尚未冻结时重构。

选择理由：

- H67 dyadic 在当前 AEE/AAE/spikes 上支配 H68，适合作为论文精度主线。
- H68 证明固定 TTX 数据流可通过训练协同得到接近 H67 的精度，且推理零辅助算子，适合作为硬件最小基线。
- 两者后端完全同构，复制 Shiftmax、buffer、projection 或 ATLIF 没有架构依据。
- score-class folding 把差异约束在前端和 33/35 类范围，便于同芯片公平消融。
- TTB/Delta 的理论稀疏性有吸引力，但证据不足，不应阻塞第一版 DC。

### 11.2 不推荐

- 不实现 H68 full-matrix 推理核。
- 不按 12 blocks 或 105 ATLIF modules 复制物理单元。
- 不在首轮 DC 引入 dense/sparse 双核、ROB 或多 row OOO。
- 不把当前 Yosys top 直接当完整 accelerator top。

## 12. DC 前门槛

### P0：开始有意义的 DC 之前必须全部完成

1. **冻结数值规范**：H68/TTX `alpha0=1/64`，H67 motion权重1/4，统一 RNE/饱和/score范围/gate范围。
2. **关闭运算顺序**：确定 `center->quant` 还是 `raw quant->Shiftmax`，用 H67、H68 各 825 samples 验证精度。
3. **逐 row golden**：至少覆盖 12 blocks，每个 block 包括全零K、全活跃K、半格点、max tie、backpressure；score、class、row max、exp、sum、gate、token output 逐级比较。
4. **冻结 top 边界**：至少包含 score/class/Shiftmax/gated-K；若论文声称 attention accelerator，还必须包含 projection 及其 SRAM 事务。
5. **存储宏化**：为 256x16、256x32、256x8、64x8、81x64 建立明确的 flop/SRAM 选择与同步读延迟 wrapper；消除 TTX 一拍全阵列 reset 对宏映射的阻碍。
6. **接口规范**：clock/reset、CSR、descriptor、input/output stream、memory request/response、error/status 完整定义。
7. **综合约束**：目标 library、PVT、`create_clock`、IO delay、clock uncertainty、false/multicycle path、max fanout、transition/capacitance。
8. **基线矩阵**：A H68/TTX、B H67/TPSF、B-no-fold 三个 top 使用同一 filelist、wrapper、SDC 和 compile effort。

### P1：论文级 PPA 前必须完成

1. 门级或 RTL SAIF 使用 H67/H68 真实 workload，不用均匀随机向量。
2. DC 报 logic area/Fmax/WNS/TNS；SRAM compiler 报 macro area/读写能量；PT-PX/Joules 报动态/漏电。
3. 输出每 row/frame cycles、stall、input/output bits、SRAM reads/writes、fold ratio、exp transactions。
4. 加入 clock-gating、scan、MBIST 后重新综合，至少预留 20% area/power margin。
5. 运行 LEC/形式等价或独立 gate-level golden；SDF smoke 覆盖 reset、backpressure、mode switch。
6. 报端到端网络 PPA 时加入 projection、ATLIF、其他 encoder/decoder 和 DRAM，不能只外推 attention 核。

### P2：DATE 投稿前必须完成

1. 至少两个 checkpoint/seed 复验 H67 与 H68 的部署结果。
2. 论文消融：TTX、H68训练协同、H67 Motion-XOR、TPSF on/off、unified gating on/off。
3. 独立 novelty search 证明 claim 边界；不使用其他论文的 PPA 数字替代本设计。
4. 同工艺或归一化对比时公开 process、frequency、precision、SRAM scope、batch 和 workload。

## 14. 下一步执行顺序

1. 先修规范，不先扩 RTL：冻结 H68 alpha0、RNE、center/quant 顺序并重跑 H67/H68 hardware-order valid825。
2. 导出真实 12-block row golden 和 H67 K-pair/class profile，关闭 Shiftmax 全链 bit-exact。
3. 定义统一 engine 的系统接口和 SRAM wrapper，明确完整 DC top 是否包含 projection/ATLIF。
4. 设置工艺/频率/面积/功耗约束，做 A/B/B-no-fold 同约束 DC。
5. 只有当 B 相对 A 的精度收益能覆盖实际 PPA 增量时，冻结 H67 为产品 mode；否则采用 H68/TTX 最小核。
6. TTB/Delta 留作第二轮可选优化，必须先完成 locality-v2 与 queue/cycle 模型。
