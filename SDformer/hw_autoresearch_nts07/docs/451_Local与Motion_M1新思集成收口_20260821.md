# Local 与 Motion M1 新思集成收口（2026-08-21）

## 结论先行

M1 已把 Local 主路径与 Motion 条件增量路径从彼此独立的 selector/streamer，收口为一个
具备精确状态合同的 tile 执行单元。默认配置为 256-bit 输入 tile、16 路 Acc32，验证和
综合只使用 Synopsys VCS、DC 与 Formality；不再把 Verilator 或其他开源工具结果作为证据。

真实 s10 trace 中 Local 当前激活 source 密度只有 H67 约 6.87%、Local5 约 7.46%，但低
密度本身不等于加速。打铁评审发现 v0 系统映射把已经按活动度缩减过的 ledger eligible
cycles 再除一次 `dense/selected`，重复计算了稀疏收益。原 `2.139412x` 已撤销，不得引用。

修正为以真实 s10 candidate cycles/10 直接替换 eligible cycles 后，在权重已驻留、每次选择
source 发射一个 weight segment、按集成 VCS 校准的每条命令 5-cycle 控制下：

- H67 16-lane dense/Local 为 `13.022138x`，dense/Local+Motion 为 `13.312378x`，但
  相对 96-lane activity-weighted baseline 的直接系统 ratio 只有 `0.229467x`；
- H67 96-lane 直接系统 ratio 为 `0.914932x`；128-lane 为 `0.978070x`；
- 256/512/1024 lane 的无冲突下界也仅为 `1.089670x`/`1.162858x`/`1.180423x`，受到
  逐 output-row command 地板限制；
- Motion 在 Local 之上仅增加约 `1.02x--1.03x`；
- Local5 16-lane dense/Local 为 `12.126530x`，dense/Local+Motion 为 `12.406029x`。

这些仍是忽略 SRAM/DRAM 的 source-issue 下界，不是实测 latency。它证明现有
`1 source/cycle + 每 row/segment 单独命令` 数据通路没有性能优势；M2 的核心不再是盲目加
lane，而是跨 row 的 bitmap block issue、每拍多 source、banked weight gather 和减少 command
amortization，同时把状态交通纳入。

该表仍按完整 output row 只发一个 command；当输入宽度或卷积 receptive field 超过 RTL 的
256-bit tile 时，尚未乘 input-chunk command 数。因此它依然偏乐观，M2 必须用真实
`input-tile × output-segment × temporal-step` trace 替换。

## 精确状态合同

`qfit_dual_line_stateful_tile_top.sv` 以同一组 masked bitmap 同时生成：

- Local 当前 source count；
- Motion 正/负 transition count；
- selector 决策；
- streamer 实际 source token。

Motion 只有在以下条件全部满足时才允许执行：

1. sequence/operator/call/output-tile 身份键完全相同；
2. prior valid extent、prior bitmap、完整 Local seed 与 prior Acc32 有效；
3. 非 sequence boundary，非周期 refresh；
4. transition source 数严格小于 current source 数。

任何身份、shape、seed 或协议异常都 fail-safe 到 Local；状态只在一个输出命令完整提交后
更新。这里的“精确”等价以 Acc32 不额外饱和、权重身份正确、上述状态合同成立为前提。

## M0 打铁评审闭环

独立 subagent 对启动资产给出 `49/100` 条件评分（correctness 70、innovation 57、
performance 39、DATE completeness 29）。M1 针对其主要否决项逐一收口：

- 用 stateful executor 补齐 selector 到 weight/update/Acc32 的集成断点；
- count、decision 与实际 stream 改由同一 masked bitmap 生成；
- 补齐 state key、boundary、refresh、shape、seed 和 commit 协议；
- 纠正 55 个 Local eligible 与 31 个 Motion comparable 的覆盖口径；
- 计数器从 32 bit 扩大为 64 bit，证据从“文件存在”改为 PASS marker、状态和 SHA
  fail-closed；
- 明确 operation-row trace、source-issue envelope 与 tile/cycle/memory trace 三种证据
  不能互相冒充。

M1 独立打铁评审最终给出 `47/100 CONDITIONAL`（correctness 72、innovation 58、
performance 20、DATE completeness 38）。它发现并促成关闭了 source-work 重复稀疏、
weight epoch 并发接收及 loaded epoch 末项覆写三个 P0；性能否决项进入 M2，不以当前文档
作者自评替代。

## VCS/SVA 结果

四级验证均通过：

| 层级 | 随机规模 | 关键覆盖 |
|---|---:|---|
| selector | 20,000 requests / 46,449 cycles | Motion 4,894，forced-Local 10,768，tie 与非法 count |
| source streamer | 5,000 commands / 157,787 source tokens | 39,170 个负 transition，68 个空 tile |
| tile executor | 2,000 commands / 250,864 Acc32 updates | Local/Motion 各 1,000，stall/顺序/符号/last |
| stateful integration | 2,100 commands / 2,049,456 Acc32 updates | Motion 503，state miss 462，invalid/boundary/refresh/key/seed/shape 全覆盖 |

修复 weight epoch 并发接收漏洞后的默认 256-bit/16-lane 集成回归为 562,418 cycles，
2,200 commands，Local 1,688、Motion 512；额外注入 100 次 `request+weight_epoch_clear` 和
100 次 `request+weight_valid` 竞争，全部拒绝请求且计数不变。全部 reference miter 与 SVA
为零 mismatch。性能计数器已扩大到 64 bit，避免长跑溢出。

## DC 3 ns 预宏结果

目标库为 TSMC 28HPC+ NLDM slow `ssg0p9v125c`，时钟 3.00 ns：

| 指标 | 结果 |
|---|---:|
| critical path | 2.78 ns |
| WNS / TNS / violating paths | 0.00 ns / 0.00 ns / 0 |
| logic levels | 120 |
| cell area | 125,206.452327 um² |
| leaf / sequential cells | 113,272 / 36,782 |
| macro count | 0 |

综合中的 32,768 个 weight bit 被实现为触发器，并且网表没有 SRAM macro，因此这个面积只
能标为 **premacro/flop-storage diagnostic**，不能作为论文 PPA。120 级组合路径与零裕量也
说明 M2 需要把内部超宽 weight mux 拆成外部 banked SRAM/segment interface，再重新做
DC/STA。

与上述最终 RTL/DC 网表配对的 Formality 已通过：`37,846/37,846` compare points passing，
`0 failing`、`0 unmatched`。内容寻址 evidence manifest 绑定 15 个源码和 22 个证据文件；
除 tracked diff SHA 外另加入完整 source-set SHA，使未跟踪新文件不能以空 diff 漏过审计。
DC 的 leakage constraint 仍因默认 required=0 显示违规，且 macro=0；因此 Formality PASS
只证明 RTL-to-gate 逻辑等价，不提升 paper PPA 等级。

## trace 覆盖口径修正

全网络 Local eligible 是 55 个 operator，其中：

- 31 个 operator 同时具备可比的时间状态，允许 Local/Motion selector；
- 24 个 attention Q/K projection 因 window 时间轴重排，只允许 Local；
- 其余 operator 为显式 bypass 或由 attention RTL anchor 接管。

所以不得写成“55/79 均为 dual-path”。另外，ordered operator/source-work trace 不等于
tile-level cycle trace；M2 会以确定性对象地址、bank 和 timestamp 生成独立事务账本。

## M1 声明边界

可声称：双线路径算术合同、状态失配 fail-safe、默认配置 VCS/SVA、3 ns 预宏 DC 时序、
真实 s10 source-work conservation，以及 source-issue envelope。

不可声称：paper-ready 面积/频率、含 memory 的全系统 latency、FPS、能耗或 `2.139x`
实测加速。
