# H85 行差分对象与 H82 身份隔离

日期：2026-08-18。不改 `docs/359`。不写生产 RTL。不抢 H82 GPU。不把 H85 并进正在训的 H82。

算法侧 H84 审阅 3.5 之后开始写 H85。本机独立核对：H85 已经不是 H82 那个算子。

## 1. H85 改了什么

磁盘 overlay 里 `_build_h85_row_files` 把 15×15 窗切成空间行，**每一行自己做一类一票 Shiftmax**，再按行内 member 下标 `scatter_add` 写回 K。展开函数禁止 `codes` / `token_gate` / `member_mask`。相邻行吐 `shared/insert/delete` 的是 **class 名字集合**，正则最大化 `reuse_set`。

这和活着的 H82 ft15 不是同一份合同：

| | H82（RAM 里在训） | H85（磁盘新图） |
|---|---|---|
| Shiftmax 域 | 整窗 occupied Q7 | 每一空间行 15 token |
| 展开 | `K ⊙ gather(gate_c)` | 行内 class-major scatter |
| 差分 | 无 | class-set shared/insert/delete |
| 身份 | SHA `807a50e0` 装进 PID 2133687 | 尚未开训，且会换 SHA |

CPU 对照同一行分数：H82 与 H85 gate 的 maxabs 在随机场上约 **0.12**，光滑场约 **0.05**。不是同一套门。

## 2. 硬件 TLM 钉死的两句话

参考：`scripts/h85_row_delta_class_file_reference.py`，单测 4/4。

1. **可以**不物化长度 450 的 token 门：`expand_without_token_gate` 按行、按 class 写 `attn[i]=K[i]*gate_c`。这是执行调度，不是新乘法。
2. **不能**靠 class-set 差分去碰 41% active store。合成反例：两行 class 集合 Jaccard=1，幸存 class 的 member Jaccard < 0.5。冻结包也是这个结构（class 0.76 / member 0.30）。

面积代理（随机场）：

| 账 | raw | 空间光滑 |
|---|---:|---:|
| 全量行文件 | 11326 bit | 10050 |
| 只差分 class 名 | 7662 | 5900 |
| class 名 + 成员增删 | 8728 | **8916** |
| class-set Jaccard | 0.052 | 0.203 |
| member Jaccard | 0.179 | 0.183 |
| 每缝成员编辑 | 2.93 | **8.29** |

光滑让 class 名更稳，幸存 class 变多，成员编辑账更差。H85 的 `reuse_set` 正则正好优化了**几乎不占面积的那一栏**。

## 3. 和 41% / docs/433

PTPX 的 41.1% 是 450 条名单，不是直方图。H85 若只存 class 名的 shared/insert/delete，省的是那一栏 163/513 档 hist。成员 CSR 还在。要动 41%，差分必须是幸存 class 的 **member insert/delete**，并且 rank-1 上测到的 member Jaccard 要明显高于 0.30。H85 现网正则不训这个。

展开最后数值仍是 dest-owned `K_i * gate_c`。敌意审稿会写成 “循环版 token 门”。4.0 要的引擎是：directory 的操作数只有 Class File / 行文件，Shiftmax 不再看见 450 个 score。H85 TLM 做到了调度；算法图还没有一份冻过的 SHA 在真数据上跑过。

## 4. 口径

- 活身份：H82 ft15。epoch 0 将尽，force_save 在 4/9/14。
- H85 是**下一份算子 SHA 的候选对象**，本机只收 TLM，不写 RTL，不开训。
- 创新分不因这篇 TLM 上调到 4.0。里程碑 1 的独立分仍是 **2.6 / 2.7 / 2.0 / 2.3**。
- 下一刀仍是：H82 ep4 AEE → ep14 rank-1 → 513 档 Class File 统计。H85 若要立项，等 H82 让卡后单独冻 SHA，并把 C8.1 改成成员 TV，而不是再叠 H86。

## 5. 硬件扫描邻行（41% 真正对应的轴）

`scripts/h82_hwscan_delta_directory.py` 把连续滑窗当成 T450 扫描行。合成场上 class Jaccard 已经 0.92–0.93，member Jaccard 只有 0.003–0.028，成员增删 / 全量重建 ≈ **1.9**——比整表重写还贵。空间光滑几乎帮不上成员名单。H85 窗内行差分不是这个对象。
