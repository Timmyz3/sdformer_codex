# 等并行度 96-Lane 公平基线与 DCTF 晋级合同

## 1. 为什么必须补这个基线

HATF96-Central 相对 HATF32 的周期改善同时来自两个变化：

1. product/Acc lane 从 32 增加到 96；
2. 三个 32-channel output tile 共享一次 replay/decoder/term 生成。

仅用 `OUT_TILE=32/64/96/128` 扫描无法分离普通 SIMD 展宽与共享前端收益。DATE 审稿人可以合理质疑 HATF96 只是 96-lane SIMD。因此必须固定 96 个 product lane，比较三种组织方式：

| 名称 | replay/decoder | weight/product/Acc | 目的 |
|---|---|---|---|
| 3xIndependent32 | 三套独立 | 三个32-lane本地路径 | 纯并行基线 |
| HATF96-Central | 一套共享 | 中央96-lane join/product | 当前候选 |
| DCTF96-Distributed | 一套共享 | 三个32-lane本地路径 | 主架构候选 |

只有这组三角消融才能回答：收益究竟来自 lane 数、共享 replay/decoder，还是 bank-local 分布式数据流。

## 2. 统一比较边界

比较边界冻结在 `gatestack_multihead_decoder_projection_top`：

~~~text
typed-slot replay stream
        |
        v
resident/IPD/FADC/RAW decoder
        |
        v
term/event -> weight -> product -> AccTile -> bias/final
~~~

Builder/workspace/typed-slot 容量只计一份，但 projection-only 对照必须明确 slot read 端口需求。不能直接复制三个 `gatestack_builder_projection_single_context_top`，否则把 Builder、workspace 和 slot 也放大三倍，会人为抬高 Independent 面积。

## 3. 3xIndependent32 精确定义

每路实例固定：

- `OUT_TILE=32`；
- `LANES=32`；
- `BANKS=2`；
- `GATE_W=9`、`WEIGHT_W=8`、`PRODUCT_W=17`、`ACC_W=32`；
- 独立 resident/IPD/FADC/RAW replay 流；
- 独立 decoder、weight 请求、product engine、AccTile、bias 和 final；
- 独立 backpressure 与完成状态。

三路合计 96 个 product lane 和六个 token-interleaved Acc bank。逻辑 supertile 与物理 32-channel tile 的地址映射为：

~~~text
physical_output_tile = 3 * logical_supertile + bank_id
bank_id = 0, 1, 2
~~~

三路 wall time 取最大完成时间加 join 延迟，不能把三个引擎周期相加。任一路协议错误、overflow 或 abort 都使整个逻辑 supertile 原子失败。

## 4. 公平资源合同

### 4.1 算力

三种候选都固定 96 个 INT8 product lane。不能给 Central 96 lane、Independent 只有 32 lane，再把加速写成架构收益。

### 4.2 权重存储

三种候选都使用三个相同 32-lane weight bank、相同端口、相同返回延迟和相同 outstanding 限制：

- Independent：每个 decoder 直接访问自己的 bank；
- Central：一个逻辑请求经 coalescer 展开为三个物理 bank 请求，再中央 join；
- DCTF：每个 bank 收到窄 term command，本地读权重和计算。

H67 四阶段的物理访问应保持 `15030` 次、payload `3847680 bit`。Central 的逻辑请求为 `5010`，只说明控制事务减少三倍，不代表权重 bit 或 SRAM read energy 减少三倍。

### 4.3 AccTile

最终物理比较必须统一为六个 32-lane SRAM macro：

- Independent：天然为 `3 x 2` bank；
- Central：行为 RTL 的 `2 x 96-wide` 必须在物理映射时拆为相同六宏；
- DCTF：三个 bank-local backend 各两个 Acc bank。

如果 Central 保留 96-wide flop array、Independent 使用 32-wide SRAM macro，则面积和功耗不公平。

### 4.4 Bias/final

三种候选使用相同同步 bias SRAM 时序、相同 `BIAS_STATIONARY_ENABLE` 和相同六路物理 final sink。Central 的 96-lane bias/final 必须显式 split 到三个 32-lane bank，不能使用零延迟 lookup 或原子宽 sink 获得额外优势。

## 5. 不允许偷用的共享机制

`3xIndependent32` 中以下做法禁止：

1. 一个 payload beat 通过 ready-and 广播给三个 decoder；这把三次 slot read 变成一次；
2. 一次 decoded term 广播给三个 product bank；这已经是 DCTF；
3. 使用 HATF weight coalescer；它会重新形成中央 768-bit join；
4. 三路共用 decoder cache/fill/release 状态；
5. 只报告逻辑请求数，不报告物理 bank access 和 payload bit；
6. 用 `3 x HATF32 area` 算术值替代真实结构 wrapper 综合。

真实系统集成有两种合法 slot 方案：

- 三个独立 replay read client/port，面积和能量计入 Independent；
- 单端口 slot 串行服务三路，串行等待计入周期。

不能同时假设单份存储面积和三读口零代价吞吐。

## 6. RTL 与验证分阶段

### 阶段 A：结构面积基线

实现三套独立 decoder projection wrapper，完整暴露三路 replay、weight、bias、final 接口；小规模不同反压测试验证无串扰；在相同 Nangate45 filelist 下取得真实 wrapper logic area/cells/memory 数。

该阶段只回答逻辑复制代价，不能回答真实 H67 wall time 或目标 PPA。

### 阶段 B：真实四阶段 projection-only

复用当前 S0-S3 payload、weight、bias 和 expected acc32 向量，分别驱动三路独立 replay client，比较：

- 逐元素 acc32、checksum、term/head/final 守恒；
- 三路完成时间和 join wall time；
- slot word read、decoder term、weight bank access、bias access；
- p50/p95/p99/max bank skew 和 stall。

### 阶段 C：Central 与 DCTF 同物理 bank

Central 接入三 weight bank coalescer和六个32-lane Acc macro；DCTF Q=2 接入三个 bank-local weight/product/Acc。相同 SRAM latency、相同 SDC、相同 final sink 下运行同一 trace。

### 阶段 D：目标库签核

在同 node/library/PVT/SDC/SRAM macro 下完成 DC/STA/SAIF/LEC，并分账 logic、memory、clock、interconnect、leakage。当前开放库映射不替代此阶段。

## 7. 必报指标

| 类别 | 指标 |
|---|---|
| 正确性 | acc32 mismatch、checksum、完成/abort唯一性、stale输出 |
| 周期 | projection-only wall time、Builder+projection、p50/p95/p99/max |
| replay | slot read word、read port数、decoder term、cache fill/release |
| 权重 | logical req、physical bank access、payload bit、bank skew |
| Acc/final | bank update、conflict、final stall、宽度和宏形状 |
| 面积 | decoder、command fabric、product、Acc SRAM、bias、控制、互连 |
| 功耗 | weight SRAM、Acc SRAM、logic、clock、interconnect、IO、leakage |
| 系统 | full encoder Amdahl占比、帧率、energy/frame、AEE/AAE不变性 |

## 8. 创新晋级门槛

HATF/DCTF 只有满足以下之一才作为 DATE 主架构贡献：

- 相对 `3xIndependent32`，完整 projection EDP 改善至少 `15%`；
- 或总能量降低至少 `10%` 且总面积降低至少 `10%`；
- 同时 full encoder 分账仍有可见净收益，且 H67 部署结果 bit-exact 或满足已冻结精度门槛。

若只证明 96 lane 比 32 lane 快，HATF96 降级为实现参数；若 DCTF 只完成多消费者 FIFO 叶模块而未接 bank-local weight/product/Acc，也不能列为主贡献。

## 9. 当前状态

- HATF96-Central：真实单窗口 RTL 周期与开放逻辑映射已完成，但物理宽网和等并行度对照未关闭；
- DCTF：Q=2/3/4 多消费者有序 command queue 叶模块已通过，尚未接真实后端；
- BSF：功能和周期收益成立，但 flop-based 面积归一吞吐 `0.963x`，已条件降级；
- `3xIndependent32`：进入结构 wrapper 实现，真实四阶段三读口 replay 仍待补。

因此当前仍是架构探索状态，不是 DATE 接收或 ASIC sign-off 状态。
