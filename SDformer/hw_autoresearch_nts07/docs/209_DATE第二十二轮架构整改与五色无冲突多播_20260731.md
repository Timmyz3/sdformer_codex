# DATE 第二十二轮架构整改与五色无冲突多播

> 本文件是 TCFM-5 物理化前的历史快照。显式五 bank、同步 RMW、
> RAW forwarding、close/drain、K-bitmap iterator 和第四轮复评整改，以
> `210_DATE第二十三轮五色拓扑多播物理化与第四轮复评整改_20260731.md`
> 为准。

## 1. 本轮结论

本轮没有继续堆叠普通 FIFO、context 或 bank 数，而是完成两类工作：

1. 关闭第三轮独立复评发现的关系转置正确性 P0；
2. 在 FCSR-RX 后提出并实现 **TCFM-5（Topology-Colored
   Five-bank Multicast，五色拓扑无冲突多播）**，把 source-major
   descriptor 变成可实际执行的 product-multicast 数据流。

当前 Local5 架构链为：

```text
XBF-DBDR exact score fabric
    -> FCSR-RX bounded-lifetime relation transpose
    -> source gate-equivalence term builder
    -> TCFM-5 conflict-free product multicast
    -> five bank-local Acc
```

这比“score 算子 + 三 bank DCTF”更具架构特异性，因为每一级都由固定五点
关联图的代数或拓扑性质驱动。

当前裁决仍是：

- 架构研究：继续；
- RTL：可进入目标 SRAM mapping 前的下一轮审阅；
- DATE：仍为 Weak Reject，主要缺真实 Local5 trace、完整投影集成和目标工艺
  PPA。

## 3. P0 整改

### 3.1 边界 SRAM 地址

旧实现即使最后用 mask 丢弃边界数据，仍无条件形成 `x-1/x+1` 地址。
`x=0` 会下溢，最后一行槽的 `x=W-1` 会产生 `RING_ENTRIES`。

整改后：

```text
west invalid -> clamp to source_addr
east invalid -> clamp to source_addr
valid bit    -> 决定响应是否进入 descriptor
```

并在同步 bank bind 中加入：

```text
wr_en -> wr_addr < DEPTH
rd_en -> rd_addr < DEPTH
```

钳位只保证物理地址合法，不把边界关系重新标为有效。

### 3.2 真实平面生命周期

单看 scheduler/FIFO 为空不能代表一个平面已经结束。定向测试在前三个 token
后保持下一平面 `plane_start`，旧实现确实出现 `sid=12` 的跨平面 K mismatch。

整改后 relation leaf 增加：

```text
plane_active
accepted_tokens in [0, H*W]
plane_input_complete
datapath_drained
```

只有满足：

```text
accepted_tokens == H*W
&& scheduler/FIFO/read pipeline fully drained
```

才拉高 `plane_idle`。实际切换为：

```text
plane_start_fire = plane_start && plane_idle
```

提前保持 start 的定向测试通过，24 个两平面 descriptor 仍逐项 exact。

### 3.3 partial-valid 关系转置

每个 gate bank 的数据项由 9 bit 扩为：

```text
{1-bit relation_valid, 9-bit gate}
```

descriptor mask 不再只按几何坐标重建，而是把 destination 侧 runtime
partial-valid 按逆方向读取并转置。测试覆盖：

- self 动态失效；
- 纵向候选动态失效；
- 横向候选动态失效；
- `gate=256` 的第九位；
- 几何边界与动态 invalid 同时存在。

因此当前 mask 合同是“真实关系是否存在”，不是“坐标是否合法”的代理。

## 4. Stripe 公平基线与负结果

### 4.1 两个真实 Pareto 点

| 候选 | ring | 策略 |
|---|---:|---|
| Stripe-3 | 3 行 | 行首保守阻塞 + row-distance watermark |
| Stripe-4 | 4 行 | 允许提前填充 + row-distance watermark |

水位规则保护的不只是最老 source 行，还包括其所需的前一 destination 行：

```text
writer_row < oldest_required_relation_row + ring_rows
oldest_required_relation_row = max(oldest_source_row - 1, 0)
```

### 4.2 被测试否决的版本

仅以“两项 row context 是否满”为依据放行 Stripe-4 会在长反压下提前覆盖
旧 relation。测试先后抓到：

- source `sid=3` 的横向 gate 被 row4 覆盖；
- source `sid=5` 的 north relation valid 被 row4 覆盖。

这两个失败版本不进入候选结果。

### 4.3 最终周期与结构

`15x15`、同步六 bank、两项 FIFO、无 descriptor 输出反压：

| 候选 | 周期 | relation 状态 bit | Yosys flat cells |
|---|---:|---:|---:|
| FCSR-RX | 244 | 3690 | 11640 |
| Dynamic Frontier-RX | 244 | 3690 | 51113 |
| Safe Stripe-3-RX | 451 | 3690 | 11142 |
| Early-fill Stripe-4-RX | 265 | 4920 | 12388 |

可辩护结论：

- FCSR 与公平 Dynamic 同周期，收益是消除动态依赖追踪；
- 相同三行状态下，FCSR 比安全 Stripe-3 少 207 cycles；
- Stripe-4 的第四行确实用于提前填充，把 451 降至 265 cycles；
- FCSR 仍比 Stripe-4 少 21 cycles，并减少 25% relation state bit。

不可辩护结论：

- Yosys flat cells 不是目标工艺面积；
- Dynamic 的变量索引网络尚未映射为公平 banked physical baseline；
- 这些周期仍是规则流，不是 post-G0 trace。

## 5. TCFM-5 架构

### 5.1 源侧精确因子化

Local5 投影满足：

```text
Y[d,o] = sum_s sum_l Gate[d,s] * K[s,l] * W[l,o]
```

对固定 source、lane 和 gate：

```text
P[s,l,g,o] = g * W[l,o]
```

所有满足 `Gate[d,s]=g` 的 destination 共享同一个 `P`。因此 FCSR descriptor
可按非零 gate 等价类变换为：

```text
{source, lane, gate, five-role destination mask}
```

该变换不删除边，不改 gate，也不改变整数累加顺序允许的结果集合。

实现文件：

- `rtl_qfit/qfit_source_multicast_term_builder.sv`
- `tb_qfit/tb_qfit_source_multicast_term_builder.sv`
- `verif_qfit/qfit_source_multicast_assertions.sv`

定向向量包含四个 active K lane、三个 gate class 和 `gate=256`：

```text
12 product terms -> 20 destination updates
```

Icarus、Verilator/SVA 和 Yosys `check -assert` 均通过。该数字仅是功能向量，
不是部署压缩率。

### 5.2 五色无冲突定理

定义 destination bank：

```text
bank(x,y) = (x + 2y) mod 5
```

若 source color 为 `c`，五点 destination 的 bank 分别为：

```text
self  : c
east  : c + 1
south : c + 2
north : c - 2 = c + 3
west  : c - 1 = c + 4        (mod 5)
```

它们覆盖模 5 的全部五个剩余类，因此互不冲突。对 `W=15`，每 bank 的本地
地址可写成：

```text
local_addr = plane * H * 3 + y * 3 + floor(x/5)
```

一般宽度使用 `ceil(W/5)`，空槽只作为 padding。

### 5.3 物理数据流

```text
source multicast term
 {source y/x, lane, gate, role mask}
             |
             v
       one gate*W product
             |
     fixed role-to-color rotation
      /      /     \      \
 bank0   bank1   ...    bank4
 local Acc 1W each, no conflict
```

它与普通 destination-modulo bank 的区别是：

- bank 函数由五点拓扑推导；
- 同一 source 的全部合法 destination 天然一一落入五个 bank；
- 不需要运行时 conflict detector、重放队列或 crossbar 仲裁；
- product 计算一次，destination update 保持原数目。

实现文件：

- `rtl_qfit/qfit_tcfm5_projection_top.sv`
- `tb_qfit/tb_qfit_tcfm5_projection_top.sv`
- `verif_qfit/qfit_tcfm5_assertions.sv`

定向测试的 3 条 term 完成 11 次 bank-local Acc 更新，所有 readback 与整数
金参考一致；Icarus、Verilator/SVA 和 Yosys 均通过。

## 6. 与既有工作的关系

| 工作/范式 | 借鉴 | 本土化变化 |
|---|---|---|
| Prosperity | exact product reuse | 不做运行时 matcher；复用类由 gate 与固定 relation 直接给出 |
| Phi pattern/residual | 固定 pattern 走专用快路 | 五点 relation 和 color rotation 是编译期固定 pattern |
| Bishop TTB | metadata-first 工作单元 | term 携带 source/gate/role mask，不做 ECP 近似或密疏双核 |
| sparse outer product | product 后 scatter | 用五色拓扑保证五 destination 单拍无冲突 |
| graph coloring | 相邻元素映射到不同颜色 | 选择 `x+2y mod5`，使五点 star 的五个目标恰好覆盖全部 bank |

TCFM-5 不是把上述工作换名字。可写的新差分是：

> 利用 Local5 固定五点关联图的模 5 完美着色，把 source-side gate-equivalence
> product reuse 与 Acc bank conflict elimination 合并为同一数据流。

## 7. 下一项架构主张：双轴精确商执行

现有 destination-major MFEP 与本轮 source-major multicast 是同一关系矩阵的
两种精确因子化：

```text
destination quotient:
  fixed d -> group source edges by {gate,lane} -> multiplicity fold

source quotient:
  fixed s -> group destination edges by gate -> product multicast
```

下一轮应实现 **BiQX（Bidirectional Quotient eXecution，双轴精确商执行）**：

1. 用相同 gate/K/weight/Acc 合同实现两种方向；
2. 以每 stage 或 window 的真实 term 数选择方向；
3. 共享 product lane 与五色 Acc bank；
4. 给出 destination-only、source-only、BiQX 三者的 term、cycle、SRAM
   traffic、bank stall 和能耗分账；
5. selector 必须基于 exact metadata，不允许改变网络结果。

在 post-G0 trace 到达前，只能证明双轴代数等价和 RTL 可行，不能声称 selector
带来部署收益。

按优先级：

1. Local5 full-resolution post-G0 trace，统计每 stage 的 destination/source
   quotient term、gate class、K firing、五色 bank 活跃度和 p95/p99；

   bit-exact tile；
3. 建立 destination MFEP 与 source multicast 的同 lane、同 SRAM、公平基线；
4. 使用同一 SRAM macro、Liberty 和 SDC 运行 DC/STA/SAIF；
5. 清理参数化 RTL 的宽度告警，并补最小尺寸、raster 顺序和非法坐标断言；
6. 用多个真实 sample/window 报告 mean/p95/p99，而不是只报 24 个合成
   descriptor。

因此本轮的正确表述是：

> 已形成并验证新的架构机制 TCFM-5，且关闭 FCSR-RX 三项功能 P0；尚未形成
> DATE 可接受的真实 workload/PPA 结果闭环。
