# 拓扑商裂分融合架构与 DATE 主张冻结

> **更新说明：**同 lane monolithic 基线与 ACQN-163 结果已在
> `docs/188_同lane基线负结果与ACQN共享归一化架构_20260730.md` 更新。
> 本文件中的 Motion fission/fusion 与“三项贡献”不再视为最终冻结结论。

## 0. 本轮结论

本轮停止把 `SCS-Shiftmax`、term 编码、3-bank、双 context 分别包装成
架构创新，冻结一条新的系统主张：

> **Topology-Quotient Event Architecture（TQEA）**：利用网络已经声明的
> temporal-pair 或 five-point stencil 拓扑，在硬件中构造 exact 候选等价类；
> 一个 32-lane anchor 核与四个可裂分/可融合 residual slice 在 Motion 和
> Local5 间改变组织方式；候选 multiplicity 贯穿加权归一化、term 形成和
> receiver-owned projection，不再反复展开重复候选。

TQEA 当前包含两项需要独立证伪的架构假设：

1. **TQ-FFE：Topology-Quotient Fission-Fusion Engine**；
2. **TRCF：Term-Resident Cross-Term Coalescing Fabric**。

`SCS-Shiftmax`、MFEP、DCTF、TTB/STT 和 butterfly 均降为支撑单元或数据格式，
不再单独列为 DATE 核心贡献。TQ-FFE 与 TRCF 也尚未因命名而自动成为贡献，
只有完整边界 RTL/PPA 达标后才能晋级。

---

## 1. 为什么必须换架构抽象

当前 Local5 同顶层 RTL 已证明：

| 路径 | 相对 Direct 周期 | 开放门数变化 |
|---|---:|---:|
| 串行 TARE | 慢 10.20% 至 14.08% | 仅减少约 1.35% |

根因不是 residual 算法无效，而是核组织错误：

- Direct 同时计算 self/N/S/E/W 五个 score；
- 旧 TARE 让四个方向共用一个 residual transaction 通路；
- anchor 驻留、candidate commit 和状态切换串行；
- lane-work 虽减少，但五点 row 的完成时间反而增加。

因此，本轮不再问“如何继续缩短 descriptor”，而是回答三个架构问题：

1. score 核如何组织，才能在减少 lane 的同时保持一 row/cycle；
2. 重复候选如何从 score 一直保持压缩到 projection；
3. destination fanout 如何避免反复穿过全局 fabric。

## 2. TQEA 总体数据流

```text
Topology Descriptor / Line Buffer
        |
        v
+---------------------------+
| Exact Topology Router     |
| identity / sparse / dense |
+-------------+-------------+
              |
              v
+-----------------------------------------------+
| TQ-FFE                                        |
|                                               |
|  32-lane Anchor Score                         |
|          |                                    |
|   +------+------+------+------+               |
|   | R0x4 | R1x4 | R2x4 | R3x4 | residual PE |
|   +------+------+------+------+               |
|                                               |
| Motion:  4 slice fuse -> 16-lane temporal     |
| Local5:  4 slice split -> N/S/E/W in parallel |
+----------------------+------------------------+
                       |
                       v
        {score_q7, multiplicity, relation, tag}
                       |
                       v
+-----------------------------------------------+
| Weighted Quotient Normalizer                  |
| Motion: SCS weighted class occupancy          |
| Local5: Shiftmax5 weighted candidate set      |
+----------------------+------------------------+
                       |
                       v
       {gate_q17, lane, multiplicity, dest-list}
                       |

+-----------------------------------------------+

| unique term header -> global fabric once      |

| cross-term M4 walker -> bank-local Acc         |
+-----------------------------------------------+
```

这是一条完整的 `candidate formation -> score -> normalization -> projection`
数据流，不是把现有叶模块串成框图。

## 3. 核心机制一：TQ-FFE

### 3.1 物理组织

平衡配置冻结为：

```text
anchor score lanes  = 32
residual slices     = 4
lanes per slice     = 4
total score lanes   = 48
```

四个 slice 不是四套完整核。它们共享：

- descriptor decode；
- anchor Q/K 寄存器；
- score class/rounding 单元；
- weighted normalization backend；
- direct escape 与最终 commit。

每个 slice 只含：

- 32-bit delta mask 的有界 lane selector；
- 四个 signed residual update lane；
- 小型 pending FIFO；
- relation tag 和完成计数。

### 3.2 Motion 模式

```text
{K_t0, K_t1}
   -> anchor score(K_t0)
   -> delta mask(K_t0 XOR K_t1)
   -> R0/R1/R2/R3 fuse into 16-lane residual engine
   -> score(K_t1) reconstructed exactly
```

只有 `delta=0` 时，两个 temporal candidate 才形成 multiplicity=2 的等价类。
不能使用事后 `score_equal` 统计折叠非 identical K。

profile100 ordered 模型结果：

| slice 配置 | nominal score lane | residual 服务保持 | nominal lane 指数 | 最大待服务周期 | 决策 |
|---|---:|---:|---:|---:|---|
| 4x2 fused | 40 | 0.99995x | 1.600x | 2080 | 淘汰：队列过深 |
| 4x4 fused | 48 | 1.00000x | 1.333x | 179 | **进入 RTL** |
| 4x8 fused | 64 | 1.00000x | 1.000x | 0 | 淘汰：无 lane 收益 |

这里的 lane 不是门面积，residual 服务保持不包含 selector、FIFO、atomic join、
normalizer 和 projection 反压；最大待服务周期也不是 FIFO entry 深度。上述结果
仅是 `[模型]+[prof-ordered]` 的 RTL 原型筛选。

### 3.3 Local5 模式

```text
                 +-> R0: self -> north
Q, K_self ------ +-> R1: self -> south
                 +-> R2: self -> west
                 +-> R3: self -> east
```

每个方向拥有独立 residual slice 和 FIFO，四条关系并行。`neighbor K ==
self K` 时不发重复 score transaction，只增加 anchor equivalence class 的
multiplicity。boundary-invalid candidate 不进入 multiplicity。

pre-G0 profile100 服务量下界：

| slice 配置 | nominal score lane | residual 服务保持 | nominal lane 指数 | 决策 |
|---|---:|---:|---:|---|
| 4x2 split | 40 | 0.946x | 3.784x | 淘汰：低于 0.95x |
| 4x4 split | 48 | 0.999x | 3.331x | **等待 ordered trace** |
| 4x8 split | 64 | 1.000x | 2.500x | 保守备选 |

Local5 结果只证明总服务量，不证明瞬时 FIFO 深度。fullres post-G0 ordered
trace 到达前，不允许写入论文主结果表。

### 3.4 Exact Topology Router

router 使用三个守恒出口：

```text
ZERO     : exact identity，增加 multiplicity
SPARSE   : 1..W 个 delta，进入 residual slice
DENSE    : >W，进入多拍 residual 或 direct escape
```

必须满足：

```text
accepted_candidate = ZERO + SPARSE + DENSE
```

完整 32x32 butterfly/Benes 不是默认实现。RTL 阶段必须同约束比较：

1. linear priority selector；
2. 分层 `8x4` selector；
3. partial butterfly；
4. 现有 LIST4 decoder。

只有 partial butterfly 在计入布线、toggle、FIFO 和 escape 后仍改善 EDP，
才保留该实现。论文不能声称“提出 butterfly zero skipper”。

## 4. 核心机制二：Multiplicity-Carrying Quotient Flow

### 4.1 等价关系

只允许使用网络拓扑已经给出的 exact identity：

```text
Motion:
  candidate(t0) ~ candidate(t1)
  iff K_t0 == K_t1

Local5:
  candidate(self) ~ candidate(direction)
  iff K_self == K_direction and direction is valid
```

每个等价类存储：

```text
{representative_K, score_q7, multiplicity, relation_mask, destination_list}
```

### 4.2 数值顺序

为保持 hardware-order bit-exact，不能把 multiplicity 随意前移：

1. representative score 按原 Q7 顺序计算；
2. Shiftmax denominator 使用
   `multiplicity * exp2(score - max)`；
3. representative gate 仍按原 Q1.7 顺序量化；
4. projection 对量化后的 gate 做 multiplicity 次等价整数累加；
5. 禁止先计算 `multiplicity * float_gate` 再一次量化。

因此，本工作不是“把相同 score 删除”，而是把重复候选改写为带权元素，并保持
原算法的计数与舍入顺序。

### 4.3 双线实测工作量

| 主线 | 候选减少 | score lane-work 减少 | 候选缓冲 bit 减少 | unique product 生成减少 |
|---|---:|---:|---:|---:|
| Motion | 37.04% | 48.75% | 32.85% | 82.49% |
| Local5 | 67.13% | 76.57% | 60.56% | 92.71% |

Motion 使用真实 ordered profile100；Local5 是 pre-G0 profile100。T162 缓冲
位宽按 `Q7 score + 8-bit token id + 1/3-bit multiplicity` 建模；T450 必须
使用 9-bit destination/token id。

`unique product` 不含 destination Acc RMW。每个 destination 的 accumulator
更新和 multiplicity 守恒仍必须执行，不能把该比例与 TRCF 服务上界相乘，也
不能写成端到端加速或功耗。

## 5. 条件候选：TRCF

### 5.1 为什么 DCTF 不足

现有 DCTF 的优点是共享 sparse frontend、发送窄命令并在 bank-local 执行。
但 source-side push 仍随 destination fanout 重复发送命令：

```text
unique term -> destination0 command
            -> destination1 command
            -> ...
```

3-bank、consume-mask 和双 context 都是合理工程结构，但不能解决上述全局
fanout 流量，也不足以单独构成 DATE 创新。

### 5.2 Term residency 与跨 term 尾部合并

现有 3 个 projection bank 按 output channel 分 bank，并不是三个独立
destination port，不能把 destination 数简单除以 3。TRCF 保持同样的 M4
destination 端口预算，只改变 term 和 destination list 的驻留位置：

```text
term builder
   |
   +-> projection-bank local destination list SRAM

unique term header --global fabric once--> term context
multiple resident terms -> cross-term M4 walker -> local Acc update
```

现有 source-side M4 在每个 term 内单独打包，fanout 不能整除 4 时会留下尾部
空槽。TRCF 允许多个 resident term 的尾部 destination 在同一拍占用四个
destination port；每个 term 的 product 保存在小型 context 中，global
sequence 在全部 destination 完成后退休。

全局 fabric 携带：

```text
{global_seq, gate_q17, lane, multiplicity, bank_mask, last}
```

bank-local destination SRAM 携带：

```text
{destination_id, first, last, parity/port_class}
```

### 5.3 预筛结果

模型假设：

- source push command 为 64 bit；
- unique term header 为 48 bit；
- local destination entry 为 11 bit（9-bit id + 2-bit flag）；
- 三个 output-channel projection bank；
- 每拍最多四个 destination，与 M4 基线一致；
- Motion 只在同一 ordered row 内理想跨 term 合并；
- 只比较 projection execute phase。

| 主线 | 全局 fabric bits 减少 | 计入本地 list 后总 bits 减少 | 服务周期代理 |
|---|---:|---:|---:|
| Motion | 61.56% | 11.23% | 1.177x |
| Local5 | 93.30% | 76.11% | 4.000x |

关键证伪条件：

> destination list 必须在 projection bank 本地构建，且多个 term product
> context 必须允许 M4 尾部跨 term 合并。若每个 destination 仍需先通过全局
> fabric，或 product 只能逐 term 串行驻留，TRCF 主张立即失效。

Motion 的 1.177x 是逐 row 理想上界，现有 trace 没有逐 term destination
和 port class，尚不能证明无 RAW 冲突或 product context 命中。Local5 的
4.000x 还建立在 pre-G0 一 destination/command 保守基线上，必须等待真实
ordered term stream。

按 T450 所需 `9-bit destination + 2-bit flag` 修正本地 list 后，Motion
计入本地 SRAM 的总 bit 收益只有 11.23%，低于 15% 门槛，**Motion TRCF
当前淘汰**。Local5 TRCF 仍为 post-G0 trace 阻断的条件候选。

## 6. 接口合同

### 6.1 Topology descriptor

建议逻辑字段如下，物理压缩在 RTL 后再定：

```text
mode              TEMPORAL2 / LOCAL5
stage_id          2 bit
block_id          4 bit
window_id
head_id
token_id
valid_relation    5 bit
anchor_addr
peer_base/stride
projection_bank_mask  3 bit
first / last
```

descriptor 是控制合同，不作为独立创新。

### 6.2 Quotient score stream

```text
q_valid / q_ready
q_tag
q_score_q7
q_multiplicity    1 bit Motion / 3 bit Local5
q_relation_mask
q_first / q_last
```

### 6.3 Quotient term stream

```text
t_valid / t_ready
t_global_seq
t_gate_q17
t_lane_id         5 bit
t_multiplicity
t_projection_bank_mask
t_first / t_last
```

### 6.4 Backpressure

- residual slice 可以独立停顿；
- 一个 candidate set 只有全部合法 relation 完成后才能原子提交到 normalizer；
- normalizer 反压必须回传到 anchor issue；
- TRCF term context credit 独立，但 global sequence 只在全部 destination
  ack 后退休；
- 不允许同一 quotient class 局部可见。

## 7. 存储层次

```text
L0 registers
  Q / anchor-K / 4 residual slice state

L1 topology buffer
  temporal pair buffer or Local5 line buffer

L1.5 quotient FIFO
  {score, multiplicity, relation, tag}

L2 term directory
  {gate, lane, multiplicity, bank mask, list pointer}

L2 bank-local destination SRAM
  destination list and cross-term walker state

L2 bank-local Acc SRAM
  output partial sums

Weight SRAM
  bank-local, one read per unique term
```

SRAM macro 数、端口与 banking 必须进入同边界 DC/PPA。不能继续只综合控制逻辑，
再把 SRAM 视为免费。

## 9. DATE 候选贡献

若完整 RTL/PPA 达标，论文最多保留三条候选贡献：

1. **拓扑商事件执行原则**：将 temporal/stencil exact identity 转换为
   multiplicity-carrying quotient stream，并保持原 Shiftmax 与整数投影顺序；
2. **TQ-FFE 核组织**：一个 anchor 核与四个 residual slice 在 Motion 中融合、
   在 Local5 中裂分，以同一物理组织匹配两种拓扑并消除串行 TARE 瓶颈；
3. **条件贡献 TRCF**：unique term 全局只发送一次，destination list 在
   projection bank 驻留，并通过多 term context 合并 M4 尾部碎片；当前只在
   Local5 post-G0 逐 term trace 与 RTL 达标后才允许晋级。

其中：

- 第 1 条是软硬件协同表示与数据流贡献；
- 第 2 条是计算核组织贡献；
- 第 3 条是存储层次与互连贡献。

Motion TRCF 已被 9-bit destination 流量门槛淘汰。Local5 TRCF 在逐 term
trace、本地建表与 product context RTL 完成前不能列入投稿贡献。若最终只有
TQ-FFE 与 quotient contract，仍需完整 PPA 和系统调度贡献补强。

## 10. 公平评估矩阵

同一 transaction 边界：

> 首个 topology descriptor 被接受，到最后一个 destination accumulator
> commit。

必须比较：

| 编号 | Score | Quotient | Projection fabric |
|---|---|---|---|
| B0 | Direct-wide | off | source push |
| B1 | 串行 TARE | on | source push |
| A1 | TQ-FFE | on | source push |
| A2 | TQ-FFE | on | TRCF |

必须统一：

- 相同 Q7/Q1.7 和 hardware-order；
- 相同目标频率与 SDC；
- 相同 SRAM macro/端口规则；
- 相同 weight/Acc 容量；
- 相同反压与 1/2/3-cycle SRAM latency；
- 相同 fullres T450 workload；
- crop T162 只作为 debug 与回归，不作为最终 PPA workload。

输出指标：

- cycle mean/p50/p95/p99/max；
- residual FIFO 与 destination FIFO 最大占用；
- logic area、SRAM area、总面积；
- Fmax/slack；
- SAIF 动态功耗、漏电、energy/frame、EDP；
- activation/K/descriptor/weight/Acc/fabric bit traffic；
- bit-exact mismatch 数；
- Motion 与 Local5 分 stage/block 的收益和负结果。

### G0：模型收口

1. Motion W4 fused 与同 lane monolithic16 的同顶层 RTL 校准；

3. Local5 fullres post-G0 ordered relation/destination trace；
4. partial-butterfly、hierarchical selector、LIST4 的 toggle/Fmax 代理。

### G1：TQ-FFE 叶模块

## 12. 淘汰门槛

### TQ-FFE

- 完整 score-to-term RTL 相对 Direct-wide 吞吐保持 `>=0.95x`；
- nominal lane 减少至少 20%，但只作结构筛选，不替代面积；
- residual 最大待服务债务 `<=256 cycle` 才进入 RTL，真实 FIFO entry 深度
  由 RTL replay 决定；
- transaction latency `p99/mean <=1.25`，不能使用 sample-total p99 替代；
- 目标工艺 score 核面积或动态功耗至少下降 20%；
- attention-to-projection EDP 至少改善 15%。

### TRCF

- 全局 fabric bits 至少下降 50%；
- 计入 local destination SRAM 后总流量至少下降 15%；
- 逐 term RAW/port conflict 和本地 walker 后端到端 EDP 仍改善 15%；
- destination SRAM 与 router 增量面积不超过子系统 15%；
- destination 无丢失、无重复、全局退休无死锁。

### 整篇论文

- Motion fullres hardware-order bit-exact；
- Local5 fullres hardware-order bit-exact；
- 至少多 sample、多 window 的 mean/p95/p99；
- 同 SRAM/SDC 的 DC+STA+SAIF；
- Motion 使用 A1 对 B0 校准；Local5 只有在 post-G0 trace 到达后才评估 A2。
  任一准备写入主文的架构机制，其同边界 EDP 改善必须至少 15%。
