# M912｜M528 元数据流水草案与商业验证门

## 裁决

M912 是 additive timing-repair draft，不覆盖 M528 r2，不改变 product-capture 算法、父关系、稳定执行顺序、单口 scratch、两项 parent-response 容量或顶层端口。它只把目录选择/预取和 96-lane 算术用元数据寄存边界隔开。

当前不得引用为 RTL 加速、3 ns 时序或 PPA。M892 的正式 top-100 timing report 已完成并证明 r2 未过 3 ns；M912 VCS、DC、Formality 尚未完成。

## M892 实测对 M912 的约束

M892 在 9/9 parent-scratch macro 绑定成功、precompile `TIM-209=0/OPT-150=0`、DC/TCL 正常退出的前提下，setup slack 为 `-7.0468 ns`，因此目录被 fail-closed quarantine。top-100 路径具有如下统一特征：

- `100/100` 起点都是 `exec_bank_q_reg`；
- 终点包含 `psum_write_valid`、`row_complete_valid`、`issue_data_ready` 各 10 条；
- 10 条落到真实 parent-scratch macro 端点；
- 其余 debug 终点与功能终点共享同一条长锥，所以“只延迟 debug”不能解决真实时序。

这些证据准入 M912 的 `active_ctx/next_ctx/pf_token` 元数据边界，但不证明 M912 一定达到 3 ns。当前 top-100 被 `exec_bank_q` 长锥垄断，切断后 64-row 候选选择器或 96-lane 算术路径可能成为新的 critical path，必须用 M912 商业 DC 实测。

## 唯一允许的结构变化

1. `active_ctx` 保存 epoch、row、remaining mask、parent 元数据、popcount、live、first、`primed` 与关系合法位。`primed` 在一个独立元数据周期内锁存“已预留下一行或已证明无下一行”，避免 64-row 组合扫描回到功能 ready/valid 路径。
2. `next_ctx` 仅保存下一行相同元数据；当前行 final accept 时同沿提升，因此目标是行间零泡。
3. `pf_token` 保存一个 `(consumer,parent)`；接受当前 token 的同沿可装入严格更晚的候选。
4. 既有两项 `1152-bit` parent response slot 保持不变。禁止新增 residual/psum payload FIFO，禁止第三项 parent slot。
5. debug event 变为真实内部接受事件的一拍观察值。macro enable、bitmap 更新、queue enqueue 和 `psum_write_valid` 仍由真实内部事件驱动，禁止以 false-path 或只延迟 debug 的方式冒充功能时序修复。
6. row-dispatch 和 prefetch 各使用一棵每 bank 独立的 64-leaf/6-level 平衡 tournament，再在根部用 `exec_bank` 选择。这一变化保持 `(popcount,row-id)` 稳定顺序，专门避免 M892 中 `exec_bank` 被复制到线性 64-row 优先链的结构根因。它仍需 DC 证明工具实际保留平衡形态。

## 外部 ready/valid 语义

- 顶层端口集合、方向和位宽与 r2 完全相同。
- `issue_request_valid` 和全部 request 字段只来自已 `primed` 的 `active_ctx`。
- `issue_data_valid && issue_data_ready` 仍是唯一 payload/beat accept；没有新增 request handshake。
- stall 期间 request、residual payload 和 psum prior 必须稳定。
- final beat 仍要求 psum 与 row-complete 两个 sink 同时 ready，二者同时 valid/accept。
- overflow、格式错误、parent-only 非零 residual 仍在任何架构事件之前 fail closed。

## 冻结性能门

冻结 CPU 同账本基点：

- candidate：`435,293,339` cycle；
- M468 strong-zero：`760,350,133` cycle；
- same-coordinate bit：`757,946,784` cycle；
- task：`812,160`；active row：`27,305,568`。

当前 M912 为了不让候选扫描直接控制发射，显式收费每 task 两拍：一拍填 `active_ctx`，一拍锁存 `next_ctx`/无后继证明。因此当前唯一的预注册目标是 `436,917,659` cycle，分别为 `1.740259560x` 和 `1.734758869x`。`+1/task` 的 `436,105,499` cycle（`1.743500448x/1.737989513x`）只作未来双 context 同拍填充优化上界，不得套到当前 RTL。这些仍是预注册门，不是当前测量结果。

任何每 active row 一拍的方案会变成 `462,598,907` cycle，只剩 `1.643649x/1.638453x`，立即 NO-GO。保持 `>=1.70x` vs bit 的总周期硬上限是 `445,851,049`。

面积门：禁止宽 payload 新寄存；新增 metadata 不得超过 `512 FF`。按显式字段计数，当前 `active/next/pf/debug` 新边界共 `130 bit`（平衡 tournament 全为组合逻辑）。M892 诊断基线的 macro-aware total cell area 是 `156,394.874050 um^2`，其中 9 块 macro 为 `78,825.243164 um^2`，standard-cell 约 `77,569.630886 um^2`。M892 未过 setup，这些只是同流程面积对照，不是 paper PPA。M912 同工具门设为：macro 数量仍为 9、total cell area `<=172,034.361455 um^2`、standard-cell area `<=85,326.593975 um^2`（两者都是 M892 对照的 `1.10x`），并最终要求 matched throughput/mm2 `>=1.15x`。正式面积只取 DC report，不能误读 compile 进度表的 leakage 列。

## VCS 改造计划

从 r10 cleanroom oracle additive 派生，禁止覆盖旧 TB：

1. 保留全部 64-row parent/reference、96-lane signed result、psum、single-port、queue order、conservation 与攻击 oracle。
2. oracle 增加 `active_ctx/next_ctx/pf_token` 状态；目录选择仍按 `(original_popcount,row_id)` 稳定排序。
3. 执行启动显式允许两次 metadata fill（`active` 装入 + `primed` 锁存）；必须逐 task 计数，不得把填充或尾排空藏在窗口外。
4. final accept 后若 `next_ctx` 或合法 candidate 存在，下一拍 request 必须有效；统计所有非协议 stall 的行间泡，要求为零。
5. debug 事件与内部真实事件错开一拍；功能 scoreboard 只能看内部 accepted-event mirror 或架构输出，不能用 debug 延迟改变接受时刻。
6. 覆盖 empty/nonempty、one-beat、16-beat、parent-only、partial-parent、多行连续 final、deadline read-then-write、same-address forward、read-response+forward dual enqueue、queue-full、随机双 sink backpressure、reset 与全部旧攻击。
7. 增加长随机回归，逐 task 比较 r2 与 M912 的完成行顺序、每行结果、scratch read/write/forward/dead 数量；允许的差异只有明确收费的 pipeline fill/debug 观察延迟。
8. 若 pf token 导致新的 parent wait 或 deadline hold，全部计入 measured cycle；不得继续套用“每 task 一拍”的分析值。

## 商业工具顺序

1. M892 正式 top-100 timing endpoint 已消费；确认 debug mirror 与真实 `psum_write_valid`/macro/state endpoint 共享 `exec_bank_q` 长锥。
2. 新源码独立静态 hammer；随后单次 VCS compile+directed/random regression。
3. VCS 全绿且 measured cycle 过门后，才允许一次 3 ns macro-aware DC。
4. DC 必须同时检查 `psum_write_valid`、macro enable、completed/written/prefetched bitmap、queue enqueue 与 debug pins；不能只让 debug endpoint 消失。
5. setup MET 后才做 Formality；PT/PTPX 与 matched baseline 之后才能讨论 paper PPA。
