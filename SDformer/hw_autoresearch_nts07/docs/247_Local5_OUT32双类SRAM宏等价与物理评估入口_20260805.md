# Local5 OUT32 双类 SRAM 宏等价与物理评估入口

## 1. 本轮要回答的问题

第九轮 DATE 独立评审认为，DS-GASR 相对 Issue-GASR 的同版本周期收益只有
`1.025x`，不能仅凭抽象 SRAM 事务数宣称能效优势。本轮因此冻结所有架构变量，
只补齐部署输出维度和 SRAM 宏合同：

1. 输出维度固定为 `OUT_DIM=32`；
2. 五个累加器 bank 均为 `90x1024 bit`；
3. 每个累加器 bank 用四个 `fakeram45_128x256` 并联，共 20 个累加器宏；
4. 关系存储使用两个 `256x32` 和十个 `256x16`，共 12 个关系宏；
5. Direct、Issue、DS 使用相同的 32 个宏、相同端口和相同一拍同步读合同；
6. 三者只保留原有的执行方式与 descriptor 同步点差异。

本轮不改变 Local5 算法、term 集合、五色映射、权重位宽或累加结果。

## 2. 宏绑定结构

### 2.1 累加器宏

一个五色 bank 覆盖 `2 x 15 x 3 = 90` 个空间位置，每个位置保存 32 个
32-bit 累加值，总字宽为 1024 bit。硬件采用四个 256-bit SRAM slice 并联：

```text
command {valid, write, addr[6:0], data[1023:0]}
            |
            +--> SRAM0 128x256 --> data[255:0]
            +--> SRAM1 128x256 --> data[511:256]
            +--> SRAM2 128x256 --> data[767:512]
            +--> SRAM3 128x256 --> data[1023:768]
```

五个 bank 共 20 个 `fakeram45_128x256`。Liberty 中单宏面积为
`36,582.980 um^2`，累加器宏裸面积合计 `731,659.6 um^2`。该数字不含关系宏、
标准单元、halo、通道和布线。

### 2.2 关系宏

关系前端保持已有的 450-entry 合同：K 使用两个 `256x32`，五个方向各使用两个
`256x16`。全部三种候选共用同样的 12 个关系宏。

## 3. 功能验证结果

验证入口：

```bash
sim_new_arch/run_local5_out32_macro_equivalence.sh
```

结果目录：

```text
results/local5_out32_macro_equivalence_rtl_20260804/
```

验证使用 profile100 的 100 组 ordered workload。权重是可复现合成权重，因此可
验证控制、数值等价、周期和事务，但其翻转活动不能替代部署权重 SAIF。

| 模式 | 周期 | term stall | SRAM 读 | SRAM 写 | generic/宏逐组等价 | 随机空隙+SVA |
|---|---:|---:|---:|---:|---:|---:|
| Direct | 121,501 | 13,055 | 152,894 | 166,080 | PASS | PASS |
| Issue-GASR | 122,360 | 4,544 | 23,662 | 36,848 | PASS | PASS |
| DS-GASR | 119,348 | 10,965 | 23,662 | 36,848 | PASS | PASS |

三种模式均处理：

- 9,427 个 descriptors；
- 53,085 个 product terms；
- 166,080 个 destination updates；
- 100 组 Acc32 读回全部匹配。

结果表明：

1. 双类 SRAM 宏替换没有改变任何一组周期、工作量、事务数或累加结果；
2. DS 相对 Issue 的周期加速仍为 `1.025x`，这是 descriptor 同步位置的有限收益；
3. DS 相对 Direct 的周期加速为 `1.018x`；
4. DS 相对 Direct 的累加器 SRAM 事务减少 `81.03%`；
5. Issue 与 DS 的 SRAM 读写完全相同，二者的周期差异不能归因于访问集合变化。

## 4. 对架构创新判断的影响

### 4.1 已经成立的部分

GASR 的两个 resident context 把源相关的多次 RMW 合并为寄存器内累加和少量
evict/prefetch，`81.03%` 的事务下降已经在真实 1RW 宏接口上成立，而非仅为脚本
估算。DS 将 prepare 与 descriptor commit 对齐，在四个 stage 均无退化，并额外
获得 `2.46%` 的周期缩短。

### 4.2 仍不能宣称的部分

不能把 SRAM 事务下降直接写成：

- 芯片功耗下降 81.03%；
- EDP 提升 5 倍；
- DS 是独立的高冲击架构创新；
- 已达到 DC、PrimeTime 或 PTPX 签核。

DS 需要额外保存五个 bank、两个 context、每个 context 1024 bit 的 resident
vector，即 10,240 bit 宽状态。其时钟、寄存器和布线功耗可能抵消 SRAM 节省，必须
由宏感知物理实现和后续部署 SAIF/DC/PTPX 判定。

## 5. OpenROAD 公平对照

入口：

```bash
openroad_hifp/run_openroad_local5_out32_allmacro.sh all route
```

冻结条件：

- Nangate45 开放库；
- 5 ns 时钟；
- 相同 `1800 x 1400 um` die 和固定 core；
- 相同 32 个 SRAM 宏、halo、channel、引脚 seed；
- 相同 OUT32、T450、关系存储和 Acc32 合同；
- Yosys 保留重复 bank 层次，并关闭耗时异常的可选 `extract_fa` 重写；
- Direct 为 `MODE=0`，Issue 为 `MODE=1, GEOMETRY_SYNC_MODE=0`，DS 为
  `MODE=1, GEOMETRY_SYNC_MODE=1`。

必须从同一流程报告：宏数、宏面积、标准单元面积、总面积、WNS/TNS、关键路径、
拥塞、DRC、max-cap/max-slew/max-fanout、线长、via 和开放库功耗代理。

## 7. 下一轮门槛

1. 三模式必须都识别为 20 个累加器宏和 12 个关系宏；
2. 不允许残留被标准单元展开的主累加器 memory；
3. 三模式必须使用相同 SDC、outline、宏规则和 seed；
4. DS 若没有可验证的功耗或物理优势，应降级为实现细节；
5. 若 DS 的总能耗收益达到可辩护量级，再进入部署权重 SAIF 和 Motion 迁移评估；
6. OpenROAD 只能标为 `[open-pnr][代理]`，不能替代后续 DC/PTPX 主表。
