# DATE 第二十五轮：架构强基线与源商化主张收敛

> **2026-07-31勘误：** 本文旧版将 `(source,lane,gate)` 写成product复用键。
> 该定义错误；`source`不参与product数值。正确值键是
> `(lane,gate,weight_epoch)`，source键只用于destination/schedule商。
> “product下界”相关旧结论已撤回，后续以`docs/213`和`docs/214`为准。

## 1. 本轮结论

本轮重点不是增加 RTL 数量，而是回答 DATE 审稿人最容易追问的两个问题：

1. `FCSR-RX + Source-Quotient + TCFM-5` 是否只是若干常规模块的组合？
2. TCFM-5 是否只比刻意做弱的 single-bank 基线更快？

当前结论是：

> **SQEF 的主张应冻结为“关系布局、计算等价类和物理写端口联合编译”的
> 数据流架构，而不是 Shiftmax、term、五 bank、FIFO 等微结构的并列清单。**

其核心变换为：

```text
输入关系布局：destination/query-major gate edge
计算复用布局：source-major (source,lane,gate) quotient term
物理提交布局：topology-colored destination multicast
```

这三个布局不能独立决定。FCSR-RX 在线完成第一步转置，Source-Quotient
消除等价 edge 的重复 product，TCFM-5 把 quotient term 的 destination set
编译到无冲突同步 1R1W Acc。联合之后，数据不再回到逐 edge 中间表示。

这才是可单列的架构贡献。下面这些只属于实现手段：

- 五 bank；
- 模 5 颜色；
- bitmap iterator；
- replay FIFO；
- close/drain；
- RAW forwarding；
- 双缓冲或 descriptor。

## 2. 三个真实 RTL 强基线

### 2.1 公平合同

TCFM-5、Affine-4 和 Linear-5 当前满足：

- 相同 weight/run/term/close/read 外部语义；
- 相同 `gate × weight` 整数算术；
- 相同 `OUT_DIM=4` product 向量宽度；
- 每个 Acc bank 为同步 1R1W RMW；
- product 每个 term 只计算一次；
- 冲突项必须 exact replay，禁止丢弃；
- close 必须等待 replay 和 Acc writeback drain；
- Yosys 展平后无运行时 `$div/$mod`。

### 2.2 功能验证

| 后端 | Icarus | Verilator/SVA | Yosys check | mask覆盖 | 整数结果 |
|---|---|---|---|---|---|
| TCFM-5 | PASS | PASS | PASS | 定向+边界 | exact |
| Affine-4 | PASS | PASS | PASS | 32种 | exact |
| Linear-5 | PASS | PASS | PASS | 31种非空+边界 | exact |

Affine-4 的 31 个有效 term 完成 80 次 destination update，其中 8 次
south/north 冲突通过下一拍 replay 完成。Linear-5 的 32 个 term 完成 83 次
update；冲突由 pending role mask 逐拍精确退休。

### 2.3 同一开放结构流程

三个后端使用同一个：

```text
hierarchy -> flatten -> proc -> opt
-> memory_collect -> memory_dff -> opt -> check -> stat
```

| 后端 | bank/槽 | W6周期 | 相对TCFM | cells | wire bits | mem | mul | mux |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| TCFM-5 | 5/450 | 1494 | 1.000x | 813 | 15357 | 6 | 4 | 323 |
| Affine-4 | 4/480 | 1579 | 1.057x | 680 | 13989 | 5 | 4 | 248 |
| Linear-5 | 5/450 | 1598 | 1.070x | 1292 | 16499 | 6 | 4 | 551 |

必须克制解释：

1. W6 是确定性架构向量，不是部署 trace；
2. cells/mux 是开放结构代理，不是面积；
3. Affine-4 少一个宏和部分控制逻辑，但总槽位是 480，高于 TCFM-5 的
   450；
4. 因此不能用当前表宣布 TCFM-5 或 Affine-4 的 EDP 胜者；
5. 该表的价值是证明 TCFM-5 面对的是两个真实强基线，而不是 single-bank
   稻草人。

## 3. 第三个强基线：Role-Sharded

Role-Sharded 不依赖坐标着色。它为 self、south、north、west、east 五个角色
分别保存 partial Acc，因此每个 term 的五个 role 天然写入五个独立 bank。

边界压缩模型：

| 架构 | Acc向量槽 | Acc bit | 最终读向量 | 128-bit向量加法 |
|---|---:|---:|---:|---:|
| TCFM-5 | 450 | 57600 | 450 | 0 |
| Role-Sharded | 2130 | 272640 | 2130 | 1680 |

Role-Sharded 与 TCFM-5 都可以做到一 term 一 delivery 拍，但代价来源不同：

```text
Role-Sharded:
  复制 destination partial state
  -> 消除写冲突
  -> readback 时归约五个角色

TCFM-5:
  destination state 只保留一份
  -> 编译坐标颜色
  -> 写入时无冲突
  -> 无最终归约
```

模型显示 Role-Sharded 的槽位和读向量均为 4.733 倍。完整同接口 RTL 正在补齐；
在其完成前，这一项只属于结构下界模型。

## 4. 架构创新的准确表述

### C1：Bounded-Lifetime Relation Transpose

Local5 attention 的 gate 按 destination/query 顺序产生，而 gated-K projection
需要按 source 聚合。通用做法需要完整关系平面、CSR 建表或运行时引用计数。
FCSR-RX 利用固定五点图的闭式最后消费者，在有限行状态中在线退休 source：

```text
destination-major gate stream
  -> bounded frontier state
  -> source-complete descriptor
```

创新边界是 **有界生命周期在线关系转置**，不是普通 line buffer。

### C2：Source-Quotient Exact Execution

定义边等价关系：

```text
e1 ~ e2
iff source(e1)=source(e2)
and lane(e1)=lane(e2)
and gate(e1)=gate(e2)
```

硬件不再对每条 edge 计算 `gate × W`，而是对每个等价类计算一次并向
destination set 多播。该变换保持 hardware-order 整数结果，不需要
top-k、预测器、相似度阈值或误差恢复。

创新边界是 **把事件关系按计算不变量取商并原生执行 quotient term**，不是
字典压缩的重新命名。

### C3：Topology-Compiled Exact Commit

Source-Quotient 会把多个 destination 的写回集中到同一拍。TCFM-5 不复制
partial state，也不运行时 replay，而是将 Local5 冲突图联合编译进 Acc 地址：

```text
bank(x,y) = (x + 2y) mod 5
```

内点五角色构成 K5 冲突团。在“每 bank 每拍一次更新、无 replay、无复制归约”
合同下，五个 bank 是下界，TCFM-5 达到该下界。

创新边界是 **quotient multicast 与物理写端口的联合编译**，不是图着色算法
本身。

## 5. 与既有架构的实质差分

| 工作 | 可借鉴机制 | SQEF的本土化差异 | 不能宣称 |
|---|---|---|---|
| Prosperity | exact product reuse | reuse key 是 attention 输出的 `(source,lane,gate)` 精确等价类，并与关系转置、Acc提交贯通 | 首次发现所有SNN复用 |
| Phi | pattern/residual 分层 | 固定五点 incidence 由拓扑编译，动态部分是 exact gate/edge residual | 发明层次稀疏 |
| Bishop | TTB、metadata-first | Motion 用 TTB/STT；Local5 用 frontier-complete source descriptor，不做 ECP | 发明TTB或异构稀疏核 |
| Sanger | score-stationary 数据流 | 本工作让 source-quotient product 在一个 destination set 生命周期内驻留并多播 | 发明stationary dataflow |
| stencil banking | 仿射着色 | 颜色与 quotient destination set、同步Acc端口联合选择 | 发明模着色 |
| sparse CSR/CSC | 关系转置 | 不物化完整CSR/CSC，利用五点图闭式 frontier 在线完成 | 通用稀疏矩阵转置 |

最重要的差分不是“我们也使用复用、descriptor 或 banking”，而是：

> 既有工作通常在已经给定的稀疏矩阵布局上优化执行；SQEF 将 attention
> 产生顺序、projection 计算等价类和 Acc 物理端口一起改变，并保持全链 exact。

## 6. 为什么这比“Gate-Code Superscalar”更稳

“Gate-Code Superscalar”“WAL 式提交”“SSA 不变量”等说法可以辅助解释，
但不应成为论文主张：

- superscalar 容易被认为只是三个 bank-local executor；
- WAL 只是原子提交类比；
- SSA 只是 term 内 product 不变；
- gate-code 低基数是 workload 性质，不自动构成架构。

相比之下，关系转置、等价类取商和物理端口联合编译都有：

1. 明确的输入输出合同；
2. 可证明的整数等价；
3. 可量化的状态、product、replay、槽位和端口代价；
4. 可实现的完整 RTL；
5. 可与 CSR、逐 edge、Linear-5、Affine-4、Role-Sharded 做同边界消融。

因此论文标题级叙事保留 SQEF，辅助类比降到正文说明或讨论。

## 7. Motion 与 Local5 的双线边界

两条线统一：

```text
source-quotient term = {
  source_id,
  lane_id,
  gate_code,
  destination_set,
  transaction_last
}
```

但前后端不同：

| 项 | Motion | Local5 |
|---|---|---|
| 关系 | 动态全窗口 | 固定五点图 |
| 元数据 | TTB/STT、SCS class | frontier-complete descriptor |
| source聚合 | 动态目录/term | FCSR-RX |
| destination set | bitmap/list | 五角色mask |
| 写回 | DCTF/replay | TCFM-5或Affine-4 |
| exact性 | SCS/term合同 | quotient/着色合同 |

Motion 可复用 C2 的 source-quotient term IR，但不能复用 C1 的固定 frontier
或 C3 的 K5 五色保证。Local5 架构创新更强，Motion 当前算法和 fullres 结果更
成熟；在 Local5 valid825 与 post-G0 trace 完成前继续双线，不宣布唯一主线。

## 9. 当前 DATE 判断

本轮关闭了“强基线只是模型”的一部分缺口：

- Affine-4：完整 RTL、SVA、整数 exact；
- Linear-5：完整 RTL、SVA、整数 exact；
- 统一开放结构脚本：完成；
- Role-Sharded：模型完成，RTL进行中；
- post-G0：等待训练队列；
- 目标工艺 PPA：未完成。

当前可辩护的是：

> **SQEF 已从微结构拼装收敛为一条明确的数据流架构：有限状态在线转置
> attention 关系，按 source/gate 计算不变量取商，再把 quotient multicast
> 联合编译到同步 Acc 端口。**

但在 post-G0 trace 与同宏 PPA 到达前，仍不能声称达到 DATE accept。当前
文档应被视为“架构主张已清晰、实验证据正在补齐”，而不是投稿完成态。
