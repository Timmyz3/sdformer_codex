# Local5 有界生命周期在线关系转置与 FCSR 架构

## 1. 本轮裁决

Local5 的新架构候选冻结为：

> **FCSR（Frontier-Complete Source Retirement，前沿完整源退休）**：
> 利用固定五点 stencil 的消费者集合可静态求解，在 source 的最后一个
> destination 消费者完成时，将 destination-major gate 在线转置为
> source-major relation descriptor，并在 K 离开三行缓冲前启动投影。

它取代此前 SOSW/DiSEP 的弱表述：

- 不再声称交换 query/source 循环会减少 Q/K 总读取；
- 不把五方向 bank、双缓冲或 3-bank 当作架构创新；
- 不依赖 Local5 gate-code 重复度才成立；
- 不需要完整窗口 gate plane、实体 transpose 或动态 reference count。

FCSR 的核心架构抽象是：

> **Bounded-Lifetime Online Relation Transpose**
> （有界生命周期在线关系转置）。

它把 destination-major attention 与 source-major projection 之间的图关系转置，
从 `O(HW)` 全窗口状态变为 `O(W)` 行状态，并把两个串行 phase 变成受 FIFO
约束的生产者/消费者流水。

---

## 2. 为什么这不是普通 line buffer

卷积 line buffer 解决的是：

```text
同一个输入像素被多个局部卷积窗口重复读取
```

FCSR 解决的是：

```text
attention输出按destination产生edge gate
projection却按source复用K与product
```

两者的数据拥有者不同：

```text
Destination-major normalize:
  d -> {Gself[d], Gn[d], Gs[d], Ge[d], Gw[d]}

Source-major projection:
  s -> {(d, Grole[d]) | d consumes K[s]}
```

因此，普通三行 Q/K buffer 只提供 stencil operand，不会自动完成：

1. 五方向 gate 的逆方向寻址；
2. destination 到 source 的在线关系转置；
3. source 消费者完整性判断；
4. source K 的安全退休；
5. score 与 projection 的跨 phase 重叠。

FCSR 的 gate ring 和 frontier scheduler 是关系流硬件，不是 Q/K line buffer
的改名。

## 3. 拓扑定理与硬件含义

### 3.1 五点 stencil 消费者集合

对 source `s=(y,x)`，会消费 `K[s]` 的 destination 是：

```text
C(s) = {(y,x), (y-1,x), (y+1,x), (y,x-1), (y,x+1)}
```

越界 destination 不属于 `C(s)`，也不能作为 gate=0 注入 Shiftmax
denominator。

在逐行 raster 顺序中，source 的静态退休时刻为：

```text
R(s) = max raster_index(d), d in C(s)
```

内部 source 的最后消费者恒为 `(y+1,x)`；底边 source 由同行 east 或 self
消费者收口。该规则只依赖坐标和边界，不依赖 Q/K/gate 数值。

### 3.2 有界生命周期

五点 stencil 的消费者只跨 `y-1/y/y+1` 三行。因此：

- 最早 gate 到最后消费者的生命周期不超过三行；
- gate relation 只需三行环形存储；
- source K 在最后消费者完成时仍位于三行 Q/K buffer；
- 在 T0/T1 平面串行前提下，9×9 与 15×15 的最大几何退休突发均为 3；
- 不需要每 source 的动态引用计数器。

对半径为 `r` 的有界 stencil，该结构可推广为：

```text
relation state = O((2r+1) * W * directions)
```

而完整 edge plane 为：

```text
relation state = O(H * W * directions)
```

论文不能将该渐进式结论写成面积结果；它是存储生命周期上界。

## 4. FCSR 数据流

```text
paired-time Q/K row stream
        |
        v
Direct-5 stencil taps (1 destination/cycle强基线也使用)
        |
        v
5 x alpha-XNOR score -> exact Shiftmax5
        |
        +--> direction gate ring
        |    {time,row_mod3,x,role}
        |
        +--> static frontier event
                 |
                 v
        atomic source snapshot
        {source_id, K[source], 5 incoming gates, valid mask}
                 |
                 v
        bounded source descriptor FIFO
                 |
                 v
        MFEP source term builder
                 |
                 v
        gate/product-stationary projection backend
                 |
                 v
        destination-indexed integer Acc
```

### 4.1 在线关系转置

destination `d` 产生的 `G[role][d]` 写入方向 gate ring。source `s` 退休时按
逆方向读取：

| source 在 destination 中的角色 | 读取 |
|---|---|
| self | `G[self][s]` |
| north | `G[north][south(s)]` |
| south | `G[south][north(s)]` |
| west | `G[west][east(s)]` |
| east | `G[east][west(s)]` |

这与 DiSEP 的地址双射相同，但 DiSEP 等完整窗口后再读；FCSR 在 relation
生命周期结束的同一 frontier 上读取、转置和退休。

### 4.2 原子退休合同

一个 source descriptor 只有在以下条件同时成立时可见：

1. `C(s)` 内所有合法 destination 已完成 hardware-order Shiftmax；
2. 五个 gate 已写入对应 ring entry；
3. source K 尚未被行旋转覆盖；
4. T0/T1 两个无跨时刻邻接的平面串行执行并复用行状态；
5. 底边 2–3 source burst 由单 snapshot 通路按一项/拍序列化；
6. descriptor FIFO 至少有一个槽；
7. invalid direction 由真实 valid mask 删除，而不是写普通 gate=0。

FIFO 满或 retirement bundle 尚未排空时反压 destination producer。当前行只有
在该行所有应退休 source 的 K 已被 descriptor 捕获后才能旋转。当前
destination 新产生的 gate 与 self/north/west 等 K 必须提供 write-through
bypass，避免同拍读到 gate ring 旧值。

### 4.3 TTB/STT 的本土化

Bishop 的 TTB 可在 FCSR 中改成 **frontier-complete STT**：

- 同一 `(y,x)` 的两个时间平面共享 coordinate、boundary 和 retire metadata；
- Q/K 和 gate 数值仍按两个时间平面独立保存；
- descriptor 仅压缩控制元数据，不跨时间合并 Shiftmax denominator；
- 未证明周期/能耗收益前，STT 只是接口格式，不列独立贡献。

这比直接复制 Bishop 的 dense/sparse 双核更符合 Local5：这里的确定性来自
stencil frontier，而不是 bundle density 分类。

## 5. 与现有工作的借鉴边界

| 工作/范式 | 借鉴 | FCSR 本土化 | 不声称 |
|---|---|---|---|
| Bishop TTB | token-time 打包、metadata-first | frontier-complete STT，时空元数据与数值分离 | ECP、异构双核原创 |
| Prosperity | exact relation/reuse、先识别关系再执行 | relation 由 stencil 拓扑静态给出，不用 TCAM 搜索 | product-sparsity matcher 原创 |
| Phi | pattern/residual 分层表示 | 固定 direction/valid pattern 作为静态关系头 | learned pattern/codebook 原创 |
| FireFly-T | 多 lane 二值事件执行 | MFEP 后端处理 source gate/lane term | sparse decoder 原创 |
| Sanger/score-stationary | 关系元数据驻留 | gate relation 在三行 ring 内驻留至 source frontier | score-stationary 原创 |
| streaming stencil | 三行 operand reuse | 对 edge relation 做在线 graph transpose 与原子退休 | line buffer 原创 |
| sparse outer-product | source 驱动的 destination scatter | source K/product 驻留，五方向 destination 集合有界 | 通用 SpMSpM/merger 原创 |

复旦 ISSCC 蝶形网络当前不进入 FCSR 主线。五方向固定 fan-in 与最大 burst=3
没有证明需要通用 butterfly compactor；强行加入只会增加路由和控制面积。若
post-G0 trace 证明 MFEP lane event 同拍突发显著高于小型 prefix/LIST 网络的
能力，再作为等输入带宽 PPA 对照，不预先包装为贡献。

## 6. 公平基线

| 编号 | 前端 | gate/K 生命周期 | projection启动 |
|---|---|---|---|
| B0 | 当前单口五次随机读 | 当前 RTL 小窗口形状 | destination串行 |
| B1 | Direct-5，1 destination/cycle | 完整 K plane + 完整 gate plane | 窗口结束 |
| B2 | Direct-5 + stripe double buffer | stripe K/gate | 上一 stripe 完成后 |
| B3 | Direct-5 + DiSEP | 完整方向 gate plane，无实体copy | 窗口结束 |
| A0 | Direct-5 + FCSR | 三行 Q/K + 三行 gate ring + 有界FIFO | source frontier |

主结果必须比较 A0 与 B1/B2/B3 中最优者。B0 只说明当前原型瓶颈，不能作为
架构收益的唯一基线。

统一约束：

- 相同 5-score lane 和 hardware-order Shiftmax5；
- 相同 projection term/cycle；
- 相同 Q/K SRAM 端口和 latency；
- 相同 Acc 端口、反压和整数宽度；
- 相同 T450 边界、invalid mask；
- line buffer、gate ring、FIFO 和完整 plane 均计 macro；
- score 输入 stall 必须计入端到端 window latency。

## 7. 当前模型结果

脚本：

- `scripts/model_local5_frontier_retirement.py`
- `tests/test_local5_frontier_retirement.py`
- `results/local5_frontier_retirement_model_20260730/report.{md,json}`

### 7.1 解析存储上界

口径包含三行 Q/K buffer；B1 另含完整 K plane 和五方向 gate plane；A0 改为
三行 gate ring 与 8-entry source descriptor FIFO。共享权重与 Acc 不计。

| 窗口 | B1 peak state | FCSR peak state | 降低 |
|---:|---:|---:|---:|
| 2×9×9 | 7,965 bit | 3,663 bit | 54.0% |
| 2×15×15 | 20,205 bit | 5,633 bit | 72.1% |

两个时间平面无跨时刻邻接，因此 B1 与 FCSR 都按逐平面复用状态计算。此前把
B1 按 `2HW`、FCSR 按 `HW` 计算的 74.2%/85.0% 已撤销。修正结果仍只是
`[解析/模型]`，不是 SRAM macro 面积；完整 plane 可能映射 SRAM，而小 ring/FIFO
可能映射寄存器，bit 比例不能直接转成面积比例。

### 7.2 旧 W9 profile 的抽象周期敏感性

旧 profile 只有全窗口 MFEP 目录 term 数，没有每 source 的有序 relation
work。模型将该总量人工分配到 source，令 score 为 1 destination/cycle、
projection 为 1 抽象 term/cycle，FIFO=8，ready=100%。

| stage | term均值 | 两阶段周期 | FCSR均匀周期 | 加速 |
|---:|---:|---:|---:|---:|
| S0 | 34.84 | 196.84 | 165.30 | 1.191× |
| S1 | 3.55 | 165.55 | 162.04 | 1.022× |
| S2 | 11.69 | 173.69 | 162.29 | 1.070× |
| S3 | 31.23 | 193.23 | 164.16 | 1.177× |

最坏“全部 term 压在退休序列尾部”时，各 stage 都是 1.000×。因此：

- FCSR 不保证吞吐提升；
- 它保证的是 relation/K 生命周期有界；
- 真实吞吐取决于 per-source ordered term 到达分布；
- 全窗口 MFEP term 与 source-local term 不等价，表中数字不是加速证据；
- pre-G0 旧 crop 不能进入 DATE 主表。

为此已将 ordered trace 升级为 `et3_ordered_term_trace_v2`，新增：

- `source_term_count`；
- `source_gate_count`；
- `source_k_popcount`；
- `source_retire_destination`。

真实回放入口为 `scripts/replay_local5_frontier_trace.py`。它以
`(source,final-gate,lane)` term 为服务量，不再由全窗口 MFEP term 反推。

## 8. 为什么它比 DCTF-2C 更像架构创新

DCTF-2C 主要在既定 term 流内部做：

- 双 context；
- 窄命令 multicast；
- bank-local execution；
- 有序退休。

这些单独看都是常见微结构。

FCSR 改变了：

1. **数据拥有者**：destination gate 转为 source relation；
2. **存储复杂度**：全窗口 relation/K plane 转为有界行状态；
3. **阶段边界**：score 完整窗口 barrier 转为 per-source frontier；
4. **调度方式**：动态 relation 完整性跟踪转为拓扑静态退休；
5. **数据搬运**：store/reload/transpose 转为 ring 内在线转置；
6. **执行重叠**：normalize 与 projection 从串行 phase 转为弹性流水。

因此 DCTF/MFEP 应作为 FCSR 的 projection backend，而不是论文标题级贡献。

## 9. RTL 分解建议

第一阶段只实现可证伪最小链：

1. `local5_direct5_tap_frontend`
   - 三行 Q/K；
   - 每拍一个 destination 的 self/N/S/E/W；
   - B1 与 A0 共用。
2. `local5_direction_gate_ring`
   - `3 x W x 5 x 9b`；
   - 同拍五方向写；
   - source frontier 五方向读；
   - 边界 mask。
3. `local5_frontier_retire_scheduler`
   - 纯坐标/边界规则；
   - 最大三 source 原子退休；
   - 行旋转许可。
4. `local5_source_snapshot_fifo`
   - 起点 depth=8；
   - `{source,K,gate[5],valid[5],time}`；
   - 随机反压和 occupancy counters。
5. `local5_fcsr_reference_top`
   - 先接简单逐 edge source projection；
   - bit-exact 后再接 MFEP/DCTF。

第一版不加入：

- butterfly；
- TARE/Prosperity residual；
- AENR/模式预测；
- PPDI；
- 多 context；
- 近似 gate 删除。

原因是先隔离 FCSR 自身的存储和重叠收益。

## 10. 验证与晋级门槛

### 10.1 必补真实统计

Local5 fullres hardware-order follower 新增：

- 每 source 的 `retire_destination`；
- 每 source 的 MFEP term 数；
- 每 cycle 退休 source 数与 term arrival；
- FIFO depth 2/3/4/8/16 的 overflow、stall、occupancy p95/p99/max；
- score 与 projection overlap；
- gate ring read/write；
- K plane write/read 被取消的 bit traffic；
- stage/head/window 的 mean/p95/p99；
- valid boundary 与 bottom drain。

### 10.2 RTL 正确性

- T=2×9×9、2×15×15；
- 四边四角和全 invalid 组合；
- 每 source 恰好退休一次；
- 每合法 edge 恰好投影一次；
- gate/K/destination/multiplicity 守恒；
- 随机 producer/consumer backpressure；
- FIFO 满时不覆盖 K；
- 行旋转与 bottom drain；
- 与 destination-major 整数 Acc bit-exact；
- SVA：no early retire、no late overwrite、no duplicate/missing edge。

### 10.3 DATE 晋级

FCSR 成为主贡献必须同时满足：

- post-G0 fullres 状态减少至少 50%；
- A0 相对 B1/B2/B3 最优者 mean latency 或 EDP 至少改善 15%；
- p99 无 descriptor overflow，或 fallback 开销纳入；
- 同约束 DC/STA/SAIF 为正；
- 多 sample、多 stage 结论成立；
- 收益不来自额外 Q/K/gate SRAM 端口。

若只满足状态减少、不满足速度，则可写成 memory-lifetime 贡献，但必须用 SRAM
macro 面积/能耗证明系统 EDP，而不能继续用周期代理。

## 11. 双线主次暂定

### Motion

保留：

- TTB/STT temporal-pair 数据布局；
- Motion-XOR + exact SCS-Shiftmax；
- term 流与 bank-local projection；
- ACRT 仅作低状态/PPA 候选。

问题：

- ACRT 已输给 all-class replay 强基线；
- DCTF-2C 新颖性仍偏工程；
- 需要 PPA 而不是继续增加控制机制。

### Local5

新增：

- 有界生命周期在线关系转置；
- 静态消费者 frontier；
- source K 原子退休；
- score/projection 弹性重叠。

当前判断：

> 从纯硬件架构新颖性看，FCSR 比 Motion 的 ACRT/DCTF 更有潜力；
> 从算法结果与 exact 成熟度看，Motion 仍领先。Local5 fullres valid825、
> post-G0 profile 和 FCSR 强基线 PPA 未完成前，双线继续，不提前宣布唯一主线。
