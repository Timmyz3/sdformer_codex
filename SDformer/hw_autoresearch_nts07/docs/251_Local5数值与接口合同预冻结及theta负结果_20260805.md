# Local5 数值与接口合同预冻结及 theta 负结果

## 本轮结论

Local5 当前可以冻结的是 score、真实 invalid mask、hardware-order Shiftmax5 和 relation transpose 的接口定义；不能冻结的是 value/projection 数值合同和 12-block 顶层调度。

CPU-only 审计首次定量证明，旧 checkpoint 的 theta 虽极接近 1，仍改变 80 个 dyadic INT8 权重码。正式 Local5 projection 必须使用 `quantize(theta_block × W)`；现有投影 RTL 算术结构无需改变，但权重生成、manifest、向量金参考和 checkpoint 绑定需要更新。

现有 `qfit_local5_tile` 回归已重新执行并通过：Icarus 功能仿真、Verilator lint/build、断言执行均完成，最终为 `PASS qfit_local5_tile descriptors=24`。该结果的证据等级为 `[rtl]`，但覆盖边界仅到 `score→Shiftmax5→relation transpose`。日志仍有地址算术宽度扩展/截断和未驱动 stripe 状态告警，不能据此宣称综合洁净，更不能把它扩大为 attention-to-projection 端到端闭环。

## 为什么当前不能直接改生产脚本

新 Local5 fullres rank-1、deploy YAML 和 post-G0 profile 仍由现有 watcher 生成。此时修改 `profile_local5_hardware_features.py` 会改变正在绑定的 source SHA，并可能污染正在生成的 acceptance。因此本轮只新增旁路审计脚本，不修改生产 producer。

待新 rank-1 释放后，下一次唯一代码修改应是：

1. projection contract 提取每 block K theta；
2. 先折叠 theta 再量化 W；
3. projection vector/golden 使用折叠后权重；
4. acceptance 验证 theta 数组、折叠脚本和 payload SHA；
5. 用同一 checkpoint 重跑 score 与 projection RTL。

## 双线影响

该缺口只影响 Local5 的 threshold-valued K projection，不推翻 Local5 的五候选 attention、relation transpose 或 TCFM5 架构。

Motion 继续独立推进。Motion 的 T450 profile 当前仍等待 Local5 producer 释放 GPU/acceptance；现有 HIFP RTL 回归不受 theta 折叠脚本影响。Motion 新机制仍按真实 T450 trace 的收益上界筛选，不因 Local5 暂时预冻结而停止。

## 严格 DATE 评审

### 评分与裁决

- 评分：`2/5`。
- 推荐：`Reject（大修后重审）`。
- 创新性增量：`+0.0`；theta 折叠和方向审计属于部署正确性，不是新架构。
- 完整度增量：约 `+0.3/5` 的证据质量提升，但尚未跨过端到端门槛。

### 评审确认的问题

1. `80 / 2,156,544` 个 INT8 权重码差异足以阻断端到端 bit-exact；`0 / 4416` 个 scale exponent 差异不能抵消权重码差异。
2. 候选方向与 source-major consumer 反向位移的定义合理，但尚缺 T450、双 plane、四边界、五 role 的全量 edge multiset miter。
3. 24 个 descriptor 且无 relation stall 的 tile PASS 只能证明局部前半链；width、未驱动和未使用告警需要分类、修复或明确 waiver。
4. 下一步必须先闭合 `quantize(theta_block × W)` 的部署合同，再做单顶层 term/projection，最后扩展 12-block scheduler。先集成 scheduler 会把已知数值错误扩散到更大范围。

### Motion 双线裁决

Motion 不能停止，但本轮不与 Local5 同时扩第二套大型顶层。允许并行推进 T450 多样本 ordered profile、p50/p95/p99、stall 分账、新机制收益上界和现有 HIFP 回归；候选机制只有通过真实 trace 与最小 RTL 因果验证后才能晋级为已实现贡献。
