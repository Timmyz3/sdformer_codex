## 3. fail-closed修复

1. `report_activity_vcd.py`从VCD头解析真实module scope；手填`strip_path`不存在时失败。
2. 活动合同分别记录`busy_cycles`与`measured_cycles`，并要求日志中的
   `measurement_scope`与调用参数一致。
3. 解析器从VCD直接读取timescale和`dump_active`，要求活动持续时间等于
   `measured_cycles * clock_period`；论文功耗只接受一个连续活动区间。日志含
   `ERROR/FATAL`、PASS不唯一、VCD无翻转或trace为空均失败。
4. `run_dc.tcl`在没有SAIF时不调用`report_power`，只写
   `power_scope.rpt: NO_SAIF_POWER_NOT_RUN`；遗留默认翻转率功耗文件会使工件审计失败。
5. DC的`PPA_ADMISSION=1`和所有PTPX运行都拒绝`identity_smoke` SAIF。
6. VCD转SAIF的manifest记录实际activity-contract、源VCD和trace路径；生成端和
   审计端都会重新计算三组SHA，并逐项比较关键合同字段，纯格式哈希不能通过。
7. PTPX覆盖率解析只接受明确的`SAIF annotation coverage`行；clock-gating或
   analysis coverage不能误触发准入。目标PT版本若输出格式不同会失败，需显式适配。
8. `ptpx_unannotated.rpt`必须能解析出明确的未注释对象总数且等于0；格式未知或
   SRAM/RF/目录对象未注释都会失败，不能以默认翻转率补齐。
9. SPEF仍必须配同次P&R网表；PVT、宏库、Formality和PT工件身份保持原P0约束。

当前证据handoff审计为 `79/79 PASS`，九项本机 admission 负例/正例测试通过；该审计
同时重算三份正式activity contract的VCD/trace身份、Motion配对合同和`docs/359` SHA。
本机仍缺 `dc_shell`、`fm_shell`、`pt_shell` 和 `vcd2saif`，所以没有SAIF、DC面积、
WNS/TNS或PTPX功耗数字。

## 4. 独立DATE口径

本轮提高的是验证与实验完整度，不改变存储对象或执行边界，架构创新分不应上升。
保守评分暂定：创新 `3.1/5`、工作量 `4.9/5`、验证 `4.6/5`、实验完整度
`3.0/5`、工程 `4.8/5`，综合仍为 Borderline。

验证分未到满分的原因：Motion仍是单checkpoint/单window的138行，Local5仍是
`OUT_DIM=2` population；尚无门级回灌SAIF、Formality、目标宏或多角PT。

实验完整度仍缺：

1. 三份VCD在有Synopsys工具的服务器转换为SAIF并核对注释覆盖率；
2. 三个冻结顶层同库同SDC的DC/Formality/setup/hold/PTPX；
3. 目标SRAM/RF wrapper与宏实例准入；
4. Motion跨样本真实RTL，Local5多window/更高OUT_DIM；
5. 12-block/full-encoder周期、带宽与能量Amdahl。

机制继续冻结。下一轮首先完成Synopsys服务器证据或多样本/系统账本，不再用小型
编码、额外cache或新拓扑名称替代上述缺口。
