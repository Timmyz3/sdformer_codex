## 1. Motion / Local5：创新分已经封顶

独立收口还在 `docs/432`、`docs/433`、`docs/389`、`docs/407`。本机又核了一遍，没有翻案。

| 线 | 可守的一条 | 创新 | 完整度还能动 | 创新 4.0 |
|---|---|---:|---|---|
| Motion / H67 | TESC+RQTB，公平锚 `112589/94891=1.1865×` | **3.2** | 能 | **不能靠再拆 RTL** |
| Local5 / ep44 | QS → FCSR → source-owned unique-gate → TCFM5 | **3.1** | 能 | **不能** |

Local5 再筛过 QAT、系数融合、dyadic、wavefront、Memo、2-wide、第三 stencil：没有新的 exact 物化对象。`docs/389` 问的“rolling inverse-stencil 干掉 T450 relation”就是已经闭合的 `docs/208` FCSR-RX，不许再造一轮。

Motion 还开着的唯一创新门（389）是：

> 把 RQTB quotient 保持到**新的存储/调度边界**，并且保住 destination identity。

class-wise K folding、公共 K 多播、FGP late-gate 都已否决。现网 directory 已经是 C7：class hist + 450 带分名单 + `exp * multiplicity`。只删乘法、只换模块名，到不了 4.0。

完整度缺口仍是真的，但不加创新分：full-encoder Amdahl（现有模型 Motion `1.1997×`、Local5 tile `1.1165×`，不是整网）、多样本真实 INT8 全通道、12-block 同窗、目标库 DC/SAIF。这些在另一台新思机器或等 H82 让卡后再补。本机不伪造 encoder 份额。

**所以：优先 Motion/Local5，不等于还能把这两条从 3.2/3.1 画到 4.0。** 优先的是守住这两条 DATE 身份、补完整度，而不是再贴 Prosperity。

## 3. 算法新线怎么接回 Motion

H86 那句话，正好是 Motion 389 还开着的门：

| Motion 现网 | H86 / 本机 TLM |
|---|---|
| 450 带分 active + 再算 token exp | 窗级 Class File |
| `class_sum_term *= multiplicity`（C7） | 同一份 directory；H82 把分母改成一类一票 |
| 每行重建 450 名单 | 邻行 **member insert/delete** |
| 投影前已经回到 dest-owned `(K_i, gate_i)` | expand 直接 `K_i * gate_c`，dest 身份不丢 |

参考：`scripts/h86_window_member_delta_reference.py`。单测：patch 可逆、C7 与一类一票数值不同、合同禁止 Motion-XOR / Local5 焊死。合成邻窗几乎整表在换人（446 insert / 446 delete / 4 stay），所以 **ST_PATCH 现在还不能卖 41%**。要等 H82/H86 rank-1 上的 member Jaccard，不能用 H85 的类名 `reuse_set` 充数。

这不是把 Motion 改名为 H82。活身份仍是 H67 RQTB。H82/H86 是下一份算子 SHA 上的 **directory 后继**。没有 rank-1 之前不写生产 RTL。

## 4. 本机继续怎么排

1. **Motion / Local5（主身份）**：守 3.2 / 3.1。完整度只做不改 359 的账（Amdahl 边界已经写明不是 full encoder）。不重开 C1–C7，不重写 FCSR。
