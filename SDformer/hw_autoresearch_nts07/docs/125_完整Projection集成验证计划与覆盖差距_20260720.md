# Builder→typed-slot→projection 完整集成验证计划与覆盖差距

> 日期：2026-07-20  
> 验证对象：`gatestack_builder_projection_single_context_top` 及其 C0/C1 Builder、typed-slot 服务、single-context projection 执行链  
> 文档性质：独立验证计划与签核差距，不是 RTL 完成声明  
> 本轮边界：只制定验证计划和审计现有证据，不修改 RTL、TB 或运行脚本

## 1. 独立结论

当前完整集成已经证明两件重要事情：

1. 小规模正常路径下，C0/C1 都能完成 `Builder→typed-slot→inspect/replay→projection→release→group_done` 闭环，输出签名一致，且 `count_payload_copy_words=0`。
2. 真实 S0 的三个 head、162 token、96 维投影已经在 C0/C1 下各完成 15,552 个 `int32` 元素逐项比较，均为零差异；C0/C1 校验和同为 `-693483`。

但从验证签核角度，当前仍是“正常路径定向测试通过”，不是“完整 projection 集成已签核”。最关键的缺口是：

- 集成顶层没有专属动态 SVA bind 与 assertion 命中报告；
- 没有 reset-in-flight 矩阵；
- execution 子系统虽有 abort 叶级和旧顶层证据，但 Builder 与外部 typed-slot 接入后的集成 abort、slot 清理和下一批恢复尚未证明；
- 重复或非法 `head_id` 的恢复合同不闭合；从当前 RTL 静态路径看，它会置位 `batch_protocol_error_q`，同时阻断 `group_ready`，却没有已证明的本地有界清理路径，存在“只能依赖系统复位恢复”的风险；
- 没有完整的接口背压交叉、随机 seed 回归和覆盖率数据；
- 真实 S1/S2/S3 尚未进入同一 Builder→typed-slot→projection 顶层；
- 没有集成顶层的代码覆盖、功能覆盖和形式辅助报告。

因此，当前验证成熟度判定为：**正常功能 P0 原型通过，完整集成 sign-off 未通过**。在本文第 12 节列出的 P0 全部关闭前，论文只能写“所覆盖配置的 RTL 仿真零差异”，不能写“完整加速器已充分验证”。

## 2. 验证范围与不在范围

### 2.1 在范围

- C0 单 workspace Builder 与 C1 双 workspace Builder；
- 162×32 的最终 gate/K token 捕获；
- typed payload 格式选择、序列化、原子提交与 typed-slot 生命周期；
- slot inspect、metadata、replay、release；
- IPD32W、FADC24、RAW41 及 adaptive CSR 路由；
- descriptor residency、weight 请求/响应、bias 提交、banked accumulator；
- 多 head、多 output tile 的 projection；
- group admission、完成、异常终止、复位恢复和计数器；
- H67 真实 S0/S1/S2/S3 数据；
- ready/valid 协议、功能覆盖、代码覆盖、断言覆盖与必要的形式辅助。

### 2.2 不在范围

- voxel 生成、卷积、ATLIF 和完整 encoder 顶层；
- 模拟 SRAM 宏的电气时序、DFT、CDC/RDC、门级 SDF；
- 目标工艺 PPA 与 SAIF 功耗。

这些不在本 V-plan 的功能签核范围内，但不代表 DATE 论文可省略系统级性能与 PPA 证据。

## 3. DUT 协议边界与验证平台

### 3.1 建议验证平台层次

```text
完整集成虚拟序列器
  ├─ Builder输入主动代理：head_begin + token流
  ├─ Group控制主动代理：group请求 + group_done背压
  ├─ Weight存储主动代理：weight_req监视 + weight_rsp驱动
  ├─ Bias主动代理：bias_req监视 + bias值/ready驱动
  ├─ Final输出主动代理：final监视 + 各bank ready驱动
  ├─ 状态被动监视器：slot、错误、完成、全部计数器
  ├─ 分层金参考：typed格式模型 + projection整数模型
  ├─ 生命周期记分板：head/slot/tile/token事务
  └─ 独立覆盖采集器：功能覆盖、assertion命中、代码覆盖
```

建议保持 UVM 1.2 的组件边界；在当前开源环境中，可先用 SystemVerilog 自检 TB 实现同样的 agent/monitor/scoreboard 分工，再由 Verilator 覆盖数据库和 SVA 补齐签核证据。不能继续把所有驱动、金参考、覆盖和结束判断堆在单一 `initial` 块中作为最终验证平台。

### 3.2 接口到代理映射

| 接口 | 方向 | 代理类型 | 监视重点 |
|---|---|---|---|
| `head_begin_*`、`token_*` | TB→DUT | 主动 | head 身份、token 连续性、`token_last`、输入背压稳定 |
| `group_*`、`group_done_*` | 双向 | 主动 | admission 前置条件、单 outstanding、完成稳定、下一批开放 |
| `weight_req_*`、`weight_rsp_*` | 双向 | 主动 | tag/channel/tile 身份、响应乱序策略、长背压 |
| `bias_req_*`、`bias_req_values` | 双向 | 主动 | token 范围、每 tile 每 token 恰好一次、背压稳定 |
| `final_*` | DUT→TB | 主动 ready、被动数据 | 每 bank 稳定性、bank 映射、tag/token、逐元素数值 |
| `builder_done_*` | DUT→TB | 被动 | 每 head 一次、格式/字数/错误、C1 完成顺序 |
| `slot_valid_flat`、`slot_reset_pulse` | DUT→TB | 被动 | 提交、回放、释放、异常清空、无 stale slot |
| 计数器与 `protocol_error` | DUT→TB | 被动 | 守恒关系、错误原因、复位语义、溢出 |

### 3.3 金参考必须分两层

1. **Builder/typed-slot 参考层**：由 162 个 `{gate_code,K_bits}` 生成候选 IPD/FADC/RAW payload、格式、字数、term 数、destination 数及 slot 内容。
2. **Projection 参考层**：直接计算

```text
output[token][out] = bias[out]
                   + Σ_head Σ_lane(K[token][head][lane]
                     × gate[token][head]
                     × weight[head×32+lane][out])
```

记分板必须同时比较最终数值和生命周期；只比较 checksum 不能定位 token/tile/head 错配，只比较计数器不能发现数值错误。

## 5. 通用签核判据

每个 P0 用例必须同时满足：

- 0 个 `$fatal`、assertion failure、记分板 mismatch；
- 每个输入事务都被 monitor 观测，每个预期输出都被消费，不允许以 timeout 代替检查；
- 正常组恰好一个成功 `group_done`，异常组恰好一个失败 `group_done`；
- 正常路径满足：
  - `slot_commit_heads = HEADS`；
  - `slot_replay_heads = HEADS × output_tile_count`；
  - `slot_release_heads = HEADS`；
  - `projection_heads = HEADS × output_tile_count`；
  - `bias_commits = TOKENS × output_tile_count`；
  - final token handshake 数为 `TOKENS × output_tile_count`；
  - 当 `OUT_TILE=32` 且 stage 维度为 `HEADS×32` 时，逐元素比较数为 `TOKENS×HEADS×32`；
  - `count_payload_copy_words = 0`；
  - group 完成后 `slot_valid_flat = 0`，下一批可接收；
- 异常路径满足：错误原因可识别、响应有界、无重复 completion、slot 全清、无异常组的 stale final、下一批可恢复；
- C0/C1 的数值、事务身份和功能计数一致；允许 Builder 周期及 C1 overlap/blocked 计数不同。

**P0 设计风险：**当前重复/非法 head 会置位 `batch_protocol_error_q`，而错误批次不能达到 `group_fire`，因此 execution abort 控制器未必能接管。验证必须先冻结预期：推荐由 wrapper 产生本地 batch abort/cleanup，而不是要求整芯片 reset。若最终合同确实规定“非法上游事务只能用系统 reset 恢复”，论文和接口规格必须明确说明，且仍需 R001/R004 证明恢复；否则 H004/H005/H006 预计会暴露真实死锁。

## 7. 真实 S0-S3 签核矩阵

完整集成必须使用同一个 DUT 顶层、同一套记分板和同一套计数不变量覆盖四个 stage，不能用 decoder 叶级结果代替。

| Stage | head 数 | 维度 | output tile 数 | 每模式逐元素数 | replay 数 | 当前状态 |
|---|---:|---:|---:|---:|---:|---|
| S0 | 3 | 96 | 3 | 15,552 | 9 | C0/C1 正常流已通过 |
| S1 | 6 | 192 | 6 | 31,104 | 36 | 未覆盖 |
| S2 | 12 | 384 | 12 | 62,208 | 144 | 未覆盖 |
| S3 | 24 | 768 | 24 | 124,416 | 576 | 未覆盖 |

单个模式四 stage 合计必须比较 233,280 个元素；C0/C1 合计为 466,560 个元素。每个 stage 至少执行：

1. 无背压正常流；
2. 固定周期背压，便于 cycle-exact 重现；
3. stage 分层随机背压，seed 可重放；
4. 格式审计，覆盖该 stage 真实出现的 IPD/FADC/RAW；
5. C0/C1 逐元素、tag、token、tile 和功能计数一致性比较。

每个真实向量必须记录：checkpoint、sample/block/window/stage、源文件 SHA256、head 范围、格式、term/event/destination 数、权重/偏置定点合同。当前 S0 只是 `sample0/B0`，不能外推为 profile100 覆盖。

- 合法参数要通过 elaboration、lint、最小正常流与关键断言；

## 9. Assertion 计划

### 9.1 集成顶层 P0 断言

| 编号 | 断言语义 |
|---|---|
| AS001 | 所有 DUT 输出 ready/valid 通道在 `valid && !ready` 时保持 valid、payload、tag、id 稳定 |
| AS002 | `accepted_count`、`completed_count` 始终不超过 `HEADS`，accepted bitmap 的置位数与 accepted count 一致 |
| AS003 | 一个 batch 内同一 head 最多接受一次，非法 head 永不握手 |
| AS004 | `group_ready` 只在全部 head 已接受并完成、全部 slot 有效、无错误且无 group inflight 时为 1 |
| AS005 | `group_fire` 到 `group_done_fire` 期间禁止第二个 group/head admission |
| AS006 | 每个成功 builder_done 对应一个已接受未完成 head；tag/head/format 不串扰 |
| AS007 | slot commit 每 head 最多一次；inspect/replay 只能访问有效 slot |
| AS008 | replay word index 从 start 连续递增，`word_last` 只在 metadata 指定的末 word |
| AS009 | 每 head 的 replay 次数等于 `group_output_tile_count`，release 恰好一次且晚于最后 replay |
| AS010 | `count_payload_copy_words` 恒为 0，证明共享 typed-slot 没有旁路复制 |
| AS011 | final token id 小于 `TOKENS`，bank 映射正确，tile tag 落在请求范围内 |
| AS012 | 每 bank 的 final 在背压下稳定，两个 bank 可独立推进而不串数据 |
| AS013 | 正常 `group_done_valid` 不早于全部 final、bias commit、head replay 和 slot release 完成 |
| AS014 | fabric error 或 timeout 后，在有界周期内出现一次且仅一次 error done 与 slot reset pulse |
| AS015 | reset/slot reset 后无 slot valid、无 pending output、无 inflight group、无半事务 valid |
| AS016 | abort done 背压期间 admission 阻塞且 done tag/error 稳定；握手后允许新组 |
| AS017 | C1 的 workspace 所有权 onehot，完成次序符合序列号，两个 workspace 满时 admission 阻塞 |
| AS018 | 在环境最终提供 ready/response 的公平假设下，accepted group 在推导上界内完成或 abort |
| AS019 | 正常计数器守恒关系成立，abort 计数器与原因一一对应 |
| AS020 | `protocol_error` 的 sticky/清除语义与接口规格一致，不得无响应地永久挂起 |

输入端稳定性属于环境协议，应放在 driver/interface checker 中；DUT 输出稳定性属于 assertion。两者不能混为一类，更不能用不合法驱动造成的失败归咎于 RTL。

### 9.2 Assertion 覆盖要求

- 每条 P0 assertion 至少有一次非 vacuous 成功命中；
- 错误类 property 必须有对应 cover property，证明 antecedent 真正发生；
- reset、abort、backpressure property 要分别在 C0/C1 命中；
- 叶模块已有 assertion 必须在完整集成动态仿真中真正 bind 和执行，不能只做 lint/elaboration；
- assertion 命中率目标 100%，未命中视为测试缺口，不得直接 waiver。

当前 Verilator 5.020 支持 line、toggle 和 user coverage；需要生成可合并 coverage 数据与 HTML/LCOV 报告。若开源工具无法可靠提取 branch/FSM coverage，必须补充 Questa/VCS/Xcelium，或用明确的 cover property 与形式可达性报告替代相应 FSM 证据，不能把“工具不支持”写成已覆盖。

### 11.2 形式辅助 P0

在缩小参数但保留同一控制 RTL 的配置上，用 `yosys-smtbmc` 或等价工具证明：

1. accepted/completed/slot bitmap 不越界；
2. 无重复 slot commit/release；
3. group 不会在 batch 未完成时接收；
4. reset 后一拍内控制状态清空；
5. abort response 唯一且有界；
6. final 背压稳定；
7. 公平 ready/response 假设下不存在控制死锁；
8. 重复/非法 head 的恢复合同可达且不会永久阻塞。

所有 liveness 必须有有限 bound；每个 assumption 做 vacuity 审计。若 H004-H006 在现 RTL 下出现反例，应登记 RTL bug，而不是扩大 assumption 屏蔽非法事务后的恢复问题。

### 11.3 回归层级

| 层级 | 内容 | 最低频率 | 通过条件 |
|---|---|---|---|
| Smoke | 小规模 C0/C1、真实 S0、全部 P0 assertion | 每次 RTL 提交 | 0 failure，<30 分钟 |
| Nightly | 全部定向、参数子集、C0/C1 各至少 20 个随机 seed | 每夜 | 100% pass，覆盖可合并 |
| Weekly | 真实 S0-S3 双模式、全参数矩阵、至少 100 个随机 seed | 每周 | 0 mismatch，P0 覆盖关闭 |
| 论文 sign-off | 全套定向、真实 trace、多 seed、形式、覆盖、开放 bug 审计 | 投稿结果冻结前 | P0/P1 bug=0，所有目标达到或批准 waiver |

随机回归每个 seed 必须记录：DUT 参数、向量 SHA256、背压策略、随机 seed、周期、检查数、覆盖增量和结果。出现第一个 mismatch 时立即停止该 seed 并分类为 DUT、TB、规格或向量问题。

## 13. 推荐执行顺序

1. 先冻结重复/非法/缺失 head 的错误恢复规格，并写最小定向测试；该项可能直接暴露控制死锁，应早于扩展真实 stage。
2. 建立完整顶层专属 assertion bind，先跑现有小规模与真实 S0，保证断言不是 vacuous。
3. 完成 reset-in-flight 与 abort/recovery 矩阵，特别是 slot 已提交、replay 中途和 final 背压三个时相。
4. 将现有 S0 TB 参数化为 S0-S3 共用环境，使用 stage manifest 选择 head 偏移、维度、tile 数和 projection 向量。
5. 加入可重放随机背压与连续双 group，形成 C0/C1 差分记分板。
6. 打开 Verilator line/toggle/user coverage，按 uncovered bin 增加定向测试；同时对控制缩参顶层跑形式辅助。
7. 形成最终回归、覆盖、bug 和 waiver 四张表，再进行独立 DATE 审稿。
