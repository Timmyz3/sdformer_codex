## 4. 事务服务闭环

v3 不再拼接带歧义的字符串。每笔事务使用：

```text
sorted-key compact UTF-8 JSON
+ schema/seed/kind/identity 的 uint64 长度前缀 frame
+ SHA-256
```

事务类别分别冻结 relation、epoch read、weight 和 final 的完整逻辑身份字段。
候选依赖的全局 transaction index 在任意嵌套层级均被禁止。

服务延迟定义为：

```text
delay = uint64_be(SHA256(frame)[0:8]) mod 4
response_edge = accept_edge + delay + 1
```

因此注册响应延迟严格为 `1..4` 拍，不存在零拍组合响应。每个物理 service
port 只允许一笔 outstanding 请求；请求在接受前保持稳定，响应在消费前保持
稳定，各 port 相互独立。

重复逻辑事务必须显式带唯一、非负 `occurrence`。参考器同时生成有序 ledger
digest 与顺序无关的 multiset digest，并逐候选核对共同逻辑事务的
`identity -> delay` 映射。

## 5. 命令级生命周期闭环

v3 的输入是逐拍 `RelativeCommand`，不是每 head 一个标量 `F/E`。每个 phase
必须给出正 duration 和下列命令：

- relation workspace 访问；
- epoch slot 1RW 读写；
- FIFO2 enqueue/dequeue；
- 五 bank Acc32 1RW 写；
- context prepare 与公共 vector drain。

调度器使用半开区间 `[start,end)`，并逐资源拒绝重叠。slot 生命周期固定为：

```text
FREE -> FILL -> SEALED -> CONSUME -> FREE
```

FILL、SEALED 与 CONSUME 之间不允许所有权空洞；未 seal 的 epoch 不可见。
Acc context 从 prepare 开始占有，直到公共 drain 退休后才释放。

FIFO2 的同拍规则也已冻结：enqueue 先对 occupancy 生效，同拍 dequeue 可以
通过显式 bypass 看到该项；空 FIFO 单独 dequeue 必须失败。每个 output tile
仍严格保持 input-head `0..H-1` 的 Acc32 累加顺序，S2 尾部按宽度 1 重建。

正式 G0 adapter 还必须证明：命令 ledger 能逐项重建现有 Direct RTL 的 task
边界与完整 joint-window 周期。未通过该检查的行不得进入统计器。

## 6. C4/C5 强基线闭环

### 6.1 C4 relaxed oracle

C4 与 C3 使用相同的 `561,600 bit` payload 预算：

- 每 record `112 bit`；
- 可容纳 `5,014` records；
- 固定余下 `32 bit` 不可使用；
- whole-head 粒度；
- offline 0/1 knapsack 最大化 saved cycles；
- 平手时先最小化 records，再选字典序最小的 input-head tuple。

tag/valid 单独报告，不从 payload 预算扣除。因此 C4 是故意偏强的
**payload-only relaxed oracle**，不是可实现的同 bit cache。G0 统计字段 `c4`
唯一映射到这个 oracle。

### 6.2 C4 first-fit 与 C5

C4 first-fit 是固定的可实现策略：按 input-head 顺序，仅接收 saved cycles
为正且能放下的 entry；不替换、不回看。它在 G0 中只作次要报告，在 G2 中
作为物理可实现对照。

C5 full memo 使用 stage3 最坏 `10,800 records / 1,209,600 bit`，无 capacity
miss，但不是面积公平基线。

## 7. 唯一统计口径

主统计量固定为：

```text
R_x = sum_j(w_j * C0_j) / sum_j(w_j * Cx_j)
```

其中 `j` 是 1,200 个 sampled joint windows，`w_j=stage_windows`，每个窗口只
加权一次。禁止使用 per-window speedup 的加权平均。

统计器固定：

- 恰好 18 个 `sequence_key` cluster；
- paired complete-expansion cluster bootstrap；
- NumPy `PCG64`，seed `20260810`，20,000 次；
- percentile 使用 `inverted_cdf`，不插值；
- weighted p95 使用 left-continuous inverse CDF；
- 四个 stage 使用 Bonferroni `alpha=0.0125` 的 98.75% 单侧上界；
- synergy 与 C4 在每个 bootstrap replicate 内重新计算。

边界比较无容差：点估计用 `>=`，CI 下界严格用 `>1.0`，stage p95 delta
上界用 `<=0`。

## 8. G0/G1/G2 晋级门槛

### G0：profile + RTL calibration + model

必须同时满足：

1. `C0/C3 >= 1.25x`；
2. 主比率 bootstrap 95% 下界 `>1.0`；
3. 四个 stage 的 p95 delta 上界全 `<=0`；
4. C3 相对更好的 C1/C2 `>=1.05x`，且 CI 下界 `>1.0`；
5. C3 相对 C4 relaxed oracle `>=1.05x`，且 CI 下界 `>1.0`。

G0 失败就停止 EREP RTL，不允许用 sensitivity 或另一个 cache 口径补救。

### G1：RTL

只有独立评审无 P0 且 G0 全通过后才允许开始。必须做到 Acc32 零失配，并
覆盖 S2/remainder、empty/dense、slot/FIFO/drain 长反压、epoch invalidation、
跨 block/window 与 identity-keyed 长随机延迟。

### G2：物理

主指标固定为 memory-inclusive EDP：

```text
EDP = 加权每 joint-window 能量 * 同目标频率下的加权每 joint-window 延迟
```

要求 C3 相对 C0 的 EDP 至少下降 20%，相对可实现 C4 first-fit 至少改善 5%。
所有候选使用同 process、voltage、SDC、SRAM macro、activity trace/hash 与
floorplan policy。任一候选不满足共同目标频率即 G2 失败，不允许只给该候选
降频。

OpenROAD 结果只能写为 `[开放物理代理]`；ASIC 主表仍需
DC/STA/SAIF/PTPX。

C4 first-fit 端口与 SRAM 实现。故 v3 已在 formal manifest 出现前作废：

