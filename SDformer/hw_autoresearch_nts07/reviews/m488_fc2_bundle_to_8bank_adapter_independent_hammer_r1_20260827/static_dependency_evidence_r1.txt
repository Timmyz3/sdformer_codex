M488 same-cycle slot-reuse combinational dependency
===================================================

Frozen RTL SHA256:
98b11764ea186b57b27ae04be36e313e7d6a82270250282cd34dcb07fdc856e4

Dependency, with frozen RTL line numbers:

  core_rsp_accept
    -> req_slot_open                 rtl_m488/...sv:147-148
    -> req_shape_legal              rtl_m488/...sv:149-154
    -> illegal_request              rtl_m488/...sv:160
    -> protocol_error               rtl_m488/...sv:184
    -> core_rsp_valid               rtl_m488/...sv:191
    -> core_rsp_accept              rtl_m488/...sv:192

For a valid request that reuses the slot retiring on this edge, both of these
Boolean fixed points satisfy the equations:

  A. core_rsp_accept=1, req_slot_open=1, illegal_request=0, protocol_error=0
  B. core_rsp_accept=0, req_slot_open=0, illegal_request=1, protocol_error=1

The directed VCS test reaches fixed point A and covers one reuse. That does not
prove that synthesis, timing analysis, or silicon sees a unique acyclic logic
function. The canonical wrapper must split intrinsic request legality from
resource availability and derive slot-retire eligibility without feeding
illegal_request/protocol_error back through core_rsp_accept. Alternatively,
remove same-cycle reuse and accept the one-cycle bubble.

This is a static P0. No production RTL was changed by the independent review.
