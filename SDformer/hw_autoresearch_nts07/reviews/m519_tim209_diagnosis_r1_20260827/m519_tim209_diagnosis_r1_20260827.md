# M519 K1 precompile TIM-209 只读诊断 r1

日期：2026-08-27  
结论：`DIAGNOSIS_COMPLETE__RESIDUAL_CROSS_CHANNEL_FAULT_GATING_LOOP__CURRENT_ATTEMPT_NO_PPA__R5_CHANNEL_LOCAL_FAULT_DECOUPLING_PREFERRED`  
工具：未运行 VCS、DC、PT、PTPX、Formality 或开源 EDA；未中断既有进程

## 一、裁决先行

M519 修掉了 M496 的“response 当拍释放 slot/context 又重发”路径，但没有完全修掉
**response/request 两个独立通道之间的组合 fault gating**。K1 precompile 现在只有一条
TIM-209，而不是 M496 的两条；该环跨越：

```text
g_k1.implementation/core/g_k1.service
 -> g_k1.implementation/memory_adapter
 -> g_k1.implementation/core
 -> g_k1.implementation/core/g_k1.service
```

高层方程是：

```text
R  = C && !(Fa || Ireq || Irsp)        // M499 core_rsp_valid
Es = Fs || ... || (R && !response_id)  // service protocol_error
Q  = W && !Es                          // service mem_req_valid
Ireq = Q && !request_payload_legal     // M499 illegal_request
```

所以结构依赖为：

```text
R -> Es -> Q -> Ireq -> R
```

即使正常功能下有内部不变量 `Q -> request_payload_legal`，STA 仍必须把 RTL 中可敏化的组合图
视为环。封存 VCS 的两态 directed PASS 只能证明被测事务正确，不能证明组合图无环。

当前唯一 DC attempt 的 K1 `check_timing_precompile.rpt` 已确定报告 TIM-209=1，
`precompile_loop_gate.rpt` 为
`FAIL_PRECOMPILE_LOOP__NO_UNGROUP_OR_COMPILE`。因此该 attempt 不得引用任何面积、时序或
三轴 Pareto；K8/K1x8 也不能由 K1 失败点外推为 clean。本文不终止、不重启、不改写该任务，
仅静态诊断已经落盘的报告。

## 二、原始证据与 RTL 对应

### 2.1 GTECH 环

precompile 报告列出一条 14-cell-arc 环：service 中 3 个 cell arc，跨入 M499 adapter 的
5 个 arc，经 core 1 个 arc回到 service 的 5 个 arc。其层级拓扑与上述方程逐段一致；
`references_precompile.rpt` 随后也以 OPT-150/OPT-314 识别并临时断开同一 arc。任何利用断弧后
图得到的 optimizer 中间数字都不具引用资格。

### 2.2 service 一侧

`m519_fc2_k1_registered_release_service_island.sv` 已正确将：

- free slot 搜索限制为注册态 `!sb_valid_q`；
- context open 限制为注册态 `!ctx_busy_q`；
- response accepted 后只在时钟沿清除两者，下一拍才能复用。

但 service 的 `protocol_error` 仍组合包含
`mem_rsp_valid && !response_identity_legal`，而 `mem_req_valid` 又组合依赖
`!protocol_error`。所以仍存在 `mem_rsp_valid -> mem_req_valid` 的 error-gating 路径，
只是已不再有 release bypass 路径。

### 2.3 adapter 一侧

`m499_fc2_bundle_to_8bank_no_reuse_adapter.sv` 已把 slot availability 从 request legality 中
分离，`illegal_request` 只看 payload legality；但 `protocol_error` 组合 OR 入
`illegal_request`，`core_rsp_valid` 又由 `!protocol_error` 门控。于是独立的 request-side
violation 能在同一拍撤回一条已经 complete 的 response，闭合了剩余环。

顶层 `consistency_fault_now` 不是这条环的根因：它只汇总 core/adapter accept 是否一致并输出
fault，没有反馈进 core 或 adapter 的内部 ready/valid。

## 三、修复候选排序

| 排名 | 候选 | 断环性 | 正常周期 | 面积/公平 | fail-closed 风险 | 裁决 |
|---:|---|---|---|---|---|---|
| 1 | **R5：channel-local fault decoupling** | 直接切断 `Ireq -> R` | 目标 0 拍 | 最小；无需给 K1 加专属数据缓冲 | 需把 state enable 也按通道拆分 | **首选** |
| 2 | **R6A：K1 request register slice** | 由注册 `Qq` 切断环 | 首事务 +1；稳态可 1/cycle | 约 189-bit payload + valid；只罚 K1 | 协议最保守，但 accept 账本必须重写 | 条件 fallback |
| 3 | **R6B：response register slice** | 注册 `R` 后断环 | response 至少 +1 | 若在 8-bank bundle 边界可达 1024-bit weight payload | retirement/occupancy 改动大 | 不优先 |
| 4 | **trusted-core adapter 参数** | 可令 `Ireq=0` | 0 拍、可能减面积 | 容易不对称优化 K1/K8 | 内部 payload bug 失去硬件 fail-closed | **不建议** |
| 5 | 仅从 service `mem_req_valid` 移除组合 `protocol_error` | 可切一边 | 0 拍 | 小 | fault 当拍可能多发一个 request | **禁止单独使用** |

### 3.1 首选 R5：按通道拆 fault，而不是删检测

推荐保留：

```text
protocol_error = fault_q || illegal_request || illegal_response
```

但不要再让 request-side 的同拍 `illegal_request` 撤回独立 response channel 的 valid。
建议语义是：

```text
core_rsp_valid = complete_found && !fault_q && !illegal_response;
```

同时把 adapter state 更新从全局 `if (!protocol_error)` 拆成 channel-local enable：

- 当前拍非法 request：`core_req_ready=0`，不得产生新 bank request，不得修改 request/pending
  账本；`protocol_error` 当拍拉高并在沿上 sticky；
- 同一拍若恰有先前合法事务的 complete response，可让 core 与 adapter **双方一致地**接受并
  retirement；这不是接受攻击请求，而是完成独立通道上已经拥有 identity 的旧事务；
- 当前拍非法 bank response：不得进入 complete response，不得接受新 request，标记 stale/fault；
- 下一拍 `fault_q=1` 后所有新流量 fail-closed。

这样既保留组合 attack detection，也消除 `Ireq -> core_rsp_valid` 跨通道反馈，正常流量不新增
pipeline latency。关键不是简单删除 `!protocol_error`，而是保证 `core_rsp_valid`、
`core_rsp_accept` 和 response retirement 使用同一套 response-side enable；否则 service 接受而
adapter 不清 slot，会触发 consistency fault 和重复响应。

R5 只改 K1 的 M499 adapter 时，三轴外部 pin/clock/SRAM 端口仍相同，且不人为给 K1 增加
pipeline bubble；这是当前最干净的恢复。代价是 protocol 状态机需要一次新的 unit-level attack
验证，不能凭正常 top-level workload 推定安全。

### 3.2 K1-only request register slice 是否“最安全”

从**结构断环**和 ready/valid 教科书边界看，它最保守：service 先把完整 request payload 放入
one-entry registered slice，M499 只看注册后的 `Qq`，因此 adapter response 无法在同拍反馈到
service 当前 request valid。

但它不是最小、也不是自动协议安全：

1. 当前顶层要求 `core_mem_req_accept == adapter_core_mem_req_accept` 同拍相等；切片后 producer
   enqueue 与 consumer dequeue 不再同拍，必须改成累计守恒
   `producer_accept - adapter_accept == occupancy`，不能删除 consistency checker 了事；
2. slice 必须冻结 epoch/slot/generation/tag/block/slice/source_count/bank mask/八路 channel，
   粗计约 **189 bit + valid**；若用 fall-through 又会重新引入组合路径，必须是真注册输出；
3. 需要定义 fault 时 buffer 内合法旧请求是 drain 还是 poison。推荐 fail-closed 为“不再向 bank
   发出，sticky fault 后保留 occupancy 仅供 debug/reset”，不能静默丢掉并假称已完成；
4. 正常情况下至少增加首 request 一拍；stall 序列与 token cycle 必须重测。

只给 K1 加 slice 在物理比较上是**可披露且可测的真实实现成本**，不是非法不公平；但它会让
K1 面积更大、周期更长，从而机械放大 K8/K1 与 K1x8/K1 的优势。不得把这部分恢复税包装成
稀疏收益。尤其论文主比较 K8 vs equal-bandwidth K1x8 不受 K1-only slice 直接影响，但三轴表
中的单 K1 倍率必须脚注“registered request boundary”，并在同一新 identity 下重跑 VCS/DC。

若评审要求最强公平，可给三轴都加语义相同的一拍 request boundary；但 K1/K8 的内部 atomic
bundle 与 K1x8 的八独立 service 边界不同，统一 slice 会大幅扩展改动且不再是本次最小恢复。
因此 R6A 只在 R5 static review 或 precompile 再失败时使用，并将其成本完整计入 K1。

### 3.3 response register slice

显式注册 M499→service response 也能切环，但当前 core response 接口携带八 bank × 16 lane 的
weight array。即使 SOURCE_CAP=1 最终只用 128-bit bank word，直接在 bundle 边界实现可能保留
约 1024-bit storage/mux；做 cropped 128-bit slice 又需要下沉到 service 内部，改动层级更深。
同时 adapter dequeue 与 service consume 分拍，现有 response accept consistency checker 也需
改为 occupancy 守恒。它增加 response latency，可能进一步延迟 registered slot/context release，
所以不如 R6A。

### 3.4 trusted-core adapter

给 M499 加 `TRUST_CORE_REQUEST=1` 并令 `illegal_request` 常零，逻辑上能断环，也符合内部 core
正常生成请求的设计意图；但它把“内部不变量”从 fail-closed 硬件检查降成假设。除非同时有
Formality/SVA 证明所有 reachable `core_req_valid` 都满足 payload legality，并且 K1/K8/K1x8
采用可解释的一致 trust policy，否则不能作为 DATE 物理恢复。攻击 TB 若只能证明 trusted 模式
会静默接受非法 payload，则该候选直接 NO-GO。

## 四、R5 必需的 VCS/SVA 攻击矩阵

新 identity 不能只重跑既有 B1/B2/B4/B8 正常场景。至少新增：

1. adapter unit：complete legal response 与 malformed core request 同拍；非法 request 0 accept、
   0 new bank request，旧合法 response 两侧 accept 一致且只出现一次，下一拍 sticky fault；
2. malformed request 分别覆盖 source_count/mask mismatch、zero mask、channel-bank mismatch、
   slot/block/slice 越界；每项不得改变 request/pending/slot 账本；
3. illegal/stale bank response 与 legal core request 同拍；response 0 accept、request 0 accept、
   stale+fault sticky，所有 payload/state 稳定；
4. pending bank-request drain 期间注入 malformed core request；攻击拍不得额外 bank accept，已有
   pending mask 不得丢失或重复，fault 后不得继续发出未接受 beat；
5. legal response backpressure + attack：`core_rsp_valid`/identity/weight 在 policy 允许的最后一个
   合法 transaction 上稳定，禁止 service/adapter accept mismatch；
6. 不同 slot 的 legal request+response 同拍仍维持 conservation；同 slot 因 registered-release
   必须等下一拍；
7. SVA 计数：bundle request、bank request、bank response、bundle response、service request/
   response、adapter occupancy 在无 fault 前严格守恒；fault 拍后没有新外部副作用；
8. reset 后 sticky fault、hold、pending、slot 全清；攻击后没有 result/token_done；
9. 原 B1/B2/B4/B8 exact numeric、zero-token、stall、protocol attacks 全部回归；三轴 cycle 全重测；
10. VCS PASS 后仍必须逐点运行 precompile hard gate；VCS/SVA 不得冒充 TIM-209=0 证明。

若选择 R6A，还必须补 slice empty/full、simultaneous enqueue/dequeue、下游长 stall、payload stable、
fault 时 occupancy policy、producer/consumer cumulative conservation，并替换同拍 consistency 断言。

## 五、恢复门和停止条件

1. 当前 M519 DC identity attempt 已消费且 K1 precompile FAIL；不得改目录或重跑同 identity。
2. R5 先做独立 static hammer，证明所有 response accept/retirement enable 一致且 request attack
   无副作用；再做 exact-SHA VCS/SVA。
3. VCS 后建立新的 DC identity，K1/K8/K1x8 均用同 top、filelist、3.000 ns SDC、DB、flatten/
   compile 序列和端口；每点 TIM-209/OPT-150 必须为 0。
4. K1 clean 不能替代 K8/K1x8 clean；三点 final reports/netlist/五类约束全部闭合后才算
   area、throughput/mm2 和 Pareto。
5. 若 R5 precompile 仍有环，只允许转 R6A；若 R6A 仍失败或同资源 Pareto NO-GO，则停止 M519
   物理线，不开第三个协议结构。
6. 任何修复后的 K1 周期/面积变化都必须进分母，禁止沿用 M519 r2 的 K1 11718 cycles 或旧
   M496 optimizer 中间面积。
