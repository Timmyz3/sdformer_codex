# M37-r11 evidence hardening

R11 retains the exact r10 candidate RTL bytes.  It repairs the independent
hammer's evidence-admission finding; it does not change or strengthen any
functional or physical claim.

The auditor has no RTL, contract, root, or SHA-enforcement override.  Every run
resolves the canonical candidate inside the repository and verifies SHA256
`f9474151...` against both a source constant and the contract.  A separate pin
manifest closes the actual contract, auditor, test, result, README, candidate,
and r10 NO-GO review bytes.  JSON is loaded with duplicate-key and non-finite
number rejection, and expected values use recursive type-strict comparison so
booleans cannot masquerade as integers.

Source-semantic negative tests now reject all attacks demonstrated by the r10
hammer: swapped bias rows, product beat shifted by one cycle, clearing a
same-cycle phase-4 replacement, reversing phase-table loading, sourcing valid
metadata from negative metadata, and adding another `issue_product_comb`
driver.  Path override, realpath escape, duplicate JSON keys, non-finite JSON,
nested bool/int confusion, and pin SHA drift are also rejected.

The 168-bit phase `case` remains only a source-level factoring observation.
Neither a unique physical mux nor mapped sharing is claimed.  State bits and
the two explicit source-selector equations remain 5,979 bits and 1,104 mux-bit
equivalents respectively; neither predicts mapped area.  The 70,038.737606 um2
limit remains a future exact-SHA DC admission gate.

No Synopsys tool was started for this evidence-hardening milestone.  An
independent r11 static hammer is required before the frozen VCS gate.
