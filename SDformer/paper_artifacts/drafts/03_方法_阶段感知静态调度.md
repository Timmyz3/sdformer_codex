**风格**：research-paper-writing（DATE 系统协同设计视角）+ 后续 nature-polishing 提示。严格执行主张-证据-推理纪律。所有主张绑定证据。DATE 语气：聚焦实现、静态调度作为主角，而非神经元技巧。

## 3.1 动机：为什么选择静态调度而非均匀或动态替换

SDformerFlow baseline（事件体素上的脉冲驱动 Swin 风格编码器）在不同阶段的计算量极不均匀（见规划结果图 Fig. 2：Stage 2 单独占据约 23% GFLOPs 代理）。先前 SNN 稀疏工作（QKFormer、STAtten、多种三值神经元）已证明，用二值/三值或剪枝等价操作替换密集计算，可显著降低 SOPs 和发放率。然而，简单地在全网均匀应用此类替换，要么 (a) 在运动边界和大位移上导致不可接受的精度下降，要么 (b) 产生异构数据通路，其控制逻辑和缓冲管理在硬件上代价过高。

**主张**：通过敏感度和每阶段 SOPs 画像得出的编译期阶段感知静态替换策略，可生成确定性的层级调度，既保留大部分效率收益，又使硬件映射保持简单可预测。

**证据**（来自 EXPERIMENT_REDESIGN_PLAN.md，Phase 2-S02 / S012 实验）：
- SN（signed_shiftnorm）注意力 + S02 FFN 替换，在多次短测和较长运行中 consistently 将 SOPs 控制在 3.0-3.3G 范围（baseline 约 3.6G），AEE 稳定。
- TX（ternary_axnor）+ S012 在短测中将 SOPs 降至约 2.92G（降低约 19%），发放率 0.069。
- 跨 FFN 分析显示，SN 是唯一在仅替换高 SOPs 阶段或替换更多块时仍保持鲁棒的注意力变体。
- 发放率从 baseline 的约 0.085 降至候选方案的 0.069-0.077。

**硬件友好的推理**：
- 策略在离线一次确定，使用任何设计空间探索都会进行的相同画像。
- 部署时网络以固定每块内核标注（密集 PSN、二值 ATLIF、三值 ATLIF + 特定归一化）输出。
- 加速器仅需一张小调度表和多路选择器，即可为当前层选择预综合内核——无需运行时掩码生成、无复杂动态稀疏控制器、无频繁缓冲格式转换。

这直接回应了 DATE 对“设计方法学”和“架构设计”的要求，而非单纯算法改进。

## 3.2 软件原语与替换策略

### 神经元层面
早期层保留上游 PSN（表达力需求最高），后期阶段引入 ATLIF（自适应阈值泄漏积分发放），输出为三值。ATLIF 的可学习阈值缩放直接控制稀疏度，同时对称正负发放保留事件极性信息（对基于事件的运动至关重要）。

### 注意力层面
将密集 QK 乘法 + softmax 替换为重设计搜索中探索的硬件轻量变体：
- **TX（ternary_axnor）**：三值脉冲 → 符号提取 + XNOR + popcount（或 L1 变体）。
- **SN（signed_shiftnorm）**：带符号共识或基于移位的归一化，可映射为廉价移位而非乘法。
- **SC（signed_consensus）**：类似共识机制。

所有变体均在 SDformerFlow 上游已有的脉冲驱动 Q-K 路径上操作，仅在必要时添加轻量局部时间偏置（受 STAtten 启发但保持轻量）。

### FFN / MLP 替换
FFN 块（补丁嵌入后主要计算消耗者）进行选择性替换：
- 高 SOPs 阶段（主要是 Stage 0 和 Stage 2，按数据流分解）使用二值或三值 ATLIF + 稀疏线性层。
- 较低 SOPs 或高敏感度阶段保留更密集的 PSN 路径。
- 决策编码为静态调度表（示例见表 X，由 EXPERIMENT_REDESIGN_PLAN.md 中的敏感度分析生成）。

因此最终网络是**静态异构 SNN Transformer**：不同块使用不同内核，但映射在编译时已知，运行时不变化。

## 3.3 硬件子系统架构

软件策略映射到**脉冲事件 Transformer 加速器子系统**（非完整 SoC；解码器和后处理保留在软件或更轻加速器中，供未来工作）。

关键引擎（直接来自上述原语）：
- **脉冲神经元引擎**：支持 PSN（密集）、二值 ATLIF、三值 ATLIF，支持实时阈值自适应。每个神经元小状态（膜电位 + 阈值）保存在寄存器中。
- **三值注意力引擎**：符号/有效位提取、XNOR 或移位归一化数据通路、popcount 树或移位累加，随后 shiftmax/shiftnorm 门控。采用窗口平铺以匹配 Swin 结构，并利用双 bank 窗口 SRAM。
- **稀疏 FFN 引擎**：二值/三值稀疏矩阵-向量单元，根据调度表跳过零激活。
- **静态调度控制器**：简单有限状态机，遍历层级调度表，为当前块配置多路选择器和引擎模式。关键路径上无动态搜索逻辑。

**存储系统**（边缘可行性目标 <2MB 片上 SRAM）：
- 权重缓冲（256KB）：每层从 DRAM 流式加载。
- 双 bank 窗口 SRAM（512KB 总计）：用于当前时空窗口 tile（Q/K/V + 部分结果）。
- 每调度表条目的显式乒乓与重用分析（后续在代价模型中量化）。

数据类型在早期锁定（见 HARDWARE_DATAFLOW_SPEC.md）：1-bit/2-bit 脉冲、FP16 或 INT8 权重、注意力分数与门控用窄定点。这使 DATE 审稿人期望的面积与能耗数字成为可能。

## 3.4 协同设计闭环与证据链

闭环为：
1. 软件重设计搜索（EXPERIMENT_REDESIGN_PLAN.md 中的 H 系列）→ 候选策略 + 测得的 SOPs/发放率/AEE。
2. 敏感度 + 每阶段 SOPs 画像 → 基于规则的替换掩码（S02 或 S012 模板）。
3. 输出静态层级调度表。
4. 硬件代价建模（算子级：XNOR vs MAC、SRAM 访问等）与微架构尺寸确定。
5. 反馈：若精度或硬件代价不可接受，则调整替换范围或原语参数并重新搜索（闭环，而非单向模型到硬件）。

- 发放率与相对 SOPs 总结（规划 Fig. 3）量化稀疏收益。
