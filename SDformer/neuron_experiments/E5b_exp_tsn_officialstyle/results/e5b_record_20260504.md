## What Was Ported

E5b replaces the earlier simplified TSN node with the official implementation pattern from `models/spike_layer.py`:

- `spike_activation(x)`:
  - forward ternary states are `{-1, 0, +1}`;
  - `abs(x) < 0.5` maps to `0`;
  - backward uses the official clamp STE.
- `mem_update(x_in, mem, V_th, decay, fire_ratio)`:
  - `mem = mem * decay + x_in`;
  - `spike = spike_activation(mem / V_th)`;
  - `mem = mem * (1 - abs(spike))`;
  - `spike = spike * fire_ratio`.

E5b also follows the official training style:

- SGD with momentum.
- `split_weights` style parameter groups:
  - Conv/Linear weights get weight decay.
  - Bias, BN, and `fire_ratio` use no decay.
- Cosine LR schedule.

Baseline files under `third_party/SDformerFlow` were not edited.

## Decision

Do not run full E5b from this setting.

Reason: the official Ternary-Spike dynamics are now correctly ported and the official optimizer/scheduler paradigm is connected, but the blanket replacement in SDFormerFlow produces very high ternary activity and severe accuracy collapse. This is worse than baseline on both accuracy and SOPs.

The official TSN repository is an ANN-to-SNN image-classification conversion/training pipeline with `SpikeModel`, `SpikeConv`, `LIFAct`, step count commonly 4, and layer/block conversion. The SDFormerFlow transplant uses temporal event bins and replaces every `Spiking_neuron` module directly. That is a major paradigm mismatch, even though the local neuron update itself follows the official source.
