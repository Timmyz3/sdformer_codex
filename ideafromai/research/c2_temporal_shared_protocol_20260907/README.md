# C2 时间共享部分和：第一份可执行协议

**三配置 Verilator 功能验证通过。** 机制解释及强先验比较见 [C1/C2 融合报告](../fusion_delivery_20260907/report.html)。这是隔离研究原型，尚未建立 TCAS-II 强接收结论。

多个源若在相同的时间步发放，它们对下游输出的贡献可以先加一次，再交给多个时间输出。例子中，a、b 都服务第 0/2 时间输出，就先形成 `phi_a+phi_b`，然后各提交一次；`phi=theta*W` 保留连续值阈值幅值。

此版按原通道次序接收源，仅为服务多个时间输出的签名保留 8 个部分和。命中时累加；满槽时将最旧部分和交付给全部相关消费者，最后一个确认后才复用。单时间源直接送往其输出。曾被驱逐的签名再来时形成新段，付出新的分发成本。数值抵消成零的部分和仍有效。

相同签名归约、完整 T 组织、LRU 和多播确认均有先验；本原型检验的是有限状态实现与服务边界，不能用“RTL 写完”提升概念新颖性评分。前轮独立概念评分仍为 **6.5/10**。

最新收据：[functional_r2/result.json](records/functional_r2/result.json)。两种 T10 配置都包含同一份真实 FC2 发放支持：stage0/3 block0、每层 16 个位置，共 32 帧、55,296 个源。其余为定向和随机输入，T2 不冒充真 FC2 捕获。随机源与背压共用 PRNG，跨配置随机部分不同，表中事务或模拟周期不能相除成为性能比。

测试同时核对独立 LRU 参考的每一个分发段、每个消费者的确认位和直接整数求和结果；覆盖输入与输出背压、valid 跨拍保持、done 等待、D+1 类抖动、末源为零、有效零、负数及符号扩展、非法身份拒收，以及一个消费者已确认后的复位。

独立审阅发现 r1 测试器没有检查整段 valid 临时撤回及 done 撤回。r2 增加跨拍断言，沿用原 fixture 重跑通过。RTL 没有因此修改；r1 原收据及当时源文件 SHA 快照均保留，不能把 r2 断言算作 r1 已验证。字典命中/驱逐计数来自独立参考，不是 DUT 内部活动计数。

## 数字、端口与工程边界

- 载荷是 8 lane × 48 bit 的诊断有理数分子，分母为 10⁶，含非 1 的阈值。它不是实际 checkpoint W 或冻结 FP32 测试；每个参考中间值必须在有符号 48 bit 内。
- 8 个共享向量＋SRC＋WORK，共 10 个工作向量；另有 10 个持久 Y 及有效位。Y 由 C++ 数组模拟可直接读取的寄存器消费者，本轮没有实例化或映射 Y 的 RTL。标签、LRU、控制、宽加法器和扇出均需后续计费。
- 单源在途，没有 8-bank 并行返回、同步 SRAM 读改写、生产者免转置、BN 集成或生产 RTL 合并。
- 前轮 8 槽 CPU 参考的 **20.78%／42.21% 加法减量**来自该轮完整 sample0 两层统计，不是本 RTL 的加速比。相同源系数仍各读一次。
- 未运行 VCS、DC/PT、Formality 或 PPA；没有新增 AEE、整网 FPS 或录用保证。

复位只覆盖最终排空中部分消费者已确认的情况；REPLACE、PROCESS、DONE 中复位未逐状态穷举。最大合法索引长度、非二次幂槽数和其它位宽/lane 配置未测。独立静态复核另检查了 D1–D5 的 2,364 个 LRU 秩转换，该检查不是 RTL 仿真。

完整接口与预算见 [contract.md](contract.md)。RTL 为 [c2_temporal_shared_sum.sv](rtl/c2_temporal_shared_sum.sv)，测试为 [scoreboard.cpp](sim/scoreboard.cpp)。

复现使用 `/opt/anaconda3/bin/python3.12 sim/run_functional.py --run <新名字>`。既有 fixture 不重建、既有收据不覆盖；编译器为系统 Verilator 4.028。`records/*/source_snapshot/` 内字节与各自收据输入 SHA 相符；生成的 `obj/` 是可重建产物，不进入研究源码封存表。

下一项性能工作应固定相同的 bank、输入暂存、Y 端口、位宽与背压，再比较直接完整 T FTP、平坦共享归约和此版有界分段。当前原型提供可核对的服务基准，尚不解决新颖性和净硬件收益的全部问题。
