# ep34 注意力：M0–M2 实测说明

2026-09-07。已完成现有 ep34 Q/K 的普查、同账本 MAC 工作量表及归一化检查。**保留配对分数复用的研究空间，但“三 popcount＋token enable”还没有取得主电路贡献的证据。** 不自动切回已经没有时延增量的 C2 静态共享。生产 nts07、主稿和 Grok 原包未改。

## 1. Grok 漏掉了可直接分析的 ep34 数据

M1458 已有40样本×12块，共480个Q/K文件；它与C1/C2使用同一账本。4个序列各10样本，不是valid825。输入、网络、ATLIF幅值和量化设置没有改变，本轮没有GPU运行。

捕获范围是每次调用的前 `min(100, 窗口总数)` 个窗口。S0捕获100/440，S1为100/120，S2为30/30，S3为10/10。**不能称为全网络窗口普查。** 尤其S0的捕获K bit密度仅0.0171%，完整调用却是1.5587%；这个前缀明显不能代表整层。

Grok的ep35包则每块只取一个窗口，其“全网”数字也只是所取窗口的汇总。三项popcount均值还采用每文件等权，未按不同stage的head-token数加权；本次按两个时间片的全部token加权。两包的检查点、样本及窗口覆盖不同，不做前后改善比较。Grok脚本用默认大端解包，实际文件为小端；由于本轮指标跨完整32-lane归约，相同的字节内置换不改变那些汇总数，但后续逐lane映射必须改正。

## 2. 已捕获窗口内的结果

统计覆盖39,960,000个“时间配对×head×位置”，对应79,920,000个时间token。这里的token不是单个bit，也不是不分head的空间位置。

## 3. 必须改掉的两条跳过推论

**K=0只能直接证明该token的输出乘积为零。** 它的分数仍参与450-token行的max、指数和及分母。诊断中直接删除这些项，会改变4,599,344个非零K token的gate，占非零K token约34.86%。一个450-token行只含一个K事件的反例中，原有效gate约0.87853，删除其他零K项后变成450。

零值项可以继续研究“按分数类别计数，再保留其归一化质量”。本次66,726,054个零K token对应1,242,945个逐行分数类别；这只是后验压缩机会，未计分类构造、查找、计数及数值顺序代价。现有profiler已经有 `zaf_fold_classes`，不能把类别计数本身冒充新原语。

**整行有dirty，不会自动破坏行内某一对相同分数的复用。** 冻结实现将两个时间片合成同一条450-token行；相同分数通过共同归一化后仍相同。需要区分行内配对复用和跨窗口复用整条旧gate。Grok用“整窗脏”直接把前者降成只剩能量门，条件过强。

## 4. 本次使用的是ep34算术

冻结配置为

`score = (overlap + 0.02 × same_zero + 0.125 × motion) / 32`。

`mu=0`，量化关闭，K的连续阈值幅度仍保留在 `gate × K`。现有SV叶的 `same_zero/64 + motion/4` 是另一套部署候选系数，不能直接称为这份ep34原算术。

本次用NumPy重建分数、center、Shiftmax和450倍均值恢复，得到的Q1.7观测码与捕获的79,920,000个gate码全部一致。这支持统计视图和公式对齐；不等于全部FP32中间值逐位相同，更不是新AEE结果。捕获gate码两时间片相同率95.53%，也不能把舍入后的相同当成原FP32等价。

## 5. M0：算术工作量小，真实周期份额仍不能混报

旧 `operator_runtime` 有79个算子，漏掉四个ConvTranspose。本次根据同样40个样本的输入及下游BN形状补回，MAC表覆盖83个点积算子。ConvTranspose按3×3、stride2、padding1的有效散播tap计数，没有把插入零算作有效MAC。

| 算子族 | Dense MAC/帧（G） | 活动率加权MAC proxy/帧（G） |
|---|---:|---:|
|Patch残差卷积|254.804|10.830|
|FC1|84.935|9.607|
|FC2|84.935|2.836|
|ConvTranspose|78.849|15.141|
|瓶颈卷积|63.701|6.421|
|其余Patch卷积|52.199|5.835|
|Q/K投影|49.766|2.954|
|注意力输出投影|24.883|0.776|
|Downsample与flow head|10.829|1.808|
|合计|704.901|56.206|

另有图上活着的45个T10、36个T2 ATLIF，其满秩PSN时间矩阵为12.290 G MAC/帧。12个已调用但结果无消费者的attn_sn单列，不纳入这个图上成本。每帧完整分数工作量为3,024,000个32-lane token；gated-K为96,768,000个标量乘积机会。

MAC与popcount不是同一种物理操作。因此这里只给换算敏感性：若每次32-lane打分记为96/256个MAC等价工作量，在“活动率加权点积＋图上PSN＋gated-K”的分母中，分数叶占0.4214%/1.1160%；要达到2%，该换算因子约需463。它们不是频率、周期或功耗测量。BN每帧另处理约1.394G个输入元素，Shiftmax、残差、布局及存储调度也没有被偷偷认作免费，只是不在MAC分母中。

**当前判断：M0仍不支持把分数叶写成显著系统加速；也不能用MAC proxy机械触发“2%以下就恢复C2共享”。** 若继续注意力，应先比较合法保留分母的配对/类别处理与已有强基线，而不是照原B3草图直接关闭零K打分。
