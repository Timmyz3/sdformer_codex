**四个区间的含义与检查**

`occupy` 使用半开区间 [first,end)，同一具名 slot 的新区间必须不早于旧区间结束。全局事件排序在同拍先释放再占用，符合在时钟边沿完成消费后复用寄存器。区间零长度跳过，不用于掩盖本例中的实际计算占用：活值系数、目的操作数、待写结果的保留终点都包含其消费者完成时刻。

| slot | 实际保留范围 | 独立判断 |
|---|---|---|
| A：源累加器 | 首父或首系数响应到达，到本行或公共值全部目的消费者完成 | 公共值没有在首个 scatter 后提早释放；父捕获还增加 `source_free >= parent_ready[row]` 断言，覆盖父写完成 |
| X：系数与回填传输 | 活值上的系数从 weight 响应到源 ALU 完成；回填从首 beat 到达至 cache write 完成 | 没有只记到 ALU 开始而把整向量免费搬到未声明的输入寄存器；六拍组装复用同一个 X |
| D：旧目的值及最终输出 | 旧 Y 从响应到目的 ALU 完成；最终输出从响应到第六 beat 发送完成 | 输出发送不再需要另一个未声明的完整向量缓冲 |
| P：唯一待写结果 | 目的 ALU 结果产生，到 output SRAM write 完成 | 写阻塞期间保持结果；后续操作由原 `pending_free` 约束 |

首父响应直接装入 A，首个残差系数可同时装入 X；根行首系数也直接装入 A。这些旁路已明确写进计划。它们是独立 SRAM 响应入口和寄存器装载路径，不是未收费的额外加法。A/X 保持到相应 ALU 消费完成，不需要另加完整 ALU 输入保存向量。

六拍回填中，`bus.use(t,6)` 返回第六拍完成时刻；`first_beat=end-5` 是首拍到达时刻。X 从这时起保存逐拍组装的数据，再保持到 cache write 完成。等待首拍以前尚没有返回的数据，不需要提前占一个接收向量。外部 backing memory、16/256/1024/6912 项 coefficient cache 和源/common bitmap 是资源表中的存储，不应与四个临时寄存器混为一谈。

`live_events` 的全局 peak 检查建立在“全部持久临时值已经归属 A/X/D/P”的静态枚举上。单纯峰值数字本身不能排除遗漏路径；本轮通过上述回填、首值旁路、父捕获、scatter 和最终发送的路径检查补足这一部分。

**动态容量 LRU 的行为和解释边界**

从固定 `age[16]` 改为 `position`＋双向 LRU list 后，每次 ensure hit 和每次实际 weight read 都将该系数移至 MRU；满容量时淘汰 LRU；未填满时按顺序分配新槽。它与原版每次相同访问 `age=++clock`、淘汰最小 age 的行为对应。无效 iterator 不会被使用：只有 `position[f]>=0` 的驻留条目进入 touch，淘汰时先将旧 position 清为 -1，新插入时重建 iterator。

缓存实例仍在每个 M/N tile 内新建，不能跨 M/N 免费驻留。容量参数没有改变全 K、APEC 分组、父图、bank 服务或输出提交的语义。lookup 的 host 数组/链表用于加速模拟，不是免费提供给硬件的 6912 项索引结构；模拟的 tag/read/write 费用仍显式保留。

容量 16 的实核回归支持这一等价关系；容量扩展点仍只能解释为既定编码、冷启动和服务率下的工作集敏感性。增大阵列后保持一周期服务，是声明的 CPU 模型参数，不建立等面积、等频率或真实 SRAM/CAM 延迟结论。

前次记录中的其它保守边界继续有效，包括每 M/N 清空缓存、每 K 排空目的访问、统一 K 启动周期和 48-bit 诊断 φ 编码。新增区间检查解决的是临时状态一致性，没有将这些选择变成最优微架构或普遍性能界。
