# C2：生产前端与完整 T 的同负载隔离参考

首轮成功收据是 `functional_r3/result.json`。生产 `m2018` 和 `m803` 两份 RTL 从 nts07 按 SHA 只读编入，未改生产树。本目录没有新 Card，也不是完整 LoAS 加速器。

范围是 ep34 已封存 sample0、stage0 block0 FC2 的空间位置 256–287，分成 8 个独立冷启动的相邻四位置工作负载。每个位置完整覆盖 T10、C384 和 96 个输出通道；这不是完整 19,200 位置帧，也不是整网测量。模式 0x140 沿用此前前 256 个位置的选择，评价位置不参与本轮选模，仍不能称独立帧泛化。

| 轴 | 周期和 | canonical 源组行读取 | 16-lane 逻辑请求 | 逐值检查 |
|---|---:|---:|---:|---:|
| 原 SHA m2018，SCHEDULE_MODE=1 | 662,018 | 732 | 70,272 | 30,720 |
| 完整 T 直接 FTP | 442,009 | 720 | 14,436 | 30,720 |
| 完整 T FTP，加静态共模共享归约 | 438,401 | 720 | 14,436 | 30,720 |

三轴都零错误。共享版相对生产轴少 33.778% 周期，但相对直接 FTP 只少 **0.8163%**。直接和共享 FTP 的请求、行读取完全相同；RTL 加法分别为 270,144 和 245,952，独立支持计数公式给出同样结果。这里的整体差额主要来自 FTP 和逻辑向量拆包服务，不是共享归约的独立收益。

`plan.json` 是首次运行前写入的不可覆盖预声明。生产轴保留 B4 空间分组，逐 T 运行十个 B4；没有把生产分母改成 T4，也没有虚增尾部空上下文。生产加载只发实际非空源组，空上下文仍有合法零终端描述符。候选每个位置先装载完整 T 的 384 个时间掩码，原 c 顺序取系数，RTL 同步构造匹配计数；最后匹配源到达才播发该 bank 的共享和。

地址服务是**统一的行为模型**。捕获地址为 `393216 + floor(c/16)*6144`，bank 为地址行号模 8。`c%8` 只作为 m803 的逻辑返回通道，没有冒充 captured bank。每次 6,144 B 行填充收费 384 个 128-bit 传输周期，16 个 32-bit backing word 拆为 16 个 INT8 数值收费 4 周期；八个逻辑请求槽、一个行缓存、一个响应保持寄存器共用串行服务。逻辑请求大幅减少，backing 行读取只少 1.64%；不能把请求减量写成同比例外存带宽节省。该服务预算未对应实测 SRAM，也没有综合行拆包电路。

计时从每个 quad 第一个源传输模型周期开始，到最后一个输出向量被消费者接受。120 周期源 DMA 模型允许生产轴在第 12 周期后开始第一个 T，FTP 等待完整 T。所有 RTL 加载、事务间退休和输出背压在计时内；初始 reset 不计。掩码打包/转置由 Python/C++ 生成，**其组合逻辑和计算周期未实现、未计入**。消费者是 C++ 校验/存储端，没有 BN2、shortcut 或外部写回 DMA。不得称完整 FC 推理时延。

系数是公开定义的有理数诊断：θ=9/8，`W[c,h]=((7c+11h+3)%25)-12`，SRAM backing 中保存 INT8 范围内的分子 `9W`。输出按共同分母 8 解释。真实捕获只提供支持；没有使用 checkpoint 权重，没有证明冻结 FP32 等价、AEE 或 PPA。24-bit 累加的静态绝对上界为 41,472。

候选裸宽状态包括 8×96 个共享部分和、10×96 个最终累加器以及两个 16-lane 工作向量，均为 24 位；另有 384×10 位时间掩码、8 个 6-bit 计数、live/输出有效位和控制。直接 FTP 使用同一候选 RTL，将共享开关关闭；它不是经过独立面积优化的 LoAS 实现。共同的行为行缓存另占 6,144 B，源输入缓冲上界另为 1,920 B，元数据和物理宏开销仍需独立收费。

`functional_r1` / `functional_r2` 保留失败日志和当时源码快照：新 C++ 内存驱动在响应接收边沿后，尚未撤销旧 valid 就检查组合错误，产生瞬时 stale 误报。r3 在同一边沿更新行为生产者并重新组合求值后检查稳定状态，生产 RTL 未变。主战役实际出现输出背压；响应保持周期为 0，不能声称本工作负载动态覆盖了响应背压。

复核入口：`plan.json`、`c2_ftp_shared.sv`、`scoreboard.cpp`、`make_fixture.py`、`run.py`、`fixture.json` 和 `functional_r3/source_snapshot/`。`run.py` 只接受新 attempt 目录，失败也不覆盖；其 Verilator 构建与 C++ 运行命令逐条记录在 `commands.json`。本轮没有 VCS、DC、PT、Formality、GPU 训练或生产目录写入。
