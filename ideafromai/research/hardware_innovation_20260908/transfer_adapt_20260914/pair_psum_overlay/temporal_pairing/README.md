## 接口和完整机会账

原端点路线要承担额外状态与恢复费用。这里只迁移其排序接口：正事件的T顺序重排后，把相关的两T放进同一个四P×双T计数块，继续使用原正count8、psum阶段复用和signed packed双P退休。不生成差分端点，不增加第二z域，也不把此前7.45%和端点3.99%相乘。

`cfg_kind=2`加载十个4bit索引，40bit寄存器在本次权重生命周期驻留。L_GATHER在RTL内部从原始source word选择排列后的十个bit；源文件没有预重排。所有Q1和Q2内部位置使用同一顺序；DRAIN按原result_addr做组合逆映射后只读一个p_mem行，完整raw p恢复原P/T/N顺序。逆映射没有第二张驻留表。mode14/20旁路该排列。

[独立机会模型](probe.py)从原全帧native source逐K/P/T重建事件，并重算每类计数、首触、读写和packed/scalar退休。source_blocks仅指实际进入计数的更新块；retire_blocks指实际退休读块；退休乘法总数按每T的P-pair及高计数保护逐项计算。

## 资源、验证和判断

21只增加40bit配置状态，组合源bit选择与输出逆映射。既有8×480×32bit psum仍在Q1借前160行共5120B，独立count数组仍为零；八银行各一个地址、一读或一写，不把不同时钟拍的读写当双口。原8bit分段加法、signed19×13乘法、13bit负借位修正、高计数>127标量退休和类频次>255的direct63规则不变。[资源合同](resource_contract.json)

本次重配同时降低计数搬运bit：原64的32bit银行读/写各337,038→269,604次，即各1,348,152→1,078,416B；新增64各415,438→339,202次，即各1,661,752→1,356,808B。这里相对mode20字宽没有改变。原19→20曾因20bit变32bit而增加字节，两个对照不能混称。以上访问账不证明能耗降低，额外mux也尚无物理时序证据。

23fixture×3模式×有无背压×重复命令=276命令，包括原22角落与新T唯一向量签名，验证源内部排列和最终逆映射。原255/256界、零Q2、正负极值、密集和padding poison继续逐值检查。4tile两轮短流48命令和两套64tile各768命令都无reset跨tile运行、参数持久；每个输出按原gold的全部3840值检查，保持holding和输出地址顺序。原14/20小测与原流共720记录全字段复现。[小测核验](checks_small.json)、[短流核验](checks_short.json)、[原64核验](checks_held.json)、[新增64核验](checks_disjoint.json)

[独立核验器](verify_run.py)另从各fixture原source重建事件和Python整数raw，核对每个计数访问、退休数、所有公开计数器、配置拍和状态和。RTL原有单银行互斥、计数不溢出、计数后全p覆盖再drain断言继续启用，并检查排列是0..9双射。结果JSON保留每条RTL命令完整计数记录；gold比较覆盖全部raw值。

这次明确发现是：导致端点状态税失败的路线里，已学得的局部顺序能服务另一种正计数表示，减少真实同银行事务，而无需恢复端点状态。它支持继续研究“重复权重计数域—分段psum存储—signed退休”的表示接口。当前新颖性仍3/10待证：排序局部性、静态范围证明、阶段复用和精确packing各自都不是首次；本次转接还可被普通布局/调度优化解释。更强raw四P没有消灭当前服务优势，但同资源反事实仍需将class表/mux预算给强控制后比较。参照[独立新颖性审阅](../../da_adapt/novelty_review.md)，不因百分比大小直接宣布或否定家族。
