# Count8与psum阶段复用：实际RTL结果

**删除独立6400B计数数组后，本固定接口的64个真实tile冷服务由983,682降到910,446拍，净省7.445%。** 相对上一轮pair19的953,300拍再省42,854拍（4.495%）。这是native双P13、208bit z口、完整raw输出的组件服务结果；原7.445%分母不含416bit z三P/四P、RR或I24。后续已补四P另一资源点比较及固定T重配，见文末，不称全预算最优或已证同面积。[最终检查](final_checks.json)

[PLAN](PLAN.md)先于RTL制定。本目录独占；原[pair_sparse](../pair_sparse/README.md)源码、metadata与记录保持只读，原19用原模块实际重跑参考。新模块同时保留mode14直接执行和mode20候选，不含独立count_mem。无训练、EDA、生产变更、commit或hash。

## 改了什么，为什么能改

完整C96/K864/R8/N96/P4/T10函数保持p=Q2@(Q1@g)，中间不舍入。AT-LIF {0,theta}的theta沿用既有吸W约定，RTL只读取native二值事件g。对固定R2类，任何位置/时间的计数不超过该类在864个K中的频次。因此[静态编译](prepare.py)仅将频次2..255的非零重复键编为class1..32；频次>255、单例及未选中键均direct63，零键0。没有将256截成0，也没有用source/gold决定是否计数。真实四组最大类频次122/158/106/123，所选类与原19相同。

Q1计数与Q2输出物化不重叠。候选将既有p_mem的8bank×480row×32bit中的前160行作为计数空间，共借用5120B：`row=slot*5+time_pair`，`bank=2*R2group+time_in_pair`，一个32bit字的四个byte是P0/P1/P2/P3。一次八银行服务覆盖四P×双T；八条原32bit ALU在bit8/16/24切carry更新计数。相比原10块扫描，现在每class仅5块，活动块仍由真实source门字产生。

计数首触用640bit有效位，每次start清零。未触行不读取p_mem，返回零后写入，故不依赖上次输出或SRAM批清零。完整计数退休结束后才允许进入Q2；Q2实际STORE覆盖全部480行，随后才DRAIN。零Q2、换源、换权和无reset运行均验证了该生命周期。[RTL](decomp_core.sv)

退休继续使用原八个signed19×13乘法器。每次选择一个空间P-pair，将a+2048b与signed3代表q相乘；a天然<=255，b<=127才双P恢复，否则沿用精确标量路径。q<0且a!=0时，在原13bit分段ALU高段carry-in补回借位；两组P-pair依次退休。没有四P同时乘法、额外宽ALU或额外z口。

## 资源账与限制

|项目|原19|新20|
|---|---|---|
|独立计数数组|6400B|0B|
|已有psum容量|15360B|15360B，其中5120B在Q1阶段计数|
|计数银行字/总服务宽度|20bit/160bit|32bit/既有psum256bit|
|count_live|1280bit|640bit|
|count_hold|160bit|256bit，多12B|
|class/代表表|2592B/96B|相同|
|ALU/乘法器|8×32bit／8×19×13|相同表达式数量|
|z容量/向量口|520B/208bit|相同|

psum每银行每拍只有一个地址、一次读或一次写。计数期四个R2组可有不同class地址，因此候选增加了真实银行地址/使能/数据选择mux；输出期则广播同一行。源码每银行只有一个p_mem读表达式和一个写表达式，读检查与后续写分拍。mode14也处于同一新模块并具有这些资源权限，但没有使用计数数据流；不能由此推导单臂综合等面积或最优资源使用。[完整资源合同](resource_contract.json)

访问次数与字节不能混淆。64流计数银行读由439,768降到337,038次，但字宽20→32，使读流量由1,099,420升到1,348,152B，写流量同样变化。周期减少来自事务合并和更宽既有端口，不代表搬运bit或能耗下降。物理SRAM映射、mux时序、Fmax和能耗尚未测量。

count8也是一个明确限制。频次255的边界保持计数，256全类退direct；例如`edge_low_255`核心14/19/20为23,182/12,810/10,250，`edge_low_256`为23,245/12,832/23,501。整类864的密集测试中新20强制direct，64,573拍，高于旧19的28,428及native14的63,709拍；额外864拍是MREAD控制税。功能精确不意味着各分布都更快。

## 验证与去留

共**1104条实际RTL命令、4,239,360个raw输出全部通过**。其中mode14/20各376条，旧19参考352条。包括22fixture（原20加混合255/256与零Q2）、四source两轮短流、64tile两轮流，以及16组第二命令完整重配source/Q1/Q2/class的序列；全部覆盖无/有source、weight、result背压。TB逐值检查3840个真实输出及holding、顺序、状态和；旧14/19小测160条、64流512条记录逐字段复现。

[独立核验](verify.py)从卷积坐标重建events、z和Python整数raw点积，验证每个类的完整频次、所有>255键direct、代表值、每个实际计数、首触轨迹、银行读写、退休支持、状态费用及配置拍数。Verilator内逐拍检查bank读写互斥、count地址<160、8bit不溢出、退休后不再访问count、全部480行覆盖后才drain。[检查汇总](verification.json)、[换权结果](reconfigure_checks.json)

结果支持保留这个针对原存储/循环成本的接口改进。新颖性仍按3/10待证：静态范围证明、阶段buffer复用、分段累计和精确packing均有先验，不能以aliasing首次提出命名。后续四P比较已补如下，但同面积和全部资源重新分配仍未建立；本轮不扩接RR/I24或启动EDA。

## 后续收口：固定T重配与强四P
