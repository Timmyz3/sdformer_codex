# 两路径实试：负迁移修复、完整消费者与存储取舍

2026-09-14。承接[上轮40类复审](../transfer_adapt_20260914/audit/REVIEW.md)，本轮继续实写RTL和测性能：**位平面原负迁移已在真实I24消费者后转正；计数融合接更强完整对照后只剩小正；Gustav失败前端已按实际稀疏格式修复。** 又把位平面从完整bitmap改成K16条带，做出了速度、存储与读取之间的实测取舍。当前仍没有TCAS-II强接收证据。

本轮实际新增/接入11个选项：位平面11/12/13/10四项、条带9/缓存8两项、count20/21完整双context接入两项、Gustav2/3/4三项。这是三类机制的消融和迁接，**不是11个新发明，也不等于全部idea已试完**。每条保留原迁移、修改后的布局及普通强控制；没有用加法数代替真实周期。

## 1. 原效果差→定位问题→适配后再测

原位平面模式15比原生慢，问题包括额外构造拍、空块扫描、读与执行串行。合拍构造、单项流水、实际live块遍历，再对onehot门字切回原生AAC，均已实现。之后接原FP32 identity→J20→I24，仍保持原T/P/N、舍入和饱和边界。

|同一单context、原生源→完整I24组件冷服务|128–191|4000–4063|
|---|---:|---:|
|原生双P13|1138971|1232921|
|原位平面15，失败控制|1249559|1314971|
|构造/流水/live13|1014578|1071032|
|再加onehot原生10|**978610**|**1029806**|

10比原生减少**14.0795%/16.4743%**，有source/weight/identity/输出BP时仍减少9.3780%/10.9516%。这是该组件从配置、实际源加载到完整I24退休的Verilator经过时间，不是整网或ASIC加速比。原始失败模式没有删除。

证据：[原生→raw的构造与费用](bitmap_pipeline/README.md)、[完整消费者接入](bitmap_consumer/README.md)。位平面额外有4320B bitmap、2592B系数副本、270B live和八棵pop16，不能用单一ALU数量相同冒充等面积。

## 4. Gustav：补回的是供数适配，旧双指针本来就存在

实际代码核查发现上一轮“尚未实现通用NRV∩W双指针”的缺口描述过期；旧RTL已经有真实压缩地址和交集，并接GP/NR4/PSN。原私人字节索引重读在近密W下很慢，不能归咎于整个Gustav家族。

新mode2实际加载tile共享bitmap，3付费读取头并旁路密W，4延迟到首个非空NRV再加载支持，复用旧游标补齐压缩地址。没有免费交集、免费flag或新增全前缀表。
