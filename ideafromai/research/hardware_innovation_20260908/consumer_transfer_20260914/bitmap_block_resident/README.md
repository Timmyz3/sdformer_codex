# K16驻留与系数复用：实际存储／服务交换

2026-09-14。以本轮已经转正的[完整位图执行器](../bitmap_pipeline/README.md)为A，继续按两个已测缺口做适配：完整4320B source bitmap太大；缩成条带后相同系数仍被反复读取。这里不改变网络、系数或gold，最终仍为完整K864/P4/T10/R8/N96的3840个raw值。

## 实际三个控制

- mode14：原生双P13，必要共同对照。
- mode9：只构造当前K16的40个16bit源字，共80B，live仅40bit。条带构造完后枚举实际非空P/T，读一个208bit z字，将选中的13bit半字符号扩展，执行原onehot AAC或三plane流水，再用保留的另一半拼接**完整208bit写回**。随后下一条带覆盖位图。不是保存全部位图再只缩报告里的字节数。
- mode8：再将该条带的三plane经真实W口预取，复用Q1阶段闲置的Q2 qblock前三行48B；多活动位每拍从其单128bit读路径供给原pop/ALU，单活动位仍读原Q1。Q2开始时VLOAD覆盖全部八行后才用，生命周期没有并行。没有增加数据数组或pop树。

每个非空K16条带付三拍预取槽，live plane受weight_allow背压；空plane槽也收费。缓存零plane不读不消费，实际enable与cache_reads计数一致。cache多位路径三拍对照9的四拍流水，因此收益由`多位P/T条带数−3×非空K16条带数`决定，不能仅看权重读取次数。

## 存储与端口

source bitmap从4320B降至80B（−98.148%），live从270B降至5B，主数组合计减少4505B；迭代pending54bit→40bit。系数plane副本2592B、八棵pop16仍保留，不能称已达到原生相同面积。原source1920B、Q1 2592B、Q2 1536B、z520B、psum15360B及Q2 qblock128B均在。mode8在该128B中借48B，没有新的缓存数组。

源构造仍需40路bit写，qblock也是原寄存器tile，不宣称任意SRAM宏支持。当前SV用一个qblock地址/128bit读表达式供原Q2乘法或缓存pop，读使能显式互斥；z每bank一个地址/读表达式，BASE_MAC只使能selected_rank，向量阶段使能全部八bank。BM_POS保留全字，BM_STORE写全字，不依赖免费半字写口。q_mem与bp_q单读表达式沿用父版。

8的路径增加cache读mux→pop→共享ALU组合深度；原乘法器数量仍8×19×13，ALU仍8×32，物理Fmax未测。容量变化和实际周期不是PPA结论。
