## 4. 接续执行：一个硬件主任务，一项算法诊断

### 硬件首先做：真实 G4 子集和查表 vs 普通二值 AAC

- **A**：完整二值 AAC 与 G4 子集和查表的共同整数函数。不能写已经完整复现了LUT-GEMM原论文。
- **B**：同一四源组多位发放造成重复发射；表方案省加法却扩大参数状态，现有计数器没有处理这个代价。
- **第一份 RTL**：C96→H8，真实packed源、signed8共同权重、signed10表项、足宽累加；真实构表、扫描、请求响应、输出提交。共同8加法通道、128-bit口、有限总状态和同背压；基线同样获得缓存/源重用权限。
- **必须测**：冷/热周期、建表/换块、源/权重/表字数、状态、stall及完整Y逐元素一致。先用真实源tile流，走完48个H8块后才称H384整层。
- **X怎么找**：若净收益存在，再查有限表容量下的分组/驻留或源模式共享增量；若失败，按实测瓶颈选一个改动。普通查表、缓存驻留本身不自动成为新贡献。
- **精度边界**：W8若来自新量化，就是独立部署候选，不能继承ep34浮点AEE。

### 第二件硬件融合：Scrooge 的独立完成能否兑现为请求取消

先修正余项数值界，保留完整live BN与PSN函数；不再用“独立判决MAC数之和”预测T10×H8 SIMD周期。要具体解决的是：部分判决已完成时，有限端口下能否释放执行位置、安排其他未完成工作，并负担输入选择/排队/输出恢复成本。

强对照包含同资源全深度PSN、共享组等待、现有门核、允许生产者侧直接判门的融合基线。新增bound乘法/比较资源也要计入，不以“免费重叠”规避面积。此项是候选X；未验证前不写论文创新已成立。

### 算法并行只做：固定batch训练回路诊断

从独立ep34副本和相同初始化出发，先比较旧AMP裁剪顺序与 `unscale→clip→step`，记录实际scale/norm/clip系数/θ更新。不保存回原checkpoint。若裁剪没触发，排除该解释；若触发，量出影响后再决定后续训练规则。

此后再做一对固定BN恢复与动态BN控制，预算/数据顺序/梯度规则一致，校准只用训练集。η=.004/.008/.016作为已有算法资产，捕获相同层真实请求，再选择哪一点更适合硬件。不是同时开三套全训。

## 5. 第二队列保留什么

| 方向 | 去留及重新进入条件 |
|---|---|
| Prosperity/Gustav/LoAS | 强底座与对照继续保留；原父行融合负结果不等于整个复用家族死亡。需要新的执行接口，避免重跑相同静态共享布局 |
| 有损剪枝/近静默/结构稀疏 | 继续保留；纠正死块证明后按有损候选评估，目标是物理事务/广播组减少，而非单点发放率 |
| MI-TRQR | 公开PSN算法实现可核；等训练回路干净后作为时间冗余训练探针，测真实T10事务，不从他人能量百分比套收益 |
| MM2IM/polyphase | decoder映射共同底座；比较已跳结构零的执行器，再找cropped输出/累加驻留等剩余洞 |
| θ-fold | 合法编译使能，逐消费者导出；不单独当标题，不把连续PSN算术也叫二值 |
| lifting/原证书核 | 保留实现与已测同资源结果，当前增量和新颖性不足以优先占标题；不再用节点数代周期 |
| 注意力替换/三元warm-start | 当前不抢上述工作；已有负结果只约束被试配置，后续新接口另行定义质量身份 |

下一阶段达到可评审的成果应是一张**实际RTL净服务/状态/流量表**，配匹配质量结果和相对先验的差分句；不会把本次审阅发现的问题包装成硬件创新，也不会将paper列表长等同于创新证据。
