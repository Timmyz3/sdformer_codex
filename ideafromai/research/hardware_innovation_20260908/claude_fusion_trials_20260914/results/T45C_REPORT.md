## 1. T45c-1：全网判决有多软（成本 × 判决软度交叉表）

**动机**：C1 在门路上做的事本质是"用未读比特的可达集给出剩余不确定度再早停"。
这种机制的成本由**判决离阈值多近**决定。如果全网判决都很软，就说明还有别的门路值得做同类机制；
都很干脆，就说明证书便宜、没有第二个 `fc1`。

**数据**：`m1458_..._unified_hardware_capture_s40_r1_20260831/atlif_activity.json`
（93 个 ATLIF neuron，40 样本，与 ep34 checkpoint 同身份），
字段定义源码 `runtime_profile_nts11_hardware_p0_de881269.py:818-821`
（`margin_abs_le_1_K = (h_seq − threshold).abs() ≤ 1/K 的样本数`）。

**口径**：`margin_abs_le_1_K / quant_sample_events` 是"**所有**膜电位样本"里近阈值的比例，
**不是**"可省 SOP 的比例"。本表把它当**判决软度信号**用，并同时给
`r_K = f_K / activity`（近阈值样本数 ÷ 脉冲数）。

`t45c_margin_cost.py` → `results/t45c_margin_cost.json`：

| 超级组 | SOP(G) | SOP% | f1/16 | f1/32 | f1/64 | f1/128 |
|---|---:|---:|---:|---:|---:|---:|
| encoder.swin3d | 17.856 | 31.97% | 0.012 | 0.006 | 0.003 | 0.001 |
| frontend.patch_embed | 16.288 | 29.16% | 0.008 | 0.004 | 0.002 | 0.001 |
| decoder | 15.291 | 27.38% | 0.015 | 0.008 | 0.004 | 0.002 |
| bottleneck | 6.400 | 11.46% | 0.016 | 0.008 | 0.004 | 0.002 |
| pred | 0.020 | 0.04% | 0.009 | 0.004 | 0.002 | 0.001 |

逐 neuron 软度榜（前 14，全活跃）：`resblocks.1.sn1` f1/16 = 0.0181（r1/16 = 0.13）、
`decoders.3.sn` 0.0169（0.06）、`enc.layers.2/0.downsample.sn` 0.0163/0.0161（0.08）、
`resblocks.1.sn2` 0.0158（**0.21**）、`mlp.sn1` 一族 0.0140–0.0155（0.09–0.11）。

**结论（两条）**：

1. **全网判决都是干脆的**：近阈值样本占全部膜电位样本 ≤1.6%（f1/16），
   且**任何**活跃 neuron 的 `r1/16 ≤ 0.21`、`r1/64 ≤ 0.05`。即"落在阈值 ±1/K 内的样本"
   比脉冲本身还少一个量级 ⇒ 精确证书在这层很容易早停，**没有一处是判决特别软的硬骨头**。
2. **没有第二个 fc1**：C1 挂的那批 `mlp.sn1` neuron（f1/16 0.0140–0.0155）
   恰好是全网**最软**的那一档。也就是说网络其余部分对同类机制只会更便宜，
   不存在"另一个值得专门为它设计机制的决策群"。供给轴的余量基本已被 C1 吃干净。

顺带确认：唯一"无 neuron 可挂"的组是 `frontend.patch_embed.head.conv`（修正后 0.7035G）——
它的输入是连续 voxel，不是脉冲。

### 2.1 `proj.conv_res` 的"代码 vs 实测矛盾"已解决（不是矛盾）

T45b 之后曾留了一条悬念：`Spiking_modules.py:819` 看着像 `conv_res` 和 `conv` 吃同一个 `x`，
但实测密度是 1.0 vs 0.056。**读全了就不矛盾**——`SpikingPEDLayer.forward`（`Spiking_modules.py:816-823`）：

```python
x_res = self.conv_res(x.flatten(0, 1))   # ← 吃 spike 之前的连续 x
x = self.sn(x)                           # ← 只有 conv 这一支被重新脉冲化
x = self.conv(x.flatten(0, 1))           # ← 吃 sn(x)，0/1 脉冲
x = (x + x_res)...
```

`sn` 只插在 `conv` 这一支上，所以两个算子**本来就该拿不同的张量**。
实测数据互相印证得极好：

- `conv_res` 是 **1×1** stride-2（macs 1.769G），`conv` 是 **3×3** stride-2（macs 15.925G），
  `15.925/1.769 = 9.0 = 3²/1²` ✓；
- `conv_res` 输入 `density 1.0 / binary01 0.0 / min −11.94 / absmax 15.42 / near_integer 9.6e-7`
  ⇒ 连续、有符号、多比特（累加膜电位）✓；
- `conv` 输入 `density 0.0564 / binary01 1.0 / max 1.0` ⇒ 干净脉冲 ✓。

**旁证**：生产树早就记过这件事——
`hw_autoresearch_nts07/system_simulator/scripts/analyze_m374_patch_zero_rf_constant_replay_fastkill.py:590-592`
把 `head.conv.0` 与 `proj.conv_res` 列为 `missing_nonbinary_cycles` 的 `missing_modules`，
并注明 `proj_conv_res_profile_input_activity ≈ 1`；`:357` 也用
`module.endswith("patch_embed.proj.conv")` 标出这是 PED shortcut 层。
即 T45c-3 独立复现了生产树已有的观察。

## 3. T45c-3：C1 天花板的"结构"判据 —— 不是效果弱，是没有作用对象

C1 的精确证书作用在**被逐位送达的多比特操作数**上。**如果操作数本身就是 0/1 脉冲，
就没有位平面可裁**，证书无从谈起。所以问题变成纯计数：全网活动加权 SOP 里
多大比例的操作数是**多比特**的。

判据：0/θ 型脉冲张量满足 `mean_abs == θ·density == max·density`，于是
`bulk = mean_abs / (max·density)`，`bulk≈1` ⇒ 所有非零值同一个常数 ⇒ 0/θ 脉冲；
`bulk<1` ⇒ 非零值有分布 ⇒ 真多比特。

> **注意 `input_sample_binary01_ratio` 不能直接拿来判**：它测"值落在 {0,1} 里的比例"，
> 但本模型的脉冲值 θ≈0.99991 而非 1.0，于是所有非零值都判"不是 1"，该指标退化成零占比
> `1−density`。resblocks 那几个 `binary01_ratio 0.87/0.85` 就是这么来的，
> 它们其实是干净的 0/1 脉冲（另有 payload 逐值核对作证：非零值全等于 0.99991065）。

结果（口径 B，分母 55.856G）：

| 类别 | 判据 | 算子 | SOP | 占全网 |
|---|---|---:|---:|---:|
| **真多比特** | bulk < 0.90 | 2 | 2.4730G | **4.43%** |
| 浅分布边界带 | 0.90 ≤ bulk < 0.99 | 10 | 0.7804G | 1.40% |
| 0/θ 脉冲 | bulk ≥ 0.99 | 67 | 52.60G | 94.17% |

再往下一层看**那 4.43% 是什么**：

| 算子 | macs(G) | 实测 r | SOP(G) | 输入性质 |
|---|---:|---:|---:|---|
| `patch_embed.head.conv.0` | 2.654 | 0.26506 | 0.7035 | 稀疏多比特（max 0.8426，近整数率 65%） |
| `patch_embed.proj.conv_res` | 1.769 | 1.00000 | 1.7695 | **稠密连续**（min −11.94，absmax 15.42） |

**两条结论**：

1. **真多比特的 2.473G 全部落在"网络边界上"**：`head.conv` 吃的是前端原始输入，
   `proj.conv_res` 吃的是 `residual_encoding` 的**连续残差**。二者都不是
   "生产者在时间上逐位送达给消费者的脉冲流"，因此 C1 的位平面证书**在结构上不适用**
   （没有"未读位"，也没有可退休的位平面序列）。
2. 剩下唯一的候选是 encoder 的 10 个 `attn.proj`（0.7804G = **1.40%**），
   其 `bulk` 0.956–0.983 说明非零值在 θ=0.8789 附近有 **2–4% 的浅摊开**——
   是"值域很窄的多比特"，最多摊出 2–4 个有效位，可裁空间本来就小。

> **所以 C1 的 17.1% 天花板是结构性的（操作数宽度），不是可调的（效果强弱）**：
> 全网 **94.17% 的 SOP 跑在 0/θ 操作数上**，那里根本没有位平面这个东西。
> 论文里的表述因此可以比"效率有限"强得多：**该机制在 94% 的网络上没有作用对象**。

## 4. T45c-4：抽头/通道轴上的"精确版"早退 —— 实测判负

**问什么**：既然位平面轴被堵死，退一步在**抽头/通道轴**上做同样的精确证书行不行？
即把 in_ch×k×k 个抽头按 |w| 降序喂进累加器，用剩余抽头的可达区间做证书，
单侧分离就锁定、跳过剩余抽头。这就是 **CGNet 通道前缀 / ICCD'24 "Early"（权重重要度早退）的精确版**。

**怎么测**：`t45c4_tap_axis_cert.py` 用 **真实权重**（ep34 checkpoint）+
**真实输入脉冲张量**（m1458 捕获里保留的 payload，逐位打包）在
bottleneck 的 768ch 3×3 卷积上精确递推：

```
lo = part + Σ_{j>m} min(0,w_j)    hi = part + Σ_{j>m} max(0,w_j)
锁定 ⟺ lo ≥ thr  或  hi < thr
```

阈值取"能复现该 neuron 实测发放率的经验分位数"（另设零阈值对照臂）。
两条判据都不需要 BN 建模：
**相对窗口判据**（阈值无关的**必要条件**）：`Σ_{j>m}|w_j| ≥ |acc|` 时任何阈值规则都无法锁定；
**带阈值判据**：如上。

结果（`results/t45c4_tap_axis_cert.json`，M = 768×9 = 6912 抽头，采样 48 个输出通道，
每通道 3000 个位置）：

| 量 | resblocks.0.conv1.0 | resblocks.1.conv1.0 |
|---|---:|---:|
| 输入密度 ρ（实测） | 0.12787 | 0.14549 |
| **预测下界 1−ρ** | 0.87213 | 0.85451 |
| **相对窗口锁定 m*/M** | **0.87906** | **0.88351** |
| 带阈值锁定率 | 1.000 | 1.000 |
| 带阈值 m*/M 均值 / 中位 | 0.74564 / 0.74060 | 0.76126 / 0.75434 |
| **锁步阵列（逐通道取 max）m*/M** | **0.99117** | **0.99327** |
| ⇒ 可省抽头（锁步） | **0.88%** | **0.67%** |
| ⇒ 可省抽头（oracle 逐位置） | 25.44% | 23.87% |
| 零阈值（定符号）均值 / 锁步 | 0.82910 / 0.99667 | 0.83578 / 0.99638 |
| σ(acc)/Σ\|w\| | 1.379e−2 | 1.342e−2 |
| 尾 L1 占比 @ m/M = 0.25/0.50/0.75/0.90/0.95 | 0.477/0.200/0.048/0.008/0.002 | 0.479/0.202/0.048/0.008/0.002 |

**为什么必然如此（根因，不是巧合）**：

- 相对窗口的下界**精确命中预测**（0.87906 vs 0.87213；0.88351 vs 0.85451，差 <1pp）：
  尾 L1 随 m 只**线性**收缩 `(M−m)·w̄`，而量的尺度 `|acc| ~ σ·√m` 只按 √m 增长 ⇒
  要 `Σ_{j>m}|w_j| < |acc|` 必须 `m/M ≳ 1−ρ`。**密度的倒数就是抽头轴证书的天花板**。
- σ(acc)/Σ|w| = 1.34–1.38e−2 独立给出同一答案：尾 L1 要降到该尺度需 m/M ≥ 0.986。
- 锁步阵列里 `m/M → 1` 是**必然**：一个通道的所有位置共用一条流水线，
  必须等**最慢的那个位置**锁定（逐通道取 max），3000 个位置里只要有一个不锁就全通道不锁。
  零阈值对照臂（0.9967）与带阈值臂（0.9912）一致 ⇒ **结论对阈值选择不敏感**。
- 对比 C1 的位平面轴：那里区间宽度按 `2^−j` **指数**收缩，所以十几个位平面就够。
  抽头轴是**线性**收缩，维度又只有 6912 —— 结构性劣势。

**判负及其延伸意义**：抽头轴精确证书在本网络上**在锁步阵列里可省 0.7–0.9%**，
即使在需要逐判决控制流（T37b/T1B 已判致命）的 oracle 逐位置设置下也才 24–25%。

这条把 `NEW_AXIS_SCREENING.md` 里的 **card 7（ICCD'24 "Early"）从"只作引用"升级为定量判负**，
理由从"有踩 operand-ordering 红线的风险"变成"实测可省 <1%，因为线性收缩 vs 指数收缩"。
**论文的完备性论证因此从 17.1% 扩到 100% 的网络。**

## 6. 下一步的正向方向（从判负里读出来）

三条判负把方向挤到"零"这件事上，而不是"位"：

1. **零插值/零抽头的数据流**：`decoder stride-2 deconv` 用相位分解（4 个 polyphase 子滤波器）
   等价地去掉零插值，硬拿 4×；因为操作数是二值，MAC 退化成 select ⇒ **0 DSP**。
   这是 §5 第 1 条里唯一还没做成 RTL 的部分（T44a/T44b 已铺垫）。
2. **frontend `residual_encoding`**：4×Conv2d(96→96,k=3)@240×320 = MAC 254.80G（全网 26.9%）
   但发放率只有 3.3–5.0% —— 典型的"spike-driven 省不动"结构。
   它的 gap 不在硬件而在**训练侧**（降分辨率/降通道），必须带精度约束在 sd5ai 上做。
3. **`proj.conv_res` 是被系统性低估的一块**：本次修正 +1.7122G（3.07% of 全网），
   输入稠密连续 ⇒ activity-weighted 口径下**拿不到任何脉冲红利**（r=1.0）。
   它和 `head.conv`（0.7035G）合计 4.43% 的操作数既非脉冲也非可裁位平面，
   是这个模型里唯一"两头都不占"的部分，值得单独端详（例如把连续残差也做成事件表示）。

## 7. 诚实的边界（不可外推的部分）

1. **`attn.proj` 的"多比特"是边界判断**。`bulk` 0.956–0.983 说明非零值在 θ=0.8789 附近有
   2–4% 的浅摊开，故本报告把它单列为"浅分布边界带"而不是并入真多比特。
   它占 1.40%，无论怎么归类都不动 §5 的结论。若将来能补 `sn2_q` 进 profiler，
   可把它变成硬数。
2. **`input_sample_binary01_ratio` 在本模型上失效**（θ≈0.99991 而非 1.0），
   本报告不用它做判据，改用 `bulk = mean_abs/(max·density)`；后者对所有干净脉冲算子
   都返回 1.0000（四位小数），判据本身是锐的。
3. **T45c-4 的阈值是代理**：用"能复现实测发放率的经验分位数"代替真实阈值+BN。
   零阈值对照臂给出同样结论（锁步 0.9967 vs 0.9912），所以结论对阈值不敏感。
4. **T45c-4 只测了 bottleneck 的两个 conv1**（payload 只对 `c1_conv3x3` /
   `decoder_convtranspose` 保留）。`frontend residual_encoding`（M = 96×9 = 864）
   与 decoder deconv 的抽头轴没有实测，**是外推**：由 `1−ρ` 判据预测前者 m/M ≳ 0.96、
   后者 m/M ≳ 0.74–0.87。外推方向与实测一致，但数字本身不是实测。
5. **T45c-4 只采样 48/768 个输出通道**，且 payload 只来自 sample s00（40 样本里 1 个）。
   T45c-2 显示逐样本方差很小（40 样本密度与 825 样本差 <5%），但这不等于抽头轴锁定点的
   方差不小；本报告只说"平均 m/M"，没有给跨样本置信区间。
6. **口径 B 是"若硬件支持跳过零插值抽头"的代价**，是设计目标不是既成事实。
   论文里 A/B 两个数都要给（A 101.585G / B 55.856G），并说明 B 需要什么样的数据流。
7. **修正后的绝对总量是 55.856G**，比 T45B 的 55.712G 高 0.144G（+0.26%），
   组成是 §2 的三处 frontend 修正。**组占比的三足鼎立结论不受影响。**
8. **不能宣称 decoder 是"最贵的"**，也不能再引用 T45 的 55.6%/60.2%（错因见 T45B §3）。
