且几乎全部是**计算侧稀疏 / 数量维**（少算多少个算子/多少 token），不是**位级供数轴**。
但精读有**两个正面产出**：

1. **独立先例（prior art）**：MICRO'25 的 **MCBP** 里的 **BGP**（MSB-first 渐进估计 +
   超过阈值即停）**就是 C1 的核心想法**，只是用启发式阈值 `θ=max−α·radius` 而我方是
   **精确区间证书**（更紧）、且我方停在**组判决**而非逐 score。这既**佐证了 C1 的方向**，
   又给出了干净的差分点（我们不是"首个"，我们是"**精确且可证**"的那个）。
2. **最邻近工作域**（CICC'26 28nm 光流加速器 #649）的"bit-width-aware"是**离线静态权重打包**，
   **不是**激活位宽早停 → 与我方机制**不重叠**；其评估表格与双口径能耗报告可直接作模板。

## 2. 两个正面产出（论文可用）

### 2.1 MCBP 的 BGP = C1 的独立先例 → 改写"novelty"叙事

MCBP（MICRO'25, §III-C "Bit-wise Progressive …"）在**注意力分数**上做
"MSB-first 逐位渐进估计，超过可行 top-k 阈值 θ = max(A) − α·radius 即停"。
这与 C1 **同构**（MSB-first 位串 + 阈值早停）。差异有且仅有两条，且都是**对我方有利**的：

| 维度 | MCBP BGP | 我方 C1 |
|---|---|---|
| 停止判据 | 启发式半径 `α·radius` | **精确区间证书**（`Vmin/Vmax`，含未读低位上界） |
| 紧性 | 无紧性声明 | **已证：对该信息集不存在更紧的精确界**（T27/T28） |
| 遍历序 | MSB-first（未证明最优） | **已证：MSB-first 是唯一最速收缩序**（T27） |
| 粒度 | 逐 score | **组判决**（10 判决共享证书） |
| 数值保证 | 近似（有 α 旋钮） | **零数值差**（RTL 逐位对齐） |

⇒ 论文的措辞应从"首次提出"改为：**"MSB-first 渐进早停已被独立提出；本工作的贡献是
把启发式早停替换为可证紧的精确证书，并证明其遍历序最优、数值零差"**。这比"首个"更稳、
也更符合 T23 总结的 TCAS-II 合法技巧（消融阶梯 + 盈亏平衡不等式）。

### 2.2 CICC'26 光流加速器（#649）= 最邻近工作域 → 差分点 + 方法学模板

- **差分点（可直接写进 related work）**：它的 "Bit-Width-Aware Compression" 是
  **离线静态权重分组最小位宽 + Non-Zero-Map 位图**，**完全不碰激活**、无运行时位宽决策、
  无界、无证书。而它宣称的 "speculation" 是阈值式（θ_ch）且**实测 +0.03 AEE** 的近似损失。
  ⇒ "事件域光流加速器早已做冗余削减"这一事实**削弱不了** C1；C1 的精确证书 / 紧性定理 /
  MSB-first 最优性 / 零差，在该文中**全部缺席**。另注：其 SNN 激活是 **1-bit spike**，
  "多比特激活的位平面早停"在其数据流里**根本不出现**——这正是我方的问题设定。
- **可抄的方法学**：① 表 I 式**逐子数据集消融表**（基线 AEE / 加特性后 AEE / 退化量 /
  冗余 % / ops 或 EMA 削减 / 能耗 / 时延）；② **双口径能耗**（纯计算 vs 含 EMA，明确 pJ/bit）；
  ③ Fig.9 式**级联瀑布图**把节省归因到 weight/FMap/cache/Psum（对应我方"证书开销 vs 节省"）。
  **不抄**：其表 II 把已有 ASIC 归一到各自电压比——软性 apples-to-oranges（T23 已列为"不用"）。

### T37b：门 3 的 2.857× 是**序统计量**，不是新轴（重要否证）

门 3 的 2.857× 看似是"某个输出时间步恒难 → 训练侧均衡 margin 可省 ~66% 供数"的巨大头寸。
方差分解把它判死：

| 方差来源 | 占比 | 含义 |
|---|---|---|
| 组效应 `a_g`（全局难度） | **0.3312** | 改不了（T30/T31 已证） |
| **判决效应 `b_t'`（某个 t' 恒难）** | **0.0064** | ← **可训练头寸只有 0.64%** |
| 残差（序统计量噪声） | **0.6624** | 不可利用 |

- `b_t'` 逐 t' 值：`[0.846, 1.006, 0.773, 0.687, 0.631, 0.952, 1.086, 0.851, 0.913, 0.916]`，
  **极差仅 0.455 平面**（均值 ~0.87）——没有任何一个输出时间步系统性更难。
- 三个供数口径：**实测 0.1224**（mean max = 2.938 平面）、组内齐平 oracle 0.0361、
  **iid 零假设 0.1497**。**实测 max 甚至低于 iid 重抽的 max**（2.938 < 3.592）
  ⇒ 组内最慢判决**不比随机抽样更慢**，纯属"10 个抽样的最大值"这个序统计量。

**⇒ 判定：组级共享的粒度税是 2.9×，但它是序统计量，不是可训练的不均衡。**
之所以无法利用：10 个判决共享同一条 Y lane 传输（Y 的 10 个 lane = T=10 时间步，
被 10 个判决共用）——逐判决停止意味着**把共享操作数重复发 10 次**；唯一出路是把
MAC 搬进生产者改发 V，那会推翻"消费者累积共享操作数、0 DSP、子集和 LUT"的整个架构。
这与 T1B 的"逐判决路径需要逐词归一化浮点供数"结论**同源**，此处给出其**代价的定量**。
