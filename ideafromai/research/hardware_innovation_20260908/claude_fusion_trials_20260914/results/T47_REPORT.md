# T47 报告：相位分解走路器的 RTL 与 PPA —— 4× 槽位、更小的面积、0 DSP

日期：2026-09-17　　state：**完成**（数字可直接进论文，边界见 §5）

T46-2 已经证明：零插值口径与相位分解**逐元素 0 误差**，且**非零乘法次数完全相同**
（都是 `active×9×Cout`）。既然算术量一模一样，那么两者的一切硬件差异**必然全在控制路径**。
T47 就是把这句话落成 RTL + PPA：

- 两版可综合走路器 `t47_deconv_z`（零插值）/ `t47_deconv_p`（相位分解），共用**逐字相同**的 MAC；
- Verilator 零差回放：三个用例下两版都必须和 Python 金标**逐元素相同**；
- Vivado out-of-context 综合：LUT / FF / DSP / BRAM / WNS。

---

## 1. 两版走路器（`t47_fused/t47_deconv_walker.sv`）

共同点：输出平稳（output-stationary），单 MAC 时分复用，`K=3,S=2,P=1,OP=1`，
输入是 1 bit 稀疏脉冲，权重是 int8，累加器 24 bit。乘法写成

```systemverilog
wire signed [ACCW-1:0] prod = (xbit && tap_ok) ? {{(ACCW-8){wdata[7]}}, wdata} : {ACCW{1'b0}};
```

即**二值操作数 ⇒ 乘法退化成 select**（这一点与相位分解无关，来自操作数是脉冲）。

**Z（零插值行走器）**：对每个输出位置枚举 3×3=9 个 `(kh,kw)` 槽位，
逆映射 `ih = (oh + P − kh) / S` 必须非负、能被 S 整除、且 `ih < H`：

```systemverilog
wire signed [16:0] nhs = $signed({1'b0,oh}) + 17'sd1 - $signed({1'b0,kh});
wire th_ok = (nhs >= 0) && (nhs[0] == 1'b0) && ((nhs >> 1) < H);
```
**9 个槽位里有 3/4 过不了整除判定** —— 这正是要量的浪费，而且它必须被逐槽位算出来。

**P（相位分解行走器）**：输出按相位优先 `(a,b,j,l)` 遍历，抽头表**静态**
（`a=0`→1 抽头 `kh=1`；`a=1`→2 抽头 `kh=0` 与 `kh=2`），地址是**直接偏移**：

```systemverilog
wire [15:0] dih = pa ? (ti == 0 ? 16'd1 : 16'd0) : 16'd0;
wire [15:0] ih  = {1'b0, jj} + {1'b0, dih};     // 无奇偶判定
wire        tap_ok = (ih < H) && (iw < W);      // 只剩越界判定
```
内层循环界 `nth = pa?2:1`、`ntw = pb?2:1` 是**编译期常数的函数**，所以阵列可以按相位专门化，
拿到完整的 4×（而不是用统一 4 抽头阵列只拿 2.25×，见 §4）。

## 2. 零差回放（`t47_fused/t47_verify.sh`）

规模 `H=4, W=5, CIN=4`（80 个输出元素，一个输出通道）。
权重取 `decoders.3.deconv.0` 第 0 个输出通道、真实实数里最活跃的 4 个输入通道（120/126/169/175），
量化到 int8（尺度 4.79e−4）；输入取该算子真实保留 payload 的第 0 时刻前 4×5 小块。
三个用例：**真实权重+真实脉冲**（活跃 38/80）、**全 1**（打满所有抽头与边界）、**随机 30%**（活跃 22/80）。

```
real : Z nslot=2880 mism=0 | P nslot=720 mism=0 | Z-vs-P mism=0   PASS
ones : Z nslot=2880 mism=0 | P nslot=720 mism=0 | Z-vs-P mism=0   PASS
rand : Z nslot=2880 mism=0 | P nslot=720 mism=0 | Z-vs-P mism=0   PASS
```

**80 个输出元素 × 3 个用例，两版都与金标逐元素相同，且两版互相同。**
槽位数 **2880 vs 720 = 4.000×**（金标独立算出 720，与 RTL 的 `nslot` 一致）。

## 3. PPA（`t47_fused/t47_synth.tcl` → `results/t47_ppa.json`）

器件 `xczu5ev-sfvc784-2-e`，`-mode out_of_context`，4ns 时钟预算（与 T25/T39/T41 同口径）。

| | **Z 零插值** | **P 相位分解** | 比 |
|---|---:|---:|---:|
| LUT as Logic | 219 | **155** | **1.413×** |
| CLB Registers | 170 | 172 | 0.99× |
| DSP | **0** | **0** | — |
| Block RAM | 0 | 0 | — |
| WNS @4ns | +1.303 ns | +1.227 ns | — |
| **抽头槽位 / 输入元素** | **36.0** | **9.0** | **4.000×** |
| 周期 / 输出元素（单 MAC） | 36 | 9 | 4.000× |

**三条读数**：

1. **槽位 4× 是架构性的，不是综合运气**。`nslot` 是计数器，Z 的控制器**架构上**就要枚举
   9 个 `(kh,kw)` × Cin，P 只枚举 `(1/2/2/4)` × Cin —— 综合器不可能把它优化掉。
2. **面积不但没变差，反而小 29%**。Z 要付模 2 判定 + 范围判定 + 3×3 计数器，P 只用直接偏移
   和越界判定。所以这不是"拿面积换吞吐"，而是**两轴同时赢**（面积 0.71×、周期 0.25×）。
3. **两版 DSP 都是 0**，直接坐实「二值操作数 ⇒ 乘法退化 select」。注意这条来自**操作数是脉冲**，
   不来自相位分解。

## 4. 与 §T46 的归因保持一致（最重要的一段）

T46 已经把话说死：`A/B ≡ 4` 是**对一个稠密引擎**说的；对已带零跳过的引擎，
**非零乘法次数完全不变**（都是 `active×9×Cout`）。T47 的 PPA 与这句话**完全自洽**：

- 这里量到的 4× 是**抽头槽位 / 发射周期**，不是乘法次数 —— 两版 RTL 执行的乘法
  `(xbit && tap_ok)` 次数**逐位相同**（都是 9·Cin 个有效抽头）。
- 所以论文里这一段的正确写法是：**相位分解把控制路径（槽位枚举 / 地址生成 / 有效判定）
  从 36 降到 9（4×），把输入缓冲从 4·Cin·H·W 降到 Cin·H·W（4×），
  而活动加权 SOP（55.856G）一个数都不动。** 它买到的是周期与控制面积，不是算力。
- **4× 需要阵列按相位专门化**（静态抽头数 1/2/2/4，编译期定死，很便宜）。
  若退而用统一 4 抽头阵列，槽位是 16 vs 36 ⇒ 只有 **2.25×**。两个数都要给。

## 5. 诚实的边界

1. **规模是玩具级**：`H=4,W=5,CIN=4`、单输出通道。**槽位比（36 vs 9）与规模无关**
   （它是"每输入元素"的计数，且已由金标独立复算），但 **LUT 比 1.413× 与规模有关**——
   真实 `Cin=1536` 时地址位宽变宽、计数器变长，两侧都会膨胀，比值会变。
   **不能把 1.413× 当成真实规模的面积比。**
2. **out-of-context、I/O 延时钉 0**：这里的 WNS（+1.303 / +1.227 ns）只说明"两版都轻松满足 4ns"，
   **不是频率声明**，也不代表真实设计里的关键路径。
3. **存储器在核外**（走路器只出地址，不出存储），所以 **4× 输入缓冲不在本表里**，
   仍是 T46 的解析结论（`4·Cin·H·W → Cin·H·W`）。BRAM 那一行 0 不代表真实设计是 0。
4. **单 MAC 的周期数**是"控制器必须枚举的槽位数"的代理。若换成并行阵列，4× 的成立条件见 §4
   （需要相位专门化；统一 4 抽头阵列只有 2.25×）。
5. **只测了 `decoders.3`**（输入通道 120/126/169/175）。四个转置卷积的 `(K,S,P,OP)` 完全相同，
   相位公式与 `Cout` 无关，所以这是结构性的；但报告里应写明"在一级上做的 RTL 对照"。
6. **权重是 int8 量化的**（尺度 4.79e−4，范围 [−67,127]）。这影响的是 MAC 位宽，不影响槽位普查。
7. **精度不受影响**：本脚本不涉及训练，只做整数等价性核对（逐元素 0 差）。

## 7. 一句话总结

**相位分解在硬件上是"白拿"的**：在同一块 FPGA、同一条 4ns 预算下，
它用 **155 LUT（比零插值少 29%）** 做到 **720 个抽头槽位（比零插值少 4×）**，
两版 **DSP 都是 0**，且 RTL 在金标上**逐元素 0 差**。
但它**不改任何一次有效乘法** —— 那 4× 属于控制路径与缓冲，不属于算力。
