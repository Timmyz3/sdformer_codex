## How the three binary columns are assigned

- **Binary?** `yes` = inter-layer activations that hardware actually multiplies are 0/1 (or ±1) spikes after any compile-time absorb. `no` = graded / analog / multi-bit activations on the synaptic path. `hybrid` = documented mix (e.g. dense non-binary input layer, then binary spikes). `algo-only` = no accelerator; column still states what the *model* emits.
- **Already Prosperity-after-absorb?** `yes` only if the paper (a) has compile-time absorb of a layer-shared \(\theta\) into \(W\), **and** (b) then runs **product-sparsity / Prosperity-class prefix-reuse** on that 0/1 GeMM. Prosperity itself is (b) without (a). Almost nothing is both.
- **Same-producer dual-consumer?** `yes` only if **one** producer tensor is consumed both as a **binary spike/gate** and as a **continuous residual / PED-like** value. Two engines on two different spike tensors is **not** this. SNN-ANN chip-split is **not** this. IAND that *deletes* residual is the opposite.

## Query 1 — AT-LIF absorb threshold into weights; inference binary spikes; accelerator

### Q1.1 Activity Pruning / AT-LIF — `NOT_LOCAL` — **algorithm, not accelerator**

- **Title:** Activity Pruning for Efficient Spiking Neural Networks  
- **Venue:** NeurIPS 2025 poster. OpenReview `zjOXZEXQKZ`. Authors: Tong Bu, Xinyu Shi, Zhaofei Yu. Primary: [neurips.cc/virtual/2025/poster/115023](https://neurips.cc/virtual/2025/poster/115023), [openreview.net/forum?id=zjOXZEXQKZ](https://openreview.net/forum?id=zjOXZEXQKZ).  
- **Binary?** Yes **at inference**, after absorb. Training output is \(o_i[t]=\theta_i\cdot H(m_i[t]-\theta_i)=\theta_i s_i[t]\in\{0,\theta_i\}\). OpenReview PDF: “this mechanism does not imply graded output spikes”; “During inference, when the thresholds are fixed, the scaling can be absorbed into the subsequent layer’s weights”. Rebuttal: all neurons in a layer share one \(\theta\), so the deployed model is 0/1 on event-driven hardware.  
- **Already Prosperity-after-absorb?** **No.** Absorb is stated as *compatibility* with neuromorphic hardware. There is no product-sparsity detector, prefix GeMM, or Prosperity datapath. No accelerator.  
- **Same-producer dual-consumer?** **No.** One spike path. Residual SNNs in the experiments are ordinary SNN residuals, not a continuous residual consumer of the same \(o\).

This is the **official AT-LIF absorb identity**. It licenses copying Prosperity/Gustav/FireFly on the spike GeMM. It does **not** already do that copy, and it is not optical-flow hardware.

### Q1.2 Training-free ANN–SNN conversion (channel-wise absorb) — `NOT_LOCAL` — **algorithm**

- **Same-producer dual-consumer?** **No.**

Same authors as Q1.1; conversion absorb, not AT-LIF activity pruning.

## Query 2 — hybrid binary spike + continuous residual datapath, SNN hardware 2025–2026

### Q2.1 SymbolicLight V1 — `NOT_LOCAL` — **closest algorithm dual-consumer; hardware not delivered**

- **Title:** SymbolicLight V1: Spike-Gated Dual-Path Language Modeling at High Encoder Spike Sparsity  
- **Venue:** arXiv:2605.21333 (cs.CL), submitted 20 May 2026, v3 7 Sep 2026. Ting Liu. [arxiv.org/abs/2605.21333](https://arxiv.org/abs/2605.21333).  
- **Binary?** Hybrid. Abstract: “couples **binary Leaky Integrate-and-Fire (LIF) dynamics with a continuous residual stream**.” Binary spikes gate where/when; continuous residual carries content. HTML: “Binary LIF spikes determine where and when computation occurs, while a continuous residual stream carries representational content.”  
- **Already Prosperity-after-absorb?** **No.** No product sparsity. V1 text: dense-hardware inference is slower than GPT-2; neuromorphic deploy is future work.  
- **Same-producer dual-consumer?** **Yes at the block, algorithmically.** Each block emits spikes (to decay / FFN-down) **and** updates a continuous residual. Not AT-LIF absorb; not optical flow; not a TCAS datapath.

### Q2.2 SymbolicLight V2 — `NOT_LOCAL` — **closest hardware hybrid; still not Prosperity-after-absorb OF**

- **Title:** SymbolicLight V2: Hybrid Neuromorphic Architecture and Sparse Execution for Low-Energy Language Inference  
- **Venue:** arXiv:2609.09772 (cs.CL), 9 Sep 2026. Ting Liu. [arxiv.org/abs/2609.09772](https://arxiv.org/abs/2609.09772), [HTML](https://arxiv.org/html/2609.09772). Alveo U50C FPGA 175 MHz + ARM integer.  
- **Binary?** Hybrid. V1 binary sites inherited; V2 **adds graded signed events** \(e_\theta(x)=\mathbf{1}[|x|\ge\theta]\,\mathrm{clip}(\mathrm{round}(x/\theta),-L,L)\) at extra projections. Table in HTML: “Event-consuming projections: Decay and FFN down” (binary) plus “Additionally FFN up and Q/K/V inputs” (graded). Continuous residual retained.  
- **Already Prosperity-after-absorb?** **No.** Sparse execution is **nonzero-event row gather** of weights, not Prosperity prefix-reuse of binary GeMM rows. Graded events are the opposite of absorb-to-0/1.  
- **Same-producer dual-consumer?** **Yes, language-block level.** HTML Fig. 1 / eqs (3)–(7): block writes \(s'\) (Heaviside) to the next decay path **and** \(c'\) to the next continuous residual. FPGA implements “sparse events coexist with recurrent state and a continuous residual.”  
- **Task mismatch:** 194M language model, not event-camera optical flow. Quality trails a same-budget dense control (authors state this).

This is the strongest 2026 hardware hit for “binary spike consumer + continuous residual consumer.” It is **not** a reskin of Prosperity-after-absorb, and it is **not** this OF net.

### Q2.3 DMP-SNN dual memory pathways — `NOT_LOCAL` — hardware, dual **memory**, not dual residual consumer

- **Title:** Algorithm–hardware co-design of neuromorphic networks with dual memory pathways  
- **Venue:** Nature Machine Intelligence, vol. 8, pp. 901–912, 16 Jun 2026. [nature.com/articles/s42256-026-01255-3](https://www.nature.com/articles/s42256-026-01255-3). 22FDX near-memory-compute, post-layout.  
- **Binary?** Fast path is binary spikes: \(I^l[k]=W_f s^{l-1}[k]\). Slow path is a low-dimensional continuous memory \(m^l\) with \(I_m^l[k]=W_m m^l[k]\). Input stage: AER binary spike addresses.  
- **Already Prosperity-after-absorb?** **No.**  
- **Same-producer dual-consumer?** **No as defined.** Two pathways (spike vs compressed memory current), not one AT-LIF producer feeding both a binary GeMM and a residual/PED tensor. Memory is a summary of spikes, not a residual shortcut of a continuous activation.

### Q2.4 FireFly v2 non-spike ops — `NOT_LOCAL` (FireFly-S is the local FireFly ID; v2 is earlier)

- **Title:** FireFly v2: Advancing Hardware Support for High-Performance Spiking Neural Network With a Spatiotemporal FPGA Accelerator  
- **Venue:** IEEE TCAD, vol. 43, no. 9, Sep 2024. arXiv:2309.16158. [IEEE 10478105](https://ieeexplore.ieee.org/document/10478105/).  
- **Binary?** Mostly yes; **first SNN FPGA they claim that also supports non-spike operations** used in SOTA SNN algorithms (the residual/integer problem). Systolic spike engine 500–600 MHz; on-the-fly spike processing, no Vmem storage in the spatiotemporal dataflow.

- **Same-producer dual-consumer?** **No.** Non-spike ops are extra operators so a residual *can be computed*, not two consumers of one AT-LIF \(o\).

### Q2.5 Spike-IAND-Former accelerator — `NOT_LOCAL` — **deletes residual**

- **Title:** Hardware Efficient Accelerator for Spiking Transformer With Reconfigurable Parallel Time Step Computing

## Query 3 — product sparsity × (optical flow OR event camera)

### Q3.1 Prosperity itself — `IN_LOCAL` (2503.03379)

- **Title:** Prosperity: Accelerating Spiking Neural Networks via Product Sparsity

## Verdict for round-2 fusion (facts, not a proposal)

1. **Absorb exists as an algorithm identity, not as an accelerator.** NeurIPS 2025 Activity Pruning (Q1.1) is the locked AT-LIF: \(\{0,\theta\}\) then \(\theta\) into next \(W\), deployed 0/1. Conversion papers (Q1.2, Q1.3) absorb thresholds/scales into \(W\) independently. **No accelerator paper implements “AT-LIF absorb then Prosperity.”**

2. **Prosperity / LoAS / FireFly\* remain complete priors on the post-absorb spike GeMM, and they have not been applied to optical flow.** Query 5 is a clean null. Copying them onto DSEC OF is not a reskin of an existing OF paper; the OF SNN chips that do exist (ASNA-Flow, SENECA FireNet) use other sparsity.

3. **Same-producer dual-consumer (binary spike + continuous residual) is almost empty in SNN hardware.** The only FPGA that *states* binary spike sites plus a continuous residual stream is **SymbolicLight V2** (language, graded events on extra projections, gather sparsity). FireFly v2 / Spike-driven Transformer / residual SCNN FPGAs add a residual *operator* on spike features. IAND accelerators **remove** residual. DATE 2411.15409 is dense-vs-sparse **layers**, not two consumers.

4. **Therefore a true increment X, if any, is not “invent product sparsity” and not “invent absorb.”** Those are taken. What this scan did **not** find, and so cannot be called already published, is: *after AT-LIF absorb, a Prosperity-class binary GeMM engine and a continuous residual/PED engine that share one producer, on an event-camera optical-flow SNN, in a TCAS-II-sized datapath.* That combination is a **gap in the retrieved literature**, not a claim that the combination works.

5. **CIM / analog / OpenROAD** hits (STT-BSNN, subthreshold SRAM-CIM SNN arXiv:2605.00319, ISSCC SNN CIM rows) are recorded as out of identity, not as X.
