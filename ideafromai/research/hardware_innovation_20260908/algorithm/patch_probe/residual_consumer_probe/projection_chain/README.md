源字 `[G64,K,P4]` 的 bit=t；head 的 3×3 中心为 `(2y,2x)`，r0/r1 为 `(y,x)`。实际卷积核分别为 `96×48×3×3`、两份 `96×96×3×3`。`K=C·diag(gain)·W` 的三个核全部非零。表中加权项含首次赋值，普通生成这些门的卷积、BN、PSN 全部继续存在。

新增项合计 **24,879,840**；原 C 有 **23,592,960 个连续乘积**。数量比 1.054545 不代表相同成本，AAC/MAC 不能直接相加或换算周期。r1 的源项更少而 NRV 更多，表明仅按发放数不能推供数优势。

NRV 是 source-ready 后的逻辑行请求：把非 anchor 的 p 位清零，`全T/P=Σ(g,k)[OR_p word≠0]`；另外两列分别只合并同 t 的 P 或同 p 的 T。四帧共 106,824 个全 T/P 非空行；普通逐行目录方案在静态 anchor 过滤后检查 **276,480 个 `(g,k)` 项**。这未包含实际目录字布局、打包、端口、零行扫描时序与 H8 消费者重放；每行只算一次要求完整 T 已知并能驻留／广播至全部输出消费者。单 P4 非空行峰值为 432/688/619，不能默认整包免费常驻，允许普通流式 NR4 分块。

halo 复用能省源读，不能自动省不同核偏移的 K 更新。按真实源坐标去重，anchor 的非零源项变为 86,612/79,734/63,513；同坐标门字全部相等。stem 在本组 anchor 间没有重叠收益，r0/r1 有约 16.81%/17.20% 的源项重复。实现这些复用需要行缓存、地址或散射支持；跨 P4 更大的共用范围尚未排程，不把独立坐标计数当 SRAM 请求数。

三 K 的 CPU 独立重构与已存 FP64 结果最大差 **2.49e−14**；但对 native 投影最大差 **0.001769745**、汇总 RMSE **0.000215630**。本次 matmul/cudnn 的 TF32 开关均为 True；不能仅凭开关断定每个核使用 TF32，更不能把代数重排当 native FP32 等价。用实际 BN 输入单独重构 stem BN，全域最大差仅 3.55e−6，源卷积 FP64 重构误差另存于结果中。

stem BN 仍使用本帧完整 T10/空间统计，动态 gain 已捕获；其 K 不能作为免费静态表。显式重算要每帧另付 9,216 次 gain 缩放及 3,981,312 个稠密矩阵产品，还存在统计屏障及源保留／重放。三个 K 共 207,360 个系数，是 C 的 22.5 倍；记录的 1,658,880 B 只是软件 FP64 容器，未来定点位宽尚未确定。固定 r0/r1 核可离线编译，但取数仍收费。

若普通对照采用 `C≈V96×R·UR×96`，把 U 前移后，稠密有效核假设下新增源项为 **259,165R 个 AAC 项**，末级 V 为 **245,760R 个连续产品**；普通不前移的低秩 U→V 为 **491,520R 个连续产品**。三源合并、偏置、动态 stem 系数与状态另付，未扫描 R、未作精度或速度承诺。这一捕获支持继续检验低秩普通对照；当前直接 96 路版本没有证明净硬件优势。
