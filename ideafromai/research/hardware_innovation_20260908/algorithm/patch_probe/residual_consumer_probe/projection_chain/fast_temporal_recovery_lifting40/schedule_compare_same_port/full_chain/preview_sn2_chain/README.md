# 源程序至真实双消费者：同一有限机器的局部执行证据

本轮把原来分开的source、preview、整数消费者和原生投影接到同一台真实载荷CPU机器。**局部端点功能通过；整帧Stage B仍NOT_CLOSED，没有新RTL/PPA或强接收结论。** AT-LIF为`{0,θ}`且静态θ可吸权；连续计算对应I24/PED。

完整执行顺序：原I24输入→完整编译源图→sn1→K864 preview U32/V32→固定BN1→非因果sn2→整数U16/F/BN2与残差→投影门及PED U32/V96→原生投影。sn2和投影门驻留同一状态SRAM直接交接；连续PED按当前direct-V控制写外存等待BN后合并。

## 数值边界

- 两学生合计source门387840位、sn2门278400位、投影门278400位，均与实际捕获零差。
- updated I24共278400值、连续PED共61440个q24值，均零差；四个整数矩阵的完整合法输入域48bit累加界写在结果中。每个必要RNE、sat24、BN2常量和残差加法都实际执行。
- preview Z与捕获数值一致；BN1有约1e-6级FP32差异，但上述窗口的sn2门不变。原生投影61440值中198值不同，最大绝对差3.0517578125e-5。不能宣称全浮点位等价或直接沿用新函数的valid825。
- 固定背压下门/整数仍零差。源整数不能放在FP32寄存仿真里截位；程序用FP64容器精确存放signed48，每个浮点操作显式按FP32舍入，不给硬件增加FP64算术。

## 已加强的共同分母

有效preview U32、V32及参数共124544B，能同时驻128KiB。V死尾16行是原有属性，旧粗表已经删除，不能重复当增量。

压缩U8/PoT-V从现有参数精确重建，单P2冷启动看似有利，**整窗反而更慢**：例如ordinary角落906626→1004524槽。解码/还原成本被整窗暴露，后续采用双方更快的展开FP32分母。只停这个解码布局，不否定低位宽表示。

普通24bit符号扩展与下一MAC预取给双方，跨64bit字读取继续计费，不作为新增机制。从sn1门开始、包含原生投影的ordinary角落在此底座为1825564槽；更早带额外向量解码的结果只是控制器消融。source接入后使用自然空间/C门字布局，NRV读数也随之变化，不能把表差当成旧源核槽数。

## 新idea的本轮验证

**F1，物理字共同删除：** 当前updated I24每P2为5760B/720个64bit字；门比较与PED U分别都需要720字，并集仍720，静态可删首次读取为0。[实际参数读义务](read_obligations.json)。只针对消费者不变的删除边界；训练改变联合依赖、不同布局和减少重复读取仍是不同接口。preview与PED两个潜变量缓冲不能假扮同一个物理源。

**F2，真正gate-only边界：** preview V/BN1只供sn2，正确门证明可避免V/PSN而不误删PED。按[先写的工单](LATENT_GATE_PROBE.md)只试一次V前L∞界；278400个门、1848个P2×H8组均无新证书命中。[结果](latent_gate_probe.json)。廉价界太松，停止这一界的RTL；不将它扩展成所有区间、可训练范围或有损共同完成都失败。

2. 此前数值验证过的“保留U32跨BN、延后V展开”尚未接入同一机器。它应作为双方共同对照，当前direct-V不是最强完整消费者控制。
3. 仍需跨算子条带的完整层排程，计halo、权重驻留和原I24重复输入。输入声明空间/T/C连续packed24，source读后留在外存、后继另付重读；未称整窗I24驻留。两个预选窗口不代表整帧吞吐。
4. Gustav式活动列共享只是已借部分。官方CPTB/NRV∩W/完整分块重叠未全部迁入，不能称完整Gustav，更没有相对它的实测优势。

原有valid825：ordinary1.219801338，lifting raw1.232979368，差+0.013178030，仍超相对+0.005。**不因局部7%启动成对恢复或生产RTL，也不全家淘汰lifting。** 下一步先闭动态BN/延后V的共同完成边界；新颖性第二队列保留F1训练后共同需求改变，但先写能消失的实际事务和强对照，不重复当前掩码OR/廉价界。
