## 1. 真实完成边界

链为 `I24 → source/sn1 → FP preview U32/V96 + BN1 → full T10 sn2 → integer residual → gate/continuous 两个消费者 → native projection → dynamic BN → final add`。

| 观察到的 BN | 实际配置 | 对电路的影响 |
|---|---|---|
| 预览 BN1 | eval，`track_running_stats=True` | 可用实际固定仿射参数 |
| 原生投影 BN | eval，`track_running_stats=False`，running mean/var 为空 | 每通道需等 **192,000** 个值；局部 tile 不能先定最终输出 |
| 投影 BN 输入 | `[10,96,120,160]` | 共 **18,432,000** FP32 值，原始张量 **73,728,000 B** |

`capture_reference.py` 没有替换原前向。它捕获完整 BN 输入/输出及观测到的全域均值方差。均值方差目前是数值检查用的参照，不能当硬件免费常量。

## 2. 数值链：哪些已经相等

同一既有首帧、两学生，各检查预先指定的角落和内部 **4×4 最终输出**，连同所需真实 halo、全 K864 和全部 T10；越界 padding 在 spike 后置零。

| 学生 / 输出块 | source/sn2/proj 门、updated I24、连续 q24 | 最终 FP32 输出最大差 |
|---|---:|---:|
| ordinary / corner | 全部零差 | 0.000158012 |
| ordinary / interior | 全部零差 | 0.000194788 |
| lifting / corner | 全部零差 | 0.000159621 |
| lifting / interior | 全部零差 | 0.000197172 |

每块连续出口检查 15,360 个值。原运行开启 cuDNN TF32；NumPy 的 TF32 乘数近似重建仍不等同其具体归约顺序。内部块预览 FP32 曾出现最大 **0.001953125** 的差异，但这四个块的门输出相同，不能外推为全量门等价。全域 BN 使用实际统计量重建时，相对 CUDA 输出最大差分别约 3.815e-6 / 5.722e-6。

结果见 `numerical_result.json`。`numerical_result_fp32_diagnostic.json` 保留未模拟 TF32 乘数时的诊断，两个文件不能混读成两次部署或 AEE 消融。

## 3. 完整帧粗服务账：定位 B，不充当最终周期表

共同资源：8 lane、96×48 bit RF/lane、128 KiB 状态 SRAM 的 1R64/1W64、128 KiB 系数 SRAM 的 1R256、32 B/5 槽共享 DMA；整数算术延迟 2、FP 算术延迟 4，II=1。原生投影按 H32 分成三块驻留，每块权重 110,592 B。程序、端口和精确跳零权限相同。

| FP 预览 + 非因果 sn2 | 1,005,355,863 | 947,579,079 | 48.93% |

范围是这一帧的指定残差链，不是整网份额。三源 full-K occurrences 与之前独立捕获一致：ordinary 为 36,173,704 / 5,928,264 / 1,339,274，lifting 为 29,979,277 / 4,636,838 / 1,279,971。

`serialized_frame_service.py` 是层间落存、行间排空的**标量预约构造**。它收费了 halo、目录构造/读取、连续载荷、DMA 的状态端口、原始 I 重读和 BN 的全域屏障，但仍有三个关键缺口：

1. BN 统计的 sum/square 和每通道 32 槽 finalizer 只是资源估计；实际浮点统计单元与归约顺序未闭合。
2. FP/整数消费者尚未全部执行逐地址、逐拍载荷；系数保持、供数预取与流水重叠需要具体控制。下面的小核已说明把各端口工作相加不能替代最强排程。
3. 当前为 GP 式公共供数构造，尚不能称完整 GustavSNN 的 Skip/Fetch/Exec、NRV∩W、分块及重叠均已复现；后继常量编译的最强控制也未全部迁完。

因此 **6.3981% 不是已通过同资源门的性能，也不是小于 10% 的全家淘汰证据**。此前 6.7% / 6.9% 是取数、写回费用补齐前的中间值，以本表为当前粗构造。

## 4. 最贵连续投影：已执行载荷的排程小核

`preview_v_schedule.py` 比较完整 K32/H96/P2/T10 的直接预取和显式 scratch 转置。系数已驻留；入口含实际输入 DMA 和逐向量 TF32 转换，终点为 H96 结果写入状态 SRAM。后继 BN 和外部输出 DMA 不在小核中。

| 共同控制 | always-ready 槽 | 固定状态端口背压槽 | always-ready SRAM 读 / 写词数 |
|---|---:|---:|---:|
| 原 TP,K 布局直接预取 | **10,396** | **13,362** | 7,680 / 1,280 |
| 先转置成 K,TP | 11,356 | 14,145 | 4,480 / 1,600 |

背压是预先固定的测试轨迹：32 槽中最后 8 槽暂停读、最后 4 槽暂停写；它不是实际后继捕获。两轴、两块、两个布局、两个背压场景都执行真实 RF/SRAM 值：相对相同顺序的 `fmaf` 参考零差，没有 RAW 或单写口冲突。RF 分配仍为 96 字，累加器使用 80 字；公共 64 B staging 峰值用 48 B；最多 4 个向量在途。系数/源响应延迟均为 1 槽。

四组真实输入相对原 CUDA 的 7,680 个输出中，只有 lifting 内部块的一个值相差 1.1921e-7。**这不是整个浮点链的等价证明。** 保留直接预取为共同控制；在该端点停止 scratch 转置，不把普通供数优化记入 X。小核与上一表完成边界不同，禁止直接相减或外推替换整帧分项。

## 5. BN 等待期的连续状态：一项精确共同改进

连续支路在 U32 后已有真实 signed24 RNE 边界。把 **V32→96、其 RNE、bias/sat 延后**到原生 BN 统计就绪，等待期间只存 U24。`consumer_lifetime.py` 对实际 updated I 执行 U、三字节有符号打包/读取、V 和 bias，四块均与实际连续出口零差。

| 整帧尺寸推导 | 先存 V96 | 延后展开，先存 U32 |
|---|---:|---:|
| 等待期间外部连续状态 | 55,296,000 B | 18,432,000 B |
| 写出 + 读回减少 | — | **73,728,000 B** |

这是普通低秩状态寿命优化，**两轴都享有，单独不是 X**。V 的算术没有删除。按 DMA 协议释放的 11,520,000 个总线占用槽也不是整链净节省；延后 V 的取数、写回、归一化和最终相加仍须连成共同时间线。
