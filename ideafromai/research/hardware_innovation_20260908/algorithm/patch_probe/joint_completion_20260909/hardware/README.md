# r1 完整链：真实请求与有限服务

2026-09-09。目标为 `sn1的θg → Conv1 → 固定BN1 → T10 PSN/预测 → θg → Conv2 → 固定BN2+identity`。已补完整空间、W2/BN2、边界窗口和实际接受位图，并完成16份完整帧的有限服务排程。**普通银行交错控制后，common3四帧合计仅少1.41%服务步，逐帧有赢有输；row34多8.10%。当前尚未形成足以支撑主机制的稳定完整链优势。** 这里是 CPU 需求和服务模型，不是 RTL 周期或 PPA；没有以 INT24 单元执行 FP32 Conv2。

## 完整帧需求与数值来源

[完整请求结果](full_frame_request_result.json)覆盖 row34/common3 两学生，各自 exact/conditional、各四帧，共16个完整 `T10×C96×240×320` 捕获。条件预测有损，因此分别计算其真实 Conv2。两个卷积的 FP32 W 各有82,944个非零系数、331,776 B；H8 向量256 bit。实际模块两侧θ为1仅是导出事实，接口仍保留θ。

|---|---:|---:|
| Conv1需要的k,t/H8向量使用 | 0.93688 | 0.69453 |
| Conv1组列范围源×W活项 | 0.94339 | 0.70071 |
| Conv2实际源×W活项 | 0.99471 | 0.99256 |

这是逻辑地址需求。[脚本](full_frame_requests.py)包含真实边界、`K=((c*3)+kh)*3+kw`、P4/H8和非零W交集。FP32 H32条带110,592 B可进128 KiB系数池，两Conv各付三趟源补给；没有沿用W8全层驻留口径。

每帧核了五个内部/边界5×5窗口。16份完整位图与窗口sn2门全部0差。直接FP64卷积与GPU FP32/TF32最大差为Conv1 `6.4612e-4`、Conv2 `7.0959e-4`；用捕获raw和真实参数重建BN1、BN2+identity最大差 `1.2679e-6`、`1.6882e-6`。这核对来源、θ、边界与消费者，**没有声称重排FP32算术位等价**。

## 有限资源服务

[模型](finite_frame_service.py)与[源流核心](finite_frame_core.cpp)使用有限队列和实际依赖。每个抽象步提供32路FP32条件加、8路FP32 FMA、8路比较；寄存文件读和依赖结果在步末可用。这是明确的乐观算术合同，不表示同步SRAM加FMA能在3 ns完成。

- 一个256-bit W读口、128 KiB系数池；冷W/参数、源、门图、identity/输出共用一个32B/5步DMA。W使用不等于片外重读。
- 公共32 KiB裸状态含两份P4×H32×T10 Y、普通六像素源字双缓冲、行门缓冲、预测参数、接受/输出位图及寄存器。32加法lane按H8串行；源字广播四个H8。不同Y bank上的Conv与PSN可重叠。字节和端口见JSON，不当SRAM面积。
- 每份新Y上下文显式付40次零向量写；它们在更长的源装入期间使用尚未参与计算的Y bank，未另藏每Y有效位。门图按P4/x顺序提交：年轻任务即使先完成，也留在已收费的输出位图中等待；只有部分字carry而无整字输出时仍付一次提交步。
- 候选保10Y，失败重算整行PSN，包括公共部分。实际逐lane接受位图决定相应p/H8是否还需Y；BN、参数读取、比较、重算和阶段等待均收费。
- 普通/候选都比较全T共取、time-major、各p独立选T及固定`bank=(p+t)%4,row=10*hctx+t`。后两者不增加四bank读写口，需要小选择器/地址控制；未用任意跨bank装包下界替代实现。
- Conv2比较时间字全T与直接时间平面/三行缓存两条一致布局。门图生成、halo、缓存补给、BN2、294.912 MB identity读和同大小结果写进入排程。完整门图是本实现的两层边界。
