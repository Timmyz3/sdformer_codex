# 实际源写入到完整 T10 门：本轮 RTL 结果

**完成的是 Gustav 适配底座的生产接口；seen-code 摘要没有形成新的性能增量。**

`gp_slice.sv` 实现四个 72×64bit 单读写口行为 RAM、提交长度、跨字 code3 提取、保持响应，以及现有 NRV∩W、两 tile×四 source ID、双 NR4 和完整 CSD/Acc24 T10 PSN。TB 只发送实际原始 packed 源字和响应实际地址的 W；不送 NRV、非空标志、S 或答案。上游把网络输入变成 packed code 的量化/编码器未实现，故这里的“生产”起点是 accepted packed word。

四臂使用相同声明状态、口数和 PSN：3 为 eager W metadata；4 为首次非空 NRV 后 lazy metadata；5 为完成 bank 的 seen-code∩live-decode 准入；6 为在生产写入上直接累积的单 bit nonempty 准入。6 的谓词不依赖 seen-code 状态。每代 decode 固定，所以 5/6 应等效，实测核对了这一点。它们仍共用测试网表，不构成不同方案的等面积/Fmax 比较。

**功能与协议。** Verilator 4.028 编译/运行通过，54 个完整 C384 切片：32 个真实 class/time 配对案例、16 个原有诊断、6 个本轮追加诊断。每个案例跑四臂×两种规约×两种背压×两种生产日历，共 **1728 次任务，552,960 个门判决**零差。独立 NumPy 与 C++ dense-dot 核 S、touched 和 T10，另核实际源读取、W 地址/字节、NR4 包、各消费者顺序和持有响应。

追加诊断包含 code0 映射非空、非零 code 映射空、最后 C383 才出现非空以及全空代次。所有任务连续换源/W/program，不靠清 RAM 内容隔离；本代提交长度阻止读旧字。实际运行 6,739,515 拍，发生 165,739 个 W 返回背压事件计数，NR4 占用峰值 2、W 同拍接受峰值 4。该运行总拍数是测试总量，不是某个网络的周期。

**访问与状态。** 每次四臂都写 288 个64bit源字、读288个源字，分别2304B；没有给摘要模式整bank跳读。新增 source RAM 为2304B；四个64bit响应寄存器32B；提交长度共28bit，seen共32bit，直接非空标志4bit，跨字carry共16bit，响应有效4bit。逐字最多检查22个code，不能把这段组合提取视为零面积。既有 PE/S/program/W metadata 状态各臂相同；没有 SRAM 宏综合或面积计数。

**裁决。** 保留完整生产/存储接口作为 A；停止“seen-code 摘要”独立 X。未尝试的逐行 prefix/rank 写入、提前消费和其他表示仍是不同接口，但本轮没有证据值得继续围绕摘要扫参。下一项应转向精读明确暴露的有限 PWP/公共结果供数问题。

本结果是有真实捕获输入的 **Verilator 组件仿真**，不是完整层、前级编码器、FC2/BN2/shortcut、VCS/DC/PT/Formality 或 PPA，也不是准入的“RTL加速比”。不得与旧外部源响应日历的周期直接相减。
