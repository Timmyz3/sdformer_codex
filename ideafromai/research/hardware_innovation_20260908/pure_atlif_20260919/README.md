# 当前 ep34 的纯递推 AT-LIF（去 PSN）试验

2026-09-19 开始，跨日继续。用户要求先解决神经元，并实际尝试不沿用 PSN。此目录只作隔离算法试验；原 ep34、third_party、生产硬件和投稿稿件未改。

## 已有修复与本轮问题

[前一阶段](../neuron_repair_20260919/README.md)已验证正确 AMP 次序 `unscale → clip → step`，定位 θ 梯度额外平均、Adam ε、低精度比较及 Q 布尔路径断梯度。修复/候选均在隔离入口；不是所有生产入口已更换，更不是已经得到更好的新模型。official+θ专用ε的64步 θ-only 完整 valid825 配对为 **1.198609554 → 1.201340636**，没有晋级。

本轮另问：是否删除 PSN 的 dense T×T 时间矩阵，采用官方递推 AT-LIF？这是架构改变，不能视作相同函数的硬件替代。

## 不是从未试过，但旧试验不是当前 ep34

2026-05 的 E2 已经使用官方 `mem=tau*mem+x[t]`、阈值发放、hard reset 的 AT-LIF，没有 PSN。历史 [实验汇总](../../../../SDformer/neuron_experiments/neuron_results_summary_20260506.md)记录旧协议 valid40：PSN baseline AEE **1.5848**；E2 full-pretrained **2.5128**；official-copy low-SOP epoch59 **3.7574**。这些来自旧汇总，本轮未重跑其 checkpoint，不与当前 ep34 数字拼表。

H3 的 `atlif_only` 指训练参数选择；H34 的 `pure_official` 指官方 binary/θ规则，它们仍含 PSN，不能算成另外两次去 PSN 成功。旧 E2 负结果没有排除当前骨干、正确训练回路及恢复方式下的可能性。

## 实现和迁移边界

[pure_atlif.py](pure_atlif.py)用新模块替换当前活路径神经元，模块参数只有 θ，没有 T×T weight 或 time bias：

```
u[t] = tau * v[t-1] + x[t]
y[t] = theta * 1[u[t] >= theta]
v[t] = (1 - y[t] / theta.detach()) * u[t]
```

每次调用膜从0开始。保留官方 reset 的反向路径；没有把 spike detach。tau 是衰减乘数；1.0 为官方默认的无泄漏特例，0.9 为另一官方使用值，不能把旧配置 `tau=2` 当相同含义。膜运算 FP32；匹配训练对照的 PSN 同样 FP32，卷积保留 AMP。

[test_recurrence.py](test_recurrence.py)直接抽取 E2 官方副本的实际源类作参考，T2/T10 × tau0.9/1.0 的前向、输入梯度、θ梯度均逐位相等；跨调用清零与首轴因果性通过。见 [RECURRENCE_TESTS.json](RECURRENCE_TESTS.json)。这不是全网精度测试。

[独立 Gustav 迁移审阅](GUSTAV_MIGRATION_REVIEW.md)：Gustav 的 GP、NRV、CPTB、局部膜状态更适合递推神经元；其论文 LIF 是 soft reset，迁移 AT-LIF 需明确改成 hard reset。动态 BN、T2 注意力和残差消费者仍有同步与保存费用，不能直接引用 Gustav 的加速比。

**T2 的现有首轴不保证是真正相邻时间，batch2 最小复现甚至跨样本。** 本轮保持原 layout，测的是沿已有轴递推；T10-only 用来隔离大部分时间矩阵替换。完整 chronological T2 路径需要另一独立实验，不能悄悄改分窗/逆变换再归因于神经元。当前 installer 注册的是81个图上活 AT-LIF，旧 checkpoint 仍含105个历史安装位置；两批12个死路径的历史计数不变。

## 当前 ep34 的实际结果

评测统一使用 valid825 中事先等间距选定的10帧、batch1、FP32、no_running BN、最终 flow[-1]、原尺度。不是 valid825 结果，不与其他报告的十帧直接混比。

| 臂 | 替换活模块 | 移除时间矩阵/偏置参数 | 零样本十帧 AEE | 活神经元按元素加权发放 |
|---|---:|---:|---:|---:|
| ep34 原 PSN+AT-LIF | 0 | 0 | 1.0450443 | 6.0525% |
| 仅 T10→递推 AT-LIF，tau1 | 45 | 4950 | 23.9346102 | 15.7164% |
| 全部活路径→递推 AT-LIF，tau1 | 81 | 5166 | 23.0469044 | 18.8854% |
| 全部活路径→递推 AT-LIF，tau0.9 | 81 | 5166 | 22.7134422 | 18.8743% |

原始逐帧与逐模块结果：[SCREEN.json](SCREEN.json)。明显损失说明“删矩阵直接用”不成立；没有用零样本结果杀掉可训练的递推 AT-LIF 家族。

[REMOVED_PSN.json](REMOVED_PSN.json)读取真实 ep34：45个T10矩阵严格上三角占矩阵平方能量 **42.2497%**，36个T2为 **25.5368%**（T2仅指已有轴）。该量不是精度损失比例，只说明原模型确有大量不能直接保留到因果递推中的连接。

运行时形状给出的活PSN标量乘积数代理：T10约 **11.70936G/帧**，T2约 **0.580608G/帧**。这是 dense 时间矩阵表达式的运算数，未采用常量编译、不代表执行周期；替换后还需计算膜更新、复位、状态读写和同步，禁止写成整网加速比。

## 短恢复与下一步

[run_trial.py](run_trial.py)重用前轮正常 H9 加载/数据/损失入口，在同一个原始 ep34 起点依次运行原 PSN 和全活路径纯 AT-LIF tau1。共同64个训练样本、batch1、同增强与RNG，端到端训练；共同θ专用ε1e−12、正确 AMP 裁剪、FP32神经元。原 PSN 时间 bias 的 weight decay 保持0，经[独立代码审阅](CODE_REVIEW.md)指出后在启动恢复前修正。

恢复已完成，见 [RECOVERY64.json](RECOVERY64.json)：

| 臂 | 训练前十帧AEE | 64次尝试后十帧AEE | 成功更新 | AMP跳过的0-based样本步 |
|---|---:|---:|---:|---|
| 原PSN匹配训练 | 1.0450443 | 1.0947175 | 64 | 无 |
| 全活路径纯递推AT-LIF，tau1 | 23.0469044 | 14.1457564 | 60 | 0、1、3、9 |

纯递推 loss scale 从8192退到512后稳定；后续梯度有限，按共同上限100裁剪。预算是相同64个数据尝试，**不是相同64次成功更新**，也不是两臂相同有效训练样本。下降证明这份实现可做恢复训练，距离原精度仍很大，当前没有可替换模型。没有完整825帧候选结果，不按十帧/60步判定最终可达到的精度。原模型共同恢复也略退化，不能把这套短训超参数称为优化后的公平训练上限。

官方递推每tick分别mean再累加θ梯度，与旧PSN一次全T mean的尺度不同；忠实保留这项规则，不偷偷除T或宣称两者θ有效步长完全相同。

下一步先独立核验并处理真正的T2时间轴，用原PSN布局对照隔离其精度影响；再做分阶段/蒸馏初始化的纯递推恢复和相同成功更新预算对照。不能把“原样删除全部时间权重”的负结果当作训练能力上限，也不能在当前精度下直接晋级硬件。取得可用精度后，再把递推接口接到 Gustav 的供数/局部膜状态对照，给动态BN和注意力同步单独计费。
