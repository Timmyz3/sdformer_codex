The executable contract is X24Q16 -> source PSN A16Q12 with integer thresholdQ28 -> exact nearest Hamming D code (lowest-index tie) or the whole-H384 response class -> RTL dictionary expansion -> 320 x 96 projected gate rows -> actual FC1 -> existing full temporal PSN -> Y24/U48/gates. Source and consumer thresholds are distinct. The backend A/tau/sign/constant fields are the existing fixed integer function, not a claim about the accuracy of this newly joined chain. W' is the already fixed integer response-class weight matrix; all four primary modes use the same W'. Original W may be checked separately and cannot be pooled with W'. No AEE is inherited.

The four modes are static64+direct FC1, static64+LUT10, D-entropy code graph with packed32/prefetch+LUT10, and D-entropy response-class graph with packed32/prefetch+LUT10. Static64 also receives the parent's ordinary next-source-X prefetch, using the same existing cache capacity. Parent source_classifier.sv and the previous support_fc1.sv are read-only instantiated modules. Ordinary graph reduction, fixed D-only variable order and prefetch are baseline mechanisms. This experiment measures the actual connection, not a new classifier algorithm or a multiplication of leaf speedups.

Only one external service is exposed: eight 128-bit banks, one accepted outstanding request per bank, shared by source, dictionary configuration and backend in phases. Global word addresses 0..6143 hold 32 X tasks; source local metadata addresses >=192 map to 5952+address; backend addresses map to 8192+address. The physical address pool is 16384 x 128bit = 256 KiB, identical for all modes, not the old 128 KiB pool. Initial external-to-pool population is outside this component model; every actual pool parameter/X/graph/coefficient read is counted. Graph images are static D/W' functions, not source-dependent hints.

The bridge first loads the real 12 dictionary words through the shared service, holds one 96x16-bit dictionary (192 B), then reads one selected entry per expansion cycle and writes one 16-bit group of the 320x96-bit gate memory (3840 B, six banks). It holds one group of ten code IDs (40 bit). All 1920 entry lookups/writes per joined tile are counted. Source calculation may proceed during these local writes, using the same source grant; no backend executes concurrently. Each backend H96 pass reads all 320 bridge rows. Four H96 blocks execute successively in the one backend, reusing its Y and temporal state. This is a legal additional bridge, not free P storage.

Source 10 parallel MAC units and backend 96 parallel MAC units are physically distinct and serially active: all arms have the same 106 units plus both modules' existing arithmetic/state. This does not establish the original 96-MAC area budget, equal timing, or an optimized shared arithmetic design. Source per-P cold parameter loads remain unchanged and charged; 32 source tasks use done/start handshakes without reset. The complete test reuses the same top instance across modes, input tiles, BP and repeat passes, with only initial reset.

Validation begins with one H96 and a real tile, then all H384 on the two training-frame x 32-position tiles and fixed zero/signed-extreme diagnostic inputs. C++ independently recomputes every source MAC, Hamming code/class, expanded gate, Y, U and final gate from X and static parameters; TB never supplies projected gates to the DUT. Bank request/response ownership, held requests, ordered output stability, exact accounting, and repeated execution are checked. Report full start-to-done service and first-X-request-to-last-gate separately, with per-stage words and cycles. No training, EDA, production edits or parameter sweep.

After the initial 112 joined commands passed, the bounded W'' input adaptation supplied by root is added without reselecting pairs. Both W' and W'' receive the stronger ordinary backend content-dedup control: exact-code and early-class source arms both select the existing support_fc1 mode4, compute the same local H96 content classes from their actual W, and load the real three class-map words per H96. Thus main code-vs-class comparisons include downstream ordinary dedup on both sides. The mode2 results remain an ablation. The only RTL addition is the backend selection bit; no backend implementation is altered. W'' is a separate function selected with frame0 training-source costs; its AEE is also unknown.
