# 响应类别按源生产成本选择：独立审阅

结论：这次适配修中了旧选择器的一个真实弱点，**源 RTL 的独立增量为约 2.53% / 2.70%（ready / BP）**。数学与选帧代码未见阻断错误；它目前是正但薄的接口证据，尚不能作为完整网络加速或独立创新标题。独立创新暂评 **3/10**，不是录用概率。本审阅只读取代码、既有结果并用 Python 3.12 聚合/比对，没有重跑 RTL、训练或改权重。

## 数学及数值合同

对每组字典行差 `δ = D[a]−D[b]`，在非零坐标有 `δ_j∈{−1,+1}`。令 `v_j=δ_j W[h,j]`，则要求两行完整 H384 响应相等恰好等价于 `Σv'_j=0`。复用的 `bounded_zero_sum` 先求盒约束连续投影，再按最小平方误差增量补齐整数余数；符号还原保持欧氏距离。因此这是逐输出通道、给定 pair 的精确有界整数投影，约束域是对称 **[−127,127]**，不能表述成遍历整个非对称 INT8 域的最优解。六组坐标互不重叠，后续组不会破坏前组等式。[实现](probe.py)、[投影函数](../../support_lut_execution_20260915/probe_response_projection.py)。

`canonical()` 按**全部 H384 整数响应逐值相同**建类，随后枚举每组全部 65,536 个原始门字校验类别图；类标号可替代 code 只对当前 W″ 消费函数成立。它不要求原始门字相同，也不允许跳过仍被其他消费者使用的原 g/U。响应范围 [−388,413] 满足原 INT10 表合同。Y/U 误差由实际投影后 g′ 与 W″ 重算，源的 A/X/τ、原始 X 输入、原 code 图和 nearest-code 规则不变。

一次 pair 约束可以顺带产生更多响应等式：实际只修改 g0–4 五组，g5 无正校准收益保留原值；最终每组类别数为 `[13,15,14,14,15,16]`。因此准确说法是“每组至多一项 pair 约束”，并非与旧六组修改**总约束数相同**。评分中强制 `b→a` 只预测两帧节省 34/20 个 T10 通道任务，最终 canonical 重建实际节省 48/45。选择器的分母是代理，不能称为对最终全部类别或物理周期的精确优化。

## 选择数据与实际增量

`probe.py` 的 `save`、`options` 和排序 key 只使用 frame0 的前 32 包；frame1 数字虽为每个候选记录，但不进入选择。原 D-only 熵序也没有使用 frame1 活动率。两帧均来自原训练缓存，frame1 只能称“未参与这次选择的训练探针”，不能称独立验证集。630 对是六组各 105 对的离线编译搜索，不是 630 个机制或训练试验。

局部门翻转采用旧验证首 tile 的固定整数 τ/gain；它既没有进入 pair 选择，也不是这两训练帧的动态 BN 统计。新旧两种 W 的局部误差可在该固定函数下比较，但不能据此宣称网络精度或复用旧 AEE。新 W″ 的平方改变量 2,752,395，较旧 W′ 的 2,638,069 增加 4.33%；两帧 Y 相对 RMSE 为 0.23471/0.20337（旧 0.23674/0.24077），门翻转 428/244（旧 391/253），每帧分母 122,880。没有单一局部指标全面支配，更没有误差预算证明。[数值结果](results.json)。

## 普通强控、先验与 X 边界

**整数 L2-only 控制已可闭合，无需另起机制。** 我从既有 630 行 [pair_choices.csv](pair_choices.csv) 逐组取实际整数平方改变量最小项，得到 `(4,6),(2,8),(9,15),(9,11),(3,5),(1,4)`，全部与旧连续 L2 选择恰好相同，总平方改变量也同为 2,638,069。新脚本的 `integer_nearest` 不按 saved jobs 筛选，使用同投影函数，故应与旧 W′ 逐值相同；根在补 W/节点/roots/canonical 的显式相等断言。该控制引用旧已跑记录，不声称又运行一次 2680 任务。最初担忧“同时改变 L2 精度与成本权重”的混淆在这组实数据上已经消除。

| 借入 A / 最近邻 | 已有覆盖 | 本次还能主张的有限增量 |
|---|---|---|
| [Bryant 1986](https://www.cs.cmu.edu/~bryant/pubdir/ieeetc86.pdf)，定义 5、§§2–3 | 固定变量序的相同子图共享、低/高分支相等时删除节点；当前 `Diagram` 就是这类普通约简 | 选择修改哪个消费者响应等式，让约简后少请求源通道；不能把 cofactor 相等或终止证书本身称新 |
| [The Greedy Miser](https://icml.cc/2012/papers/592.pdf)，§§3–5；[CSTC](https://arxiv.org/html/1210.2771v1)，§§3–4 | 将特征获得成本、路径成本及已获得特征复用纳入模型/树优化 | 当前将成本单位定为共享 T10 的一次真实通道生产，并通过改 W 的响应商类减少特征需要；“按成本选”或误差/收益比不是新方法 |
| [Bishop](https://arxiv.org/html/2505.12281v1)，§4.1 BSA、§5.3 TTB | 以执行束为粒度改变活动模式，配合时间共享执行；不是只数独立发放率 | 已读方法未建立本例的“非零 code 完整消费者响应等价→取消源生产”接口，不能说 Bishop 完全覆盖；本例也未迁入其完整训练和硬件体系 |

真正候选 X 是**改写消费者允许区分的函数，再将完整响应等价反推为共享源生产义务的删除**。本轮新增实现主要是离线 pair 选择、W″ 和类别表；整数投影、约简图与运行时预取均是已有 A。最强反对是：这很可能只是特征获得成本优化与普通函数商约简的一项实例，有限两帧、2.5–2.7% 源增量还不能证明可投稿的通用新机制。反过来，也不能由当前证据否定响应等价家族。

## 唯一优先后续接口

**冻结此次 W″，将 typed class 接入真实 H384 消费者，并以同一 W″ 的“exact-code 源图→普通响应内容 dedup”作强对照。** 两臂须共享参数容量、端口、128B 图缓存/预取权限；实际读写目录与响应、路由并收费，再独立核最终 Y/U/gates。这样只变“何时知道等价”，不把改权重和后端普通去重一起算作 X；原 W 与旧 W′ 留作质量/成本取舍点。当前源表已经证明的正增量足以支持这一步，但尚未提供这一整链同函数强控或新 W″ 的网络质量。若最终只剩普通 cofactor/去重即可解释的收益，就保留为成熟 A 的有效适配，不抬成新标题。
