## 2. 完整 A 应继承什么

| 强先验 | 已读机制及对照要求 | 当前不能冒称已经做完的部分 |
|---|---|---|
| Prosperity，HPCA’25 | 完整 product/subpattern 检测、部分和复用、缓存与回退 | 旧完整层融合负结果只约束当时布局；不能等同新接口均失败 |
| GustavSNN，HPCA’26 | in-situ GP、CPTB、NRV、Skip/Fetch/Exec、有限 L1D/GLB、同 ID 共享、稀疏权双指针 | 当前预约模型不是完整原架构；不能只把GP循环写出来就称“抄全” |
| LoAS / ExSpike | 前者需完整时间处理/校正/存储格式，后者需检测/APEC压缩/重建/冷启动 | 旧共享字典叶和公共部分和分别只覆盖其中一部分 |
| FABNet，MICRO’22 | 规则变换与配置/存储执行是强架构先验 | 一张蝶形图或学习提升因子不能单独立新意 |
| MFPSN，arXiv:2501.14490 | 无乘、通道差异及滑窗时序神经元是直接算法先验 | 其可训练结构不等于本地非因果T10与双消费者实现，也不能略掉当普通LIF比 |
| HiNM / VENOM / CRISP / FireFly-S | 剪枝结构、实际取数粒度和恢复流程需一并迁移 | 只用幅值打mask、只测稀疏率，未完成强控制 |
| da4ml / DeepShift / 通用融合 / 低秩寿命 | 普通对照同样有这些权限 | 相应节省不得独占为lifting的X |

GustavSNN 正文把 Prosperity 当 product-sparsity 对照，不是“在 Prosperity 内核上加 Gustav”。论文 §VII-B 已指出极稀权下 Skip 会成为瓶颈，并采用 NRV 与非零权索引双指针；因此 `NRV∩W` 本身也不是新的 X。该段必须作为 F1 的完整对照。

FABNet 与 MFPSN 的原始来源：[FABNet](https://arxiv.org/abs/2209.09570)、[MFPSN](https://arxiv.org/abs/2501.14490)。本地原文分别在 `../survey_ab_fusion_20260910/p0_txts/`；Gustav 镜像在 `../literature/GustavSNN_HPCA2026_public_mirror.txt`。这次未重新声称穷尽检索所有会议。

## 3. F1–F7：具体保留什么，为什么没晋级

这里的0–4为**主代理的增量潜力判断**，不是录用概率或独立专家共识：0=目前仅胶水；1=完整先验/普通优化；2=可检验增量但关键接口未闭；3=有跨强控制的初步证据；4=完整强证据。现有卡没有理由直接记4。

| 融合 | 潜力 | 当前决定与差分条件 |
|---|---:|---|
| F1 lifting活动 × 共同物理源剪枝 | 2 | **保留，第二队列优先。** 需要覆盖所有 kernel offset、邻接位置和 H 组消费者；单广播组零不能让原 sn1 源字停止读取。对普通学生做同预算相同剪枝，再比完整HiNM/窄稠密/2:4；新增部分必须超过一般活动加权剪枝。 |
| F2 半步检查点 × 共同门预测 | 2 | **保留预测接口。** 接受后具体取消什么要写清：source半步剩余算术可停，但预测非零门仍产生权请求；在proj门侧预测不能撤掉连续残差所需I。MP2没有训练预测器或量过这些依赖。 |
| F3 Prosperity虚拟节点 × lifting源图 | 2 | **保留未试表示，后排。** spike支持共享不自动适用于任意连续I；先给真实相等操作数/公共子式域，再与完整静态CSE比。旧G4失败不是本接口的证明。 |
| F4 局部合并 × 证书/回退 | 2 | **保留跨更早RNE的局部合并。** 最后五个门的精确cutoff已给两轴；X必须跨越额外舍入且证书、误判和回退都收费。整图合并失败只停整图布局。 |
| F5 Avalanche式寿命 | 1 | **作为共同控制推进。** 源RF峰值72→15都装得下96字，不构成当前容量优势；但本轮实际动态BN暴露了真正的长寿命连续状态，已验证延后V而保留U32精确省存储。它仍是普通低秩寿命优化。 |
| F6 训练clip × 严格完成界 | 2 | **保留训练资格，暂不启动。** 改clip会改函数，要对普通同clip控制与PACT等；不能继承现学生AEE。门完成仍需检查连续消费者。 |
| F7 NRV供数 × lifting组完成 | 2 | **保留部分时间词ready接口。** lifting混的是T，NRV行对应channel×kernel offset；两轴并不因改名就对齐。需要明确未完成T10词如何安全交接，并偿还共享算术/缓冲冲突。 |

这些分数针对目前的融合草案，不是给原论文打分。条件不满足时停止相应布局/控制器，不把整条先验家族删除。

## 4. 新旧 RTL 探针的边界

| 实际内容 | 能说明什么 | 还不能说明什么 |
|---|---|---|
| MP1 信用/仲裁 | 固定/RR/信用控制可表达 | 真实请求并集下有净吞吐 |
| MP2 接受/继续 | TB给定接受信号后能走不同状态路径 | 预测器便宜、AEE合格、能取消真实消费者工作 |
| MP3 keep_mask+双出口 | 给定mask后过滤和toy重构成立 | 真实r1物理源可删、所有halo消费者都覆盖 |
| MP4 接受/回退证书 | 控制互斥与路径长度 | 证书实际计算、真实RNE误差界、回退概率 |
| MP5 两种融合谓词 | 通用融合可以更强，必须给对照 | 真实source −13.56%被复现，或lifting独占此收益 |
| 旧OP-STW/PRRC/SCI | 实际为流差/事件阈值、预算计数、预供warp差值比较 | 完整因果运动估计、金字塔调度或SciFlow迁移 |
| 旧HBG/SMAM/ADP | 实际为幅值死区、计数、外部skip控制的普通乘加 | 完整幅度datapath压缩/双边bit调度 |

实际 HBG 源码还把 `g/p` 留为组合输出、`gp_valid` 延迟一拍；不能未经接口对齐就当生产包。其 int8 幅值和 EPS 也需明确量纲，不能直接套 θg 的浮点阈值。这里记录待补接口，不修改 Grok 的隔离树。

## 5. 对 Grok 裁决的两项纠正

1. **AT-LIF是二电平，支持编码直接适配。** `z=θg`，g可用bitmap/NRV编码，固定θ可折入下游W。不能因θ是实数就把LoAS/Prosperity/Gustav的发放支持机制或Motion-XOR支持叶全家判死。折后累加的是有效权重W'，并非丢弃θ。
2. **“θ不可折权，必须实值双轨”是已撤销的前提。** 当前数值helper已有 `U_conv2_theta`。任意逐事件int8载荷不属于当前AT-LIF身份；真正连续的PSN输入和残差支路仍需保留。

同样，卡片多为 A 的来源；“卡片本身不构成 X”是正常结论，不能据此说融合思想全部无效。
