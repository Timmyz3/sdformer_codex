## 四臂到底保留了什么

1. **密集原树。** 直接复用旧 `global_bn.cpp` 的 `Engine`，四条交错累加支路、256 值叶块、10 层 SRAM 树，先均值再中心化方差，原 rsqrt seed 与三步 Newton。新编译的密集臂重现旧统计、全部输出及完全相同服务槽数。
2. **保序 tag 压缩。** code0 来自实际完整 K864 输入：96 通道、9 个卷积位置及边缘 padding 上的投影门 OR。没有根据待算输出为零倒推免费标签。普通/提升分别 110365/110961 个位置被证明为全 H96 **+0**，保存剩余完整 96 路载荷。每个逻辑位置及原归约次序保留；方差仍逐位置执行原 SUB/FMA。
3. **默认省算。** 同一 tag 底座上省掉 +0 的均值加法；方差阶段用 12 个收费 SUB 生成 −μ 到 RF48–59，每个零事件仍按原次序执行 FMA。方差完成后这些 RF 再由原 `0×scale+bias` 浮点顺序生成的默认规范化向量覆盖。仍逐位置完成全部规范化输出的 SRAM 写、SRAM 读和外存传输，没有把默认输出或 PED 消费当免费。
4. **完整零叶复用。** μ 就绪后，用原 64 次 FMA、从 +0 开始生成每 H8 的完整默认支路。只在 256 个逻辑位置全部有 code0 证明时，将同一支路加载到四条累加支路，再走原树。同一预选帧的两学生分别命中 209/210 个完整叶。未改为 `count×μ²`，未重排非零项，也未扩展到任意混合支路。

## 端口、状态与输出

所有臂保持 128 KiB 状态、128 KiB 系数、96×8 RF、SR64/SW64/CR256。每 256 个位置读一份 32 B 标签，落 SRAM 地址 8192 后通过真实 SR64 取回，四次收费的解包/RF LOAD 将字节码放入 RF88–91；逐位置位提取也收费。完整零叶判断另收四个控制槽。没有额外不计费的标签缓存；tag 的 RF 和 32 B 状态来自共同容量。

方差阶段共用 −μ、后续默认规范化向量分时使用 RF48–59，+0 使用 RF95；零叶支路缓存只有 384 B，位于共同 SRAM 地址 12288。共用 −μ 生成收费 **12 槽**，每域额外准备支路缓存 ready 收费 **3948 槽**、固定背压收费 **3960 槽**；ordinary/lifting 复用额外读取 SRAM **321024/322560 B**，没有把加载当免费。固定背压沿用每 32 槽 SR 最后 8 槽、SW 最后 4 槽禁止。

密集外存三遍读取 221184000 B；所有压缩臂的普通/提升读取分别 **94115520/93428928 B**，已经包括三遍共 72000 B 标签。所有臂最终仍输出 **73728000 B**，系数冷填均 864 B。零叶复用不再减少外存字节，其增量来自复用保持原次序的完整浮点归约支路。

## 验证与诚实边界

最终 12 个完整域对照配置，每个均比较 **18,432,000 个规范化 FP32 位模式和 288 个统计 FP32 位模式**，相对密集原树差异全部为 0。ordinary 四臂的 ready/背压输出与统计也逐位相同。密集原树本身仍与 CUDA 有此前约 4e−6 的规范化差异；本次没有掩盖或消除这一数值合同差别。

这里输入的 native projection 全图载荷仍来自捕获。tag 的 K864 来源已核对，但未重放完整 native producer、未计其压缩流生成吞吐；这部分不能被称为整层闭链。连续 PED、最终 `BN + PED[p]` 相加和下一层均未执行。code0 不代表原始 I24 shortcut 或 PED 为零，也不能把当前默认规范化向量直接变成一个共享输出门字。

未执行“与 native projection 融合均值第一遍”的更强完整层控制，也未复现 Welford 或完整 BN 编译器工件。普通默认表达/BN 融合不构成 X；零叶复用虽已实际正增量，补强控制后仅余 0.47–0.55%，目前保留为公共底座或后续表示接口的对照，不能单独据此给强接收判断。没有用单次薄增量杀死其他接口。
