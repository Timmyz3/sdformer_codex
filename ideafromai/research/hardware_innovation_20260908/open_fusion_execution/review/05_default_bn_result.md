# default-BN 四臂独立结果审阅

2026-09-12；审阅者 `ped_bitplanes`。读取最新 README、summary、四臂 C++、驱动/汇总和复用的 `global_bn.cpp` Engine；另核 Finch、BNFF、FlexAcc 的相关原文章节和图。未修改实现、未重跑性能，独立复算计数关系，并直接比较现存输出文件。

**结论：实现结果成立；当前独立新颖性 4/10，保留为公共底座，不能据此立标题。** 评分依据是通用默认表示、常量传播和重复子图缓存的先验碰撞，不是用约 0.5% 的性能替代新颖性评分。尚未试的消费者表示接口可以保留。

## A 借入了什么，哪些尚未完整迁移

| 先验 | 当前已借入/碰撞 | 未完成部分与强对照 |
|---|---|---|
| Finch，OOPSLA 2025 | §3.2/§3.3、Table 4 明确支持可配置 fill、重复 Run、SparseScalar 的默认值特化；§2.1 的常量传播/循环外提覆盖共用 −μ、默认规范化的基本思想。[原文](https://commit.csail.mit.edu/papers/2025/Finch-OOPSLA-2025.pdf) | 本轮是手写 code0 控制，不是 Finch 编译器迁移。保序完整零叶缓存与原文示例的 `n×x` 重写不同，但重复子图 memoization 本身仍是通用手段；不能由“保持本归约树”推导全新编译机制。 |
| BNFF，MLSys 2019 | Fig.5/§4 已将统计和规范化拆分，再分别融进前后算子；还明确包含 `E[x²]−E[x]²` 的 mean/variance fusion。[原文](https://proceedings.mlsys.org/paper_files/paper/2019/file/9db64c20dee0011899dfdf200e61ef35-Paper.pdf) | 当前完整 BN 单算子执行没有 native projection 第一遍融合，也没把规范化融进真实后继。不应只写“Welford 未做”而漏掉该原作的单遍 sum/sumsq。 |
| FlexAcc，ISCAS 2025 | Fig.4/§III-B 的 FWBW1 对同次输入并行累积 sum 与 sumsq，FW2 再规范化。[作者全文](https://jiemingyin.github.io/docs/ISCAS2025_FlexAcc.pdf) | 没有迁入其完整 GPU/FPGA 供数与状态系统。图中明确是 `E[x²]−μ²`；正文相应一句有文字错误，不应据此判其仍为中心化两遍。原文硬件并行度不可免费搬来，也不能省略这个更强算法对照。 |

两种对照合同须分开：**保位轨**保持现有四路/256叶/中心化两遍及原浮点顺序；**允许改变舍入顺序轨**才可引入 sum/sumsq 或 Welford，并另付数值差异/后继精度检查。原两遍是当前合法的保位分母，但不是已证明最优 BN。不能通过锁定一棵自选树，把所有不同算术的强先验宣布“不适配”。

表为 **CPU 载荷服务槽**，引用自 [summary.json](../default_bn/summary.json)。四臂完整分项之和均与总数一致。初版漏提公共 `0−μ` 后出现的约 3.3% 已不适用；相对 dense 约 47.5% 是完整压缩/常量优化总效果，不能全归第四臂 X。

- **12 配置准确，但不是 12 帧。** 2 学生×4 臂 ready，加 ordinary×4 臂固定背压。两学生使用同一 `zurich_city_09_a_0001`；每配置 192000 个逻辑位置×96 通道，18,432,000 个输出和 288 个 μ/var/rsqrt 位模式。审阅独立按字节比对 24 个 output/stats 文件，全部等于相应 dense；不是新增独立样本。密集原树已有相对 CUDA 的约 4e−6 差异，本次没有变成 CUDA 位等价。
- **分母保留。** code0 来源是完整 K864 的门支持证明，压缩后每通道仍除以 192000。方差零位置仍贡献 `(−μ)²`；第四臂只重放从 +0 出发、原 64 次 FMA 生成的同一完整支路，四支路和上层树不改。未把 `count×μ²` 偷换进来。
- **外存字节成立。** dense 三遍 `3×192000×96×4=221184000 B`；ordinary 压缩为 `(192000−110365)×96×4×3+72000=94115520 B`，lifting 为 93428928 B。全部臂仍输出 73728000 B。这里三遍标签共 72000 B，不是另可减去的载荷。
- **第四臂没有额外外存收益。** 209/210 个完整零叶另读 `叶数×4支路×96×4=321024/322560 B` SRAM，支路缓存另写 384 B。tag 解码、解包、全叶判断及 RF 占用已收费；状态缓存来自共同 128 KiB。完整零叶的净收益仅位于方差阶段。

两处 README 小勘误：`原两帧` 应为“同一预选帧的两学生”；准备缓存 **3948 槽仅 ready，stress 为 3960**。数值表本身未受影响。

**边界仍实质性存在。** native projection 全域生产、完整 K 标签产生和打包吞吐没有重放；BN 输入压缩格式由 host 准备。连续 PED、最终 `BN+PED[p]` 和后继也没执行。因此只成立于已提供格式的完整 BN 域，不能称完整层/整网闭环，不能和原 4×4 窗口费用直接相加。

## 唯一保留的不同接口

不再扩大零叶长度或缓存扫参。保留 **默认表示跨规范化边界、直接接真实 `BN+PED[p]` 消费者** 这一项：默认位置传索引/code0 和已就绪的 C96 默认向量，非默认位置传载荷，直到逐位置残差相加才必要地展开；真实 PED 值、原舍入及背压都保留。当前第四臂约 55.6–57.2% 服务仍花在全量规范化/输出，这个接口针对的是实际剩余费用。

最强对照同时享有普通 BNFF 式规范化＋残差相加融合、相同默认表达和不物化中间量权限。只计算该对照之外的净服务、真实端口与状态收益；不能把“不写中间张量”重新命名成 X，更不能认为 code0 使 PED/I24 或最终门字相同。若等权限融合已吃完收益，则保留这套压缩实现作为底座，不制造新贡献句。该接口尚未执行，现有结果既不证明它成功，也不证伪它。
