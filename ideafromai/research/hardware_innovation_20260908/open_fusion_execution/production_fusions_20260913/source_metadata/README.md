# 真实门生产摘要 × 有序NRV：36例完成，保留公共底座

**完整局部链有正收益，但生产接口自身的增量很小。** source＋sn2两处生产时形成H4占用摘要，相对原目录省0.696%–4.234%服务；相对已经允许预取的普通扫描摘要，仅再省0.110%–0.136%。因此保留格式和跳过实现，不把“生产时生成摘要”作为TCAS-II标题，也不关闭生产顺序/结构训练家族。

范围是同一真实帧的corner/interior两个halo、dense两项/lifting两项/ordinary34三个各自不同数值函数。每个halo完整执行源I24输入与门生成→preview的完整K864→非因果sn2→Conv2/BN2/shortcut→projection门及连续PED，所有臂共同使用**普通P1保留Z立即消费**。它不是完整层或整网；native projection、全域动态BN及最终join不在这里。

## 成本落在哪里，究竟删了什么

以ordinary34/interior为例，原两个目录阶段254,314＋48,285，占本局部链14.02%。两摘要将它们降到181,792＋27,311；生产摘要新增7,676槽，最后净少85,820槽。连续算术、projection/PED、冷系数与外送均照旧执行，不能把少读门字称为少做PSN或省掉连续I24。

该例实际SR64读419,847→411,442（少67,240B），SW64写159,423→159,625（多1,616B），系数读写不变。普通扫描两摘要仍需416,290次SR读，但通过重叠，其总服务已接近生产摘要。所有行的SR/SW/CR/CW物理字节见summary.csv，逻辑24bit掩码不冒充24bit物理写。

每空间pixel一个24bit摘要，每位涵盖四通道×T10。source用既有H8门collector产生两位，sn2在两个实际P2位置分别更新；保留原门字写出。摘要实际占source 648/968B、sn2 512/648B，最多1,616B，来自原128KiB状态池。最大地址低于128KiB；无新增SRAM/RF阵列。

后继读取真实摘要并放入原geometry RF的空lane4/5；许可为几何有效位与H4摘要之交。缺失位置清零，防止继承前一组缓存值。原c-major K864次序、全部非零NRV、完整索引扫描控制保留；仅有许可的源字才真正请求，仅非空组才运行INRV。没有让金值或Python外部门图决定跳过。

普通扫描臂用**相同H8摘要操作**：两个真实SR64响应形成既有16B collector，与下一首字请求重叠；RF94结果就绪才写摘要。这将首轮未预取布局所呈现的约0.36%–0.48%“生产者增量”降到上述最终范围。双方共有完整CSE、P1留Z、端口重叠与常量编译权限。

## 原语功能已验证，面积/时序仍未验证

同96×8×48 RF、512×128源ROM、SR64/SW64/CR256、单issue及128KiB状态/系数池。source摘要RF94，sn2摘要RF93/94；算术、目录和消费者按各自生命周期复用。新摘要/许可微操作按两槽写回执行，增加控制逻辑，**同端口和数组容量不等于同面积、同频率**。

[隔离SV原语](../rtl_metadata_owned/README.md)经Verilator4.028功能通过，覆盖H8/H4摘要、几何许可、OR更新、两槽RF封装和输出背压保持。它只证明这个小接口的功能，未将完整36条CPU时间线迁到RTL，也没有DC/PT/Formality或ASIC PPA。

最终30例ready＋6例pressure均通过各自独立数值参考：Z、raw、BN1、sn2、updated、projection gate、PED零差；程序另外比较实际source门和两份摘要。相同帧在不同布局重复执行不算新增独立样本。`strong_suffix`新增的U观察不反馈硬件控制，原U/V的RNE、sat及bias次序保持。最终独立静态审阅附在原语README。

## 对A/B/X的裁决

A借的是Gustav式NRV供数、已有H4读合并、普通稀疏元数据与生产就绪接口；没有完整移植Gustav芯片。B是本链重复读取/解码本来为空的物理源字，实测在普通优化后仍存在。X试图把索引形成放到真实门commit处，但最强普通扫描已获得几乎全部服务收益，因此**这一增量不支持新标题**。

保留代码作共同执行选项；停止当前固定摘要控制的创新主张。未试的优先迭代、形成物理组支撑的训练、未完成时间词的接口仍开放；它们若执行，也要给普通格式相同权限。本轮不靠继续扫摘要粒度续命，下一具体融合转向压缩连续码到真实消费者的接口。
