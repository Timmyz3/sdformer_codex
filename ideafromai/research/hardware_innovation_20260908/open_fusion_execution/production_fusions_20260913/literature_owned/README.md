## 精确接口与实际取消的工作

部署量化函数是`xhat=sat24(Dg+c+s_t q)`。本次直接计算

`U xhat = s_t(Uq) + D(Ug) + c_t sum_h U_h + U[sat24(raw)-raw]`

所有项在**原U RNE前**相加，再保留原U sat24、V/RNE及bias/sat。这里D作用T轴、U作用C轴，允许整数和式换序；没有跨RNE搬移，也没有把PED U和另一组projection卷积当作同权。

十套参数的静态界覆盖每个T10门的全部1024码、每个signed8码范围，不依赖样本碰巧没饱和：重建输出在signed24内，故这些固定函数的饱和修正恒为零。最保守的两父完整因子累计绝对界为369,870,878,200与407,752,632,248，均小于2^47。代码保留一般饱和修正公式；另用一个故意越界的三值反例确认漏修正会错，不把反例算成实际命中。

对center/affine，原本每位置每通道的`c_t+s_t q`可以不产生：每4×4窗有15,360个连续I24源值，改为15,360个Q8码；常数项改为离线`Uc`，共10×24个signed48、1,440B，实际经CR读入30个现有RF。动态尺度只对U的24个输出做：每窗480次SIMD8 shift与480次pre-RNE基值add。这避免源域的15,360标量scale/base重建与46,080B预测/重建块的强制物化，但**未把这份理论物化账再从实测槽数扣一次**。

fixed零基值对照更强：`RNE(2^e Uq/2^eu)`精确合成`RNE(Uq/2^(eu-e))`，连额外scale shift也不发射。所有普通控制得到相同权限。

## 槽数真正从哪里来

以ordinary/corner affine为例，I24入口→Q8消费者内入口为100,928→96,578槽，净少4,350槽。

- 实际SR64读为19,200→15,360次，153,600→122,880B；去掉3,840次跨64bit字的第二次读取，每次请求+响应两槽，**少7,680槽**。逻辑输入体积虽然降66.7%，当前逐k收集布局的真实读流量仅降20%。
- 原source gather仍有3,072次RF写；MAC或零旁路机会仍为46,080槽。更高标量零率没有虚构成更多整指令跳过。
- Uc的冷fill、CR读取、30次RF装入等多450槽；480次scale、480次add及其等待多2,880槽。共多3,330槽，因此7,680−3,330=4,350。
- U24必须输出的11,520B完全相同，未消失。对于fixed零基值，合并scale/RNE后无这3,330槽附加项，净少7,680槽。

因此**单纯代数换序没有加速**：expanded24码＋因子对center/affine反而慢约3.30%。有效的是这一个不跨原舍入的压缩输入消费布局，收益可以完全归给普通表示与共同执行优化。

数值试验20例：pre-U累加76,800值、U24 76,800值、完整PED 307,200值全0差；另36次执行检查138,240个实际累加器及138,240个U24值全0差。每窗先对原保存continuous_q24核对U/V指数及bias，零差后再比较编码函数。两组检查有重叠，不把它们相加宣传成更多独立样本。

## 全D门预测尚未得到的东西

完整D(Ug)已通过同样整数/原舍入核对，但**没有执行计时**。它仍需独立U权重门投影，四窗至少有666–1,260个按实际激活计的AAC8操作，再有4,800个D×Ug向量产品（对角D为480个）。此处“至少”只针对当前直接展开，不是所有CSE图的数学下界；没有控制、索引、权重、拼接和等待费用。D需19位、这些窗Ug需18位，不能把其乘积冒充一拍现有signed16×24乘法。更宽乘法拆分和CSE必须另付。

没有证据表明full-D能比普通affine更省消费者槽，更不能把已有门或神经元全部当连续PED的替代。候选C1的gate专属X仍开放；**本次确认的是共同消费者接口可行**。

## 结论和后续边界

保留本次消费者内Q8入口作为普通强底座；停止“因子展开本身就是lifting或门预测新意”的主张，也停止把expanded24因子布局称为更快。下一可直接编码的候选是[ C2系数响应内W8解码](CANDIDATES.md)，它改变已失败RF84解包→staging布局的具体失败原因，仍需同函数普通控制。C3固定rank量化补偿保留低优先级，未训练。

当前计时起点免费提供各自输入表示，I24对照还免费得到重建值；编码、projection门生成、V、原生projection、全域动态BN和join均未计时。不把4.31%/7.61%外推到完整r1，ROM循环控制尚非编码后的微码收据，也无RTL/PPA。root对边界和cache48预算做了代码审阅；尚无第二个独立实现的完整调度复放。
