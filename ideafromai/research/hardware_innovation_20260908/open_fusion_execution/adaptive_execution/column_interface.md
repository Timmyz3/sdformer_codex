# 直接在 NRV 列流上寻找精确父关系

2026-09-12，隔离试验。B：刚完成的 full-K 版本先把 NRV 转成行位图，再逐对从 SRAM 找 subset；四窗口光匹配就花 21–35 万 CPU 服务槽。这是该控制器的问题。实际完整 K864 的可复用父很少，改变 detector 不能凭空增加复用。

最强对照包括原 GP，以及 Prosperity 原文的 **TCAM 一次 query 返回全部 subset**；不能把旧串行搜索称为完整原作的最佳 detector。借入的是 Prosperity 的 max-popcount / earliest-equal 父规则，Gustav 式列流 NRV，以及已有集合包含判定的反例淘汰方法。SPIDER 等 inclusion-dependency discovery 是算法近邻。

本次改接口：输入每个物理源 k 的 20 位活动 mask，维护 20×20 候选关系。child i 不活动时，删除本列活动的所有 parent；同时更新每行活动计数。完整 K 结束后按原规则选父，随后再次读取同一 NRV 并构造残差。无需建立20×864行位图。所有源都参与规则；空列对关系没有影响，由原 NRV 省略。

先写真实 RTL 叶并对实际列流核验，再把逐列输入、父输出、残差回放与 SRAM 端口计入原载荷模型。TCAM 面积和新 comparator / 候选矩阵面积均未映射；同端口/相同算术执行器不等于已证明同面积。若完整 K 的父复用仍不足，停这个挂点，并留下官方 K16 分块、较大 token 批量的未试接口；不把局部 K16 加法机会写成完整层收益。

这不是新集合代数，也不是完整 Prosperity 或 GustavSNN 复现。候选 X 只可能来自兼容现有 NRV 供数的 detector、残差格式与有限状态实现。必须实际胜过强 detector 的完整费用后才能成为贡献句。

## 本轮实际结果

[322次Verilator叶验证](column_rtl_results.json)已通过；154个真实组的两配置共99,628个残差与6,160次父/计数比较全部一致。无新增工艺面积或时序结论。

[同端口载荷执行](column_ready.json)进一步将detector输入搭在原NRV写上，用原NRV-select槽执行一拍残差过滤，支付20个父输出/表写。GP与新接口四窗口分别为405890→406288、591182→592222、350334→350280、523790→524788。值完全一致，服务净减少仅−0.19%～+0.015%。这修复了旧适配器的串行转换税，但完整K864下只有129/31/324/28次源发生可删。

停止本轮M20/full-K挂点，不据此否定原作K16分块。新RTL的720位主要状态之外仍有cursor/输出缓冲/父包缓存与组合逻辑；同端口和相同算术执行器不等于同面积。下一不同接口需包含原PR合法K16完整算子及更大M的实际状态/供数，不能外推本M20测量。
