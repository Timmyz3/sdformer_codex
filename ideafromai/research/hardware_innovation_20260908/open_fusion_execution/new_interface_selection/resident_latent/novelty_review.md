# 驻留潜变量独立新颖性审阅

2026-09-12，限本次 R24/R32 同资源驻留接口；不改实现、不使用 GPU。**结论：应当实现并保留正性能结果，但“选 rank 让 Z 与消费者部分和同时驻 RF、少落 SRAM”目前属于普通低秩融合分块，不能单独作为 X。** 本页评的是机制边界，不把性能或分数换成录用概率。

| 最贴近主源 / 本次核读范围 | 已有机制及本次边界 |
|---|---|
| [LoopTree，IEEE TCAS-AI 2024](https://arxiv.org/html/2409.13625v1)，§II-C、III、VI-F | 联合决定 tile 形状、顺序、每张量保留/重取/重算及容量；中间 tensor 留近端供后继、为容量拆空间/通道本来就在其映射空间。文中“rank”主要指张量维度，不能误称它完成了低秩训练，但给定 R24/R32 后的本次 blocking 可用这些普通选择表达。 |
| [TwinQuant，arXiv 2606.01556，2026 预印本](https://arxiv.org/html/2606.01556v1)，§4.3 | 明确将两阶段低秩 GEMM 放在片上；第一段 INT32 中间值在线再量化后供第二段，输出在寄存器累加，并与残差在单 epilogue 合并。故“低秩中间值不落全局存储”“中间量化边界仍保留”已有非常近先验；它不是本网 I24/RNE/96RF 的已迁实现。 |
| [LowRank-SSM，arXiv 2608.02954，2026 预印本](https://arxiv.org/html/2608.02954v1)，§2.2、4.1–4.2 | 直接指出两段 MVM 若不将 z 留片上并融合，低秩节省会被流水开销吞掉；其 z 使用 LUTRAM 双口缓冲，第二段分两路扩展，含 LR/FR 旁路。不能借它的多端口和 FPGA 吞吐替代本次同端口结果，但“rank+低秩供数电路+z 驻留”不是新组合。 |
| [Ultra Memory-Efficient On-FPGA Training of Transformers via Tensor-Compressed Optimization，TCAD 作者稿](https://web.ece.ucsb.edu/~zhengzhang/journals/2025-TCAD-on-FPGA-tensor-transformer.pdf)，§V-B.2、V-C；[作者列为2025录用](https://web.ece.ucsb.edu/~zhengzhang/pubs.htm) | 低秩张量收缩被拆成细粒度子收缩，后继立即使用前级小结果，只需 O(r) 中间缓冲；另计物理 BRAM 宽深/并行访问/分组浪费。它的对象含训练、张量链而非两矩阵 PED，但已把压缩表示与中间缓冲调度联合处理。 |

**本次不能漏的分母。** R24 的 P1/T10 有30个 Z 向量，H48 有60个 Y 向量；R32 的 P1/H32 同样能留40Z+40Y，均有合法96RF布局。因此不能写“R24首次令融合可行”，至多是少一轮 H 分块及相应服务。必须分别报告：同 R24 的原 P2 非驻 Z vs 驻 Z、同 R32 的原 P2 vs 最佳已知合法 P1/H32，再比两学生选定布局。P1 导致的权重重复取数、CR256对齐、源选择 lane mux 和 src+acc RF 两读/一次写回、原 U/V RNE/sat、尾块、潜变量最后消费者与输出背压全部计入。不能在P2分母中假设未取回的Z可用，也不能让R32强制落盘。R24 P1/H32可作为唯一因果诊断，非必需的新扫描。

**目前没有准备好的 X；一个尚未试、但需先证明的不同接口。** 将“仅服务连续 PED 的潜变量”改成**同时足以服务二值 gate 与连续 PED 的可训练共享表示**，目标是让原 I24 在两类消费者都可继续时释放，保住 P2 权重共享；不是只压 U/V 的 rank。对照必须给普通编译器相同表示、最佳静态融合、独立 gate 头、相同训练预算与 RNE；普通最后使用释放、V 块稀疏或更小 tile 单独都归入底座。只有新表示/执行协议确实改变了两个消费者的必要请求或完成边界，且在上述普通分母之外留下净服务，才可能形成候选 X。该接口尚无训练/精度/硬件证据，不能因当前驻 Z 正收益自动晋级，也不据此否定值得保留的普通实现。

本次只补核上述4篇相关方法，未迁其完整工件；两个2026条目按预印本处理。没有以检索未见同款96RF数值宣称首创。

**实际结果补注。** 两学生16个真实载荷配置数值均逐位一致。R24原P2→P1/H48：ready32,192→28,752（−10.686%），压力35,853→31,437（−12.317%）；R32同权限P1/H32：38,344→33,696（−12.122%）、42,285→35,482（−16.088%）。R32受益更大，结果支持将驻Z作为双方共同底座；“R24跨容量门槛才可融合”的独占X不成立，不必再扫H32参数。这里仍是CPU真实载荷服务模型，非RTL/PPA。上文共享潜空间接口在 projection_chain_prior_review.md 已有共同/私有源草图，不能再称首次提出；需先核其既有费用与真正未执行的表示差分。
