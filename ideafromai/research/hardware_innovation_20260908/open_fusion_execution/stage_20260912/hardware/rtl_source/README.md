# 结构化 T10 源：同一 RTL 执行两套真实程序

2026-09-12。已实现并运行 Verilator；不是 VCS/DC/PT/Formality 闭环，也不是完整消费者 RTL 或 ASIC PPA。

## 实际做了什么

`temporal_source.sv` 是同一个可编程整数源执行器。ordinary 的282条程序与 lifting 的216条程序都从既有 `two_stage_writeback` 导出，没有为 lifting 更换数据宽度、放宽端口或省掉35次中间 RNE/sat。

实际接口为96组×8 lane×signed48 RF、512×128指令ROM、两级移位/加减/舍入/比较流水；状态读为SR64请求/响应，状态写为SW64 ready/valid。每个T10/H8输入实际发30次SR64读，产生两次SW64门字写。两臂均支持相同常量编译；门方向、阈值、负号和舍入均来自原程序。RF为逻辑寄存器阵列，未映射 SRAM 宏。

两个学生的corner/interior各有972/1452个真实H8 tile。输入是原捕获signed24，保持非因果完整T10；参考输出是捕获的AT-LIF门字。两个学生同窗口的原I24输入已由集成模型逐值核对相同。

## 回放结果

| 窗口 | ordinary，ready周期 | lifting，ready周期 | 周期减少 |
|---|---:|---:|---:|
| corner | 483,084 | 398,520 | 17.505% |
| interior | 721,644 | 595,320 | 17.505% |

每tile对应497/410周期，包含本模块启动、SR64读取、流水及RF等待、门收集、两次SW64提交。**不包含上游外部DMA、程序配置或后继消费者。** 外部DMA和后继消费者在CPU模型内计费；一次性程序配置在两张表中都未计运行时费用，两表均假设固定驻留ROM。RTL测试先配置程序，ROM容量两边均8192B。上述周期不能直接代入另一个CPU槽模型，也不能把它称为整链17.5%加速。

共13个真实case：四窗口分别ready、固定压力、实测SW64等待时长回放，另加ordinary/interior集成压力trace。共检查31,991,424个RF标量写回及1,279,680个门位，零差异；重复模式不是新增样本。每一条load/addsub/norm/gate的RF值都与独立C++整数解释器比较，解释器输出也与真实捕获比较，避免只核对稀疏最终门而漏掉算术错误。

固定压力明确为：周期模32时SR64后8拍不接受、SW64后4拍不接受，读响应延迟1–3拍。它是协议压力测试，不是假造的网络负载。所有阻塞写均检查valid/address/data保持，两个SW64字按序接受。实测trace模式只重放每笔写的等待时长，未声称复现原模型绝对时间线或并发消费者；批缓存架构ready trace的实际等待为0。

另外两个定向case覆盖正负半整数ties-to-even、signed24两端饱和、正反阈值、常量门。结果在 `results.json`。lint无错误，唯一提示是128位ROM中预留的29位未使用。

## 新颖性与边界

移位加减、CSE、可编程RF、RNE和流水本身都是已有方法。此实现验证的候选对象是：**训练所得lifting时间结构，在真实I24、原舍入边界和相同源执行资源下仍有服务净减少。** 这还没有证明相对所有可学习结构化PSN的独占新意，也没有完成28nm物理结果。

完整局部链的收益应引用上一级同Machine表（约8%），其中还包含完整K864、非因果sn2、Conv2、BN2、rawI24及连续PED。全域动态BN和原生投影生产者仍未接入该表。8%的局部收益不能外推网络。

RTL还有额外的公共流水暂存：两组移位操作数、一级结果共144B，I24 gather24B，门收集16B，控制寄存器另计。它们不是从96RF中消失的面积；两种程序都使用同一份。指令ROM和RF的实际面积、频率、能耗均未测。

## 补试：更小活跃集是否只是原调度遗漏

为检验“lifting只用0–14通用RF、ordinary用到71”是否只是遍历次序造成，另写 `schedule_controls.py`，在**同一算术DAG**上分别按原门输出序和T0→T9顺序深度优先生成程序、按真实最后使用重新分配RF。节点数、所有移位/阈值/35次RNE、输入读次数均不变，不重训、不重算、不溢写。

| 编译程序 | 通用RF地址范围或重分配峰值 | ready周期/tile |
|---|---:|---:|
| ordinary原编译 | 地址0–71 | 497 |
| ordinary DFS原门序 | 峰值58 | 766 |
| ordinary DFS时间序 | 峰值60 | 764 |
| lifting原编译 | 地址0–14 | 410 |
| lifting两种DFS | 峰值16 | 648 |

门收集仍另用RF95。两新调度×两学生×两窗×两压力共16个RTL回放全部对原捕获和逐操作参考零差。DFS减小了ordinary地址范围，却增加相关指令连续出现导致的等待，不能拿慢调度替换主表的更强原编译来放大lifting收益。保留原编译；这两个固定控制未证明ordinary无法在16RF内通过重算/溢写或更好的调度执行，也未证明source/consumer交织有净收益。结果在 `schedule_controls.json`，属于后续资源接口的边界试验。
