# 阶段交叉审阅：真实进展成立，标题级 X 尚未闭合

审阅日期：2026-09-12。范围为本阶段 integrated/rank/mask CPU 执行、共同源 RTL、融合候选及 codec 一页结果。由同一团队内另一代理独立检查代码与产物；不是盲审、外部评审或真实录用概率判断。未改被审代码，未跑 GPU、综合或物理设计。算术与性能结论仅限列明范围。

**判断：阶段确实前进。** 已从分别收费的算子结果，推进到真实源门字在同一个 Machine 中驻留并服务完整局部双消费者；又新增可重放的共同源 RTL。当前支持“同资源、相同原始输入与局部计算范围下，两名已过 NB0 质量门的学生存在服务差异”。尚不支持整网加速、面积/功耗优势或标题级独有机制。

## 1. 同资源、同负载与原对照

- **原始输入公平。** 我直接比对导出的两臂 signed24 输入：corner 77,760 值、interior 116,160 值均逐值相同，见 [input_equality.json](input_equality.json)。T10 非因果、C96、K864、窗口/halo 不变；AT-LIF 的 `{0,theta}` 门及可折权合同没有被误写成任意幅度事件。
- **局部执行资源公平。** `integrated.py` 两臂使用同类 Machine、96×8×48 RF、128 KiB state/coef、SR64/SW64/CR256、8192 B ROM及同 CSE 权限。前级 124,544 B 与后级 44,096 B 系数确实依次 DMA 替换，未假装同时驻留。source/preview/consumer 串行错峰，因此 RF64..72 的目录缓存、RF80..88 几何寄存器与源程序重用没有同时占用冲突。
- **R24 对照合理。** `rank_fusion.py` 复制的是已执行 producer 的完整 Machine 状态；`consumer_ranked.py:20,50-54` 真正加载新系数并执行 rank24 循环，两个普通 R24 基底也同时给两学生。每窗均省 45,184 槽是同宽度的硬件费用结果，不能推断两个 R24 的输出或 AEE 相等。新 gold 由整数矩阵链独立算出，没有作为输入替代驻留门缓存。
- **“同负载”须限定到输入与任务范围。** 两学生的中间门、系数和输出不同；稀疏消费者实际工作量也不同。这在共同 NB0 质量约束下是合法算法比较，但不是同一中间 trace 的纯微架构比较。

| R32 窗口 | 总节省槽 | 源执行节省槽 | 后级节省槽 | 源占总节省 |
|---|---:|---:|---:|---:|
| corner | 164,070 | 84,564 | 79,506 | 51.54% |
| interior | 223,948 | 126,324 | 97,624 | 56.41% |

因此 7.784%/7.996% 应叫“两个学生的局部净服务差异”；其中约 44%–48% 来自 preview/Conv2 等后级活动差异。单独将源差额除以原总服务，分别是 4.012%/4.510%，这只是归因分解，也不是另一次实测加速。将约 8% 全归于少 101 条加减指令会过度归因。

**发现后已补：mask 原报告混入调度改变。** `integrated.py:21` 固定 `coalesced_scan`；`mask_fusion.py` 在 producer 之后改为 corner 的 `address_iterator`、interior 的 `static_predicate`。最初 `summarize.py:25-29` 将二者之差命名 `common_mask_reduction_*`，实际包含掩码算术省略、目录跳过和调度改变。ordinary corner 的目录阶段少 7,444 槽，interior 少 7,726 槽，原表无法单独归因。

通知 root 后已新增并实际执行 `all_keep` 四窗控制。我复核其全部整数 gold 与原 R32 相同、目录臂与 global_group2 相同，见 [all_keep_control_check.json](all_keep_control_check.json)：

|---|---:|---:|---:|---:|---:|
| ordinary/corner | 2,107,838 | 2,108,663 | 2,015,403 | 825 | 93,260 |
| lifting/corner | 1,943,768 | 1,944,593 | 1,853,929 | 825 | 90,664 |
| ordinary/interior | 2,800,716 | 2,802,304 | 2,678,362 | 1,588 | 123,942 |

这补齐了最便宜的同路径归因控制，且原主比较未被推翻：全保留管线在两学生上同样稍慢，原更强 unmasked 分母应继续保留。主表相对强 unmasked 的净节省，等于同管线 mask 节省再扣除 825/1,588 槽公共框架开销；不能换用稍慢的 all_keep 抬高主收益。目录读数仍包含掩码驱动的合法跳过，不能全归作“源结构”贡献。

## 2. RTL 功能与收费口径

**可复现的功能证据成立。** 我直接运行现有 `obj_dir/Vtemporal_source`：13 个真实 case 加 2 个定向 case 全部逐字段复现原 JSON，用时约 3.30 秒，见 [rtl_binary_replay.json](rtl_binary_replay.json)。这是现有可执行物复放，没有独立重新编译。

- `temporal_source.sv:99-127` 通过共同两级路径执行 signed48 运算、35 个 lifting norm24 和门比较；`tb.cpp:35-54,105-109` 核对每条 RF 写回，再将解释器门与 capture 对比。13 个真实 case 共检查 31,991,424 个 RF 标量和 1,279,680 个门位，零差；模式重复不构成新增样本。
- `temporal_source.sv:144-160` 实际执行每 tile 30 次 SR64 请求/响应及 2 次 SW64；阻塞输出的 valid/address/data 保持由 TB 检查。ready 为 497/410 周期每 tile，源局部周期减少 17.505%。
- ROM 实际程序为 4,512/3,456 B，两边都保留 8,192 B 容量；最高通用 RF 分别为 71/14，但 gate 使用 RF95，且双方仍实例化完整 96RF。不能把小活跃集自动兑现成 SRAM/RF 面积节省。
- RTL 额外公共状态包括 144 B 流水数据、24 B gather、16 B 门收集与控制位；README 已明确列出。CPU 中还存在 FP32 运算、resident MAC、目录控制等，隔离源 RTL 没有实现它们。双方程序共用同一 RTL 资源是已验证事实；完整链已落实为同一物理设计不是。
- 人工 stress 与真实 observed waits 分开是正确的。observed 只重放每笔相对等待；正常批门缓存路径等待为零，压力 trace 的 183 槽也没有并发消费者含义。TB 每 tile 重建局部内存并使用固定基地址，不是完整 SRAM/消费者互连的 RTL 集成仿真。

**发现后已修：程序配置/SRAM 宏表述。** 最初 `run.py:41` 与 `results.excluded` 把程序配置时间和 SRAM 宏实现也笼统说成由 CPU 补齐。上游 `source_program.py:18-30` 实际采用固定驻留 ROM，只计取指次数，不计配置 DMA；CPU 也没有宏实现。已通知 root，当前文本已改为“两表均排除一次性配置；CPU 只补外部 DMA 和消费者；宏实现双方均未评”。数值不受影响。固定驻留 ROM 可以成立，但不能同时宣称包括启动配置。

**两表现在没有数值混用。** CPU source 包含 I24 外部 DMA；RTL source 排除此项，且流水/控制拍定义不同。16.369% CPU 源服务减少、17.505% RTL 源周期减少和约 8% 局部 CPU 净减少应保持三种分母，不能相乘或互换。

**补审：固定 DFS 调度控制通过，但不形成新 X。** 对新增 `schedule_controls.py/json`，我独立逐 `logical_node` 比较原程序与两种 DFS 程序：除寄存器编号、目的寄存器和 issue_slot 外，节点类型、全部依赖边、移位/符号、输入时间、阈值/方向、常量门及 RNE 参数全部相同；节点唯一且无删减，ordinary/lifting 仍为 282/216 条指令，lifting 保留 35 次 norm24。另逐指令核查每个操作数读取对应的活节点、末次读取后复用寄存器不会覆盖仍需使用的值。16 个新增现有 RTL 用例已再次逐字段复现，全零差；没有重新编译或生成额外审计文件。

重新计算的 DFS 通用 RF 峰值为 ordinary 原门序 58、时间序 60、lifting 两序 16，与 JSON 一致。这里的峰值采用“操作数末次读取后允许原位分配结果”的固定调度口径，流水操作数/结果暂存仍另计。原程序最高地址 71/14 本身不能证明最小需求；独立按原固定顺序计算的逻辑活集峰值恰为 72/15，也只能描述该顺序，不能作为所有合法调度、重算或溢写策略的下界。

性能控制保留正确：ordinary DFS 的 766/764 周期均比原 497 慢；lifting DFS 的 648 周期也比原 410 慢。不能把较慢 DFS 换进主表放大 lifting 优势。它只检验了两种固定遍历是否轻易消除资源差异，没有证明搜索空间中不存在更好的 ordinary 调度，也没有测得 source/consumer 交织收益。

未来“16+80”必须把 gate RF 一并计入：**原 lifting 是 15 个通用 RF 加 RF95，共 16 个；DFS lifting 是 16 个通用 RF 加 RF95，共 17 个。** 因而 DFS 结果不能声称直接与 80 个消费者累加 RF 同驻留。原调度即便经重映射满足 16+80 容量，也仍须测共享 issue、RF端口、流水和 SRAM 争用后才有性能结论。该控制有助于排查编译遗漏，尚非新硬件机制或独立标题。

## 3. 精度及公共底座与 X 的边界

阶段质量规则正确使用同人口 NB0 originalSDformerFlow 本地 valid825 AEE **1.445352534681**，没有重新引入 `+0.005` 硬门。原 fixed R32 的 ordinary **1.219801338299**、lifting **1.232979367919** 均低于 NB0，但 lifting 比 ordinary 高约 0.013178；这是需要呈现的质量/服务权衡，不是本轮否决条件。

`algorithm/run_combinations.py` 对新 R24+单遍 BN 真实重推理，检查 825 文件集合与逐帧有效像素，并将原 final head 与学生 coarse exit 的区别明示；审阅时不能借旧 R32 的 825 结果覆盖新参数。其两轴分别选择不同 R24 基底，和硬件中“两基底各跑两学生”的完整矩阵是不同实验设计，引用时必须指明 mode。本审阅没有读取远端未完成的 A800 结果或预判其通过。

当前最强正面候选是“训练所得时间结构在共同编译及真实连续消费者义务下仍保留局部服务优势”。CSE、lifting/结构变换、普通 coalescing、稀疏目录、RF 驻留 MAC、低秩以及可编程源 RTL 都不能单独算新 X。当前阶段没有新近邻结构学生的等预算对比，因而仍未排除“标准可学习结构+已有编译即可解释全部收益”的反方解释；RTL 证明能执行，不能替代新颖性论证。

文献页的降级判断有数据支持：I24 全普通模式相对 signed-width 只省 **0.1045%/0.1080%**；FP32 fill+exp 还被全普通模式超过。序列化测试累计 43,008 个 FP32 和 20,480 个 I24 mode-block 为零错，但全域主要是逐块长度计算，不能写成整张量逐块编码/解码都实跑。最关键的是当前强 ordinary BN→PED 融合已不物化 BN 输出，针对这一输出 codec 的新增可避免事务为零。

F-L2 的符号主体+低秩残差已有 ReverB/MiLo 先验，F-L3 的缩放/surrogate 是训练控制，F-L4 需要面对非因果 T10 与动态 BN 跨窗变化；文献页均没有把它们冒充已验证 X。它们是新函数试验建议，不是本阶段性能结果，也未完成原论文复现。

## 4. 最小下一实验与继续条件

1. **最小公平性控制已完成：all_keep 四窗。** 上表已将同路径 mask 效果与公共框架开销分开，并保留强 unmasked 主分母。这个修补不需新训练，零差功能检查也已经闭合，无需继续把它列为阻塞项。
2. **尚缺的最小创新判别是最近结构对照。** 给一个最接近的普通可学习稀疏/结构 T10 控制相同训练预算、相同量化/RNE合同、同 CSE/ROM/RF及后级权限，在固定样本筛查后按 NB0 门验证。若已有这样的旧学生，应直接纳入共同执行器；不能只用未编译 dense 实现陪衬。通过后报告源/后级分解，必要时关闭双方同类动态跳过作归因消融。这个对照的目的，是检验普通结构先验是否已经解释候选 X；继续堆叠 codec 或低秩名词不能代替它。
3. **下一硬件闭合实验要使用最终过门的同一组参数。** 新组合 AEE 通过后，对其实际 capture 接续完整 native projection 与全域 BN 或给出明确的端到端服务分母。隔离源 RTL 无需为抬数字而扩大；只有目标主张涉及真实共享端口/总延迟时，才补一个共享 SRAM 的 producer→consumer RTL 闭合窗口。任何新增的“16RF源与80RF消费者交织”机制当前都还只是提案。

本阶段值得保留为可审阅的阶段证据；其价值是集成、可复现和排除无效创新方向。程序配置口径和 all_keep 对照已在审阅期间修补，但尚不足以承诺 TCAS-II 强 accept。标题级 X 还要由最近结构对照和最终参数的服务证据来决定。
