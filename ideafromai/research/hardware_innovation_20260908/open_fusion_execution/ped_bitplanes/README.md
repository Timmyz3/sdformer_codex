# 连续 PED 的 T10 位面默认项／校正：已执行，当前串行布局停止

本项直接试了真实数据，没有等待新颖性或全链证据齐全。**功能通过，性能未过；同时保留一个更强的普通 MAC 供数底座。** 没有新训练、量化、RTL、PPA 或整网加速声明。

AT-LIF 仍为 `{0,θ}`，θ 可吸入下层权重。本项输入来自真实连续 `full_updated_I24`，不是把 AT-LIF 改称连续发放。两个既有学生 ordinary/lifting_raw、同一帧 `zurich_city_09_a_0001`，固定原 corner 的 `(0,0)/(0,2)` 和 interior 的 `(120,160)/(120,162)` 两组 P2；每组计算完整 PED_U `K96→H32`、T10、真实 INT16 权重。不是完整帧或完整层周期。

## 实际写了什么

[probe.py](probe.py) 复用现有 payload 执行的 `Machine`，新增一个计费的 T10 位字解码操作，以及普通打包 RF 标量选择。四臂共用 8 lane、48bit 累加、96×8 RF、128KiB 状态、128KiB 系数、SR64/SW64/CR256 端口、整数延迟 2、每槽一条执行指令。冷填与输出 DMA 都收费；stress 使用原 SR 每 32 槽末 8 槽阻塞、SW 末 4 槽阻塞。

普通位串行和候选都先去冗余符号扩展，保留正确的负号位；一个真实 T10 组最短所需位宽为 16.3–17.5 位的均值。候选对每个位字取多数 0/1 为默认，共享累加器加默认项，少数时间点作有符号校正，K96 完成后才合并、执行原 RNE 和 sat24。所有中间积累都受原 signed48 检查约束。默认不是由输出 oracle 选择，而由已经收费读到 RF 的实际 10 个数产生。

新控制假设为两次 RF 读可供一个 T10 位字提取／popcount 指令；解码的硅面积尚未评估。这一有利于候选的假设下它仍输。原文的 fast/laggy prefix、CSF 内连接和完整 LoAS/BitVert 阵列没有移植，不能称完整复制了两颗加速器。

## 净服务表

单位是 CPU 端口／issue 模型的服务槽，包含冷填和输出。四种布局输出位级一致。

| 状态／学生／位置 | 现行 MAC | 源驻 RF 的普通 MAC | 普通位串行 | T10 默认＋校正 |
|---|---:|---:|---:|---:|
| ready / ordinary / corner | 24,322 | 17,794 | 98,497 | 82,079 |
| ready / ordinary / interior | 24,322 | 17,794 | 101,214 | 89,476 |
| ready / lifting / corner | 24,322 | 17,794 | 97,796 | 81,370 |
| ready / lifting / interior | 24,322 | 17,794 | 101,287 | 89,253 |
| stress / ordinary / corner | 30,874 | 19,738 | 100,538 | 84,026 |
| stress / ordinary / interior | 30,874 | 19,738 | 103,181 | 91,437 |
| stress / lifting / corner | 30,874 | 19,738 | 99,738 | 83,354 |
| stress / lifting / interior | 30,874 | 19,738 | 103,258 | 91,194 |

默认＋校正比普通位串行少 11.38–16.80% 服务，但比更强 MAC 慢至 **4.22–5.03 倍**。不能选较弱位串行作标题分母。它仅算术就需 49,048–55,516 条向量 shift-add，已经超过强 MAC 的整个服务 17,794／19,738 槽；把位转置或系数读取免费化仍不能在当前单 issue 点上翻正。

普通 MAC 改进来自每个 k 的 T10 源只取一次、在所有 H8 上复用：真实 SR64 读从 9,840 次降为 2,640 次；CR256 都是 192 次。ready 总服务 −26.84%，stress −36.07%。这是共同底座的普通循环／供数改进，**不是 X，不是同面积 RTL 提升**。候选同样拿到了这项源复用。

原始输入每 P2 5,760 B、权重 6,144 B、输出 1,920 B；新三臂的输入字节相同，没有凭理论位编码包冒领 DRAM 流量下降。位字直接从 RF 生成和消费，没有免费字典或未计元数据 SRAM。

## 功能与可复用实现

[results.json](results.json)、[results_stress.json](results_stress.json) 记录全部计数。32 次实际运行合计检查 20,480 个 q24 输出，差异为 0；新三臂还核验 15,360 次 48bit 原始点积结果。

`resident_mac()` 保留了与 `integer_chain.dense()` 对应的接口，可在 `ProbeMachine` 上接 U32 或 V96、原 bias/RNE/sat。RF `0..79` 是输出积累，`88..91` 保存当前 k 的 20 个源标量；最后使用在本 H32 全部 H8 组完成后，下一 k 才覆盖。源聚集使用原向量加载已有的 24B staging 及 3B scalar collector，不另设大型状态；候选额外使用 `80..87` 的共享积累和 `92` 的位字。所有臂仍预留同一 96 向量 RF。V96 采用普通 H32 分块并重读源，未预支跨三块复用。

[check_callable.py](check_callable.py) 另在同一个真实 ordinary corner P2 上接通 U→V→bias，ready/stress 均与完整捕获的 1,920 个连续 PED 值相等，见 [callable_check.json](callable_check.json)。这只是接口回归；没有扩大成全窗口／全链服务结果。

复现：使用仓库 Python 3.12 环境运行 `probe.py`、`probe.py --stress`、`check_callable.py`；原始大 NPZ 留在既有 capture 目录。

**后续处置：** 停当前逐位串行布局；普通驻 RF MAC 下一轮可接双方完整 U/V 消费链。未试接口只留一个：若有经电路量化的低成本 bit-PE，或训练确实形成更窄幅值／低校正密度，再比较不同面积点；本次结果不能判死位稀疏或连续 PED 家族。
