# 完整 A 消费者加 B 源的独立审阅（2026-09-12）

审阅 `PLAN.md`、`run.py` 及其实际调用的既有控制器。沿用[上一范围的共享 Machine 审阅](../REVIEW.md)，没有重复小测，也没有运行 GPU、训练、EDA 或修改实现文件。本次独立核读了 **12 项 ready 和 6 项固定 stress 的完整实际产物**，检查了数值边界、输入输出计数、状态迁移成本和唯一时钟账本。

**结论：当前固定几何与四种控制中，未发现活状态覆盖、未收费的保存/搬移，或强普通即时 PED 对照被迫承担候选保存成本。18 项结果均通过完整边界检查。** 这是完整 A 本地窗口消费者加完整 B 源的载荷执行证据，不是两窗完整推理、整层/整网或硬件 PPA 通过。

## 完整终点

A=corner 的完整 9×9 源、K864 preview/sn2；随后覆盖全部 8×8 updated/投影门及 4×4 PED。非 anchor 的 updated 按原函数保留实际原 I24，逐位置检查并进入投影门；不声称在片内额外保存完整 8×8 updated 张量。A 的投影门和所有 PED 均真实外送。B=interior 的完整 11×11 源产生门并保存到 SRAM，B 后续 preview 不在终点内。

所有结果检查相同数量：updated 61440 值，投影门 61440 值及 12288 实际 DMA 字节，PED 15360 值及 46080 实际 DMA 字节，B 源门 116160 值。所有 differences 为零；共同 A 源与 preview 的原检查也均为零。PED monitor 累积全部八对的外送字节，而不是只检查最后一对的复用 SRAM。投影门先与独立金值比较，再核对实际外送字节。观察器数据没有反馈执行控制器。

## 状态生命周期复核

| 阶段/对象 | 实际地址范围 | 生命周期与覆盖条件 |
|---|---|---|
| 原 sn2 | `[49152,61440)` | batch 在第一笔 anchor 保存前，先完整搬到 SN2 新址；direct 留在原址 |
| batch 临时 sn2 | `[98304,110592)` | A 全部 anchor 的目录消费完成后死亡，随后允许 B 门覆盖 |
| 16 个 batch updated anchors | `[32768,78848)` | 逐对从真实 UPDATED 复制，每对 5760B；直到八对 PED 依次消费完才死亡 |
| A 投影门 | `[79872,92160)` | 不与 anchors 重叠；全部 12288B 外送完成后，才释放给 PED/B 输入 |
| batch PED U24 | `[81920,83360)` | 每对 1440B；只在 A 门外送后使用 |
| batch PED V96 | `[83968,89728)` | 每对 5760B；每次实际外送后，下一对才覆盖 |
| B 输入 | `[90112,92992)` | A 门外送完成后启用，与存活 anchors/PED 区间不重叠 |
| B 源门 | `[98304,121536)` | 在 A 临时 sn2 最后消费之后启用 |

原 I、目录、LAT16、UPDATED 仍使用低地址区，不与保留的 anchors 重叠。direct 使用原 PED U/V 的 `[32768,34208)` / `[40960,46720)`，不覆盖仍存活的原 sn2；direct 不保存 anchors。A 投影门虽与后续 B 输入和 batch PED scratch 部分重叠，但这些后续写入全部发生在投影门外送完成之后。

`copy_state` 每次从一个实际 SR64 响应获取八字节，再经 SW64 写入；没有从金值、host anchor 数组或第二片内张量填充执行状态。两次复制的源/目的范围互不重叠，不存在覆盖未读源的问题。最高实际状态地址 121536 小于共同 131072 字节容量。PLAN 中 U24 的有效范围已更正为 1440 字节。

## 强对照和实际成本

`direct_CSE_P1_Z` 和 `direct_CSE_P2` 每完成一对 A anchor 就立即完成 PED 并外送，八对全部实算。两者的 sn2 迁移和 anchor 保存次数均为零，`direct_PED_pairs=8`。因此净收益必须相对其中更强的即时 P1 对照计算。

`batch_serial_CSE` 和 `batch_joint_CSE` 使用完全相同的保存布局、源程序、RF 映射、两 RF 供数、H 分块与消费顺序；它们可隔离同布局内的交织作用。三函数的 RF/ROM 仍是上一范围已审的 CSE 布局：dense H16、lifting H32、matched34 H24，PED RF93/94、源门 RF95。组合 ROM 分别为 288/276/254 字，未超共同 512 字；direct 可复用未重映射源程序。

18 份实际报告均核对以下计数：

- producer 后的 A 消费者 64 个像素与 B 源 121 个像素，总输入 532800B，实收 83250 个 DMA 槽和 66600 次 SW64。
- batch 的 sn2 搬移 12288B，实收 1536 次 SW64 及真实源读取；anchor 保存 46080B，实收 5760 次 SW64 及真实源读取。ready 两阶段分别为 4608、17280 槽，合计 **21888 槽**；固定 stress 分别为 6143、22960 槽，合计 29103 槽。direct 两阶段均不存在。
- A 投影门外送实收 1920 个 DMA 槽；全部 PED 外送实收 7200 个 DMA 槽；B 门保存实收 2904 次 SW64。
- 各报告的阶段槽数之和等于唯一全机时钟；每函数同压力条件下的四臂/两臂从相同实际 producer 前缀出发。

交织仍只有一个 RF、ready/pending 表、issue 和时钟。SR、gather24、DMA32 的共同所有权沿用已审实现。只有 PED 流使用 CR，不能把此代码推广为两条任意 CR 使用流的通用控制器。DMA 互斥锁仍非公平：释放后同协程可立即重获；round-robin 是就绪 issue 级规则，不是逐 32B 事务公平保证。

## 新颖性与未测界限

当前实现组合了既有常量源程序、resident MAC、原 RNE/饱和、状态保存与就绪交织，没有因重新命名出现新指令或独占表示。普通 matched34 同样获得净收益，且本次百分比大于 lifting；这些结果尚不能证明 lifting 小活跃集带来了普通同权限源无法取得的机制。它们支持的是该固定窗口布局可以实现且有上述局部收益。

这次完整窗口扩展避免了把一个 A-PED P2 对完整 B halo 的小工作组合当作整个家族裁决，但依然只测试一个 A/B 几何、保存布局、CSE 分块和固定压力形状。未测试 B 后续 preview、native/global BN、真实系统流量、完整两窗口、整层或整网；未重新执行 825/AEE 质量，也不允许跨函数继承质量。没有新 RTL/PPA 或普遍调度最优性结论。

如继续研究，下一接口应先指明要改变的已计成本，并给普通同样权限：例如本次可直接核验的 sn2/anchor 搬移，或经计数确认的 latent 落存重读、供数等待。仅改变队列长度、工作量比例或重新扫描分块，不足以提出新的机制。此处不否定尚未实现和测量的流式生产接口，也不以当前收益大小否定整个交织家族。
