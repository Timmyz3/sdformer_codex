# 两块目录复用：普通blocking分母获得净服务改善

**固定两块目录在128KiB内成立。完整帧实际重载1800个H32权重tile后，普通融合后段仍比原weight-stationary少6.46486%服务。** 这是普通有限容量blocking控制，X=0；没有只报目录省拍而忽略权重重新加载。

| 同函数完整后段 | 原整帧weight-stationary | 固定两块目录复用 | 服务减少 |
|---|---:|---:|---:|
| native完整帧 | 256,663,590 | 227,115,624 | 29,547,966槽 |
| native→onepass→BN物化→PED | 533,087,251 | 503,539,285 | 5.54280% |
| native→onepass→普通BN/PED融合 | 457,055,251 | 427,507,285 | 6.46486% |

不是旧表相加：此候选重新从完整实际projection gate/PED输入，执行同一个Engine的native与统计，再由完整实际Machine前缀分叉两后缀。新旧native raw、统计与两个最终输出全部逐位相等；native及每个最终输出各18,432,000值，统计480值。原独立升序K reference检查仍全部通过。原GPU浮点归约差分未变，不继承其825精度。

两个目录合计110,592B，头128B，一份顺序复用的门缓存15,552B，另有32B输出暂存，总最高占址**126,304B**。地址分别为目录[0,110592)、头[110592,110720)、gate[110720,126272)、输出[126272,126304)。构造第二区块时保留第一份目录，随后三个H32依次消费两份目录；输出不再写原state32..63。每批在每次H32完成后核对目录/头的110,720B都没被覆盖。该核对的主机shadow仅是断言参考，不参与模型读取或硬件容量。

同一600批×两块的实际费用分解：

| native义务 | 原布局槽数 | 目录复用槽数 |
|---|---:|---:|
| W冷填 | 62,208 | 37,324,800 |
| 门加载 | 15,981,390 | 5,327,130 |
| 完整K864目录 | 84,234,447 | 28,078,149 |
| 有效计算及读系数 | 121,825,545 | 121,825,545 |
| raw地址/写出 | 34,560,000 | 34,560,000 |

每批的三份W只有一份同时驻留，每份110,592B实际经32B/5槽DMA与coefficient写口载入。W总填充从331,776B增加到199,065,600B，增加198,733,824B；门读取从55,624,896B降到18,541,632B，减少37,083,264B。目录构造从3,335,247项降至1,111,749项，但计算仍从同一实际SRAM目录读取三次，CR、有效ADD和完整raw写出义务不变。省掉的门/目录66,810,558槽，超过额外冷填37,262,592槽，净少29,547,966槽。

融合后段外部读从258,709,568B增加到420,360,128B，写仍为147,456,000B。**服务改善伴随外部读取增加161,650,560B**；这里只在既有32B/5槽合同下成立，未建DDR行时序、片外能量或功耗模型。不能由本结果申领能效改善。后续新增机制应至少对这个已测普通blocking分母，不再只对原重复目录构造版。

`port_or_writeback_waits`只统计Engine对应的端口阻塞/写回日历冲突。普通RF依赖等待也经`tick()`付入总服务，但不累加这个窄counter；即使它为0，也不表示没有RAW等待或访问服务费用。

仍是dense BN/common fusion，source-code0与更强固定编译尚未进入；本轮没有扫block尺寸、表压缩或容量。原始weight-stationary结果保留。计划：[PLAN.md](PLAN.md)；执行：[reuse_native.hpp](reuse_native.hpp)、[pipeline.cpp](pipeline.cpp)、[run.py](run.py)；结果：[results_ready.json](results_ready.json)。
