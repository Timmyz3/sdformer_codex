# F_live=2：固定56字S、双NR4的新接口实测

**本轮确实执行了此前未做的双在途上下文接口，但当前固定布局没有平均净服务收益。** 相对本次最强普通F_live=1配置，F_live=2在原整数学生、训练2:4、训练C16三组捕获上分别慢 **18.26%、15.37%、9.95%**。这只停止这个双包/当前行广播的F2布局，不能外推所有多上下文排程。

前置核查和强对照写在 [PLAN.md](PLAN.md)。旧 `gustavsnn_resident_core.cpp` 中F仅表示驻留W行数，逐行完成，F_live始终1；其Packet仅有selected/mask计数。本次没有把它改个F变量就称数值执行，而是按已有 `gp_slice_pe.sv` 的私人压紧、双包、S15和CSD消费语义，编写 [有界CPU解释执行器](run.py)。

输入为已有GPS1 fixture：**16位置×2输出权重行×完整C384×全T10**。本次把两条真实W行放到**一个tile×4PE**，执行两个f任务；旧fixture曾在两个tile上运行。它们是不同资源映射，旧RTL周期没有带入本表。16个不同输入/权重选取产生32个class/time实际表示用例，再加12个定向表示用例；每例跑F1/F2×private/merge×scalar/member，共352次。没有新学生、GPU、AEE或完整层/Gustav实验。

| 共同资源或控制 | 本次实现 |
|---|---|
| S状态 | 每PE固定56×S15+valid；F1最多一组P4×R，F2最多两组P4×R7=56。实际峰值F1≤28、F2=56 |
| NR4 | **每PE总共两个包**，每包四组code12/W8。F2每包带f标签，未翻倍为四包；W返回先预约包位，0权重不占源项 |
| 源 | 4×1KiB、每bank一个64bit读口、一拍返回、128bit滑窗；576B实际packed code。每ID一个当前NRV bridge和最多一个W请求在途 |
| W与参数 | 每tile共同2KiB：两dense W行768B、两份τ60B、共同控制预留128B；两个W8口，一拍返回、II=1。源码/W/程序/τ驻留，冷配置不在端点内 |
| 共享读 | private和同址merge两边都跑；每拍最多两个不同W字节地址返回，有限owner mask广播，无隐藏第三个口 |
| issue与S端口 | 每PE一个标量W10局部累加、一个Acc24供S提交或PSN使用；单S读/写口。可选四成员归约两边同权；packet与consumer不能同拍共占issue |
| 消费 | 每PE七字S15 cache、U24、一个10bit输出保持；四份256×16程序ROM，一读/PE/拍；整个tile一个10bit门输出口 |
| 普通编译 | 两边都给旧b0/b4更便宜的原位恢复→A_eff；实际执行LOAD_U/add_store、U→cache写回及重映射CSD，每条付一issue槽。全部8个码先核函数同一，再核实际门；32次运行使用该普通恢复尾 |
| F1普通预取 | F0最后W返回后，即可扫描/压紧F1到原两个NR4包，与F0 PSN重叠；只有F1的S执行等待F0释放。没有把普通前端也强制等到最后门输出 |
| F2新增行为 | 一次源码扫描，当前NRV行先后供两个f；两个接收者处理后才前进。共用两个包、读口和issue，两个S上下文保持到各自消费完毕 |

端点为驻留输入的start到最后T10输出握手，实际计入源码请求/返回/解码、W服务、私人零W压紧、包启动、逐成员或成员合并、S提交、S加载、每条τ/CSD/恢复指令以及输出仲裁。程序ROM读取为固定每拍一条的组合取数模型，输出握手可与下个位置S加载同拍；这是明确的CPU服务定义，未逐拍复刻旧RTL。元数据容量为有界逻辑状态预留，未做宏/面积/频率综合。

主表对每组捕获选**同组平均槽数最小的固定配置**，不是每个样本事后选一个oracle配置。所有赢家都使用共同允许的同址merge和成员归约；class/time路线仍允许独立选择。

| 实际W/捕获数 | 最强本次F1：路线/槽 | 最强本次F2：路线/槽 | F2/F1 |
|---|---:|---:|---:|
| 原整数学生 / 12 | class / **2385.08** | class / 2820.67 | **1.1826×** |
| 训练row2of4 / 2 | time / **2346.00** | class / 2706.50 | **1.1537×** |
| 训练C16 / 2 | class / **2431.50** | class / 2673.50 | **1.0995×** |

2:4若固定相同class路线，则F1为2408.5、F2为2706.5，F2仍慢12.37%；主表保留更强的普通time分母2346。三组没有拿差的private/scalar作为唯一对照。

F2每次完整任务把源64bit读取从**576降到288**，但没有减少私人W逻辑请求、NR4包数、选中事件、S提交或同路线PSN指令。两个f占用同一双包后，当前NRV广播等待变多，源读取节省未变成完成时间节省。例如相同class+merge+member下，原整数学生NR4准入等待从平均1516.5增到3271.58个ID等待槽；2:4从1368.5增到2285；C16从1209.5增到2220.5。这是该调度器内的等待计数，不是能耗或完整硬件利用率。

结果也保留例外：128对实际同配置F1/F2比较中，**8对F2更快、120对更慢**；8对全部来自同一个 `v006...s2b0_p52_h97_830` 捕获的两表示及四执行控制。48对定向比较中20对更快、28对更慢。不能写成所有输入都失败，也不能把这个单捕获优势扩大为整体胜出。

[results.json](results.json) 保存352次逐例结果，[summary.json](summary.json) 与 [summary.csv](summary.csv) 保存全部48个实际组配置均值与比较。检查 **78848个S值、112640个门bit，0差异**；present、selected事件与稠密独立计数、包/提交/指令守恒均通过，NR4峰值2、S有效峰值56。定向用例包括空源码、全零W、满包压力、非对称尾包/相消、S15边界和非1θ有理数接口。真实学生θ身份来自fixture，未改为额外连续逐事件幅度。

本次没有计入源码生产者、外部冷DMA、FC2/动态BN2/shortcut，也没有采用旧full825结果作为新质量证据。普通恢复和有限包行为有实际代码，但这个新CPU调度尚无RTL交织验证，不能称完整Gustav、完整FFN或芯片周期。最强对照指本次列明的既有编译/队列/合并控制，未声称找到了所有合法调度的最优下界。

下一项区别明确的接口是：保持总双包/源bridge容量，改变两个f的NRV推进和包所有权以减少当前行屏障；若需要额外源支持缓存或独立游标，必须另计容量和端口。另一个source16+consumer80交织也仍未被本次替代。用户要求此次不扫F4，已遵守。
