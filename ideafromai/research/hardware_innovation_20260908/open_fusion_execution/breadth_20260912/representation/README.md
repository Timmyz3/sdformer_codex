# 训练集拟合的五种Q8表示：两条父路径结果不同

已实际运行两学生×五种表示的完整diverse10推理。**ordinary的完整门预测最接近原R24；lifting则是普通dyadic affine最好，超过完整门预测。** 因此“Dg利用门信息一定优于普通量化”不成立，lifting后续保留普通affine作强对照。十臂全部优于同集本地NB0，但没有任何一臂因此获得硬件加速结论。

同协议NB0：十帧1.454602861、九帧1.446425661。采用当前用户质量规则，不套旧+0.005门。这里是10种配置，其中固定Q8两臂重复已有函数作控制，另外8种参数化配置为本轮新增；并非10个独立idea。各臂10帧、516,735个有效像素。两原R24＋onepass父的825结果不能继承给这些有损新函数。

参数只来自一个预先固定训练帧 `thun_00_a_0012.npy` 的4096个均匀anchor、完整T10×C96，共3,932,160个值/学生。源和门均是实际同生产者的updated I24与projection g；没有使用验证帧拟合D。center/affine/diagonal/full共用相同训练数据，规则提前固定，无位宽、步长或验证损失扫描。完整D是带截距最小二乘；affine从逐时间训练min/max确定最小可覆盖的二次幂step。保留两父实际U24/RNE16→V24/RNE15→bias和单遍BN。

普通原R24十帧为1.164805881，完整Dg+Q8仍稍差。门预测的价值目前是量化误差控制，**尚未胜过不量化的父函数，也没有证明节约消费者服务**。lifting上的普通affine则推翻了原固定零点Q8这个弱对照所给的优势印象；只停止该比较方式，不停止预测编码家族。

十帧每臂检查9,216,000个P2×T10物理源字。center、affine、diagonal和full八臂整字全零均为0；固定Q8分别有5066/5141个空字，仅约0.055%。标量零比例约1.3%–4.9%不能冒充字级跳过率。预测后变成零的残差仍可能需要非零基值Dg+c，不能直接停整个PED。

CPU两真实窗口按原整数R24重建0差；GPU每臂另核15,360个整数端点，与独立CPU量化/消费者函数0差。全网络运行中再次检查所用门确实等于实际projection gate。以上是函数验证及AEE；GPU把Q8重建回I24送入原消费者，不是压缩乘法执行或速度测量。

[实际解码费用](../hardware/prediction_decoder/README.md)另测顺序条件加与固定5+5表，包括不同H8门模式、表载入、寄存器和端口。端点质量在这里，解码成本在那里，两者不能相加成完整消费者速度。普通affine所需常量和运行时尺度也须由同一执行平台收费。
