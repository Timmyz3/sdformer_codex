# 独立审阅：R8 支持、差分与原生窗口执行

审阅对象为相邻 `fusion_rtl/r8_fusion.sv`、`tb.cpp`、最终 `results.json`。只读源码与既有收据；未重跑 RTL/GPU。结论：在固定完整 K864/R8/N96/T10、一个 2×2 输出 tile 的整数函数和已列资源口径内，未发现阻断功能或周期比较的问题。不能由此直接声称端到端网络或物理频率收益；bitmap/priority/普通窗口复用本身属于已有执行方法。

独立脚本 [review_fusion_counts.py](review_fusion_counts.py) 从每份原生 source、origin、Q1/Q2/expanded 和 gold 重建全部 53,760 个独立参考值，验证 `Q2@Q1=expanded`、`p=Q2(Q1g)` 及差分前缀恢复。对 280 条最终记录的 5,600 项输出数、完整核心周期和工作量检查均一致，覆盖原测试累计 1,075,200 个输出值。结果见 [review_fusion_counts.json](review_fusion_counts.json)。另逐记录确认旧 mode6/7 共112条、各11字段原值完全复现。

## 状态与数值

- mode9/11 的 `z_live[r][position]` 在每次真实 `F_ZADD` 后按新和是否为零覆盖，初始40行清零；因此消去后归零的值不会被“曾活跃”位保留。后半段按当前 `fr` 读40位支持，每个输出组重读，权重驻留后逐支持位置枚举。`f_pending` 每个 rank 显式重装，最后一次更新后清最低位，空集合出口计费。
- mode10 完成全部 Q1 累积后按39到0倒序做差；`D_CUR` 与 `D_PREV` 分拍占用同一个 z 行读口，t0 减零。原 z 前驱尚未被覆盖。差分再经过同 Q2；每相位 t1…t9 在 RTL 内三拍（两次 psum 读、一次共享加写）前缀恢复，t0 保留。无 TB 前缀或隐含输出重建。
- `z` 与 `Δz` 都可用 signed13：对二值 g，同一个 Q1 算子作用于 g 或 `g_t-g_(t-1)`，绝对和均不超过864×3=2592；不能用两次独立最大值的松界错误推断需要额外位。Q2×z 使用真实 signed16×signed13，结果 signed29，再扩展到共同 signed32 累加。冻结 p 绝对界679,477,248。delta/prefix不另用数据加法器，进入原八条32位加法链。
- mode11 每个 C96 通道由 `L_START` 后16次 `L_LOAD` 顺序读入160位寄存器。9个tap的 `L_GATHER` 由四个本地 mux 产生 P4 源字；外部 source 仍一口10位，无四外部读口。每次切换通道全部覆盖16字，越界元素由 origin 门写零；重启仍执行全清零和重新加载。即使该通道九个 K 全死仍加载，这是当前函数/调度的代价，未假装省掉。
- TB 配置一次后连续两命令、不复位，核480个8lane输出 beat 的地址顺序与阻塞时值稳定；三类背压只在对应读取/发送状态停留，结束计数包含清零、连续输出、FINISH。

## 独立闭式周期

设 K 为活 K 列数，A 为这 K 列的 P4×T10 脉冲数，Q 为至少一次活动的 K 列数，Z 为 R8×P4×T10 中最终非零 z 个数，R 为存在至少一个非零 z 的 rank 数；带 Δ 下标者对差分 z 计算。每 tile：

```
F = 2(864-K) + 6K + 2Q + 3A
core7  = 1482 + F + 7776 + 24Z
core9  = 1482 + F + 192 + 24R + 48Z
core11 = 1482 + F + 1632 - 3K + 192 + 24R + 48Z
core10 = 1481 + F + 116 + 192 + 24RΔ + 48ZΔ + 1296
```

1482包含共同清零、完成、输出及 `F_OUTPUT`；mode10绕过一拍 `F_OUTPUT` 故1481。其116为40当前读+36前驱读+40差分写，1296为12组×36前缀×3拍。总测量 cycles 减 source/weight/output 实际 stalls 后逐条等于这些公式，配置14017拍单列。

mode9/11 的第二权重读为12R，MAC/update为12Z；z读 A+12Z，z写40+A，psum读写均480+12Z，支持读96。mode10把 Z/R 换成差分量，另付z读76、z写40，psum读864、写432；delta40、prefix432均有真实计数。mode11外部源读为96×图内4×4位置数，四mux gather为K次。所有这些量均独立核对。

八个真实 tile 无背压 core：mode7 173,739；mode9 149,691；mode11 142,059；mode10 181,811。mode9→11少7,632拍等于8×(3×862−1632)，源字23,364→9,600。mode10负结果由额外差分/前缀及非零 delta 数共同产生，仅适用于此固定布局。

共同新增状态有320位最终支持、160位本地源窗口、8×13位差分前驱、8×32位前缀保持，以及状态/选择逻辑；全模式拥有同一资源集合。40位优先选择和本地4读 mux 的组合延迟尚无综合/时序证据，本审阅只认可周期与端口/状态账本，未把新增逻辑称免费。
