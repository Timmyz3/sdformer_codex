# 阶段结果：完整 R8 消费者和五条融合的实际筛选

本批完成了三件事：把窄整数 R8 从 raw p 接到真实残差/I24 完成边界；重新跑完本函数和同环境原模型的官方 valid825；将五个候选都写成完整源到输出 RTL 并筛选。保留了更快且可复用的底座，**尚未找到新颖性与大幅净收益同时成立的标题机制**。

## 1. 挂点与函数

对象是既有 matched-dense 学生链中昂贵的 patch 残差 r0.conv2，完整 C96/N96、K864、T10。每帧源空间240×320，分成19,200个2×2输出tile。当前学生使用已有粗头读出，并非原始 ep34 不变网络。本轮没有重测全网份额，不沿用历史 patch 百分比推系统加速。

沿用上轮固定 Q1∈[−3,3]、Q2 signed16：`z=Q1g` 保守幅值≤2592，signed13足够；`p=Q2z` 保持signed32，中间不舍入。g 是 AT-LIF 发放门；当前静态 θ 已吸收，没有连续 θg 双 MAC 的假设。

本次新增的真实消费者为：

```
T10 原生源窗口 → Q1 → z13 → Q2 → p32
                                      ↓
FP32 identity → J20 RNE/sat → 固定 scale/BN 宽乘加 → I24 RNE/sat
```

精确部署式为 `I24=sat24(RNE((p*a + (b+J)*2^20)/2^26))`，a/b由原scale和固定BN导出，J由真实FP32位模式在RTL里转换。宽乘、bias、identity加法和舍入各计拍。没有将As跨过I24舍入，也没有遗漏连续残差。该部署式改变原float32 BN/add的舍入过程，因此独立质量评价必不可少。

## 3. 真实消费者、单指令整帧，不再只看叶子

两套完整边界均直接输入本轮A800的真实FP32 identity；SV处理源图地址、padding、配置、背压、tile及最后输出退休。每个完整作业是同一个实例一次go、连续19,200tile。每臂raw p、J、I24各73,728,000个值全部通过；另有跨行64tile的背压/warm测试。完整帧只测cold无外加背压。

| 同一完整边界内的对照 | 控制总cycles | 候选总cycles | 净周期减少 |
|---|---:|---:|---:|
| 最终支持 → 再加原生窗口 | 511638152 | 493321352 | 3.5800% |
| 新cachedOS/26bit bank scalar → dualP | 336199028 | 324217349 | 3.5639% |

第一行来自[consumer_rtl](consumer_rtl/REPORT.md)，第二行来自[consumer_packed](consumer_packed/REPORT.md)。第二行两侧均预取完整R8×N8 Q2并驻留输出psum；共同具备208bit latent向量口、异步选读到MAC、逻辑19×13乘法接口。第一行的数组、读拍、系数控制不同，因此不能把493M→324M标成同面积增量，也不能把表内百分比相乘。

第二行在真实完整帧共合并3,993,893次双活更新，减少11,981,679拍，严格等于每次少一次三拍Q1更新；W、Q2 MAC、source及消费者事务未少算。静态参数只装一次1848拍，全部源/origin、FP32转换和最终完成已付费。生产者与消费者cycles重叠，总周期以wrapper计数为准。

这使R8底座有了真实消费者和全层工作量证据，但仍只是这个子链的一帧，不能称825帧硬件回放或整网加速。常量缓存、carry选择、局部多读mux和宽消费者都没有免费的面积/时序假设；尚未做SRAM宏映射与Fmax检查。

## 4. 本函数完整825、同环境原模型与尾差

三臂均在同一A800/env312运行，官方本地825帧、48,152,523有效像素逐帧对应，使用frame-mean AEE。

| 网络/数值出口 | valid825 AEE |
|---|---:|
| 原本地SDformerFlow NB0（本轮同机复跑） | 1.447936665574317 |
| 固定整数R8＋原float32消费者 | 1.3276465686026133 |
| 固定整数R8＋本次真实定点消费者 | 1.3276350226079938 |

新函数比同环境NB0低0.12030164，满足用户“好于原baseline”的当前门。历史NB0 1.44535253468097另保留，两份分母不混写。NB0采用其原完整flow[-1]，学生沿用已有粗头/结构；质量优势属于整个既有改造链，不能归因于本轮无损打包或供数控制。详细定义和逐帧表见[data质量核验](data/quality_validation.json)。

总体AEE几乎相等也不表示与原R8逐帧无损：425帧变差、400帧变好，平均绝对帧差0.04882，最大2.65545。最大尾帧两函数各重复两次，flow逐位稳定且复现825；源g/p/identity相同，新I24仅部分相差1，但后继非线性与连续路径会放大影响。不能将全部变化归给个别翻转门，也不能用平均值掩盖尾差。所有真实J/I24无饱和。

运行时审计确认实际BN/Dropout等子模块均eval，参数全冻结。training=true仅是两个无训练分支语义的参数化容器，不改变此推理函数；没有为修饰结果盲目修改动态BN或重选格式。

## 5. 新颖性和借鉴完整度

[独立判断](ROOT_NOVELTY_REVIEW.md)给当前具体X约2–4/10，理由是可实现增量仍靠普通支持枚举、局部窗口、重复值归组或子字并行。新读的[Envision/Bit Fusion等先验](PACKING_PRIORS.md)进一步限定了打包标题空间。正收益继续保留，负收益只停止已测布局；不因为原作存在就拒绝动手。

本地补齐的是完整算子、有限状态与真实消费者，并不冒称已完整复现所有原论文系统。Prosperity的旧官方外层对照仍保留；当前R8借入小整数分解及驻留思想，归组借入UCNN/Phi方向，打包借入精度匹配执行。尚未搬完整的原阵列、训练或ISA继续标为未迁完。
