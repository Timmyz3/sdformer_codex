# 连续 PSN：完整 da4ml CMVM 基线

2026-09-09。**官方完整编译算法、整数图及真实数值验证已完成；有限端口的整链时间线尚未完成。这里没有新的硬件创新或加速比结论。** 新代码、环境、官方源码镜像与结果均在本目录，旧脚本和生产树未修改，没有训练、捕获、RTL/EDA 或哈希封存。

## 实际承接了什么

使用 [da4ml 官方发行版 0.6.0](https://github.com/calad0i/da4ml) 和[官方 CMVM 方法](https://calad0i.github.io/da4ml/cmvm.html)：矩阵图分解、两阶段带位宽权重的跨输出公共子式、正负移位、可选延迟限制。没有把逐常量 CSD 称作完整 CMVM。论文为 [da4ml，TRETS](https://arxiv.org/abs/2507.04535)。

固定比较两种官方求解设置：不设硬延迟限制、编译器最小延迟限制；两者都使用 `wmc/auto`、官方内部的分解搜索、`adder_size=carry_size=1`。该位成本/延迟模型只用来编译，不是 ASIC 面积或时序模型，第二轴也不代表已经找到本地最佳时钟方案。

输出包括官方原始两级图、展平后的整数 DAG、官方 DAIS 可执行文件；每个 DAG 节点有10维（前缀为3维）完整系数、输入符号/移位、严格静态范围、合法位宽、加法依赖深度、扇出及消费者。输入先乘有效 W，Q14 已含于 Aq/τ，比较之前不再右移；保留输出 θg，τ不是幅值θ。

### 算术、供数和状态意味着什么

完整 CMVM 比逐项 CSD少49.14%的加减节点，但不等于比字 MAC快49.14%。十帧普通已知零跳过后为59,667,600次96-lane MAC发射；同已知零传播后的 CMVM 为153,874,040次向量加减。两者运算单元和图并行度不同，**这个2.579比值也不是周期比，更不能据此判定完整 CMVM 架构失败**。

原同学生 forced-L16 前端十帧 FC1 为21,653,516模型服务步，系数池读取21,780,048个16B字；旧 PSN含输出为64,275,600步，旧整链为87,084,346步。这里只引用旧母模型分项，没有把新加法计数直接替换旧拍数，也没有减掉已有前端重叠费用。[完整归因](attribution.json)

为暴露保存/重读成本，给了两个合法静态 DAG 顺序及两操作数寄存器的读取计数，尚非最优端口调度。默认图的原顺序临时值峰值为1124 bit/标量，即96lane的13,488 B；简单压力优先为12,924 B。原顺序442次向量 RF读，其中116次读Y；压力优先347次，其中119次读Y。完全展开的电路可能用导线/流水寄存代替这些RF读，必须同时计面积、配平、扇出与时序，不能把上述折叠流量套到所有CMVM映射。

按共同缩位，原 MAC 裸状态预算可从113,944 B降到66,400 B；同母边界的默认CMVM原顺序约76,792 B（压力优先76,228 B）。它们都可落在旧裸容量以内，但**这不是同面积或端口已闭合**：普通MAC也有权使用剩余容量作跨p流水和更多驻留。图的状态数字包含临时值和两个操作数寄存器，尚不含任意充分流水所需的配平复制。

## 官方接口问题与本地适配

本轮实际发现并处理了两处接口问题，未修改官方源码：

1. `solve` 的原生绑定按C连续内存读取矩阵；直接传F连续的转置数组会把本地矩阵方向弄错。所有调用显式 `ascontiguousarray(A.T)`，并验证整个kernel。
2. 0.6.0原始级联逐stage调用 `predict()` 时，第二stage的输入范围未包含第一stage的输出移位，导致合法值在边界被截断。输入0…9即可复现；完整数学Pipeline调用与整数DAG正确。适配器不改分解/CSE节点，将尺度/符号别名合并为单个DAIS块，按严格整数范围设置位宽，再交给官方C++解释器验证。[具体复现](official_interface_notes.json)

原始图保留供检查；修正后的`.dais`是本轮实际验证的可执行图，不能把未修正的逐stage解释结果写成PASS。
