# GustavSNN 借鉴完成度与下一硬件切片（2026-09-08）

**更新：已新增[2 tiles×4 PE 连线切片](rtl/gp_slice/README.md)，144个任务、46,080个门位验证通过；完整 GustavSNN RTL和完整FFN仍未完成。** 下表保留的是本次连线前的缺口审阅，不再表示这里只有三个未连接叶子。新顶层已经连接实际源/W请求、私人双NR4、跨tile屏障与同PE完整T10消费；W口连续吞吐、全层条带、通用双指针以及FC2/BN2仍缺。生产 C1/C2 与主稿未改。不能用这个有限切片的功能完成替代性能闭环。

原作依据：[GustavSNN，HPCA 2026](https://doi.org/10.1109/HPCA68181.2026.11408587) §IV–V、§VII，[已读全文](../literature/GustavSNN_HPCA2026_public_mirror.pdf)来自公开镜像，尚未找到作者 RTL/模拟器工件。本地 NR=4、端口宽度、返回延迟和具体仲裁是注明的实现选择。原作实际使用 LIF；本项目有意将其消费者换成同学生非因果 T10 PSN，不声称原 ep34 满秩实数算术等价。

三个功能结果各自有效：[源叶](rtl/direct_temporal_result.json)为 7728 次向量回放；[GP 叶](rtl/gp_temporal_result.json)为 232 次常规任务加 3 次取消后任务；旧 FC1→PSN 叶为 [294 次局部 tile 回放](rtl/run.log)、7,835,520 个 gate 比较。真实 tile 都保留完整 C384，但抽取位置和输出行；不能累加 PASS 数量称全 H／全层覆盖。实际 GP 测试参数中的 θ 恰为 1.0，通用接口仍为 θg；非 1 θ 的折权、尺度和 τ 一致性不能因此省略。

建议只按以下三步推进，先做强底座，再把新稀疏机制挂到同一请求接口上。

1. **先闭合 2 tiles×4 PE、P4/F_live1、完整 C384→T10 门的最小切片。** 四个源 ID 足以制造每 tile 两读口争用，两 tile 足以制造不同 W 零模式与完成先后。加入有实际地址/返回的行为 SRAM 适配、私人 W0 压紧、双 NR4 及明确源块结束；复用 GP 叶的 S/提交/背压逻辑，移植旧共享叶的 CSD 编译和标量 Acc24 消费者。采用共同的 class/time 与标量/成员控制。首先验证整个切片从请求到最后门握手；不是继续只给叶子灌完整 W 包，也不宣称已映射 SRAM。
2. **扩成 8×8，补齐完整强控制。** 接通同 ID 多播/完成屏障、F_cache 与末条带、有限源/DMA/门 slot；补原通用两指针交集，再接 C16/2:4 的实际压缩地址与元数据端口。运行一个完整真实 S2 算子的 P1200/C384/H1536（减宽另标 H768），两表示采用相同资源。新机制以后只改变真实请求或消费者行为，直接和该完整底座比较。
3. **接真实生产者，明确并闭合最终评价端点。** 将 `direct_temporal_code` 的输入、码写入与上述源 bank 接通，收费量化、布局和装入；若主张完整 FFN，则继续接 FC2、BN2 全域统计及 shortcut。若短文只评 FC1＋PSN 组件，就清楚停在该接口，并保留外围费用，不能称完整 FFN。达到这个集成端点且增量成立后再考虑 EDA，不为多个未连接叶子先做一套 PPA。

先前“完整借鉴”的承诺，**论文与大部分数据流服务参考已兑现，私人供数前端、通用双指针、真实存储/跨 tile 控制以及消费者连线尚未兑现**。下一步补的是能承载新机制的完整执行底座；不再用“名字有先验”作为停止实现的理由，也不因功能完成而提高创新评分。
