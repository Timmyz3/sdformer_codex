# 单 PE：NR4 → 持久 S

`gp_temporal_pe.sv` 实现了完整源维累加的单物理 PE。它支持 P8/F1、P4/F2，R=1…7；类别 onehot 与普通时间行通过同一张 `8×7 bit` incidence 表配置。输入来自本轮整数部署学生，真实 θ 已折入 W8，输出是该整数函数的部分和，不能称原 ep34 FP32 等价。

本次实际读取的六块参数文件中 `theta_source` 均为 1.0，结果按实记录；测试并未单独证明非 1 θ 的编译。该叶不处理 θ，非 1 θ、权重行尺度与后续 τ 的一致性属于上游编译合同，不能由此推广为 ATLIF 幅值恒为 1。

固定数据状态为 **56×S15＋56 valid**，地址 `(f*P+p)*7+r`。R<7 的空槽保持 invalid，读出 0；非零贡献相互抵消则为 valid 的 0。宽数据不做全清，只有显式消费者完成、任务取消或 reset 才使其失效。没有 SRAM 宏映射。

一次只接收一个 NR4 包：四行×八位置×3-bit code、两 F×四个 signed W8、源数 0…4、last。包被接收后直到所有目的写回完成才再次 ready，**没有隐藏双缓冲或额外在途请求**。共用源窗口内的 W=0 会被屏蔽；这里没有实现 GustavSNN 上游按各输出 W=0 私人压紧的取权前端。

- **标量模式**每拍处理一项 W，在包内累积同一目的的全部贡献，再只写一次 S。
- **成员模式**每拍选择一个目的，四位 mask 选出相应 W，用实际两级 3:2 compressor、最终 W10 CPA 归约，再经 S16 保护位加法写回 S15。四个 W8 的和在 `[−512,508]`；实际 W 的正负和静态界保证所有源前缀均在 S15 内。
- 两模式共用 P8→R7 的层级选择、单 S 更新口；P4/F2 依次执行 F0、F1。标量局部加法器、成员压缩树及状态加法器均在此可配置实现中，**不是最小面积标量单元与归约单元的面积比较**。

收到 last 包且全部提交后才拉高 `state_complete`。PSN 端用 `rd_valid/ready` 随机读 S；响应有一个弹性寄存器，支持背压与同拍替换。积累和消费者读取明确共用一个寄存阵列读地址 MUX。只有没有未完成读响应且没有新读请求时，`consumer_done` 才能释放上下文。`cancel` 为明确的整任务取消，允许撤回尚未消费的响应；正常任务不能提前释放。

功能结果为 **232 次常规任务＋3 次取消后的完整任务全部通过**。常规任务来自 58 个 case×两模式×有/无空隙：其中 48 个真实 case 使用 integer60 中 v000/v006 两帧、六个 S2 block，每个 case 完整累加 C384，但只覆盖选定 P8/F1 或 P4/F2 的位置/输出通道，未覆盖全 H1536。另 10 个定向 case 覆盖空包、1/2/3/4 源、负/零 W、数值抵消、无效字段污染及 S15 两个边界。

NumPy 参考从**未分包**的实际 code incidence×W 做 int64 dense dot；C++ 另核每包的成员、每次提交、完整 S，并在每任务读取全部 56 个字两遍。正常/背压读回、完成后延迟消费、连续换配置不 reset、等待/标量执行中/读响应被阻塞时取消均通过。只有整个战役开始时做一次全局 reset。

复跑：在本目录执行 `/opt/anaconda3/bin/python3.12 -B run_gp_temporal.py`，使用 Verilator 4.028、`make -j1`。结果为 `gp_temporal_result.json`，逐任务服务为 `gp_temporal_results.tsv`；`gp_temporal_cases.json` 给出实际文件、位置、输出通道和 θ。
