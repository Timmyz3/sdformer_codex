# 从支持码读表税重新提出假说（2026-09-15）

**本轮完成十条独立生成的假说、三条收敛接口及一个真实 D/W 数值探针。已测的固定零响应投影没有胜过同响应稀疏率的普通 W 组剪枝：载荷读下降上界仅多 0.1744 个百分点，局部误差反而更大。** 这否定不了恢复训练或改变源表示；它具体指出，约束零字、整数舍入与其他码响应的耦合不能拆开处理。没有网络训练、AEE、RTL、EDA 或整链服务新结果。

**两句 pitch。** 支持码减少了累加，却使原本几乎没有整字零的宽响应表成为更多的真实读请求；优化 token 频率、权重零率或字典规模，并没有直接优化这个对象。我们把候选问题改为“消费者究竟必须区分哪些源状态”，尝试在整数可实现约束、tile 内码共同出现和真实消费者义务下合并响应，而不是继续为同一张稠密表换缓存策略。

**已知 B 及边界。** 旧 forced-code 学生的 CPU 服务模型中，W/L 系数读由 13.681 增至 34.848 MB/帧；普通 INT10 已降至 **23.232 MB**，所以 34.848 MB 不能作为本轮最强流量分母。旧模型 PSN/输出占 73.81%，FC1 等待仅占 0.133%；这里首先是流量问题，减少表字节不自动改善整链时延。当前 D[6,16,16]、W[384,96]、L[g,k,h]=D[g,k,:]·W[h,g,:]；W 已吸收 θ 和原尺度。原 H8 全零字为 0，本轮 H12 全零字亦为 0。[既有运输控制](../bn_state/support_table_transport_probe.json)、[模型边界](../bn_state/response_zero_one_page.md)

**唯一数值探针的冻结合同。**

脚本 [probe_response_projection.py](probe_response_projection.py)，紧凑结果 [probe_response_projection.json](probe_response_projection.json)。真实输入为 [dictionary.npy](../algorithm/support_training/dictionary.npy)、[forced_code_weight_int8.pt](../algorithm/support_training/forced_code_weight_int8.pt)、原 `run.json` 顺序的十帧 `forced_code_*_source.npz`。这批源是**最近支持码投影之后**的真实捕获，不是原始 gate 生产器；本轮不伪造其前端开销。D 六组秩为 8/11/13/8/10/8。

固定每 g 的 **code1**，它来自原 train32 字典既有顺序；不根据本轮十帧选码、不扫稀疏率/超参。要求该码在全部 384 个 h 上为零，共 6×32=**192/2880 个 H12 字**，6.667% 响应字稀疏率；每 h,g 一个独立线性约束，共 2304 条。选中支持大小为 5/2/2/5/3/2。

先求在 `−127≤W′≤127` 且 `d·W′=0` 下最小 `||W′−W||²` 的连续投影；再比较独立 RNE 与保持整数和为零的平衡舍入。后者对投影向下取整，再按最小平方误差增量补足整数和，所有结果仍为 INT8。重新按原 θ/尺度导出和量化后整数完全一致；原 scale 的 float32/float64 存储相对差仅 2.22e−16，合同采用原固定整数消费者参数。

普通控制包括：

- **同约束数 W 组剪枝**：每 g/H12 选择一个活动输入列，按原 W 最小组能量置零。匹配 2304 条标量约束，不假称响应稀疏率匹配。
- **同响应稀疏率 W 组剪枝**：对每 g/H12，从会消掉恰好一个非零码响应的 W 支持组中选最小组能量者，实际验证同为 **192** 个响应零字。此普通控制没有恢复训练，也不是全局最优质量剪枝；但足以检验固定投影能否赢一个具体强控制。
- **同靶码 W 支持全剪**：把 code1 支持上的 W 直接置零，保证相同目标，但允许其额外消掉其他响应，实际为 704 字；单列预算差。
- **自由 L 同靶字剪零**：只删除相同 192 个 L 字，不补其他码。六组投影回 `col(D)` 的 Frobenius 残差分别为 1119.01/615.17/608.86/1200.44/1003.28/738.58，确实不能当作同一个线性 W；它是任务允许改函数时必须比较的普通 LUT 控制。

全部臂实际 L 范围仍在 **[−388,413]** 内，H12×INT10 的 120 bit 装入独立 128 bit 字；每 H96 为 8 字，没把 H8 零字和紧凑 INT10 打包混领。十帧全量重算 B32×T10 的码出现集合，原始请求 **14,520,032 字**与旧 fixed10 记录逐帧完全一致。局部误差仅取每帧固定 tile **0/199/399/599**，全 T10/384h，共 **4,915,200** 个 Yi/U/gate；原 Yi 另用真实解码 source 与 W 的原生整数乘法交叉核对。下游使用 `integer_s0_valid825/integer_parameters.pt` 的 **sn2 temporal_int16/threshold**，没有误用 `forced_code_parameters.pt:A` 的上游 sn1。Yi→U 为精确整数线性链，门用同一原阈值；没有重算/调整 τ 掩盖误差。

MB 为 10⁶ B。整数平衡投影将 7,164 个 W 标量改变，最大变化 98；独立 RNE 留下 **1005/2304** 个非零响应标量约束，导致只有 22/192 个目标整字可跳。平衡舍入修复了表示问题，没有修复局部质量。相同响应稀疏率的普通 W 控制虽 ΔW 范数更大，真实 Yi/U 误差却更小，说明 **W 的欧氏距离不是这批相关码源的质量距离**；它正是后续需要输入协方差/任务恢复控制的具体理由。

十帧的整数投影请求下降范围为 **6.6457–9.2408%**，不是稳定的固定 7.5% 结构收益。code1 的 token 次数按 g 为 70,540/115,559/140,897/59,252/49,084/113,031，但对应 tile presence 为 5,693/5,892/5,939/4,865/5,699/5,947；二者不可交换作为读表费用权重。

**资源与可达性仍未免费。** 非零码的 H12 live bitmap 为 90×32=2880 bit，**360 B**；128 bit 冷配置至少 **23 字**，若保留 code0 的条目则 384 B/24 字。直接保持稠密地址加 valid 可免地址目录，但表容量仍为 46,080 B；若压缩存储，还要地址/长度或 popcount 前缀解码。若每次 H96 请求额外读一个未缓存 bitmap 字，十帧要额外 1,815,004 字，整数投影变为 **24.3935 MB/帧**，比原 23.2321 MB 更差。360 B 静态驻留并不自动解决其读口、地址 mux、mask 合并、原子更新/输出退休；所有臂都应拥有同容量/端口权限。

下一最小执行接口仍可用普通 `lookup(g,code,h96)→live8`、固定地址逐 H12 的 payload 请求与目的 mask 广播，只有 `(目的非空 && live)` 才发读。原 Yi 应按零初始化/首次有效写管理，**没有 Yi 更新不代表 gate=0**，完整 PSN/τ 或既有零模板照常执行。这是成熟稀疏执行 A；在本轮数值状态下，不建议为固定投影另外扩根 RTL。若后续①得到可用整数等价类，才增加 class-map 与真实 source 证明接口，并与普通合并去重同权比较。

**近邻与原创性边界。** 本轮追加核了 [SparseGPT 原论文 §2](https://proceedings.mlr.press/v202/frantar23a/frantar23a.pdf)：它明确把局部输出重构、mask 选择和权重更新结合，因而“投影后补偿”“用输入输出误差代替 W 范数”不是原创。普通结构组剪枝已有 [Learning Structured Sparsity](https://papers.nips.cc/paper_files/paper/2016/hash/41bfd20a38bb1b0bec75acf0845530a7-Abstract.html)；普通码本/表训练已有 [LUT-NN 作者论文](https://www.microsoft.com/en-us/research/wp-content/uploads/2023/09/LUT_NN_2023-3.pdf)。前者本轮仅核作者摘要，后者本轮核作者论文入口/摘要，未冒充又做整篇精读。旧零响应审阅已指出 [WINS](https://openaccess.thecvf.com/content/ICCV2025/papers/Park_WINS_Winograd_Structured_Pruning_for_Fast_Winograd_Convolution_ICCV_2025_paper.pdf) 是变换域结构剪枝近邻；本轮该 PDF 请求失败，不据标题补写其具体算法。

因此可诚实保留的新增内容是：**固定真实整字约束在量化后怎样失败、怎样修复；修复后为什么又输给同响应稀疏率普通控制；以及由此提出“别强行归零，改查消费者可区分状态”的待证接口。** 没有声称这些方向穷尽，也没有把未训练的小探针当全家族淘汰或整网 AEE 结论。
