# 支撑码先按时间聚合：真实病例的换序成本

2026-09-15。**该换序在这批真实输入上没有算术容量收益。** 32 个 H96 命令需要 195,240 次向量 MAC，仅 MAC 的理想下界已比当前 LUT10 RTL 的完整无背压服务 184,184 拍高 **6.00%**；这里还免费赠送了聚合、参数/系数供数、清空、阈值、输出和所有控制。保留现有 96 路 48bit 公共 ALU 的累加路径，再计标量归约，理想算术下界为 196,360 拍。没有运行新 RTL，也没有将下界称为候选实测周期。

换序并非没有压缩作用：跨时间的非零码实例由 30,128 降到 19,524，减少 **35.20%**。失配是原 FC1 已先把六组贡献相加为一个 Y，然后每个 Y 只过一次时间 MAC；换序把时间 MAC 分散回多个 `(g,k)`，重复的 H96 运算远大于省掉的向量加法。这定位当前布局，不能推成时间码家族都无效。

## 2. 重排的精确函数与计数方式

原式和候选式分别为：

```
L[g,k,h] = Σc D[g,k,c] W[g,c,h]
Y[p,s,h] = Σg L[g,k(p,s,g),h]
U[p,t,h] = Σs A[t,s] Y[p,s,h]

C[p,g,k,t] = Σ{s: k(p,s,g)=k} A[t,s]       (k ≠ 0)
U'[p,t,h] = Σg Σ{k≠0} C[p,g,k,t] L[g,k,h]
```

这里每个 p 的六组、所有 s 和所有 t 都计入；零码的 L 是全零，直接跳过。`C=0` 也可跳过 MAC，但必须先计形成 C 的归约。没有在 Y、C 或 U 中插入 Q14 右移/RNE，原阈值/正负增益/常量分支保持，所以换序是该整数函数的精确代数重排。

令 `n[p,g,k,t]` 为该桶中 A 非零的输入项数，最乐观的标量归约加法数为 `max(n−1,0)`：**第一次赋值免算术，但其写入不能自动免掉。** 统计输出分别保留输入项数、第一次赋值数、后续 read-modify-write 数、最终非零 C 和精确相消数。

每个非零 C 对非零 L 行产生一次 96 lane 向量乘加。本批四种 Hblock 的每个非零码响应行都非零，而且没有全零 H12 bank；逐 lane 零只报告数量，不假设能在现有固定 h 映射中免费挤走空 lane。表/码从源直接推导，已有 Y/U/gold 只用于核验。

## 4. 下界、数值与未计的实际接口费

候选固定 h 向量布局仅由乘法容量得到 `LB_MAC=M`。若保持当前每项通过 `U+=product` 的公共 ALU 路径，则 96 路 ALU 还要执行 106,040 次标量归约，给予任意打包和零供数延迟后，每个独立 H96 命令有：

```
LB_ALU = M + ceil(scalar_reduction_adds / 96)
LB_compute = max(LB_MAC, LB_ALU)
```

对 32 命令分别取整为 **196,360 拍**，是原公共 ALU 操作下界 113,528 的 **1.7296 倍**。如果允许第一次 U 产品直接赋值、免第一次累加，并免费生成全部 C，较强的 **MAC 单独下界 195,240** 仍成立，是原 PSN MAC 数的 **2.3410 倍**，已超过原完整 mode2 总服务。它不是任何新控制器的实际时序。

即使进一步不现实地允许所有非零标量产品任意跨 h/命令打包，总计 18,637,940 个非零产品仍需至少 `ceil(/96)=194,146` 拍，比原完整无背压服务多 **5.41%**。实际固定 h 布局没有该打包网络；这里只表明少量 L lane 零也解释不了差距。

数值逐值核验 **983,040 个 U、983,040 个最终 gate，全等**。另独立重算 `S@W` 与存档 Y，再以原 `A@Y` 对照。C 的任何可能时间子集都在 signed16 内：十行全部子集的全局范围为 **[-31,685,22,462]**；本批实际聚合范围 [-24,047,22,462]。没有因聚合而需要更宽 A 乘数。观察到的产品范围 [-9,200,401,9,276,806]、按 `(g,k)` 顺序的 U 前缀范围 [-13,731,052,12,477,031]，均落在原产品/48bit 累加合同内。

下界故意没有收费的项目包括：源码识别与跨 T 建桶、C 有效位/首次写、后续 106,040 次标量读改写及对应存储端口、301,280 次增量逻辑写、C 到乘法器的标量供数、L 读取/解码、清空、流水相关、门判决、输出与背压。它们不能在未来 RTL 中消失。若每 p 逐次处理，排除零码的 C 稠密槽为 `6×15×10×16bit=1,800B`；若同时保存 P32 全部 C，则为 57,600B。每 p 的时间成员 mask 另有 900bit。复用现有 Y 存储空间不自动提供所需的多地址读写与路由。

四个 Hblock 理论上可共享一次 C 形成，把标量归约从 106,040 降为 26,510，但 **195,240 次向量 MAC 不变**。当前叶没有实现这种跨命令 C 保留/回收；即便免费给它，也无法改变 MAC 下界的负结论。

## 5. 失败适配应保留的条件

这是普通线性收缩顺序的选择，不是新公式。它在“每组跨 T 极少数码反复出现”或“后级 A 实际稀疏/聚合频繁相消”时可能有机会。本批平均 3.18 个非零码/`(p,g)`、A 全密集、实际 C 无相消，未达到该条件。单纯把现有 table 的求和顺序调换，压缩了码实例却丢失了原六组归约后的共享。

下一接口若再试，应先改变这一失配条件，例如形成有费用的多组联合响应、或让同质量训练产生更强的时间码复用；二者都需要重新核表规模、供数和原生强控制。不能把“联合表变大”忽略，也不能在本负结果后直接宣布整族结束。**本轮没有实现这些扩展，没有新增 RTL 或网络任务。**
