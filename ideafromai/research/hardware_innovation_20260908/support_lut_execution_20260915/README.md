# 支持码执行落地与下一失配（2026-09-15）

**这轮完成了实际 FC1→完整 T10 PSN 的五模式 RTL，不再只有表访问 CPU 模型。** 32个真实病例合计，普通 INT10 查表相对宽广播 bit 对照，总周期减少 **28.3275%**；带背压为 **25.2601%**。但系数请求增加 **75.8300%**，新增零字目录/响应去重没有形成独立时延收益。结果是有正服务收益的借入执行底座；尚无可以宣称原创增量闭环的标题。

## 实际实现与验证

[实验问题与范围](EXPERIMENT.md)、[RTL](support_fc1.sv)、[测试台](tb.cpp)、[原始周期表](rtl_cycles.csv)、[汇总](rtl_summary.json)、[独立审阅](RTL_REVIEW.md)。41病例×5模式×2背压=**410任务**，Y/U/gate各 **12,595,200** 个数值与独立dense整数参考一致。32真实病例只来自两个帧的8个固定P32空间tile、每tile四个H96块；另有3个修改W探针与6个诊断，分开统计。

状态与算术在RTL：96bit实际源→字典等值识别/逐bit逃逸→目的mask→8bank实际请求/返回→持久Y24→完整10×10 Q14 PSN→U48→有符号阈值/常量出口。没有把Y或gate交给C++代算后回灌。所有模式都有宽广播、一行系数跨P/T复用、首次写免清空和零bank门控；直接对照不逐token重复取权重。

输入来自已有支持码学生**最近码投影之后的g′**，不是原始ep34浮点输入，也没有实现上游最近码投影。当前测试继承的是已有整数消费者函数，不是原始FP32 BN逐位等价或新网络AEE。来源及数值方向见[CASES.md](CASES.md)。

总周期包括启动、片内参数装载、源码输入、FC1、完整PSN、输出背压；逐任务累计不是整层/整帧排程。SRAM初次从外存装载、上游投影、跨H块复用/重叠和FC2/BN2/shortcut未接入。宽广播direct与LUT使用同一份资源参数化RTL，但未做VCS、综合、时序、功耗或Formality，**不能称准入RTL加速比、同面积收益或整网倍率**。

INT10相对LUT16的系数流量减少1/3；它的额外总周期减少仅0.0716%（无背压）/1.1977%（背压）。这说明当前计算服务占主导，不能把压缩比写成周期增益。mode3/4原W没有可跳零字或相同行，额外配置反而收费；背压为相同绝对时钟的确定性扰动，极小周期差还会受相位影响。

## 从失败机制中推出的下一接口

**剩余大头已测到完整PSN。** LUT10下，32任务的FC1为30,352拍，PSN为118,344拍（占总服务64.25%）。因此新X必须减少PSN实际必须完成的工作，或把上游源码生产改成能减少最终执行义务的表示。继续只省表字节，主要是流量目标。

我们已经实际检验简单时间换序：先按相同码归约时间A，再乘响应L。它跨T减少了码实例，但丢掉原FC1先合并六个源组后再做一次PSN的共享，候选仅MAC下界就超过现RTL总服务。详见[时间码收缩探针](TEMPORAL_CODE_CONTRACTION.md)，不是把数学恒等式当加速。

目前仍保留三个有具体缺口的研究接口：

1. **响应等价类反向约束源判决。** 原创候选是消费者不再需要区分的源码状态，能否让生产者少完成一些判决；普通后端去重已证明不省更新。下一步必须取得投影前原gate/PSN输入，付费执行“所有合法补全得到同一响应类”的判定，并检查其他消费者义务。没有这段生产接口前不宣称提前结束。
2. **训练减少tile实际出现的响应集合或完整时间义务。** 比较普通firing/token entropy/组剪枝和自由L；优化对象必须是共同广播后剩余请求与PSN服务。当前只是待试训练接口，不能因改了loss名字就称新机制。
3. **光流粗头之后的局部细节恢复。** 真实decoder2的动态全域BN使非空细节仍依赖全域统计；仅冻结/恢复decoder2 BN后再比较同固定BN的全细节、普通块mask及直接粗头早退。[图依赖实测](FLOW_NEXT_INTERFACE.md)已明确这个移植缺口。没有把最终光流当同帧免费唤醒先验。

这三者都有未试接口，但当前都没有强接收证据。特别是“原始W不存在响应别名”和“当前A满秩”只否定无修改的免费合并，不否定可训练表示；全T10区间/门证书也必须继续付真实供数粒度和连续消费者的义务。

## 资源、复现与边界

共同资源为96路48bit加法器（FC1/PSN分时）、96路16×24bit PSN乘法器、4级乘积流水、8bank×128bit单bank至多一笔在途请求；Y为320×96×24bit，需每lane 1R1W；U为10×96×48bit。显式统一了FC、PREAD和输出观察的Y读地址，U同样只用一个分阶段读地址。

384B payload是可同时多bank写入、整行组合解码的**寄存器池**，另有192B活动系数、4个描述符和流水状态；不能把该池当成普通单口SRAM。源码routes为7.5KiB，Y为90KiB，U为5.625KiB；τ也要5.625KiB。128KiB系数/参数bank池之外仍有这些本地状态，不称128KiB全芯片。全模式参数地址布局最高至8161/8191字，满足池容量；尚未映射宏。

再生输入：`/opt/anaconda3/bin/python3.12 prepare_cases.py`；再生响应类W：`/opt/anaconda3/bin/python3.12 probe_response_classes.py`；完整运行：`bash run.sh`。可选`bash run.sh 1`只跑首病例调试，不覆盖完整结果宣称。Verilator4.028需脚本中的unroll参数；它影响展开兼容性，不将流水运算移到C++。大输入/构建产物不入Git，脚本与数值表入Git。

实现检验包括原始bit/多项逃逸、INT10负数、48bit τ跨128bit字、正负gain/常量优先、部分word跳读、整行跳读、精确内容合并、队列容量、请求/输出背压稳定性。测试尚未覆盖无reset连续多任务重启；本次每任务独立reset。生产nts07、投稿稿、训练参数均未改。
