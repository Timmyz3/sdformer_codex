# Support FC1 执行叶独立审阅

审阅对象：最终五模式 `support_fc1.sv`、`tb.cpp`、`export_tb.py`、`run.sh`、`EXPERIMENT.md`，以及 `cases.bin`、`rtl_cycles.csv`、`run.log`。本次只读实现，未重跑 Verilator / EDA。审阅者另用 NumPy 从原 S/D/W 重建请求和消费次数，并重新聚合最终收据；没有采用 DUT 给出的分类结果作为参考。

**结论：在“已投影 g′、片内已驻留静态表、P32×T10×C96→H96、固定 A/τ”合同内，五模式有完整 RTL 数值与实际请求闭环，未发现阻断性功能错误。mode0 是具有列广播复用的普通稀疏 AAC 强对照。原始真实输入的有效加速来自支持码聚合；INT10 的字节节省大于其周期收益；零字目录与响应去重在原 W 下均没有额外执行机会。** 尚不能把本叶解释为完整层、完整网络、最近码前级或等面积等频率实现。

## 1. 数值与输入边界

- `SOURCE` 实收 320 个 96bit 原始 g′ 行，行号 `p*10+t`。RTL 用六组、每组 16 个真实字典模式完成匹配；未命中和 onehot 都落原 bit 路径，零源不发系数任务。输入没有 code ID、PWP 地址、Y 或 U 答案。源编码前 g 不在本叶；最近码投影不在 RTL。
- `tb.cpp::memory` 用静态 D/W 离线构建表、零字目录和 mode4 类别表，这是预计算数据，不是在线已知源活动或输出答案。它们的**片内读取**实付，但离线构建及首次写入片内 SRAM 的代价未进入周期。A/τ 是已固定参数；本叶不做 BN 统计及 τ 生成。
- FC 的 `y[320][96]`、两拍更新流水、逐 bank 首次写有效位都在 RTL；遇到同一行连续更新，用较新 `fv[0]` 优先于 `fv[1]` 的转发。真实固定 W 下任何二值源及 FC 累加前缀都在 `[-2351,2317]`，Y24 足够；按组 LUT 或逐 bit 求和不会重复原通道，因此同一前缀包络适用。
- 完整下游 PSN 是 `U[p,t,h]=Σ_s A[t,s]Y[p,s,h]`。RTL 中有 signed16×signed24→signed40 乘法、四级 product 流水、signed48 累加；没有中途 RNE 或右移 Q14。`busy[t]` 阻止上一笔 U 写回前再次发同一目标，FC 流水完全退休后才启动 PSN。真实固定参数 U/前缀界 `[-73887065,74819101]`，U48 足够。
- 出口先检查 constant override，再按正 gain 做 `U>=τ`、负 gain 做 `U<=τ`，均含等号。τ 的 48bit 二补码加载、10bit 系数符号扩展、原行映射均核对正确；全部当前 41 个 binary fixture 的 τ 都在 signed48 内。真实参数只有正 gain、无 constant 通道，负向与 constant 覆盖来自明确标注的合成诊断。
- N12 物理字严格为低 120bit 的 12×signed10 加高 8bit padding。固定原 D×W 全表 36,864 值及构建前缀在 `[-388,413]`；TB 也对实际每个修改 W 的全部表值执行 signed10 admission。不能把此 admission 推广到任意 INT8 矩阵。

## 2. 五臂公平性

| 模式 | 真正执行的改动 | 与普通对照的关系 |
|---|---|---|
| 0 direct bit | 原 bit 列任务；每个活动 c 的 H96 权重行取一次，广播服务所有 P32×T10 对应行 | 具首次写省清空、整行系数复用、零 bank 门控、同预取队列及完整 PSN；不是逐事件重复取 W 的弱分母 |
| 1 LUT16 | 真源匹配后按支持码任务广播；每 H96 系数行 12 个 128bit word | 使用相同 96 路加法/PSN 资源；另付 12 个字典配置 word |
| 2 LUT10 | 同一函数与路由，仅换成 N12 精确打包，每行 8 word | 与 mode1 的差是格式和请求，不是量化误差或额外算术宽度 |
| 3 LUT10+directory | 读取本 H96 的 96B 目录；按实际非零 N12 word 请求，整零行不入队 | 额外 6 个配置请求真实发生；跳过 word 的输出系数显式置零，不会用到 payload 陈旧值 |
| 4 LUT10+response dedup | 读取本 H96 的 48B class map，在 SOURCE 合并完整 H96 响应相等的 code 路由 | 额外 3 个配置请求真实发生；这是普通静态内容去重强控制，不是新的 X |

mode4 的合并只在**同一 C16 组内**，每个源行在该组至多命中一个 code，因此 routes 的 OR 不会丢掉加法重数；不同组即使响应相同也没有跨组合并。map 比较全部 96 个整数响应，不是签名近似。代表 code 从非零模式编号选取，避免把一个全零响应误指向未存储的零模式表项。全层四 H 块 map 共 192B，当前核内只驻留 48B；不同 H 块可能有不同等价类。当前 mode4 没有兼用 mode3 目录，不能把两项收益相加。

该 mode0 支持本叶“优于普通稀疏 AAC”的结论；未证明它支配所有可能的压缩/打包/双上下文实现。所有模式运行在同一带全部功能的 RTL 中，不等于去掉附加分类器的专用 direct 电路与 LUT 电路已等面积、等 Fmax。

## 3. 端口、存储与生命周期

- 外部系数/参数 SRAM 合同是 **8 bank×128bit，每 bank 一笔在途**；地址低三位选 bank。请求只在握手后标 issued，返回才标 recv；同拍响应与新请求使用旧 pending 归属，已完成头描述符才可弹出。固定 24 word 环形池、4 个描述符，按整行保留容量，mode3 没有靠跳字免费扩容。
- 所有配置走同一实读接口。每命令启动参数字数为 mode0/1/2/3/4 的 **382/394/394/400/397**；无 BP 时对应 764/788/788/800/794 拍。最终 class map 最大地址为 8161，小于 8192 个 128bit word；固定布局仍在 128KiB 内。各 H 块参数重复装入已计费，没有假设跨命令命中。
- 最新源码将 FC、PSN `PREAD`、测试 `POUT` 的 Y 地址合成一个 `y_read_addr`，U 也用一个 `u_read_addr`；测试 Y/U 观察不另开动态存储读口。**Y 仍需每个 bank 一读一写**，因为 FC 同拍读新行并退休旧行；不能称单端口 1RW。源码是异步组合读后流水写回的行为模型，没有实测同步 SRAM 宏时序。
- 384B payload 可同拍接收最多 8 个 word，并在弹出时组合读取整行 6/8/12 个 word。它应按寄存器/有相应端口的缓冲计资源，不能仅凭 384B 容量当作普通单口 SRAM。系数另有 192B 寄存器；队列不是唯一中间状态。
- 明确可见的数据状态包括：Y 92,160B、Y valid 320B、routes 7,680B、U 5,760B、τ 5,760B、A 200B、pattern 192B、class map 48B、directory 96B、lut index 84B、flags 144B、payload 384B、coeff 192B、FC 两级结果 576B、Y hold 288B、PSN 四级 product 1,920B，另有消费者掩码/队列/控制寄存器。不能只报 128KiB 外部 SRAM 与 384B 预取池。
- 算术为 **96 路 48bit 共享 ALU**，FC 与 U 退休按阶段互斥；另有 96 路 16×24 乘法用于 PSN。SOURCE 的 96 个 16bit 匹配、popcount、优先编码/路由写入有实际组合逻辑，1 拍接受不代表逻辑免费。
- 输出停顿时 POUT 状态、行号及 Y/U/gate 保持；最后输出被接受后才 DONE。TB 核了请求地址在拒绝时稳定、bank 单在途、输出全部数据稳定与每行唯一退休。TB 每命令重置，且看到 `done_valid` 就结束、未给 done 握手；**无 reset 连续命令、跨 mode/H 块重载和 done 退休后重启尚未动态测试**，不扩大当前通过范围。

## 4. 最终收据与独立复核

`run.log` 最终为 **41 cases×5 modes×2 BP=410 tasks 全 PASS**；每任务完整检查 320×96 个 Y、U 和 gate，即三种结果各 **12,595,200 值**。其中 32 个原样真实病例只对应 8 个不同源 tile×四个 H96 块；余 3 个修改 W 探针、6 个诊断未混入性能均值或网络质量。

原样真实 32 病例累计服务（含 start、参数读取、源输入、FC、完整 PSN、输出；不含 DONE 接受）如下：

| mode | ready cycles | 相对 direct 减少 | BP cycles | 相对 direct 减少 | 系数 word 请求，两种 BP 相同 |
|---|---:|---:|---:|---:|---:|
| 0 | 256,980 | — | 284,540 | — | 12,048 |
| 1 | 184,316 | 28.2761% | 215,243 | 24.3540% | 31,776 |
| 2 | 184,184 | **28.3275%** | 212,665 | **25.2601%** | 21,184 |
| 3 | 184,568 | 28.1781% | 213,447 | 24.9852% | 21,184 |
| 4 | 184,376 | 28.2528% | 212,954 | 25.1585% | 21,184 |

mode1→2 系数请求少 1/3，但 ready 只少 132 拍；因此不能把格式字节收益当同比周期收益。原 W 的目录跳字、整行跳过和响应类别合并均无机会，mode3/4 只增配置费。ready 下三种 LUT 扩展的 PSN 都是 118,344 拍，占 mode2 总服务约 64.25%；同一函数下它不是 LUT 避免掉的工作。BP 的小差额还受固定全局周期背压相位影响，不是新的稀疏机会。

修改 W 仅是独立函数的执行探针：`variant_response_classes` 的 mode4 将 jobs 81→74、word 648→592，但 ready 总服务 5,783→5,789，仍净慢 6 拍；完整行 dedup 已实现，不能再列为未做强控制。`diagnostic_directory_holes` 的 mode3 实跳整行 14、部分 word 176，word 648→360，满足 `288=14×8+176`；ready 总服务与 mode2 同为 5,590。响应投影、普通 W 剪枝与原 W 的 gold 都分别重算；这些局部数值通过不提供 AEE 优劣。

独立复核未重启 DUT：读取 binary 原 S/D/W，逐 case/mode/BP 重建路由、完整响应类别、请求字数、jobs、zero_jobs、updates、PSN MAC 和 bank_skips，**2,460 项全同**；另外 **2,255 项服务恒等式/容量检查通过**。注意 `source_to_gate` 从首个实际接受源开始：

`cycles = 1 + boot_cycles + source_phase + fc_cycles + psn_cycles`

`words = coeff_words + boot_words[mode]`

BP 时 SOURCE 刚开始可能等 1 拍才接到首字；所以不能一律写 `cycles=1+boot+source_to_gate`。输出末拍到 DONE 可见没有另漏一个 PICK/DONE 周期，本 TB 的 `cycles` 已含接受 start 的那拍。

## 5. 能保留的结果

可以保留完整 FC1+时间 PSN 的同函数执行底座、原样真实输入下支持 LUT 的有费改善，以及 mode3/4 在当前普通 W 上无额外机会的负例。紧凑精确 LUT、零 word 元数据与相同行内容去重都属于成熟机制，当前实现完整度与数值闭环并不自动构成新的论文机制。

边界仍是 P32/H96 叶：四 H 块独立装参/重读同源，不是 H384 调度；未实现原 g→最近码投影、完整空间尺寸、FC2/BN2/shortcut、在线 BN、外存首次装载或与上游/下游重叠。旧 CPU 模型百分比、其他函数硬件百分比和该叶数字不能相乘。保留上述范围即可；本审阅没有发现需要阻止当前叶收口的功能 bug，也不要求为这些明确范围外事项继续扩实验。
