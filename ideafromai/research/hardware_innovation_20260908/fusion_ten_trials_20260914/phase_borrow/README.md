# 借用完整消费者的宽加法链：已测小幅正收益

完整C96/K864/N96/T10的原生源→Q1→Q2→FP32残差转换→BN仿射→I24。**同416bit latent口**下，一帧19200块由324025349降至310814282周期，减少**4.0772%**。这是Verilator组件服务测量，尚无综合、时序、面积、能量；结果不足以单独形成TCAS-II创新主张。

## A、B、X

A是子字并行、生命周期不重叠的资源绑定与carry分段。B是Q1工作时，已有I24后端的八条64bit加法链尚无消费者工作。候选X是把它们暂借作四P×signed13更新，随后恢复64bit仿射，完整保留RNE/饱和边界。四P是同T四个空间位置，不是偷删T10神经元计算。

`wide_phase_alu.sv`只有八条64bit carry链。`i24_consumer.sv`中的bias/identity加法被改为对该链的请求，没有另保留八份对应宽加法器。Q2仍使用八条producer32bit链与八个19×13表达式的乘法器；FP32转换及舍入的increment逻辑不属于这次复用。

两臂共享8bank×10row×52bit的z存储（520B）及416bit向量口、相同源/权重/psum/consumer状态。mode2控制每次更新两个P，整52bit字合并写回；mode3四P同时更新，carry在13/26/39断开。不能拿上一阶段208bit向量口的数作本候选同面积分母。

全帧每臂比较73728000个raw p、73728000个J和73728000个I24，全部一致。全帧仅无BP；BP和暖重启由16种小fixture及64块连续回放覆盖。128个小命令+8个64块命令+2个全帧命令，共138份结果记录。

`verify.py`独立从完整native源计算：scalar贡献23767485，两个P的union19773592，四P union15369903。多合并4403689次，每次省TIMESEL/ZREAD/ZADD的3拍，合计13211067，恰等于全帧周期差；不是用此模型替代RTL测量。全部2702条算术/计数检查通过，完整展开矩阵再次核61440个小fixture输出。

## 限制与裁决

当前materialized producer→consumer顺序下，两个请求自然不同时出现，所以无BP自然borrow conflict为零。真实grant等待通过外部wide许可停顿覆盖；这不能证明并行生产/消费时仲裁无代价。consumer优先只是已实现策略，未借此宣称任意组合皆可并行。

精度函数与上一阶段完整消费者逐值相同；没有新有损参数，故保留其同A800 valid825 AEE1.3276350、原NB0 1.4479367的已有评价，不称本项新跑825。组件回放没有整网周期或FPS。

**保留为执行底座选项，标题暂不晋级。**没有证据表明这比普通子字资源共享有足够新差分；4.08%也不足以掩盖更宽局部口和mux的时序/面积风险。新组合如果引入生产/消费重叠，必须重新解决该链的争用，不能直接把此4.08%与别项相加或相乘。

## 复现与来源

`prepare.py`→`run.py`→`run_stream.py`→`run_stream.py --full`→`verify.py`；Python使用3.12。原始输入来自上一阶段只读`r8_consumer_fusion_20260914/data/`，`fixtures`和build产物不进Git。`build_from_parent.py`保存了相对前阶段的源码生成方式，当前SV亦独立留存。

子字重构的已知强先验包括Bit Fusion/Envision；不能把carry切分本身称首创。补查[DeVSA出版页](https://www.mdpi.com/2079-9292/15/6/1296)仅取得摘要/检索片段，正文返回429，不据此断言其内部没有同类接口。[MIDAP作者项目](https://openmidap.github.io/)提供DAC2026 University Demonstration材料，完整compiler/simulator/RTL计划2027H1公开；当前不能称已复制其公开RTL。
