# 通过项的实际组合：halo＋直接消费＋宽链借用

三项已接到同一份RTL并完成19200块单帧组件回放。两臂共同具有横邻halo轮转、直接输出到I24、416bit latent口和相同状态预算；唯一比较差分仍为dualP与借用消费者宽链的四P更新。

| 范围 | 共同halo/转发，dualP | 再启用宽链四P | 周期减少 |
|---|---:|---:|---:|
| 连续64块，冷启动、无背压 | 920491 | 869734 | 5.514% |
| 连续64块，暖重启、无背压 | 918643 | 867886 | 5.525% |
| 19200块整帧组件，冷启动、无背压 | 261166493 | 247955426 | 5.0585% |

全帧两臂均实际装入14837760个源字；配置、跨行首块重新装入、源取数、身份残差、BN仿射、最终I24和末尾排空均在时间线内。每臂核对73728000个raw p、相同数量的J及I24，全部匹配。源重复读写的下降来自普通halo复用；直接消费取消p存储事务；四P借链使更新次数下降。这些差异在一份时间线上实测，没有把独立试验倍率相乘。

16种小fixture、64块跨行、背压与无reset重启加上全帧，共138条命令。[verify.py](verify.py)独立核算源义务、配对/四P更新及消费者计数；[checks.json](checks.json)记录1081项通过。全帧仅跑无背压，背压结论限小块/64块范围。基础源码与输入来自[phase_borrow](../phase_borrow/README.md)，本目录保留了实际组合源码和[生成脚本](build_joint.py)。

它是三项的相容性试验，不计为第十一条新idea，也没有建立新颖性。控制端口已经同为416bit，不能改用旧208bit端口作分母。代码中保留的mode4物化路径不是本表已测对照；mode2/3没有p_mem事务，但未综合，不能宣称面积已经删除。宽链在Q1与消费者之间按现有先后阶段复用，尚未证明能无代价叠入另一目录的双context并行执行。

结果属于隔离Verilator组件周期；无新网络函数、无新训练、无PPA/整网FPS。复现：`prepare.py`、`run.py`、`run_stream.py`、`run_stream.py --full`、`verify.py`，使用Python3.12。
