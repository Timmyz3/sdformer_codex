# 当前 C1/C2 的独立判断与一个值得检验的研究假说

日期：2026-09-05。

状态：`RESEARCH_HYPOTHESIS_ONLY_NOT_VALIDATED`。无实测收益，无原创性保证，不是启动实验的指令。

## 1. 独立判断：先解决创新性，不是继续包装

当前 C1/C2 的主要问题是独立创新论证不足。不能据此认定抄袭或实现者没有理解 prior art；但已有验证投入也不能替代贡献成立的证据。

### C1：受约束实现不自动等于新架构

Prosperity 已经提出公共子组合、parent/residual 复用和依赖调度。C1 的单口仲裁、转发、死写抑制和原子完成具有工程价值，但还需要回答：

> 在同样合理的有限存储和接口条件下，已有 product-reuse 实现遭遇了什么重要问题？C1 用什么非显然机制解决？

仅报告相对 zero-skipping 的提升，不能单独证明相对已有 product-reuse 方法的新贡献。不能把 Prosperity 泛称为“无限容量设计”，必须读取其实际 tiling、buffer 与调度结构再比较。

审阅的期刊稿中，“strongest-zero 仍走 parent-state traffic”的叙述也值得审计：不做 parent reuse 的独立高效基线为什么需要这些访问？这只是基线审计问题，不是已经判定其实现不公平。

来源：[Prosperity，HPCA 2025 正文](https://arxiv.org/html/2503.03379v1)。

### C2：循环交换、广播和避免重复控制器属于强近邻区域

当前稿件已承认 group-major order、weight reuse 和 broadcast 并非新原理。K8 比 K1×8 少复制状态和控制器，也不代表胜过合理设计的共享多输入归约单元。

“typed-signed”目前主要证明协议与算术覆盖。审阅稿件说明，自然非零 descriptors 均为 +1，负号由 directed tests 单独覆盖。这不能支持“真实工作负载需要一种全新的 signed 架构”的强动机。

即便 power、hold、更多 workload 闭合，首先得到的是更可信的实现，不会自动得到更强的新颖性。

### 研究策略

将 C1/C2 降为可复用的基线与验证基础，允许新机制取代旧的两岛故事。不删除既有成果，不打断已运行任务；本建议也不授权停止进程或修改现有工作。

## 2. 首要假说：动态公共部分和的选择性构造与广播

核心问题：

> 哪些 source 被相同的一组 token 使用？能否先将其权重向量归约一次，再把结果送给这些 token，而不是仅共享权重读取？

这一机制改变执行的算术图，而不仅是 token-major/source-major 顺序。

### 2.1 一个没有完整 subset parent 的例子

设 a 到 h 是同一合法线性算子中的权重向量，四个独立 token 的结果为：

```text
y0 = a + b + c + d
y1 = a + b + e + f
y2 = c + d + g + h
y3 = e + f + g + h
```

只考察这四个输入行：它们互不包含，且四行公共交集为空。当前以完整输入行为候选的 subset-parent 方法无法在这四行内找到非空 parent；这不意味着更大 tile 中也一定没有 parent。

可构造：

```text
u = a + b      v = c + d
w = e + f      z = g + h

y0 = u + v     y1 = u + w
y2 = v + z     y3 = w + z
```

按普通二元向量加法计数，前者需要 12 次，后者需要 8 次。这个计数不含先前 accumulator、读写、路由、建组和退休成本，绝不是周期、能量或系统加速比。

TSBG 已可将 a 到 h 各读取一次。因此这里不能再把读取复用重复记为新机制的收益；新增机会是公共归约的复用。

### 2.2 目的掩码表示

对 B 个 token，令 S 为当前 B×K 二值 source 矩阵，W 为 K×N 权重矩阵，Y=SW。

第 j 个 source 的目的掩码为 m_j=S[:,j]。将非零列按相同掩码 m 归组：

```text
G_m = { j : S[:,j] = m }
U_m = sum(W[j,:] for j in G_m)
Y[c,:] = sum(U_m for m with m[c] = 1)
```

每个 source 只属于一个组。B4 二值输入最多有 15 种非空掩码，可以直接编码，不需要以完整输入行做两两 subset 搜索。

“目的地址不同”意味着需要保持独立 accumulator、tag 和 retirement，不意味着所有中间数值都必须独立计算。对 SNN 而言单项乘积只是 W 或 -W，单独共享该项本身价值很小；真正的研究对象是多个项的归约结果。

### 2.3 signed 边界

以上首个假说针对真实捕获中的二值输入，不用合成负号制造主要收益。

若未来扩展到 {-1,0,+1}，可以研究完整 signed 目的向量的分组；B4 非零签名上限成为 3^4-1=80，不再是 15。将相反签名规范化还需要额外符号变换、位宽和 overflow 证明，不能直接沿用二值结论。

不同 context 的最终状态、目的地址和 commit 仍然独立；不能跨非线性、时间依赖或不兼容量化尺度合并。

## 3. 查重结果：数学思想不能宣称原创

上述按列模式聚合、再分发的分解与 Mailman algorithm 直接相关。该算法将有限字母矩阵分解为模式矩阵和列到模式的对应关系，以先聚合后分发计算矩阵向量乘积。

来源：[Liberty 与 Zucker，The Mailman algorithm: a note on matrix vector multiplication，作者原文](https://cs.yale.edu/homes/el327/papers/mailmanAlgorithm.pdf)。

因此不能把“列签名分组”或 SW 的代数分解作为新数学原理。需要进一步检查硬件实现、在线公共子表达式消除，以及 SNN 局部共享基向量设计。

近邻关系：

| 工作 | 主要对象 | 必须验证的差异 |
|---|---|---|
| Prosperity / 当前 C1 | parent 及残差结果 | 是否确实能覆盖其完整输入行 parent 之外的重要机会，且总开销更低 |
| 当前 TSBG | 权重读取与传输 | 在已共享读取的强基线上，公共归约还能带来多少净收益 |
| Phi | 预定义模式及残差 | 在线局部构造是否确实减少模式结果存储与访问，而不增加更大控制成本 |
| Comperity | 相邻行共享基向量与差分 | 需全文核对其分组、公共子组合与 datapath，不能只凭摘要声称不同 |
| Mailman | 有限字母矩阵的列模式分解 | 动态输入、有限硬件、并行 bank 下是否存在真正新的实现机制 |

Comperity 已核到出版方提交的题名和摘要，ACM 全文访问受阻。本记录不声称完成其实现级比较。

来源：[Comperity 出版方摘要记录](https://api.crossref.org/works/10.1145/3828526)，[Phi 正文](https://arxiv.org/html/2505.10909v1)。

## 4. 可能值得设计的硬件，不是“全部模式桶”

直译为“先逐源更新桶，再逐桶分发”可能更慢。研究重点应是选择性物化公共部分，而不是无条件建立全部桶。

### 初始设计约束

- 单消费者的组不建立跨 token 共享结果。
- 单 source 的组保留普通权重广播，不另建部分和。
- 只允许有限个同时存活的共享组；容量、有效位、清理和分发队列必须记账。
- 状态生命周期限定在当前局部任务，不依赖跨任务命中和长 parent 链。
- 以共享同一套加法／累加资源为优先设计假说，不能只通过增加第二套 PE 获得周期优势。
- 同拍多 bank 返回时，分类、同组归约、分组结果暂存和消费者发射必须在明确端口约束下实现。
- 分发必须遵守 accepted handshake；stall、reset、stale response 和 final commit 不能污染共享状态。

### 机会判据，不是 PPA 模型

若某组含 k 个 source、服务 m 个消费者，在“每次向已有 accumulator 加入一个向量”的抽象计数下，普通路径有 km 次更新；构造共享和需 k-1 次加法，再有 m 次消费者更新。

```text
粗略算术差值 = km - (k-1+m) = (k-1)(m-1)
```

该式不含零初值赋值优化、归约树吞吐、位宽差异、构造与分发重叠、SRAM 端口及路由成本，只能识别候选。实际入选条件应是同一硬件服务模型下的净成本更小，不能用此公式推导 speedup。

### 位精确性边界

整数加法的重组只有在中间位宽、overflow、舍入和饱和语义全部满足时才成立。保持 Acc24 终态语义；共享部分和需要重新证明上界。不能把此整数线性算子证明推广为 frozen FP32 全网络的逐位等价，也不能跨 ATLIF 非线性或改变其时序状态。

## 5. 自我反驳与淘汰条件

### 反例 A：只有稀疏，没有相关性

若绝大多数非空目的掩码只服务一个 token，或每个多消费者掩码只出现一次，则共享归约几乎无机会。5.6709% 全局 firing 不能替代按层、按任务的联合模式统计。

### 反例 B：算术数量减少，但时钟周期增加

K8 已能并行归约一组输入。少几个加法不代表少一拍；串行构造共享组后再分发可能更慢。必须比较平衡归约树、相同吞吐和相同资源预算，不能与低质量串行链比较。

### 反例 C：共享状态比重算更贵

部分和写回、读出、选择和广播可能超过重新做窄位宽加法的能量。硬件需要支持不物化，但 fallback 本身也有面积、控制和延迟成本，不能因此保证“永不回退”。

### 反例 D：研究点被近邻完整覆盖

如果近邻已有同样的在线分组、有限状态和归约分发机制，且我们没有额外可证明的重要差异，则不能靠换名称建立新贡献。

## 6. 后续验证门槛（仅建议，未执行）

1. 查重：完成 Mailman、Comperity、Prosperity、Phi 与相关在线归约实现的逐项对照。
2. 固定抽样规则：在真实 ep34 工作负载上统计多 source、多消费者的签名组；保留全零、单播、低复用与最差任务。
3. 机会先行：报告构造次数、消费者更新次数、组存活量、数据读写量及关键层覆盖；不给未知 SRAM/RF 免费端口或零成本。
4. 强基线：当前公平 TSBG、合理的流式多输入归约，以及适用的 product-reuse 实现；不是只比较重复读取或复制八套控制器的实现。
5. 若公平的乐观上界都不足以支持架构变化，立即淘汰，不进入 RTL。
6. 若上界可观，再建立有限 bank／端口／资源周期模型。容量、队列、建组与清理成本不能后补。
7. 只有用户明确授权后，才以新 namespace 开始 RTL、精确校验及商业工艺 PPA。不得复用已失败实验身份，不抢其他 session 的 lock。

## 7. 当前建议

这是当前唯一优先检验的具体架构假说，不是已经确定的投稿主线。前序的小模式表、无损压缩、融合累加器和窗口重组保留为备选，不同时开工。

先允许旧故事被证据推翻，再决定新硬件。若该假说不成立，应换方向，不以更多实验数量替代创新性。
