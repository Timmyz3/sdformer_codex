# Local5 当前单顶层合成 T450 部署壳与检查点边界

## 1. 本轮结论

本轮将已经通过通用小规模验证的 Local5 单顶层参数化到当前 full-resolution
attention 窗口几何：

```text
H=15, W=15, T=2, TOKENS=450, HEAD_DIM=32, OUT_DIM=2
```

当前顶层数据流为：

```text
binary Q/K + invalid-candidate mask
  -> Q7 alpha-XNOR Local5 score
  -> hardware-order Shiftmax5 Q1.7
  -> destination-major relation transpose
  -> source-major gate-equivalence term
  -> TCFM-5 projection
  -> five-bank Acc32
```

得到以下结论：

- `[rtl]` 当前单顶层已在 `H15xW15xT2=450` 几何下完成 450 个 descriptor、
  19191 个 term、33954 个 destination update 和 900 个 Acc32 的完整执行；
- `[rtl]` 独立 Python oracle、Icarus 和 Verilator/SVA 的工作量与全部 Acc32
  一致，失配为 0；
- `[rtl]` 固定种子 term 反压命中 2724 个可发边界，未改变 term、update 或
  Acc32；
- `[rtl]` `OUT_DIM=32` 生产输出宽度 smoke 完成 14400 个 Acc32，输出地址、
  1024-bit Acc vector 和 1024 项权重覆盖账本均被实际执行；32 个输出列使用
  非退化权重，Python 检查确认 32 组输出列向量互不相同；
- `[rtl]` 三组 Q/K 数据种子、三组 LFSR 反压种子、首 term 全停、长 burst
  和 run-final term 定向停顿全部由 Icarus 与 Verilator/SVA 交叉执行，并保持
  工作量与 Acc32；
- `[rtl]` 等五 bank 的 Linear-5 RTL 使用完全相同的输入、权重和工作量，
  TCFM-5 在本合成向量上减少 23.91% tile 周期；
- `[模型]` Yosys 参数化、层次展开和 `check -assert` 通过，只有开放逻辑结构
  统计，不是 ASIC PPA；
- `[待验证]` 当前向量不是最终 equal-plus10 checkpoint 的真实 fullres trace，
  也没有绑定最终 theta-folded 权重、配置与 payload SHA。

本工作包补的是 Local5 的部署几何、地址宽度、存储深度、close/drain 和反压
完整度，不新增 DATE 架构贡献。

## 2. 为什么需要单独做 T450

通用顶层此前主要在 `H3xW6xT2=36` 下验证。参数化 RTL 虽然理论上支持
`H15xW15xT2`，但以下错误只可能在部署尺度暴露：

1. `source_id`、plane 恢复和 `H*W` 边界在 9-bit 地址下截断；
2. relation transpose 的 450-entry 驻留深度和 raster retirement 越界；
3. 最后一个 descriptor、最后一个 term 与 `projection_close` 相序错误；
4. 大量 term 反压时 builder、backend 与 accumulator 没有完全 drain；
5. 参数化后综合层次或 memory inference 失效。

因此，本包不是重复小例，而是当前生产几何的控制与存储回归。主周期对照仍用
`OUT_DIM=2` 的可审计 projection head-slice；另以 `OUT_DIM=32` 运行完整 Python
到 Acc32 smoke，覆盖 5-bit 输出地址、1024-bit bank word 和 32x32 权重空间。
OUT32 运行用于几何与协议覆盖，不与 OUT2 周期混为同一 PPA 点。

## 3. 独立 Python 全链 oracle

生成器：

```text
scripts/generate_local5_t450_fullchain_oracle.py
```

固定种子：

```text
0x45052026
```

Python 不读取 RTL 的中间结果，而是独立执行：

```text
Q/K bit vectors
  -> exact Q7 score
  -> exact integer Shiftmax5 Q1.7
  -> relation transpose
  -> source/lane/gate term formation
  -> deterministic INT8 projection
  -> Acc32
```

输入包含窗口边界非法候选、额外运行时 invalid mask、全零和全一事件极值，
并保证相同 source 的 K 在不同 destination 关系中一致。生成账本为：

| 项目 | 数值 |
|---|---:|
| input descriptor | 450 |
| Acc32 output | 900（OUT2 主对照）/14400（OUT32 smoke） |
| product term | 19191 |
| destination update | 33954 |
| Acc32 mismatch | 0 |

这里的 `synthetic` 只表示 Q/K 和 INT8 权重由固定种子生成，不表示金参考由 RTL
日志反推。Python 与 RTL 是两套独立执行路径。

## 4. RTL 结果

一键入口：

```text
sim_qfit/run_qfit_local5_projection_t450_shell_checks.sh
```

结果目录：

```text
results/qfit_local5_projection_t450_shell_20260809/
```

### 4.1 无额外反压

| 后端 | tile 周期 | relation stall | descriptor | term | update | Acc32 |
|---|---:|---:|---:|---:|---:|---|
| TCFM-5 | 19835 | 7935 | 450 | 19191 | 33954 | 零失配 |
| Linear-5 | 26069 | 11010 | 450 | 19191 | 33954 | 零失配 |

在这一组固定合成 T450 向量上：

```text
(26069 - 19835) / 26069 = 23.91%
```

该结果是 `[rtl]` 的单向量周期证据。它说明 TCFM-5 在当前真实顶层接口下没有
被前端控制开销完全抵消，但不能外推为真实 Local5 网络平均加速。

### 4.2 固定种子反压

| 项目 | 数值 |
|---|---:|
| LFSR seed | 17717 |
| tile 周期 | 22524 |
| issue stall cycle | 2748 |
| term 边界命中 | 2724 |
| descriptor/term/update | 450/19191/33954 |
| Acc32 mismatch | 0 |

Icarus 与 Verilator/SVA 的 22 项完整结果 tuple 相同。反压增加周期，但没有丢失、
重复或重排有效工作。附加覆盖为：

| 类型 | 配置 | 结果 |
|---|---|---|
| Q/K 数据种子 | `0x45052026/27/28` | 全部 Python-to-Acc32 零失配 |
| LFSR term 反压 | `1/17717/48879` | 全部工作量保持、命中可发边界 |
| 首 term 全停 | 首个 valid term 连续停 64 cycle | 65 个阻塞命中，零失配 |
| 长 burst | 32 cycle stop/32 cycle release | 19622 个阻塞命中，零失配 |
| run-final term | 最终 source 的最后 term 停 32 cycle | 33 个阻塞命中，零失配 |

三类定向反压均由 Icarus 与 Verilator/SVA 交叉执行。

### 4.3 回归门槛

`status.tsv` 只有在报告解析、工作量交叉核对、Acc32 miter、Yosys 检查和 SHA
自校验全部完成后才生成。本轮为 `7/7 PASS`：

1. synthetic T450 Python-to-Acc32 Icarus/Verilator-SVA；
2. fixed-seed backpressure cross-simulator；
3. multi-data-seed and directed-stall regression；
4. OUT32 Python-to-Acc32 production-width smoke；
5. Linear-5 equal-bank RTL baseline；
6. Yosys parameterized and memory-contract check；
7. oracle/source SHA-256 self-check。

共冻结 8 个 oracle 文件和 28 个 RTL、断言、TB、脚本文件的 SHA-256，校验结果
全部为 `OK` `[rtl]`。

## 5. Yosys 结构代理

| 指标 | 数值 |
|---|---:|
| generic cells | 14798 |
| wire bits | 150052 |
| `$mem_v2` | 23 |
| Acc memory | 5 个 `90x1024 1R1W` |
| Relation K memory | 1 个 `45x32 1R1W` |
| Relation gate memory | 5 个 `45x10 1R1W` |
| Weight row memory | 1 个 `32x256 1R1W` |

Yosys 除了 `check -assert`，还导出结构化 netlist；报告脚本将 memory 的数量、
深度、位宽和读写端口作为 fail-closed 门槛。该检查用于确认 OUT32/T450 参数化后
仍可综合、关键存储没有因越界被优化掉、层次内无未驱动结构错误。它没有目标
standard-cell library、SRAM macro、SDC、SAIF 和布线寄生，因此只能标为
`[模型]`，不得写成面积、频率、功耗、能量或 PPA。

## 6. 与最终 checkpoint-bound 签核的边界

本包不能替代最终部署签核。正在等待的 equal-plus10 rank-1 checkpoint 释放后，
必须在同一 checkpoint 上补齐：

1. 冻结每个 block/head 的 theta、Q7、Q1.7 和真实 invalid-candidate mask；
2. 记录 checkpoint、配置、源码、trace 和 theta-folded payload SHA；
3. 导出真实 full-resolution `H15xW15xT2` 多窗口 trace；
4. Direct 与 TCFM-5 使用同一真实权重做逐 Acc32 miter；
5. 报告多 sample/window 的 cycle、stall、term cardinality 和 bank utilization
   mean/p95/p99；
6. 加入可变 SRAM latency、读返回乱序约束和下游 Acc32 反压；
7. 最终在另一台服务器完成同约束 DC/STA/SAIF/PTPX。

旧的 Local5 T450 分量回归和旧 checkpoint 结果只能证明模块历史可工作，不得
替代本轮最终 rank-1 的重新绑定。

## 7. 双线范围

Local5 当前优先级是补系统完整度，但这不意味着 Motion 停止。双线范围为：

- Local5：优先完成 checkpoint-bound T450、12-block 时间复用调度和真实 SRAM
  时序闭环；
- Motion：保持现有 SCS/NMF/DCTF/RQTB 回归，同时允许基于真实 Motion workload
  扩展有强基线、可 bit-exact 的新机制；
- 两条线的新机制都必须先给出 workload 上界、等资源基线和预期收益，再进入
  RTL，不能用模块数量代替架构新颖性。

## 8. 当前允许引用的结论

可以写：

> Local5 当前单顶层在 H15xW15xT2 部署几何下完成了从二值 Q/K、整数
> Shiftmax5、relation transpose、source-major term 到五 bank Acc32 的独立
> Python/Icarus/Verilator 等价回归，并在固定种子反压下保持工作量与 Acc32
> 不变。

不能写：

- “Local5 fullres checkpoint-bound RTL 已完成”；
- “TCFM-5 在真实网络上加速 23.91%”；
- “Local5 ASIC 面积为 7867 cells”；
- “当前已完成 full encoder 或 12-block 调度”；
- “本轮 T450 参数化本身是 DATE 架构贡献”。

## 9. 独立 DATE 包级评审与整改

### 9.1 第一轮

独立审稿人只读取本包及其直接 RTL/TB/脚本/结果，不按历史工程量加分：

- 评分：`3.0/5`；
- Recommendation：`Major Revision`；
- `P0=0`；
- 认可 Python/Icarus/Verilator 数值账本和 OUT2 周期对照真实；
- 不允许关闭的 P1 是 OUT2 未覆盖生产输出地址、term 反压范围过窄，以及
  Yosys 没有自动核对 memory 深度/位宽/端口；
- P2 是数据/反压单种子和旧哈希清单歧义；
- 明确本包没有 DATE 架构新颖性。

### 9.2 本轮整改

对应整改如下：

1. 新增 `OUT_DIM=32` Python-to-Acc32 smoke，14400 项零失配；
2. 新增三组数据 seed、三组 LFSR seed 和三类定向 stall；
3. Yosys 导出 netlist，报告 fail-closed 核对 5 个 Acc memory 与 6 个 relation
   memory 的数量、深度、位宽和 1R1W 端口；
4. runner 启动时删除旧 `oracle_sha256.txt/source_sha256.txt`，当前目录只保留
   `oracle_hashes.sha256/source_hashes.sha256` 两份有效清单。

整改后的包必须再次接受独立审阅。在复审允许关闭前，不将其状态写成 signoff。

### 9.3 第二轮复审

第二名独立审稿人在第一轮整改后仍给出：

- 评分：`3.0/5`；
- Recommendation：`Major Revision`；
- `P0=0`；
- P1-1：OUT32 虽然跑通，但旧权重的 32 个输出列退化为相同值，无法检出
  output-address alias；
- P1-2：并非所有数据种子与反压种子都同时经过 Icarus 和 Verilator；
- P1-3：旧 Yosys netlist 中权重被识别成 `1024x8`、32 读口和 1025 写口，
  不能视为可实现 SRAM 合同；
- P2：结果目录仍残留过期的固定种子反压日志，存在证据歧义。

该复审指出的是验证可辨识性和存储实现合同问题，不是表述问题，因此不能只改
文档，必须修改 oracle、RTL 存储组织和回归矩阵。

### 9.4 第二轮整改

本轮完成以下实质整改：

1. Python 与 TB 的 INT8 权重统一改为 lane/output 联合非退化公式；报告脚本独立
   验证 OUT32 每列 450 个 Acc32，确认 32 个输出列向量互不相同；
2. 三组数据种子、三组 LFSR 反压种子以及三类定向停顿均在 Icarus 与
   Verilator/SVA 上交叉执行，报告脚本逐项比较完整工作量 tuple；
3. 四个 projection backend 的权重从带复位的二维 scalar array 改为
   lane-row 存储；主 TCFM-5 Yosys netlist 现在必须且仅允许出现一个
   `32x256 1R1W` 权重 memory；
4. runner 启动时删除旧固定种子日志；报告脚本将过期文件存在本身视为失败；
5. 修改后的通用小几何包重新执行 `12/12 PASS`，其 33 个源文件哈希全部通过，
   防止 T450 修复破坏既有单顶层回归；
6. T450 包重新执行 `7/7 PASS`，8 个 oracle 与 28 个源文件 SHA-256 自校验通过。

当前证据仍是 `[rtl]` 合成 T450 部署壳与 `[模型]` Yosys 结构代理。是否允许关闭
本工作包，仍由下一轮独立复审决定；即使包级关闭，也不等价于 checkpoint-bound
Local5、12-block encoder 或 ASIC signoff 已完成。

### 9.5 第三轮独立关闭评审

新的独立审稿人逐项重算 OUT32 权重、交叉比较全部仿真结果并直接解析 Yosys JSON
后给出：

- Recommendation：`Accept`；
- 包级评分：`4.0/5`；
- `P0=0，P1=0`；
- 允许关闭“合成 T450 部署壳验证包”。

审稿人确认：

1. OUT32 每个输出列均有 32 个非退化权重，32 个列向量互不相同；Icarus 与
   Verilator 的完整结果 tuple 一致；
2. 三组数据 seed、三组 LFSR seed 和三类 directed stall 均完成跨仿真器比较；
3. Yosys JSON 中精确存在一个 `32x256 1R1W` weight memory、五个
   `90x1024 1R1W` Acc memory 及约定的 relation memory；
4. 旧日志与旧哈希命名已经清除，当前 source `28/28`、oracle `8/8` 校验有效；
5. synthetic、checkpoint-bound 与 Yosys 非 ASIC PPA 的证据边界明确。

两个 P2 不阻断本包关闭：Verilator 摘要行没有打印 OUT_DIM，且结果日志/Yosys
JSON/报告自身尚未纳入一个可搬运 manifest。它们进入后续可复现性清单，不改变
本包功能结论。

因此本包状态冻结为“包级关闭”。该状态不代表 checkpoint-bound Local5、真实
fullres 多窗口、Direct/TCFM-5 同 checkpoint miter、12-block/full encoder、
SRAM macro、DC/STA/SAIF/PTPX、形式验证或覆盖率关闭。
