# H81 G0 与 Local5 创新筛选收口

日期：2026-08-16。本文不修改 `docs/359`，不新增 H81 RTL，不改变封存性能列。

## 1. 本轮裁决

| 线 | 当前裁决 | 可安全主张 | 仍禁止主张 |
|---|---|---|---|
| Motion/H67 | 冻结新机制，保留维护与服务器 PPA 主线 | H67 冻结身份下 RQTB 公平 RTL `112589/94891=1.1865x` | 不能把该周期、VCD、PPA 或 MSSB5 搬给 H81 |
| H81 | `G0_PASS_G1_BLOCKED_BY_SELECTOR_AND_MVSEC_FAIL` | H81 workload 适合 exact pair quotient，且 attention-core hardware-order 数值门通过 | MVSEC 四序列门已失败；不是 H81 RTL、cycle、energy 或 PPA |
| Local5/ep44 | 保留既有一条数据流；新系数融合 NO-GO | `QS -> compiled inverse-stencil/FCSR -> source-owned unique-gate -> TCFM5` | 不把 QAT、系数融合、cache/Memo 或 2-wide 包成新 DATE 贡献 |

## 2. H81 no-RTL G0 证据

冻结 checkpoint SHA：
`8825c933e4911b6a91c036a56c45870ac1280dda2e741c40215426b82ff188e2`。

十样本 ordered profile：

- pair-score equal ratio：`98.1184%`；
- modeled RQTB slot reduction：`49.0592%`；
- 分 stage equal ratio：S0 `99.9246%`、S1 `99.7269%`、S2 `96.7774%`、S3 `89.3938%`。

该全体 equal ratio 必须拆开解释：四向量全零 pair 占 `68.6273%`；由于全零必然
score-equal，剔除这些 pair 后，非空 pair 的 exact equal ratio 为 `94.0025%`，对应
nonempty-only slot reduction `47.0013%`。分 stage 非空 equal ratio 为 S0 `99.7409%`、
S1 `97.6048%`、S2 `91.8426%`、S3 `84.2046%`。因此 H81 仍有较强的非空同分结构，
但 `98.1184%` 不能写成纯时间冗余或新创新，只能作为包含大量空 pair 的 workload 统计。

同一 ordered count trace 的 score fractional-bit 只读敏感度如下；QF7 在 120/120
record 上与封存 `pair_score_equal_ttx` 逐条一致：

| score precision | all-pair equal | nonempty equal | modeled slot reduction |
|---|---:|---:|---:|
| QF5 | 99.6755% | 98.9656% | 49.8377% |
| QF6 | 99.5903% | 98.6942% | 49.7952% |
| QF7 | 98.1184% | 94.0025% | 49.0592% |
| QF8 | 93.9203% | 80.6210% | 46.9601% |

该表只证明同分率随 score 精度变化。QF5/QF6 没有对应 valid825 accuracy，也没有 RTL，
不能因为同分率更高就选作部署位宽；当前通过 hardware-order accuracy gate 的仍只有 QF7。

valid825 attention-core hardware-order：

- 825 samples；config/checkpoint/load/protocol/deployment checks 全部通过；
- float AEE `1.3305971`；hardware-order AEE `1.3289528`；相对变化 `-0.1236%`；
- 准入状态：`PASS_H81_HARDWARE_ORDER_ACCURACY_GATE`。

可复用对象仅限：pair quotient、multiplicity-aware normalization、K recovery、双 slot
公平壳和验证方法。不能复用的 H67 特化包括 MSSB5、Motion-XOR、时间极性叙事，以及
所有 H67 周期/活动/PPA 数字。

H81 同协议 MVSEC full-sequence 的 mean AEE 为 `1.792591`，但四序列全优于 NB0 的门
失败：`indoor_flying1` 为 `1.624761`，NB0 为 `1.599827`。该 MVSEC checkpoint SHA
`31facb69...` 是 NB0 初始化的 CICC day2，与 DSEC G0 `8825c933...` 不同，不能合并身份。

H81 G1 的硬门现为：新训练重新通过 MVSEC 四序列门、算法 selector 选中 H81，然后补
H81 Fixed2S/RQTB 公平 RTL 与真实 INT8 Acc32。前两项未通过前不写 H81 生产 RTL。

## 3. Local5 系数融合被同端口强基线否决

候选按 destination 完成五邻域系数：先形成每个 `(destination,lane)` 的整数系数，再做
一次 `coefficient * W`，理论上可减少部分和 SRAM commit。

ep44、100 group、OUT_DIM=2、真实 INT8 权重数值 miter：

- Acc32 `90000/90000`，mismatch `0`；
- source-owned product terms：`48769`；
- coefficient product terms：`108726`，为 `2.229x`；
- 100/100 group 均没有减少 product term；
- source partial updates `147383`，但候选仅在理想本地累加下可降到 `12752` 次 destination commit。

生产 TCFM5 每拍至多接收一个 OUT2 product term。在相同 product 端口下，即使把现有
`17218` 个 `memory_wait` 全部乐观视为候选可消除，候选仍净增加 `42739` 个 service
cycle；additive proxy 为 `283664 -> 326403`，即 `0.869x`。该模型未计 coefficient
build、scratchpad、commit 和控制开销，因此已经偏向候选。

裁决：`NO_GO_SAME_PRODUCT_PORT_NO_RTL`。若靠拓宽 multiplier 才翻盘，就改变了面积和
端口合同，不能视为该 exact 变换在同资源下成立。

## 4. 创新分与下一步

| 线 | 创新 | 验证 | 完整度 | 综合 |
|---|---:|---:|---:|---:|
| Motion/H67 | 3.2 | 4.8 | 3.2 | 3.1 BR |
| Local5/ep44 | 3.1 | 4.8 | 3.3 | 3.1 BR |
| H81 | 2.8（预评） | 3.7 | 2.6 | 2.7，非投稿对象 |

Local5 当前算子下，继续 cache、码本、2-wide、第三 stencil、近似剪枝或分配律换序，均不会
产生新的 exact 物化对象。要把创新从 3.1 推到 4.0，下一步必须来自新的算法算子合同，且要
同时改变硬件存储/执行对象；不能再从现有 RTL 中拆分工程模块计数。

本机后续只做身份、回归、活动合同和服务器 handoff。Synopsys DC/STA/SAIF/PTPX 仍在另一台
有目标库服务器执行；现有封包不因本轮 sidecar/G0 重打。
