# H67 主线切换与增量 RTL 设计验证

## 1. 当前结论

当前应把 **H67 Motion-XOR TTX 升级为精度优先的软件候选主线**，但不能立即删除 TTX RTL
和部署基线。H67 epoch19 已通过 full30 与 standard valid825：AEE `1.4671`、AAE `9.4155`、
spikes `26.3898G`。相对 NB0，AEE 改善约 `1.35%`，spikes 下降约 `40.1%`；相对 TTX float，
AEE 改善约 `2.2%`。epoch4 是效率点：AEE `1.4896`、spikes `24.2416G`。

仍需保留两个条件：

1. H67 epoch19 的统一 dyadic score/gate valid825 尚未完成，当前等待 H68 释放 GPU；
2. attention 新增 XOR/popcount 和时间对读取尚未进入 DC/后端功耗，`spike_energy_proxy` 不能代表总能耗。

因此主线状态定义为：

- **算法精度主线：H67 epoch19**；
- **算法能效点：H67 epoch4**；
- **硬件保底基线：TTX dyadic**；
- **硬件替换条件：H67 dyadic valid825 通过，且综合后总能效不劣于论文预算**。

H73 DE9、H74 MC49、H75 AX17 目前只有配置和加载审计，没有 full30 结果，不能替换 H67，也不应
提前实现 9/17/49-offset halo、codebook SRAM 和投影阵列。它们胜出后只替换本报告定义的 score/
descriptor 前端，ATLIF、调度和后端仍复用。

## 2. 软件公式与 RTL 整数公式

软件代码对 `T=2` 同空间位置的 K 做时间配对：

```text
motion = popcount(K_current XOR K_peer)
score_float = (overlap + same_zero/64 + motion/4) / 32
score_q7 = round_even(128 * score_float)
```

在冻结参数 `head_dim=32`、`alpha0=1/64`、Motion-XOR 权重 `1/4`、score step `1/128` 下：

```text
base_integer = 4*overlap + motion + floor(same_zero/16)
score_q7 = base_integer + RNE_increment(base_integer, same_zero mod 16)
```

所以 Motion-XOR 在 Q7 域是直接加 `motion`，不是 `motion >> 2`。历史文档中的右移只适用于
归一化前原始分数域；若在 Q7 RTL 中继续右移，会把 H67 项缩小四倍。

RTL 显式对完整分数实现 round-to-nearest-even。tie 时必须同时看 Motion-XOR 的奇偶性：例如
`motion=0,same_zero=8` 时 `0.5 -> 0`，而 `motion=1,same_zero=8` 时 `1.5 -> 2`。
独立参考审计穷举 `35,937` 组计数组合，并检查 `100,000` 组随机 32-bit 向量，中心化前分数
不一致为 `0`。

这里不能扩大成“整行 bit-exact”。当前软件部署顺序是 `center_scores -> 1/128量化`，RTL 复用
TTX 路径时是“原分数量化后，利用 Shiftmax 平移不变性省略 center”。round-to-nearest-even 在
半格点不具平移不变性：若 162-token row 中 Q7 原分数 `0/1` 各81个，软件中心化后两类都舍入为
`0`，当前 RTL 仍保留`0/1`。正式冻结前必须增加 hardware-order valid825：先量化原分数，再省略
center 或只做不再量化的 center；该顺序仍保持 Shiftmax 数学平移不变性。

## 3. 增量数据流

```text
Q_current[31:0] ───────────────┐
                               ├─ overlap/same-zero ─┐
K_pair={K1,K0}[63:0] ─ pair ──┤                     ├─ H67 Q7 score
                               └─ K_current XOR K_peer ─ popcount ┘
                                                               │
                  ┌────────────────────────────────────────────┘
                  v
        row max -> exp2 LUT -> power-of-two denominator -> gate_q8
                  │
                  └─ gated-K late accumulation -> 原投影/ATLIF
```

输入按照同空间 token/head 的 `{K1,K0}` 64-bit 时间对常驻。`time_sel` 只交换 current/peer，
不重新访问另一时间片 SRAM。该布局同样支持 TTX 和未来 Exact Delta-TTX；它改变调度，不改变容量。

## 4. 精确 Score-Class Folding

旧 TTX 的零 K 折叠键是 `q_active`。H67 中若 `K_current=0`，分数还依赖 `K_peer`，继续按
`q_active` 合并会错误改变 Shiftmax 分母。

H67 改用最终 Q7 score 作为折叠键。零 K 时：

```text
score_q7 = round_even(popcount(K_peer) + (32-q_active)/16)
```

其严格范围只有 `0..34`。硬件使用 64-entry 物理数组、35 个合法 score 类；分母阶段固定扫描
`0..34`，并在读取后清零。与旧 TTX 固定扫描 33 个 q-active 类相比，每个存在折叠 token 的 row
只增加 2 个 class-scan 周期，不需要 256 类直方图，也不需要类列表或多端口清理网络。

建议论文暂命名为 **Temporal-Pair Score-Class Folding，TPSF（时间对分数类折叠）**。可声明的
贡献边界是“针对 H67 dyadic score 推导 35 类精确折叠并保持 Shiftmax 分母”，不能泛化声称为任意
attention 的通用压缩。

## 5. 新增与复用模块

| 模块 | 状态 | 作用 |
|---|---|---|
| `h67_temporal_pair_adapter` | 新增 | `{K1,K0}` 与 current/peer 选择 |
| `h67_motionxor_score_q7` | 新增 | overlap、silence、XOR popcount 与 RNE Q7 合成 |
| `h67_score_class_row_engine` | 新增封装 | 35 类 TPSF；复用原 exp2/denominator/gate 数据流 |
| `h67_attention_top` | 新增封装 | 复用原 12-block descriptor scheduler |
| `ttx_exp2_lut_q8` | 复用 | Shiftmax 指数近似 |
| `ttx_ceil_log2_u32` | 复用 | 2 的幂分母 |
| `ttx_descriptor_scheduler` | 复用 | 12 个 block 的 stage/head/window 调度 |
| gated-K、投影、binary ATLIF | 复用 | 不随 H67 复制 |

这里的“12 blocks”是 12 组 descriptor，不是 12 套物理 attention engine。单个 engine 按
stage/block/head/window 分时执行；ATLIF105 同样是网络调用次数，不是实例化 105 个状态单元。

## 6. 当前 RTL 与验证结果

新增目录：

- `rtl_h67/`：4 个 synthesizable SystemVerilog 模块和 filelist；
- `tb_h67/`：score 随机测试、row folding/dense 对照测试；
- `sim_h67/`：Icarus、Verilator、Yosys 一键流程；
- `scripts/h67_score_reference.py`：不占 GPU 的独立分数参考审计。

执行 `sim_h67/run_all_checks.sh` 的结果：

| 检查 | 结果 |
|---|---|
| Icarus H67 score 定向 + 1000 随机向量 | 通过 |
| Icarus TPSF 与 dense row 有效 gate 对照 | 通过 |
| q-active 相同、peer-K 不同的反例 | 通过，形成 3 个正确 score 类 |
| Verilator top lint | 通过 |
| 中心化前 35,937 计数组合 + 100,000 随机向量 | 通过，0 不一致 |
| `center -> quant` 与 RTL 顺序反例 | 已发现，整行 bit-exact 未关闭 |
| Yosys 4 个 top hierarchy/check/synth | 通过，0 problem |

Yosys 通用 cell 只用于结构回归：

| top | 通用 cell 数 |
|---|---:|
| TTX score | 131 |
| H67 score | 198 |
| H67 temporal-pair adapter | 2 |
| TTX row hierarchy | 3016 |
| H67 row hierarchy | 2990 |
| TTX attention top hierarchy | 3096 |
| H67 attention top hierarchy | 3070 |

H67 完整 top 数字略低来自零 K 类生成逻辑被 35 类整数 score 直接替代，不代表实际工艺面积更小。
只有相同 library、约束、SRAM mapping 和综合选项下的 DC 差分才可写进论文。

## 7. 与文献的关系和创新边界

- Flow1D 使用正交 1D attention/correlation 降低二维搜索成本；它只支持 H75 AX17 的候选动机，
  不支持 H67 的硬件收益，也不能把 Flow1D 的结果迁移到本设计。
- STAtten 说明时空块式 spike attention 可以在不整体重做网络的前提下引入时间关系；H67 的
  `{K1,K0}` 成对布局是本项目针对 `T=2,D=32` 的具体硬件化，不复现其 attention 公式。
- MEET 提醒时间稀疏收益必须扣除状态存储。TPSF 和未来 Delta-TTX 的论文能耗必须计入 K-pair
  SRAM、直方图读写和控制，不能只报告跳过的 popcount。

相关原始论文：

- Flow1D：<https://openaccess.thecvf.com/content/ICCV2021/html/Xu_High-Resolution_Optical_Flow_From_1D_Attention_and_Correlation_ICCV_2021_paper.html>
- STAtten：<https://openaccess.thecvf.com/content/CVPR2025/html/Lee_Spiking_Transformer_with_Spatial-Temporal_Attention_CVPR_2025_paper.html>
- MEET：<https://openaccess.thecvf.com/content/CVPR2025/html/Zhu_MEET_Towards_Memory-Efficient_Temporal_Sparse_Deep_Neural_Networks_CVPR_2025_paper.html>

TPSF 是当前项目从 H67 数学边界推导出的组合设计，正式写“首次”之前仍需完成专门 novelty search。

## 8. 下一步最小清单

### P0：决定是否正式替代 TTX

1. 等待当前 H67 epoch19 dyadic valid825，比较 AEE/AAE/spikes 与 float H67、TTX dyadic；
2. 补一次 hardware-order valid825：`raw score quant -> no center requant -> Shiftmax`；
3. 从 H67 epoch19 抓取每 block 的 `motion_xor`、零 K score-class、row-max 和 gate 直方图；
4. 报告 35 类中每 row 的非零类数，验证固定 35-cycle scan 与直接 dense 分母的吞吐交点；
5. 用软件 Shiftmax 与 RTL LUT/ceil-denominator 做逐 row 差分，不能只验证 score 前端；
6. 对 H67 score 前端、TPSF on/off、TTX baseline 做同约束 DC 差分综合。

### P1：论文级 PPA

1. 映射 K-pair/active-entry buffer 到同一 SRAM macro 口径；
2. SAIF/VCD 使用真实 H67 profile 驱动，不用均匀随机向量估功耗；
3. 报告 area、Fmax、每 row cycles、每 frame cycles、SRAM bit/读写次数、动态/漏电功耗；
4. 分列 Motion-XOR、TPSF、Shiftmax、gated-K、ATLIF，不把 spike proxy 当芯片总能耗；
5. 若 H73--H75 后续胜出，只新增 halo/match/codebook 前端，不重写 ATLIF 和顶层调度。

在 P0 第1、2、5、6项完成前，本套 RTL 是“可综合、可回归的 H67 增量微架构”，不是可直接提交论文的
最终 DC/PPA 结果。
