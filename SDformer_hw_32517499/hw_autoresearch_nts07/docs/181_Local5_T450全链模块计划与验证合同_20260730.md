# Local5 T450 全链模块计划与验证合同（2026-07-30）

## 1. 目标

本轮补齐 Local5 全分辨率 `window=2x15x15` 对应 `T=450` 的 RTL 功能深度证据。验证边界从已有的 score/MFEP 计数扩展到：

`Local5 score/gate -> MFEP term -> multiset bridge -> bank-local projection -> Acc[449] 读回`

本轮不改变 Local5 算法语义，也不把寄存器数组实现当作 SRAM 宏或目标工艺 PPA 证据。

## 2. 模块层次与接口合同

顶层采用 `local5_window_attention_top`，关键参数为：

| 参数 | 值 | 合同 |
|---|---:|---|
| `HEAD_DIM` | 32 | all-binary Q/K 通道宽度 |
| `OUT_DIM` | 4 | 最小投影输出维度，用于数值自检 |
| `MAX_DEST` | 450 | 合法目的 token 范围为 0 至 449 |
| `DEST_W` | 9 | 必须无损表示目的 token 449 |
| `USE_TARE` | 0 | 当前 Local5 默认 Direct self-K stationary 路径 |

接口相序：

1. 通过 `w_load_*` 装载 32x4 权重；
2. `run_start` 启动窗口并清空 Acc；
3. `dest_*` 发送一个 `dest_id=449` 的 self-only stencil；
4. 顶层完成 score、Shiftmax5、MFEP、bridge 与 projection；
5. `run_done` 后，通过 `acc_read_*` 检查 `Acc[449]`；
6. 同时读取 `Acc[0]`，排除 9 位目的地址被截断或回绕。

`local5_banklocal_projection_top` 使用 `ST_CLEAR` 逐行清零 Acc。该相序避免单周期复位全部 `MAX_DEST x OUT_DIM` 寄存器，允许后续替换为单行写端口 SRAM；清零开销必须计入窗口周期，不能隐藏为零成本初始化。

## 3. 自检数值设计

测试使用全 1 的 Q/K 与仅 self 有效的 candidate mask。权重仅设置：

- `W[lane0][out0]=3`；
- `W[lane1][out1]=-2`；
- 其余权重为 0。

golden gate 由独立 `local5_stencil_token` 组合参考产生。预期累加值为：

- `Acc[449][0] = gate_self x 3`；
- `Acc[449][1] = gate_self x (-2)`；
- `Acc[449][2] = 0`；
- `Acc[0][0:1] = 0`。

## 4. 覆盖与非覆盖范围

本轮必须覆盖：

- `DEST_W=9` 从顶层输入穿过 term/command 到投影累加器；
- `MAX_DEST=450` 的最高合法地址 449 可写、可读；
- 最高地址与地址 0 不混叠；
- 正负权重的整数累加 bit-exact；
- `protocol_error=0`，窗口能够有限时间完成。

本轮不覆盖：

- 450 个目的 token 的完整窗口吞吐；
- 真实 fullres ordered trace；
- SRAM 读写延迟、宏面积和功耗；
- Local5 fullres 软件 RTL-exact 精度；
- DC、STA、SAIF 和 LEC。

## 5. DATE 证据定位

若测试通过，只能将结论写为 `[rtl] Local5 的 T450 目的地址、累加深度和全链数值路径已完成定向验证`。不能据此宣称：

- 已达到全分辨率实时吞吐；
- 已完成全分辨率 PPA；
- 已证明寄存器数组可直接作为最终 SRAM 实现；
- Local5 已优于 Motion 主线。

下一步仍需真实 ordered fullres trace、多窗口压力、存储宏映射和同约束 DC/STA/SAIF。
