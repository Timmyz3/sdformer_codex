# 外部论文机制复用与 DATE 架构创新审计

## 0. 直接结论

已经从其他论文迁移了硬件机制，并且部分已经进入 RTL；但当前不能说这些
机制已经共同支撑一篇可接收的 DATE 架构论文。

当前状态更准确地表示为：

```text
论文机制迁移：有
独立 RTL 原型：有
真实 workload 动机：有
统一端到端架构：未闭合
目标工艺 PPA：没有
当前 DATE 判断：Borderline Reject，约 2.5/5
```

可形成 DATE 主线的不是七八个小模块，而是下面三层组合：

```text
C1  TARE-4 静态锚定精确残差执行前端
    |
C2  SCS -> NMF 的归一化结果重编码与免物化数据流
    |
C3  DCTF-2C term-atomic bank-local projection 后端
```

其中 C1、C2、C3 分别解决 score 计算、归一化到投影的数据表示、投影存储与
调度。三者尚未在同一个完整 H67/Local5 attention-to-projection 顶层中闭合。

## 1. 已经实际用进 RTL 的论文机制

### 1.1 Prosperity：Product Sparsity 与精确残差复用

原论文：

- Prosperity, HPCA 2025：
  <https://arxiv.org/abs/2503.03379>
- 原机制是利用二值行之间的组合相似性复用内积结果，并在运行时识别冗余
  product。

本项目实际采用：

- 复用“anchor product + residual update”的精确计算思想；
- H67 使用固定 T=2 时间锚点；
- Local5 使用 self/neighbor 拓扑锚点；
- 只在变化 lane 上计算 signed alpha-XNOR contribution delta；
- 最终结果与 direct raw16/Q7 保持逐整数一致。

本项目修改：

- 不使用 TCAM 或在线相似行搜索；
- anchor 由网络时间或 stencil 拓扑静态给出；
- update-count 大于 4 时不继续做稀疏匹配，而是回放到同一个 direct32 引擎；
- Motion 与 Local5 通过一个 mode descriptor 共用同一实例。

RTL：

- `rtl_delta/tare4_residual_composite_core.sv`
- `rtl_delta/dual_mode_tare4_composite_top.sv`

判断：

- **已使用并有实质修改。**
- Prosperity 的 exact/product reuse 不能称本项目原创；
- “静态语义锚点 + bounded delta + 同核 exact replay + 双模式”可以作为组合
  差异，但目前只到单 edge/pair，架构新颖性约 `2.5/5`。

### 1.2 Bishop：密度分层与 TTB 思想

原论文：

- Bishop, ISCA 2025：
  <https://arxiv.org/abs/2505.12281>
- 原机制包括 Token-Time Bundle、density stratifier、dense/sparse
  heterogeneous cores、BSA 和带误差界的 ECP pruning。

本项目实际采用：

- profile 中使用 TTB2/TTB4 统计 temporal bundle empty；
- TARE-4 classifier 将 operand update 分为
  `ZERO / SPARSE(1..4) / DENSE(>4)`；
- H67 exact issue 使用 pair-empty 和 K-zero metadata；
- `rtl_allbinary/ttb_skip_unit.v` 存在 TTB skip 叶模块。

本项目修改：

- 不采用 BSA 和 ECP，不删除 Q/K/V 或 attention pair；
- 不复制 dense/sparse 双核；
- DENSE 路径回放到同一个 32-lane anchor engine；
- stratification 是 exact execution routing，不是近似 pruning。

判断：

- **density stratification 已进入 TARE-4；TTB 只到 profile/叶模块。**
- 可以写“Bishop-inspired exact stratification”；
- 不能写“提出 TTB”或“实现 Bishop 异构架构”；
- TTB 当前不能作为 DATE 贡献。

### 1.3 FireFly-T：每拍多非零抽取

原论文：

- FireFly-T：
  <https://arxiv.org/abs/2505.12771>
- 原机制是在 sparse engine 中每拍并行抽取多个非零 spike，并配合 dispatch、
  load balance 和 dual-engine overlay。

本项目实际采用：

- `delta_bounded_classifier` 从 32-bit update mask 中最多抽取 4 个 lane；
- `alpha_xnor_delta4` 同拍计算 4 个 lane 的 signed contribution delta；
- classifier 保留原始 mask/count，超过 4 的事务精确 fallback。

本项目修改：

- 解码对象不是普通 activation nonzero，而是 Q/K operand update；
- 输出不是 weight MAC request，而是 alpha-XNOR score residual；
- 没有复制 FireFly-T 的 FPGA dual-engine overlay、LUT6 AND-popcount 或
  load-balancing 数字。

判断：

- **多 lane decoder 思想已进入 RTL。**
- decoder 本身是已有机制，不是 DATE 创新；
- “有向 operand delta extraction + exact score reconstruction”可作为
  TARE-4 的微结构组成。

### 1.4 FLAT/LoAS：驻留、融合与时间维数据组织

原论文：

- FLAT：
  <https://arxiv.org/abs/2107.06419>
- LoAS, MICRO 2024：
  <https://arxiv.org/abs/2407.14073>

原机制：

- FLAT 通过 attention operation fusion 和 tiling 降低中间张量与片外流量；
- LoAS 将 timestep 放入内层，配合一位 spike 压缩和 inner-join。

本项目实际采用：

- H67 temporal pair 连续组织；
- SCS 逐 token 输出 `{gate,K,token}`，但不物化完整 gated-K 数值 tensor；
- NMF 将 `(gate,lane,destination)` 变为 projection term；
- DCTF 只广播窄 term command，在三个 bank 本地读 weight、算 product、
  更新 Acc；
- score/normalization/projection 之间使用流式 descriptor 和本地驻留。

本项目修改：

- workload 不是 FLAT 的 dense attention，也不是 LoAS 的 dual-sparse spMspM；
- 中间表示是 all-binary attention 的 final gate class 和 K-event；
- DCTF 的边界是 whole-term atomic commit、multi-reader ordered retirement
  和 bank-local projection。

RTL：

- `rtl_hitflow/hitflow_nmf_g1_builder.sv`
- `rtl_hitflow/gatestack_dctf_term_event_adapter_2c.sv`
- `rtl_hitflow/gatestack_dctf_term_fabric.sv`
- `rtl_hitflow/gatestack_dctf96_banklocal_projection_top.sv`

判断：

- **驻留/融合/时间组织范式已使用。**
- FLAT/LoAS 的数据流原则不能称本项目原创；
- “final-gate normalization metadata 直接驱动 bank-local projection”是
  本项目最有潜力的数据流差异。

### 1.5 SpAtten：级联 issue 思想

原论文：

- SpAtten, HPCA 2021：
  <https://doi.org/10.1109/HPCA51647.2021.00018>
- 原机制是 cascade token/head pruning 和 progressive quantization。

本项目实际采用：

- pair-empty、K-zero、bounded-delta、direct replay 的分级 issue；
- K-zero 仍进入 Shiftmax denominator，但不进入 projection destination；
- 所有被跳过的计算都有代数等价路径，不做 weak token/head deletion。

本项目修改：

- 将有损 cascade pruning 改为 exact cascade issue；
- 级联条件来自 all-binary score/gate 语义，而不是 token importance。

判断：

- **控制思想被采用，但不是独立架构模块。**
- 只能作为 TARE/SCS/NMF 的统一 exact issue 规则；
- 单独不能列为贡献。

## 2. 已实现但主要不是从某篇论文直接复用的结构

### 2.1 SCS Occupancy-Class Shiftmax

基础 Shiftmax/整数 exp2 归一化不是本项目首次提出。本项目的硬件增量是：

- K-zero token 不写 active bank，但按 score-class multiplicity 精确注入分母；
- 只扫描实际 occupied score classes；
- 同一 class 的指数项只计算一次；
- 保持 zero-K denominator 语义和最终 gated-K 精确。

证据：

- H67 token K-zero 约 `88.7%`；
- 每行 fold class 平均约 `2.27`；
- SCS 行核周期模型相对固定 35 类扫描约下降 `12.9%`。

判断：

- 是有 workload 支撑的 operator microarchitecture；
- 单独新颖性约 `2.0-2.5/5`；
- 应作为 C2 数据流的前端，不应单独承担 DATE 主贡献。

### 2.2 NMF/GCM-P：Normalization Metadata Forwarding

结构：

- Shiftmax 最终 Q1.7 gate code 直接成为 projection 执行 metadata；
- 不物化 `token x channel` gated-K tensor；
- 按 `(gate,lane)` 聚合 destination bitmap；
- gate product 计算一次后多播到 token Acc。

实现边界：

- 当前 SCS 仍逐 token 输出 `{gate,K,token}`；
- NMF 随后重新构建 `(gate,lane)->destination bitmap`；
- 因而当前成立的是“免 gated-K 数值张量物化”和“跨阶段元数据重编码”，
  不是 score histogram 到 NMF directory 的零拷贝代数闭包；
- G1 顶层尚未实现 `unique gate classes > SLOTS` 时的无损 overflow
  fallback，因此 bit-exact 结论只覆盖 `unique gate classes <= SLOTS` 的
  已验证合同，不能外推为全 workload 全链路 bit-exact。

证据：

- profile100 的 final-gate product work 下降约 `82.5%`；
- gate active class `p95=3`，S=4 overflow 约 `0.014%`；
- G1 builder/product/Acc 顶层已有整数等价 RTL。

判断：

- 这是当前**最有潜力的软硬件协同数据流贡献**；
- 与 FLAT 的 fusion、Sanger 的 stationary dataflow、Prosperity 的 product
  reuse 有思想关系，但 final Shiftmax gate metadata 直接跨阶段成为
  projection command 是本项目特定组合；
- 仍需要接入统一流水并给出 SRAM traffic/energy 才能支撑 DATE。

### 2.3 DCTF-2C：Term-Atomic Bank-Local Projection

结构：

- 共享一次 sparse term decode；
- 只分发窄命令，不搬运中央 96-lane weight/product 总线；
- 三个 32-lane bank 本地读 weight、计算 product、更新 Acc；
- multi-reader ordered fabric；
- 双 context 重叠 term collect/validation 与前一 term emit；
- whole-term 验证通过后才原子可见。

当前证据：

- 与 Central96、3xIndependent32、DCTF-1C 做过等 96-lane 边界对照；
- 单个真实 H67 trace 上 DCTF-2C 周期为 `53910`，Central96 为 `59853`，
  即 `1.110x`；
- 开放逻辑面积归一吞吐约 `1.158x`；
- `233280` 个 acc32 输出零失配。

判断：

- 是当前最接近“系统架构贡献”的实现；
- bank-local、本地 Acc、双 context、多消费者队列单独都常见；
- 可辩护的是
  `shared sparse frontend + narrow ordered multicast + bank-local execution
  + term-atomic overlap` 的组合；
- 没有 DC/STA/SAIF 和多 trace 前，仍只是 DATE architecture prototype。

### 2.4 PPDI：Parity-Paired Destination Issue

结构：

- 利用同一 gate term 的 product 不变性；
- 一条命令配对一个 even 和一个 odd destination；
- 复用 Acc 已有偶奇双端口；
- commit mask 保证独立反压下 exactly-once。

证据：

- 真实 trace command-work 理论下降约 `30.27%`；
- 当前只完成单 bank executor 与局部 Acc flush 合同。

判断：

- 是 domain-specific microarchitecture，约 `2.0/5`；
- 没有完整 adapter/fabric/三 bank 集成；
- 不能作为 DATE 主贡献，只能作为 DCTF 的可选增量。

## 3. 看过但当前没有真正用上的论文机制

| 机制 | 当前状态 | 不计入贡献的原因 |
|---|---|---|
| Phi pattern/codebook + residual | 只保留为公平基线 | 没有 pattern SRAM、k-means codebook 或双层执行 RTL |
| 复旦 ISSCC 2023 butterfly zero skipper | 未采用 | 固定 32->4 extractor 和 Local5 固定五点更简单；尚无 PPA 证明 butterfly 值得 |

| Bishop ECP/BSA | 明确不采用 | 会改变训练或 attention 数值 |

| Canon decoupled orchestration | 文档概念 | 当前 mode descriptor 很小，不等于分布式 orchestrator |
| 复旦 local-attention reusable CIM engine | 未采用 | 当前是数字 RTL，Local5 row anchor context 尚未实现 |

## 4. 哪些点可以列入 DATE 贡献

### 候选 C1：Static-Anchor Exact Residual Execution

表述：

> 面向 all-binary event attention，利用时间和 stencil 拓扑天然给出的静态
> anchor，在一个物理数据通路中统一 zero bypass、bounded signed residual
> 和 direct replay，并逐事务切换 Motion/Local5 模式。

来源与差异：

- 借 Prosperity exact reuse；
- 借 Bishop stratification；
- 借 FireFly-T multi-lane extraction；
- 差异是无 matcher/TCAM、无异构双核、无近似、静态语义 anchor。

当前评级：

- 新颖性 `2.5/5`；
- 完成 H67 双 score packet 和 Local5 row-context 后可到约 `3.0-3.5/5`。

### 候选 C2：Normalization-Metadata-Driven Projection

表述：

> 将 SCS-Shiftmax 输出的 active `{gate,K,token}` 流重编码为 projection
> term，在不物化 gated-K 数值张量的条件下，以 gate product 多播代替
> 逐 token 乘法。

来源与差异：

- 借 FLAT operation fusion/tiling；
- 借 stationary dataflow 和 Prosperity product reuse；
- 差异是 final gate code 同时承担 normalization result 和 exact execution
  metadata。

当前评级：

- 潜在新颖性 `3.0-3.5/5`；
- 当前缺 SRAM traffic、融合流水周期和目标功耗。

### 候选 C3：Term-Atomic Distributed Bank-Local Projection

表述：

> 共享稀疏 term 前端只广播窄有序命令，三个 projection bank 独立取数与
> 累加；双上下文 whole-term commit 在保持全局有序的同时重叠验证和发射。

来源与差异：

- 借 FLAT/LoAS 的局部驻留和流式数据组织；
- 借多消费者流控的常规原则；
- 差异是 gate-term 的原子提交、多 reader ordered retirement 与 bank-local
  projection 组合。

当前评级：

- 新颖性约 `2.5-3.0/5`；
- 已有公平开放 RTL 对照，但缺目标 PPA 和多 trace。

## 5. 是否足以支撑 DATE

### 5.1 仅凭当前结果

**不足。**

原因：

1. C1、C2、C3 仍是三个分离顶层；
2. C1 不是完整 H67/Local5 attention producer；
3. C2 没有与 C1/DCTF 形成统一 attention-to-projection cycle/traffic；
4. DCTF 只有单个真实窗口的公平周期对照；
5. 没有目标工艺 DC/STA/SAIF、SRAM macro 和 EDP；
6. 当前最大实测架构收益约 `1.11x`，在无功耗/频率证据时偏弱。

按 DATE 审稿口径，当前仍约 `2.5/5`，属于 Borderline Reject。

### 5.2 补齐后是否有机会

**有机会，但必须把论文收敛为一套架构，不是机制清单。**

最小闭环：

```text
TARE score packet
  -> SCS occupied-class normalization
  -> NMF gate-term generation
  -> DCTF-2C bank-local projection
  -> Acc/final
```

必须增加：

1. H67 T0/T1 原子 packet；
2. Local5 `ANCHOR_LOAD + 2/3/4 PROBE + row Shiftmax5`；
3. 多 sample、多 window 的 mean/p95/p99 周期和 stall；
4. Direct、zero-only、Prosperity-like、Phi-like、Central96、
   Independent32 的公平基线；
5. 相同 SRAM latency、端口、lane 数和 SDC；
6. DC 面积/Fmax、SAIF 动态功耗、energy/frame、EDP；
7. 接通 `SLOTS` overflow 无损 fallback，并覆盖 flush、malformed、长反压
   和 epoch 回绕；
8. full-encoder Amdahl，证明端到端收益至少约 `8%`。

建议 DATE 晋级门槛：

- 目标库下 EDP 至少下降 `10%`；
- 面积归一吞吐至少提升 `8%`；
- 多 trace p95/p99 无异常失衡；
- 所有整数结果 bit-exact；
- unified architecture 相对专用双核的面积/功耗税有明确分账。

## 6. 最终贡献排序

按“硬件架构价值”排序：

| 排名 | 候选 | 当前状态 | DATE 角色 |
|---:|---|---|---|
| 1 | SCS/NMF normalization-metadata-driven projection | RTL 子系统已存在 | 主数据流贡献候选 |
| 2 | TARE-4 static-anchor exact residual execution | 双模式 edge/pair RTL PASS | 主计算架构候选 |
| 3 | DCTF-2C term-atomic bank-local projection | 完整 projection 原型 PASS | 主存储/调度贡献候选 |
| 4 | SCS occupancy-class scan | 已实现 | C2 的算子机制 |
| 5 | PPDI parity-paired issue | 叶模块 PASS | 可选微结构增量 |
| 6 | TTB skip | profile/叶模块 | 基础设施或消融 |
| 7 | 蝶形、Phi、Canon | 未实现 | 只能作为 related work 或基线 |

论文主贡献建议只写三条：

1. 静态锚定、精确分层的双模式事件 attention score 执行；
2. 归一化元数据直接驱动 projection 的免物化融合数据流；
3. term-atomic、窄命令、多 bank 本地执行的分布式 projection。

SCS、PPDI、TTB、descriptor 和双 context 放在三条贡献内部，不再单独计数。

## 7. 独立 DATE 审稿复核

独立只读审稿复核给出：

```text
评分：2.5/5
推荐：Weak Reject / Borderline Reject
```

复核确认：

- Prosperity、Bishop、FireFly-T、FLAT/LoAS 和 SpAtten 的机制迁移与 RTL
  大体对应，但均应写为 inspired/adapted，不能将原机制据为原创；
- DCTF 的双 context、whole-term 完整后可见、三个 reader 独立推进和全局
  有序退休是真实 RTL 行为；
- DCTF 的 `1.110x` 周期结果只来自单个真实窗口，`1.158x` 开放逻辑面积
  归一吞吐不包含等价 SRAM，不能视为物理 PPA；
- TARE-4、SCS occupancy-class 和 PPDI 当前属于算子微架构；
- 三 bank、双 context、ready/valid、consume mask 和完整性检查属于常规
  工程机制，不能独立列为架构创新；
- Phi、蝶形、Canon 仍未实现，只能作为 related work 或后续候选。

因此，当前最值得保留的三项仍是：

1. Normalization-Metadata-Driven Projection，但必须按“active token 流重编码
   与免数值张量物化”表述；
2. Term-Atomic Bank-Local Sparse Projection；
3. Static-Anchor Exact Residual Score Engine。

达到 Weak Accept 的关键不是增加命名，而是形成一个带无损 fallback 的
`score -> SCS -> NMF -> DCTF -> Acc` 顶层，并补齐多 trace、公平 SRAM
边界以及 DC/STA/SAIF/EDP。
