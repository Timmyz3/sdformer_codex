# M961｜D2/D3 10K bounded-prefix 执行合同与 100K 门

## 结论

M961 只准备一个未来的一次性执行命名空间：D2 与 D3 各跑 `sample0 / A1_OSG / t0 / 10K expanded requests`。本轮仅完成 source contract、driver、one-shot runner、静态检查和无前缀测试；没有创建 attempt/result，也没有执行任何真实 prefix。

Runner 在缺少 exact M969 release SHA 或 exact M970 release-hammer 三重身份时立即 fail closed。即使未来 10K 两行通过，也只能建议另开 100K scheduler-prefix release，绝不自动运行 100K。

## 最重要的 transaction-scope 边界

冻结 M785 的 D2 首个 source-fetch transaction 含 231,600 requests，D3 含 465,600 requests。因此：

| Prefix | D2 | D3 | contributor mapper | commit |
|---|---:|---:|---|---|
| 10K | source-fetch 内 | source-fetch 内 | 未覆盖 | 未覆盖 |
| 100K | source-fetch 内 | source-fetch 内 | 未覆盖 | 未覆盖 |

这意味着 10K→100K 只能验证 RUN-GTLS 对同一个闭式 source-fetch transaction 的 scheduler-state 扩展，不能证明 contributor materialization、psum/weight transaction、commit 或 full-row scalability。该限制已进入 result schema 和 release gate，不能靠论文措辞绕开。

## 冻结 exact 语义

- M946 选择 D2/D3 exact-binary row；
- M785 生成 transaction，mapper/resource/address/order 不变；
- M896 使用冻结六类 cycle priority；
- 10K 必须逐字段通过 M768/M861/M890/M896 exact miter；
- 每行必须保持一个 compressed source-fetch transaction、零 commit request。

## 100K 决策门

10K 结果对每层将 measured scheduler state 与 elapsed 线性投影到 100K，并要求：

1. `2 × projected 100K peak` 同时小于 MemAvailable 与 commit headroom；
2. `2 × projected 100K elapsed <= 1800 s`；
3. exact/address/cycle identity 均通过；
4. transaction scope 仍明确为 `SOURCE_FETCH_ONLY`。

两层同时过门时，结果只写 `GO_TO_SEPARATE_100K_SCHEDULER_PREFIX_RELEASE_DESIGN`。仍需新的 release 与 release hammer；`automatic_100k_authorized=false`、`full_row_authorized=false` 固定不变。

## 一次性与失败语义

未来 release 最多消费一个 attempt。Attempt 在执行前原子封存；任何超时或异常都会保留已消费身份并把 stage 移到独立 failure namespace。Canonical result 只允许 no-replace publication。运行前要求 2 GiB disk、16 GiB MemAvailable、16 GiB commit headroom，pair timeout 1800 s，30 s kill-after。
