# 独立审阅：非法 Metadata 活性修复

## 1. 审阅结论

**结论：CONDITIONAL**

- **P0：0 项**。
- **P1：2 项**。核心 RTL 修复方向正确，但 SVA 尚不能独立证明 ready/valid 解锁，且 2C 混合并发没有定向覆盖；`clear_error` 与新错误同拍的优先级也存在未定义且会漏报的行为。
- **P2：3 项**。零目的地、drain 中 flush、证据可追溯性仍有覆盖缺口。

在约定 source 对非零非法 term 最终提供一次握手的 `event_term_last`、且 `clear_error` 不与新错误同拍的条件下，本修复可判定为：**非法 term 能被消费，非法 payload 不进入 adapter/fabric，纯合法 1C/2C 主路径未见回归**。在下述 P1 关闭前，不建议把“非法 metadata 活性与隔离已完整签核”写成无条件结论。

## 2. 已确认成立的部分

### 2.1 ready/valid 解锁成立

`rtl_hitflow/gatestack_dctf96_term_datapath_top.sv:188-200` 中，`term_ready` 只受 `adapter_term_ready`、drop 状态和 flush 控制，不再受 `term_metadata_legal` 控制；非法 term 在 adapter 可接收时可完成握手。合法性只用于门控 `adapter_term_valid`，因此非法 metadata 不会被送入 1C/2C adapter。

结论：此前“source 持续 `valid`、sink 因 payload 非法永久不给 `ready`”的问题在 RTL 上已解除。这里的活性仍合理地依赖下游 adapter 最终可用；非零非法 term 的 payload 活性依赖 source 最终发送 `event_term_last`，该边界已在 `docs/145_非法Metadata握手活性修复与主路径回归_20260722.md:38`、`:90-91` 明示。

### 2.2 drain 的结构隔离成立

`rtl_hitflow/gatestack_dctf96_term_datapath_top.sv:190-200` 在 drop 期间同时关闭 `adapter_term_valid` 和 `adapter_event_valid`，外部 event 仅由 drain 接收；fabric 的唯一新增命令入口仍来自 adapter command，见 `:216-221`、`:329-345`。因此非法 term/payload 本身没有进入 adapter、fabric、weight 或 Acc 的结构路径。

`rtl_hitflow/gatestack_dctf96_term_datapath_top.sv:537-540` 仅以已握手的 `event_term_last` 退出 drain，`:547-559` 的 flush 优先清除 drain 和 tracking。`:222-224` 也正确把 drain 排除在 `datapath_idle` 之外。

需要区分：2C 下 drain 期间，先前已合法提交的 context 仍可继续向 fabric/weight/Acc 前进。这不是污染，因此不能简单断言 drain 时所有下游 valid/counter 为零；应验证“下游变化只能归因于 drain 前已提交的合法 context”。

### 2.3 纯合法路径回归基本充分

`results/gatestack_dctf96_2c_real_trace_20260722/report.json:3-49` 给出 S0-S3 Icarus 与 S0 Verilator/SVA 计数，`:50-57` 给出总周期及 bit-exact 结论。对应 `docs/145_非法Metadata握手活性修复与主路径回归_20260722.md:75-85` 的 53910 周期、5010 term、15030 weight、233280 个 acc32 检查与修复前一致。

对“纯合法数据是否回归”而言，四 stage 真实 trace 加 S0 动态 SVA 是足够的窄修复回归证据；它不能替代非法/合法混合并发验证。

## 3. P1 问题

### P1-1：新增 SVA 对“解锁”是后验/派生自证，无法捕获 ready 再次被锁死

位置：

- `verif_hitflow/gatestack_dctf96_term_datapath_top_assertions.sv:65-80`
- `verif_hitflow/bind_gatestack_dctf96_term_datapath_top_assertions.sv:25-33`
- `rtl_hitflow/gatestack_dctf96_term_datapath_top.sv:194-200`

`p_illegal_term_consumed_outside_adapter` 以前件 `illegal_term_fire` 触发，而该信号本身就是 RTL 内部的 `term_valid && term_ready && !term_metadata_legal`。如果将来 `term_ready` 又错误地被合法性门控，非法 term 永远不 fire，该属性会全程 vacuous PASS。`p_legal_term_enters_adapter` 和 `p_illegal_nonempty_enters_drain` 也依赖同一组内部派生 fire 信号。

要求：至少增加独立于 `illegal_term_fire` 的接口属性，例如在 `!flush && !illegal_drop_active_q && adapter_term_ready && term_valid && !term_metadata_legal` 时同拍要求 `term_ready && !adapter_term_valid`；并增加对应 cover，证明非法握手、进入 drain、last 释放均实际命中。当前 SVA 可检查部分隔离结果，但不能作为“标准 ready/valid 已解锁”的独立证据。

### P1-2：2C 非法/合法混合并发未覆盖，且 clear 与新错误同拍会漏报

位置：

- `tb_hitflow/tb_gatestack_dctf96_term_datapath_top.sv:125-145`
- `tb_hitflow/tb_gatestack_dctf96_term_datapath_top.sv:522-583`

要求：补一个 `ADAPTER_CONTEXTS=2` 混合并发测试；明确 `clear_error` 与新错误同拍的合同。建议采用 new-error-wins，或至少在规格中明确 clear-wins 并补定向测试。未明确前，此项阻止无条件 PASS。

## 4. P2 问题

### P2-1：零目的地非法 term 只有 RTL 路径，没有测试或 SVA 命中

### P2-2：flush 未在非法 drain 中定向验证，SVA 也未检查 drop 清除
