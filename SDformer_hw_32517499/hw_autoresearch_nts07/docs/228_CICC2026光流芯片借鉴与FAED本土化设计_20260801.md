# CICC 2026 光流芯片借鉴与 FAED 本土化设计

> 日期：2026-08-01  
> 本地论文：`Zhang 等 - 2026 - A 28-nm Optical Flow Estimation Accelerator with Redundancy Speculation, Bit-Width-Aware Compression.pdf`  
> 证据边界：论文数字为文献报告；本工作数字为 `[open-vector]`、
> `[checkpoint-static]` 或 `[模型]`。本文不包含 DC、STA、SAIF 和目标工艺 PPA。

## 1. 先给结论

这篇 CICC 论文值得借鉴，但不能把三项机制原样搬到 H67 Motion/Local5：

1. **Dense-Channel-First Speculation 不能直接用于 Shiftmax 跳算。** 原论文依赖
   MaxPool/ReLU 的提前可判定性；我们的 silent token 仍影响 Shiftmax 分母，提前删除
   会改变数值语义；
2. **BWAC 可借鉴评估方法，但原版编码不适合当前权重。** Motion/Local5 投影
   INT8 权重零值率只有约 1.51%/1.43%，nonzero bitmap 反而把数据扩大到约
   1.059x/1.069x；
3. **DLSS 不应进入当前精确主线。** fullres Motion/Local5 AEE 已比 NB0 差约
   43% 至 45%，再按相似度跳过深层缺少精度余量；
4. 真正可以本土化的是：**FAED 幅度-事件分离、精确门码密度调度、可选变位宽
   权重流，以及 memory-inclusive 的系统评估口径**。

因此，这篇论文对我们的价值不是再增加三个名字，而是帮助冻结两条架构原则：

- 网络内部的高重复标量应进入低频 descriptor，而不是跟随每个事件搬运；
- DATE 主表必须同时报告运算、片上/片外 bit、延迟、能量和 AEE 增量。

## 2. 原论文到底做了什么

该工作在 28 nm 实现面向事件光流的混合 SNN/ANN U-Net 加速器，主要机制为：

| 机制 | 原论文条件 | 原论文报告结果 |
|---|---|---:|
| Dense-Channel-First | 高密度输入通道先算，超过阈值后提前执行 MaxPool/ReLU，并停止已判定地址的剩余通道 | 非线性冗余最多减少 73.8% |
| BWAC/BWADU | 权重按组选择最小位宽，并用 nonzero bitmap 挤掉零值；片上按指针解压 | weight EMA 减少 71.4% |
| DLSS | 比较相邻 feature map，Level0 相似度高时跳过深层 U-Net | 总运算约 0.20x |

芯片报告 core 0.80 mm2、12--744 MHz、0.21--75.48 mW；MVSEC 上片上
35.80 TOPS/W，计入外存后 14.07 TOPS/W，单推理 2.07--2.88 mJ、
58.53--79.95 ms。三项方法使平均 AEE 从 0.96 增加约 0.03。这里所有数值都
属于原论文，不能移作本工作的 PPA。

## 3. 为什么 Dense-Channel-First 不能照搬

原论文的停止条件位于 MaxPool/ReLU：当当前部分和已足以确定非最大值或负值时，
后续通道不会改变该地址的最终输出。这是该网络和算子提供的提前判定边界。

我们的 attention 行为是：

```text
score classes -> Shiftmax denominator -> gate -> gate * K -> projection
```

即使某个 K 为零，其 score 对应项仍可能参与 denominator。把“当前输出看起来小”
直接解释成“后续不用算”，会同时改变归一化和 gated-K。除非给出严格上下界或回到
软件重训，否则以下行为全部禁止：

- 按部分 score 提前删除 token；
- 因 K-zero 直接删除 Shiftmax 分母项；
- 按相似度跳过 attention block；
- 把原论文 73.8% 的操作降低率用于本工作。

### 3.1 第一版精确改造：GDF 调度

可将 Dense-Channel-First 改为 **GDF（Gate-Density-First，门码密度优先）**：

```text
SCS/NMF 已知的 exact fanout
        -> fanout bucket/LPT selector
        -> 高 fanout term 优先
        -> DCTF/Local bank-local executor
        -> context 全部完成后统一 final
```

GDF 只重排同一 context 内的整数累加项，不删除项，不改变 gate、destination 或
weight epoch。由于 accumulator 在 context final 前不可见，整数加法在无溢出合同下
可交换。其目标不是减少算术量，而是：

1. 让长 fanout term 更早进入多 bank，减小尾部拖延；
2. 延长同一 gate/lane product 的有效驻留期；
3. 让 DVCO 更早释放上一 vocabulary bank；
4. 用 descriptor 已有的 count 取代原论文的运行时 density 排序器。

只按 fanout 长短排序的初步服务模型没有减少总服务量：当 backend 每拍持续有工作
时，顺序不能改变所有 fanout 的和。因此不把“高 fanout 优先”直接做成 RTL。

本轮进一步得到更强的本土化版本 **ECGB（Exact Cross-Context Gate
Batching）**：不是按 fanout 排序，而是在有限 context 组内按 `(lane,gate)` 聚类，
用窄 term reorder buffer 换取 product/weight 复用。结果见
`docs/229_ECGB精确跨Context门码批处理架构_20260801.md`。

## 4. BWAC 在本工作上的真实 DSE

新增脚本 `scripts/analyze_cicc_bwac_faed.py`，输入为 H67 已导出的四 stage INT8
projection 权重和 Local5 fullres epoch29 checkpoint。每组比较：

- `raw8`：固定 INT8；
- `MinBW`：3-bit 位宽头 + 紧凑有符号码；
- `CICC bitmap`：MinBW + nonzero bitmap + 非零 payload；
- `adaptive`：每组用 2-bit mode 在上述三者中择优。

| 线 | 最优 group | 权重零值率 | MinBW/INT8 | CICC bitmap/INT8 | adaptive/INT8 |
|---|---:|---:|---:|---:|---:|
| Motion | 16 | 1.514% | 94.723% | **105.858%** | **94.040%** |
| Local5 | 16 | 1.433% | 95.707% | **106.905%** | **94.823%** |

结论很明确：原版 bitmap 依赖高零值率，在本网络上是负优化；三模式自适应最多只
减少约 6.0%/5.2% bit，还要付出 mode 解析、变宽拼接和指针控制。因此：

- 不把 BWAC 单独列为 DATE 贡献；
- 若后续片外权重能量占比高，可将 G=16 adaptive 作为可选 loader；
- 若 DC/SAIF 表明解压逻辑抵消收益，直接使用固定 INT8；
- 除非软件侧引入结构化稀疏并重新训练，否则不采用 nonzero bitmap。

这项负结果也解释了为什么不能只看到 CICC 的 71.4% EMA 降低就照搬：两篇工作的
权重分布不同。

## 5. CICC 权重共享对 FAED 的启发

原论文每条 PE line 共享解压后的 weight。我们可将该“高频输入与低频权重元数据
解耦”的思想本土化为双线共享的 **FAED（Factorized Amplitude-Event
Dataflow）**。

Local5 的正确 value 合同是：

```text
K = E_K * theta_block
Y = gate * E_K * theta_block * W
```

其中 `E_K` 是 1-bit 支持，theta 是每 attention block 一个标量。硬件数据流为：

```text
1-bit E_K ------------------------------+
                                        |
gate term -> gate/lane directory -> product reuse -> INT32 Acc
                                        |
INT8 W + block theta/scale descriptor --+
```

### 5.1 不采用运行时 W_theta 乘法

正标量 theta 可并入逐输出通道 scale。最小 exact 部署合同应是：

```text
INT8 weight code 保持不变
effective_scale = weight_scale * theta_block
```

而不是每个 block 启动时重新计算更宽的 `W_theta`。checkpoint DSE 中，若先折叠
theta 再重新量化，仍出现少量舍入码差；这说明必须固定运算次序，不能把“数学上
可交换”直接写成“所有有限位宽实现 bit-exact”。

FAED 的架构价值在于：

1. score、relation、TTB、K SRAM 和事件 NoC 始终只处理 1-bit `E_K`；
2. theta 只在 block/weight epoch 切换时更新一次；
3. Motion 与 Local5 共用同一个 projection backend；
4. Local5 不再因 `k_orig != k_event` 被迫恢复逐事件多位 K；
5. theta=1 的 Motion/Local block 可旁路 descriptor 乘法。

FAED 与 CICC BWAC 的差异是：CICC 压缩每组权重的表示位宽，FAED 消除每个事件
重复携带的幅度因子。前者由权重统计决定，后者由 ATLIF block-scalar 合同保证。

## 6. DLSS 的可用边界

原论文按平均相似度跳过 U-Net 深层，允许平均 AEE 增加约 0.03。当前本网络 fullres
结果没有这类精度预算，因此 DLSS 只保留两级候选：

| 级别 | 条件 | 数值语义 | 当前决定 |
|---|---|---|---|
| exact context reuse | `E_Q/E_K`、theta epoch、weight epoch、skip state 全部相同 | 精确 | 先 profile 命中率 |
| bounded similarity skip | 相似度超过阈值后跳 block | 近似 | 暂停，需重训与 valid825 |

exact reuse 也不能只比较输入 bitmap：ATLIF 带状态，skip S0/S1/S2 也会改变后续值。
只有状态签名和所有版本号一致才可复用。若 exact hit 低于 1%，不进入 RTL。

## 7. Motion 与 Local5 的落点

| 机制 | Motion | Local5 | 是否共享硬件 |
|---|---|---|---|
| FAED 1-bit event plane | 直接适用 | 修复 theta 语义后适用 | 是 |
| theta/scale epoch | 多数可旁路 | 必须保留 | 是 |
| GDF exact term ordering | SCS/NMF count 已知 | gate-equivalence mask/count 已知 | selector 可共享 |
| adaptive MinBW loader | 约 6% bit 潜力 | 约 5.2% bit 潜力 | 可共享，但低优先级 |
| exact context reuse | 待 profile | 待 profile，需 ATLIF/skip state | 可共享 hash/epoch 前端 |
| approximate DLSS | 不采用 | 不采用 | 否 |

两条线的注意力前端仍不同，但 CICC 借鉴后的新增硬件应尽量放在统一边界：

```text
Motion SCS/NMF ----+
                   +-> exact term descriptor -> GDF(optional)
Local5 MFEP/ABIC --+                         -> FAED projection banks
                                             -> accumulator/final
```

## 8. 能否包装成 DATE 创新

### 8.1 可以主讲，但必须补实现

**贡献候选 A：FAED。** 面向 ATLIF block-scalar 事件的幅度-支持解耦数据流，在不
恢复逐事件多位 K 的情况下同时支持 Motion 和 Local5，并将幅度绑定推迟到 weight
scale epoch。需要补数值合同、valid825 和最小 scale-loader RTL。

**贡献候选 B：Vocabulary-Guided Exact Scheduling。** 把 SCS/MFEP 已知的 gate
cardinality、fanout 和 destination mask 直接用作投影调度元数据，避免预测和近似
剪枝。DVCO/ABIC 是其控制基础，ECGB 是已有定向 trace 证据、但仍待 post-G0 晋级
的跨 context 实例。

### 8.2 只能作为子机制

- adaptive MinBW 权重流：收益约 5%--6%，单独不够新；
- DVCO/ABIC：解决气泡和有限缓冲正确性，属于必要工程；
- exact identity reuse：命中率未知，未晋级；
- CICC 的 EMA 能量常数：只能做敏感性，不能当测量值。

### 8.3 不能写的说法

- “提出 Dense-Channel-First”；
- “BWAC 使权重流量降低 71.4%”；
- “DLSS 不损精度”；
- “theta 折叠后所有量化码天然完全相同”；
- “CICC 芯片 PPA 可代表本架构”。

## 9. 评估口径升级

CICC 的最大警示是：只报片上 TOPS/W 会隐藏外存代价。后续 Motion/Local5 的
同约束评估必须包含：

| 类别 | 最小指标 |
|---|---|
| 运算 | score、Shiftmax、term build、projection、ATLIF 的有效/跳过操作 |
| 存储 | Q/K event、theta/scale descriptor、weight、term、Psum、skip SRAM bit |
| 流量 | 片外和各级片上 SRAM 的读写 bit，metadata/padding 单列 |
| 控制 | decoder stall、bank idle、context tail、fallback、FIFO p95/p99 |
| 性能 | cycle、频率闭合后的 FPS、平均/p95/p99 latency |
| 能量 | SAIF 后逻辑/SRAM/时钟/IO 分账；外存只在明确技术假设下估算 |
| 精度 | float、hardware-order、FAED、任何近似机制的 valid825 AEE/AAE |

## 10. 本轮 DATE 标准审阅

本轮没有可用的独立 subagent，以下是作者侧审阅，不冒充外部评分。

| 项目 | 分数 | 原因 |
|---|---:|---|
| 同应用文献差分 | 3.8/5 | 已明确同为事件光流，但网络与提前判定条件不同 |
| 架构抽象 | 3.1/5 | FAED 有清晰跨线合同，GDF 尚未实证 |
| 新颖性证据 | 2.5/5 | CICC 本身没有提升分数；需 GDF/FAED RTL 与消融 |
| 实验可信度 | 3.7/5 | 真实权重 DSE 给出 BWAC 负结果，证据边界明确 |
| 系统 PPA | 2.0/5 | 仍无 DC/STA/SAIF 和 memory-inclusive 主表 |
| 算法主结果 | 1.5/5 | fullres AEE 仍是硬拒稿点 |

**总体仍约 2.6/5，Weak Reject。** 这篇 CICC 论文带来了更严谨的机制筛选和评估
口径，但论文不会因为 related work 多一篇自动变成 accept。下一轮只有在 FAED
定点合同和 GDF 真实 trace 收益至少一项闭环后，创新性评分才有理由上调。

## 11. 下一步

2. 用真实 DCTF/Local backend ready trace，而非周期性反压；
3. 冻结 `INT8 W code + theta*scale` 数值顺序并跑 valid825；
4. 实现最小 FAED scale epoch loader，不做在线 `W_theta` 乘法阵列；
5. 将 fixed8 与 G=16 adaptive loader 放入同约束综合，收益不足则删除；
6. 后续 DC 主表增加外存/片上 SRAM bit 和 AEE 增量，和 CICC 做同口径边界对比。
