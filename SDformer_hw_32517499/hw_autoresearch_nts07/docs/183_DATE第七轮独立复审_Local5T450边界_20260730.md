# DATE 第七轮独立复审：Local5 T450 边界（2026-07-30）

## 1. 审稿结论

独立审稿评分：`2.1/5`，Recommendation 为 `Weak Reject`。

本轮只关闭了窄范围 P1：

- `DEST_W=9/MAX_DEST=450` 的最高合法地址449能够贯通全链；
- Acc 清零从不可扩展的单周期全阵列复位改为逐行 scrub；
- 清零开销被计入周期。

本轮没有关闭真实 fullres/post-G0/ordered-trace P0，也没有提升 DATE 架构创新性。

## 2. 审稿人认可的改进

1. 目的地址449可以正确写入和读回，地址0没有混叠；
2. `ST_CLEAR` 从0到449逐行推进，T450 总周期为485；
3. Verilator、Icarus和动态SVA能够复跑通过；
4. 改动提高了大深度存储相序的工程可信度。

## 3. 主要拒稿理由

1. T450 测试实际只注入一个目的 token，不是450目的完整 workload；
2. golden 复用了 `local5_stencil_token`，score/gate 参考不独立；
3. 刺激为全1 Q/K、self-only、固定 gate128，覆盖不足；
4. SVA 只证明状态和计数推进，没有直接证明每行内容被清零；
5. Acc 仍是组合异步读寄存器数组，不是同步 SRAM/read-modify-write 合同；
6. `acc_read_ready` 恒为1，运行或清零期间允许读取部分状态；
7. 没有真实 workload、MFEP 公平基线、DC/STA/SAIF/EDP。

## 4. 本轮后续整改优先级

### P0：等待真实数据

- post-G0 fullres ordered trace；
- 真实 invalid mask；
- 多样本、多窗口、全部450 destination；
- 独立 Python/C++ bit-accurate golden。

### CPU-only 立即整改

1. T450 TB 去除 RTL golden 依赖，使用独立整数参考或固定已知向量；
2. 增加第二次运行，先写非零、再重启并验证旧值完全消失；
3. 覆盖重复 destination、多输出、不同 gate/multiplicity；
4. 读口只在 DONE 状态 ready/valid；
5. 增强 SVA，检查 clear 从0开始、恰好450拍、清零期间禁止外部读写；
6. 对逐行 scrub 与 epoch-tag/lazy-clear 做同顶层消融。

## 5. 证据边界

独立复审明确指出，逐行清零和地址扩宽属于实现修正，不是新的架构贡献。论文创新性仍需由真实 workload 驱动的数据流、存储层次、调度机制和同约束 PPA 支撑。
