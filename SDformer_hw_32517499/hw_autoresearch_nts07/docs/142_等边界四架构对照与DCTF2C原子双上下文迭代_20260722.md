# 等边界四架构对照与 DCTF-2C 原子双上下文迭代

## 1. 本轮结论

在相同 `term/event -> projection final` 边界、相同 96 个 INT8 product lane、三个 32-lane weight bank 和六个 32-lane Acc bank 合同下，DCTF96 单上下文版本没有取得吞吐收益，四阶段累计 62264 周期，比 Central96 慢 4.03%。根因不是 bank-local 数据通路本身，而是单上下文 adapter 把“完整 term 收集与验证”和“逐 destination 命令发射”严格串行化。

本轮实现 DCTF96-2C：两个有序上下文分别保存完整 term 的 payload、去重 bitmap 和物理映射 sideband。当前 term 通过 whole-term 原子验证后才能进入命令可见态，同时第二个上下文可以收集下一 term。该修改不改变 H67 数值计算、term 顺序、三 bank 权重读取、Acc 更新、bias 或 final 语义。

真实 H67 S0-S3 回放结果为：

| 结构 | S0 | S1 | S2 | S3 | 总周期 | 相对 Central 加速 | 开放逻辑面积值 | 面积归一吞吐 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Central96 | 871 | 718 | 7208 | 51056 | 59853 | 1.000x | 189141.960 | 1.000x |
| 3xIndependent32 | 871 | 730 | 7232 | 51112 | 59945 | 0.998x | 224987.588 | 0.839x |
| DCTF96-1C | 822 | 718 | 5652 | 55072 | 62264 | 0.961x | 182119.826 | 0.998x |
| DCTF96-2C | 764 | 718 | 5356 | 47072 | 53910 | 1.110x | 181392.050 | 1.158x |

DCTF96-2C 相对 1C 提速 1.155x，S3 周期降低 14.526%，并把 DCTF 从慢于 Central96 反转为快 1.110x。233280 个 `acc32` 输出逐元素零失配。

这些结果支持 DCTF-2C 晋级为 DATE 架构原型，但不等于目标工艺 PPA 签核，也不能承诺论文接收。

## 2. Workload 为什么要求这种架构

### 2.1 稀疏性已经被编码成 term，而不是零值 SIMD

H67 上游 GateStack/NMF 把 final-gate 与二值 K 的有效乘积压成 term 和 destination token 列表。已有 profile100 证据显示 token K-zero 约 88.7%、pair empty 约 74%、final-gate 乘积 work 减少约 82.5%。因此 projection 后端真正接收的是不规则 term 流，而不是规则 dense tensor。

DCTF 的目标不是再次近似裁剪，而是保持这一稀疏语义：

~~~text
term = {gate, input lane, input-channel base, logical supertile,
        destination count, issue sequence, head boundary}
event = 1..4 destination token IDs per beat
~~~

完整 term 验证后，一个逻辑 term 只进行一次 decode，再由三个 bank-local backend 各取自己的 32-lane weight，并将同一 product 复用于该 term 的全部 destination。

### 2.2 S3 是 term 密集阶段

| Stage | term | destination | destination/term | 最大 destination/term |
|---|---:|---:|---:|---:|
| S0 | 62 | 179 | 2.887 | 24 |
| S1 | 0 | 0 | 0.000 | 0 |
| S2 | 652 | 1380 | 2.117 | 12 |
| S3 | 4296 | 21616 | 5.032 | 52 |

1C adapter 每个 term 都经历 `collect -> validate -> emit all destinations -> collect next`。在 S3，4296 次 term 边界和平均 5.032 个 destination/term 使前端相序气泡累计放大。2C 允许 `emit(term n)` 与 `collect/validate(term n+1)` 重叠，因此收益主要出现在 S3；S1 没有 term，2C 与 1C 都是 718 周期。

这一 stage 差异说明架构来自真实 workload，而不是泛化的“双缓冲一定更快”。

## 3. DCTF-2C 完整数据流

~~~text
H67 GateStack term/event stream
              |
              v
  +-----------------------------+
  | Whole-Term Atomic Frontend   |
  | Context 0: meta/seen/tokens  |
  | Context 1: meta/seen/tokens  |
  | validate before visibility   |
  +-----------------------------+
              |
       ordered head commit
              |
              v
  +-----------------------------+
  | Q2 Multi-Reader Term Fabric |
  | per-bank consume mask       |
  | global ordered retirement   |
  +-----------------------------+
       |           |           |
       v           v           v
  +---------+ +---------+ +---------+
  | Bank 0  | | Bank 1  | | Bank 2  |
  | W SRAM  | | W SRAM  | | W SRAM  |
  | 32 MAC  | | 32 MAC  | | 32 MAC  |
  | Acc E/O | | Acc E/O | | Acc E/O |
  +---------+ +---------+ +---------+
       |           |           |
       +---- six bank-local final streams ---->
~~~

中央共享边界只传窄命令，不拼接 768-bit 权重返回，也不形成中央 96-lane product 总线。三个 bank 可以独立接收、反压和完成；fabric 用 consume mask 保持每个 bank 的命令顺序，并在三个 bank 都接受后全局 retire。

## 4. 原子双上下文的关键协议

### 4.1 Whole-term 原子提交

每个 term 在对下游产生第一条 command 前必须完成：

1. `destination_count` 在 1 到 162 范围内；
2. event 的 gate、lane 与 issue sequence 匹配 term；
3. first/last/head-last 边界一致；
4. event valid mask 的 popcount 等于 event count；
5. token ID 不越界，term 内无重复；
6. 累计 destination 数精确等于 term 声明。

任一检查失败时，整个 term 被丢弃并置 sticky protocol error，已经缓存的 destination 不会产生 partial command。这一点把软件的“一个 term 是不可分割稀疏工作单元”落实成硬件提交语义。

### 4.2 有序双上下文所有权

`head_context` 只能发射已经 complete 的最老上下文；`tail_context` 只能接收当前为空的上下文。下一 term 即使先完成，也不能越过前一 term。命令反压时，tag、sequence、gate、lane、destination、input-channel base 和 logical supertile 全部稳定。

与普通 ping-pong buffer 的区别是，两个上下文不是任意数据块缓存，而是带完整性验证、物理映射 sideband、全局 sequence 和原子可见边界的语义提交槽。

### 4.3 必须按上下文保存物理映射

`head_input_channel_base` 和 `logical_supertile` 不能使用顶层全局锁存值。2C 在前一 term 发射时会接收下一 term，如果 sideband 仍是全局寄存器，下一 term 会覆盖前一 term 的物理 channel/tile 映射。本实现将两者随每个 context 保存，并在 command 发射时从 head context 读取。

## 5. 接口合同

| 接口 | 主要字段 | 语义 |
|---|---|---|
| term ingress | valid/ready、tag、gate、lane、destination count、issue sequence、head-last | 声明一个完整逻辑 term |
| event ingress | valid/ready、4-way token valid/IDs、count、first/last/head-last | 分拍携带 destination token |
| adapter command | tag、global sequence、gate、lane、destination、term first/last、head-last、base、supertile | 只对已验证 head context 可见 |
| fabric bank command | 三路独立 valid/ready | 每 bank 保序消费同一逻辑 command |
| weight | 三路独立 request/response | 每 term 每 bank 一次 32-lane 权重读取 |
| Acc update | 每 bank 奇偶 token 两路 | 六个物理 32-lane 累加通道 |
| bias/final | 三路 bias、六路 final | 完整 projection 生命周期 |

实现入口：

- `rtl_hitflow/gatestack_dctf_term_event_adapter_2c.sv`；
- `rtl_hitflow/gatestack_dctf96_term_datapath_top.sv`，参数 `ADAPTER_CONTEXTS=2`；
- `rtl_hitflow/gatestack_dctf96_banklocal_projection_top.sv`，参数 `ADAPTER_CONTEXTS=2`。

## 6. 存储与控制分账

当前 `TOKENS=162`、`TOKEN_ID_W=8` 配置的双上下文状态合同为：

| 状态 | 位数 |
|---|---:|
| 两套 destination token 数组 | 2592 |
| 两套 seen bitmap | 324 |
| 两套 valid/complete、term 元数据和接收计数 | 192 |
| 共享 fill/head/tail、emit index、command sequence 和 error | 30 |
| 合计 | 3138 |

3138 bit 是架构状态位，不是 SRAM 宏面积。开放映射中的 `$mem_v2` 从 1C 的 11 个增到 2C 的 20 个，而 `$mem_v2` 不计入 Yosys 报告的 logic area。因此 2C 逻辑面积比 1C 小 0.400% 只能解释为逻辑优化波动，不能写成“双上下文免费”或“总面积下降”。

## 7. 等边界消融的意义

### 7.1 Central96

一套 term client 驱动中央 96-lane 数据通路。真实周期是 59853，开放逻辑面积值是 189141.960。它是共享控制、中央宽数据通路基线。

### 7.2 3xIndependent32

三套独立 32-lane frontend/backend，不共享 term client。周期 59945，接近 Central96；开放逻辑面积值 224987.588，比 Central 大 18.95%。该基线证明简单复制三个小核不能自然得到面积效率，并暴露三套 term/event 读握手的上游端口代价。

### 7.3 DCTF96-1C

共享 decode 和 bank-local execution 使开放逻辑面积比 Central 小 3.71%，但相序串行导致总周期慢 4.03%，面积归一吞吐只有 0.998x。保留这个负结果是必要的，它证明 DCTF-2C 不是从不公平弱基线获得收益。

### 7.4 DCTF96-2C

2C 维持一套 term client 和三路 bank-local backend，在真实 trace 上得到 53910 周期，开放逻辑面积归一吞吐为 1.158x。当前最可辩护的结论是：在这一个真实 H67 窗口和开放逻辑代理下，原子双上下文关闭了 DCTF-1C 的前端相序瓶颈。

## 8. DATE 贡献如何表述

当前硬件贡献应组织为一条系统架构贡献和两条机制贡献，而不是把每个 RTL 模块单独包装成创新：

1. **DCTF bank-local distributed projection architecture**：把共享稀疏 term decode 与三个本地 32-lane weight/product/Acc bank 解耦，用多消费者有序命令 fabric 消除中央宽权重/product 搬运；
2. **Whole-term atomic dual-context commit**：以软件稀疏 term 为硬件原子单元，完整验证后可见，并在全局顺序不变的前提下重叠下一 term 收集；
3. **H67 workload-driven software/hardware co-design**：利用 all-binary final-gate/K 形成的 term/destination 表示，将 88.7% K-zero 和 82.5% final product work reduction 转换成真实 bank-local 执行，而不是零值 dense MAC。

与相关设计范式的边界必须克制：

- 可借鉴 Bishop 的 metadata-first 与密度驱动执行思想，但本设计没有 ECP 近似裁剪，也没有实现 dense/sparse 双核；
- 可借鉴 SpAtten 的级联 issue 思想，但本设计不删除弱 attention pair，所有输出 bit-exact；
- 可借鉴 FLAT/LoAS 的驻留与时间维数据重排思想，但 DCTF 的特定贡献是 `whole-term commit + multi-reader ordered fabric + bank-local projection` 组合；
- 双上下文本身是常规技术，不能单独作为 novelty。创新声明必须绑定原子语义和分布式执行数据流。

## 10. 当前仍不能宣称的内容

1. 真实 trace 只有 sample0/window0，不能代表 valid825 或 100-frame 分布；
2. weight/bias 是固定一拍行为模型，final 全 ready，没有真实 SRAM latency 与 sink p95/p99；
3. 开放映射无 SDC、STA、SAIF、DC、P&R 和 SRAM macro，不能报告频率、功耗或 EDP；
4. Central 的宽 Acc 仍需统一拆成与 DCTF 相同的六个物理 SRAM macro 后再做目标库比较；
5. 3138 bit 上下文状态必须在 SRAM/RF macro 方案中计入面积和读写能量；
6. `EPOCH_W=4` 的 flush 回绕仍依赖迟到响应寿命小于 16 次 flush 的系统合同；
7. 当前只覆盖 projection slice，不是 full encoder 30 FPS 闭环；
8. 现有证据支持可综合架构原型，不等于可以直接拿开放网表作为 DC 结果发文。

## 11. 下一阶段签核门槛

优先级按是否会推翻论文主张排序：

1. 扩展到多个样本、多个窗口，至少给出周期、term/destination、bank stall 的均值、p95、p99；
2. 给 Central、Independent、DCTF-1C/2C 接相同 SRAM latency 分布和 final sink 反压 trace；
3. 将 Central Acc 物理拆分为六个同规格 32-lane macro，固定相同 SDC；
4. 在目标库运行 DC/STA，并对门级网表采集 SAIF；
5. 用同一 SRAM macro 计入 2C 的 3138 bit 状态和三种候选的全部存储；
6. 报告吞吐、面积、功耗、SRAM/互连/计算能量分账及 EDP；
7. 增加长随机反压、连续 malformed term、flush/epoch 回绕压力与 functional/code coverage；
8. 将 full encoder descriptor、ATLIF、S0/S1/S2 skip 和 projection 调度接入系统周期模型。

只有上述 1 到 6 完成后，DCTF-2C 才能从“DATE 架构原型”升级为“目标工艺有竞争力的论文主架构”。

## 12. 独立审稿后正确性修复

独立审稿发现原非法 channel/supertile term 因 ready=0 可能锁死标准 ready/valid source。现已改为握手消费非法 term，并在隔离 drain 状态吞掉其 event 至 term_last，不进入 adapter/fabric/weight/Acc。term-datapath、完整 projection 和 DCTF96-2C H67 四stage全部重新 PASS，合法主路径仍为53910周期、233280个acc32零失配。详见 docs/145_非法Metadata握手活性修复与主路径回归_20260722.md。
