# Local5 EREP v4 第六次复审裁决

## 1. 最终裁决

第六次独立 DATE 风格复审对 synthetic RTL 校准设施给出 `4/5、Weak Accept`：

| 子项 | 裁决 |
|---|---|
| Final-stream | `ACCEPT` |
| Snapshot fire/state | `ACCEPT`，仅限固定 fixture |
| Synthetic calibration 整包 | `ACCEPT` |
| Formal adapter | `DENY` |

P0 为 0、P1 为 0、P2 为 2。这个分数不代表 Local5 EREP 架构或 DATE 论文整体
已达到接收标准。

## 2. 独立复现

评审人 CPU-only 复跑 `10/10` 单测，并复现两项上轮攻击：

1. Direct cycle 0 同时伪造 `valid=2/fire=2`、但不增加 FIFO 事件：被离散
   snapshot-event ledger 拒绝；
2. 同步移动 TCFM5 state/phase/busy/EXECUTE boundary：被固定 boundary golden
   拒绝。

评审人另行重放 Direct 186 个、TCFM5 69 个 snapshot，packed fire mismatch 均为
0。位序与 RTL 拼接一致：Direct bit 0--4 为 relation/FIFO/term/close/read，TCFM5
bit 0--3 为 term/close/scalar-read/vector-read。

## 3. 已闭合证据

当前 `[synthetic-RTL]+[rtl校准]` 已闭合：

- Direct/TCFM5 final-stream 顺序、身份与 Acc32；
- Direct read response 固定 `+2 cycle`；
- serializer input/output 唯一 `last`；
- 固定 3x3/OUT_DIM2 fixture 的 boundary、state、busy/done；
- packed fire 与离散事务逐 cycle 对齐；
- Icarus/Verilator 跨模拟器一致；

## 4. P2 与不可声称项

1. snapshot 的 valid/ready 没有分别绑定到独立事件。当前只证明
   `fire=valid&ready`、fire 事件账本及 state 合同，不能写“完整 valid/ready 波形
   逐字段独立证明”。
2. `source_git_state.txt` 显示相关源文件未纳入可复现 Git revision。本地 SHA 可
   防误配，但不等价于提交版本、签名、外部时间戳或第三方认证。

本包不能用于声称 formal T450、13800 head-group/1200 window G0、EREP 候选 RTL、
DC/STA/SAIF 或 ASIC PPA 已完成。
