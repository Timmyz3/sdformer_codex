# Motion 与 Local5 双线投稿策略及外部预审整改分解

> 日期：2026-08-13  
> 范围：Motion/H67 与 Local5 两条硬件架构线  
> 原则：双线并行、分别准入；不以 Motion 当前证据较强为由替代 Local5  
> 证据等级：本文为 `[事实审计]+[计划]`，候选机制均为 `[待验证]`

## 1. 路线裁决

外部预审关于证据边界、强基线和潜在机制的意见大部分成立，但“立即冻结 Motion 为
唯一主线、Local5 只作附录”的路线不采纳。当前执行策略为：

| 线 | 论文对象 | 当前优势 | 当前最高优先级缺口 |
|---|---|---|---|
| Motion/H67 | 量化脉冲注意力的可逆时间 score-class 合并 | 冗余可公式化，已有最终 checkpoint 公平单窗 RTL 周期锚点 | 多样本真实 RTL、RQTB到真实投影联合闭环、能量和系统占比 |
| Local5 | 固定五邻域注意力的 source-major 精确关系投影 | 全分辨率 12-block 数值链正在扩到 100 sample，拓扑可静态利用 | 全 profile 准入、强基线性能主表和拓扑特有数据流 |

两条线分别满足 DATE 门槛后都可以独立成稿。是否最终合并、拆成两篇或选择先后顺序，
只能依据后续同约束周期、能量、面积和系统收益决定，不能用当前单项证据先验替代。

## 2. 立即接受的事实修正

### 2.1 统一精确性边界

Motion 与 Local5 中的 `exact` 均限定为：

> 相对于冻结的 hardware-order 定点部署参考 bit-exact，不额外删除、近似或改变有效贡献。

它不等于原始浮点 attention 数学无误差。论文必须绑定 checkpoint、config、BN 策略、
score/gate 位宽、舍入/饱和次序、软件金参考和 RTL commit。

### 2.2 修正 formal 用语

仓库内部历史名称 `formal G0` 保留用于路径兼容，但在没有 model checker 对所有合法输入
给出证明前，论文统一写为：

```text
全 profile 定点一致性准入门
full-profile bit-exact admission gate
```

Icarus/Verilator/SVA、完整 trace 和 SHA archive 分别是 assertion-based simulation、
exhaustive trace validation 与 provenance-controlled validation，不写成数学形式证明。

### 2.3 消除符号和模型身份歧义

论文统一使用：

```text
T_snn     : 网络时间步
T_w       : window 时间长度，当前为 2
H_w, W_w  : window 空间尺寸，当前为 15 x 15
N_tok     : T_w * H_w * W_w = 450
N_pair    : H_w * W_w = 225
```

禁止用单个 `T=450` 同时指时间步和 token 数。另需画出公开 SDformerFlow、NB0、H67、
Local5 和各自 hardware-order 版本的模型谱系，解决 H67 ep30/ep35 及公开模型是否含
Shiftmax 的身份混用。

## 3. Motion 线冻结与下一代候选

### 3.1 当前可守的一条架构贡献

Motion 暂只保留一条核心贡献：

> 可逆归一化域时间 score-class 合并：相等 Q7 score 以代表、multiplicity 和 temporal
> mask 表示，在 weighted normalization 中保持分母，在 gated-K 边界恢复全部贡献。

现有主锚点已从历史 ep30 切换到最终 rank-1 ep35：sample0/window0 的 138 个真实
`N_tok=450` head-row中，Fixed2S 到 RQTB2S 为 `1.1865x`、周期 `-15.72%`、
slot `-45.09%`、descriptor级 exp/gate 重建活动 `-22.22%` `[rtl]`；138/138行更快。
报告绑定 checkpoint/config/vector/source-trace SHA。旧 ep30 `1.1850x` 只作历史结果，
不再与 ep35 算法指标混用。
100-sample 约 `1.17x` 只能写 `[rtl校准模型]`。

SCS、FIFO、双 bank、TTB8、ZKQI、定点化和 Motion-XOR 是实现组件或消融，不能分别
列为架构首创。必须补一张逐周期例子，解释当两个 score class 相同时，SCS 的物理 entry
与 exp transaction 为什么仍能减少；若强 histogram 基线已经天然合并同类，则必须修正
当前收益归因。

RTL 语义复核已确认：`class_present` 是全行唯一 score-class 位图，因此 Fixed2S 与
RQTB2S 的 `class_transactions` 相同。当前 `perf_exp_transactions` 定义为：

```text
unique class scan + active descriptor emit-time exp/gate rebuild
```

RQTB 的 exp 下降来自同 pair/同 score active descriptor 合并，不是 class cardinality 下降；
它是逻辑活动代理而非独立周期。class-exp/gate cache 强基线尚未完成前，`exp -22%` 不单独
写成 SCS 架构优势或能量收益。

现已完成 class-cache 强基线 `[rtl派生模型]`：ep35 的138行共有1,317次唯一class事务，
Fixed/RQTB active descriptor分别为21,073/16,098。163-entry direct-index exp cache的
精确紧凑下界为1,630 bit（9-bit有效值+valid），若保持RTL的16-bit接口则为2,771 bit；
gate cache约1,630 bit（9-bit gate+valid）。理想模型可使两边的exp LUT或gate quant求值
都变为1,317次。因此：

- 撤回 `exp transaction reduction` 作为独立创新；
- 保留 RQTB 已有 `1.1865x` `[rtl]` 周期证据，因为slot、descriptor、FIFO/issue压力仍减少；
- SAIF或时序未证明exp/gate为瓶颈前，不写class-cache RTL。

### 3.2 候选机制与准入实验

| 候选 | 本土化原因 | 实现前必须通过的 profile/证明 | 失败处理 |
|---|---|---|---|
| class-wise K folding | 同 score class 共享 gate，可将 quotient 推进 projection | class-lane 非零数、计数位宽、真实投影事务下降；逐 token 与 class-fold 整数金参考 0 mismatch | 压缩低或定点次序不等价则否决 |
| temporal-pair K folding | 相等 pair 共享 gate，`K0+K1` 只需 0/1/2 | `K0&K1` overlap、weight-read 降幅、Acc32 次序等价 | 重叠低则不进 RTL |
| base-delta score | Motion 时间 lane 可能稳定 | Q/K lane change ratio、score 前端能量占比 | 变化 lane 高则否决 |
| Q5-Q8/stage precision | 等价率可能受量化位宽驱动 | AEE/AAE、hardware-order 差、equality、class 数、周期 Pareto | 不以损坏精度换碰撞率 |
| length-aware head-row schedule | quotient 后行长度精确可知 | 多 engine 尾延迟和利用率模型，强静态调度基线 | 只改善模型均值则不进贡献 |

已有 ep35 checkpoint-bound real INT8 projection component RTL 覆盖12个block、Icarus/
Verilator+SVA均 bit-exact，但它与当前RQTB公平包仍是两个组件证据，不等于联合端到端闭环。
Motion 下一轮先做真实多样本RTL、RQTB到真实权重投影联合闭环和class-gate cache强基线；
上述候选不满足准入前不新增 RTL。

`class-wise K folding` 已完成首轮整数合同审计并 **否决**：当前 H67 输出保留逐 token
destination，把同 class 的 `K` 压成一个 lane count 后写一个 accumulator 会删除 token
轴。两个不可区分输入具有同一 class-lane count `[1,1]`，却分别产生 `[8,12]` 与
`[12,8]` 的 token 输出，因而 count representation 信息不可逆。保留 destination
bitmap 的 algebraic form 与既有 FCIP representation
`class_bitmap & K_lane_bitmap -> destination_bitmap` 相同，不重复包装；这不代表
FCIP 已有端到端 RTL/PPA 证明。证据为
`[integer-counterexample]+[contract-audit]`，不是性能结果。

`base-delta score` 也不作为新候选重复实现：仓库既有 TARE-W16 已覆盖该思路，138 行
周期反而约退化 0.2%，开放逻辑面积代理增加约 51.8%，面积归一吞吐约 0.657；该结果只
用于淘汰当前 arbitrary-lane compactor 实现，不能写成 ASIC PPA，也不能理论否决未来
无需 compactor 的固定切片或天然有序 delta stream。

## 4. Local5 线冻结与下一代候选

### 4.1 当前系统主张

Local5 当前可描述为一条待性能晋级的系统数据流：

```text
score/Shiftmax5
  -> destination-major relation
  -> source-major relation transform
  -> descriptor reuse
  -> source-major term
  -> TCFM5 accumulator
```

数值 RTL、跨 H phase telemetry、来源隔离和 archive 是正确性证据，不是架构创新。
普通 CSR 转置、cache、banking、ping-pong 和 FIFO 也不单列贡献。Local5 的 DATE 价值必须
来自固定五邻域与定点 gate/K/weight 语义共同形成的特有数据流。

截至本文更新时，已独立审计 sample0-99：1,200 个 canonical block-window、
198,720,000 个 Acc32，mismatch=0；sample2-99 属同一 sealed v5 release。独立
execution-chain 审计可证 91 个 `RUN`、2 个 `RESUME`，并显式保留 3 个 pre-batch 来源
与 4 个 legacy receipt 缺口。H24 单窗 compact phase 包已封存并获证据方法学 `5/5 GO`；
sample15-99 的 compact summary 也已形成健康层，但这些都不替代 462,600-phase ledger，
不改变全 profile 准入状态。

Local5 已补出第一张组件级公平强基线性能表。冻结包为
`results/local5_joint_ep29_tcfm5_linear5_realw_sample100_population_rtl_v5_final_20260813`：

- 100 个 sample 各选一组 qualified T450 group，选择不依赖运行结果；stage 配额
  `4/9/52/35` 由来源总体 `600/1200/7200/4800` 用最大余数法确定；
- TCFM5 与 Linear5 共享同步 relation SRAM、frontier、term builder、checkpoint INT8
  权重、五个单写 Acc bank 和 readback 合同，仅映射/replay 策略不同；二者是独立 RTL；
- SRAM L1 下 `132388 vs 198108` cycle，即 `1.496x`；L2 下
  `135936 vs 199327` cycle，即 `1.466x`；
- 四配置分别归档 90,000 个 actual Acc32，合计 360,000 次比较零失配；四配置均有随机
  input/read gap 的 Verilator+SVA 压力回归；
- 49 个报告、日志、RTL/TB/SVA/source 文件已由 `complete.json` 封存。

这是 `[rtl]+[profile-qualified-trace]+[sync-1r1w-contract]`，仍只覆盖 post-score
relation-to-Acc slice。13,800 group 的 active Linear5/TCFM5 `1.932x` 结果属于
`[prof]+[exact-port-model]`；不能混写成全量 RTL。该模型包已补 producer、全部输入 SHA
与执行环境封存。同一 100-group cohort 的模型到 RTL 校准为 `1.963x -> 1.496x/1.466x`，
即 L1/L2 保留理想收益的 `76.21%/74.68%`；差额来自尚未细分的 relation build、同步读、
clear、frontier 和控制开销。

四个 stage 的 full-profile 最大 term group 另完成完整 32-channel output tile 回放：
TCFM5/Linear5 × L1/L2 每配置 57,600 个 Acc32，合计 230,400 次比较零失配。它是定向
高负载参数化压力，不是无偏性能样本或跨 head 最终输出。

### 4.2 外部候选与既有实现去重

复查 `docs/209`--`docs/214` 后，外部预审提出的两项并不是本仓库的新缺口：

- `inverse-stencil source generator` 已由 **FCSR-RX** 实现：固定五 offset、三行有界
  生命周期、destination-major 到 source-major 在线转置，并非通用全窗口 CSR；
- `bank(x,y)=(x+2y) mod 5` 与五 bank 下界已由 **TCFM-5** 给出并验证。该结论只在
  “同周期五 destination、单归属、无 replay/复制归约”的端口合同下成立，不能扩大。

因此二者进入已有主线的命名澄清与强消融，不再作为新候选重复开发。deterministic reuse
也与现有 Relation Memo/EREP 暴露度机制重合，除非能形成新的 interval-allocation 强基线，
否则不再增加缓存缩写。

### 4.3 候选机制与准入实验

| 候选 | 本土化改造 | 实现前必须回答 | 可形成的架构结论 |
|---|---|---|---|
| FCSR-RX 强消融（已有） | 用固定 5 offset 的有界在线状态替代通用 runtime transpose | 与通用动态追踪、Stripe、离线 CSR 同接口周期/状态/反压 | 固定拓扑的有界生命周期 source-major 生成；不再包装成新模块 |
| source projection hoisting | `g_pq*(K_q W)` 与 term-first 两种 hardware-order | source degree、K popcount、位宽/舍入、weight read 和 gate-scale 代价 | 基于真实密度选择 term-first/project-first 的双数据流 |
| Relation Memo 强消融（已有） | first/next/remaining-use 由 12-block/tile schedule 已知 | ideal source-stationary 强基线、容量-收益、commit/replay 能量 | 若无 interval-allocation 新收益，只作支撑机制 |
| TCFM-5 bank proof（已有） | `bank(x,y)=(x+2y) mod 5` | 端口合同、K5 下界、1RW 发射宽度、边界行为 | 受限合同下达到五 bank 下界；不单列首创 |
| Shiftmax5 pattern memo | sorted relative-score tuple + inverse permutation | pattern entropy、top-K 覆盖、Shiftmax 周期/能量占比 | miss 可 exact recompute 的规范化模式复用 |

`source projection hoisting` 已完成第一轮强基线修正 `[prof]+[模型]`：保留现有
unique-gate multicast 后，静态 full-profile project-first 相对 DQFS 多 `19.800%`
weight-row，同时需要 `110,724,877` 次 13-bit vector add 和 `70,852,080` 次
13x9 wide product。ordered canonical 子集的 row-level 乐观 oracle 中，即使把
project-first 宽算术全部视为免费，weight read 也只比全 DQFS 再低 `6.208%`；将不同
位宽 vector-op 等权时仅为 `2.777%` 灵敏度收益。这不是周期或能量，结论是：

- 静态 project-first 不晋级主 RTL；
- 动态 DQFS/project-first hybrid 保留为待同约束 PPA 裁决，不写成贡献；
- DQFS 仍是必须保留的 Local5 强基线。

最高优先级不是立即实现五项，而是先对已有 joint-head profile100 生成一个只读决策表：

```text
五个真实 offset
source degree 分布
K popcount 分布
term-first 与 project-first 事务/位宽成本
bank conflict graph
Shiftmax5 relative-pattern entropy
```

只有至少一项在强基线下预测周期或能量有独立收益，并能保持 frozen hardware-order
bit-exact，才进入 RTL。这样 Local5 的新意来自拓扑和数据的本土化，而不是新缩写。

## 5. 双线统一评估门槛

| 层级 | Motion | Local5 |
|---|---|---|
| `[prof]` | equality、class、K overlap、位宽 Pareto | source degree、pattern entropy、bank conflict、reuse interval |
| `[模型]` | 强 histogram/CAM 基线、Amdahl、candidate crossover | term/project 双序、inverse-stencil/FCSR、memo/ideal-stationary |
| `[rtl]` | 多样本 mean/p95/p99、真实权重 Acc32、随机反压 | 100-sample Acc32、跨 H phase anchor、post-score 强基线周期主表已完成；完整链路仍缺 |
| 物理 | 同 SDC/SRAM 的 DC/STA/SAIF | 同 SDC/SRAM 的 DC/STA/SAIF |
| 系统 | full encoder 周期/能量占比 | 12-block 连续调度、存储和输出频率 |

OpenROAD/Yosys 只作 `[open-pnr代理]`；验证回归 cycle 不能当部署 latency；spike、slot、
term 或 SRAM access 减少都不能在无 SAIF/PTPX 时直接写成节能。

## 6. 当前执行顺序

1. Local5 sample0-99 只读累计审计和执行来源链已完成；保持 100/100 canonical 数值
   覆盖与 phase admission 两套口径分离。
2. sample15-99 compact RTL summary 健康层已完成；继续按 30-anchor 计划补
   H3/H6/H12/H24 phase 证据，它不替代 phase ledger。
3. Local5 同接口 post-score 强基线性能主表已经形成；下一步把 score/Shiftmax5 到 relation
   build 纳入同一部署周期边界，并补 12-block 连续调度/Amdahl。compact 验证回归 cycle
   继续禁止进入性能表。
4. Motion paper checkpoint 已冻结到 ep35；继续闭合 H67 精确算子合同、RQTB到真实投影
   联合路径和 class-gate cache 强基线。
5. Motion class-count folding 已因删除 token destination 轴而否决，base-delta 已被既有
   TARE 负结果覆盖；Local5 不重复开发已有 FCSR-RX/TCFM-5，project-hoisting 静态方案
   已否决，动态 hybrid 只在 PPA 有正收益时送入 RTL。
6. 每个证据包完成后由独立 DATE 审稿代理复核，评分对象必须写清是“证据包”还是
   “整篇论文”，不得用验证包 `5/5` 冒充论文可接收度。

## 7. 本轮结论

Motion 不能因为当前公平周期证据领先就替代 Local5；Local5 也不能因为系统模块更多就
自动成为更强论文。两线下一阶段分别解决不同的硬门槛：Motion 将 quotient 收益向真实
投影和系统能量推进，Local5 将固定五邻域从工程转置/缓存提升为可证明、可量化的数据流。
最终主线排序由同约束证据决定，而不是当前文档中的默认标签决定。
