# 双线 OUT32 与整帧 Attention 模型收口（2026-08-14）

## 1. 本轮结论

本轮没有修改 `docs/359_DATE终局冻结_20260813.md`，也没有把旁路周期写入冻结主表。

- Motion：冻结公平 RTL 主锚点仍为 `112589 / 94891 = 1.1865x`，slot 仍为 `62100 / 34099`，equal 仍为 `28001`。
- Local5：冻结十二窗主锚点仍为 `482520 -> 272624 = 1.770x`，其范围仍是 `OUT_DIM=2 tile`，不是 encoder。
- 新增 Local5 当前生产数据流的 `OUT_DIM=32` population 证据，以及双线 scoped attention/Amdahl 模型；二者均为旁路证据。

## 2. Local5 OUT32 当前源码证据

证据包：`results/local5_out32_population_sensitivity_20260814/`。

- `[rtl]` 100 个 sample-disjoint、stage-weighted group，使用 checkpoint theta-folded INT8 权重。
- 覆盖 `score/Shiftmax5 -> relation -> TCFM5 -> Acc32` 的一个连续 32-channel 输出 tile。
- Icarus 与 Verilator `--assert` 的 100-group ledger 逐行一致。
- 检查 `1,440,000` 个 Acc32，mismatch 为 `0`；另检查 `45,000` 个 score row 与 `450,000` 个 score/gate 标量。
- Query-Silent+T450 到 Query-Silent+rolling 为 `183379 -> 155791 = 1.1771x`；per-group `67/0/33` 胜/平/负。
- OUT2 与 OUT32 的 projection-busy cycle 对每个 group 完全相同。这证明冻结数据流可扩展到 32-channel packed backend，但 accumulator、乘法器和权重端口资源随 `OUT_DIM` 扩展，不能解释成免费吞吐。

该结果只覆盖一个输出 tile，且 busy cycle 不含权重装载和 Acc32 读回；不能写成所有 output tile、cross-head、12-block encoder 或 ASIC PPA。

完整宽度证据矩阵位于 `results/local5_fullwidth_evidence_matrix_20260814/`：当前优化前端覆盖 100 个单 OUT32 tile、`1,440,000` 个 Acc32；旧 recompute HxH 集成链覆盖四个 stage 各一个真实窗口，合计 `648,000` 个最终 Acc32，mismatch 均为 `0`。两条链是互补证据，不是同一个优化 HxH DUT；矩阵对此 fail-closed。

### 当前源码修复

生产 tile 已向 relation frontier 传入 `ROLLING_SCHED_MODE`，但 frontier 旧接口缺少该参数，旧二进制掩盖了当前源码编译错误。本轮在 `qfit_dual_color_relation_frontier_sync.sv` 中加入默认值为 `0` 的参数，并对非零值 fail-closed。默认生产功能未改变，当前源码的 Icarus 与 Verilator 路径均重新通过。

## 3. 双线 scoped attention 模型

证据包：`results/dual_line_attention_frame_amdahl_20260814/`。

### Motion

`[rtl校准模型]` 将 sample0 的真实 T450 选中窗口按各 stage 的实际窗口数扩展：

| Stage | 选中窗口 Fixed/RQTB | 每帧窗口数 | stage speedup |
|---:|---:|---:|---:|
| 0 | 3466 / 2868 | 440 | 1.2085x |
| 1 | 4555 / 3825 | 120 | 1.1908x |
| 2 | 51016 / 42303 | 30 | 1.2060x |
| 3 | 53552 / 45895 | 10 | 1.1668x |

整帧 attention-row 校准模型为 `4,137,640 -> 3,448,960 = 1.1997x`。它只是把 sample0 每个 stage 的同一个选中窗口克隆到该 stage 的全部窗口数；若选中窗口活动偏高，模型会偏乐观。它不是多样本真实 RTL，也不是完整 encoder。

### Local5

`[rtl]+[population] -> [模型]` 对 100-group OUT32 结果按每个 stage 的 block、input-head 与 full-resolution window 数扩展：

- 每个 input-head/window 只执行一个 OUT32 tile：`8,625,420 -> 7,725,115 = 1.1165x`。
- 诊断项：若朴素地按 stage 输出 tile 数重放当前 packed score-to-Acc pipeline，则为 `86,647,157 -> 74,877,139 = 1.1572x`。

后一项会为每个 output tile 重算本应共享的前端，只保留为调度诊断，不进入 Amdahl 表、论文性能表或 encoder 估计。它也不含 cross-head accumulation 与 final readout。仓库已有 sample0/stage0、三 input head、三 output tile 的真实 recompute canary：Icarus/Verilator 均完成 `43,200` 个最终 Acc32 且 mismatch 为 `0`，但它走旧 recompute 前端和标量跨头排空，不能与本轮 packed QS+rolling 周期直接拼接。

### Amdahl 边界

由于目前没有完整 encoder 的实测 operator breakdown，只给 optimized fraction 的敏感性，不选择一个有利比例当主结论。例如 optimized fraction 为 50% 时：

- Motion 系统上限模型为 `1.0908x`；
- Local5 单 tile 口径为 `1.0551x`；

ATLIF/neuron update、residual、FFN、decoder、DMA 与外部存储均未计入。

## 4. 创新筛选裁决

最新 Local5 相邻 destination 完整输入对象复用候选为 `NO-GO`：虽然 100-group 的相邻输入等值边占 `41.89%`，但在已有 Query-Silent/ident-K 后，付费 normal score destination 的 left/up/oracle incremental reuse 均为 `0`；destination/source 坐标也不同，relation 物化对象不减少。该候选是已覆盖的 score-front CSE，不再换名重开。

Projection-to-neuron exact interval retirement 也在算子拓扑审计后判为 `NO-GO_AS_CURRENT_ATTENTION_MECHANISM`。当前 attention 中 `attn_sn(x)` 是 12 个 deployment-dead 调用之一，真正的 `proj` 消费阈值前 `x`；因此 projection partial 后没有可直接决定的 spike consumer。若跨 residual、MLP 和 PSN temporal matrix 建立剩余贡献界，需要新的完整 block hardware-order 合同与 trace，不能把 PADE/BitStopper 式早停改名套入当前数据流。

跨 head 空间条带 Acc 前沿也完成 best-case 审计，报告位于 `results/local5_cross_head_spatial_stripe_gonogo_20260814/`。它不是旧 relation Stripe 的换名，而是尝试把 B2v 的完整 `450xOUT32` Acc 生命周期缩短到若干空间行；但两种可实现调度均未过预注册门槛：

- 每条带重复装载单 head 权重时，`r=1` 的外部权重读取至少增加到 `15x`，即使忽略条带切换/排空，周期下界也显著退化；
- 一次驻留全部 24 个 head 权重并保留最小 K halo 时，Acc payload 虽下降 `15x`，但候选友好的总状态下界仍只下降约 `1.85x < 2x`；
- 两种方案都不删除任何 term 或 Acc update，memory bit-activity 的可证明降幅上界为 `0% < 20%`。浅 Acc 宏可能降低单次访问能量，但必须由真宏/DC/PTPX 证明，不能用容量缩减代替。

该候选因此记为 `NO_GO_NO_RTL`。模型还刻意忽略了 per-head relation-frontier 与控制状态复制，已经偏向候选；不再写 RTL，也不将循环换序包装成第四条贡献。

窄 Acc + exact promotion 也完成真实有序更新筛选，报告位于 `results/exact_promoted_accumulator_profile_20260814/`。Local5 100-group 的每次 source-major Acc 更新均按现行 term builder 顺序重放，最终 `1,440,000` 个 Acc32 与已有金参考一致。`b=16` 时动态高位占用 mean/p95/max 为 `0.005% / 0.028% / 0.167%`，高位访问 max 为 `0.038%`，观察到的 sticky promotion 最多 24 项；相对全 32-bit 逻辑状态最差仍约 `1.874x`。但这不是合格的新 DATE 机制：

- 相同 exact fallback 合同下，`b=18` 在 100 组中零 promotion；`b=16` 相对该强基线的最差状态增量仅约 `1.11x`，访问 payload 增量约 `10.5%`，均未过 `20%`；
- profile 最大容量不能证明任意合法输入的 sidecar 上界，仍需要 spill/replay 或全宽 fallback；
- ISCAS 2025 已有 overflow-aware partial-sum management，A2Q/AXE/MGS 也分别覆盖低位累加约束与重排。当前候选只能记为 `NO_GO_AS_DATE_HOLD_AS_IMPLEMENTATION`；
- Motion 已补当前 ep35、sample0/window0、12 block、T450 的真实 projection term/gate/lane/destination 与 checkpoint INT8 权重有序重放，全部 Acc32 mismatch 为 `0`；这仍不是多样本证据。

当前 T450 结果进一步否决该候选：`b=16` 的 high-path access max 为 `18.09%`，dynamic sidecar peak max 为 `35.55%`，最差逻辑状态相对 Acc32 仅为 `0.911x`，即已经比全宽状态更大；`b=18` 的 high-path access max 仅约 `0.0059%`，最差逻辑状态约 `1.683x`。因此 `b=16` 并未打赢带相同 exact fallback 的 `b=18` 强基线，且 S3.B0 sticky promotion 达 `166294 / 345600 = 48.12%`。该负结果不是旧 T162 外推，而是当前 T450 hardware-order vector 的双线补证。

因此本轮不新增 Acc RTL，不把 `1.874x` 写成面积或能量，也不提高项目创新评分。

本轮两次独立 DATE 复审认为：OUT32 population 提高 Local5 验证与完整度，不提高创新分；当前没有一条尚未否决、同时改变存储对象或执行边界的 exact 候选。贡献应继续收敛为：

1. Motion：可逆 Q7 时间 score-class 商化、multiplicity-aware normalization 与精确 payload 恢复，作为一条 normalization-to-projection 数据流。
2. Local5：Query-Silent early-out、固定拓扑编译的有界 inverse-stencil transpose、TCFM5 累加，作为一条端到端局部关系数据流。

其中 MSSB5、banking、FIFO、generation、compiler codegen 和 rolling retirement 都是主数据流的实现或证明，不单列为 DATE 贡献。

项目级评分：

| 创新 | 工作量 | 验证 | 实验完整度 | 工程 | 综合 |
|---:|---:|---:|---:|---:|---:|
| 3.1 | 4.9 | 4.7 | 3.1 | 4.8 | 3.1（Borderline Reject） |

Motion 的多样本真实 RTL 完整度仍约为 `2.6/5`。创新距离 4 分的根因不是 RTL 数量，而是两条线目前都没有第二个不可化约的新存储/执行对象；仅靠包装、开放综合面积或更多 SVA 不能补足。

## 5. 追加创新筛选：Local5 phase residual 与 Motion denominator certificate

### Local5 quantization-phase residual：Exact，但物理 NO-GO

证据包：

- `results/local5_quantization_phase_residual_20260814/`
- `results/local5_phase_residual_openproxy_20260814/`

该候选利用冻结 Q7 score 的低七位 phase，尝试将五路绝对 score 状态改写为共享偶数 base 与窄 residual。软件对全部 `4,198,401` 个 raw-score pair 穷举，100-group 的 `45,000` 行 score/gate 均为 `0` mismatch；RTL 默认关闭分支也通过 Icarus 与 Verilator `--assert` 的 320 组定向/随机 miter。

但是，在复用现有绝对 accumulator、仅在 RNE 后减共享 base 的较强实现下，同配置 Nangate45/OpenSTA 代理只得到约 `0.98%` 面积下降，关键路径反而增加约 `4.44%`，周期与存储端口均未改变。理论上的 `145 -> 102 bit` 只是不含控制和 datapath 的状态计数，不能代替映射结果。因此裁决为 `NO_GO_AS_LOCAL5_SCORE_DATAPATH_SUPPORT`：保留 default-off 历史分支，不进入 Local5 贡献、主表或后续主线 RTL。

### Motion load-time denominator certificate：Leaf RTL conditional

证据包：

- `results/h67_static_denominator_certificate_20260814/`
- `results/h67_denominator_certificate_rtl_20260814/`

冻结 score 合同满足：固定 `q=popcount(Q)` 时，对任意 K/Kpeer 有

```text
score <= 32 + 4q + RNE((32-q)/16)
```

因此 `q<=15` 给出 `score<=93`。对 T450，若整行 `row_max<=96`，Shiftmax LUT 的最小 exp 为 152，严格有 `256+449*152>2^16` 且 `450*256<2^17`，故 denominator shift 必为 17。`q=16` 可构造 score 97，证书必须失败，边界不是经验阈值。

`[prof]` 结果为：只看 Q-popcount 的静态证书在公平包命中 `124/138` 行、profile100 命中 `664042/672000` 行。进一步利用 preload 可见的 Q/K popcount 与 temporal K-motion count，并使用 `overlap<=min(q,k)`，可得到更紧但仍严格的上界：

```text
score <= 4*min(q,k) + motion + RNE((32-q-k+min(q,k))/16)
```

该 Q/K/motion 证书在公平包命中 `138/138`，最大上界 71；profile100 命中 `672000/672000`，上界 p50/p95/p99/max 为 `5/21/34/91`。这些仍是本 checkpoint/profile 的覆盖事实，不是通用分布定理。Q-only 可避免的 histogram update/class scan 事务分别为 `98.62%/97.86%`，但这些不是能量。只跳 class scan 的公平周期模型仅为 `94891 -> 94004 = 1.0094x [模型]`；即使 Q/K/motion 在公平包全命中，class-scan-only 上界也只有约 `1.014x [模型]`，因此性能不能作为卖点。

本轮新增的独立 `[rtl]` leaf 与 gate-select miter覆盖 18 行、两种证书合计 16200 个 gate，Icarus/Verilator `--assert` 均为 `0` mismatch；包括 `qmax=15, score=93` 命中、`qmax=16, score>=97` 失败、Q/K/motion 上界不低于实际 row-max、短行和乱序 fail-closed、load gap。证书失败或无效时，shift 端口强制为 0，只有 `valid&&pass` 才输出 17，避免误接线静默使用错误常数。

开放代理中，Q-only 复用上游 Q-popcount 的 core 面积约 266；Q/K/motion 的 standalone 五棵 popcount 版本约 1358。更现实的接点是复用 metadata 已有两路 Q-count、仅新增 K0/K1/motion 三棵树，面积约 1049。一份 `fakeram45_256x16` 开放宏面积为 3155；双 histogram 对比“一份宏 + 现实 Q/K/motion 证书”的局部面积模型约为 `6310 -> 4204 = 1.501x [开放映射代理]`。该模型仍不含 directory 控制、布线、目标 SRAM 或活动率；真实 163x10 histogram 未必使用该过大的 256x16 宏。certified gate 的开放逻辑面积还增加约 `3.1%`，且没有 SAIF。

最终裁决为 `FROZEN_LEAF_ONLY_NO_DIRECTORY`。它比“只跳 scan”更强的唯一理由，是证书命中行理论上可不物化 per-workspace histogram；但共享 fallback 会破坏 LAWS 的双 workspace 解耦，且公平 class-scan-only 性能上限仅约 1.014x。因而不拆 directory、不修改冻结 LAWS 顶层，只保留 default-off leaf 作为 RQTB 的严格 denominator 注脚；不提高创新评分、不进入冻结主表，也不称第三条贡献。

## 6. 仍缺的工作

### 本机可做

1. Motion 多样本真实 RTL：基础脚本存在，但 100-sample profile 没有原始 Q/K bit trace；当前 GPU 被算法训练占用，不能从 aggregate count 伪造回放。算法侧释放 GPU 后应导出分层 raw trace，再运行 Fixed2S/RQTB2S 真 RTL。
2. Local5 多 output tile/cross-head：把当前 Query-Silent+rolling packed front 接入已有 HxH cross-head shell，并扩到多 stage/population；现有 stage0 recompute canary 和本轮单 tile population 不能互相替代。
3. 双线 full-encoder operator shell：纳入 ATLIF、FFN、residual、decoder、DMA 和存储访问，获得真实 optimized fraction。
4. 真实存储延迟与随机反压：在同一 population 上报告 stall、端口占用和 tail latency。

### 目标 EDA 服务器

1. 三个冻结顶层在同一目标库、同一 SDC 下做 DC 与 STA。
2. 使用与冻结性能相同的激励生成 VCD/SAIF，并分别报告 compute-only 与含 IO 的 matched energy。
3. 用真实 SRAM/RF 宏及相同端口合同重算存储面积、时序和功耗。
4. Formality/LEC 后再做 PTPX；OpenSTA/Yosys/OpenROAD 继续只作为开放代理。

## 7. 下一轮原则

不再为创新分堆叠局部编码、cache、bank 或第四种 stencil。若继续探索新机制，必须在 profile 阶段同时满足：

1. 改变现有 TESC/RQTB 或 inverse-stencil/TCFM5 的存储对象或执行边界；
2. 相对于点名强基线仍有增量，而不是只打赢 destination 重算或弱 counter；
3. 保持冻结 hardware-order bit-exact；
4. 在 RTL 前给出周期、存储、端口和能量代理的共同 Pareto。
