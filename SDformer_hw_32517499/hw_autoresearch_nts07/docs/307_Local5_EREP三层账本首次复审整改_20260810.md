## 1. 独立复审

首次独立 DATE 复审给 sidecar `3/5 Accept-Synthetic`。它确认三层重放能阻断旧的
admitted/command 同源 scalar 共谋，但指出：

1. P1：phase 只保存 resource-cycle，编码过程丢失 `RelativeCommand.identity`；
2. P1：测试未覆盖 identity permutation 与无文件 SHA 信任根；
3. P0-formal：per-head trace/miter SHA 只是字符串，没有原始 archive 文件绑定；
4. P2：runner 没有 executable mode，文档直接命令不可执行；
5. P2：源文件仍为 Git untracked。

Formal adapter 和 formal G0 继续 DENY，这与 sidecar 被接受并不矛盾。

## 2. Identity-preserving phase ledger

phase schema 从：

```text
resource -> [cycle]
```

改为：

```text
resource -> [{cycle, identity}]
```

event 字段集合、排序、cycle 唯一性和 identity 非空全部严格检查。fill 的 relation-read/
epoch-write，以及 execute 的 epoch-read/FIFO-enqueue/FIFO-dequeue，必须具有完全相同的
identity 序列；同一资源重复 identity 也会失败。

因此交换两个 epoch-write transaction 与 cycle 的对应关系，不再编码成相同 ledger；
即使重算 phase SHA，也会因跨资源 identity 顺序不同被拒绝。

## 3. Strict canonical comparison

上层 window/command ledger 不再使用 Python dict 宽松相等，而比较 canonical JSON SHA。
因此整数 `84` 与浮点 `84.0` 的 JSON 表示不同，不能利用 `84 == 84.0` 绕过独立重放。

新增 mutation tests 后，ledger replay 单测从 5 项增至 7 项；与 statistics、schedule、
capacity 的联合数量为 37 项。

## 4. Formal archive binding contract

head ledger 顶层新增并冻结：

```text
rtl_trace_archive_file = rtl_trace_archive.npz
rtl_trace_archive_sha256
acc32_miter_archive_file = acc32_miter_archive.npz
acc32_miter_archive_sha256
```

admission receipt 同时新增两项 archive SHA。正式统计入口必须定位 admission 目录内这
两个固定 basename，逐文件复算 SHA，并要求 head ledger、receipt、真实文件三方一致。

该修改关闭的是“formal 合同没有文件绑定入口”的缺口，不声称真实 archive 已存在，
也尚未证明 archive 内每条 raw event 与 per-head digest 的解析关系。正式 adapter 实现时
仍必须保存 raw trace/miter 内容并由统计器独立解析；在此之前 formal G0 保持 DENY。
