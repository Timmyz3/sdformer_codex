# 同 lane 基线负结果与 ACQN 共享归一化架构

## 0. 本轮结论

第八轮二次复审为：

> **Weak Reject，2.1 / 5**

复审确认整改真实生效，但要求补一个决定新颖性的基线：

```text
anchor32 + monolithic residual16
```

新增同 lane 模型后的结论是：

1. **Motion `4x4 fused` 与 monolithic16 服务完全相同**；
2. **Local5 `4x4 split` 相对 monolithic16 的服务量下界为 1.138x**；
3. fission/fusion 不能写成 Motion 创新，只能是 Local5 条件创新；
4. 代码审阅发现一个新的共享后端候选：
   **All-Candidate Class-Quotient Normalizer（ACQN-163）**。

因此，双线架构重新组织为：

```text
Topology-declared quotient contract
       |
       +-> Motion: monolithic temporal residual frontend
       |
       +-> Local5: four-direction split residual frontend
       |
       v
Shared ACQN-163
       |
       v
member replay -> gated-K term/projection
```

共享部分不再强行包含 score frontend，而是 quotient 合同与 ACQN 后端。

---

## 1. 同 lane monolithic 基线

### 1.1 比较方法

对每个 `4xW` 候选增加同总 residual lane 的 monolithic worker：

```text
split/fused candidate : 4 x W residual slice
monolithic baseline   : 1 x (4W) residual worker
```

两者具有相同 nominal residual lane 数。该对照仍不是面积公平 RTL，但可以
回答“分成四片本身是否减少服务周期”。

### 1.2 结果

| 主线 | W | split/fused 相对 monolithic |
|---|---:|---:|
| Motion | 2 | 1.000x |
| Motion | 4 | 1.000x |
| Motion | 8 | 1.000x |
| Local5 | 2 | 1.128x |
| Local5 | 4 | 1.138x |
| Local5 | 8 | 1.137x |

### 1.3 决策

Motion 将四片融合后，调度行为就是一个普通宽 residual worker。四片物理边界
没有带来额外并行或复用，因此：

> **Motion fission/fusion 新颖性淘汰。**

Motion 仍可用于：

- 校准 anchor/residual 完整流水代价；
- 验证 quotient multiplicity；
- 验证 ACQN；
- 提供有 ordered trace 的 RTL/PPA 基线。

Local5 的四个方向是独立关系，split worker 可以并行推进，服务量下界相对
monolithic16 提高 13.81%。但没有逐方向 ordered trace，不能宣称真实周期。

## 2. ACQN-163 的来源

### 2.1 现有 H67 SCS 的边界

现有 `h67_score_class_row_engine` 已经：

- 对 zero-K score class 建 histogram；
- zero-K class 计入 denominator；
- active nonzero-K entry 单独存入 member memory；
- active entry 逐项调用 exp/gate；
- 最后按 active member 输出 gated-K。

这说明 SCS 不是“全部 candidate 的 class quotient”，而是：

```text
zero-K: class folded
active-K: per-token normalized
```

### 2.2 新观察

Shiftmax/Softmax 的 denominator 只依赖 score，不依赖 K identity：

```text
D = sum_i exp(score_i - row_max)
```

把相同 score 的 candidate 构成 class `c`：

```text
D = sum_c count[c] * exp(score[c] - row_max)
```

对 class 内任一 member：

```text
gate_i = Quantize(exp(score[c]-row_max) / D)
```

因此：

- exp 每个 occupied score class 计算一次；
- gate 每个 occupied score class 量化一次；
- K/token/destination identity 仍保存在 member list；
- zero-K 只增加 class count，不进入 gated-K member replay；
- active-K member 按 class gate 精确回放。

这不是删除 active token，也不改变 denominator、量化或 destination。

## 3. 为什么 score domain 是 163

H67 integer score：

```text
4 * overlap + motion_xor + round(same_zero / 16)
```

当 `HEAD_DIM=32`：

```text
overlap    <= 32
motion_xor <= 32
silence    <= 2
score      <= 162
```

Local5 alpha-XNOR score 上界不超过该域。因此统一合法 class domain 为：

```text
0 .. 162
```

profile100 观察：

| 主线 | observed score support | observed range |
|---|---:|---:|
| Motion | 44 class | 0..55 |
| Local5 pre-G0 | 26 class | 0..37 |

硬件仍实现完整 163-entry 合法域，不能只按 profile 的 56-entry 裁剪。

## 4. ACQN-163 微架构

### 4.1 每 context 状态

| 结构 | 规模 |
|---|---:|
| class count | `163 x 9 bit` |
| occupied bitmap | `163 bit` |
| class gate cache | `163 x 9 bit` |
| class state 总计 | 3097 bit |
| optional exp cache | `163 x 16 = 2608 bit` |
| 含 exp cache class state | 5705 bit |
| T450 member score 字段节省 | `450 x (16-8) = 3600 bit` |

9-bit class count 可覆盖 T450 的 `0..450`。member entry 不再存 16-bit score，
只存 8-bit class id。

### 4.2 流水

```text
COLLECT
  score -> class_id
  class_count[class_id] += multiplicity
  occupied[class_id] = 1
  if K != 0: append {class_id,K,token,destination}

FIND_MAX
  highest occupied class -> row_max

SUM_CLASS
  iterate occupied bitmap
  D += class_count[c] * exp2(c-row_max)

GATE_CLASS
  gate_cache[c] = Quantize(exp2(c-row_max), D)

REPLAY_MEMBER
  member.class_id -> gate_cache
  preserve member order
  stream {gate,K,token,destination,last}
```

双 context 只用于让 `COLLECT(n+1)` 与 `SUM/GATE/REPLAY(n)` 重叠，是常规
pipeline 支撑，不列创新。

### 4.3 条件候选：Class-stationary quotient-to-term

若允许按 class 重排，ACQN 可以不生成逐 token gate SRAM：

```text
class gate stationary
  + class member stream
  -> active K lane expansion
  -> {gate,lane} term directory
```

同一 class 的 member 共享 gate context；后端仍按 `{gate,lane}` 合并 term，
不同 score class 若量化为同一 gate code，可在 term directory 再次 exact
合并。

该候选数据流试图将 normalizer 与 term builder 融合，潜在避免：

- 每个 active member 写一次 gate；
- 每个 active member 再读一次 gate；
- score/gate/token 中间流的重复物化。

但保序 replay 无法同时做到“一次加载 class gate 后连续消费全部 members”。
因此上述收益只属于按类重排候选；在证明投影累加交换性并计入 member bucket
成本前，不能把它写成已实现结果。member identity 与 destination 仍全部保留，
不能把 class-stationary 写成 token 删除。

### 4.4 exact 不变量

1. `sum(class_count) == valid candidate multiplicity sum`；
2. denominator 与逐 candidate 求和逐 bit 一致；
3. 同 class active member 的 gate 逐 bit一致；
4. zero-K member 不输出 gated-K，但其 count 不能从 denominator 删除；
5. invalid Local5 candidate 不进入 count；
6. member replay 无丢失、无重复；
7. 原整数算法的 RNE/截断点不改变；
8. 保序模式的 `{context,token,destination,K,gate,last}` 顺序不改变。

## 5. Motion 实测预筛

profile100：

| 指标 | 值 |
|---|---:|
| rows | 672,000 |
| candidate entries | 108,864,000 |
| occupied classes/row mean | 3.154 |
| occupied classes/row p50 | 2 |
| occupied classes/row p95 | 11 |
| occupied classes/row p99 | 14 |
| occupied classes/row max | 31 |
| active-K member entries | 12,327,067 |

公平基线不是 naive candidate，而是当前 SCS：

```text
current SCS exp eval
  = 2 * active nonzero-K entries + zero-K occupied classes
  = 26,442,147

ACQN without exp cache
  = 2 * all occupied score classes
  = 4,239,552

ACQN with 163x16-bit exp cache
  = all occupied score classes
  = 2,119,776
```

因此：

> **无 exp cache 时减少 83.97%；增加 2608-bit exp cache 时减少 91.98%。**

这只是 exp/LUT 事务数，不是周期、功耗或端到端加速。ACQN 新增全 class
histogram update、gate cache 和 member replay，必须用同顶层 RTL 结算。

若未来允许按 class 重排并直接驱动 term builder，以“全 occupied class”作为
理想 gate-context load 下界：

```text
active member gate loads = 12,327,067
class gate contexts       =  2,119,776
load reduction upper bound = 82.80%
```

该 82.80% 是条件上界，不适用于当前保序 replay。实际 gate-cache 读、
member bucket/pointer 和 term directory 冲突必须进入 RTL/SAIF。

## 6. Local5 边界

Local5 拓扑保证每 row 最多五个候选，因此 occupied score class 最多五个。
当前 pre-G0 profile 只提供全局 score support 与 gate cardinality，没有逐 row
score-class ordered trace。

当前只能声称：

- `0..162` class domain 可覆盖 Local5；
- 同 score gate 共享在数学上 exact；
- ACQN 可以提供与 Motion 相同的物理 normalizer 接口。

不能声称：

- Local5 exp eval 减少比例；
- ACQN 比直接 Shiftmax5 更快；
- Local5 ACQN p95/p99；
- ACQN 已证明双线总面积更低。

## 7. 更新后的架构贡献排序

### C1：ACQN-163 exact class quotient

**候选主贡献。**

从 H67 的 zero-K-only class folding 扩展到 all-candidate exact class
quotient，在保留 K/destination identity 的条件下按 score class 共享
exp/gate 求值。它同时支持 Motion 和 Local5，是当前最明确的共享
normalizer 候选。

`class-stationary quotient-to-term` 暂不并入已成立主张。它只有在
`CLASS_GROUPED_REPLAY` 证明重排合法、member 组织成本可控且内部流量真实下降后
才能升级为跨阶段数据流贡献。

### C2：Local5 topology-parallel split residual cluster

**条件架构贡献。**

四个独立方向用四个 W4 worker 并行，pre-G0 服务量下界相对同 lane
monolithic16 为 1.138x。等待 post-G0/fullres ordered trace 与 RTL。

### C3：Motion temporal anchor/residual frontend

**实现基线，不列独立贡献。**

它为 ACQN 提供真实 ordered 输入和完整 RTL/PPA 载体，但 fused slice 相对
monolithic 没有新意。

### C4：Local5 TRCF

**远期条件候选。**

Motion 已淘汰；Local5 需要逐 term destination/port-class trace。

## 8. 与已有工作的差分

| 工作 | 已有机制 | ACQN/Local5 split 差分 |
|---|---|---|
| Prosperity | exact/partial product reuse、online relation | relation 静态；ACQN 处理 normalization class，不做在线匹配 |
| Phi | anchor/pattern + residual | 无 learned pattern/PWP；Local5 四方向物理并行 |
| Bishop | TTB、dense/sparse stratification | 无 ECP；不复制 dense/sparse 双核 |
| Sanger | score-stationary sparse attention | 不预测 mask；同 score class gate 精确共享并回放 K identity |
| FLAT | attention operator fusion | class histogram 到 gate/member replay 的 exact 流水 |
| FireFly-T | multi-nonzero worker | 固定 topology relation + ordered candidate join |
| 复旦 ISSCC 2023 | butterfly zero skipper | selector 仅是 split frontend 实现候选，不是 ACQN 创新 |

单纯“可重构 pipeline/parallel mode”在既有 accelerator 中并不新。因此论文不能
只写 fission/fusion 名称；主差分必须落在：

```text
exact topology quotient
  + all-candidate class quotient normalization
  + identity-preserving member replay
```

## 9. 下一轮最小实现

### 9.1 ACQN bit-exact 金参考

比较：

```text
逐 candidate 整数 Shiftmax
vs
class count + class gate + member replay
```

覆盖：

- 全 163 score class；
- T=`1/2/5/162/450`；
- multiplicity `1..450`；
- zero-K/active-K 混合；
- invalid mask；
- row_sum 极值；
- gate RNE 边界；
- 随机 member 顺序。

本轮已完成：

| 项 | 结果 |
|---|---:|
| directed rows | 10 |
| random rows | 20,000 |
| preserve-mean on/off checks | 40,020 |
| mismatch | 0 |
| synthetic exp-eval reduction | 76.20% |

产物：

```text
scripts/acqn163_reference.py
tests/test_acqn163_reference.py
results/acqn163_reference_20260730/report.{md,json}
```

该金参考使用两套独立书写的 exp/gate 整数函数，比较 `row_sum_q8`、
`n_tokens` 与原序
`{context,member,destination,K,gate,last}` 记录，未进行排序。它只证明
class count/member replay 的原序整数算法合同；不包含 ready/valid、背压、
清空、RAW、双 context 或逐拍 RTL，synthetic reduction 不进入论文性能表。

复审后补充了四项输入/输出约束：

1. 一个 normalization row 只能属于一个 context；
2. `k_nonzero` 必须严格等价于 32-bit K payload 非零；
3. active member 必须逐 identity 保存，只有 zero-K count 可携带
   `multiplicity>1`；
4. 输出 `last` 在 zero-K/invalid 过滤后重新生成，不能复制输入 `last`。

### 9.2 两种互斥 replay 模式

#### A. `ORDERED_MEMBER_REPLAY`

```text
member SRAM 按输入顺序保存 {class_id,K,token,destination,last}
  -> 每个 member 随机读 gate_cache[class_id]
  -> 保持原序输出
```

这是下一轮 RTL 的基准实现。它不需要 class linked-list，但也不能宣称
“每 class 只加载一次 gate context”或 82.80% gate 流量下降。其主要收益只来自
exp/gate class quotient。

#### B. `CLASS_GROUPED_REPLAY`

```text
occupied class
  -> class member bucket / head-tail-next
  -> gate stationary
  -> class 内 member 连续回放
```

这是条件架构优化。它需要证明：

1. gated-K projection 的整数累加在该边界允许交换顺序；
2. `last`、destination 与 context 语义可重新生成；
3. head/tail、next pointer 或 counting-sort SRAM 的面积和访问能耗没有抵消收益；
4. grouped replay 后的 term builder 冲突和尾延迟优于保序模式。

在这些条件完成前，82.80% 只能标作 gate-context load 的条件上界，不能写成
真实片上流量收益。

### 9.3 ACQN RTL

```text
acqn163_collect.sv
acqn163_class_store.sv
acqn163_denominator.sv
acqn163_gate_cache.sv
acqn163_member_replay.sv
acqn163_top.sv
```

第一版只实现 `ORDERED_MEMBER_REPLAY`，保持接口、顺序和背压与当前 SCS 对齐。
`CLASS_GROUPED_REPLAY` 必须作为独立候选与保序版公平比较，不能直接替换。

### 9.4 完整状态账本

| 结构 | 保序模式 | 按类重排模式 |
|---|---:|---:|
| class count + bitmap + gate | 3097 bit | 3097 bit |
| optional exp cache | 0/2608 bit | 0/2608 bit |
| member class id | `T x 8 bit` | `T x 8 bit` |
| member K/token/destination/last | 两者相同，必须计入 | 两者相同，必须计入 |
| class head/tail | 0 | 至少 `2 x 163 x 9 bit` |
| member next pointer | 0 | 至多 `T x 9 bit`，或等价 counting-sort 空间 |

仅比较 3097-bit class state 与 3600-bit score 字段节省是不完整的。按类重排模式
若采用 head/tail/next，在 T450 下额外索引状态可达 7000 bit 量级，必须以
综合后 SRAM/register 实现为准。

### 9.5 公平基线

Motion：

```text
B0 current SCS
A0 ACQN-163
```

Local5：

```text
B1 Shiftmax5
A1 ACQN-163
```

相同 score stream、K/member stream、输出顺序和 backpressure。

## 10. 淘汰门槛

ACQN 必须同时满足：

- 全向量 bit-exact；
- Motion 完整 normalizer 周期不高于当前 SCS；
- 同 SDC 下 normalizer EDP 改善至少 15%；
- 163-entry class state + member memory 总面积不超过当前 active memory 的
  1.20x；
- p99 transaction tail 不高于当前 SCS 的 1.10x；
- Local5 若比 Shiftmax5 EDP 更差，则 ACQN 只作为 Motion 专用贡献，不能再写
  双线共享。

Local5 split 必须满足：

- post-G0 ordered service 相对 monolithic16 `>=1.10x`；
- 完整 score-to-term 吞吐不低于 Direct5 的 `0.95x`；
- 目标工艺 EDP 改善至少 15%；
- selector、四 FIFO 与 line-buffer 端口全部计入。
