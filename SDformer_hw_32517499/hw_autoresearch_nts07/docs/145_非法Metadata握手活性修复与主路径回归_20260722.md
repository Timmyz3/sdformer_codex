# 非法 Metadata 握手活性修复与主路径回归

## 1. 独立评审发现

DATE 独立评审指出，原 gatestack_dctf96_term_datapath_top 使用：

~~~text
term_ready = adapter_term_ready && term_metadata_legal
~~~

当 source 按 ready/valid 合同保持一个非法 channel 或 supertile 的 term_valid=1 时，sink 永远不返回 ready，事务无法被消费，输入流可能永久锁死。原设计虽然置 protocol_error，但“报错”没有解决接口活性。

该问题被定为 P1 正确性问题，必须在 PPDI 或 PPA 迭代前关闭。

## 2. 修复后的协议

修复后，合法与非法 term 共用 adapter 的输入可用条件：

~~~text
term_ready = adapter_term_ready && !illegal_drop_active && !flush
~~~

合法 term：

1. 正常进入 1C/2C adapter；
2. term/event、whole-term 验证、fabric 和 bank-local execution 语义不变。

非法 term：

1. 在 adapter 可接新 term 时正常完成 ready/valid 握手；
2. 不把 term_valid 或后续 event 送入 adapter；
3. 若 destination_count=0，握手后立即结束；
4. 若 destination_count>0，进入 illegal_drop_active；
5. drop 状态只拉高外部 event_ready，持续消费 event，直到握手的 event_term_last；
6. 全程禁止新 term，datapath_idle=0，不产生 fabric、weight、Acc、term-done 或 issued-term 副作用；
7. flush 可随时清除 drop 状态。

如果非法 source 声明非零 destination 却永远不发送 event_term_last，流仍会停在 drain；这是 source 违反自己已声明 payload 长度后的预期 fail-stop，而不是 sink 对首个非法 term 拒绝握手造成的死锁。

## 3. SVA 更新

删除原“非法 term 必须永远 ready=0”的错误断言，新增：

- 非法 term 握手时不得进入 adapter；
- 合法 term 握手必须进入 adapter；
- 非零非法 term 下一拍进入 drain；
- drain 期间 term 阻塞、event 可消费、adapter 隔离且 datapath 不得 idle；
- 握手 event_term_last 后下一拍退出 drain；
- datapath idle 方程显式包含 !illegal_drop_active；
- 直接以前端 `adapter_term_ready && term_valid && !term_metadata_legal` 为前件检查同拍解锁，避免依赖 `illegal_term_fire` 造成空洞通过；
- `clear_error` 与新非法 term 同拍时采用 new-error-wins；
- flush 后 drop 状态必须清除，drain 隔离和释放场景均设有 cover。

绑定文件把 legal_term_fire、illegal_term_fire、illegal_event_fire、drop 状态及 term/event 边界接入动态 SVA。

## 4. 定向验证

term-datapath TB 参数化覆盖 1C 与 2C，并将两个旧的“保持 valid 三拍且期待 ready=0”测试改为真实协议测试：

1. input channel 越界 term 持续 valid，直到 ready 握手；
2. 发送一个 last event 并确认 drain 接收；
3. 检查 adapter idle、drop 清空、weight/Acc/issued-term 均无副作用；
4. physical supertile 越界重复同一流程；
5. sticky protocol error 必须置位；
6. 零目的地非法 term 当拍结束且可立即恢复；
7. drain 中 flush 无需等待旧 `event_term_last` 即可恢复；
8. `clear_error` 与新非法 term 同拍时保留新错误；
9. 2C 下一个合法 context 已提交并在 fabric 中前进时，另一输入非法 term 仍可独立 drain，且非法输入不增加 issued/fabric 状态。

2C 比 1C 多出的一个 issued/completed term 是专门用于混合恢复证明的合法 term：它在另一输入非法 drain 之前已完整提交并被 fabric 阻塞，drain 结束后再释放三路 weight 和六路 Acc。TB 逐项核对 tag=`0x155`、issue sequence=`7`、token=`12/13/14`、每 bank 一次 weight、三次 Acc 更新和一次 term-done；非法 term 本身在 drain 前后均未增加 issued/fabric/weight/Acc 计数。随后 flush 进入原主回归，executor 的 issued/completed 性能计数按既有合同跨 flush 保留。

## 6. 证据边界

- 本轮关闭的是非法 metadata 输入活性和隔离，不增加架构 novelty；
- 已覆盖定向 malformed/flush 组合，但没有覆盖随机长序列 malformed、多次随机 flush 或形式化 liveness；
- 仍依赖非法非零 term 最终发送 event_term_last 的 source 合同；
- 没有重新映射面积，因为合法数据通路未变，新增 drain 状态仍需在下一次 PPDI/目标 PPA 比较中计入；
- 单 sample/window、SRAM、STA、SAIF 和目标工艺缺口不因本修复而关闭。
