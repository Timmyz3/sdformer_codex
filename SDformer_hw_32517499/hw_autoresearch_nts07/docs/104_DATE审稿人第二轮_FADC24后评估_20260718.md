## 一、复审范围与判定口径

本轮以严格的DATE硬件架构审稿口径独立复审，不默认接受首轮结论，也不把新增RTL数量等同于架构创新。重点检查以下证据：

- `docs/97_DATE审稿人视角_硬件创新与工作量差距评估_20260717.md`；
- `docs/101_H67真实四Stage消融与GateStack架构再冻结_20260717.md`；
- `results/gatestack_fadc24_fulltop_20260718/report.md`与`report.json`；
- `results/gatestack_fadc24_profile100_20260717/analysis.md`与`analysis.json`；
- FADC24流式decoder、格式金参考、向量生成器、leaf/full-top runner、SVA和真实trace日志；
- DC交付目录、约束审计以及物理公平基线的实际存在状态。

证据等级保持严格分离：

| 等级 | 本轮含义 | 可支持结论 |
|---|---|---|
| `[prof]` | profile100统计或真实位级trace软件分析 | workload动机、容量与工作量边界 |
| `[RTL]` | RTL仿真、断言、整数参考对照 | 被覆盖配置的功能与周期 |

## 二、总体结论

### 2.1 推荐意见

| 项目 | 第二轮判定 |
|---|---|
| 推荐意见 | **Weak Reject（弱拒稿）** |
| 综合评分 | **2.5/5** |
| 接收概率风险估计 | **约15%至20%**，仅表示当前稿件成熟度，不是会议统计预测 |
| 审稿信心 | 高 |
| 当前硬件定位 | 真实workload驱动、经过较强定向验证的稀疏投影子系统 |
| 尚不能使用的定位 | 完整H67 encoder加速器、运行时混合格式架构或已签核ASIC |

严格结论是：

> FADC24使GateStack从“常规稀疏表示、驻留和共享后端的组合”前进到“final-gate语义term、fanout自适应目的集合和multicast执行协同设计”。这是实质微架构增强，不再只是格式提案；但新增创新仍局限于投影子系统，而且最强混合结果来自两个编译期配置的离线择优，并非一个已实现的统一硬件。缺少目标工艺PPA、物理公平基线、完整部署精度和整encoder闭环，仍足以直接拒稿。

### 2.2 相比首轮是否有实质增强

**有，但增强幅度为“中等”，不是从无到完整系统架构。**

本轮新增的实质内容包括：

1. FADC24不再停留在软件容量模型，已经实现流式24-bit descriptor解包、token-list读取、162-bit bitmap装载与分段扫描、回压和错误排空；
2. 真实S3高扇出head完成leaf逐term、逐event检查，并覆盖随机反压、无反压和bitmap padding错误；
3. FADC24接入single-context投影执行顶层，四stage真实trace均完成候选INT8 accumulator零mismatch回放；
4. 实验得到明确的stage差异：S0和S2因decoder开销变慢，S3因消除RAW fallback显著加速，这比“全局采用新格式”的叙事更可信；
5. profile100给出了FADC24容量的保守上下界，证明该机制不是只针对一个手选样本。

但以下架构层内容没有因FADC24自动补齐：

- 运行时IPD/FADC/RAW选择与对应控制、端口和面积代价；
- head-major partial-sum spill对照；
- physically-stripped Direct/IPD/FADC公平面积基线；
- ATLIF、SCS attention、skip/residual、stage存储和外存调度；
- 目标工艺时序、面积、功耗和系统吞吐。

因此，FADC24增强的是**表示与执行数据流协同微架构**，尚不是完整加速器组织层创新。

## 四、主要审稿发现

### 4.1 FADC24的新颖性边界

FADC24不能宣称发明token list、bitmap或自适应稀疏格式。现有文档已经正确承认SMASH、Cerberus、Spada和ZeD等工作具有相邻机制。

当前可辩护的新意是以下耦合，而非任一单点：

```text
H67 final-gate与K-lane精确等价类
        -> 一个共享乘积对应一个destination set
        -> 按term fanout选择list或bitmap
        -> 直接驱动multicast累加，不展开为逐token乘积
        -> 超容量时RAW41无损回退
```

该耦合确实比首轮的“多格式前端加共享后端”更具体，也有H67 workload语义。但目前只在投影子系统中成立，且尚未用目标PPA证明多出的decoder、选择控制和bitmap扫描成本低于减少的term与数据移动。因此新颖性可上调，不能上调到强接收水平。

### 4.2 最强的混合格式结果尚未由一个硬件实现

报告给出的逐stage择优配置为S0/S1/S2使用GateStack-IPD、S3使用FADC24，四stage周期和为`195149`，相对GateStack为`1.427x`。该数字有明确的方向筛选价值，但存在关键实现边界：

- `CSR_FORMAT_FADC24`是编译期参数；
- FADC24测试显式关闭descriptor residency；
- 当前顶层没有运行时IPD/FADC选择；
- 如果分别为不同stage综合不同核，需要给出多实例面积、复用方式和stage调度；
- 如果在同一个核中同时放置两个decoder，需要重新测量选择器、双decoder、缓存格式和时序代价。

所以`1.427x`是**离线oracle式架构上界**，不是当前RTL已实现混合架构的吞吐。全FADC24的`1.410x`同样只是四个单窗口trace的周期和，不是整encoder加速比。

### 4.3 S3局部收益成立，但代表性不足

在`sample0/B0/window0`的S3回放中，FADC24将projection term从`30960`降为`12888`，减少`58.37%`；Verilator周期从GateStack的`252942`降为`169703`，对应`1.490x`。相对IPD无驻留的`259122`周期为`1.527x`。这是本轮最强、最可信的局部RTL结果。

但是：

- 每个stage只覆盖一个样本、一个block、一个window；
- leaf重点测试只有S3/head4一个真实高扇出head；
- full-top向量中四stage均未触发RAW fallback，未覆盖同一context内FADC与RAW混合执行；
- profile100没有逐term fanout，只能给容量和term工作的宽上下界；
- S0、S2在term不变时分别比GateStack慢约`8.2%`和`9.9%`，说明格式开销不可忽略。

因此可以声称“S3该真实trace显著受益”，不能声称“FADC24对H67普遍加速”。

### 4.4 Profile100动机强，但还不是完整架构评估

profile100覆盖的head实例数量充足，且FADC24 guaranteed-fit比例达到S0 `95.428%`、S1 `99.957%`、S2 `99.836%`、S3 `98.654%`，说明候选有广泛容量可行性。

需要注意，当前上界使用`min(events, 21×terms)`，在已知`max_fanout>21`时可能是偏松的保守上界。因此“guaranteed-fit”结论安全，但部分“ambiguous”可能实际也能装入；term减少范围较宽，不能作为性能预测主表。下一轮应直接补逐term fanout，消除该不确定性并报告p50/p95/p99 payload、decoder周期和fallback率。

### 4.5 基线公平性只完成了周期层的一部分

同一single-context顶层下的RAW41-only运行路径、IPD无驻留、GateStack和FADC24对照，对回答“同一控制环境下执行周期如何变化”是有价值的。尤其FADC24与IPD无驻留的S3比较，去除了residency的主要影响。

但论文级公平性仍不成立：

- RAW41-only仍是同顶层关闭路径，未物理裁掉IPD/cache/FADC逻辑，不能用于面积或功耗主表；
- 没有head-major加partial-sum spill硬件，无法证明output-tile-stationary的净收益；
- 没有统一IPD/FADC运行时硬件，无法给出混合架构面积和关键路径；
- FADC24关闭residency，而GateStack结果包含residency，两者可以用于当前实现比较，但不能分离格式与驻留的独立贡献；
- leaf decoder的Yosys generic cell比较没有包含顶层选择器、slot/cache变化和SRAM宏。

### 4.6 验证质量较好，但尚未达到签核

已成立的验证强项：

- leaf逐term、逐event与软件向量对照；
- 固定LFSR反压和无反压两种测试；
- bitmap高位padding错误注入；
- 四stagefull-top候选INT8 accumulator逐元素零mismatch；
- Icarus和Verilator均完成回放；
- FADC24专用稳定性、计数一致性、输出相序和错误粘滞SVA已经存在，leaf回归日志晚于该SVA生成时间。

仍缺少：

- 多随机seed、功能覆盖率和代码覆盖率；
- header、长度、word index、early/late last、非法lane、非法count、event总数和截断payload等系统错误矩阵；
- 运行中reset、abort、长回归和连续多head/context压力；
- FADC与RAW fallback混合context；
- 形式等价或属性证明；
- mapped netlist仿真与netlist LEC。

独立复审完成后，主线程已使用包含FADC24专用SVA的当前runner重新执行四stage full-top，全部通过，专属SVA回放缺口已经关闭。报告JSON中Icarus与Verilator周期仍分别相差S0 `2`、S1 `1`、S2 `1`、S3 `4`个周期；功能结论不受影响，但“双工具cycle-exact”claim不成立。

### 4.7 PPA仍是直接拒稿项

当前只有decoder叶级Yosys generic cell：RAW41 `293`、IPD32W `448`、流式FADC24 `954`、全buffer FADC24 `4611`。这能说明流式实现比全buffer参考轻得多，也说明流式FADC24仍约为IPD decoder的`2.13x`结构单元数。

这些数字不能回答：

- 500 MHz是否闭合；
- 24-bit解包、256-bit reservoir和bitmap优先扫描是否成为关键路径；
- SRAM宏舍入后payload缩小是否带来面积收益；
- decoder增加的动态功耗是否抵消term减少；
- 运行时双格式的选择和缓存代价；
- 面积、功耗、能量、EDP和每帧延迟。

本机`dc_shell`、`fm_shell`和`vcd2saif`缺失，目标`.db/.lib`、PVT和SRAM宏也未提供。因此PPA评分不能因FADC24 RTL完成而上调。

### 4.8 软硬件协同与系统边界仍未闭合

软硬件协同已经从“根据稀疏率选硬件”前进到“用final-gate与K-lane的网络语义定义硬件term和目的集合”，这是有效进展。

但当前权重和bias仍是候选dyadic INT8合同，尚未完成valid825部署精度、BN folding、requant、饱和、residual/skip scale与负数移位语义。硬件也未集成H67的SCS attention、93个执行ATLIF节点、S0/S1/S2 skip SRAM、stage间存储与外存搬运。因此不能把projection accumulator零mismatch扩展为“网络逐bit等价”，也不能给出整encoder FPS或能耗。

## 六、接收风险

| 风险 | 严重度 | 审稿影响 |
|---|---:|---|
| 无目标工艺PPA和SRAM宏 | 致命 | 无法支撑DATE硬件论文最核心的面积、时序、功耗和EDP |
| 混合格式只存在于编译期离线择优 | 高 | 最强性能结果不是一个可实现架构的实测结果 |
| 无physically-stripped和head-major基线 | 高 | 无法隔离格式、驻留、调度和共享后端各自收益 |
| 仅单样本、单block、单window位级回放 | 高 | 不能证明结果对完整H67 workload稳定 |
| full encoder与部署数值合同未闭合 | 高 | 容易被评为算子加速器，任务级收益与精度不明 |
| FADC专用错误与覆盖率不完整 | 中 | RTL可信，但达不到验证签核或鲁棒性主张 |
| 相邻稀疏格式工作的差异仍偏定性 | 中 | 容易被认为是已有bitmap/list机制的workload适配 |

在当前状态直接投稿，最可能的评语是：**动机和RTL实现较扎实，局部结果有吸引力，但创新仍为增量式投影微架构，且没有可验证的完整混合硬件、PPA和系统级收益。**

## 七、最关键的三项下一步

### 第一项：实现一个可综合、可测量的最终混合架构

冻结以下二选一，而不是继续报告离线oracle：

1. 单核运行时`IPD32W/FADC24/RAW41`选择，明确descriptor、cache、slot和decoder共享方式；
2. 按stage静态异构实例，明确每个stage复用哪个物理核、总面积、调度和片上存储。

必须补FADC/RAW混合context、FADC residency或明确无residency合同，并重新运行四stagefull-top专用SVA。只有这样`1.427x`才可能从架构上界晋级为已实现结果。

### 第二项：完成同约束物理基线与目标PPA

至少实现并综合：physically-stripped Direct RAW41、IPD无驻留、GateStack-IPD、最终混合FADC、head-major加partial-sum spill。统一端口、lane、SRAM容量、频率和回压，在同一`.db`、PVT与SRAM宏下报告：

- WNS/TNS、面积和关键路径；
- SRAM宏数量、舍入、端口和面积；
- mapped SAIF注释率、动态功耗、漏电和能量；
- netlist LEC与必要的门级回放；
- 分模块PPA与机制消融。

这是当前最直接的接收门槛，不能用Yosys generic cell代替。

### 第三项：闭合真实workload、部署精度与整encoder分账

扩大位级trace到多样本、12个attention block和多个window，直接采集逐term fanout并报告fallback、payload、周期和p50/p95/p99；完成valid825的RTL-exact量化精度。随后把SCS attention、GateStack、ATLIF、skip/residual、stage SRAM和外存流量纳入统一周期与能量模型，给出GateStack占整encoder的Amdahl比例、每帧延迟和带宽瓶颈。

## 八、投稿建议

目前不建议把FADC24单独包装成第二个独立主创新。更稳妥的论文主线是：

> **GateStack是一种面向all-binary事件光流final-gate等价类的精确投影数据流；FADC24是其容量安全、fanout自适应的目的集合表示，用于保护高扇出场景的multicast复用；output-tile-stationary和统一后端负责把这种表示收益转化为实际数据移动与执行收益。**

该表述将算法语义、表示、数据流和执行后端收束为一个贡献，避免把已有list/bitmap技术包装成首次提出。若完成最终混合架构、物理公平基线、目标PPA和整encoder闭环，评分有机会进入`3.5/5`至`4/5`；若只继续增加格式或控制RTL而不补这些证据，评分不会显著上升。
