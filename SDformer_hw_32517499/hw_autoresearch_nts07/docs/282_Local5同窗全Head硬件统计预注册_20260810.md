## 2. 统计口径

### 2.1 采样与加权

每个 sample/block 的 window 是在看到数据前按固定 seed 均匀抽取，inclusion probability
为 `1 / stage_windows`。后处理必须使用 selection plan 中的 `analysis_weight=stage_windows`
做加权统计，不能把 13800 个 head group 当成等概率样本直接求平均。
mean 使用逆包含概率加权；分位数使用归一化逆概率加权经验 CDF，
不把它表述为“HT 分位数”。

正式输入必须 fail-closed 满足：

| 合同 | 要求 |
|---|---:|
| sample | 100 |
| attention block | 12 |
| joint window | 1200 |
| head group | 13800 |
| source / group | 450 |
| head / stage | 3 / 6 / 12 / 24 |
| invalid candidate | 使用真实 `descriptor_valid_mask` |

### 2.2 必须输出的分布

所有 workload 指标至少报告加权 `mean/p50/p95/p99/max`：

1. active source / head-window；
2. gate-lane term / head-window；
3. destination Acc update / head-window；
4. active source gate cardinality；
5. 合法 1RW RMW 周期代理；
6. active-source scan 与 1RW-RMW 重叠代理；
7. 每 stage 的 term、update、1RW 代理；
8. 每帧 B0v/B2v 1024-bit 向量访问和共同 Acc32 输出量。

### 2.3 跨 head relation overlap

对同一 sample/block/window 内每对 head，按相同 source id 比较：

```text
exact descriptor = {K bitmap, incoming gate[5], valid mask}
gate-valid match = {incoming gate[5], valid mask}
active overlap   = Jaccard(term_count > 0)
```

三者分别报告加权 `mean/p50/p95/p99`。该统计用于判断是否存在**精确跨 head relation
去重**机会，不能把 gate-valid 相同误写成完整 relation 相同。

### 2.4 五色 bank 与 1RW

每个 source 的一个 `(gate,lane)` term 最多向五个局部 destination bank 组播。
后处理器从 gate/valid/K descriptor 重建：

- product term 数；
- destination update 数；
- 每 term 活跃 bank fanout；
- TCFM5 与普通 linear-5 的服务周期；
- `TCFM5 cycles == product terms` 的逐 group 证明检查。

合法 1RW 保守代理把每个五色 term 计为 READ/WRITE 两拍，不利用
first-touch 直写可省读的机会。它属于 `[模型]`，不包括顶层 FSM、SRAM
实际 latency、反压和时钟，因此不能标为 `[rtl]` 周期或“exact-port cycle”。

### 2.5 公共向量边界流量

只计算 B0v/B2v 不同的 projection 后物化边界，不重复计算双方共同的 term RMW：

```text
B0v 1RW vector accesses = 3 * heads * 450 * output_tiles
B2v 1RW vector accesses =     1 * 450 * output_tiles
shared scalar results   =         450 * 32 * output_tiles
```

`3*heads` 来自原 TCFM5 readout、第二级向量 Acc 首写/后续 RMW 和最终 readout。该值是
1024-bit word 访问计数，不是 SRAM 能耗；正式报告同时给 payload byte 代理。

## 3. 架构筛选门槛

真实 profile 完成后，不立即写新 RTL。每个候选先在相同合法 1RW 和相同 workload
权重下建模：

1. 加权平均周期改善必须 `>=20%`；
2. p95 周期不得退化；
3. 不得改变 Local5 hardware-order、真实 invalid mask 或 Acc32 数值合同；
4. 过门槛后才进入最小 RTL、随机反压和 Acc32 bit-exact；
5. 未过门槛则暂停 Local5 微机制扩展，下一轮转 Motion 多样本证据。

当前 B2v/B0v 的定向 `1.0557x` 已经失败，不能用向量访问下降重新包装为已晋级贡献。
只有真实 profile 和后续能量证据才能判断存储流量是否值得作为系统机制保留。
