# Local5 合法 1RW TCFM5 跨头驻留闭环

> 日期：2026-08-10  
> 前序问题：`docs/277_Local5_TCFM5原位跨头驻留累加四方闭环_20260809.md`
> 使用了持续 1R1W 行为合同，而本机开放宽 SRAM 只有单端口 1RW。  
> 本轮唯一问题：四候选统一降到可实现 1RW 后，跨头中间物化消除是否仍满足
> B2/B0 每个服务 seed 至少 `1.5x` 的事前门槛。

> 后续强基线裁决：`docs/281_Local5公共向量边界强基线负结果_20260810.md`
> 已把两侧统一到 `450x1024-bit` 向量边界，B2v/B0v 仅 `1.0557x`。因此本文
> `1.94x` 只能作为 scalar-materialize 弱 ablation，不能用于 DATE 主结果。

## 1. 结论

本轮把合法单端口 1RW Acc 接入完整链：

```text
score/Shiftmax5
  -> relation transpose
  -> source-major term
  -> five-bank TCFM5
  -> B0/B1: 独立 scalar cross-head Acc
     B2/B3: 原 TCFM5 Acc 跨 head 驻留
  -> final Acc32
```

四候选均通过 Icarus、Verilator+SVA 和 Yosys 可综合读取检查，逐项 Acc32 零失配。

| 候选 | mean 周期 | 相对对应 scalar 路径 |
|---|---:|---:|
| B0 scalar recompute | 818469.0 | 1.0000x |
| B1 scalar memo | 809756.7 | 1.0000x |
| B2 in-place recompute | 422949.0 | 1.9351x |
| B3 in-place memo | 414236.7 | 1.9548x |

- `[rtl]` B2/B0 三个 seed 为 `1.9351x / 1.9355x / 1.9348x`，最差
  `1.9348x >= 1.5x`；该数字只相对当前 scalar-materialize B0 成立，不能写成
  相对 DATE 强基线的架构加速；
- `[rtl]` B3/B1 三个 seed 为 `1.9548x / 1.9553x / 1.9544x`；
- `[rtl]` 原位路径删除 `129600` 个 partial、`129600` 次 scalar 累加写和独立
  `460800-bit` cross-head Acc 状态；
- `[rtl]` memo 的独立周期增量仍只有约 `1.021x`，不是主收益；
- `[待验证]` 当前工作负载是定向 T450 三头三 output-tile，不是 joint-head
  fullres profile100；
- `[待验证]` 尚未完成同宏开放布局布线、活动功耗或 DC/STA/SAIF/PTPX。

因此，`docs/277` 的正结果不是非法 1R1W 服务模型制造的假象；但本轮只通过
**合法端口与 RTL 周期门槛**，尚未通过 DATE 的物理和真实 workload 门槛。

## 2. 合法 1RW 数据通路

新增参数 `ACC_BACKEND_KIND=1` 后，每个颜色 bank 使用同一个
`qfit_direct_1rw_acc_bank`：

```text
第一次触达地址：1 x WRITE(delta)
重复触达地址：  1 x READ(old) -> 1 x WRITE(old + delta)
结果读取：      1 x READ
```

读写共享一个 command/address/data 端口，同拍只能执行一次读或一次写。每个 bank
保留一个 90-bit validity bitmap 做 lazy-zero：

- 首个 input head 的 `run_accumulate=0` 清 validity，不扫描写零；
- 后续 input head 的 `run_accumulate=1` 保留 validity 和 SRAM 内容；
- 第一次写某地址直接提交 delta，重复地址才执行两命令 RMW；
- 五个 bank 的存储深度、字宽、端口和控制完全相同。

这不是把 1R1W 延迟乘二的模型，而是进入原 score/relation/term 顶层的可综合
ready/valid 后端。只要一个目标颜色 bank 正在 RMW，整个多播 term 保持不接受；待所有
被选 bank 同时 ready 后才原子提交，避免同一 term 只更新部分目标。

## 3. 跨 head 驻留语义

B0/B1 每个 head 都以 `run_accumulate=0` 启动 TCFM5，得到完整 per-head
`450xOUT32` 后读出到第二级 scalar 1RW memory，再做跨头 RMW。

B2/B3 的首 head 同样清 validity，后两 head 使用 `run_accumulate=1`：

```text
head0: lazy-zero -> term stream -> five-bank Acc
head1: preserve validity/data -> term stream -> same five-bank Acc
head2: preserve validity/data -> term stream -> same five-bank Acc -> final read
```

整数顺序仍为 head0、head1、head2，每个 head 内 term 顺序不变，溢出仍为 Acc32
二补码模 `2^32`，所以旧 scalar 物化路径和新驻留路径逐项等价。

## 4. 公平服务轨迹

旧 TB 的 LFSR 每个 wall-clock 周期推进。候选周期不同后，第 n 个事务会看到不同随机
位，无法证明公平。

本轮改为 transaction-indexed 服务：

- 第 n 个 token request 的 response delay 只由 `{seed, stream=token, n}` 决定；
- 第 n 个 weight request 同理；
- 第 n 个最终 result 的 ready stall 只由 `{seed, stream=result, n}` 决定；
- 服务 hash 不随候选内部周期推进。

报告器逐 seed 检查：B0/B2 的 token 数、token delay sum、weight delay sum 和最终
result 数一致；B1/B3 同样一致；四候选的 weight 和最终 result 服务账本一致。
memo 合法减少 token 请求数，所以 B0/B1 不要求总 token delay 相等，但相同序号使用
同一生成合同。

## 5. 1R1W 与 1RW 结果差异

| 口径 | B0 | B2 | B2/B0 |
|---|---:|---:|---:|
| 旧持续 1R1W 行为合同 | 696609.0 | 307738.3 | 2.2636x |
| 本轮合法 1RW | 818469.0 | 422949.0 | 1.9351x |

单端口化使 B0 和 B2 都变慢，并把加速从 `2.26x` 收窄到 `1.94x`。B0 额外承担：

- 三个 head 的完整 TCFM5 readout；
- `86400` 个 scalar cross-head RMW 等待周期；
- `129600` 个 partial 的第二次物化与最终 drain。

B2 仍需在末 head 读取同一组五 bank Acc，因此不是“免费读出”；它节省的是前两 head
读出和整个第二级 cross-head Acc，而不是 SRAM 单端口代价本身。

## 7. DATE 贡献边界

本轮增强的是 **TCFM5 跨头驻留的可信性**，不是新增一个独立创新点。可辩护表述为：

> Local5 五色拓扑已经把空间邻接归约约束在五个颜色 bank 内；跨 input-head 维度继续
> 驻留同一组单端口 1RW Acc，可消除 per-head 向量结果的第二次物化，同时保持整数
> 精确和可实现 SRAM 端口合同。

不能单列为贡献的内容：lazy-zero、validity bitmap、单端口 RMW、banking、FIFO、
ping-pong 或 transaction-indexed TB。它们是实现和公平验证手段。

能否成为 DATE 正文机制仍取决于两项未完成门槛：

1. `[rtl]` 在真实 joint-head fullres 多样本上保持逐 workload 的显著收益和 Acc32；
2. `[开放映射代理]` 同一 1RW 宏、同 SDC、同边界下，EDP 或面积归一吞吐改善至少
   `20%`；最终仍需 DC/STA/SAIF/PTPX。

## 8. 下一步

独立评审确认没有推翻 Acc32 正确性的 P0，但指出当前 B0 的最终服务粒度比 B2 弱：
job engine 对同一 `1024-bit` 行执行 32 次独立读取，再把 32 个标量写入
`14400x32` cross-head memory。这使 `1.9348x` 混入了标量物化接口的收益。

下一单项先构造强基线 B0v，再决定是否进入物理代理：

1. B0v 按 `450x1024` 向量字物化并在向量粒度完成合法 1RW 跨头归约；
2. B0v 与 B2v 从同一个向量边界进入完全相同的 32 路 serializer/consumer；
3. 逐事务 `{type,index,identity,delay}` SHA 一致，Acc32 零失配；
4. B2v/B0v 每个 seed 至少 `1.20x`，否则不进入开放物理晋级；
5. 晋级后再以同宏、同 SDC、同 floorplan 规则比较，面积归一吞吐或可信 EDP
   必须至少改善 `20%`。

真实 joint-head fullres profile 仍由现有 GPU watcher 等待训练空闲；在其产物出现前，
本文保持“定向 RTL 通过、真实 workload 待验证”的证据边界。

## 9. 独立 DATE 评审

独立审稿结论为 **Weak Reject / Major Revision**：当前包在其预设 scalar-B0
合同内通过 `PASS_CYCLE_GATE`，但尚未通过强基线、真实 workload 与物理门槛。

### 9.1 正确性裁决

- P0：未发现；合法输入、三头三 tile 定向范围内 Acc32 正确，但不是形式完备证明；
- `[rtl]` lazy-zero 与 `run_accumulate` 语义成立；
- `[rtl]` 对合法 term，所有选中 bank 同时 ready 后才统一提交，原子多播成立；
- `[rtl]` transaction-indexed 延迟不依赖 wall-clock，但日志还缺逐事务身份 SHA；
- P2 仍缺单 bank 忙的多播压力、head-count 边界、连续 clear/accumulate、长反压
  与计数 wrap 覆盖。

### 9.2 公平性裁决

当前 `1.9348x` 可以且只能表述为：

> `[rtl]` 相对当前 scalar-materialize B0 的定向加速为 `1.9348x` 至
> `1.9355x`。

三个 seed 的 B0-B2 差值都为 `395520` cycle，且差值全部落在
readout/materialization/final-drain 路径。由于 B0 重复读取同一向量行 32 次，审稿人
会把它视为合法 legacy ablation，但不会接受为 DATE 主基线。

### 9.3 评分与贡献边界

| 范围 | 评分 | 判断 |
|---|---:|---|
| 当前证据包 | 3.6/5 | RTL correctness 较强，fairness 有 P1 |
| Local5 整体 | 3.3/5 | 系统实现扎实，真实全链和物理未闭合 |
| 架构创新 | 2.5/5 | 五色数据流有特异性，跨头驻留单独看增量有限 |
| DATE 就绪度 | 2.7/5 | Weak Reject，需强基线、profile、PPA 共同补齐 |

TCFM5 跨头驻留当前不能进入摘要贡献列表，只能作为 Local5
relation-driven source-major/TCFM5 数据流的组成机制。即使 B0v 与开放物理门槛通过，
仍需真实 profile100、跨 stage/block/head-count 的 Acc32 与收益分布才能进入正文主结果。
