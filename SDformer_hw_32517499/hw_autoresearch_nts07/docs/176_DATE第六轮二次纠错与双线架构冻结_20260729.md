# DATE 第六轮二次纠错与双线架构冻结

## 1. 结论先行

本轮最重要的结果不是又得到一个更大的加速数字，而是发现 Motion 与 Local5
不能强行共用同一种 destination 编码。

| 主线 | 当前保留路径 | 当前淘汰路径 | 判定 |
|---|---|---|---|
| Motion | 静态 temporal anchor + exact residual + fixed64/M4 | 单 destination ISHD | M4 已有打包优势，ISHD 增加发射周期 |
| Local5 | self-K stationary + directional residual + MFEP/ISHD | 在线 pattern discovery | 固定五点拓扑无需在线发现，ISHD 位数收益明显 |

共同架构原则冻结为：

> **Topology-Declared Exact Residual Execution，拓扑声明式精确残差执行。**

网络描述符提前声明时间对或五点 stencil 的关系，硬件只执行 anchor 与 exact
residual，不在运行时预测、搜索或近似稀疏关系。Motion 和 Local5 共享
`anchor/residual` 执行骨架，但在 destination 后端按真实 workload 采用不同编码。

这是一套可实现的双线架构，不是为了统一而统一的单一格式。

## 2. 第二次 P0 纠错

### 2.1 Motion PPDI 奇偶必须使用展平 token ID

旧实现：

```text
parity = (flat_token_id % spatial_tokens) & 1
```

当 `T=2,N=81` 时，展平 ID `0` 和 `81` 会先变成空间 ID `0/0`，被错误地判成
两个偶 destination。RTL accumulator 的偶奇端口实际使用展平 ID LSB，因此正确
定义是：

```text
parity = flat_token_id & 1
```

新增定向测试用同一空间位置的 `T0/T1` 构造 ID `0/81`：

```text
M1 = 2
exact PPDI = 1
```

### 2.2 `gate=0` 不得形成投影 term

gated-K 的数值定义为：

```text
output = gate_q17 * K
```

当 `gate_q17=0` 时，即使 K lane 活动，输出仍恒为零。旧 profiler 会把
`{gate=0,lane}` 计入 term、delivery 和 PPDI，夸大工作量并污染门码基数。

修复后，投影统计在形成 class count 前执行：

```text
effective_K = K & (gate != 0)
```

网络前向数值没有变化，只修正硬件工作量统计。

### 2.3 ordered trace 自适应 `int16/int32`

旧编码无条件转换为 `int16`，计数 `40000` 会静默变为 `-25536`。新合同：

| 值域 | 编码 |
|---|---|
| `[-32768,32767]` | `int16_le` |
| `int16` 之外、`int32` 以内 | `int32_le` |
| 超出 `int32` | profiler 失败 |

公共分析器、双线 delta DSE 和 Phi/Prosperity 模型均兼容两种编码。新增
`40000` 往返测试，禁止静默溢出。

## 3. destination、packed command 与 fabric bits 分账

Motion profile 中三个量必须分开：

```text
unique product term = projection_gate_class_channel_terms_deploy
destination count   = projection_gate_multicast_delivery_m1
M4 packed command   = projection_gate_multicast_delivery_m4
```

旧模型把 M4 命令数同时当成 destination 数，再用它计算 ISHD continuation，
等价于免费消失一部分目的。修复后：

- term 决定 product/weight fetch；
- M1 决定必须守恒的 destination 数；
- M4 决定现有 fixed64 接口的命令数；
- ISHD 一条 header 后按每个额外 destination 发 continuation；
- fabric 只报告接口实际传输位数，不再除以 bank-local weight fetch。

新的互连门槛为：

```text
ISHD fabric bits 相对同配置 fixed64/M4 至少减少 15%
```

旧的“fabric metadata 占全部 payload 不超过 10%”定义已废止，因为权重 SRAM
流量不经过该窄命令互连，不能作为分母。

## 4. 修正后的双线结果

结果来自：

```text
results/phi_prosperity_dual_line_sim_20260729/report.json
```

证据边界：

- T162 workload 来自旧 profile100；
- 周期是 Python 模型，不是 RTL；
- 旧 profile 尚未包含本轮 `gate=0/parity/int32` 修复；
- T450 是 `25/9` 外推，不是 fullres 实测；
- 因此以下数字用于架构淘汰，不用于论文主表。

### 4.1 Local5

| 指标 | ISHD |
|---|---:|
| raw speedup | 1.583× |
| `32/(32+W4)` lane 归一代理 | 1.407× |
| fabric bits 相对 fixed64 | -80.19% |
| p99/mean | 1.283 |

解释：

- Local5 pre-G0 没有 M4/PPDI 打包证据，模型保守使用一 destination/command；
- ISHD 位数收益很大，但周期收益来自 self-anchor/MFEP，不是编码本身；
- `p99/mean` 只是样本分布，Local5 缺 ordered FIFO trace，不能当尾延迟；
- Local5 ISHD 可以保留为 RTL 候选，但必须等 post-G0 destination delta/escape。

### 4.2 Motion

| 指标 | fixed64/M4 | 单 destination ISHD |
|---|---:|---:|
| raw speedup | 1.359× | 1.093× |
| lane 归一代理 | 1.208× | 0.972× |
| p99/mean | 1.210 | 1.253 |
| fabric bits 相对 fixed64 | 基线 | -30.22% |

解释：

- ISHD 虽减少约 30% 命令位数，却把 M4 delivery 展开为逐 destination 发射；
- 位数减少没有转化成周期收益，反而使 lane 归一吞吐低于 direct；
- Motion 的单 destination ISHD 正式淘汰；
- Motion 暂时保留 fixed64/M4，待新 profile 的 exact PPDI 判断是否替换 M4；
- 若未来设计 packed-delta continuation，必须基于逐 term destination trace重新建模，
  不能从 M1/M4 聚合数反推。

## 6. 双线下一版 RTL 冻结

### 6.1 共同前端：TDRE

```text
Topology Descriptor
  {mode, stage, token_count, anchor_count, residual_width, mask_mode}
        |
        v
Anchor Reader -> 32-lane Anchor Engine
        |                  |
        |             exact residual
        +------------> W-lane Residual Engine
                           |
                           v
                   Score/Class Commit
```

两种 mode：

| mode | anchor | residual | 是否在线 discovery |
|---|---|---|---|
| Motion | `{t0,t1}` temporal pair | XOR/toggle lanes | 否 |
| Local5 | self K | up/down/left/right delta | 否 |

共同模块只复用物理 lane、队列和 commit 协议，不要求两种 workload 使用相同
destination 编码。

### 6.2 Motion 唯一 RTL 机制

> **TARE + SCS/SET-term + fixed64/M4 exact multicast。**

必须支持：

- T162 与 T450 参数化地址宽度；
- `gate=0` 零工作；
- 展平 token parity；
- M1/M4/PPDI 三套计数器；
- stage-conditioned Prosperity-style bypass 仅作为静态配置；
- backpressure 下 destination 不丢失、不重复。

PPDI 只有新 profile100/fullres 显示命令减少至少 15%，且同约束 RTL EDP
优于 M4 至少 10%，才替换 M4。

### 6.3 Local5 唯一 RTL 机制

> **Self-K-stationary + multiplicity-preserving MFEP + native-m ISHD。**

必须支持：

- 真实 invalid-candidate mask；
- self anchor 与四方向 residual；
- unique term 和 destination count 分离；
- term header 原子提交；
- destination delta escape/fallback；
- ordered FIFO 与 final backpressure；
- post-G0/fullres T450。

ISHD 只有 `delta6 escape <=1%`、无损 fallback 覆盖 100%、fabric bits
相对 fixed64 至少减少 15%，才进入 DC。

## 7. 可单列的 DATE 架构贡献

当前可以继续验证、但不能提前写成已完成贡献的只有三条：

1. **Topology-Declared Exact Residual Execution**  
   将网络已知时间对/五点拓扑编码为硬件描述符，消除 Prosperity/Phi 类在线
   relation discovery；共享 anchor/residual lane 但允许双线后端专化。

2. **Multiplicity-Preserving Gate/Term Projection**  
   唯一 product term 与 destination multiplicity 分离，既复用
   `{gate,lane,multiplicity}` product，又严格守恒每个 accumulator 写目的。
   Motion 使用 M4/PPDI，Local5 使用 ISHD。

3. **Stage-Conditioned Exact Bypass**  
   根据真实 stage workload 静态选择 direct、anchor/residual 或 product path，
   不做有损裁剪和运行时预测。官方 Prosperity 微 trace 已提供动机，但完整收益
   仍需 full-encoder trace 和 RTL。

以下不能单列贡献：

- 双 context；
- 3-bank；
- descriptor 时间复用；
- fixed64 或 ISHD 编码本身；
- “借鉴 WAL/SSA/VC”后的重新命名；
- Phi 假设命中率。

## 9. 当前 DATE 判定

本轮应把可信度提升视为进展，不把淘汰 Motion ISHD 视为损失。

```text
当前建议：Weak Reject
架构状态：共同 TDRE 原则已形成，双线后端完成第一次数据驱动分化
RTL 状态：旧子系统 RTL 很深，但新冻结的双线端到端顶层尚未完成
PPA 状态：无同约束 DC/STA/SAIF，不可投稿
```

下一次晋级条件不是增加术语，而是：

```text
新 profile -> 每线一个端到端 RTL -> 模型/RTL误差<10% -> 同约束 PPA
```
