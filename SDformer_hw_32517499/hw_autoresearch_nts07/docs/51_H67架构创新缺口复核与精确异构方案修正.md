# H67 架构创新缺口复核与精确异构方案修正

**日期**：2026-07-13  
**对象**：H67 all-binary Motion-XOR TTX 主线及现有 attention row RTL  
**性质**：架构立项审阅，不修改 RTL，不把分析候选写成已实现贡献

## 0. 最终判断

另一个 agent 的核心诊断是正确的：当前已经完成的是算法定点化、attention row 算子微结构、逐位验证和 DC 交接准备，还不是一套经过实现与 PPA 证明的加速器架构。

但其 Arch-A 至 Arch-E 不能原样进入 RTL，原因有三点：

1. `empty`、`K-zero`、`motion-zero` 的时间范围没有写严谨，原样实现可能破坏冻结 hardware-order 部署模型的逐位等价性。
2. “dense/sparse 双核”如果只复刻 Bishop 的方框图，创新性不足；而且当前 profile100 只有聚合比例，尚不能证明双核有净周期或能耗收益。
3. Arch-B、Arch-C 和 Arch-E 分别更接近必要的数据流支撑、issue 微结构和系统完整性，不能包装成三项彼此独立的架构创新。

本轮建议把主方案修正为：

> **两时间片联合的精确充分统计量异构 attention 引擎**：同一 temporal pair 内联合计算两个时间片，稀疏路径用事件索引集合求交/对称差，稠密路径用位图 AND/XOR-popcount；两条路径生成完全相同的 H67 充分统计量，再进入共享的 RNE、SCS-Shiftmax 和 gated-K 后端。

暂用工作名 **PHEA**（Pair-fused Heterogeneous Exact Attention）。该名称只用于工程讨论，投稿前还需检索命名冲突。

## 1. 当前硬件工作的准确层级

| 已有内容 | 准确层级 | 是否可独立作为 DATE 架构贡献 |
|---|---|---|
| Motion-XOR、Q7 score、Q1.7 gate | 算法/数值格式协同 | 否 |
| K-zero score-class folding、occupied-class scan | attention 算子微结构 | 可作为子贡献，不能单独撑起架构论文 |
| 162 深度、35 类、93 个执行 ATLIF 点 | 语义和容量冻结 | 否 |
| 12-block descriptor scheduler | 固定遍历控制 | 否 |

| profile100 empty/K-zero/motion-zero | 架构机会证据 | 不是周期、功耗或 PPA 结果 |

代码证据：

- `rtl_h67/h67_attention_top.sv:60-118` 只连接固定 descriptor scheduler 和一个 row engine。
- `rtl_ttx/ttx_descriptor_scheduler.sv:90-114` 每次只发一行并等待该行完成，没有多核分流、FIFO、bank 仲裁或跨核 completion。
- `rtl_h67/h67_score_class_row_engine.sv:84-85` 的 active-entry 和 histogram 仍是 RTL 数组；正式同步 SRAM 时序尚未进入状态机。

因此“当前几乎没有架构创新”这个评价虽然措辞较重，但在论文分层上基本成立。

## 2. 先冻结 H67 的硬件部署数值合同

### 2.1 必须区分原软件顺序和 hardware-order golden

当前 RTL 不是对训练/原部署软件顺序逐位等价。原部署路径为：

```text
raw score -> center -> Q7 quant -> float Shiftmax -> Q1.7 gate
```

当前 RTL 验证路径为：

```text
raw score -> Q7 quant -> Q8 exp2 LUT -> integer denominator -> Q1.7 gate
```

代码在 `bsa_attention.py:3063-3090` 明确把两条路径分开。仓库也已有 162-token 反例：raw Q7 class `0/1` 各 81 个时，`center -> RNE` 得到 `0/0`，而 hardware-order 的 `raw -> RNE` 保留 `0/1`，见 `results/h67_score_reference.md:10`。

因此后续“exact”统一指：

> **对冻结 hardware-order deployment model 的 score、LUT、denominator、gate 和 gated-K 逐位一致。**

它不能写成“对训练网络或原 PyTorch 部署逐位一致”。当前 valid825 证明的是 hardware-order 模型可接受：H67 相对原部署 AEE 为 `+0.0001`、AAE 为 `+0.0091`、spikes 为 `-0.0404G`，见 `results/h67_h68_rtl_exact_valid825.md:7-10`。这属于经过任务精度验证的部署顺序变换，不是数学 bit-exact。

论文中应分两层报告：

- **算法到硬件部署变换**：用 AEE/AAE/spikes 说明误差和收益；
- **hardware-order golden 到 RTL**：要求 0 bit mismatch。

### 2.2 冻结公式

对时间片 `t` 的一个 spatial token/head，定义：

```text
o_t = popcount(Q_t AND K_t)
q_t = popcount(Q_t)
k_t = popcount(K_t)
z_t = D - q_t - k_t + o_t
m   = popcount(K_0 XOR K_1)
D   = 32
```

H67 中心化前 Q7 分数等价为：

```text
N_t       = 64*o_t + z_t + 16*m
score_q7  = RNE(N_t / 16)
```

这与软件中的 `overlap + same_zero/64 + motion/4`、`head_dim=32` 归一化及 RTL 的统一 round-to-nearest-even 顺序一致。对应代码为：

- 软件：`bsa_attention.py:950-983`；
- temporal K XOR：`bsa_attention.py:986-1010`；
- RTL：`rtl_h67/h67_motionxor_score_q7.sv:17-63`。

本轮另做了不写文件的 CPU sanity check：随机种子 `6702`，100000 组 32-bit `Q0/Q1/K0/K1`，分别用 dense 位图公式和 Python 事件 index set 的交集/对称差公式计算两个时间片，0 mismatch；同时确认 `PAIR_EMPTY=2`、当前时间片空但 peer-K 单 bit 时为 `3`、K-zero 可达类为 `0..34` 共 35 类。该结果只证明代数重写方向正确，不替代后续固定脚本、真实 trace、RTL 和 formal。

### 2.3 `empty` 必须区分当前时间片和完整 temporal pair

只有下面这个谓词才有固定 silent score：

```text
PAIR_EMPTY = (Q0|Q1|K0|K1) == 0
```

此时 `N0=N1=32`，所以两个时间片的 `score_q7` 都为 `2`。它们可以不读 payload，但必须向 row max/Shiftmax 分母注入两个 class-2 项，不能删除 token。

下面这个较弱谓词不是常量：

```text
CURRENT_EMPTY = (Qt|Kt) == 0
```

反例：若 `Qt=Kt=0`，但 `Kpeer` 有一个 1，则 `m=1`，`score_q7=3`；若 `Kpeer=0`，则 `score_q7=2`。因此 Arch-C 的 `Q|K empty -> S_silent` 必须改写成完整 temporal-pair empty，不能只看当前时间片。

现有 true-TTB collector 的 bundle empty 是跨两个时间片统计，定义本身是正确的；问题在于架构文案和接口必须把这个范围写出来。

### 2.4 `K-zero` 不是单一 score 常量

当 `K_t=0` 时，gated-K 输出确实为零，所以该 token 不需要写 active replay bank；但它仍参与 row max 和 Shiftmax 分母，而且 score 取决于 `Q_t` 和 `K_peer`：

```text
N_t = 32 - popcount(Q_t) + 16*popcount(K_peer)
```

其可达 `score_q7` 为 `0..34`，这正是 H67 RTL 使用 35 个 class 的原因。正确行为是“计算精确 class 后只写 histogram”，不是“注入一个 K-zero 常量”。

### 2.5 `motion-zero` 只能在早到 metadata 下节省 Motion-XOR 主体

如果 `motion_zero` 是先做 `K0 XOR K1` 和归约后才得到，则 XOR 已经发生，只能 gate 后级 popcount/累加或寄存器，不能把整条 Motion-XOR 的能耗都记成节省。

要在 payload 读取前关闭 motion 分支，`motion_zero` 必须在 pair 写入/压缩端生成，连同 tag、valid 和 ECC/parity 一起进入 metadata bank。metadata 生成、写入和读取的能耗必须计入。

### 2.6 `u=0` 复用对 hardware-order golden 是 exact，但增量更新不能只缓存已舍入 Q7

定义：

```text
U = (Q0 XOR Q1) OR (K0 XOR K1)
u = popcount(U)
```

若 `u=0`，则两时间片 Q/K 完全相同，`score_q7(t1)=score_q7(t0)`，直接复用已舍入 score 是逐位等价的。

若 `u>0` 并做 delta update，则必须缓存舍入前的 `N_t` 或等价的充分统计量，最后统一 RNE。只在已舍入 `score_q7` 上加 delta 可能因 half-way tie 破坏逐位等价。

## 3. 对 Arch-A 至 Arch-E 的逐项复核

| 提案 | 判断 | 修正 |
|---|---|---|
| Arch-A MD-HETE | 方向正确，但原样采用有复刻 Bishop 和语义不清风险 | 双路径必须位于 H67 attention 内部，并分别实现精确集合基数算法和稠密位图算法；不能写“只算 active、silent 常量补齐”而不证明公式 |
| Arch-B fused memory hierarchy | 必须做，但单独新颖性偏弱 | 与 pair-fused 计算、单格式 payload、class-aware commit 和实际 bank/port schedule 绑定，成为主架构的数据流贡献 |
| Arch-C cascade exact issue | 可做的微结构，不足以作主架构 | 将 PAIR_EMPTY/U0/计算算法、KZERO commit、motion-zero gate 拆成正交决策；不能把五个属性串成互斥 L0-L3 |
| Arch-D ETCR | 有价值，但需要状态与 tag 成本 | 对 T=2 更优先采用 pair co-compute；只有 trace 证明跨 pair reuse 有净收益时才增加 previous-state table |
| Arch-E full-encoder skeleton | 决定论文口径完整性，不是新颖性 | 必须进入系统模型；若未实现 projection/ATLIF/skip，只能称 attention accelerator，不能称全 SDformer 芯片 |

### 3.1 为什么不能直接复制 Bishop

Bishop 的异构 dense/sparse core 主要服务 MLP 和 projection 的 spike-weight synaptic integration；它另设 binary attention core，并结合 BSA/ECP。其 stratifier 按 feature 的 active TTB 数分流，论文也明确阈值失衡会降低 EDP，数据移动主导能耗。

H67 与其不同之处必须落实到电路，而不是只写 workload 不同：

- H67 双路径计算的是同一套 exact set-cardinality score，不是 dense/sparse spike-weight MAC；
- H67 同时利用 `Q/K` 空间事件稀疏和 `T=2` temporal pair 结构；
- H67 不使用 ECP，不丢 Q/K/score/token；
- 两条路径都输出同一 `(o0,z0,o1,z1,m)` 或 `(N0,N1)` 合同；
- 后端是 class-aware SCS 和 gated-K，不是 Bishop 的普通 spiking attention 后端。

只有这些差异形成 RTL、cycle 和 PPA，才是合法迁移；“Bishop 形、H67 神”不是投稿证据。

## 4. 修正版主架构：PHEA

### 4.1 核心观察：H67 不需要逐 lane 处理 silent/silent

`same_zero` 可由充分统计量恢复：

```text
z_t = D - popcount(Q_t) - popcount(K_t) + popcount(Q_t AND K_t)
```

因此稀疏路径不需要遍历 0/0 lane，也不需要对 mixed token 使用不严谨的 `S_silent` 注入。它只需对事件索引集合执行：

```text
|Q0|, |Q1|, |K0|, |K1|
|Q0 intersect K0|, |Q1 intersect K1|
|K0 symmetric_difference K1|
```

稠密路径对四个 32-bit 位图做 AND/XOR-popcount，稀疏路径对四个有序 index list 做 merge/intersection。两条路径数学上生成同一充分统计量，后端完全共享。

这比“看到 spike 稀疏就跳过 0”更适合 H67，因为 silent/silent 对 score 有非零奖励，但它已被精确代数吸收。

### 4.2 数据流

```text
Q0/Q1/K0/K1 写入
        |
        v
Pair Packer + Metadata Generator
  - pair_empty / kzero[1:0] / motion_zero / u / active_count
  - dense bitmap 或 sparse index packet（二选一，不双份常驻）
        |
        v
Exact Route Classifier
  +----------------------+----------------------+
  |                                             |
  v                                             v
Sparse Set-Cardinality Core             Dense Bitmap-Popcount Core
merge/intersect/sym-diff                AND/XOR + popcount tree
  |                                             |
  +----------------------+----------------------+
                         v
             Canonical Tuple Commit
             (N0,N1,K0,K1,token tags)
                         |
        +----------------+----------------+
        |                                 |
        v                                 v
K-zero/Class-only Commit          Active Replay Bank
35-class histogram + bitmap       score + K + token
        |                                 |
        +---------------+-----------------+
                        v
       Shared SCS Backend: row-max -> occupied class/active exp2
                        v
               single Shiftmax gate -> gated-K emit
```

### 4.3 精确 issue 不是一条互斥四级链

`PAIR_EMPTY`、`u=0`、`K_t=0`、`motion_zero` 和 dense/sparse 分流描述的是不同维度，可能同时成立。控制器应拆成三个正交决策，而不是把它们硬串成 L0-L3：

**计算路由**：

| 路由 | 精确谓词 | 行为 |
|---|---|---|
| C0 | `PAIR_EMPTY` | 不读 payload；为两个时间片各生成 class-2 score |
| C1 | `u=0` 且 t0 state/tag valid | t0 精确计算一次，t1 复用；仍分别生成两个 token completion |
| C2 | `0<u<=theta_delta` 且舍入前 t0 state 可用 | 只更新变化 lane，保存/输出完整 `N_t` 后统一 RNE；未过 H67 G0 前关闭 |
| C3 | sparse set cost 小于 stage 阈值 | 用 index merge/intersection 生成充分统计量 |
| C4 | 其他 | 用 32-bit bitmap popcount 生成充分统计量 |

**commit 路由**：

| 属性 | 行为 |
|---|---|
| `K_t=0` | 精确 score 写 class histogram，不写 active replay bank |
| `K_t!=0` | 写 active replay bank，后续 gated-K emit |

**局部门控属性**：

| 属性 | 行为 |
|---|---|
| `motion_zero` | 关闭 motion popcount/累加的 eligible cycles；只有写入端早到 metadata 才能进一步减少 peer-K bank 读取 |

例如一个 pair 可以同时满足 `u=0`、`motion_zero`，且其中某一时间片 `K_t=0`；计算路由选择 C1，commit 路由仍需分别按两个时间片的 K-zero 属性处理。这样才能避免原 Arch-C 把正交条件错误地当成互斥优先级。

### 4.4 稀疏和稠密分流不应只用一个 density

当前资料混合了两种不同的稀疏性：

- **event-set sparsity**：四个 `Q0/Q1/K0/K1` 位图中的事件数，决定 index merge 与 bitmap popcount 的交叉点；
- **temporal-delta sparsity**：`u=popcount(U)`，决定 t1 delta 是否比重算便宜。

建议路由器使用二维代价而不是 Bishop 式单阈值：

```text
w_set   = |Q0| + |Q1| + |K0| + |K1|
w_delta = u
route   = argmin(C_pair_sparse(w_set), C_delta(w_delta), C_dense)
```

最终阈值必须由同一频率约束下的 RTL latency、FIFO 等待和 SRAM 事务拟合，不允许只用 `ceil(active/lanes)` 作为完整服务时间。

### 4.5 存储层次

建议至少四级片上结构：

| Bank | 内容 | 关键要求 |
|---|---|---|
| M0 metadata bank | format、pair-empty、kzero、motion-zero、u/active count、offset、tag | 早于 payload 到达；tag/ECC 与 payload 一致 |
| M1 pair payload banks | 逻辑上同地址的 Q0/Q1/K0/K1；物理上拆成可独立使能的 4 个 32-bit bank，或存 sparse packet | 不能同时常驻两份表示后只统计一份容量 |
| M2 active replay bank | `{score_q7,K32,token}` 或 SRAM 对齐格式 | 同步读、真实宏深度/宽度、双缓冲端口需冻结 |
| M3 class/SCS bank | 35 类 count、occupied bitmap、row max/den、completion | 支持 class commit 与 active commit 的原子 row tag |

`pair co-resident` 只表示四个操作数共享 descriptor/address，不应默认做成一个不可分割的 128-bit SRAM word。若做成单个 128-bit word，则 `motion_zero` 不能节省 peer-K 的 SRAM 读取；若论文声称 selective fetch，必须采用物理分 bank，并计入额外 decoder、时钟和端口成本。

稀疏 packet 可用 `stream_id[1:0]+lane_id[4:0]` 表示一个事件，并带四个 list count/offset。其真实交叉点应比较：

```text
dense payload = 4*32 = 128 bit/pair
sparse payload ~= 7*w_set + counts/offset/align
```

SRAM 以宏读宽和事务数计能耗；即使逻辑位数减少，若仍触发相同 128-bit macro read，也不能声称 memory energy 下降。

### 4.6 调度与控制

控制至少需要：

- metadata issue queue；
- sparse/dense 两个有限深度 FIFO；
- stage-aware route threshold 和 high-watermark exact fallback；
- pair/token/row 完整 tag；
- canonical commit scoreboard，保证 row 完成后才进入 hardware-order Shiftmax；
- shared SCS credit 和 backpressure；
- FIFO overflow、starvation、duplicate/stale commit 断言；
- route、fallback、bank conflict、queue occupancy、gated cycle 性能计数器。

若 sparse FIFO 满，允许转入 dense full recompute；不允许丢 descriptor。该 fallback 只改变效率，不改变结果。

## 5. 哪些内容能成为 DATE 贡献

### 5.1 可辩护的贡献组合

1. **软硬件协同**：先把原软件 `center -> quant` 变换成任务精度已验证的 hardware-order 部署顺序，再把 H67 all-binary Motion-XOR score 重写成可由精确充分统计量计算的整数形式；所有架构优化对该 hardware-order golden 保留 silent/silent、temporal motion、分母和 gated-K 语义。
2. **主架构**：PHEA 两时间片联合异构引擎，在 attention 内用 sparse set-cardinality 与 dense bitmap-popcount 双路径执行同一 exact score，并通过有限 FIFO、stage-aware cost routing 和 exact fallback 处理动态稀疏。
3. **数据流/存储微架构**：pair-format payload、class-aware commit 与共享 SCS/gated-K 后端融合，避免 K-zero active replay，并用 occupied class 扫描减少 Shiftmax 后端工作。

### 5.2 不应单列为贡献

- 发明 Shiftmax 或 base-2 softmax；
- Q7/Q1.7 位宽；
- 162 深度或 35 类容量修正；
- 12-block descriptor 时间复用；
- 93 个 ATLIF 执行点统计；
- elastic FIFO、双缓冲、clock gate 本身；
- 未实现的 dual-path、ETCR 或 full encoder 方框图。

### 5.3 与相关工作的边界

| 工作 | 可借鉴 | PHEA 必须形成的差异 |
|---|---|---|
| Bishop, ISCA 2025 | TTB、异构分流、阈值/失衡 DSE | 双路径位于 exact H67 attention；不使用 BSA/ECP；输出精确充分统计量而不是 spike-weight 部分和 |
| SpAtten, HPCA 2021 | cascade issue 组织 | 不 prune token/head，不用 progressive quant 作为 exact 依据 |
| FLAT, ASPLOS 2023 | operator fusion、tiling、减少中间存储 | workload 不是标准 `QK^T-softmax-V`；核心是 T=2 pair 和 class-aware normalization |
| LoAS, MICRO 2024 | temporal-inner、单 bit 连续压缩、join 成本意识 | 不处理 dual-sparse weight spMspM；稀疏核执行 Q/K 集合基数 |
| Prosperity, HPCA 2025 | exact reuse 和 full-tag 方法 | 主线不依赖跨 row TCAM/product match；pair co-compute 是确定性局部复用 |
| NEURAL, 2025 预印本 | elastic FIFO、data/event 解耦 | FIFO 是支撑结构，不作为本项目主创新；需避免复述其 hybrid data-event 宣称 |

## 6. Full-Encoder Skeleton 的正确定位

系统图应包含：

```text
Frame/Stage Descriptor Scheduler
        |
        +--> projection/event-MAC lane cluster
        +--> shared PHEA attention engine
        +--> time-multiplexed ATLIF lane cluster + state SRAM
        +--> 每个 Swin block 的 attention residual + MLP residual
        +--> projection/residual ports
        +--> S0/S1/S2 skip SRAM ports
```

其中 S0/S1/S2 是三条跨 stage skip，S3 是 bottleneck 输出，不画成第四条 skip。

每个 Swin block 内还存在两次局部残差：attention 输出与 shortcut 的 `sew_function`，以及 MLP 输出与 block state 的第二次 `sew_function`，代码见 `Spiking_swin_transformer3D.py:831-845`。它们与 S0/S1/S2 跨 stage skip 不是同一层级，系统图、端口和存储模型必须分别表示。

93 是软件执行到的 ATLIF 逻辑点数量，不表示物理实例化 93 套或 105 套。硬件应按吞吐预算配置 `P_ATLIF` 条 lane，状态 SRAM 用 `{site,token,channel,time}` 索引，由 descriptor 时间复用。

该 skeleton 的作用是：

- 给 attention 加速占端到端周期/能耗的 Amdahl 分母；
- 计入 projection、ATLIF state、residual、skip 和数据搬运；
- 防止把 row-engine FPS 写成整网 FPS。

它是系统完整性要求，不应被包装为新颖性。

## 7. 当前 profile 的证据边界

已知 H67 profile100：

- bit activity：`1.502114%`；
- TTB4 pair-empty：`60.963301%`；
- TTB4 K-zero：`75.636288%`；
- TTB4 motion-zero：`75.667241%`。

这里的 TTB4 K-zero/motion-zero 都是“两时间片、四个连续空间 token、32 lane”的整 bundle 统计，不等于现有 RTL 的单时间片 per-token K-zero folding 比例，也不等于 motion branch 的实际 gated-cycle 比例。它们只能用作 bundle 级上限，不能直接代入 row RTL 周期或功耗公式。

这些只证明存在执行机会。当前仍缺：

- v2 ordered trace 的正式 artifact；当前 watcher 尚在软件串行队列后等待；
- `w_set` 与 `u` 的二维联合直方图；
- per-stage、per-head、per-row 的 burst/run length；
- sparse/dense route 的 ordered trace；
- sparse packet 对齐后实际 64/128-bit SRAM transaction；
- FIFO、bank conflict、shared backend credit 和 p99；
- raw/sufficient-statistic golden sidecar，用于逐 route bit-exact replay。

现有 `replay_ttb_dual_path_cycles.py` 已具备有限 FIFO 原型，但其 `service_cycles=ceil(active/lanes)+常数` 仍是抽象模型，尚未包含 index merge、tuple commit、同步 SRAM、row join、SCS credit 和 H67 RNE。因此不能把其未来输出直接当成架构 speedup。

## 8. 晋级门槛

### G0：两层数值门

**G0-A，软件到 hardware-order 部署**：

- 明确这是部署顺序变换，不声明 bit-exact；
- 报告 valid825 AEE/AAE/spikes 与原部署差异；
- 若主线模型或量化参数变化，重新跑该比较，不能沿用 H67 ep19 的 `+0.0001`。

**G0-B，hardware-order golden 到架构/RTL**：

- PAIR_EMPTY 两个 class-2 注入与软件逐 bit 相等；
- K-zero `0..34` 类全部覆盖；
- sparse set core 与 dense bitmap core 对全部单 lane 状态穷举一致，并对真实 trace/随机 32-bit pair 一致；
- delta 路径在舍入前状态上更新，最终 RNE 与 full recompute 一致；
- fallback、反压、flush 下无丢失、重复和 stale tag。

### G1：周期

同一 ordered trace、同一 SRAM latency/port、同一 SCS backend 下比较：

1. 现有 dense row reference；
2. metadata-first 单 dense；
3. pair-fused 单 dense；
4. pair-fused sparse/dense PHEA。

报告 frame cycles、rows/s、平均/p95/p99 row latency、FIFO occupancy、fallback、bank/backend stall。PHEA 必须相对第 3 项仍有净收益，不能只相对最弱 baseline。

### G2：存储与控制

- 逻辑 bit、macro 对齐 bit、read/write transaction 分开；
- metadata、compactor、FIFO、index packet、join、score state、class bank 全部计入；
- sparse 路径 idle power、第二供数端口和 clock tree 计入；
- peak SRAM port 不超过选定 macro 能力。

### G3：同工艺 PPA

- 相同 library/PVT/SDC/VT/频率/不确定度；
- SRAM compiler 或同一 characterized wrapper；
- trace-derived SAIF/VCD；
- logic/macro/total area、WNS/TNS/Fmax、dynamic/leakage/clock/memory power、energy/frame；
- DC 后 Formality 或等价 LEC。

### G4：端到端

- attention、projection、ATLIF、skip/residual、decoder/IO 的周期和能耗分账；
- valid825 同时报告原部署与 hardware-order 部署的 H67 AEE/AAE/spikes；RTL只对后者要求 bit-exact；
- attention 子系统收益换算成整网收益时使用实测 Amdahl 占比。

## 9. 推荐执行顺序

1. **先改规格，不先改 RTL**：冻结 hardware-order golden，以及 PAIR_EMPTY、KZERO_CLASS、U0_REUSE、SPARSE_SET、DENSE_BITMAP 的真值表和 score-state 位宽。
2. **等待并审计 v2 ordered trace**：不能从 legacy profile100 直接决定双核阈值。
3. **补联合 profiler**：输出 `H(stage,w_set,u,kzero_mask,motionzero)`、ordered route、packet bytes 和宏事务。
4. **升级 cycle model**：加入 sparse merge 服务时间、同步 bank、两个 FIFO、canonical commit、SCS credit 和 fallback。
5. **先做叶子 RTL**：sparse set-cardinality core、dense pair core、canonical tuple comparator；过 G0 后再搭双路径 top。
6. **实现 class-aware bank 与共享 SCS**：此时 Arch-B/C 才从文档变成架构。
7. **同约束比较四个 baseline**：若 PHEA 相对 pair-fused single-dense 没有周期或能耗净收益，退出双核，保留 pair-fused 单核。
8. **最后补 encoder skeleton 和系统模型**：用于端到端口径，不阻塞 attention 叶子验证。

## 10. 本轮签核结论

| 问题 | 结论 |
|---|---|
| 当前是否已有足够的架构创新 | 否 |
| 另一个 agent 的总体诊断是否有道理 | 有道理 |
| 是否应直接实现其 Arch-C 四级 FSM | 否，谓词和时间范围需先修正，且 Arch-C 单独不构成主架构 |
| 是否应直接复制 Bishop 异构双核 | 否，先用真实 trace 和本项目 exact set-cardinality 语义建立独立机制 |
| 最值得做的架构主线 | 两时间片联合、充分统计量、稀疏集合/稠密位图异构、共享 class-aware SCS 后端 |
| 是否需要 full encoder | 需要进入系统模型；是否全 RTL 化取决于论文是 attention accelerator 还是全 SDformer accelerator |
| 现在能否宣称 DATE 架构贡献完成 | 不能；需完成 G0-G4 中至少 attention 范围的 RTL、cycle、SRAM 和同工艺 PPA |

最关键的调整不是再增加一个名字，而是把 H67 的独特数学结构变成一个 Bishop、SpAtten、FLAT 和 LoAS 都没有直接给出的可综合执行机制，并用强 baseline 证明异构性本身值得付出控制和存储成本。
