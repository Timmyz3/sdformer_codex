# 转置分段 Bitmap 存储端口化与淘汰结论

## 1. 目标

C0/C1 canonical workspace 原先使用 `class × lane × token` 三维 bitmap。该写法功能正确，但没有明确物理 bank、读写端口和映射边界，开放综合会把大部分结构展开为 mux。为回答独立审稿中“存储层次是否真实”的问题，本轮实现了可选的转置分段候选：

```text
token stream: {class, token_id, 32-bit K lanes}
                       |
                       v
          segment = token_id / 16
          bit     = token_id % 16
                       |
        +--------------+--------------+
        | 11 segment groups × 32 lanes |
        | each tiny bank: 4 class ×16b |
        +--------------+--------------+
                       |
        read {class,lane}: 11×16b parallel
                       |
                162-bit term bitmap
```

对应 RTL 为 `rtl_hitflow/gatestack_transposed_bitmap_bank.sv`。workspace 参数 `EXPLICIT_BITMAP_BANK_ENABLE` 控制是否启用；默认值保持为 0。

## 2. 端口合同

### 2.1 Capture 写入

- 每拍最多接收一个 token；
- `token_id` 选择唯一 16-token segment 和 segment 内 bit；
- `K[31:0]` 选择最多 32 个 lane bank；
- 每个 `{segment,lane}` bank 只写一个 class 地址；
- 新 head 只清 valid，不清数据；读端用 valid 屏蔽旧 head 内容。

这种转置布局服务于 H67 的真实访问方向：输入是 token-major，输出 term 是 lane-major。它不是普通顺序 SRAM，也不能假定单个 1R1W SRAM 宏能直接实现 32-lane 同拍写入。

### 2.2 Term 读取

- 一拍只请求一个 `{class,lane}` term；
- 11 个 segment 并行读出并拼成 162-bit bitmap；
- 线性 walker、16-bit segmented walker 和 BPB 均从同一个 `destination_remaining` 快照消费；
- backpressure 期间快照保持稳定，不依赖 bank 输出继续稳定。

## 3. 功能结果

显式 bank 与原隐式数组在以下四个组合均保持逐 destination 精确一致：

| 存储 | Walker | 结果 |
|---|---|---|
| 隐式数组 | 线性扫描 | PASS |
| 隐式数组 | 16-bit 分段 | PASS |
| 转置显式 bank | 线性扫描 | PASS |
| 转置显式 bank | 16-bit 分段 | PASS |

显式 bank 接入完整 workspace 后，真实三 case 仍为 93 terms、941 destinations；线性扫描 10832 拍，分段扫描 941 拍。C0 全 45-head 与 C1 全 45-head 的 word、term、destination、scan 及周期也保持原结果，说明存储重排没有改变算法或序列化语义 `[rtl]`。

## 4. 综合负面结果

开放 Yosys 对显式候选提示将 `segment_bank_q` 和 `segment_valid_q` 展开为寄存器列表。仅 bitmap bank 模块在 180 秒限制内未完成 `proc; opt; memory_collect; check; stat`，返回 timeout。原因不是功能错误，而是 352 个深度为 4 的多小 bank、动态 class 地址和并行读取不能被通用 memory inference 识别。

因此本轮作出明确淘汰判断：

> 当前“全展开显式 bank RTL”不晋级为 DC 主线；它只保留为端口合同和未来 macro/generator 映射参考。默认 workspace 继续采用已通过开放综合的隐式数组。

不能在论文中把该候选写成已降低面积，也不能拿 timeout 前的中间结构推算 PPA。

## 5. 可实现的后续分支

| 分支 | 机制 | 代价 | 晋级条件 |
|---|---|---|---|
| A：专用 register-file generator | 物理生成 11×32 个 4×16b 小 bank | 宏数量和布线高 | 有真实 macro/布局面积与时序 |
| B：lane 分组 | 每拍写 8 或 16 lane，capture 变 2/4 拍 | 降低写端口，增加 capture 周期 | 系统 EDP 优于 C0，C1 可隐藏新增周期 |
| C：capture token-major、后台转置 | 单口 162×32b SRAM，空闲期转置为 term-major | 增加转置缓冲和阶段周期 | 与 C1 overlap 后 projection EDP 改善至少 15% |
| D：仅保存 active destination list | 取消完整 bitmap，低 fanout 直接 list | 大 fanout/BPB 需 fallback | profile100 长尾和 RAW fallback 可控 |

当前优先级是 B/C 的周期-端口 DSE，而不是继续优化 352-bank 的 RTL 展开写法。B/C 必须在完整 projection slice 中测量，不能只比较 Builder。

## 6. 对架构创新的影响

本轮的价值是把“canonical bitmap”从抽象数据结构推进为明确访问冲突：H67 同时要求 token-major 32-lane 写入与 term-major 162-token 读取，本质是在线 bit-matrix transpose。可辩护的架构问题是如何利用 C1 的 capture/service overlap 隐藏受限端口下的转置成本，而不是声称二维数组本身新颖。

后续论文若形成贡献，应表述为“端口受限的在线转置与有序双 workspace 协同”，并用同工艺 PPA/EDP 证明；在完成该证据前，本项仍是经过负面实验筛选的候选方向。
