# DATE 架构签核差距与三候选决策

> **同日真实四 stage 修订**：`docs/121` 已完成 S0-S3 完整 Builder-to-projection 回放。C0/C1 总周期为 `196864/192770`，C1 系统收益仅 `1.021x`，Builder 占比只有 `7.17%`。因此本文原建议的 C0-EG 跨 group 重叠降为次要调度优化；新的平衡主候选改为 `C0+BPB+HATF96`。HATF96 真实 RTL 周期为参数扫阶段的约 `2.61x`，开放库逻辑面积归一吞吐约 `1.18x`，详见 `docs/126`。本修订不改变“架构签核未通过”，因为 DC/SRAM/SAIF/多 trace 仍缺。

**日期**：2026-07-20  
**审阅对象**：H67 GateStack 的 C0+BPB、C1 双 workspace、共享 typed-slot 到 projection 数据流  
**审阅角色**：架构签核编排  
**当前结论**：**条件冻结 C0+BPB 为面积效率默认配置；架构签核未通过；当前证据不支持宣称已达到 DATE 接收标准。**

## 1. 审阅结论

当前工作已经从“压缩算子 RTL”推进到具备明确生产者、驻留存储、消费者和生命周期合同的 projection 子系统：

```text
final-gate/K
  -> canonical gate-stack workspace
  -> IPD/FADC/RAW 格式决策
  -> 分段精确 walker / BPB
  -> atomic typed-slot
  -> inspect/replay/release
  -> decoder / multicast / projection / AccTile / bias / final
```

其中，C0+BPB 的完整 Builder、C1 双 workspace 的有序共享 Serializer，以及 typed-slot 无 payload 复制接入 projection，均已有不同范围的 `[rtl]` 证据。它们足以说明架构不再只是一个行内核，但尚不足以完成 DATE 论文所需的系统签核，原因有四点：

1. C1 的 `1.403x` 只在单个真实 window 的 Builder 边界成立，不能外推为完整 projection 或 encoder 加速；
2. 小规模完整链路已观察到 Amdahl 稀释：Builder 局部 `1.597x` 最终只形成 `1.243x` 总加速；
3. C1 在开放目标库逻辑映射中面积为 C0 的 `1.728x`，面积归一吞吐仅为 `0.812x`，且 13/19 个 memory 均未计面积；
4. 当前没有任何 `[DC]` 面积、时序、功耗、SRAM 宏或 mapped SAIF 结果，不能评价真实 EDP。

因此，今天可冻结的是“架构研究方向”，不是“最终芯片配置”：

- **论文与工程默认候选**：C0+BPB；
- **下一轮优先研究候选**：C0+BPB+96-lane head-aligned term-fused supertile；
- **可选吞吐候选**：C1 双 workspace，仅在绝对吞吐或完整 projection EDP 证明必要时晋级。

## 3. Amdahl 分析

### 3.1 已实测的小规模完整链路

小规模完整集成中：

| 项目 | C0 | C1 | 变化 |
|---|---:|---:|---:|
| Builder | 115 cycle | 72 cycle | `1.597x` |
| projection | 105 cycle | 105 cycle | 不变 |
| 总周期 | 220 cycle | 177 cycle | `1.243x` |

C0 中 Builder 占比为 `115/220=52.27%`。按 Amdahl 定律：

```text
S_total = 1 / ((1-f_builder) + f_builder/S_builder)
        = 1 / (0.4773 + 0.5227/1.597)
        = 1.243x
```

该值与 RTL 总周期完全一致。它证明共享 typed-slot 的无复制接线是正确的，同时也证明只优化 Builder 不能支撑更大的系统级加速主张。

### 3.2 真实 45-head Builder 收益的系统上限

以已实测的 Builder 加速 `1.40289x` 为固定值，完整 projection 中 Builder 占比不同，理论总加速如下：

| Builder 占完整 projection 比例 | Amdahl 总加速上限 |
|---:|---:|
| 20% | `1.061x` |
| 40% | `1.130x` |
| 60% | `1.208x` |
| 80% | `1.298x` |
| 100% | `1.403x` |

因此，C1 要达到既定的 GateStack 子系统 `>=1.20x` 目标，真实完整 projection 中 Builder 必须约占 60%，或者 C1 还必须隐藏 replay、projection 或 group 间串行阶段。当前尚无真实完整链路数据证明这一条件成立。

### 3.3 对候选设计的直接指导

1. 继续增加 canonical workspace 只能改善 Builder 内部重叠，无法消除 Builder 与 projection 之间的 group barrier；
2. balanced 候选应优先让 typed-slot 的生产与 projection 消费跨 group 重叠；
3. aggressive 候选只有同时获得 head 内重叠和 group 间重叠，才可能抵消 C1 的面积与存储代价；
4. 在 full-encoder 模型仍只有约 `23.09 FPS` `[模型]` 时，不能用 Builder 局部结果宣称达到 30 FPS。

## 4. 存储与物理实现审阅

### 4.1 已知逻辑容量

既有规格在 24-head context 口径下给出：

| 存储 | 逻辑容量 | 证据性质 |
|---|---:|---|
| Head slot | `24 x 104 x 64 = 159744 bit` | RTL 参数形状，非 SRAM 宏 |
| Descriptor cache D80 | `24 x 80 x 24 = 46080 bit` | RTL 参数形状，非 SRAM 宏 |
| AccTile | `162 x 32 x 32 = 165888 bit` | RTL 参数形状，非 SRAM 宏 |
| 三项小计 | `371712 bit = 45.38 KiB` | 逻辑容量，不含 metadata 与 macro rounding |

每个 canonical workspace 至少包含：

- `4 x 32 x 162 = 20736 bit` destination bitmap；
- `162 x 41 = 6642 bit` RAW scratch；
- 两项合计 `27378 bit = 3.34 KiB`，尚未计入 valid、fanout、term directory、tag、FSM 和互连。

这些位数只能作为 `[模型]` 容量下界。C1 复制 workspace 后，开放综合 memory object 从 13 增至 19，但 memory object 数量既不表示 bit 数，也不表示宏面积。

### 4.2 当前最主要的存储风险

H67 canonical bitmap 要求 token-major 的 32-lane 写和 term-major 的 162-token 读，本质是在线 bit-matrix transpose。当前显式 `11 segment x 32 lane`、共 352 个 tiny-bank 的候选虽然 `[rtl]` bit-exact，但 Yosys 在 180 秒内无法完成 memory inference，已经正确淘汰为默认实现。

因此：

- 当前隐式 bitmap 数组可用于功能 RTL，不等价于可交付 SRAM 微架构；
- Nangate45 的 `32550/56262` logic area 不含 13/19 个 `$mem_v2`，不能用于总面积结论；
- C1 的真实面积惩罚可能高于或低于 `72.8%`，取决于 workspace 能否映射为合理的寄存器文件或 SRAM 宏及其端口复制；
- balanced 候选必须优先复用现有 typed-slot 的 1R1W 生命周期，避免复制完整 canonical workspace。

## 5. 三个候选架构

### 5.1 保守候选：C0-BPB-S

**组成**：单 canonical workspace、16-bit segmented exact walker、BPB、单共享 Serializer、atomic typed-slot、共享 projection 后端、group barrier。

**当前证据**：

- 完整 45-head Builder 与逐 word replay 为 `[rtl]`；
- 小规模 typed-slot 到 projection 的无 payload 复制为 `[rtl]`；
- 真实完整 projection 仍未闭环；
- 逻辑面积只有 `[开放目标库代理]`，没有 `[DC]`。

**优点**：控制最简单；没有 workspace 复制；当前验证成熟度最高；开放库代理下单位面积吞吐优于 C1。

**缺点**：capture、analyze、serialize 串行；group 构建完成后才启动 projection；首帧和稳态吞吐上限最低。

**风险**：中等。主要风险不是功能正确性，而是完整 projection 和 full encoder 吞吐可能不达标。

**决策**：**当前默认配置与论文保底配置。** 在 balanced/aggressive 未通过完整 EDP 门槛前，不得被替换。

### 5.2 平衡候选：C0-EG

**组成**：保留单 canonical workspace 与单 Serializer，在 typed-slot 生命周期上加入两个 epoch-tagged group；projection 消费 group N 的只读 slot 时，Builder 可把 group N+1 写入不冲突的空闲 slot。使用现有 slot SRAM 的读写分离端口，避免复制完整 workspace。

```text
单 C0 Builder -> typed-slot 写端口 -> group N+1
                         同一 slot 池
共享 projection <- typed-slot 读端口 <- group N
```

**创新定位**：不是普通 ping-pong，而是把 format、payload tag、group epoch、last-use 和 release 合并为同一个无复制生命周期，使三种物理格式在共享 SRAM 中进行跨 group 生产者/消费者重叠。

**当前证据**：typed-slot 的 inspect/replay/release 与无 payload 复制为 `[rtl]`；跨 group epoch、slot 分区和生产消费重叠尚为 `[模型待补]`，没有完整 RTL。

**吞吐预期**：改善稳态 group throughput，而不改善第一组延迟。上限取决于 `max(T_builder, T_projection)`，优于当前串行的 `T_builder+T_projection`；必须用真实多 group trace 验证端口冲突和 slot 占用。

**存储代价**：优先使用同一 24-slot 池的分区和 generation tag，只增加 group metadata；若容量分析证明必须双 bank，最坏额外复制 24-head slot payload `19.5 KiB`，但仍应避免复制 canonical workspace、descriptor cache 和 AccTile。

**风险**：中高。主要风险为 slot 容量不足、release 延迟造成生产者阻塞、1R1W 端口冲突、跨 group abort/reset 和 tag wrap。

**决策**：**下一轮首选研究候选。** 它直接攻击已观察到的 Amdahl 串行边界，且比复制整个 workspace 更符合面积效率目标。

### 5.3 激进候选：C1-EG

**组成**：C1 双 canonical workspace、sequence-ordered oldest-ready 发射、单共享 Serializer、epoch-tagged typed-slot 跨 group 流水、共享 projection 后端。只有在真实瓶颈证明后，才允许增加 lane grouping 或后台 transpose；不得默认增加第二 Serializer 或第二 projection 核。

**当前证据**：C1 Builder `1.403x` 为 `[rtl]`；跨 group typed-slot 流水尚未实现；逻辑面积 `1.728x` 仅为 `[开放目标库代理]`；`[DC]` 为空。

**优点**：同时隐藏 head capture/analyze 与前一 head serialize，并可进一步隐藏下一 group 构建与当前 group projection，吞吐潜力最高。

**缺点**：workspace 复制使 bitmap、RAW scratch、目录、mux 和控制显著增长；当前面积归一吞吐为 `0.812x`，已经给出负面预警。

**风险**：高。包括存储端口不可映射、时序恶化、共享 Serializer 饥饿、两个层级的有序提交、异常恢复状态空间和验证成本。

**决策**：**只保留为吞吐模式。** 若完整 projection 的 EDP、吞吐/面积或绝对 FPS 目标不能显著优于 C0-EG，应淘汰，不得因 Builder 局部 `1.403x` 强行晋级。

## 7. 风险登记

风险分数为“发生概率 1--5 × 影响 1--5”。分数不低于 15 的项目在架构签核前必须有可验证的缓解结果。

| 编号 | 风险 | 分数 | 缓解与退出条件 | 责任方向 |
|---|---|---:|---|---|
| R1 | 目标 node、库、PVT、面积和功耗绝对预算未冻结 | 25 | 冻结工艺与预算，建立统一 SDC/DC 主表 | 后端与架构 |
| R2 | 精确 trace 只有单样本、单 block、单 window | 20 | 100 帧、12 block、每 block 至少 4 window | 软件与 profiling |

| R4 | Builder 收益被 projection 与 encoder Amdahl 稀释 | 20 | 真实完整 projection 和 full-encoder 周期分账 | 架构与性能建模 |
| R5 | C1 面积和能量抵消吞吐收益 | 20 | SRAM+logic 总面积、SAIF energy/head、EDP 决策 | 后端与功耗 |
| R6 | 跨 group epoch、abort、reset、tag wrap 验证不完整 | 16 | 长序列随机反压、故障注入、覆盖率和 SVA 闭环 | 验证 |

当前所有高风险均有路径，但尚未全部得到结果，因此不满足 architecture sign-off。

## 8. P0 接收级门槛

这里的“接收级门槛”表示具备有竞争力、可审稿的硬件证据，不表示可以保证 DATE 录用。

### P0-1：主张边界冻结

- 在 full encoder 数据流、存储和周期未闭环前，统一称为 **GateStack projection subsystem**；
- `1.403x` 只标注为单真实 window 的 Builder RTL 加速；
- `1.243x` 只标注为小规模完整链路 RTL 加速；
- 所有 Nangate45 数字标注 `[开放目标库代理]`；
- 在真实 DC 完成前，`[DC]` 一栏明确写“无”。

### P0-2：代表性真实 trace

- 至少 100 个有效帧、12 个 attention block、每 block 至少 4 个 window；
- 固定 frame/stage/block/window/head/token/lane 顺序和版本 hash；
- 报告 IPD/FADC/RAW、BPB、fanout、term、word、fallback、C0/C1 周期、阻塞、重叠和背压的均值、P50、P95、P99、max；
- 覆盖 empty、最大 fanout、FADC 长尾、RAW fallback、负权重、饱和和随机反压。

### P0-3：真实完整 projection 与 Amdahl 闭环

- C0、C1 和最终 balanced 候选使用同一真实 S0-S3 输入、权重、bias 与输出金参考；
- Builder、replay/decode、multicast/product、AccTile、bias/final 分阶段计数；
- 逐元素零失配，payload copy 保持 0；
- 最终候选相对最佳 exact baseline 的 projection 子系统吞吐至少 `1.20x`；
- full encoder 周期模型必须由 RTL 子模块实测校准，并给出最坏场景和 1.25 保护系数。

### P0-4：目标库与存储 PPA

- 冻结目标 node、standard-cell `.db`、PVT、Vt、500 MHz SDC、面积预算和功耗预算；
- Direct RAW、单一 CSR/bitmap、C0 无 BPB、C0+BPB、balanced、C1+BPB 使用相同约束；
- SRAM compiler 或可复核宏模型覆盖 head slot、workspace、descriptor cache 和 AccTile；
- setup WNS `>=0`、TNS `=0`，hold 无未解释违例；
- mapped SAIF 覆盖率不低于 95%，报告 logic、memory、clock、IO、leakage；
- 最终候选相对最佳 exact baseline 的 EDP 改善至少 15%；
- 总面积与总功耗均不超过绝对预算的 80%，并保留 15%--20% 实现余量；
- 完成 RTL-to-mapped LEC 或独立门级等价回归。

### P0-5：候选晋级规则

- **C0-BPB-S**：若 balanced/aggressive 未过 P0，自动作为论文默认；
- **C0-EG**：只有完整 projection 稳态吞吐 `>=1.20x`、EDP 改善 `>=15%`、面积增量 `<=35%`，才晋级默认；
- **C1-EG**：除满足上述门槛外，还必须使吞吐/面积不低于 C0，且证明 C0-EG 无法达到绝对 FPS 目标；否则只作为吞吐消融；
- 任何候选一旦依赖近似删除 silent token、改变 Shiftmax 分母或改变 gate/K 数值，必须重新训练并独立报告算法精度，不得混入 exact 主表。

### P0-6：验证与部署

- C1/epoch 流水完成第三个 head 阻塞、sequence wrap、长随机反压、done stall、reset、abort、timeout 和 stale release；
- P0 功能点覆盖率 100%，关键控制 SVA 全通过，code coverage 缺口有逐项解释；
- 权重、bias、requant、residual/skip 数值合同冻结；
- valid825 部署 AEE 相对冻结算法点的退化门槛预先定义并通过，建议不超过 `0.02`；
- 论文所有周期、PPA、精度和 workload 表能够由固定入口脚本复现。

## 9. 最终决策记录

1. **当前 architecture sign-off：不通过。** 缺绝对面积/功耗约束、目标库 DC、SRAM 宏、真实多 trace 和 full-encoder 闭环，违反最终签核条件。
2. **当前默认架构：C0+BPB。** 它的证据最成熟，且在现有开放库代理下单位面积吞吐优于 C1。
3. **下一项架构创新：C0-EG。** 用 epoch-tagged typed-slot 生命周期消除 group barrier，优先复用 slot 的读写端口，不复制完整 canonical workspace。
4. **C1 的定位：吞吐模式和上界消融。** 只有系统级 EDP 或绝对 FPS 证明必要时才晋级；当前 `1.403x` Builder 收益不足以抵消 `1.728x` 逻辑面积代理。
5. **论文叙事应聚焦组合创新**：workload-derived canonical gate-stack、fanout-adaptive tri-format residency、segmented exact walker、BPB、typed-slot 无复制生命周期，以及经证据筛选的跨 group 流水；不得把 bitmap、双缓冲或 Shiftmax 单独宣称为首次提出。

下一轮架构工作应先完成真实 S0-S3 的 Builder-to-projection 周期分账，再建立 C0-EG 的多 group 周期与容量模型。若模型无法同时达到 `>=1.20x` projection 吞吐、`<=35%` 面积增量和 `>=15%` EDP 改善，则停止扩展控制结构，维持 C0+BPB 投稿主线。
