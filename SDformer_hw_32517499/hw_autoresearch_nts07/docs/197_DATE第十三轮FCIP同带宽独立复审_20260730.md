# DATE 第十三轮 FCIP 同带宽独立复审

## 1. 结论

本轮复审发生在旧 fragment 上下界模型之后、真实 bit-trace 同带宽模型之前。
结论为：

> **Weak Reject，接近 Borderline Reject；总分约 2.7/5，FCIP 新颖性约
> 3.0/5。**

FCIP 已经从算子优化上升为可讨论的关系平面架构，但当时的性能优势主要来自
不等带宽和理想装配器，不能据此进入 RTL。

---

## 2. 审稿人认可的部分

1. FCIP 与 B1 active-member replay、B2 联合关系平面之间存在真实结构差异；
2. `C[class,dst]` 与 `K[lane,dst]` 的因子分解不是简单重命名；
3. 相对仓库已有 `gatestack_transposed_bitmap_bank` 的
   `class×lane×destination` 物化关系，FCIP 有明确容量动机；
4. 整数参考证明了给定 class-to-gate 映射后的因子交集语义；
5. S16 overflow 和 whole-row fallback 被明确列为边界，没有冒充 RTL。

---

## 3. P0 问题

### 3.1 带宽不公平

旧模型的 B1 是 W1，而 FCIP 使用 W4/W8。必须补：

```text
B1-W1 = active_token + final_term
B1-W4 = ceil(active_token/4) + final_term
```

并保持相同 product/term 出口。

### 3.2 理想重叠

旧式：

```text
alias + max(intersection, emit, product)
```

隐含无限或免费 FIFO、无 fill/drain、无上下文占用和无回压，不能作为周期。

### 3.3 免费装配器与 occupancy oracle

fragment 到完整 term 的装配没有状态、端口和周期；模型直接知道非空
class-lane fragment，相当于使用联合关系 oracle。

### 3.4 fallback 不是逐拍路径

整数参考中的 overflow 只是软件分支调用 baseline，没有证明硬件 abort、
epoch 清理、Q/K 驻留和 replay。

### 3.5 tail 统计不正确

不能使用两个独立 p99 的比值，应逐行计算：

```text
slowdown[row] = candidate_cycles[row] / baseline_cycles[row]
```

再报告配对 p95/p99、慢于 10% 的行比例和 aggregate speedup。

---

## 4. 晋级门槛

审稿人只支持再做一轮 CPU 有限资源模型：

1. B1-W1/W4、B2-W1/W4、FCIP-W1/W4 同带宽；
2. 2/4 个有界 term assembly context；
3. 单外部 term sink；
4. SRAM 读延迟、回压、fallback 尾部；
5. 多样本真实 segment identity；
6. 预测收益至少 15%，p99 退化低于 10%，否则停止扩 RTL；
7. 真正进入论文前仍需 macro/DC/STA/SAIF。

---

## 5. 本轮之后的执行决定

本意见已落实为：

- 从已有 H67 NPZ 重建真实 score class 和 segment relation；
- 不再使用旧 fragment 上下界作为主结果；
- 建立同带宽、有界上下文、单出口逐拍模型；
- 原始 FCIP 若不能超过 B1，则作为负结果冻结；
- 只允许利用 SCS 与 projection 跨算子时序形成新的架构，而不是继续增加
  FCIP 端口。
