# H81 G1 硬件复用矩阵与启动门

日期：2026-08-16。状态：设计合同就绪，
`G0_PASS_G1_BLOCKED_BY_SELECTOR_AND_MVSEC_FAIL`，未写 H81 RTL。

## 1. 复用边界

| 层 | 现有对象 | H81 处理 | 证据是否可继承 |
|---|---|---|---|
| score leaf | `h67_motionxor_score_q7` | 该 leaf 已有 `ENABLE_MOTION_XOR=0` 精确路径；G1 只允许由独立 H81 wrapper 选择 | 叶级公式可复用，H67 trace/周期不可继承 |
| score pair front | `h67_mssb5_score_pair` / `h67_mssb5_temporal_slot_encoder` | 不复用；MSSB5 第五统计是 Motion-XOR 特化 | 不可继承 MSSB5 面积、路径和创新主张 |
| pair quotient | slot compare、temporal mask、multiplicity、active mask | 原理和格式复用；H81 wrapper 必须将 score leaf 设为 no-motion | 数学合同可复用，必须重跑 H81 miter |
| buffering | dual-slot FIFO、双 workspace LAWS、K store | 原样复用候选 | SVA 方法可复用，活动/性能须重跑 |
| normalization | weighted SCS、row max、Shiftmax、Q1.7 gate | 在相同 Q7/Q1.7 hardware-order 合同下复用 | 算子合同可复用；H67 denominator 分布数字不可继承 |
| recovery/projection | temporal K recovery、真实 INT8 Acc32 sidecar | 结构复用，换 H81 checkpoint 权重与 trace | TB/金参考方法可复用，结果须重建 |
| PPA handoff | DC/Formality/PT/SAIF 脚本骨架 | 可新增 H81 顶层后复用 | H67 VCD、SAIF、面积、功耗、WNS 全不可继承 |

## 2. 为什么不是“直接翻一个参数”

底层 score leaf 已支持 no-motion，但当前生产 `h67_temporal_slot_encoder`、
`h67_temporal_score_quotient` 和 LAWS wrapper 仍把 `ENABLE_MOTION_XOR` 硬连为 1，且公平
TB、向量和活动合同均绑定 H67。因此 H81 G1 应新增旁路 wrapper/filelist，默认 H67 路径不变，
不能在原顶层全局翻参后沿用旧证据。

## 3. H81 G1 最小实施顺序

仅当后续模型重新通过 MVSEC 四序列门且 selector 明确选择 H81 后执行：

1. 从冻结 H81 checkpoint 导出 sample/window/stage 有身份绑定的 raw Q/K、Q7 score 与真实 INT8 权重；
2. 新增 H81 no-motion score-pair wrapper，分别接 Fixed2S 与 RQTB2S；
3. 在同 FIFO、workspace、K store、Shiftmax、projection 和 LFSR 反压下重跑公平周期；
4. 独立重算 Q7 equality，检查 RTL `slots=2P-E`；
5. gated-K、真实 INT8 Acc32、随机反压和跨样本逐行零失配；
6. 形成新的 VCD/SAIF 身份合同，再进入服务器 DC/Formality/PTPX/PTSTA。

H81 只有在上述第 3--5 步同时通过后，才从“算法后备线”升级为“硬件候选线”。任何
H67 的 `1.1865x`、MSSB5 开放映射或活动文件都不能搬入 H81 表格。

## 4. 预期工作量

RTL 主体的大部分存储、归一化和恢复后端可复用；需要新写的是窄 score wrapper、H81 向量
adapter、公平 TB 身份和活动合同。工程上不是推倒重做，但创新上只剩 exact score-class
quotient，不能继承 Motion-XOR/MSSB5 的 3.2 分叙事。若 H81 最终成为唯一模型，必须按 H81
实测重新评创新，不能用“代码复用率高”替代架构新意。
