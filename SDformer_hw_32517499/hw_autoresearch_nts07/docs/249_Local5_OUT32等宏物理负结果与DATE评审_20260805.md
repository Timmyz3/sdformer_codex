# Local5 OUT32 等宏物理负结果与 DATE 评审

## 本轮完成内容

本轮将 Local5 投影 tile 扩展到 `OUT_DIM=32`，并为 relation SRAM 和五组 Acc SRAM 同时绑定 FakeRAM45 宏。Direct、Issue、DS 三种后端在同一 profile100 工作量下完成通用模型与宏模型逐项等价、随机反压和 SVA 回归。

开放物理流程统一使用 Nangate45、5 ns、32 个 SRAM 宏和固定 outline。Direct 完成宏放置、placement、CTS 和 global-route，并进行多轮 detailed-route 尝试。完整数字见：

- `results/local5_out32_allmacro_openroad_20260805/report.md`

## OpenROAD 物理结论

最终物理代理设置为 `2000×1600 µm²` die、`20 µm` macro halo、`40 µm` macro channel。32 个宏全部放置；CTS 和 global-route 的已约束路径在 5 ns 下无 setup violation，global-route 最差 slack 为 `+0.76 ns`。

但以下三项阻止签核：

1. 仍有 60 个未约束端点，正 slack 不能代表全设计。
2. global-route 仍有 9 个 overflow。
3. detailed-route 从 106281 个 DRC 降至最低 63 个后，在 63–114 个 M3 spacing 之间振荡，未达到 zero DRC。

因此证据只能写成 `[open-pnr][代理]`，不能写成 route-clean、STA sign-off 或 ASIC PPA。增大宏通道将违例平台从约 2.3k 降至两位数，说明宏引脚逃逸和局部通道是实质瓶颈；继续无限增加迭代没有意义。

## DATE 审稿人评审

评分：`3/5`。

推荐：`Reject（大修后重审）`。

审稿人认可：

- OUT32 与真实宏接口已进入 RTL 等价验证。
- Direct/Issue/DS 在宏配置和工作量上公平。
- 负结果如实暴露了 GASR resident state、控制和互连面积。
- OpenROAD 找到了宏引脚逃逸与布线拥塞风险。

主要拒稿原因：

- 只有 Direct 有物理尝试，三候选尚无公平物理 PPA。
- 60 个未约束端点使时序结论不闭合。
- DRC 与 overflow 非零，不是可实现 P&R。
- DS 的面积损失大于周期收益，能耗尚无证据。
- 当前仍是 projection tile 范围，不能替代 full-network PPA。

## 下一轮唯一最高优先级

先修复 Direct 基线的物理约束与布线闭环：

1. 定位并消除或合理约束 60 个未约束端点。
2. 定位残余 M3 spacing 的对象类型，区分信号线、宏 pin、PDN 或开放 LEF 规则问题。
3. 仅在 Direct 达到 zero DRC、zero overflow、完整 setup/hold 后，决定是否路由 DS。

Local5 仍是当前主线，Motion 也继续推进，但下一轮的唯一 RTL/物理闭环对象是 Direct。Motion 可以并行做 profile 和新机制筛选，不在同一轮扩展第二套顶层 RTL。
