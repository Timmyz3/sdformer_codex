# Motion ZKQI 三方强基线与同宏物理闭环

## 1. 本轮结论

本轮把 docs/267 中通过准入的 three-class zero-K quotient injection
从 [模型] 推进到行级 [rtl]，并补齐同 SRAM 宏、同 outline、同 SDC 的
[open-pnr代理]。结论不是“Motion 已完成 DATE 架构”，而是：

1. [rtl] RQTB2S、普通 pair-bitmap zero-K 和 TTB8-ZKQI 三方共享相同
   row store、双 score lane、weighted-SCS 和 gated-K 后端；
2. [rtl] 138 条真实 fullres T450 head-row、两个模拟器、四种反压模式下，
   全部 gated-K 和 synthetic Acc32 零失配；
3. [rtl] 纳入每行 225 拍 Q/K 预载后，TTB8-ZKQI 无反压周期由
   116675 降至 101707，加速 1.147x；
4. [rtl] pair-bitmap 无反压周期与基线完全相同，证明 exact zero-K gating
   单独只减少读与 score 工作，不能产生吞吐主张；
5. [open-pnr代理] 三方各绑定 6 个相同 fakeram45_256x32 宏并完成详细
   布线，DRC 均为 0；TTB8 频率折算吞吐为 1.138x，面积归一吞吐为
   1.093x；
6. [open-pnr代理] 三方在 5 ns 下均有 setup/max-cap 违例，且存在
   101 至 125 个未约束端点，因此状态是 PARTIAL，不是 STA 或 ASIC PPA
   签核；
7. [待验证] 没有门级 SAIF、功耗、EDP、多 sample/window 和 full encoder
   证据。

## 2. 三方公平边界

三方只改变“225 个 temporal pair 如何被发现和发射”，其余保持一致：

| 候选 | pair 发现 | zero-K 语义 | active score |
|---|---|---|---|
| RQTB2S | 225 pair 全扫描 | 进入通用 score/SCS | 双 lane |
| pair-bitmap | 225-bit bitmap 逐 pair 扫描 | {0,1,2} 三类直注入 | 双 lane |
| TTB8-ZKQI | 29x8 分层 mask 跳扫 | 与 pair-bitmap 相同 | 双 lane |

实装 TTB8 的 backlog 驻留在 row metadata bitmap 中，发射边界只有一个
depth-1 skid。docs/267 中的 depth-32 pointer FIFO 是 RTL 准入前的候选模型，
没有进入本轮顶层；后续架构图和论文不得把该候选画成已实现结构。

三方共同执行：

~~~text
225-cycle Q/K preload
  -> row-resident Q/K
  -> two H67 score lanes
  -> weighted score-class directory
  -> single hardware-order Shiftmax
  -> gated-K emit
~~~

因此：

- pair-bitmap 相对 RQTB2S 隔离 exact zero-K work gating；
- TTB8 相对 pair-bitmap 隔离 hierarchical bitmap skipping；
- TTB8 不能独占二者共同得到的 45.49% row-read bit 减少；
- TTB8 的论文增量只能写成“分层 metadata 扫描把不可见的 work reduction
  转换成周期收益”。

## 3. 存储层次

### 3.1 Row-resident Q/K

h67_fakeram45_qk_row_store.sv 使用 4 个单口 1RW 宏分别存储
Q0/Q1/K0/K1。写入和读取属于互斥相位，读取使用一个 ready/valid 返回槽：

~~~text
preload write: Q0,Q1,K0,K1 -> four SRAMs
scan read:
  baseline      -> Q0/Q1/K0/K1
  exact zero-K  -> 按read mask关闭不需要的K宏CE
~~~

宏 CE 由真实读 mask 独立控制，因此 pair-bitmap 与 TTB8 的读 bit 减少在
物理结构中有对应的宏使能边界；它仍不是 SRAM 动态功耗结果。

### 3.2 Active descriptor

weighted-SCS 的 active descriptor 不再按 450 深度展开为大量触发器，而是压成：

~~~text
descriptor = {pair_id, score, temporal_mask, active_mask}
logical address parity -> even/odd SRAM bank
~~~

连续两个 descriptor 地址必为一偶一奇，可同拍写入两个 1RW bank；build 与
emit 相位互斥，读取使用同步 request/response。这样 2 个
fakeram45_256x32 宏即可覆盖 active directory。

总宏合同为：

| 用途 | 数量 | 深度×宽度 |
|---|---:|---:|
| Q0/Q1/K0/K1 | 4 | 256x32 |
| active descriptor even/odd | 2 | 256x32 |
| 合计 | 6 | 相同开放宏 |

class histogram、three-class counter、pair bitmap 和 TTB8 metadata 保留为标准
单元并计面积。

### 3.3 当前等价边界

行为级存储合同在 Icarus/Verilator 中完成 bit-exact 回归；OpenROAD 模式绑定
硬宏完成综合与布线。当前没有 fakeram 宏行为模型或布线网表仿真，因此
“行为存储与宏绑定跨层等价”仍依赖相同同步接口合同，不能写成门级等价签核。

## 4. RTL 结果

### 4.1 无反压

| 候选 | 执行周期 | 含预载周期 | 相对基线 |
|---|---:|---:|---:|
| RQTB2S | 85625 | 116675 | 1.000x |
| pair-bitmap | 85625 | 116675 | 1.000x |
| TTB8-ZKQI | 70657 | 101707 | 1.147x |

TTB8 无反压执行阶段为 1.212x，但论文主表应使用包含公共 preload 的
1.147x，除非未来系统调度证明 preload 与前一 row 的执行可以重叠。

### 4.2 反压

| 模式 | 基线含预载 | pair含预载 | TTB8含预载 | TTB8加速 |
|---:|---:|---:|---:|---:|
| 0 | 116675 | 116675 | 101707 | 1.147x |
| 1 | 128325 | 124201 | 109692 | 1.170x |
| 2 | 129785 | 125327 | 111091 | 1.168x |
| 3 | 201210 | 184672 | 167317 | 1.203x |

四种反压均通过 Icarus 和 Verilator/SVA。反压越强时 exact zero-K gating 也
减少无效请求占用，所以 pair-bitmap 出现小幅周期收益；这不能替代真实 memory
latency 与系统仲裁实验。

## 5. 同宏开放物理代理

统一条件：

~~~text
Nangate45 open platform
5.0 ns core clock
900x700 um die outline
same fixed six-macro floorplan
same input/output delay and load
~~~

OpenROAD 自动 RTLMP 在浅层 6 宏层次触发内部 assert。该工具负结果保留；
随后只对宏位置采用三方完全相同的人工固定约束，标准单元 placement、CTS、
routing 和优化仍由同一流程执行。

| 候选 | 总面积(um²) | 标准单元面积 | 宏面积 | WNS(ns) | TNS(ns) | max-cap | DRC | 未约束端点 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| RQTB2S | 105845 | 44240.9 | 61604 | -0.0729 | -3.1637 | 7 | 0 | 125 |
| pair-bitmap | 110132 | 48527.7 | 61604 | -0.0160 | -0.0766 | 8 | 0 | 103 |
| TTB8-ZKQI | 110226 | 48621.9 | 61604 | -0.0565 | -0.7731 | 9 | 0 | 101 |

OpenROAD JSON 的 setup negative-endpoint metric 为 98/19/34，文本摘要的
violation-group count 均为 1；报告保留两种粒度，不把二者混成同一计数。

| 候选 | 周期加速 | 频率比代理 | 频率折算吞吐 | 面积比 | 面积归一吞吐 |
|---|---:|---:|---:|---:|---:|
| pair-bitmap | 1.000x | 1.013x | 1.013x | 1.041x | 0.973x |
| TTB8-ZKQI | 1.147x | 0.992x | 1.138x | 1.041x | 1.093x |

由此得到两个明确判断：

1. pair-bitmap 在同宏物理代理下仍为负结果；
2. TTB8 的 1.093x 面积归一吞吐是正趋势，但幅度不足以抵消错误的功耗、
   约束或多 trace 假设，不能单独支撑 DATE 接收。

## 6. 架构贡献应如何表述

当前最强、且不越界的 Motion 子机制表述为：

> Denominator-preserving Zero-K Quotient Injection with hierarchical
> Token-Time Bundle issue：利用 H67 both-K-zero score 严格闭合于
> {0,1,2}，将不能删除的 silent denominator 工作变成三个 multiplicity
> counter，同时用 TTB8 分层 mask 只向共享 score backend 发射 active pair。

其来源边界：

| 来源 | 借鉴 | 本土化 |
|---|---|---|
| Bishop | TTB metadata-first | 不使用 ECP 和异构双核；加入 H67 exact zero-K 分母直注入 |
| Prosperity | exact reuse 优先于 payload 计算 | 复用对象为 three-class quotient/multiplicity |
| SpAtten | cascade issue 层次 | 不删 token/head，不改变整数 gate |
| RQTB | temporal score 等价取商 | 仅处理 active 流，并与 zero-K 直注入合并 |
| SCS | score-class denominator | 接收 three-class counter 与 active histogram 的统一扫描 |

不能写：

- 发明 TTB、Shiftmax 或 bitmap skipping；
- zero-K 被删除；
- 45.49% 读 bit 减少全部来自 TTB8；
- 已获得 ASIC PPA、功耗或 EDP；
- 行级 ZKQI 已代表 full encoder 架构。

## 8. 双线后续边界

Motion 不停止，也不冻结新机制。它继续满足以下准入纪律：

- 新机制必须先用真实 workload 给出上界和强基线；
- 只在相对 RQTB2S/TTB8-ZKQI 有独立增量时进入 RTL；
- 不能用 banking、FIFO、ping-pong 或 TTB 名称本身当创新；
- 下一轮优先修复本包评审指出的唯一最高风险，再决定功耗活动闭环或新机制。

Local5 仍是当前系统完整度优先线；最终 checkpoint/profile 到达后恢复
checkpoint-bound T450、12-block 调度和真实多窗口闭环。Motion 的物理与验证
维护不依赖 Local5 GPU 结果。

## 10. 独立 DATE 评审

独立审稿人只读取本包报告和相关 RTL，未修改文件。结论为：

| 维度 | 分数 |
|---|---:|
| 综合 | 3.2/5，Weak Reject |
| 新颖性 | 3.1/5 |
| 架构完整度 | 2.9/5 |
| 实现可信度 | 3.5/5 |
| 实验完整度 | 2.4/5 |

相对上一轮 3.0/5 的实质改善是：三方强基线、公共 preload、同 6 SRAM 宏和
详细布线进入证据链；未晋级的原因是：

1. three-class zero-K 注入的独立无反压周期收益仍为 1.000x，主要周期收益来自
   Bishop 启发的 TTB8 分层跳扫；
2. 只有 sample0/window0，没有多样本、多窗口和 full-encoder 外部有效性；
3. setup、max-cap 和未约束端点尚未闭合，也没有 SAIF、功耗或 EDP。

评审冻结的最强可写主张与第 6 节一致；不得声称发明 TTB、ASIC PPA、功耗收益
或完整 encoder 加速。

下一轮唯一最高优先级是三方约束与活动闭环。由于本机没有 DC/PTPX，下一轮只能
形成 [open-pnr代理]+[rtl活动代理] 的预签核包，不能冒充评审要求的 ASIC 签核。
开放流程晋级门槛为：

- 三方 unconstrained endpoints=0；
- WNS>=0、TNS=0；
- setup/hold/max-cap/max-slew 违例均为 0；
- TTB8 preload-inclusive 周期加速保持不低于 1.10x；
- 面积归一吞吐大于 1.0x；
- 活动驱动能量或 EDP 代理至少改善 10%。

DC/PT/PTPX 服务器可用后必须用同一 SRAM lib、完整 SDC 和同一 trace 重跑，
才能把该包从开放代理升级为 ASIC PPA/EDP 证据。
