# M1289 — M1284 decoder completion successor receipt-blind hammer

## Verdict

`CONDITIONAL_PASS_M1284_COMMON_PATH__STOP_PUBLICATION_UNTIL_CAPABILITY_TOCTOU_REPAIR`

Score: **73/100**.  M1284 repairs the three ordinary-path M1283 P1 failures:
Boolean-as-integer counters are rejected, the completed result and final annex
claims are revalidated with exact types, and the same capability cannot be
consumed twice.  Its twelve author synthetic tests pass, and this independent
hammer confirms that final-checkpoint, Table-A, full-network, system-speedup and
headline promotions all fail closed.  Missing attempt/seal/PID identity/lock or
result also issues no capability and produces no output.

Publication is nevertheless not ready.  The deeper capability and atomicity
properties claimed by the contract are not true:

1. A holder of one valid capability can call `type(cap)(cap.gate, cap.key)`.
   The public constructor registers a fresh nonce, and `_consume_capability`
   accepts the forged object.  The capability therefore is not unforgeable.
2. `completion_capability` can be called more than once for the same completed
   result.  Two issued capabilities can publish identical evidence into two
   different caller-supplied annex paths because neither capability nor consume
   is bound to one canonical annex namespace.
3. M1284 revalidates canonical completion before calling the inherited M1278
   publisher, but the publisher never reopens that completion.  A deterministic
   synthetic replacement after `validate_annex` and before `publish_annex`
   produced a sealed annex whose recorded payload SHA no longer matched the
   canonical result.  This is a real TOCTOU boundary.
4. `verify_static_authorities` checks contract schema and source binding but not
   the exact closed contract claim boundary.  A temporary contract with
   `table_a=true` and `system_speedup=true` was accepted.
5. The M1284 payload is published through M1278's writer and therefore receives
   an M1278 completion token and `.m1278_atomic_seal` protocol.  This is not a
   performance-promotion risk, but the final output protocol is not self-
   consistent with its M1284 schema.

Thus M1284 may be retained as a repaired **source candidate**, but no canonical
annex publication should be authorized before an additive successor closes the
capability, TOCTOU, contract and output-token boundaries.

The TOCTOU test does not claim a malicious Python monkeypatch is the deployment
threat.  It is a deterministic way to schedule the same filesystem event an
external writer could perform during the unchecked interval.  The relevant fact
is that the inherited publisher reads no canonical result authority after the
last M1284 validation.

## Final claim and schema status

The generated annex payload is strongly constrained before publication:

- exact M1284 schema and status;
- exact H67 ep35 identity;
- exact top-level key set;
- exact false Boolean values for ratio, Table-A, full-network, system speedup,
  energy, PPA and headline;
- four module rows and three sequence rows with exact integer counters.

These controls are sufficient against direct payload claim promotion.  They do
not compensate for stale canonical identity after validation, multiple
capability issuance, a promoted source contract, or M1278 output-token reuse.

## Required actions

### P0 — mandatory before canonical publication

1. Replace the object/key capability with a registry whose capability object
   exposes neither constructor secret nor gate payload.  Bind one registry entry
   to the exact canonical result seal identities **and** the one canonical annex
   path.  Enforce at most one issuance for that tuple.  Prefer a zero-argument
   production publisher; do not accept caller-supplied layout/destination.
2. Treat the filesystem no-replace publication marker as the durable single-use
   authority.  An in-process Python object is a safety token, not a security
   boundary.  Consume the registry entry only as part of the final no-replace
   commit and make failure state explicit.
3. Move canonical completion verification inside the M1284 atomic publisher.
   After staging the annex, immediately before rename, recheck exact result file
   set, manifest/outer seal, payload/schedule hashes, completion token, claim
   boundary and result-hammer requirement.  Bind the staged annex to those exact
   digests.  Use held file descriptors plus `fstat`/inode metadata or an
   exclusive publication lock to narrow replacement races.
4. Validate the M1284 contract's complete exact key set and closed
   `claim_boundary`, including exact Boolean types.  Pin the contract SHA in the
   successor authority chain.
5. Implement an M1284-native writer, completion token and seal namespace.  Do
   not emit an M1278 token for an M1284 payload.

### P1 — independent regression gate

1. Add the exact attacks from this hammer: exposed-key minting, two issuances,
   alternate annex path, mutation before entry and mutation in the final
   validation-to-rename interval.
2. Retain the working bool-int, final identity/schema, claim promotion and
   missing-state tests.  Add exact schema checks for every module/sequence row,
   not only top-level payload keys.
3. Require a different-author source hammer to score all capability and TOCTOU
   tests PASS before signing one canonical no-production completion-gate run.

### P2 — result admission

1. After one canonical annex is atomically published, require a separate
   receipt-blind result hammer to verify source/result/contract identities,
   M1284-native completion token, seal coverage, all closed claims and single
   canonical destination.
2. Keep the annex decoder-only, ep35-only and diagnostic-only.  It cannot enter
   Table-A, system speedup, energy, PPA or headline claims; final-checkpoint
   rebind remains mandatory.

## Sealed conclusion

M1284 materially improves the predecessor, so it should not be discarded.  The
smallest safe successor changes the authority and publication boundary, not the
decoder computation.  Until that successor passes the same receipt-blind
attacks, publication remains STOP.
