# R19：保留完整域 BN 的目标 MLP 配对服务账

本账回答一个有限问题：**R19 独立 compact 图取消的生产者服务，是否仍可能支付完整 BN、展开、回采、评分和选择费用？** 主要部署对照是 compact k1 加自身评分/selector 对 native 无评分。以 pooling_residual_mse 为例，明确假定下目标局部服务为 **189,403,010 对 268,546,374 tick，减少 29.471023%**；评分/选择自身的 124,649,442 tick 已超过 compact 目标的 64,753,568 tick。另列同评分 dense/compact 配对只用于分离执行图费用，不能代替这个部署对照。它不是已实现加速器，不是整网速度或能耗结果，也不使不合精度门的策略变成可部署方案。R19 的实际执行通过与质量准入分开处理；本账不读取 AEE 或选择策略。

最终可复算结果为 [PAIRED_SERVICE_V3.json](PAIRED_SERVICE_V3.json)，SHA `62131f96efa1ea42367aad3a0d93fa1c02684d0fbc4ee63f883e1c77df806bd6`；[paired_service.py](paired_service.py) 生成模型，[CPU_CHECKS_V2.json](CPU_CHECKS_V2.json) 记录七项 CPU 检查通过。`PAIRED_SERVICE_DRAFT_V1.json`、`PAIRED_SERVICE_V1.json` 和 `PAIRED_SERVICE_V2.json` 是保留的未冻结中间结果，以 V3 为准。实际图来自未改的 R16 V2 primitive，执行来源绑定 [R19 独立执行审计](../independent_execution_audit/ACTUAL_EXECUTION_AUDIT_V1.json)。R16 的 coarse compact/expanded 等价失败保留，R17/R18 的 dense 质量不得转移到本图。

## 资源与执行顺序

资源固定为 2 MiB activation 存储（内含 128 KiB 统计与元数据）、512 KiB weight 存储、16 个 32-bit 1RW activation bank、32 个 weight bank、单个 64 B/tick 外部总线。PE 为 8×32，FP32 FMA 递归间隔假定 4 tick，并计输出排空。统计采用另设 SIMD16 流水，FP 操作延迟假定 4 tick，rsqrt 延迟 16 tick；这些都是配置假定，没有对应 FP 数据通路 RTL/DC 或数值验证。统计均值、方差/逆标准差及 affine 向量需各自可供给流水的分 bank 寄存器向量；六个最大 1,536-channel FP32 向量共 36,864 B，装入预留空间，但它们的物理读端口、bank 地址及面积尚未实现。权重 RF/PE 内部广播扇出与寄存器访问也未做地址级 trace。

生产者每批固定八个空间点，保留全部 T10；三个最大宽度的活跃 FP32 张量连同预留空间为 **1,605,632 B**，没有把 18,432,000 B 的完整输入假装放进片上 SRAM。每个输出列 stripe 在有限 weight 存储中驻留，该批完成后下一批重载。dense 与 compact 使用同一个分块方案，但这不代表两者各自最优；改变 weight-stationary 次序可能改变两者访存。外部 DMA 与计算阶段串行，不用隐藏访存或理想重叠放大收益。

顺序严格为 `真实尾格 pooling/pack → 全 T PSN1 → FC1 → 完整 Z1 → 全域 BN1 屏障 → BN1 输出 → 代表点 gather（仅 compact）→ 全 T PSN2 → FC2 → 完整 Z2 → 全域 BN2 屏障 → 完整 branch/residual/output`。两张图都支付完整 Z 写出、均值/中心方差/归一化三次全域读取，以及完整归一化输出写出。compact 额外支付 FC 代表值写出及回读、展开与 BN1 回采存储；本账未借用失败 V1 的 weighted-BN 代表域统计量，也未把 mean 与 producer 融合。

池化算术与局部 SRAM 读写显式串行，计两段 FP 排空；逐 task 检查总本地字节不超过 16×1RW 时隙。repeat/expand 对每个目的元素重复本地读取代表值，是保守的无广播方案。全域 BN 的数值归约顺序仍未映射到硬件；因此这些 tick 是声明机器的服务日程，不能写成复现了 GPU 精度的加速器周期。检查覆盖容量、依赖屏障、外部 beat、逐 task 端口下界和行数守恒，未覆盖物理 bank 冲突、地址生成或完整 RTL 时序。

## 相同普通评分与选择器

七种普通评分均继承 R18 已冻结、明确假定的串行 FP64/整数 lane 账，每种方法分别部署；dense/compact 共用同一个评分和 k1 选择器。原始 u 是 MLP 前输入，不能抵消已经完成的 attention。PSN 活动/Hamming 评分另付原生完整网格 PSN1：**46,080,000 MAC**、原生 u 读 18,432,000 B、原生 spikes 写 18,432,000 B 与参数读取；原生 PSN 输出不等于 coarse PSN 输出，不能直接复用为后者，也不能把 GPU 缓存称作免费生产者。

R18 scorer 已计十二个 binary64 分数的外部写出。本账再计 96 B 回读至有限 selector 队列，然后计选择器无停顿 **14 tick（含 retire）**；其中只有 selector 的有限位比较已有真实 RTL/Verilator/DC 证据。评分本身的 FP 算术、归约顺序和数据通路尚未实现。

## 仍未闭合的分母与投稿边界

目标外的 11 MLP、54 个外部 BN、attention、卷积、上下采样及 decoder 没有完整资源日程。真实全网每 forward 有 1,414,344,960 个 BN 输入元素：目标仅 23,040,000，剩余 1,391,304,960 不能删去；其中外部 54 BN 为 976,584,960，另 22 个 MLP BN 为 414,720,000。改变目标动作后的后层数值影响也不能按局部误差线性相加。单层 CC 最多取消十二 MLP 原 FC MAC 的 **7.361111%**，k1 为 **6.861111%**；这既不是整网周期分母，也不足以声称项目的 10% 净 PE 门已经达到。

CPU 诊断还重构四次矩归约（合计读取 46,080,000 元素）、做 cell-exact 扫描（读取 46,080,000 元素）和诊断性 BN2 gather；捕获/hash/序列化流量未测。这些不算生产执行器，但也不把诊断实测用时当生产速度。要闭合硬件证据仍需匹配该独立实际图的 FP 数值合同、真实地址/端口 trace、完整公共工作分母及目标数据通路 RTL/DC。现有 k1 RTL/DC 仅能证明选择组件。

TVLSI/TCAS-II 内部自评：本账补上“保留全域 BN 后生产者取消仍有条件性局部余量”的可检验前提，没有形成光流特异性贡献。质量不通过时应停当前动作族，不用 selector 或局部服务优势掩盖；质量通过也仍需强普通同监督对照及完整硬件收益。本文是内部研究审查，不冒充外部期刊评审。
