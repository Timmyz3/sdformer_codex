# A线 decoder0 探针（只推理，2026-10-26）

**结论：按管理开跑前冻结的口径（16×16 块、块内 EPE 差均值 < 0.5 px、拼接 AEE ≤ +5%、不变块 ≥ 36%），valid 16×16 @0.5px 不变块仅 21.60%（拼图 AEE +0.15%），all 变体 18.96%，均远低于 36%。质量远未碰到 +5% 线，卡死的是块比例。按冻结口径不过门，A 线已停。**

补充：8×8 / 0.75px / 1.0px 等档位不在冻结口径内，只作敏感性分析，不算过门。B/L 分区按管理要求不再补。oracle 用 head3 选块，本身是上界，实际上限只会更低。


## 设置
- 模型：SDformerFlow-v2 `MS_SpikingformerFlowNet_en4`，W271482（`flow_story_20261016/baseline_checkpoint_verification/source_snapshot/checkpoint_step_000271482.pt`，SHA `1e72cca3…4977`）
- 数值：all78 current BN（P_paper）、FP32、不开TF32、torch SNN后端、全图480×640、T10；ismd上RTX 3090，64次前向，0训练，峰值显存约3.77GB
- 评测集：R27 dev64快照（8个序列×8帧，训练域开发集，**不是官方DSEC测试**）
- 只用decoder0：取模型自己的head0（pred0为30×40），按模型原生方式（对T求和，再最近邻插值）放大到全分辨率
- 脚本`probe_decoder0.py`；结果`RESULTS.json`；日志`run.log`。v1只算了0.1/0.25/0.5三个阈值，留存为`RESULTS_v1_primary_thresholds_only.json`；v2补了更宽的阈值，两次运行的head3 AEE完全相同

## 注意事项
1. oracle用到了完整模型的head3来定块，**不可部署**，是上界性质；实际门控器还要为预测和误判付费。
2. 中性口径只看全GT，没有评B/L分区。36%门槛正好被跨过在0.5–0.75px之间，那里质量变化约+1%。
3. 本机3090的输出与R27在A100上的head3逐点并不一致：逐元素平均差0.436px，最大35.5px；但整体AEE只差−0.25%。推测是PSN/BN放大了微小数值差异，未定位原因。
4. 源码层面阻碍按区域跳过decoder1–3的依赖：
   - decoder1–3各含1个current-stat BN（全图T×B×H×W统计），只算部分区域会改变其余区域的数值
   - 3×3 ConvTranspose带halo
   - PSN是全T10时间耦合
   - decoder_i的输入拼接了上一级pred和encoder skip，形成串行链
   - pred0为30×40，每个pred0像素对应全分辨率16×16，8×8块小于pred0的粒度
5. 36%门槛对应"decoder1–3的工作至少取消36.4%"（来自v2费用分解估计中的划分A），默认块面积比例就等于decoder工作比例，没有扣halo和门控费用。
