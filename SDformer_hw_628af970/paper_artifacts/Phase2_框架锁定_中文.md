## 主故事弧（推荐用于 DATE 2026）

**工作标题**：硬件感知的稀疏三值 Spiking Transformer 用于事件光流的高能效设计

**核心叙事**（严格 DATE 风格，非 CVPR 风格）：
“我们并非孤立地提出一种新的 SNN 神经元或注意力技巧，而是展示一个完整的**软硬件协同设计闭环**：
1. 通过性能画像识别 SDformerFlow 中高计算量、低敏感度的阶段/块。
2. 设计硬件友好的原语（自适应三值 PSN+ATLIF、带符号/有效位编码的三值注意力，使用 XNOR/popcount 或移位归一化）。
3. 在编译期确定阶段感知的静态替换策略，生成确定性的层级调度表。
4. 将其映射到异构加速器子系统（脉冲神经元引擎 + 三值注意力引擎 + 稀疏 FFN 引擎 + 静态控制器），并提供清晰的算子级代价模型。
这一过程将模型层面的稀疏优势，转化为边缘神经形态或低功耗加速器可预测的能耗、延迟和面积收益。”

**为什么适合 DATE**（来自骨架文档）：
- 匹配方向：架构与微架构设计、低功耗能效设计、近似计算、嵌入式/边缘/神经形态系统、机器学习架构设计方法学。
- 避免拒稿陷阱：不使用“黑箱替换”，不依赖非结构化/动态稀疏（难以调度），提供明确的硬件证据链。

## 已锁定的论文结构（Phase 2 骨干）

1. **引言**（4-5 段，DATE 语气）：
   - 边缘事件光流的需求：既要精度，又要极致能效（实时、<5W）。
   - SDformerFlow baseline（脉冲驱动 Swin/QK 风格） + 先前 SNN 改进。
   - 差距：软件稀疏（SOPs/发放率）无法自动转化为硬件；部分替换可能增加控制复杂性。
   - 贡献：阶段感知静态调度，使稀疏优势可硬件映射 + 实现证据。

2. **背景与动机**：
   - SDformerFlow 架构回顾（重点阶段计算分布——Stage 2 最重）。
   - 三值神经元与注意力设计空间（来自重设计实验）。
   - SNN Transformer 的硬件挑战（数据类型、稀疏映射、缓冲区层次）。

3. **协同设计方法学**（核心技术部分）：
   - 软件重设计空间（三值 PSN+ATLIF、TX/SC/SN 注意力、S02/S012 FFN）。
   - 画像 → 敏感度 + 每阶段 SOPs 分析 → 阶段感知替换策略。
   - 静态调度表定义（编译期掩码 → 调度表）。
   - 硬件子系统架构（来自 HARDWARE_ACCELERATOR_DESIGN + DATAFLOW_SPEC）：
     - 脉冲神经元引擎（支持 PSN、二值/三值 ATLIF、阈值更新）。
     - 三值注意力引擎（符号提取、XNOR/popcount、移位归一化）。
     - 稀疏 FFN 引擎。
     - 静态调度控制器 + 片上缓冲（权重 256KB、窗口 SRAM 双 bank）。
   - 数据流与数据类型（参考 HARDWARE_DATAFLOW_SPEC.md）。

4. **实验与证据**：
   - 软件：精度-效率 Pareto（规划 Fig.1）、发放率/SOPs（规划 Fig.3）、跨 FFN 稳定性（SN 最优）。
   - 硬件证据（Phase 3/5 补齐）：
     - 算子级代价模型（MAC/add/XNOR/popcount/shift/SRAM 访问代价）。
     - 层级调度表（以选定候选为例）。
     - 能耗/延迟/访存代理 vs baseline 及 vs 均匀替换。
     - 微架构草图（来自骨架）。
   - 消融：替换范围（阶段 vs 块）、注意力归一化变体。

5. **讨论**：
   - 激进调度仍需精度恢复技术。
   - 静态调度作为可复用方法学。
   - 与 SOTA 加速器对比（FireFly-T、SENECA、Bishop 等）。
   - 局限与未来（完整端到端、FPGA 验证、28nm DC 数字）。

6. **结论**。

## 推荐主候选（供主结果使用）

- **首选**：SN（signed_shiftnorm）+ S02 FFN 替换（跨实验稳定，SOPs 降低显著，硬件友好）。
- **强备选**：TX（ternary_axnor）+ S012（短测中 SOPs 最低）。
- 在消融中同时报告。所有数据需在 canonical 825 split 上重跑后使用。

## 已考虑的备选方案（保留灵活性）

- 更激进的整阶段替换（精度风险更高，但硬件控制更简单）。
- 在稀疏基础上增加动态 token 剪枝（硬件控制开销增加，本轮 DATE 暂不优先）。
