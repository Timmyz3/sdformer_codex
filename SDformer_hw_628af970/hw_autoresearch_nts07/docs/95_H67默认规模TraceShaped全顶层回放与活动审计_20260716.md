# H67 默认规模 Trace-Shaped 全顶层回放与活动审计

## 一、为什么要做这一轮

此前 full-top 只在 2 head、2 output tile 上验证过控制和自动回填，无法回答三个架构问题：真实 head 深度是否会卡住 cache、RAW fallback 能否与 resident 混合执行、跨全部 24 个 output tile 是否真的减少 payload 数据移动。

本轮选取 H67 profile100 的 `sample0/S3.B0/window0`，保持 24 个 head 的有序 `term_count/event_count/class_count/max_fanout`，生成可逆的 IPD32W/RAW41 payload，在默认 `T162/L32/H24/O24` 顶层执行。

## 二、证据边界

真实 profile 提供统计与顺序，不提供完整 gate、lane、token 位图。因此：

- 可以证明控制、容量模式、驻留生命周期和 trace-shaped 周期；
- 可以证明所构造 payload 的整数 RTL 结果；
- 不能宣称复现了网络逐 bit 激活；
- 不能把本周期直接换算成整网 FPS。

## 三、架构观察

### 1. 表示异构、计算统一已经落到默认规模

24 个 head 中 23 个使用 IPD32W，1 个因 814 events 超过 6,642-bit slot 容量而使用 RAW41。两种表示在每个 output tile 都进入同一 TDR、多播和 AccTile，没有实例化第二套计算后端。

### 2. Decode-once promotion 的收益来自跨 tile，而非单次 decoder

首 tile 的 23 个 CSR head 全部由 IPD 解码并自动填入 Depth80 cache；之后 23 个 tile 产生 529 次 resident hit。payload 读取由 15,264 个 64-bit word 降到 8,663，减少 43.25%。这比只报“cache hit”更接近可用于功耗论文的物理口径。

### 3. 空 head 需要控制退休，但不需要 payload 重读

该窗口含 7 个空 CSR head。它们仍产生合法 session 和完成事件，但 warm tile 不再发起 slot token replay。总 session 为 576，slot replay 仅 415，减少 27.95%。这支持 metadata-first 的空 payload issue 层次，同时保持 Shiftmax/控制语义，不做近似剪枝。

### 4. 功耗热点仍在共享后端

RTL VCD 的 89.84% toggle 位于 projection 层次。下一轮真正值得做的硬件优化是：

1. term 级 product lane operand isolation；
2. destination bitmap 为空时阻断 product/accumulator 宽总线翻转；
3. AccTile 分 bank clock enable 与只读 final bank 激活；
4. weight response 只翻转当前有效 output lane；
5. SRAM macro 化后按端口 enable 重新生成门级 SAIF。

仅继续压缩 scheduler FSM 不会显著改变总动态功耗。

## 四、对 DATE 架构贡献的影响

本轮加强了三条可辩护贡献：

1. **Head-stacked output-tile-stationary replay**：576 次 head replay 共用一个持久 AccTile，不发生跨 head partial-sum spill；
2. **Decode-once descriptor promotion**：首次 IPD miss 在同一 term stream 上自动提升为后续 resident hit，不复制 parser；
3. **Representation-heterogeneous, compute-unified execution**：IPD32W、resident token-only 和 RAW41 共用后端，并按 last-use 分别释放 slot/cache。

这些已经是架构机制，而不只是定点算子；但论文速度与能效结论仍需公平基线、目标库 DC/SAIF 和整 encoder 模型。
