# 第九轮 DATE 独立评审：DS-GASR 因果闭环

## 1. 推荐

**分数：5/10；建议：Weak Reject，大修后可重审。**

本轮同版本单变量消融可信：只切换 `GEOMETRY_SYNC_MODE`，两边 descriptor、term、update 数量和 SRAM 读写事务完全相同；Acc32、随机空泡 SVA、RTL/向量/工具哈希均通过。因此 `122,360 -> 119,348` 周期的差异主要来自同步点，而不是工作量或实现版本漂移。

四 stage 加速分别为 `1.020/1.009/1.027/1.032x`，聚合 `1.025x`。方向一致且通过第八轮门槛，但幅度仍不足以单独支撑高冲击力硬件贡献。

## 2. DS-GASR 能否列为贡献

**有限允许。**

可以把 DS-GASR 写成 Local5 五着色 source-resident 数据流中的调度机制：把 backend prepare 从 relation-read issue 路径移到完整 descriptor 的原子提交边界，在相同访问集合下缩短控制暴露周期。

不能把它单独写成“显著加速器”，也不能恢复已被证伪的 mask-pruning 叙事。相对 direct 的 `1.018x` 固定周期和 `81.03%` SRAM事务下降只证明逻辑执行趋势，尚无面积、频率和功耗闭环。

## 3. 是否允许进入物理评估

**允许，且这是下一必需阶段。**

必须完成 `OUT_DIM=32` 和 SRAM 宏感知 OpenROAD 代理，并保留 `OUT_DIM=2` 对照。direct、issue-side GASR、DS-GASR 必须固定：

- 相同输入规模、算法和 Acc32 金参考；
- 相同 Nangate45、时钟、I/O delay、利用率和随机种子；
- 相同 SRAM 宏拼接规则、端口数和 banking；
- 相同综合优化、周期边界和活动向量；
- 相同错误、DRV、拥塞和未约束路径报告口径。

OpenROAD 只能标作 `[open-pnr][代理]`，不能冒充 DC、PrimeTime 或 PrimePower。

## 4. 下一唯一动作与门槛

下一唯一动作：

> 完成 `OUT_DIM=32` 的 direct、issue-side、DS-GASR 三方同约束 RTL-to-layout 与活动评估。

晋级条件：

1. 三方 Acc32、SVA、可复现性继续 PASS；
2. descriptor-sync 相对 issue-side 达到 `>=1.05x` 周期收益；或
3. 若周期仍约 `1.025x`，则在等性能约束下取得至少 `20%` 的可验证总功耗/能效改善，或由同等可信的面积/物理优势补偿；
4. 报告宏面积占比、标准单元面积、关键路径、拥塞、DRC/DRV、活动功耗代理和端到端周期；
5. 不允许用 81.03% 事务下降直接替代能耗结果。

## 5. Runtime 与 Motion 决策

runtime 双模式和 Motion 迁移不应阻塞当前物理评估，但仍不应作为当前下一实现项。

- 若论文只主张静态 Local5 DS-GASR，可把 runtime 和 Motion 泛化列为局限性；
- 若论文主张统一双线 accelerator 或 runtime adaptive，后续必须补对应硬件与公平实验；
- 当前优先级仍是部署规模 PPA，而不是继续横向增加 RTL 机制。

## 6. 公平性风险

当前风险为中等：

- `OUT_DIM=2` 可能低估宽加法器、寄存器槽和 SRAM 宽度的代价；
- 逻辑 1RW memory 不是已绑定的真实宏；
- 尚未披露三方同一 SDC 和 macro rule 下的面积、频率与活动；
- 必须明确 full-window 周期是否包含 relation build、flush 和输出读回；
- 需要保留所有负结果，避免只展示有利配置。

## 7. 结论

DS-GASR 的同步点因果已经由 `[rtl]` 单变量消融闭环，可以作为组合架构机制保留；整篇硬件工作仍未达到 DATE 接收标准。下一轮只做 `OUT_DIM=32 + 同宏同约束物理/活动评估`，结果不满足门槛时应降级 DS-GASR，而不是继续包装命名。
