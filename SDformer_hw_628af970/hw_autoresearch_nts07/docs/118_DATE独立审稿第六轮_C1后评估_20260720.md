# DATE 独立审稿第六轮：C1 后评估

## 1. 审稿结论

当前硬件部分按 DATE 架构/EDA 论文标准评为 **3.5/5，Weak Reject，接近 Borderline**，置信度 4/5。该结论不是录用预测，而是用于锁定最小补强路径。

| 维度 | 评分 | 主要判断 |
|---|---:|---|
| 新颖性 | 3.5/5 | canonical gate-stack、三格式 residency、BPB 与有序双 workspace 的组合有辨识度，但单独机制均不足以构成强架构贡献 |
| 技术正确性 | 4.1/5 | 位精确格式、原子提交、顺序约束和 RTL 计数合同较扎实 |
| 实验完整性 | 2.7/5 | 缺目标库 PPA、代表性多 trace、系统级周期与部署精度闭环 |
| 可复现性 | 3.6/5 | 脚本、RTL、TB 和证据等级较清楚，但全规模动态 SVA 与 mapped 等价未闭环 |
| 论文叙事 | 3.8/5 | workload-derived dataflow 主线已形成，仍需用端到端结果压住“局部算子优化”质疑 |

## 2. 已形成的真实进展

1. 从离线格式分析推进到完整自主 Builder：`final-gate/K -> canonical workspace -> format decision -> Serializer -> atomic typed slot` 已由 RTL 闭环。
2. BPB 保持 FADC bitmap 语义，不展开为 destination list；45-head 逻辑 destination 不变，扫描工作量从 3226 降至 2728。
3. C1 实现了双 workspace、sequence-ordered issue 和单共享 Serializer/slot 后端，而不是只停留在理想重叠模型。
4. `sample0/B0/window0` 的 45-head C1 RTL 为 10035 拍，C0 为 14078 拍，Builder 局部加速 1.403x；模型误差 0.43%。
5. IPD/FADC/RAW 的逐 word 回放、异常原子中止和多层 SVA 已形成可审计证据。

以上进展支持“架构已经超过单个行内核”，但尚不支持“完整投影或完整 encoder 加速 1.403x”。

## 3. 三个致命缺口

### 3.1 缺少同工艺、公平约束的 PPA/EDP

当前 Yosys generic cell 只能说明结构规模，不能替代目标库面积、频率或功耗。必须在同一 library/PVT/SDC/SRAM 假设下比较 Direct RAW、single-CSR/C0、C1、C1+BPB，至少报告：

- WNS、TNS、关键路径与目标频率；
- 组合面积、寄存器面积、SRAM 宏面积和总面积；
- 同一 trace 的 SAIF 覆盖率、动态功耗、泄漏功耗和 energy/head；
- throughput/mm2、energy/head、EDP；
- mapped netlist 等价或独立门级回归。

若 C1 相对最佳 exact baseline 的 projection-slice EDP 改善不足 15%，C1 不应作为默认主配置，只能作为 throughput mode。

### 3.2 精确 bit trace 代表性不足

当前 aggregate profile100 可支持 K-zero、pair-empty 和格式容量分布，但 Builder/C1 的精确周期只覆盖 `sample0/B0/window0`：44 个 IPD head、1 个 FADC head、0 个真实 RAW head。这个规模不足以证明 1.403x 在数据集、场景和 block 间稳定。

最低要求是至少 100 个有效帧，覆盖全 12 个 attention block 和每个 block 的多个 window，并报告：

- IPD/FADC/RAW head 比例及 stage/block 分布；
- fanout、term、payload word、BPB 命中和 RAW fallback 的均值、P50/P95/P99/max；
- C0/C1 周期、workspace 阻塞、重叠、背压和长尾分布；
- DSEC/MVSEC 或至少不同运动强度片段之间的分层结果。

在扩展 trace 完成前，论文只能把 1.403x 标成“单个真实 trace bundle 的 Builder RTL 结果”。

### 3.3 缺少系统级 Amdahl 闭环

C1 当前测量边界是 Builder makespan，不包含 slot replay、multicast、product delivery、AccTile、bias/final、ATLIF 和 encoder 其他阶段。因此必须把 C0/C1 接到同一完整 projection execution slice，保持相同投影后端与输出金参考，再测：

- Builder、replay/decode、multicast、MAC/accumulate、bias/final 的周期分账；
- C1 对 projection slice 的净加速，而非只报 Builder 局部加速；
- projection 在 full encoder 周期和能量中的占比；
- 按 Amdahl 定律折算的整网 FPS/energy 上限与实测或周期准确模型。

## 4. P0 验证缺口

- C1 尚缺长序列随机 backpressure、done stall、reset/abort、第三个 head 阻塞和多 context 组合场景；
- 全规模 Verilator+SVA 目前只有 lint/elaboration，动态执行超时，不能写成动态 SVA PASS；
- 尚无功能覆盖率、code coverage、sequence wrap 边界和 mapped LEC；
- C1 汇总脚本曾把浮点 `speedup` 截断为整数，已在本轮修复并要求重新生成产物；
- 量化合同仍需冻结 INT8 weight、bias、requant、residual/skip，并在 valid825 上证明 AEE 退化不超过预先设定门槛，例如 0.02。

## 5. 不可缺少的消融

审稿人需要确认收益来自所提机制，而不是“加一个 buffer 就变快”。同一后端、同一 trace、同一时钟约束下至少比较：

| 基线/候选 | 回答的问题 |
|---|---|
| Physically-stripped Direct RAW | 格式压缩与 residency 是否值得 |
| 单一 CSR 或统一 bitmap | 三格式自适应是否优于常见统一编码 |
| C0 typed residency | canonical gate-stack 与 BPB 的净收益 |
| 常规双缓冲但无 canonical/BPB | C1 收益有多少只是普通 ping-pong |
| C1 无 BPB | BPB 对周期、能量和面积的独立贡献 |
| C1+BPB | 完整主候选 |

只有 C1+BPB 相对“最佳 exact baseline”而不是最弱 RAW baseline 仍有显著 EDP 优势，主创新才可成立。

## 6. 收敛到可投的最小路径

1. 修复报告精度和文档实例化口径，建立统一 C1 signoff runner。
2. 把 C1 Builder 接入现有 full projection RTL，完成同输出金参考的 C0/C1 系统周期分账。
3. GPU 空闲后扩展至少 100 帧、12 block、多 window 精确 trace；profile100 aggregate 只作为先验和交叉校验。
4. 冻结部署量化合同并跑 valid825，保证算法精度证据与 RTL 数值合同一致。
5. 在同一目标库/PVT/SDC 下完成 DC/STA；接 SRAM 宏或给出可复核 CACTI/memory compiler 口径。
6. 对同一多 trace 回放生成 SAIF，要求关键层次覆盖率不低于 95%，完成 energy/head 与 EDP 主表。
7. 进行 mapped equivalence/门级回归和最终独立审稿。

## 7. 论文贡献的克制表述

当前可保留的主张是：

> 一种由 H67 all-binary 事件 workload 驱动的 canonical gate-stack 数据流，将重复的 gate/lane 语义折叠为可复用 term，并通过 fanout-adaptive typed residency、bitmap-preserving bypass 与 sequence-ordered dual-workspace/shared-backend 流水，在保持逐 word 与投影输出 bit-exact 的前提下降低表示、扫描和构建开销。

当前不能写成贡献的内容包括：发明 bitmap/list、发明双缓冲、发明 Shiftmax、完整 encoder 加速 1.403x、或已经达到 DATE accept。下一轮是否能进入 Weak Accept，取决于多 trace 系统级 EDP 和同工艺消融，而不是继续增加格式数量。
