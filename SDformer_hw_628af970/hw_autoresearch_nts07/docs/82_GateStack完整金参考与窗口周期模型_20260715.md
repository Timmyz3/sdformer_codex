## 2. 完整整数金参考

金参考覆盖的计算边界：

```text
H个输入head
  -> 每head构建DIRECTORY或DIRECT表示
  -> 遍历全部output tile
  -> 跨所有输入head持久累加
  -> 每个token/output恰好加一次bias
  -> 确定性RHAZ右移和有符号饱和
```

测试结果：

| 项 | 结果 |
|---|---:|
| 定向单测 | 5/5 PASS |
| 随机 trial | 80 |
| 比较输出元素 | 136800 |
| mismatch | **0** |
| 含整 head direct fallback 的 trial | 16 |

定向测试专门覆盖：两个 head 的全局通道偏移、全部 output tile、`S=4` overflow 后整 head DIRECT、bias、RHAZ/saturation，以及 `H={3,6,12,24}` 随机组合。

当前 requant 只作为 RTL 测试合同，不是网络部署合同。最终 right shift、输出位宽和逐层 scale 仍需 valid825 量化实验冻结。

## 3. OBI 的必要性

现有 G1 每次重放固定扫描：

```text
S × D = 4 × 32 = 128 cells/head/output-tile
```

真实 profile100 平均 final-gate class-channel term 约为：

```text
7,101,034 / 672,000 = 10.57 entries/head-window
```

GateStack 新增 128-bit `occupied_mask[slot][lane]`。builder 与 destination bitmap 同步置位，replay 用分层 priority iterator 遍历置位项。它没有多条 index append 的多写口问题，额外存储仅 16 B/head。

完整模型中：

| 项 | 数值 |
|---|---:|
| fixed-scan cells（跨全部 output tile） | 691,200,000 |
| OBI steps（含 slot 切换、fallback） | 59,687,085 |
| OBI 访问减少 | **91.3647%** |

## 4. 完整窗口模型口径

profile 中每条 row trace 是 `[batch_windows, heads]` 行主序。模型把每个连续 `H` row 聚合成一个完整窗口，得到：

| 项 | 数值 |
|---|---:|
| 完整窗口 | 132000 |
| head row | 672000 |
| `S=4` overflow row | 95（0.014137%） |
| build cycles | 108,864,000 |

模型默认：`T=162,D=32,S=4,P=1,M=4,L=32,B=4`，product pipeline fill 为 4 cycle；direct 和 GateStack 都允许两个输入 context，避免用故意串行化的弱基线。

每个窗口包含：

```text
H×162 build
+ H个output tile × [H个input-head backend + bias/requant尾相]
```

两个 context 的序列首填充和末排空均计入，没有把首尾免费化。

## 5. 结果

### 5.1 多播效率敏感性

| delivery效率 | fixed双context vs direct | OBI单context vs direct | OBI双context vs direct | OBI vs fixed |
|---:|---:|---:|---:|---:|
| 100% | 0.449x | 1.581x | **1.825x** | 4.060x |
| 85% | 0.446x | 1.497x | **1.692x** | 3.792x |
| 70% | 0.440x | 1.386x | **1.526x** | 3.465x |

结论：fixed-scan 在完整 output-tile 重放下会变慢；OBI 在较保守的 70% delivery 效率下仍高于 1.20x 淘汰线。

### 5.2 分 stage

85% delivery 效率：

| Stage | 窗口 | Head rows | Overflow | OBI双context speedup |
|---|---:|---:|---:|---:|
| 0 | 88000 | 264000 | 0 | **1.821x** |
| 1 | 24000 | 144000 | 0 | **1.117x** |
| 2 | 18000 | 216000 | 22 | **1.519x** |
| 3 | 2000 | 48000 | 73 | **2.050x** |

stage1 的周期收益只有 11.7%，可能不足以覆盖 priority iterator、directory SRAM 和切换能耗。因此完整控制器保留 descriptor 编译期模式：

```text
DIRECT：原始gate/K流式投影
OBI：最终门码目录 + occupied-bit replay
```

stage1 是否选 DIRECT 必须看同库 SAIF/EDP；这不是异构双核，而是同一 product/multicast/accumulator 后端前的表示选择。

### 5.3 工作量口径

完整 output-tile 加权后：

| 指标 | 数值 |
|---|---:|
| direct terms | 251,026,134 |
| 目录或fallback选择后 terms | 55,286,772 |
| 减少 | **77.9757%** |

该比例低于全局 82.49%，原因是完整模型按 stage 的 output-tile 数加权，并把 overflow row 按 direct 计入。两个数字口径不同，不得混用。

## 6. 仍未建模的风险

1. delivery 的 70%/85%/100% 是敏感性参数，不是真实 accumulator bank replay。
2. 权重 SRAM 只按吞吐抽象，未计容量、端口、bank conflict 和响应乱序。
3. OBI priority iterator 的组合深度和切换能耗尚无 RTL/DC。
4. bias/requant 只使用统一尾相模型，未计 output backpressure。
5. 双 context 只重叠 build/replay，未证明 SRAM 端口可在同周期无冲突访问。
6. 本结果是 `[prof]+[模型]`，不能写成芯片 speedup。

## 7. 架构决策

| 决策 | 状态 |
|---|---|
| `S=4` + exact whole-head DIRECT fallback | **锁定** |
| Head-stacked directory 跨 output tile 重放 | **进入 RTL** |
| OBI 替代固定 128 项扫描 | **进入 RTL，主消融项** |
| 双窗口 context | **进入 RTL v2** |
| stage descriptor `DIRECT/OBI` | **保留，等待 SAIF** |
| G≥2 窗口组 | 暂缓 |
| 异构双核 | 不采用 |
| 蝶形互连 | 无 EDP 证据，不采用 |

## 8. RTL 准入顺序

1. `gatestack_obi_iterator`：先做 128-bit mask 的无丢失 priority replay 和随机 backpressure。
2. `gatestack_head_store`：DIRECTORY/DIRECT 双格式提交与读取。
3. `gatestack_persistent_accumulator`：跨 H 个输入 head，最后才 bias/final。
4. `gatestack_projection_top_v1`：单 context 完整 head/tile loop，对齐本轮 Python 金参考。
5. `gatestack_projection_top_v2`：双 context build/replay 重叠。
6. ordered trace cycle replay、SAIF 和目标库 DC 对照。

当前第 1 项已完成叶级 RTL，详见 `docs/83_GateStack_OBI叶模块RTL验证_20260715.md`。

若 OBI 完整 RTL 相对公平 direct 低于 1.20x，或 EDP 改善低于 15%，则 GateStack 降级为算子优化，不作为 DATE 主架构贡献。
