# PPDI 奇偶配对目的令牌架构候选与 RTL 晋级合同

## 1. 发现

DCTF96 当前每条 command 只携带一个 destination token。三个 bank 在该拍都更新相同奇偶性的 Acc 通道，因此每个 bank 已经存在的另一条奇偶 Acc 端口空闲。

同一 term 的所有 destination 使用相同 gate、input channel、weight 和 product。只要整数累加不溢出，把一个偶 token 和一个奇 token 配在同一 command 中不会改变数值结果，也不会产生 Acc bank 端口冲突。

本候选命名为 PPDI：Parity-Paired Destination Issue，奇偶配对目的令牌发射。

## 2. 真实 Workload 上界

| Stage | destination | 标量命令 | PPDI命令 | command work降低 |
|---|---:|---:|---:|---:|
| S0 | 179 | 179 | 124 | 30.726% |
| S1 | 0 | 0 | 0 | 0.000% |
| S2 | 1380 | 1380 | 1084 | 21.449% |
| S3 | 21616 | 21616 | 14952 | 30.829% |
| 合计 | 23175 | 23175 | 16160 | 30.270% |

这些数字从真实 `term_tokens.memh` 的奇偶分布逐 term 计算：每个 term 所需 PPDI command 数为 `max(even_count, odd_count)`。它是精确 command-work 计数，但不是 RTL 周期。

profile100 的 H67 聚合数据含 7101034 个 G1 term 和 40560225 个 destination，平均 fanout 5.712。无奇偶约束的 M2 delivery 为 22588869，理论降低 44.307%；该数字只是 PPDI 的乐观参照，因为现有 profile100 没有保存逐 term 奇偶分布。

## 3. 候选微架构

~~~text
whole-term validated token list
              |
       parity partition
       /              \
 even token FIFO    odd token FIFO
       \              /
        one even + one odd / cycle
                    |
       dual-destination DCTF command
                    |
          three bank-local executors
                    |
       even Acc port + odd Acc port / bank
~~~

command 新增：

- `destination_valid[1:0]`；
- `destination_even`；
- `destination_odd`；
- term first/last 仍只描述一条逻辑 term 的首末 command。

每个 bank 的 weight/product 仍为每 term 一次。叶模块 RTL 迭代后采用两位 exactly-once commit mask：偶/奇 Acc 端口允许在不同拍握手，已提交端口立即被屏蔽，command 只在所有有效 destination 均提交后 retire。该结构不让 valid 依赖 ready，也不会因一个慢端口让快端口重复累加；如果中途 flush，完整 projection 的 Acc group flush/valid-bitmap 合同负责隔离已发生的部分写入。

## 4. 为什么它比普通加宽更有架构意义

PPDI不是把所有 lane 复制两倍，而是利用 H67 term 内 product multicast 和现有偶/奇 Acc 物理分银行：

1. adapter 每 term 发射次数由 destination 数降为 `max(even, odd)`；
2. fabric 的窄命令传输和 consume-mask推进同步减少；
3. 三个 bank 共享同一 product，同时使用六个 Acc 物理写端口；
4. 不删除 token、不近似 attention、不改变每个 Acc 元素的整数和；
5. 与 DCTF-2C 正交：2C 重叠 term 间 collect/emit，PPDI 压缩 term 内 emit。

论文中不能把“两个端口并行写”单独包装成创新。可辩护的组合是：`whole-term原子提交 + term内奇偶配对 + 多消费者有序fabric + bank-local product multicast`。

## 5. RTL 晋级硬门槛

1. 新文件旁路实现 PPDI adapter/fabric/executor，不破坏 DCTF-2C 标量基线；
2. 完整 H67 S0-S3 233280 个 `acc32` 逐元素零失配；
3. term、weight、bias、final 工作量守恒，双 destination 无重复无遗漏；
4. command 反压时两个 destination 和 mask 全部稳定；
5. 覆盖 only-even、only-odd、balanced、长失衡、单 destination、双端口不同反压和 flush；
6. 报告真实周期，不把 30.270% command-work 直接写成加速；
7. 与 DCTF-2C 标量版同一开放映射、同一 memory 位分账；
8. 只有完整projection面积归一吞吐继续提升，且目标 SRAM/STA/SAIF 无反向损失，才晋级主架构。
