# GateStack 三路共享投影顶层与数值闭环（2026-07-15）

## 1. 本轮结论

本轮把 doc88 的 TDR 叶模块推进到了可执行的单 head 投影链路：

```text
resident / IPD32W / RAW41 decoder 输出
  -> session-locked replay mux
  -> term/event 统一流
  -> term fork
       |- gate x weight
       `- destination bitmap assembler
  -> tag + issue-seq rendezvous
  -> segmented multicast
  -> banked accumulator
  -> 逐 token bias commit
  -> signed int32 final output
```

新增三层 RTL：

1. `gatestack_tdr_multicast_backend`：TDR、权重乘积、位图汇合、多播和完成分账；
2. `gatestack_single_head_projection_top`：在 TDR 后端后接持久累加、bias 提交和最终输出；
3. `gatestack_routed_single_head_projection_top`：resident、IPD32W、RAW41 三路表示共享同一投影后端。

当前结论是：

> **“表示异构、计算统一”已经从架构图变成可综合 RTL，并完成小尺度端到端整数等价；但实际 decoder/slot/cache/launch/lifecycle 的单一 full top、跨 head/tile 持久累加、真实 trace 周期和目标库 PPA 尚未闭合。**

因此证据等级从 doc88 的 `[rtl叶级]` 提升为 `[rtl单head集成]`，仍不是 `[rtl全加速器]` 或 `[DC]`。

## 2. TDR 完成条件

### 2.1 不能用 decoder done 直接释放资源

decoder 完成只表示 term/event 已经离开表示解码器，不表示以下工作完成：

- 权重响应已经返回；
- `gate x weight` 已经生成；
- destination bitmap 已经构建；
- product 与 bitmap 已经汇合；
- 所有目标 token 已经被多播并写入 accumulator。

后端维护：

```text
outstanding_terms = accepted_terms - multicast_completed_terms
```

只有同时满足：

```text
decoder_done_seen && outstanding_terms == 0
```

才产生 `backend_done`。定向测试中，decoder done 后仍经过 **9 cycle** 才产生 backend done，说明完成条件没有提前。

### 2.2 空 head 语义

合法空 head：

- 不发权重请求；
- 不发 accumulator update；
- decoder done 后正常产生 backend done；
- 独立计入 `count_empty_sessions`。

空 head 不是错误，也不能为了省周期而破坏原网络的其他归一化语义；这里只处理最终 gated-K 投影阶段的空回放。

## 3. 三路共享而非三套计算核

`gatestack_routed_single_head_projection_top` 只实例化：

- 1 个 replay mux；
- 1 个 TDR product/bitmap 后端；
- 1 个 segmented multicast；
- 1 个 banked accumulator。

resident、IPD32W、RAW41 的差异停留在 decoder 输出接口：

```text
term  = {gate_code, lane_id, destination_count, head_last}
event = {gate_code, lane_id, token_ids[0:3], count, first, last, head_last}
done  = {tag, error}
```

每个 group 启动时，projection group 与 replay route 必须同拍握手。route 在整个 decoder session 内锁定；未选中的两个 source 的 term/event/done ready 恒为 0。三路依次运行的验证结果：

| 项目 | 结果 |
|---|---:|
| route session | 3 |
| accepted term | 3 |
| multicast completed term | 3 |
| bias commit | 24 |
| 最终 int32 元素 | 48 |
| 数值 mismatch | 0 |
| 未选中 source 获得 ready | 0 |
| 总仿真周期 | 82 |

该测试证明的是三种表示共享后端的结构和数值合同，不是性能加速比。

## 4. 单 head 完整数值合同

单 head 顶层使用：

- gate：unsigned 9 bit，范围 0..256；
- weight：signed int8；
- product：signed 17 bit；
- accumulator：signed int32；
- 中间累加不饱和、不 requant；
- bias 暂沿用 signed 17 bit 输入；
- bias commit 时产生 signed int32 final output。

定向测试包含两个 term、五个 destination、正负权重、双 bank 反压、bias provider 反压和 final consumer 反压。结果：

| 项目 | 结果 |
|---|---:|
| term | 2 |
| completed term | 2 |
| bias commit | 8 |
| final token vector | 8 |
| 比较元素 | 16 |
| mismatch | 0 |
| 周期 | 34 |

这里尚未实现最终网络部署所需的独立宽 bias 和 requant。当前 17-bit bias 只是沿用旧 G1 接口以闭合 accumulator 行为，不代表 H67 部署量化合同已经冻结。

## 5. 本轮 RTL 审阅与修复

### 5.1 全局输入通道

产品权重请求使用：

```text
global_input_channel = head_input_channel_base + local_lane_id
```

后端检查加法是否溢出 `INPUT_CH_W`。本轮审阅又补了一层非 2 次幂 lane 防护：

```text
local_lane_id < LANES
```

否则当 `LANES=24`、`LANE_ID_W=5` 时，24..31 的非法编码可能落入相邻 head 的权重空间。虽然三个 decoder 已经检查 lane 范围，TDR 后端仍必须做第二道边界检查。

### 5.2 bias ready/valid

旧 G1 顶层的 `bias_req_valid` 与 accumulator 接受条件不是同一个握手。新顶层只在目标 bank 可接受时提出 bias 请求，并且仅在 provider ready 同拍时产生 accumulator bias update，避免 provider 误认为 bias 已被消费。

### 5.3 完成与最后 term

非空 session 必须看到 `head_last` bitmap。backend done 同时检查：

- decoder done；
- outstanding 为 0；
- 非空 session 已见最后 bitmap；
- 内部 product/bitmap/join/multicast 没有协议错误。

### 5.4 当前错误路径限制

正常路径已经闭合，但 malformed term 仍可能导致 error 后等待未完成项。例如 gate=0 或 term/event 声明不一致时，某些叶模块会 sticky error 并停止前进。完整加速器仍需统一的 abort/drain FSM：

```text
detect error -> stop new issue -> drain/drop held packets -> report session error
             -> release slot/cache -> return idle
```

在该 FSM 完成前，不能宣称任意错误输入都可无死锁恢复。

## 7. Yosys 结构审计

默认参数 `TOKENS=162, LANES=32, OUT_TILE=8, BANKS=2` 下：

| 层次 | hierarchy cells | memory bits | `$mul` |
|---|---:|---:|---:|
| TDR multicast backend | 752 | 0 | 8 |
| single-head projection | 1102 | 41472 | 8 |
| three-route projection | 1205 | 41568 | 8 |

解释：

- 8 个 `$mul` 对应 8-lane `gate x weight`，不是地址生成乘法；
- 三路路由顶层没有复制乘法器，仍只有 8 个 `$mul`；
- 41472-bit 主要是 162 token、8 output lane、32-bit accumulator 的双 bank 逻辑存储；
- replay mux 增加少量控制寄存和计数状态；
- Yosys generic cell 不是标准单元面积，也没有 SRAM macro、时序、功耗意义。

## 8. 对 DATE 架构创新的影响

本轮把以下候选贡献从“概念”推进为“RTL 支撑”：

1. **表示异构、计算统一**：三种有损风险不同的存储格式共享一套 exact 计算后端，而不是 dense/sparse 双核复制；
2. **TDR 解耦汇合**：term product 与 destination reconstruction 独立前进，在进入多播前按 tag/sequence 恢复顺序；
3. **以 multicast completion 为资源生命周期边界**：decoder done 不等于计算完成，硬件显式跟踪未完成 term；
4. **final-gate 驱动的无损目的多播**：每个 gate/lane 只做一次乘积，再传播到真实目标 token。

目前还不能写成论文最终贡献的原因：

- 没有真实 ordered trace 上的 TDR 对照周期；
- 没有 full decoder/slot/cache/launch/lifecycle 顶层；
- 没有多 head 和全部 output tile；
- 没有 DC/SAIF/LEC；
- 没有和公平串行后端、direct baseline 的同约束 PPA。

因此当前合适表述为“提出并实现核心共享投影微架构”，不能表述为“完成全 encoder 加速器”。

## 9. 下一步最小闭环

按优先级执行：

1. 将 resident joiner、IPD32W decoder、RAW41 decoder 实例接入 routed top，而不是由 TB 直接提供统一流；
2. 把 launch control、head-slot、descriptor cache 和 lifecycle 接到同一 top，并实现 error abort/drain；
3. 新增 GateStack `TOKENS=162, LANES=32` full-top 随机/定向回归；
4. 实现多 head 持久累加：bias 只能在最后一个 input head 完成后提交；
5. 实现 output-tile 循环和 descriptor residency 跨 tile 保留；
6. 从 profile100 生成 ordered RTL transcript，对比串行 bitmap-product 与 TDR；
7. 冻结 bias/requant 定点合同并与 H67 dyadic 部署逐元素对比；
8. 生成 VCD/SAIF，再进入有目标库的 DC/LEC/PPA。

TDR 继续保留的量化门槛不变：

- ordered trace 周期改善至少 10%；
- 完整 GateStack 相对 direct 吞吐至少 1.20x；
- 同库同频、含 SRAM macro 的 EDP 改善至少 15%；
- 三种 replay 路径、所有 head/tile 输出 100% bit-exact。
