## 5. 内存宏与黑盒状态

### 5.1 概念澄清

Yosys 日志中的 `$mem_v2` 是未映射的内部行为存储单元。mapped Verilog 把它们写回为 `reg` 数组与过程块。它们：

- 不是有 `.lib/.db/.lef` 的 SRAM 宏实例；
- 不是已在 DC/STA/Formality 两侧一致声明的黑盒；
- 不被 `stat -liberty` 计入面积；
- 不能供当前 STA 或功耗工具获得存储延时、内部功耗和漏电。

所以当前不能声称“无黑盒”，也不能声称“内存黑盒已关闭”。准确状态是：**内存仍为行为数组，宏选型与实例化开放**。

### 5.2 从 mapped Verilog 反算的容量

| 存储类别 | 形状 | C0 bit | C1 bit | 实现风险 |
|---|---|---:|---:|---|
| 共享 head-slot payload | 4992 x 64 | 319,488 | 319,488 | 主面积项；需容量分 bank、宏 rounding 和 1R1W 周期语义复核 |
| slot metadata | 48 深度的 format/mode/bits/tag/words | 2,784 | 2,784 | 更适合寄存器或小寄存器文件，不应按 5 个 SRAM 宏计数 |
| 共享 Serializer scratch | 128 x 64 + 128 x 24 | 11,264 | 11,264 | 需确认异步/同步读时序与提交速率 |
| 单个 canonical workspace | class/fanout/bitmap/RAW/term | 31,510 | 63,020 | C1 两份；bitmap 与 fanout 有多 bit/多地址并行更新风险 |
| C1 sequence 数组 | 2 x 32 | 0 | 64 | 应映射为寄存器 |
| **总行为数组容量** | 13/19 个对象 | **365,046** | **396,620** | **44.561/48.416 KiB，均未宏化** |

C1 比 C0 增加 31,574 bit，约 3.854 KiB，主要是第二份 workspace。这个 bit 增量不能直接换算面积：宏深度/宽度 rounding、端口复制、多 bank 互连和周边电路可能改变 C0/C1 总面积比。

### 5.3 宏化前必须解决的端口语义

1. `slot_mem` 是一条 commit 写流和一条 replay 读流，RTL 在时钟过程中寄存 replay 数据。需固定读延时、同地址读写模式、bank 选择和宏容量 rounding。
2. `destination_bitmap_q` 是 128 x 162 数组，采集时按 token/lane 更新 bit，回放时读出 162-bit destination 行。该在线转置访问不等价于普通单口或 1R1W SRAM。
3. `fanout_q` 在每个 token 上可对多个 lane 计数更新，需确定是寄存器 bank、分片 SRAM 还是多周期微架构。
4. `raw_record_q`、workspace `term_q`、Serializer `term_mem/payload_mem` 需逐个固定同步读延时。若宏化增加一拍，必须同步修改微架构合同并重做 RTL 回归与 LEC；本轮未做此类修改。
5. 每个选定宏必须同时交付功能 Verilog、`.lib/.db`、LEF，若进入布局则还需 GDS/CDL 与电源端口合同。

## 8. 最小执行命令

### 8.1 DC 最小命令


最小签核不能只跑 TT：至少要有 setup 最差角与 hold 最差角，两者都包含对应 SRAM 宏视图。DATE 主表若只能提供前布局 STA，必须明确标注“前布局、无 SPEF”，不得写成后布局 Fmax。

### 8.3 SAIF 最小命令

首先对 C0/C1 使用同一真实 workload、同一 warm-up/采样窗口产生门级 VCD，再转换和注释：

```bash
vcd2saif -input /abs/path/${TOP}.vcd -output /abs/path/${TOP}.saif

export TOP=gatestack_onchip_typed_builder_c0_top
export DDC=/abs/path/${TOP}.ddc
export SAIF=/abs/path/${TOP}.saif
export SAIF_INSTANCE=tb/dut
export OUT=/abs/path/power_runs/${TOP}

dc_shell -f /dev/stdin <<'TCL'
file mkdir $::env(OUT)
read_ddc $::env(DDC)
current_design $::env(TOP)
read_saif -input $::env(SAIF) -instance_name $::env(SAIF_INSTANCE)
report_switching_activity -list_not_annotated > "$::env(OUT)/activity_coverage.rpt"
update_power
report_power -analysis_effort high -hierarchy > "$::env(OUT)/power_hier.rpt"
quit
TCL
```

功耗报告必须同时含 logic、memory、clock、IO 和 leakage，并报告未注释对象。仅读入当前单 context 顶层的 1.1 GiB VCD，不能代替 C0/C1 层次匹配的 SAIF。

### 8.4 LEC 最小命令

Formality 必须使用该次 DC 生成的 SVF、同一 RTL filelist、同一标准单元/内存宏库和对应 mapped 网表：

```bash
export TOP=gatestack_onchip_typed_builder_c0_top
export RTL_FILELIST=/abs/path/${TOP}.f
export MAPPED=/abs/path/${TOP}_mapped.v
export SVF=/abs/path/${TOP}.svf
export TECH_DBS="/pdk/nangate45/db/standard_ss.db /pdk/nangate45/db/slot_ss.db /pdk/nangate45/db/workspace_ss.db"
export SRAM_MODELS="/pdk/nangate45/verilog/slot.v /pdk/nangate45/verilog/workspace.v"
export OUT=/abs/path/lec_runs/${TOP}

fm_shell -f /dev/stdin <<'TCL'
file mkdir $::env(OUT)
set_svf $::env(SVF)
foreach lib [split $::env(TECH_DBS)] { read_db -technology_library $lib }
set fp [open $::env(RTL_FILELIST) r]
set rtl_files {}
while {[gets $fp line] >= 0} {
  set line [string trim $line]
  if {$line ne "" && ![string match "#*" $line]} { lappend rtl_files $line }
}
close $fp
read_sverilog -r [concat $rtl_files [split $::env(SRAM_MODELS)]]
set_top r:/WORK/$::env(TOP)
read_verilog -i [concat $::env(MAPPED) [split $::env(SRAM_MODELS)]]
set_top i:/WORK/$::env(TOP)
match
report_unmatched_points > "$::env(OUT)/unmatched.rpt"
verify
report_verification -verbose > "$::env(OUT)/verify.rpt"
quit
TCL
```

内存宏必须在参考侧和实现侧采用一致的功能模型，或在两侧一致黑盒化并完成端口/实例对应。只把实现侧 SRAM 黑盒化不能构成有效等价证明。Yosys `equiv_*` 可作前检，DATE 主证据仍应保留 Formality 的全 compare-point 报告。

## 10. 最小收口顺序

1. 冻结 C0/C1 顶层参数、Git 提交、对比 workload 和库角，生成全量 manifest。
2. 先冻结内存端口语义和宏映射；未解决 bitmap/fanout 多更新端口前，不得开始报总面积。
3. 为 C0/C1 分别生成 filelist 与 SDC，在 DC 前先完成时钟、IO和无约束路径审计。
4. 同一脚本、同一库角、同一编译选项运行 C0/C1 DC，先关闭 unresolved reference、未映射 cell 和宏映射。
5. 运行 setup/hold STA 并关闭时序与电气 DRC；有 P&R 条件时优先使用后布局 SPEF。
6. 在同一真实 trace 和相同活动窗口下生成 C0/C1 gate-level SAIF，关闭注释覆盖率并报告分项功耗。
7. 最后运行 C0/C1 Formality，保存 SVF、unmatched 和全 compare-point 结果。
8. 只有 A01--A15 全部通过后，C0/C1 的面积、Fmax、功耗和 EDP 才可进入 DATE ASIC 主表。

## 11. 最终判定

- **开放映射产物：保留。** 它们是有限但有用的逻辑复杂度消融。
- **C1 逻辑面积 1.728x 与归一吞吐 0.812x：可作负面预警，不可作 EDP 结论。**
- **Nangate45 TT：可用于同库逻辑代理，不可作 DC/签核 PVT 替代品。**
- **内存：未黑盒化、未宏化、未计面积/时序/功耗。**
- **SDC/DC/STA/SAIF/Formality：C0/C1 均未关闭。**
- **DATE 准入：当前只可进入明确降级的补充消融，不可进入 ASIC 主 PPA 表。**
