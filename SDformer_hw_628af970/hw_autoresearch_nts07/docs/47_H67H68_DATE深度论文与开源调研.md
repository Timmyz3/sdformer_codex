# H67/H68 DATE 深度论文与开源调研

> 调研日期：2026-07-13  
> 调研范围：2020--2026 年 spiking Transformer/attention accelerator、Softmax/Shiftmax、时间复用、事件稀疏、score histogram/class folding、训练期分支移除与 ASIC dataflow。  
> 证据约束：只采用原论文、会议官方开放页面、作者项目页和论文作者维护的官方仓库；不把综述、博客、二手解读或搜索摘要作为新颖性证据。

## 1. 结论先行

1. **H67 仍是当前精度第一部署主线。** H67 epoch19 的统一 dyadic INT8 valid825 为 AEE `1.4626`、AAE `9.3949`、spikes `26.3948G`。H68 epoch19 的同口径结果为 AEE `1.4715`、AAE `9.4517`、spikes `26.4311G`。H68 证明了训练期富分支能够在部署时完全移除，但目前没有超过 H67。
2. **H68 不需要第二套推理 RTL。** 它的 binary full-matrix auxiliary 只在训练期存在，部署图仍是 H60/TTX。把 H68 写成“新增硬件模块”是不忠实的；它只能成为软硬件协同训练贡献或 H67 之外的零增量备选 checkpoint。
3. **没有在本轮原始来源中发现 TPSF 的直接同构先例。** 已有工作已经明确覆盖 Shiftmax、在线 Softmax、整数指数、token/head pruning、TTB bundling、重复 partial-product 消除和时间并行布局，但没有发现同时满足以下条件的方法：针对 binary gated-K 的 `K=0` 项，按**最终离散 score**精确聚合 multiplicity，只对有效 score 类执行一次指数/分母更新，并保持逐 token gate 数值等价。
4. **“没有搜到”不等于已经证明首次。** BLADE、Softermax、ITA 和 Bishop 分别构成重复计算消除、在线归一化和 bundle 稀疏的邻近先例。正式论文暂不使用“首个/首次”；只有完成更宽的引用追踪、公式级 claim chart 和审稿前专利检索后才能考虑。
5. **最有希望的 DATE 组合不是单独 TPSF，而是三级精确路由：** `(Q_toggle OR K_toggle)==0` 时做 exact Delta reuse，发生变化且 `K=0` 时进入 TPSF 类折叠，其他项进入普通 TTX/Shiftmax；三条路径共享 temporal XOR、popcount、row-max、exp2 和 gated-K 后端。该组合由 H67 的有限 score 代数和 T=2 数据布局共同产生，但必须用 profile、bit-exact RTL 和同约束 DC 证明净收益。
6. **H68 的可发表强化方向不是继续包装 Castling。** 更合理的后续假设是：利用训练期 auxiliary 提升部署 H60/H67 的精度，同时加入部署端可测的 score-class 或 temporal-stability 正则，使训练结束后 aux 为零且 TPSF/Delta 的硬件有效覆盖率上升。当前 H68 没有训练这些结构化指标，因此不能追溯性声称这一贡献已经成立。

## 2. 我们的方法边界

### 2.1 H67/TPSF

H67 在 all12 统一 H60/TTX 上增加同空间、同 head 的跨时间 K XOR：

```text
motion = popcount(K0 XOR K1)
score  = TTX_score + motion / 4
gate   = Shiftmax(center(score))
output = gate * K_current
```

冻结部署为 `T=2`、`D=32`、`alpha0=1/64`、score/gate step=`1/128`。64-bit `{K1,K0}` 时间对可同时服务 Motion-XOR 和 exact Delta changed-mask。TPSF 利用两条项目特有事实：

- `K_current=0` 时 gated-K 输出严格为零，但该 token 的指数仍进入 Shiftmax 分母；
- 部署定点后，零 K 路径只落入有限个最终 score 类，可用 `score -> multiplicity` 直方图精确折叠。

TPSF 不是 token pruning，也不是忽略零 K 的分母项；它必须保持 row max、denominator 和非零 K gate 与 dense 参考逐位一致。

### 2.2 64-bit 时间对布局

布局把同 token/head 的两个 timestep 放在一个 64-bit word 中，Q 和 K 分别形成 `{Q1,Q0}` 与 `{K1,K0}`。它的价值是请求合并、XOR/Delta 共享和 bank 局部性，不是降低逻辑数据容量。若 baseline 已经用 64-bit 接口合并 T=2，则流量收益为零，只剩地址和计算复用收益。

### 2.3 H68 训练期 auxiliary

H68 使用无新增参数的 binary full-matrix attention output 与 H60 output 做全局 `lerp`，权重从 `0.5` 退火到 epoch20 的 `0`，epoch20--29 只训练部署 H60；eval config 强制 auxiliary 为零。它不同于：

- Castling-ViT 的 threshold-masked softmax auxiliary、线性角注意力和部署期 DWConv；
- RepVGG/DBB 的线性分支代数融合；
- 知识蒸馏中的独立 teacher 网络。

因此 H68 的准确表述是 **annealed matrix augmentation for a fixed deployment graph**，不是结构重参数化，也不是 Castling-ViT 复现。

| N07 | **RepVGG**, CVPR 2021。[论文](https://arxiv.org/abs/2101.03697)，[官方代码](https://github.com/DingXiaoH/RepVGG) | 训练图与部署图分离、转换后必须做输出等价检查，是 export/audit 流程参考。 | RepVGG 把线性 conv/BN 分支代数融合，不是把非线性 attention 权重退火到零。 | 与 H68 的机制完全不同；不能称 H68 为 structural re-parameterization。无 TPSF/时间对。 |
| N08 | **Diverse Branch Block**, CVPR 2021。[论文](https://openaccess.thecvf.com/content/CVPR2021/html/Ding_Diverse_Branch_Block_Building_a_Convolution_as_an_Inception-Like_Unit_CVPR_2021_paper.html)，[官方代码](https://github.com/DingXiaoH/DiverseBranchBlock) | 多训练分支、单部署卷积和 conversion test 提示 H68 需独立验证 state-dict、module coverage 和 eval graph。 | DBB 的分支均可线性融合，H68 matrix auxiliary 不能融合，只能保证权重为零/关闭。 | 不做 score folding、temporal pair 或 attention branch annealing。 |
| N09 | **I-ViT: Integer-only Quantization for Efficient ViT Inference**, ICCV 2023。[会议论文](https://openaccess.thecvf.com/content/ICCV2023/papers/Li_I-ViT_Integer-only_Quantization_for_Efficient_Vision_Transformer_Inference_ICCV_2023_paper.pdf)，[官方代码](https://github.com/zkkli/I-ViT) | 直接提出名为 Shiftmax 的 integer-only Softmax：max-shift、换底到 2、shift-add 近似指数和整数除法；这是本项目 Shiftmax 命名和算术最直接的先例。 | I-ViT 面向 conventional ViT/TVM，Shiftmax 是近似 e-base Softmax；本项目使用脉冲 score、固定 dyadic 网格和专用 gated-K。不能迁移其 GPU speedup 到 ASIC。 | I-ViT 对每个 score 做 ShiftExp，不做零 K 最终 score 类 multiplicity；没有 temporal pair 或 training aux。**任何“提出 Shiftmax”的 claim 均禁止。** |
| N10 | **STAR: An Efficient Softmax Engine for Attention Model with RRAM Crossbar**, 2024。[论文](https://arxiv.org/abs/2401.17582) | 低精度容忍、RRAM softmax engine 和全局细粒度流水可作为非 CMOS 标准单元后端对照。 | STAR 依赖 RRAM crossbar 且用精度换效率，不能证明本项目 exact Shiftmax，也不能迁移其效率数字。 | 它仍按普通 attention score 执行 Softmax，不做最终 score multiplicity、temporal pair 或 H68 aux。 |
| N11 | **SwiftKV: An Edge-Oriented Attention Algorithm and Multi-Head Accelerator**, 2026。[论文](https://arxiv.org/abs/2601.10953) | 每个 KV 只处理一次、无 score materialization 的单遍流水，是 compact replay 与 row-buffer 生命周期的强边界。 | SwiftKV 面向 LLM decoding 和连续 KV cache，不是脉冲 encoder，也不采用 H67 的 gated-K/Shiftmax 公式。 | 它明确逐 KV 流过统一 pipeline，而不是把相同最终 score 合并成类；无 T=2 Motion pair 或 training auxiliary。 |

## 4. 直接新颖性检索结果

### 4.1 已有概念覆盖图

| 概念 | 明确已有工作 | 我们不能声称的内容 |
|---|---|---|
| binary/spike attention | Spikformer、Spike-driven Transformer、α-XNOR、STAtten | “首次二值注意力”“首次 silence match”“首次时空脉冲注意力” |
| token-time bundling | Bishop、LoAS、SpikeTA | “首次把 timestep 打包”“首次 token×time 数据流” |
| dense/sparse 双路径 | Bishop、FireFly-T | “首次脉冲 Transformer 异构核/stratifier” |
| Shiftmax/online/整数 Softmax | I-ViT、Bipolar Self-attention、Softermax、ITA、FlashAttention、FQ-ViT、Hyft | “首次 Shiftmax”“首次在线 max-exp-sum”“首次整数/exp2 softmax” |
| 动态 score pruning | A3、SpAtten、Energon、SPRINT | “首次利用 score 稀疏减少 attention” |
| attention 重复计算消除 | BLADE | “首次发现 Q/K 重复性并关断运算” |
| 训练富、部署简 | Castling-ViT、RepVGG、DBB | “首次训练期多分支且推理无开销” |
| temporal state/reuse | LoAS、MEET、SpikeTA、STAtten | “首次跨 timestep 复用” |

### 4.2 本轮未找到直接覆盖的限定组合

下述表述在 34 项来源中未发现直接同构，但仍只能写成“本项目提出”，不能写“首次”：

1. 对 `output=gate*K_current` 的 binary attention，识别 `K_current=0` 的**输出零值与分母非零值不对称性**；
2. 在定点部署图中按**最终 score code**而非 Q/K pattern、token 或 partial product 建立 multiplicity；
3. 把 `sum_j exp(score_j-max)` 精确改写为 `sum_c count[c]*exp(c-max)`，同时只为非零 K token保留 gate 回写；
4. 同一个 `K0 XOR K1` 同时产生 H67 Motion-XOR evidence、exact Delta changed mask 和 temporal route metadata；
5. 将 unchanged reuse、zero-K score-class fold、active-K dense execution 组成互斥且 bit-exact 的三级 row engine。

### 4.3 为什么 TPSF 仍有风险

- **术语风险：** 相关工作可能使用 value-aware skipping、duplicate elimination、memoization、equivalence class、run-length softmax 等不同术语。
- **组合显然性风险：** 在 score 只有少量整数 code 时，用 histogram 计算指数和可能被审稿人视为自然优化。
- **适用面风险：** TPSF 依赖 binary gated-K 和高 K-zero 比例，若只在一个模型/数据集有效，贡献会被视为过窄。
- **控制开销风险：** 35-bin histogram、清零、计数和回放可能抵消指数减少，尤其当前 row 只有 162 tokens。
- **数值风险：** 软件 `center -> quant` 与某些 RTL `raw quant -> center` 在半格点不等价；只证明 score 前端不足以证明 row output exact。

## 5. 可验证的组合创新假设

### 假设 C1：Exact Temporal-Class Routing（ETCR，精确时间-类别路由）

```text
temporal pair load
  -> XOR/change detector
  -> route 0: (Q_toggle OR K_toggle)==0, reuse exact prior contribution
  -> route 1: changed and Kcurrent=0, TPSF histogram
  -> route 2: changed and Kcurrent!=0, normal score/gate
  -> shared row max / exp2 / denominator / gated-K backend
```

**来源组合但非照搬：** LoAS 提供时间并行布局纪律，MEET 提供 state-memory 核算，Bishop/FireFly-T 提供路由风险，Softermax/ITA 提供流式归一化；上述工作均没有该三级 H67 exact route。

**可证伪预测：** 相对 dense H67，在所有 valid825 row 上 bit-exact；`exp2_txn` 至少下降 50%，TX lane compare 至少接近已测理论上限，但加入 pair SRAM、histogram、route FIFO 后 post-DC attention energy 仍下降至少 15%。若净能耗低于 10% 或频率下降超过 10%，不作为主贡献。

**必须实验：** `unchanged/zero-K/active-K` 联合二维分布、每行有效 class 数、histogram clear/update cycles、FIFO occupancy、VCD/SAIF、同约束 DC。

**新颖性风险：中高。** 单个组成均有先例，价值取决于 exact algebra、共享逻辑和实测净 PPA。

### 假设 C2：Motion-Delta Fusion（MDF，运动-差分融合前端）

把 32-bit `K0 XOR K1` 只计算一次，同一 popcount/分组树在不同 cycle 产生：

- H67 motion score；
- Delta route 的 changed bitmap/count；
- K temporal-stability profile；
- clock-gating group enable。

**区别：** 不是普通 XOR 复用声明，而是利用 H67 公式与 exact Delta condition 共享一个中间量，并冻结时序/资源调度。

**可证伪预测：** 相对“独立 Motion popcount + Delta detector”，组合前端面积下降至少 20%、动态功耗下降至少 15%，不降低目标频率；RTL 输出完全一致。

**新颖性风险：中。** 共享公共子表达式本身不新颖，必须与时间对 bank、cycle schedule 和 ETCR 的端到端收益一起呈现，不能单列为论文首要创新。

### 假设 C3：Score-Class Streaming Shiftmax（SCS-Shiftmax）

对零 K 使用 35-bin 最终 score histogram，对非零 K 保留 compact replay；row max 冻结后，分母按类更新：

```text
den = sum_activeK exp2(score_i - max)
    + sum_class count[c] * exp2(c - max)
```

**区别：** I-ViT、Bipolar Self-attention、Softermax 和 ITA 都对每个 score 执行 ShiftExp/online normalization；BLADE 消除相同 partial products；SCS-Shiftmax 合并的是最终 score 的指数与分母贡献，同时利用 gated-K 输出零值避免为折叠 token 保存 gate。

**可证伪预测：** dense/TPSF 两种 row engine 对随机向量和真实 trace bit-exact；`active_classes/zeroK_tokens` 的加权比低于 0.25；histogram+replay 总面积小于被省掉的 score/gate buffer 与 exp transaction 能耗。

**新颖性风险：中高。** 这是当前最接近独立硬件创新的部分，但 histogram softmax 的潜在同义先例仍需引用追踪。

### 假设 C4：Auxiliary-Guided Deployability Shaping（AGDS，辅助分支引导部署结构塑形）

在 H68 的 training-only binary matrix auxiliary 上增加**只作用于部署主支统计**的正则，例如：

```text
L = L_flow
  + lambda_aux(t) * L_matrix_help
  + lambda_cls(t) * active_score_classes
  + lambda_stb(t) * temporal_K_toggle
```

其中 `lambda_aux(t)` 在冻结点前退火为 0；部署图没有 auxiliary、额外参数或新算子。`active_score_classes` 必须使用可微 surrogate，最终以真实定点 profile 验收。

**区别：** Castling 只让 masked auxiliary 消退，Bishop BSA 塑造 TTB firing sparsity；AGDS 直接优化 TPSF class occupancy 与 H67 temporal route coverage，同时保持统一 H60/H67 部署图。

**可证伪预测：** 三随机种子下 AEE 不差于 H67 `+0.5%`，`active classes/row` 或 union toggle 至少下降 20%，统一 dyadic valid825 不回退，post-DC 能效提升有统计一致性。

**当前状态：未实现、未被 H68 结果证明。** H68 现有 loss 没有 class/toggle regularizer，不能把 C4 写成已有贡献。

**新颖性风险：高。** 容易被认为是 Castling+Bishop 的直接组合；必须证明优化目标来自 TPSF 的精确成本模型，并做 `aux only / hardware regularizer only / both` 消融。

### 假设 C5：Descriptor-Serialized Unified Encoder（DSUE，描述符串行统一编码器）

12 个 attention block 和 105 个 ATLIF wrapper 不按 PyTorch module 数实例化，而由 `stage/block/window/head` descriptor 在共享 score、Shiftmax、ATLIF arithmetic 上时分执行；只保留必要的 state SRAM bank。RAWAtten 的 stage-aware reuse 用于选择 tile，而不是复制不同 attention 公式。

**可证伪预测：** 与模块级展开相比，固定吞吐约束下组合面积显著下降；descriptor/control 小于总面积 8%，SRAM bank conflict 不使 p99 latency 超预算。

**新颖性风险：高。** 时分复用和 descriptor scheduler 是常规架构方法，不能单独作为创新；只能作为支持 ETCR/SCS-Shiftmax 可落地的系统组织。

## 6. DATE 贡献组合建议

### 6.1 推荐的三层贡献

1. **软硬件协同算法：H67 dyadic Motion-XOR TTX，或后续 AGDS。** 当前可提交证据是 H67 在 DSEC valid825 的精度/spike 优势和 dyadic 部署无退化；H68 只能作为“零推理增量的训练增强”消融，除非多种子或跨数据集证明稳定收益。
2. **核心硬件创新：SCS-Shiftmax/TPSF。** 强调 binary gated-K 中“输出零、分母非零”的不对称和最终 score 类 exact aggregation，不强调泛化的“重复消除”。
3. **系统数据流创新：ETCR。** 64-bit temporal pair、Motion-Delta fused detector、三级 exact route 和共享 row backend 形成完整 accelerator story。

### 6.2 暂定标题/命名

- 中文工作名：**面向全二值脉冲光流 Transformer 的精确时间-类别路由加速器**。
- 英文工作名：**ETCR: Exact Temporal-Class Routing for All-Binary Spiking Flow Transformers**。
- 核心单元：**SCS-Shiftmax: Score-Class Streaming Shiftmax**。
- 软件协同候选：**AGDS: Auxiliary-Guided Deployability Shaping**。

这些名称只描述机制，不包含“first”“novel histogram”或不受证据支持的通用性承诺。

### 6.3 禁止的包装

- 不写“借鉴 Bishop 后提出新的 TTB”；我们的 token-time 组织必须改称固定 temporal pair descriptor，并清楚引用 Bishop。
- 不写“H68 是 Castling-ViT 的硬件版”；H68 没有原论文 mask、linear-angular attention 和 DWConv。
- 不写“TPSF 跳过零 K token”；零 K 仍进入 Shiftmax denominator，硬件只折叠等价 score contribution。
- 不写“64-bit pair 降低 50% 存储”；逻辑容量不变，只有未合并 baseline 下请求/传输可能下降。
- 不用 spike-energy proxy 代替芯片能耗；Motion-XOR、histogram、Shiftmax、SRAM、controller 和 clock tree 必须单列。
- 不把 H67/H68 单次训练结果写成普适软硬件协同规律。

## 7. 最小验证闭环

### 7.1 软件与 profile

- H67/H68 至少三随机种子；报告 AEE、AAE、spikes、firing 和统一 dyadic valid825。
- H67 与 H68 在 DSEC 之外至少一个标准事件光流数据集复核，避免单数据集过拟合。
- 每 `stage/block/head/row` 输出：K-zero、temporal unchanged、union toggle、zero-K score histogram、active score classes、class entropy。
- 联合统计 `unchanged × K-zero × active-classes`，不能分别用边缘均值估算 ETCR 覆盖率。
- H68 补 `aux on/off`、退火前后部署主支 profile；未来 AGDS 做 `aux / class regularizer / toggle regularizer / combined` 消融。

### 7.2 数值与 RTL

- 软件 reference 固定 `center -> quant -> Shiftmax` 顺序，枚举所有半格点/tie-to-even 情况。
- H67 score、Motion-Delta fusion、TPSF denominator、dense vs folded row、gated-K 做逐层 bit-exact regression。
- 对真实 valid825 trace 比较每 row max、denominator、gate 和 output；不能只比较最终 AEE。
- 形式/穷举证明三级 route 互斥且完备；backpressure 下 descriptor 不丢失、不重复。
- Verilator lint、Icarus/Verilator random、Yosys synthesis check、CDC/RDC 和 SRAM interface audit 全部通过后才进入 DC。

### 7.3 同约束 DC/PPA

- 同一 standard-cell library、corner、V/F、SDC、compile effort 和 SRAM macro：TTX dense、H67 dense、H67+TPSF、H67+ETCR 四行差分。
- 面积分解：pair SRAM、XOR/popcount、score frontend、histogram、replay buffer、exp2/reciprocal、route FIFO、controller、ATLIF state。
- 功耗分解：clock、combinational、sequential、SRAM read/write、leakage；使用真实 trace SAIF/VCD。
- 性能：cycles/window、windows/s、frame latency、p99 queue、bank conflict、histogram clear overhead、目标频率 slack。
- 报告 class/toggle sweep 的 break-even 曲线；证明收益不是只来自单一 checkpoint 的平均值。

|---|---|---:|---|

## 9. 最终判断

现阶段已经具备继续做 H67/H68 DATE 硬件的文献基础，但**还不具备宣称新颖性关闭或直接投稿的证据**。推荐主线是：

```text
H67 dyadic checkpoint
  + 64-bit temporal-pair operand layout
  + Motion-Delta shared front-end
  + exact unchanged / TPSF / active-K routing
  + shared SCS-Shiftmax and gated-K backend
```

H68 不另做一套 RTL，只进入软件消融和未来 AGDS 训练实验。若 ETCR 的真实 profile 与 DC 不过 break-even，则收缩为 H67 dense + TPSF；若 TPSF 本身也不过 break-even，则论文不能依赖“概念新颖”，应回到 H67 算法结果和更有量化收益的 exact Delta 数据流。

本轮 34 项来源足以否定多项过宽 claim，并形成可验证的组合假设；但 TPSF 正式 claim 仍需沿 I-ViT、Bipolar Self-attention、Softermax、BLADE、Bishop 的参考文献与引用文献继续做公式级追踪。
