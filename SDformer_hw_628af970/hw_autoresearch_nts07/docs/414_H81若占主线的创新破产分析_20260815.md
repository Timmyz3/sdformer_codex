# H81 若占主线：完整性可重建，创新不能平移

日期：2026-08-15。来源：Grok agent。  
起因：用户在 Codex 硬件会话里的原话是

> 我担心的是，motion和local看起来跟h81并没太多竞争力，如果算法站不住脚，那我们做的这双线硬件怎么办，还有退路吗，说不定后面要做h81硬件怎么办

并再次要求就「H81 占有后创新性会不会要重做」深入讨论。  
本文件补 412 没拆开的那一半：412 答的是 RTL 复用，这里答的是 DATE 创新身份。  
不改 `docs/359`，不接 H81 RTL。

## 1. 先把两种「重做」拆开

| | 完整性 | 创新性 |
|---|---|---|
| H81 占主线时会怎样 | 证据链必须按 H81 ckpt 重绑：trace、公平周期、INT8、SAIF/DC。RTL 大部分复用。完整度会先掉一档，做完 G2 再回来。 | **不能**把 Motion 3.2 改个名继续用。贡献句里 Motion-XOR 依赖的那截会死。 |
| 工作量 | 中等验证 + 解开 wrapper 硬连，不是新后端 | 可能要换主硬件对象，或接受更薄的贡献 |
| 412 覆盖了吗 | 覆盖了 | 只写到「H81 不增加新贡献」，没有写「旧贡献会不会破产」 |

用户的担心对创新成立，对完整性只对一半。完整性是重建，不是推倒；创新是身份问题，复用网表救不了。

H81 **现在没有占主线**。算法选择器仍只要 H67（MVSEC 四序列过门）。H81 无 MVSEC、无硬件 provenance，和 H67 只是 recipe 级对照。下面全是条件句。

## 2. Motion 3.2 里哪些绑死在 Motion-XOR 上

407 现在唯一允许的 Motion 贡献链：

```text
MSSB5 score-front CSE
  -> Q7 temporal-pair score equivalence
  -> one-class descriptor + multiplicity + temporal membership
  -> weighted Shiftmax
  -> ordered K recovery
```

| 环节 | 依赖 Motion-XOR？ | H81 还在吗 | 在 H81 上还值多少创新 |
|---|---|---|---|
| MSSB5 五统计 | 是，第五项是 motion | 变成四统计或 dual-direct | 本来就只是 CSE 支撑，不单列 |
| Q7 pair 等价 | 半依赖。pair 来自 `T_w=2`，等价在无 XOR 时仍会发生 | 在，故事变弱 | 「相同 overlap+silence 分」更像普通 CSE |
| one-class descriptor + multiplicity | 否，RQTB 发射规则只看分数相等 | 在 | 对象还在，动机从「时间先验类」变成「同分合并」 |
| temporal membership | 是，不等时靠 motion 区分时间极性 | 基本没了 | 3.2 里有辨识度的那截 |
| weighted Shiftmax / 有序 K 恢复 | 否 | 在 |  Exact 必需，不是 DATE 对象 |

所以：H81 占主线后，**网表能留，3.2 不能留。**  
剩下的是「对 T=2 二值 TTX 做 pair-local 同分 descriptor 合并」。审稿会拿它去比 value clustering / CSE / 普通 skip。我的预估是 **2.7–3.0**，不是 3.2。1.1865× 是 H67 分数分布上的数，禁止搬到 H81。

更硬的一句：H81 公式里根本没有 motion 项。把「可逆时间 score-class 合并」继续当主贡献，等于给一个模型不用的算子做专用核。这比「0.069% 精度」更致命。

## 3. Local5 也救不了 H81 论文

Local5 不依赖 Motion-XOR，412 说「Local5 是另一种模型」是对的。  
但若论文模型变成 H81（自身 TTX，无五邻域），Local5 的 QS+FCSR+TCFM5 同样是 **off-model**：H81 没有 self+4。

| 若算法身份是 | Motion 硬件 | Local5 硬件 |
|---|---|---|
| H67 | on-model，主张收窄后仍是 3.2 对象 | 另一模型，附录/第二贡献 |
| Local5 | off-model | on-model，3.1 对象 |
| **H81** | **off-model** | **off-model** |

H81 若占有，**两条现成 DATE 对象一起离场**。不是「Local5 顶上」。能留下来的只是统一 TTX 引擎本身：Q==0 skip、Shiftmax、gated-K。这和 FireFly-T / BSA 挤在同一条街上，目前看不到 3.2 的新对象。

## 4. 四条退路（按创新风险排序）

### 退路 0（现在就锁，推荐）

**硬件身份 ≠ 算法消融赢家。**  
H81 只进消融表。论文模型和硬件绑定继续是 H67 ep35（外加独立的 Local5 线）。理由已经存在：MVSEC 门、硬件 provenance、Motion 是近零精度代价的可部署项。

DATE 可以写：精度台阶来自统一 TTX；硬件专做冻结 H67 部署里真实存在的时间分数类归并。审稿若问「为什么不做 H81」，答：选择器没选它；H81 没有 MVSEC 和硬件证据；关掉 XOR 会丢掉 on-model 的专用对象，却几乎不换 AEE。

这条退路让完整性和创新都不用重做。

### 退路 1（选择器正式改选 H81，且 H81-RQTB 过 G0/G1）

同一套 RQTB 当 **另一个、更薄的对象**：pair-local 同分合并，不再写 temporal membership / MSSB5 / Motion。创新重评，预计 ≤3.0。1.1865× 作废，重测 H81 自己的 Fixed vs RQTB。完整性走 412 的 G2。  
禁止：把 3.2 原句换一个模型名继续用。

### 退路 2（选择器改选 Local5，且 extension gate 全过）

硬件第一贡献改成 QS+FCSR+TCFM5。Motion 降为 H67 case study。创新不重做，是换线。H81 仍只是消融。  
注意：这要求算法也改成 Local5，不是「H81 论文配 Local5 硬件」。

### 退路 3（H81 必须当唯一模型，且 RQTB 过不了门）

现成对象全 off-model。只能缩成「忠实的二值 TTX 微架构」，或推迟投稿。412 已经写了。不存在靠换名冲 4.0 的办法。

**明确否决：** H81 算法 + H67/Local5 硬件的混身份稿。审稿会一刀切。

## 5. 完整性：会掉档，不是推倒

若真走退路 1：

- 生产 wrapper 里 `ENABLE_MOTION_XOR` 仍硬连 `1'b1`，要解开，MSSB5 收成四统计。
- sample0 138 行、十样本 1380 行、1.1865× 全部不能继承。
- 完整度会从 3.2 掉到大约 2.8，直到 H81 自己的 Icarus/Verilator、真 INT8、分层窗、DC 补回。
- projection / Acc / 调度 / pair 布局不用重写。

这和「创新重做」不是一回事。412 把这件事说清楚了。不要用完整性工作量去填创新洞。

## 6. 现在不要做的事

- 不要为防 H81 先开第三套 RTL。
- 不要用 H67 的 Q/K 套 H81 公式冒充 H81 equal-pair。训练分布不同，那是代理，只能当内部直觉，不能进 G0。
- 不要把 orbit / 共享 score 包装成「H81 创新」。两项已 NO-GO，而且共享 score 还改语义。
- 不要在 QF / Local5 40→50 结束前抢 GPU 导 H81 trace。G0 排在算法队列之后。

GPU 空了以后，G0 只读测一件事：H81 自己的 equal-pair 率和 RQTB 周期。用来判断退路 1 活不活，不是用来现在改贡献句。
