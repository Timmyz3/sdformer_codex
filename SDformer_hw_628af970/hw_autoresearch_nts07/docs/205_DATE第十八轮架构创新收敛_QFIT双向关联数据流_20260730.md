# DATE 第十八轮架构创新收敛：QFIT 双向关联数据流

## 1. 本轮结论

当前硬件工作不能继续以“Shiftmax、term、DCTF、FIFO、双缓冲”等多个弱点平铺。Local5 真正可形成架构主张的结构性事实是：

> 同一个固定五点关联图，同时决定 destination 侧的相关性计算复用，以及 source 侧的最后使用时刻。

据此冻结总架构候选：

**QFIT（Quotient-Frontier Incidence Transpose，商差-前沿关联转置）**

QFIT 只含两项候选贡献：

1. **QFSA：跨方向商差执行。** 以 self-K 为 anchor，将 N/S/E/W 的差分事件放入统一 tagged 域，在同总 W4 lane 预算下动态借用空闲 lane。
2. **FCSR：闭式前沿关系转置。** Shiftmax 按 destination 产生 gate，投影按 source 消费 gate；固定 stencil 的最后消费者可由坐标闭式生成，因此不物化完整关系平面，也不需要运行时引用计数。

term 目录、SCS-Shiftmax、DCTF、FIFO 和双上下文属于 QFIT 的算子或实现部件，不能再分别列为 DATE 架构贡献。

## 2. 为什么这是一个统一架构，而不是两个补丁

令 Local5 关联图为 \(G=(D,S,E)\)。每个 destination \(d\) 只连接 self/N/S/E/W 五个 source。

### 2.1 行方向：destination 侧商差执行

对每个 destination，QFSA 先计算：

- self anchor：`raw(Q_d, K_d)`；
- 四方向差分：`K_neighbor XOR K_self`；
- 每个差分事件携带方向 tag，并只更新对应方向累加器；
- 每个候选最终只做一次 RNE，不允许中间舍入或饱和。

这里利用的是关联矩阵的一行：五个候选共享同一个 Q，四条邻边共享 self-K anchor。

### 2.2 列方向：source 侧在线关系转置

Shiftmax 输出 `gate(d,s)` 后，gated-K projection 需要按 source 聚合：

`(source, gate, lane) -> destination set`

这是对同一关联矩阵按列消费。FCSR 定义：

`L(s) = max { d | (d,s) in E }`

当 raster 流到达 `L(s)` 时，source 的全部入边 gate 已确定，可立刻形成 source-owned descriptor。QFIT 因而完成：

`destination-major gate stream -> source-major projection stream`

而不写入完整的五候选 gate plane。

### 2.3 本土化的新意

Prosperity 的 exact residual、Phi 的 pattern/residual 表示、Bishop 的 metadata-first stratification、FireFly 类多事件执行和常规 stencil line buffer 都只能作为启发。QFIT 的本土化差异是：

- 同一五点关联图同时驱动算术商差和存储生命周期；
- destination 行方向与 source 列方向在同一流水中连续切换；
- 稀疏性不是预测、近似剪枝或运行时发现，而是固定图上的 exact 调度；
- QFSA 与 FCSR 共享坐标、边界和方向微程序，不各自维护一套邻接元数据。

这才是论文应主打的架构抽象。单独写“用了 XOR”“用了三行 buffer”或“用了双 context”均不足以构成创新。

## 3. FCSR 的闭式退休公式

对 destination 坐标 `(y,x)`：

1. `y > 0` 时，退休 source `(y-1,x)`；
2. `y = H-1 且 x > 0` 时，额外退休底行 source `(H-1,x-1)`；
3. `y = H-1 且 x = W-1` 时，再退休最后一个 source `(H-1,W-1)`。

该公式与逐 source 枚举全部消费者的结果完全一致，W9/W15 的最大同拍退休数均为 3。当前单 snapshot 通路将 2 至 3 个退休项按一项/拍序列化。

新增单元测试已经对 `3x3/9x9/15x15、T=2` 证明闭式公式与消费者枚举逐项一致。硬件无需存储 `source_retire_destination` 表；该数组只保留在 trace 中用于审计。

后续还需加入一个强控制基线：

- **动态前沿基线**：使用逐 source 引用计数和 source-ID queue，退休时刻与 FCSR 完全相同；
- **FCSR**：使用闭式坐标公式和固定顺序，无引用计数。

二者周期应相同，只比较控制面积、元数据访问和能耗。这样才能证明收益来自静态图专用化，而不是更早退休本身。

## 4. 公平强基线矩阵

### 4.1 Score 侧

| 名称 | 总 residual lane | 跨方向借 lane | direct fallback | 四个精确累加器 |
|---|---:|---:|---:|---:|
| Direct-5 | 0 | 不适用 | 同一 32-lane raw engine | 是 |
| 4xW1 | 4 | 否 | 与 QFSA 共用合同 | 是 |
| QFSA-W4 | 4 | 是 | 与 4xW1 共用合同 | 是 |

物理相序冻结为：

`anchor -> max(direct fallback cycles, residual waves) -> final RNE`

anchor/direct 共用一套 32-lane raw engine；W4 residual compactor 是独立资源，因此 direct 与 residual 在 anchor 后并行。旧模型使用两者相加，现已纠正。QFSA 与 4xW1 唯一结构变量应是“固定方向 lane”还是“统一 tagged lane pool”。

### 4.2 关系转置侧

| 名称 | 建表方式 | 退休粒度 | producer/consumer | 运行时引用计数 |
|---|---|---|---|---:|
| Full-plane | 完整 K/gate plane | 窗口 | 两阶段 | 否 |
| Nonblocking Stripe | 行内增量建表、双 row ping-pong | 行 | 可重叠 | 否 |
| Dynamic Frontier | 在线 | source last-use | 可重叠 | 是 |
| FCSR | 在线 | source last-use | 可重叠 | 否，闭式公式 |

本轮已修正 Stripe 模型：不再在行末同步 snapshot W 个 descriptor；行内增量构建，行末只交换 ownership，双 row buffer 允许 producer 与 consumer 独立运行。Stripe 和 FCSR 下游都限制为单 service/cycle。

论文联合主对照必须是：

`4xW1 + Nonblocking Stripe`

不能再用串行 Direct-5、同步行突发 Stripe 或全窗口两阶段作为唯一强基线。

## 5. 已完成的证据修正

### 5.1 Ordered trace v2

新增或冻结：

- 四方向 `delta_count[N/S/E/W]`；
- QFSA W2/W4/W8 的 direct mask、direct cycles、residual waves；
- source product-term count；
- source destination-delivery count；
- source 服务下界 `max(term, delivery)`；
- T0/T1 plane-serial 元数据；
- source last-consumer；
- Direct-5、4xW1 和 QFSA 的逐 destination 服务周期。

`max(term, delivery)` 仍只是双流水理想下界，不包含目录等待、Acc 冲突和 SRAM latency。

### 5.2 周期模型

已经修正：

- T0 的 score、projection 和 FIFO 全排空后才允许 T1；
- QFSA direct/residual 使用冻结后的并行相序；
- Nonblocking Stripe 行内建表、双 row ping-pong；
- FCSR 底边 2 至 3 source 退休由单 snapshot 通路序列化；
- Stripe 与 FCSR 使用相同单 service/cycle 后端。

### 5.3 正确性

- QFSA 10,000 个随机五候选、50,000 个 score 的整数参考零失配；
- 任意 residual 事件顺序下，raw accumulator 的解析范围为 `[0,2048]`，W4 reducer 为 `[-256,256]`，分别由 signed 13-bit 与 signed 10-bit 覆盖；
- 闭式退休公式与消费者枚举一致；
- 本轮相关 CPU 回归 37 项全部通过。

这些结果仍不覆盖 tagged compactor 的硬件事件顺序、Shiftmax、随机反压和最终 Acc。

## 6. 最小可综合 RTL 冻结

### 6.1 QFSA/4xW1 可切换 score leaf

固定七级边界：

1. S0：锁存 `{tag,plane,row,col,Q32,K[5]x32,valid[5]}`；
2. S1：四路 XOR；
3. S2：四路 popcount 与 self anchor raw；
4. S3：16 种 direct/residual route 选择；
5. S4：shared direct engine 与 residual backend 并行服务；
6. S5：五候选各一次最终 RNE；
7. S6：Shiftmax5 与 ready/valid 输出。

资源：

- 一套 32-lane anchor/direct raw engine；
- QFSA 为一个可流水 `128 -> W4` tagged compactor/reducer；
- 4xW1 为四个 W1 本地 selector；
- 四个 signed 13-bit raw accumulator；
- 同方向 W4 单拍归约范围 `[-256,+256]`，使用 signed 10-bit 中间和；
- 同一 direct engine、accumulator、RNE、Shiftmax 和输出协议。

第一版必须同时综合一拍 compactor和两拍 compactor，不能预设动态 lane pooling 一定改善 Fmax 或 EDP。

### 6.2 FCSR/Stripe 可切换关系转置 leaf

双方共用：

- 五个 role gate bank，每 bank `3W x 9b、1R1W`；
- 一个 32-bit K snapshot 端口；
- 相同 descriptor FIFO 深度；
- 相同单 service/cycle projection/Acc mock backend；
- 相同 write-through bypass；
- 相同 T0 drain/T1 warmup。

唯一变量：

- Stripe：row ownership 交换；
- Dynamic Frontier：引用计数归零；
- FCSR：闭式坐标退休。

若不保持以上同物理合同，任何 FCSR/Stripe 面积或周期差都不能进入论文。

## 8. 进入 DATE Accept 区间的证据门槛

1. Local5 fullres valid825 通过算法 guardrail，不能用硬件收益掩盖精度失败；
2. post-G0 多样本、四 stage trace，报告 mean/p95/p99；
3. QFSA 对 4xW1：同频或同吞吐 DC/STA/SAIF，EDP 至少改善 15%；
4. FCSR 对 Nonblocking Stripe 和 Dynamic Frontier：同 macro/端口，EDP 或系统存储能耗至少改善 15%；
5. 联合 QFIT 对 `4xW1 + Nonblocking Stripe`：端到端 EDP 至少改善 20%，p99 延迟不退化超过 5%；
6. T162/T450、边界 invalid、全 16 route、随机背压、plane drain、score/gate/relation/delivery/final Acc 全链零失配；
7. 真实 SRAM macro、目标 SDC、DC/STA 和 post-G0 SAIF，Yosys 只作附录趋势。

在这些结果出现前，论文只能写“候选架构”和“解析性质”，不能写“实现了高能效加速器”。

## 9. Motion 与 Local5 的主线关系

H67 Motion fullres W15 最佳结果为 AEE 2.0730，明显弱于 NB0 fullres AEE 1.4454，因此 Motion 不能仅凭旧 crop 结果自动成为唯一算法主线。

硬件上：

- Motion 保留 SCS-Shiftmax、term flow 与 DCTF 的完整旁路线，可作为通用 all-binary attention 对照；
- Local5 提供 QFIT 所需的固定五点关联图，是当前架构创新更强的一线；
- Local5 fullres exact 尚未完成，当前也不能提前宣布 Local5 为论文主线。

最终选择规则：

- Local5 通过精度 guardrail且 QFIT 同约束 EDP 为正：Local5 主线；
- Local5 精度失败：QFIT 降为架构探索，Motion 只能在算法重新修复后再竞争；
- 两者都不满足：不应为了投稿强行冻结主线。
