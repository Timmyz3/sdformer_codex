# DSEC 全分辨率 RTL-exact 签核阻塞与 T450 闭环清单

日期：2026-07-30

## 结论

当前 H67 Motion-XOR 和 H66d Local-5 的 full-resolution 部署评估只能称为
`attention-core hardware-order numeric`。它在 PyTorch 中执行 Q7 score、
Q8 `exp2` LUT、整数 row sum、ceil-power-of-two normalization 和 Q1.7
ties-to-even gate；它不是 480x640、`2x15x15`、`T=450` 的 SystemVerilog
RTL-exact，也不是全网定点推理。

在完成本文第 4 节的 T450 RTL 回放前，论文表格、图注和日志不得使用
`fullres RTL-exact` 或 `full-network RTL-exact`。

## 现有 RTL 的明确规模边界

### H67

- `rtl_h67/h67_attention_top.sv` 的默认 `MAX_TOKENS=162`。
- `rtl_h67/h67_score_class_row_engine.sv` 的默认 `MAX_TOKENS=162`，运行时
  `cfg_n_tokens` 超限会被钳制到该值。
- `rtl_ttx/ttx_descriptor_scheduler.sv` 仍直接把 `row_n_tokens` 写成 `162`。
- `sim_h67/run_iverilog.sh` 只覆盖默认规模和 `MAX_TOKENS=162`，没有
  `T=450` 测试。

因此，H67 已验证的是 crop/window9 的 T162 attention-row
算术和控制模块，不是 window15 的 T450 数据流。

### H66d Local-5

- `rtl_local5/local5_linebuf_window_top.sv` 当前默认 `ROW_TOKENS=8`、
  `MAX_DEST=16`，只维护三行小规模 line buffer。
- `tb_local5/tb_local5_linebuf_window.sv` 使用 row8、dest16、3 windows。
- `scripts/generate_local5_ordered_window_vectors.py` 明确生成 synthetic
  小规模向量，而非 fullres rank-1 checkpoint 的真实 post-G0 trace。

因此，Local-5 已验证的是 score/gate/term/projection 叶子链和小规模顺序控制，
不是 15 行滑窗、450 destination、halo/boundary 处理和 fullres 地址控制。

## 当前可以安全写入论文的声明

1. H67 的 T162 row arithmetic/control RTL 已完成模块级回归。
2. Local-5 的 Q7 score、true-invalid mask、Q1.7 Shiftmax 叶子链已独立验证。
3. fullres valid825 使用与硬件算术顺序一致的 Python 数值路径。
4. `energy_uj` 仍是 spike-activity proxy，不含完整 Shiftmax、reduction、
   SRAM、控制和数据搬运，不能作为芯片级能耗结果。

## Fullres RTL-exact 最小闭环

### G0：冻结接口与定点边界

- 明确加速器覆盖 attention core，还是包含 projection/ATLIF/decoder 的全网。
- 冻结 score、gate、Kxgate、累加器、膜电位、阈值和归一化位宽及舍入/饱和规则。
- 若不做全网定点，论文必须明确写成 attention-core accelerator。

### G1：H67 T450 参数化

- 移除 descriptor scheduler 中的常数 `162`。
- token/destination index 至少支持 0..449，并检查首、尾和 reset 边界。
- 将 score/gate/descriptor SRAM、counter 和 accumulator 深度扩展到 T450。
- 对 SRAM latency 1/2、连续 window、随机 backpressure 和中途 reset 做回归。

### G2：Local-5 fullres controller

- 实现 `T=2`、15x15、450 destination 的 15-row line-buffer/halo 数据流。
- 覆盖 window head、block/head 切换、边界 invalid mask 和 SRAM 地址。
- 保持候选顺序、term multiplicity、destination 和 final accumulator 可追踪。

### G3：真实 checkpoint trace

- 从 fullres rank-1 checkpoint 导出 12 个 attention block 的真实 T450 trace。
- 至少包含内部 window、四边/四角 window、多个 head 和非零/全零稀疏行。
- trace 必须记录 checkpoint/config SHA-256、导出代码版本和张量定点合同。

### G4：SV 零失配回放

- Python hardware-order 与 SV 在 score、gate、term order/multiplicity、
  destination、accumulator 和 `last` 边界逐项零失配。
- 保存 simulator 版本、命令、seed、日志和 mismatch summary。
- G1-G4 全部关闭后，才能称 `fullres attention-core RTL-exact`。

### G5：DATE PPA 与系统签核

- 候选和公平 baseline 使用同一 RTL/SRAM macro/SDC/PVT/频率/工具版本。
- 报告真实 cycle、traffic、SRAM access、DC/STA 和 SAIF 功耗。
- 禁止用 `25/9` 等窗口比例对面积、周期或能耗作直接外推。
- 只有在 G0-G5 全部关闭后，才能形成 DATE 硬件端最终 sign-off。

## 与当前实验队列的衔接

当前顺序保持：

1. H67 fullres FT30 + standard valid825；
2. H66d fullres FT30 + standard valid825；
3. NB0 provenance replay；
4. H67/H66d dyadic 与 hardware-order valid825；
5. 以同一 valid825 的 AEE、benchmark AAE 和归一化 spike activity 选算法赢家；
6. 只对赢家执行 G1-G5，避免同时扩两套 T450 RTL。
