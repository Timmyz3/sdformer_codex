# Local5 公平 Ordered 前端候选 V2 预注册

> 本文闭合 Local5 候选筛选模型的公平性，不是新 RTL 或 ASIC PPA 结果。

## 1. 结论

第二轮独立 DATE 审稿发现，旧 C0--C3 模型会系统性低估 Direct、惩罚
SRAC2，并使 ERM admission 随后端变化。该问题足以翻转 `1.20x` 晋级门槛。
因此：

1. `local5_joint_candidate_prereg_v1` 在正式 profile 产生前作废；
2. 保留 v1 源码、合同和 SHA 作为负结果，不原地改写；
3. 新增 v2 公平模型，四候选共享 active-source scan、descriptor capture、
   ordered builder、输出 readout 和 serializer 边界；
4. ERM7 只使用现有 vault 的统一规则 `15 + term_count < 450`；
5. GASR2C-P 明确是“支持跨 head preserve 的候选模型”，当前没有对应 RTL；
6. 三候选使用 Bonferroni `alpha=0.05/3`，不再把三个独立 5% 下界当成
   family-wise 5%；
7. 正式候选 watcher 在第三轮独立审稿通过前不启动。

## 2. V1 为什么失效

| 问题 | v1 行为 | 后果 |
|---|---|---|
| descriptor 前端 | Direct 不计 capture，SRAC2 单独计 latency=3 | 候选不公平 |
| 跨 head | 模型让两者 preserve，但现有 GASR2C `run_start` 清状态 | 把待实现能力写成既有合同 |
| ERM admission | 分别用 Direct/SRAC2 service 判定 | 同一 relation 因后端不同而改变驻留集合 |
| fallback | nonresident 直接重算，未写出控制状态成本 | 模型偏理想 |
| 预注册 | 文件 SHA 可成组改写，未绑定 profile 输入 | 不能充分阻止 post-hoc |
| 统计 | 三候选各用单侧 5% 下界 | 多重比较错误率膨胀 |

## 3. 公共数据流边界

真实 Local5 active projection 前端为：

```text
relation build / exact replay
  -> 五色 active bitmap
  -> 15-cycle word scan
  -> active-source descriptor
  -> FIFO2
  -> source-major builder
  -> lane-major / first-role gate-major term
  -> Direct 1RW 或 GASR2C-P
  -> head间Acc32 preserve
  -> 最后一次450-vector readout
  -> 450x32 scalar serializer
```

`qfit_source_multicast_term_builder` 接收 descriptor 的拍不能同时发 term。
FIFO2 只能让 frontier 提前缓存两项，不能消除每个 active source 的 capture。
因此 v2 对两候选共同计：

```text
ordered_backend = run/control
                + 15-cycle active scan
                + active_source_count descriptor captures
                + ordered term service
                + flush
```

Direct 的 term service 为首次触达直写 `1` 拍、复访 RMW `2` 拍，五 bank
按原子组播取最慢目标。GASR2C-P 只额外计未被当前 source term 隐藏的
dirty writeback/refill，不再单独加入任意 `descriptor_latency=3`。

## 4. Relation 路径

### 4.1 Recompute

```text
cycles = 4-cycle controller
       + max(450-cycle relation build,
             ordered backend,
             first-tile speculative memo writes)
```

该 `max` 延续既有 FCSR 在线重排的强基线假设，属于 `[模型]`；当前集成 RTL
并未证明所有三项都能达到该重叠度。

### 4.2 Replay

```text
cycles = 4-cycle controller
       + max(active_descriptor_words + directory_commit,
             ordered backend without 15-cycle active scan)
```

directory 已知 nonresident 时直接选择 recompute，不先做必败 replay。
模型另有 forced-replay-miss 路径，显式计 replay hit、miss 转换和 recompute，
只用于边界测试，不进入正常候选收益。

### 4.3 Admission

四候选共用同一 head-order 驻留集合：

```text
critical = 15 + exact_term_count < 450
resident = critical && cumulative_active_descriptor_words <= 512
```

该定义逐字对齐现有 `qfit_exposure_relation_vault`，不再根据 Direct 或
GASR2C-P 的后端周期分别选择。

## 5. 冻结候选

| 候选 | Relation | Backend | 证据状态 |
|---|---|---|---|
| C0 | 每 output tile 重算 | Direct legal 1RW | Direct 叶级 `[rtl]`，全模型 `[模型]` |
| C1 | 每 output tile 重算 | GASR2C-P | 跨 head preserve `[待验证]` |
| C2 | ERM7 critical-only exact replay | Direct legal 1RW | vault/controller 组件 `[rtl]`，联合周期 `[模型]` |
| C3 | ERM7 | GASR2C-P | 双生命期组合 `[模型]` |

`GASR2C-P` 固定表示 geometry-ahead、每 bank 两个 source-resident context、
head 边界 flush 到 backing SRAM、下一 head 保留 backing-valid。仓库现有
`qfit_gasr2c_acc_bank` 的 `run_start` 会清 backing-valid，因此 C1/C3 只能先做
模型筛选，过门槛后必须新增 preserve RTL 和 Acc32 miter。

## 6. 统计裁决

每候选相对 C0 使用同一 sampled window 和同一 100-sample HT 整帧估计。
同时做 sample bootstrap 与 18-sequence cluster bootstrap。

```text
per-candidate alpha = 0.05 / 3
decision LB = min(sample Bonferroni lower,
                  sequence Bonferroni lower)

PROMOTE_TO_MINIMAL_RTL 当且仅当：
  decision LB >= 1.20x
  && overall weighted window p95不退化
  && S0/S1/S2/S3各自weighted window p95不退化
```

sequence key 必须与 100 个有序 sample key 逐项一致，并由文件名去掉末尾
时间索引得到；不能只检查“恰有18个字符串”。payload 必须满足 13800 group、
每组450 source、完整 offset、source id 和 plane/y/x 形状合同。

## 10. 第三轮独立 DATE 评审

第三轮独立审稿结论为 `Reject`：证据包 `2.1/5`、筛选严谨性
`2.0/5`、DATE 就绪度 `0.8/5`。v2 evaluator watcher 被禁止启动。

四个 P0 为：

1. `max(450, backend)` 与当前 RTL 的 build-seal 后串行 emit 相序冲突；
2. v2 Direct/GASR stall 模型存在方向相反的系统偏置；在 20260805
   held-out 上会把 RTL 的 `0.995x` 错报成约 `1.43x`；
3. selection-plan writer 会在正式启动时删除手工加入的 prereg 绑定；
4. 未进入 Git ref/commit 的 loose blob 只能证明字节一致，不能证明冻结时间。

P1 包括 controller 固定拍、scan/flush 分账、readout/serializer timing 和输入
范围/seed 重放。已经确认正确的部分只有 descriptor capture、公共同一
admission、Bonferroni 与 cohort/group 形状校验。

因此 v2 保持 `INVALIDATED_BEFORE_PROFILE`。其后提出的 v3 双 fixed 串行模型
也因继续复用 v2 stall predictor 而在独立评审后作废；后续改用完整 RTL
作为周期 oracle，不再由 Python 猜 bank stall。
