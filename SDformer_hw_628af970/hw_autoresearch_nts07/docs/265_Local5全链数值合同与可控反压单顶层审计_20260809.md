# Local5 全链数值合同与可控反压单顶层审计

## 1. 本轮结论

本轮先纠正一个代码事实：仓库已经存在
`rtl_qfit/qfit_local5_projection_tile.sv`，其数据流为：

```text
binary Q/K
  -> Q7 alpha-XNOR Local5 score
  -> masked hardware-order Shiftmax5 Q1.7
  -> destination-major relation transpose
  -> source-major gate-equivalence term
  -> TCFM-5 topology-colored multicast
  -> five-bank Acc32
```

因此，旧文档中“`score/Shiftmax5 -> relation -> term -> TCFM5 -> Acc32`
单顶层未完成”的表述已经过时。本轮没有重复创建顶层，而是重新审计该顶层，
新增可控 `term_issue_enable` 边界、run/weight 两级事务账本，并补齐固定种子与
adversarial 反压回归。

当前可以成立的结论是：

- `[rtl]` 通用 Local5 数值结构已经在同一顶层内闭合；
- `[rtl]` 定向小例从 Q/K 和真实边界 mask 到全部 Acc32 均为零失配；
- `[rtl]` 独立 Python 一次性执行 Q/K→Shiftmax5→relation→term→INT8
  projection→Acc32，定向与固定种子随机集均与 Icarus/Verilator 零失配；
- `[rtl]` 三组固定 16-bit LFSR term 反压保持工作量不变且 Acc32 零失配；
- `[rtl]` 九类协议负例、每个 descriptor-final term 暂停、run-final term 暂停和
  连续两次非零运行均由 Icarus 与 Verilator/SVA 交叉通过；
- `[待验证]` 该单顶层尚未绑定正在训练的 equal-plus10 最终 checkpoint、
  同窗 all-head fullres trace 和最终 theta-folded 权重 payload；
- `[待验证]` 12-block 调度、真实 T450 多窗口反压、外部 SRAM 可变延迟及
  full encoder 仍未闭合。

本轮增加的是系统完整度与验证可信度，不新增 DATE 架构贡献。

## 2. Local5 软件数值合同

### 2.1 二值事件与五候选

软件路径位于：

```text
neuron_experiments/H9_bipolar_self_attention/overlay/models/
  STSwinNet_SNN/bsa_attention.py::_binary_alpha_xnor_stencil_attention
```

每个 destination token 的候选次序固定为：

```text
{self, up, down, left, right}
```

Q/K 事件定义为：

```text
q_event = (Q > 0)
k_event = (K > 0)
```

窗口边缘不做环绕。非法候选携带 `valid=0`，其 Shiftmax 指数和最终 gate
均严格为零。部署配置冻结：

| 字段 | 数值 | 证据 |
|---|---:|---|
| `mode` | `binary_axnor_local5_shiftmax` | `[模型]` |
| `alpha0` | `1/64` | `[模型]` |
| `mismatch_penalty` | `0` | `[模型]` |
| `consensus_score_norm` | `head_dim` | `[模型]` |
| `head_dim` | `32` | `[模型]` |
| `matrix_diag_bias` | `0` | `[模型]` |
| `binary_motion_xor_alpha` | `0` | `[模型]` |
| `preserve_mean` | `false` | `[模型]` |
| `hardware_mask_invalid_candidates` | `true` | `[模型]` |

配置中虽然保留 `consensus_bias=0.02` 字段，但 Local5 这条函数路径没有消费该
字段，RTL 也不应擅自加入此 bias。

### 2.2 Q7 score 恒等式

令 `n11` 为 32 个 lane 中 Q=1 且 K=1 的个数，`n00` 为 Q=0 且 K=0
的个数。浮点 score 为：

```text
score = (n11 + n00/64) / 32
```

量化到 Q7 整数码后：

```text
score_q7
  = RNE(score * 128)
  = RNE(4*n11 + n00/16)
  = RNE((64*n11 + n00)/16)
```

`qfit_local5_score_leaf.sv` 和 `local5_axnor_score_q7.sv` 先累加
`raw16=64*n11+n00`，再执行除 16 的 ties-to-even 舍入，因此与软件公式相同。
Python 精确参考 1000 组随机 Q/K、5000 个 score 已为零失配 `[rtl]`。

### 2.3 hardware-order Shiftmax5

`local5_shiftmax5_q17.sv` 与软件 `_rtl_shiftmax_gate_q17` 的顺序均为：

```text
Q7 row max
  -> delta
  -> 16-entry Q8 exp2 LUT
  -> invalid exp=0
  -> integer row sum
  -> ceil-power-of-two denominator
  -> Q1.7 RNE
  -> saturate [0, 256]
```

`preserve_mean=false`，因此不乘候选数 5。非法候选 gate 固定为 0。这里的
“hardware-order”是数值顺序合同，不是精度近似免责声明。

### 2.4 value/theta 边界

attention score 只依赖 Q/K 的正事件，不依赖最终 ATLIF theta 幅值；但是软件
`value_mode=threshold` 的投影值流包含：

```text
K_binary * theta_K(block) * W_projection_float(block)
```

正式部署使用离线折叠：

```text
W_eff(block) = theta_K(block) * W_projection_float(block)
W_int8, scale = dyadic_quantize(W_eff)
```

运行时仍传播 1-bit K event，不增加 theta 乘法器或 descriptor 位宽。最终
equal-plus10 checkpoint 释放后，必须重新导出并绑定 checkpoint SHA、payload
SHA、12-block ABI 和 Acc32 miter。当前通用顶层回归使用确定性 INT8 权重，
不能冒充最终 checkpoint-bound 投影签核 `[待验证]`。

## 3. 单顶层数据流与接口

### 3.1 数据流方向变换

score 前端按 destination 产生五候选 gate：

```text
destination d -> {(source role, gate[d, role]) x 5}
```

relation transpose 将其变成 source-major descriptor：

```text
source s -> {K_s, incoming_gate[5], valid_mask[5]}
```

其中 source-major role 固定解释为：

```text
{self, down-destination, up-destination,
 right-destination, left-destination}
```

term builder 对一个 source 内相同的非零 gate 合并 destination mask，并仅扫描
`K_s=1` 的 lane：

```text
term = {source_id, source_y/x, lane, gate, destination_mask[4:0]}
```

它保持整数乘加语义不变，但将“每个 destination 重算 product”重塑为
“一个 `(lane,gate)` product 多播到多个 destination”。

### 3.2 TCFM-5

TCFM-5 使用：

```text
bank(x,y) = (x + 2*y) mod 5
```

对于一个 source 的 `{self, down, up, right, left}` 五个 destination，该映射
给出五个互异 bank，因此一个 term 的最多五个更新可以同拍提交到五个同步
1R1W accumulator bank。五点邻域本身构成五节点写冲突团，在“每 bank 每拍
最多一次更新”的端口模型下至少需要五个 bank；TCFM-5 达到该下界。

### 3.3 生命周期

主机侧最小顺序为：

```text
load all folded INT8 weights
  -> projection_start
  -> wait projection_busy
  -> plane_start(0), stream H*W destinations
  -> plane_start(1), stream H*W destinations
  -> wait perf_descriptors==T*H*W and stream_idle
  -> projection_close when projection_close_ready
  -> wait projection_done
  -> Acc32 readback
```

权重装载不再只信任 `weight_last`。顶层使用 `HEAD_DIM*OUT_DIM` 位唯一覆盖表和
run-independent 计数器；只有最后一个未见 `(lane,out)` 在总数完整时携带
`weight_last` 才置 `weights_loaded`。提前 last、重复或越界地址均 fail-closed，
且 weight 协议错误只由 reset 清除。该账本验证 payload 结构完整性，但不验证
checkpoint SHA、scale 或权重数值来源 `[rtl]`。

`term_source_plane` 由 `source_id / (H*W)` 的整数区间恢复。只有 relation、term
builder 和 backend 均空闲、两个 plane 均按 raster 顺序完整接收、450 个 source
descriptor 全部唯一退休时才允许 `projection_close`。非法 start/close/plane/token
请求置位 sticky `protocol_error` 并 fail-closed；当前没有运行中 abort/recovery，错误
运行需要 reset，不能宣称“下一次 start 自动恢复”。

## 4. 本轮可控反压整改

旧顶层直接把 builder 的 `term_valid/ready` 接到 backend，只有 backend 自身状态
能够反压，无法主动模拟调度暂停或共享 SRAM 仲裁。本轮新增：

```text
input term_issue_enable

backend_valid = builder_valid && term_issue_enable
builder_ready = backend_ready && term_issue_enable
```

valid 和 ready 同时门控，确保 `term_issue_enable=0` 时 backend 不会误消费 held
term；builder 已有 SVA 检查 blocked term 的 source/lane/gate/mask/last 全部稳定。
这是一条系统 backpressure 接口，不单独包装成创新。

| 零 plane 提前 close | sticky error，禁止 done | PASS |
| 半 plane 提前 close | sticky error，禁止 done | PASS |
| plane 1 先于 plane 0 | 拒绝并报错 | PASS |

| busy 时再次 start | 不清状态，报错 | PASS |
| 错误 raster token 坐标 | 不握手并报错 | PASS |
| plane0 已退休 source 的非零重复 descriptor | 握手前 fail-stop 隔离，0 term/0 update/0 bank write | PASS |
| 每个 descriptor-final term 暂停 3 拍 | 16/16 命中，payload 稳定 | PASS |
| 两个 run-final term 暂停 3 拍 | 2/2 命中，close/drain 正确 | PASS |

连续运行向量使用全 1 Q/K、完整边界 mask 和权重 `W[lane]=lane+1`。每个
destination 的独立期望值为 `3*32*sum(1..32)=50688`，两次运行均逐 Acc32

`H=2,W=2,T=2` 的协议定向验证，不是 formal proof，也尚无运行中 abort 恢复接口
`[rtl]`。

重复 descriptor 负例在西北角使用边界合法的 `valid_mask=5'b0_1011`、
全 1 K 和非零 gate，因此测到的是 source-id 唯一性冲突，而不是边界错误。
顶层先计算 descriptor 合同，仅将合法 `valid` 送入 term builder；非法
descriptor 在生产者保持 ready/valid 稳定的 20 拍内不产生任何后端副作用
`[rtl]`。

## 6. 对 DATE 叙事的影响

本轮不应新增一条贡献。它只把已有贡献的实现边界向前推进：

1. Local5 的可辩护架构贡献仍是“双向五色拓扑不变量”：同一五色映射前端组织
   relation，后端消除五目的累加冲突；
2. source-major gate-equivalence term 是跨 attention/projection 的数据流重塑；
3. theta folding、banking、FIFO、ping-pong、定点化和本轮 issue-enable 都不是
   独立创新；
4. 只有在最终 fullres 同窗 all-head trace 上证明 TCFM-5/Relation Memo/term flow
   相对同端口强基线仍有收益，才可把组合写成 Local5 主贡献。

当前证据提升的是 correctness 和 system completeness，不能替代新颖性、真实
workload 外推或 ASIC PPA。

## 7. 冻结门槛与下一步

### 7.1 最终 checkpoint 门槛

equal-plus10 最终 checkpoint 释放后必须依次完成：

1. hardware-order fullres valid825 精度结果；
2. 12/12 block 的 Q7/Q1.7/invalid-mask 加载审计；
3. theta-folded v2 payload 独立重算和 SHA/ABI fail-closed；
4. 同一 checkpoint 的 Direct 与 TCFM-5 Acc32 零失配；
5. 同窗 all-head ordered profile，报告 mean/p95/p99、容量 overflow 和 fallback；
6. 将真实 T450 向量接入本单顶层并叠加多种 term/SRAM 反压。

### 7.2 双线继续推进

Local5 当前优先项是 checkpoint-bound 单顶层和 12-block 调度。Motion 不冻结：

- 持续维护 SCS/NMF/DCTF/RQTB 回归；
- 补多样本/多窗口和同频物理强基线；
- 新机制只在真实 workload 上先算可利用上界，再做最小 RTL；
- Local5 与 Motion 的新机制可以不同，不强制共用同一篇架构故事。

## 9. 独立 DATE 评审与整改轨迹

### 9.1 第一轮：2.0/5，Weak Reject

第一轮审稿指出：close 只检查 drain、不证明完整事务；错误可被未接受 start 清除；
反压没有直接命中 term；seeded SVA 缺失；计数和哈希不是 run-scoped/全覆盖。
本轮随后加入 start-ready、plane/token/descriptor ledger、真实 term 边界计数、
seeded Verilator/SVA 和完整输入哈希。

### 9.2 第二轮：2.5/5，Borderline Reject / Major Revision

第二轮确认主体整改有效，但仍指出：没有强制暂停 descriptor/run 最后 term；
token/descriptor 缺直接负例；连续运行是 zero-K；weight transaction 不完整；
Python exact 未进入同一 runner。对应整改如下：

| 审稿问题 | 整改 | 证据 |
|---|---|---|
| descriptor/run 最后 term 未覆盖 | 每个 descriptor-final 暂停 3 拍，16/16；run-final 2/2 | `[rtl]` |
| token/descriptor 无直接负例 | wrong-raster token + 重复 descriptor 故障注入 | `[rtl]` |
| 连续运行 zero-K | 两次 256 term/768 update，逐 Acc32 读回 50688 | `[rtl]` |
| weight 只信任 last | 唯一覆盖位图、完整计数、early-last fail-closed | `[rtl]` |
| 前端参考未纳入 runner | QFSA score 6/6 + 独立 masked score/Shiftmax 1024 向量 | `[rtl]` |


### 9.3 第三轮：3.0/5，Borderline / Major Revision

第三轮认为协议、反压和整数等价证据已明显加强，但指出一个 P1：
当时非法 descriptor 已被 term builder 消费后，顶层才报错；且旧负例使用零 K，
隐藏了副作用。整改后改为握手前 fail-stop 隔离，并用非零 K/gate 重复 descriptor
验证 0 term、0 update、0 bank write。这一改动在 Icarus 和 Verilator/SVA 下均
通过，Yosys generic cells 从 8327 增加到 8332 `[rtl]`。

注意：这不是可恢复的“接收后 reject”。非法项保持 `valid`、顶层保持
`ready=0`，并在 reset 前禁止继续执行。本文只声明 fail-stop quarantine，不声明
无复位恢复。

### 9.4 第四轮：3.5/5，Borderline Accept / Minor Revision

第四轮确认非法 descriptor 的后端副作用隔离 P1 已闭环，对本“通用 Local5
单顶层验证工作包”给出 3.5/5。这不是整篇 DATE 论文的评分。唯一剩余
P1 是独立 Python Q/K->Acc32 一次性全链 oracle，已按评审意见补齐：

| 全链集合 | Python 账本 | RTL 证据 |
