## 2. LS-COTT 的 P0

### 2.1 fallback 不可恢复

旧提案在 overflow 前已经放弃 token-major member 保存。若第 N 个 token 才发现
term/event 容量不足，直接切回 SCS+G1 无法恢复前 N-1 个
`{class,K,token}`。

可行选择只有：

1. 始终保留完整 shadow log，抵消存储和写能耗收益；
2. 把 class-owned fragment exact spill 到更大 backing SRAM；
3. worst-case 配置全部 lane bank，面积过大；
4. 允许近似丢弃，违反当前 bit-exact 主线。

因此在 spill/fallback 合同闭合前，LS-COTT 不能进入 RTL。

### 2.2 全局容量与 lane bank 冲突

`T256/E1024` 是每 row 全局统计，但 LS-COTT 要求32个 lane bank并行 append：

- 真共享池需要最高32次并行分配写；
- lane分区需要逐 lane class/event 深度；
- 全局 p99 不能推出每 lane p99；
- 22,233-bit 只是不可直接实现的下界。

### 2.3 决策

LS-COTT 降级为：

> **等待逐 lane trace 与 exact spill 合同的 Motion 条件候选。**

第一版不写 RTL。Motion 短期继续使用：

```text
ordered ACQN/SCS -> final-gate sparse NMF/GCM-P
```

作为成熟强基线。

## 3. SOSW 的 P0

只统计 K：

```text
query gather K: 495.936M
source scatter K: 108.864M
```

会得到78.05%减少。但若 source scatter 对五个 Q 重复读取：

```text
query gather: 495.936M K + 108.864M Q = 604.800M
source scatter: 108.864M K + 495.936M Q = 604.800M
```

总向量访问不变，只交换了重复侧。因此：

- 78.05% 只能称 K-side 访问重分配；
- 不能称总访存下降；
- current one-port gather 只是弱 B0；
- 必须加入相同 Q/K 驻留、相同 lane、相同 SRAM 端口的强基线。

## 4. Local5 架构重构

下一轮不再把 source-major score wavefront 作为主张，而采用两阶段关系转置：

```text
Phase A: query-major score + Shiftmax5
  -> direction-banked edge-gate plane

Phase B: source-major projection
  -> inverse-direction address read
  -> group destinations by final gate
  -> product-stationary multicast
```

核心候选改为：

> **Dual-Indexed Stencil Edge Plane（DiSEP）**：同一份五方向 gate plane
> 以 destination 地址写入，以 source + inverse-direction 地址读取，不执行
> 实体 transpose/copy。

方向映射：

| source 在 destination 中的角色 | gate plane 读取 |
|---|---|
| self | `G[self][source]` |
| north | `G[north][source+south]` |
| south | `G[south][source+north]` |
| east | `G[east][source+west]` |
| west | `G[west][source+east]` |

固定 stencil 使 inverse address 可静态生成。Phase A 保持原
`self/N/S/E/W` normalization 顺序；Phase B 只在足够宽整数 Acc 上重排加法。

该重构把架构问题从“Q/K 哪个重复读”改为：

1. normalization 天然 destination-major；
2. product reuse 天然 source-major；
3. DiSEP 用双索引地址在两种所有权之间无拷贝切换。

## 5. 新的公平基线

Local5 必须比较：

| 基线 | score/normalize | projection |
|---|---|---|
| B0 current | 单口 query gather | destination MFEP |
| B1 strong gather | streaming 5-point window | destination MFEP |
| B2 transpose baseline | query score + 实体 gate transpose | source projection |
| A0 DiSEP | query score + direction-bank原位写 | inverse-address source projection |

四者统一：

- score lane 数；
- Q/K SRAM 总端口与复制；
- line-buffer 容量；
- Shiftmax5 数值顺序；
- projection product lane与Acc端口；
- SRAM latency；
- backpressure；
- fullres T450 geometry。

只有 A0 相对 B1/B2 的 EDP 改善才属于 DiSEP。
