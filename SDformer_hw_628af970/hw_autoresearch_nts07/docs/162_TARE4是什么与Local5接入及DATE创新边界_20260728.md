**日期**：2026-07-28  
**范围**：概念说明、接入状态、DATE 可写边界；附带本轮把 TARE 接进 Local5 行上下文的结果。

---

## 1. TARE-4 是什么（用一句话说清）

**TARE-4 = Topology/Temporal Anchor Residual Engine，有界 4-lane 残差 score 核。**

它不做完整 attention，只做一件事：

```text
已知锚点 score(anchor_Q, anchor_K)
求目标 score(target_Q, target_K)
────────────────────────────────
若 lane 更新很少（0 或 1..4）：
    不重算整条 32-lane α-XNOR，
    而用 “锚点 raw + 有符号 delta” 精确重建
若更新 >4：
    回退到同一 32-lane exact replay
最后只做一次 Q7 RNE
```

| 符号 | 含义 |
|---|---|
| **T**emporal / **T**opology | 锚点来自**时间 peer（Motion）**或**拓扑 self（Local5）**，不是在线搜索 |
| **A**nchor | 静态给出的 (Q,K) 参考 |
| **R**esidual | 对变化 lane 做有符号 delta 重建 |
| **E**ngine | 可综合 RTL 流式核 |
| **4** | SPARSE 路径最多吃 **4** 个更新 lane（LIST4） |

分层（Bishop 风格，但锚点静态）：

| kind | 条件 | 行为 |
|---|---|---|
| ZERO | 更新 lane = 0 | 直接复用 anchor |
| SPARSE | 1..4 | delta4 精确重建 |
| DENSE | >4 | 32-lane exact replay |

双模式（**一个物理核**，`dual_mode_tare4_composite_top`）：

| | Motion (H67) | Local5 |
|---|---|---|
| anchor | (Q0,K0) | (Qself,Kself) |
| target | (Q1,K1) | (Qself, Kneighbor) |
| Q 变化 | 允许 | **禁止**（拓扑固定 Q） |
| bias | `16*popcount(K0 xor K1)` | **0** |

灵感来源（必须写 *inspired/adapted*，不能写复现）：Prosperity residual reuse、Bishop density routing、FireFly-T 多 lane 抽取。

## 2. 有没有加入 Local5？

### 2.1 分三层看，避免混谈

| 层级 | 状态 | 位置 |
|---|---|---|
| **A. Score 算术核（Local5 mode）** | **有，Codex 已做** | `rtl_delta/local5_tare4_composite_top.sv` + 共享 `tare4_residual_composite_core.sv` |
| **B. 双模式物理共享** | **有** | `dual_mode_tare4_composite_top.sv`（Motion/Local5 交错） |
| **C. 行上下文 + Shiftmax5 + 窗口/投影主路径** | **本轮才接上 TARE 行引擎；窗口主路径仍可走直算 α-XNOR** | 见下 |

### 2.2 本轮补上的缺口（doc155 的 P0）

原先 Local5 **窗口主路径**（`local5_row_context_engine` / `window_attention`）用的是  
`local5_axnor_score_q7` **直算**，注释写明“不重做 TARE”。

本轮**新增**（不改 `rtl_delta`）：

| 文件 | 作用 |
|---|---|
| `rtl_local5/local5_row_context_tare_engine.sv` | ANCHOR_LOAD 一次锁 Q/Kself → PROBE 邻居 → **每 cand 走 TARE** → Shiftmax5 → edge |
| `tb_local5/tb_local5_row_context_tare.sv` | score 与 TARE 同款 raw16+RNE golden **bit-exact** |

实测：

```text
PASS tb_local5_row_context_tare edges=52 tare_issues=52 zero=12 sparse=0 dense=40
```

说明：在该随机向量上 SPARSE 为 0、DENSE 居多，不代表 profile 分布；只证明 **协议+精确重建** 通路打通。

### 2.3 和“窗口全链路”的关系

```text
当前两套 Local5 score 前端（可并存）:

  [直算路径] row_context_engine  → window / linebuf tops（既有，周期账本）
  [TARE路径] row_context_tare_engine → （可替换接入 window，尚未默认替换）

投影后端 MFEP / multibank 与 TARE 正交：TARE 管 score，MFEP 管 gate 之后 term。
```

**默认窗口顶层尚未 switch 到 TARE 引擎**（避免无声改掉既有 16-dest 周期基线）。要默认启用时，在 `local5_window_attention_top` 用参数选 engine 即可（下一小步）。

## 3. 能不能支撑 DATE 里“一条创新”？

### 3.1 诚实结论

| 问法 | 答案 |
|---|---|
| TARE-4 **单独**能否当 DATE **唯一主创新**并指望录用？ | **很难 / 目前不够** |
| TARE-4 能否成为 DATE **贡献叙事里的核心机制之一（C1）**？ | **可以，且应该** |
| 需要什么才“撑得住”？ | 同约束 **PPA 或至少 open 代理 + 实迹 cycle 净收益 + 与最强基线消融** |

独立审阅（doc155）新颖性约 **2.0–2.5/5**，综合约 **2.5/5**，原因很清楚：

- 证明了：**edge/pair 级 exact residual + 双模式共享核**  
- 尚未证明：**full attention 行、SRAM 延迟、系统 EDP、目标工艺 DC**  
- Local5 侧长期缺：**post-G0 profile、同 cohort equal-lane 周期**

### 3.2 建议的 DATE 写法（可辩护）

**推荐贡献句（机制级，不是 “first residual”）：**

> 利用事件光流网络中**确定的时间/拓扑锚点**，消除通用 product-reuse 架构的在线关系发现成本，在**同一物理核**上用 ZERO / LIST4 residual / DENSE replay 精确执行 score，并把 Motion 与 Local5 的模式差压缩为可验证 descriptor。

**配套第二刀（Local5 特有，抬新颖性）：**

> 拓扑 stencil 下，归一化后的投影采用 **bounded multiset term（MFEP）**，而非 Motion 的 set multicast，避免同一 (gate,lane) 重数丢失。

**双线一张图：**

```text
        Semantic-Anchor Tileflow (目标架构名可换)
   Motion TAB ──TARE── SCS ── NMF(set) ── DCTF
   Local5 STT ──TARE── Shiftmax5 ── MFEP(multiset) ── bank-local
              └── 同一 TARE 物理核 / 模式位 ──┘
```

### 3.3 绝不能写的

- “复现 Prosperity / Bishop / Phi 架构”  
- “TARE 已是完整 attention accelerator / dual-core ASIC”  
- 用 open Nangate cells 冒充 DC 面积功耗  
- 把 preG0 MFEP 92.7% term 压缩写成端到端 speedup  
- 单独把 LIST4 当原创（FireFly 已有多 lane 抽取思想）

### 3.4 晋级门槛（对内）

要把 TARE 从 “机制候选” 抬到 “DATE 可主打”：

1. Motion：T0/T1 原子 packet + 真实 ordered score 行  
2. Local5：TARE 行引擎 **默认接入** 窗口顶层 + post-G0  
3. 同约束相对 **Direct32 / Direct residual / 无共享双核** 的 cycle 与（至少）开放映射  
4. 全链路 score→gate→term→proj 在同一 trace 上 bit-exact  
5. 有 PPA 或明确写 proxy 边界  

在此之前：TARE = **扎实的 co-design 机制 + 双线共享 substrate**，宜作 **C1**，不宜吹成唯一卖点。
