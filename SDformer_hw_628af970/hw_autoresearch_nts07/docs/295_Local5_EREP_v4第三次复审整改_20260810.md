## 2. Stall 账本整改

解析器现在同时执行以下合同：

1. `(candidate,resource,cycle)` 唯一，重复 stalled cycle 立即失败；
2. 每个 stall run 必须在下一拍由完全相同 payload 接受；
3. 一个接受事务最多消费一个 run；
4. run 形状固定为 Direct term `4x1`、TCFM5 term `1x1`、serializer `9x2`；
5. TCFM5 stall 必须 `commit=0`，下一拍接受必须 `commit=1`；
6. 输出保存全部 stalled cycle 与唯一接受事务 payload，不能只保存总数。

实测 stalled cycle 为：

| 资源 | cycle | run 形状 |
|---|---|---|
| Direct execute lane | `40,45,50,58` | `4x1` |
| TCFM5 execute lane | `4` | `1x1` |
| serializer | `162-163,169-170,...,215-216` | `9x2` |

新增负测覆盖重复 Direct stall、18 行 serializer 复制为同一行、破坏 serializer
连续双拍形状和删除 stall，均 fail closed。

## 3. 时间与位宽合同

三套 monitor 各自建立固定时间域：

```text
time = monitor_epoch + 2000 * cycle
```

全部非 preload、非预测 phase-boundary 事件必须满足该式；全局事件时间还必须
单调不减。因此把 relation time 改为 `1`、把 stall time 改为极大值均会失败，
stall 到下一拍接受的时间连续性也得到检查。

解析器还逐字段检查当前 `3x3x1, HEAD_DIM=4, OUT_DIM=2` RTL 实例的合法范围，
包括 source/坐标、5-bit candidate/mask、4-bit K、45-bit packed gates、9-bit gate、
lane/out/bank/address、64-bit delta/vector、32-bit scalar 与 8-bit weight。越宽
`candidate_valid`、lane、gate 和 address 负测均被拒绝。
