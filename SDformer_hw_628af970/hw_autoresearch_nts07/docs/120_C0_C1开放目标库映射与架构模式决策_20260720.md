# C0/C1 开放目标库映射与架构模式决策

## 1. 决策

本轮引入 OpenROAD-flow-scripts 提供的 Nangate45 typical Liberty，仅用于补齐“同一目标库映射”的公平逻辑面积消融。结果为：

| 指标 | C0+BPB | C1+BPB | C1/C0 |
|---|---:|---:|---:|
| Builder RTL 周期 | 14078 | 10035 | 0.713x |
| Builder 吞吐 | 1.000x | 1.403x | 1.403x |
| logic area 代理 | 32550.420 | 56262.192 | 1.729x |
| DFF_X1 | 1426 | 2103 | 1.475x |
| 未映射 `$mem_v2` | 13 | 19 | 未计面积 |
| 面积归一吞吐 | 1.000x | 0.812x | -18.8% |

因此架构模式冻结为：

- **默认面积效率模式：C0+BPB**；
- **可选吞吐模式：C1+BPB**；
- C1 只有在完整 projection 的 energy/head、EDP 或绝对 FPS 目标证明必要时才能晋级为论文默认配置。

## 2. 为什么这是负面但必要的结果

C1 的双 workspace 确实把 Builder 周期降低 28.72%，但复制 canonical workspace 的逻辑代价接近 73%。这说明“序列有序双缓冲”本身不足以构成高效架构贡献；论文必须回答为什么需要 throughput mode，或者进一步提出端口受限的部分复制/转置方案。

该结果也阻止两类错误叙事：

1. 不能只报 1.403x 而隐藏面积；
2. 不能用 Yosys generic cell 或未映射 memory 数量代替真实总面积。

## 3. 证据边界

本轮不是 DC PPA：

- 本机没有 `dc_shell`、PrimeTime、目标 `.db` 和 SRAM macro；
- ABC 未施加 500 MHz 时序约束，不能报告 WNS、TNS 或 Fmax；
- 13/19 个 `$mem_v2` 未映射，logic area 不含主要存储；
- 无 SAIF、时钟树、布线、拥塞和漏电；
- mapped netlist 尚未完成 LEC。

因此文中只能标为 `[开放目标库逻辑映射代理]`。真实 DATE 主表仍必须在同一目标 library/PVT/SDC/SRAM 下重跑 Direct RAW、C0、C1 及 BPB 消融。

## 4. 下一步优化方向

继续简单增加 workspace 没有意义。只保留两条可验证方向：

1. 将 C1 作为明确的 throughput SKU，在固定绝对 FPS 目标下证明 C0 达不到而 C1 达到；
2. 研究 partial-workspace 或受限端口在线转置，目标是在保留大部分重叠收益时，把 logic+memory 面积增量压到 35% 以下。

第二条必须先做周期模型和端口冲突验证，再写 RTL。若无法达到 projection-slice EDP 相对最佳 exact baseline 改善 15% 的门槛，则不进入论文主贡献。
