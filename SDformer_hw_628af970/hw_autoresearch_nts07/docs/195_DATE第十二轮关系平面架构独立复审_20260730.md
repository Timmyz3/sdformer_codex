## 2. FCIP 数学判断

定义：

```text
C[c,d] = destination d属于score class c
K[l,d] = destination d的K lane l激活
```

则：

```text
C[c,:] AND K[l,:]
```

精确给出 `{class=c,lane=l}` 的destination集合。同一row内相同score class
得到同一final gate；K-zero只进入class count，不进入投影。因此因子分解在
数学上成立。

当前只允许写：

> FCIP表示在数学上可bit-exact。

whole-row replay还需证明：

- Q/K、mask、row/context/tag保留到overflow决策完成；
- score重算使用同一位宽、RNE和配置；
- abort前禁止FCIP term进入Acc；
- bitmap/class/normalizer状态原子清除或换epoch；
- fallback不能与下一row、另一context串扰；
- Acc无逐加饱和，final/bias只在整row完成后提交。

## 3. 主要P0

### 3.1 segment统计不是周期

非空 `(class,segment)` 和 `(class,lane,segment)` 数量只有在硬件存在
occupancy索引时才能跳过。否则必须扫描全部slot、segment和lane。新增存储
账本已补：

- `slot x segment x lane` occupancy；
- gate alias；
- epoch-valid；
- 8项fragment FIFO。

但RMW、读端口和仲裁仍需逐拍模型。

### 3.2 final-gate alias

多个score class可能量化到同一final gate。FCIP若逐class生成product，会比
G1重复计算；若合并，则需要alias mask、顺序和跨fragment product residency。
周期模型必须区分：

- score-class fragment；
- final-gate/lane product；
- destination delivery。

### 3.3 存储账本只到逻辑bit

当前修正账本：

| T | 当前SCS+G1 | FCIP含occupancy/alias/FIFO | 比例 |
|---:|---:|---:|---:|
| 162 | 30,163 | 13,638 | 0.452 |
| 450 | 83,640 | 30,425 | 0.364 |

仍未计macro对齐、多口/RMW、Q/K延长驻留、fallback、双context和布线，不能
转换成面积比。

### 3.4 DF-DiSEP底边

内部source row `y` 在destination row `y+1`完成后ready；最后一行例外。
最后destination row结束时，倒数第二和最后source row可能同时ready。逐拍模型
必须支持双row enqueue或串行drain，并设置时间平面barrier。

## 4. 审稿优先级

审稿人要求先做FCIP有限资源CPU逐拍模型，至少包含：

```text
S16 class/K bitmap writer
  + occupancy
  + 64-bit segment intersector
  + final-gate alias/product residency
  + bounded fragment emitter
  + row abort/replay
  + projection backpressure
```

DF-DiSEP等待真实Local5 hardware-order gate，不先写RTL。
