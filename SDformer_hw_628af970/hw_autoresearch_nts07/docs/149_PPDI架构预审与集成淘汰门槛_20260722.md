# PPDI 架构预审与集成淘汰门槛

## 1. 预审结论

本轮由独立架构审阅者执行只读检查。PPDI 当前应归类为**具有跨模块影响的微架构优化**，不是可以独立支撑 DATE 的系统架构贡献，也不只是简单增加第二个写端口。

其相对 DCTF-2C 的唯一新增机制应克制地表述为：

> 在 whole-term 原子验证之后，按奇偶建立两个保序目的流，将一偶一奇合并为一条命令，并通过 per-destination commit mask 与 whole-command retire 映射到三个 bank-local executor。

Whole-term 验证、双上下文、有序多读者 fabric、bank-local product multicast 和偶奇 Acc 分银行均为已有机制，不能在论文贡献中重复计数。

| 维度 | 严格评分 | 结论 |
|---|---:|---|
| PPDI 独立架构新颖性 | 2.0/5 | 未改变计算模型、存储层次或 bank 拓扑 |
| 微架构价值 | 3.5/5 | 配对、分端口提交和整体退休跨越 adapter/fabric/executor |
| 当前实现证据 | 1.5/5 | 预审时只有 executor 叶级证据 |
| 先验工作抗性 | 2.0/5 | 容易被 banking、coalescing、multicast FIFO 和 completion bitmap 覆盖 |
| PPDI 当前增量综合分 | 2.3/5 | 只能作为 DCTF-2C 的增量机制 |

当前 DATE 总体评分仍维持约 2.5/5。即使完成 adapter、fabric 和单 trace projection，若没有多 trace 与目标 PPA，评分上限预计约为 3.0/5。PPDI 本身最多提供约 0.5 分增量，不能解决系统边界、物理证据和外推性缺口。

## 2. 预审发现

### 2.1 P0

1. **零 gate 跨模块合同不一致会造成永久堵塞。** 预审时 executor 的首命令合同要求 `cmd_gate_code != 0`，而 adapter 延续标量路径、把零 gate 当作合法 term。实施选择是保留零 gate 合法性，并在 executor 中加入精确零旁路：命令正常退休并保持 term/head 生命周期，但不请求 weight、不产生加零 Acc 更新。若只修改一侧，fabric 会被永久堵塞。
2. **命令工作量不等于周期收益。** 单个 parity Acc bank 当前 initiation interval 为 2。标量命令可在偶奇交替时连续发射；PPDI 同拍占用两个 parity 后，下一拍两个 bank 都可能忙。`30.270%` 只能称真实 trace 上的命令条数减少。
3. **行为数组尚无物理端口方案。** 一个 event 最多四个 token，最坏全部写入同一 parity；同时还可能发生另一 context 的 even/odd 读。若不能映射到明确的寄存器文件或分银行 SRAM，面积和频率可能抵消收益。

### 2.2 P1

1. Partial commit 不能回滚；flush 必须在同一有效边沿覆盖 adapter、fabric、三个 executor、六个 Acc bank、tracker 和 final-valid 生命周期。
2. Fabric 的无饥饿结论依赖下游 eventual-ready 或最大服务延迟，不能在无假设时声称有界活性。
3. PPDI 只保持各 parity 内到达顺序；`cmd_sequence` 是配对传输命令序号，不是原始 destination 序号。必须证明跨 parity 重排在架构边界不可观察。
4. PPDI executor 增加 pending-generation identity 表。与标量 DCTF 做 PPA 对照时必须统一迟到响应保护，或单独分账该状态开销。

### 2.3 P2

1. 动态 SVA 和定向回归不是 formal。
2. 当前真实逐周期向量仍只有 `sample0/window0`。
3. 固定一拍行为存储和 final 全 ready 不能代替目标 SRAM、STA、SAIF 与真实反压。

## 3. 完整集成前的十条合同

1. **Ingress 合法性：** count、lane、channel、tile、first/last/head-last、mask/popcount、token 范围与重复检查必须在命令可见前完成；非法 term 握手 drain，零命令。gate 等于零是合法数值，必须由下游精确零旁路完整退休。
2. **原子可见性：** 只有完整 term 通过验证后 context 才能 complete；较新 context 不得越过 head context。
3. **配对语义：** `Ncmd=max(Neven,Nodd)`；每个 token 恰好出现一次；有效端口 parity 正确；每个 parity 内保持到达顺序。
4. **Ready/valid：** `valid&&!ready` 时保持所有字段；每个 Acc valid bit 是独立 channel；valid 不依赖 ready，也不得在无 flush 时撤回。
5. **Partial commit：** done bit 只由对应握手置位并单调保持到 retire；已提交端口不重发；所有有效目的完成后整条命令才 retire。
6. **Flush：** flush 优先于 accept、commit 和 retire；所有会保留可观察状态的模块在同一边沿失效。
7. **Sequence/identity：** command sequence 按配对命令递增并允许模回绕；term issue sequence 保持软件顺序；回绕不得与在途事务别名。
8. **存储容量：** 每 context 为 `ceil(T/2)` even、`floor(T/2)` odd 和 `T` bit seen；fabric 第二 token/mask 与 epoch identity 表必须计入面积、存储和能量。
9. **端口冲突：** 明确最坏同 parity 四写、head 双读/tail 写重叠以及 Acc parity bank 的 II/latency，禁止依赖隐式无限端口 RAM。
10. **Fairness/liveness：** 冻结 weight、Acc、final 的最大响应或 eventual-ready 假设；永久 stall 必须可检测并可 flush/abort。

## 4. 分阶段淘汰门槛

### 4.1 Adapter

- 任一 token 丢失、重复、parity 错误、非法 term 部分输出或反压下字段变化：立即淘汰；
- 零 gate 必须形成合法命令并由 executor 精确零旁路，保持 term/head 生命周期且不产生 weight/Acc 事务；
- 每个 term 的命令数必须逐项等于 `max(Neven,Nodd)`；
- 多窗口命令条数几何平均降低低于 20%，或无法给出可综合物理端口方案：停止完整集成。

### 4.2 Fabric

- 三 reader 任一重复、遗漏、乱序、整体提前 retire、full 状态同拍 retire/accept 错误或 ready/valid 组合环：立即淘汰；
- 相对标量 fabric 的同约束 Fmax 下降超过 5%，或无法在冻结服务假设下证明有界活性：停止 projection 集成。

### 4.3 Projection

- 任一 `acc32` 失配、term/weight/bias/final 工作量不守恒、partial flush 污染或 sequence/epoch 别名：立即淘汰；
- 多 trace 几何平均吞吐提升应不低于 8%，95% 置信区间下界应高于 1.0，p99 延迟退化不超过 5%；
- 目标库下总能量至少降低 5%、EDP 至少降低 10%、面积归一吞吐至少提升 8%。未达到时，PPDI 退回附录微架构，不作为论文主贡献。

## 5. 仍未关闭的 DATE 拒稿项

- 多 sample、多 window 的逐周期 term/event/expected-acc32 回放；
- Central、Independent、DCTF-2C、PPDI 的统一 SRAM 宏和迟到响应安全边界；
- 同一 SDC/PVT 下的 DC、STA、SAIF、总面积、总功耗与 EDP；
- full encoder 带宽和 30 FPS 系统预算；
- 与最接近 bank-aware scheduling、coalescing、multicast FIFO、completion scoreboard 工作的差分表。

因此，PPDI 的后续实现是一次受淘汰门槛约束的架构实验，不是预设成功的论文贡献。

## 6. 实施后状态更新

截至 2026-07-22，本预审指出的两个跨模块 P0 已形成 RTL 修复和动态回归证据：

1. adapter 保持零 gate 合法，PPDI executor 已实现精确零旁路；叶回归中的 4 条零 gate command、2 个 term 完成均未产生 weight 或 Acc 更新。
2. adapter 的 token payload 已按 `2 context x 2 parity x 4 stripe bank` 拆分，每个 bank 只有一个同步写入口；`TOKENS=162` 的全容量、only-even 和 only-odd 均通过双模拟器回归。

该关闭结论只针对当前叶模块与跨模块数值合同。token bank 仍是异步读寄存器阵列风格，`TOKENS=162` 有 96 bit 条带 padding，seen bitmap 与 metadata 仍为行为级存储；同步 SRAM、fabric 集成、真实 trace 周期和 PPA 仍未关闭。零 gate 旁路属于正确性与零工作跳过，不作为独立架构创新，也不能在缺少 workload 命中率时声称性能收益。
