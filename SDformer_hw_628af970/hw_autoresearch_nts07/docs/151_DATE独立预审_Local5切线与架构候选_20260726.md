# DATE 独立预审：Local5 切线与架构候选

**日期**：2026-07-26  
**审阅对象**：`docs/150_Local5与H67硬件切线审计及架构创新候选_20260726.md`、
现有 Local5 软件/参考/叶 RTL、H67 GateStack/DCTF 基线。  
**审阅方式**：两名独立子审阅者只读检查；主协作者复核关键代码和整数公式。  
**边界**：本报告评价当前证据和候选潜力，不把尚未实现的 RCSD/MFEP 当作
已有结果。

## 1. Recommendation

### 1.1 当前状态

```text
DATE：2.0 / 5，Weak Reject
ISCA：1.5 / 5，Reject
```

相对已有 H67/DCTF 原型约 `2.5/5` 的评价，Local5 方案当前分数更低，不是
因为方向更差，而是：

- Local5 的三个数值 P0 尚未修复；
- `1.4486` 还不是实际 SV bit-exact 结果；
- RCSD/MFEP 尚只有推导和整数参考；
- Local5 ordered workload profile、RTL、PPA 均不存在；
- full encoder 物理结果仍未闭环。

### 1.2 完成候选后的潜力

若同时完成：

- 数值合同与 valid825；
- RCSD/MFEP 真实 workload 证明；
- 公平 RTL 基线；
- 多 trace；
- 同约束 DC/STA/SAIF；
- full encoder Amdahl；

则：

```text
DATE 潜力：约 3.5 / 5，Borderline Accept
ISCA 潜力：约 2.5 / 5，Weak Reject
```

Local5 更适合 DATE 的算法-硬件协同和专用数字电路/架构范围。若只实现
attention-projection 子系统，很难达到 ISCA 所要求的系统广度。

## 2. 主要优点

1. **软件候选有真实精度动机。** 当前 Python RTL-like 部署的 Local5
   `AEE=1.4486`，优于 H67 的 `1.4627`。
2. **问题来自真实应用和网络语义。** 固定 `T2 x 9 x 9`、十字五邻域和
   all-binary Q/K 不是随机生成的稀疏矩阵。
3. **新候选不再依赖命名包装。** RCSD 有明确整数恒等式、状态和舍入合同；
   MFEP 有明确 loop transposition 和多重集语义。
4. **已有后端工程基础扎实。** DCTF bank executor、Acc、bias/final、
   flush/epoch 和多层验证可以减少后续系统实现风险。
5. **相关工作边界较诚实。** TTB、exact reuse、pattern-residual、stationary、
   butterfly 均被降为借鉴或基线。

## 3. 主要拒稿原因

### 3.1 P0：Local5 当前没有统一的 bit-exact 合同

#### 边界 mask

软件/Python 参考将无效候选放入分母并产生非零 gate；SV 将其放入分母后
强制输出零；真正 masked Shiftmax 应从分母排除。三者不等价。

#### Shiftmax 缩放

Python 使用 `exp_q8 * 128`，SV 实际使用 `exp_q8 * 256`。当前 gate 相差
约两倍。

#### score 舍入

Python 使用 ties-to-even；SV 使用 half-up。`same_zero=8` 是可达半格反例。

**审稿影响**：在这三项关闭前，论文不能写“RTL-exact Local5”，也不能用
当前 `1.4486` 决定硬件切线。

### 3.2 RCSD 尚未证明有硬件净收益

RCSD 的公式正确潜力较高，但 delta engine 需要：

- `0->1`/`1->0` 方向分解；
- Q-conditioned set-bit extraction；
- signed delta；
- remainder/RNE；
- direct fallback。

若邻居 K XOR 不够稀疏，上述开销可能比共享 q-count 的五路 direct score
更高。必须以真实 Local5 trace 和公平 Direct5-CSE 为基线。

### 3.3 MFEP 尚未解决多重集的物理表达

Local5 的同一 destination 可能收到多个相同 `(gate,lane)` 贡献。现有 H67
NMF bitmap 会把重复项 OR 成一次，DCTF adapter 也拒绝 term 内重复 token。

候选有三类：

| 方案 | 正确性 | 复用程度 | 风险 |
|---|---|---|---|
| 按方向分 term | 容易保证 | DCTF 高 | term 多、复用差 |
| 重复目的拆多个 term | 可保证 | DCTF 中 | builder/调度复杂 |
| multiplicity-coded term | 可保证 | DCTF 后端中 | schema/fabric/executor/位宽均要改 |

MFEP 必须相对“按方向分 term”这个强且低风险的基线证明收益。

### 3.4 物理和系统证据仍为空

当前没有 Local5：

- sequential row/window RTL；
- SRAM latency；
- 多窗口 backpressure；
- DC/STA；
- SAIF 功耗；
- edge-term format/storage；
- full encoder cycle/带宽。

数学重排和 Python 参考只能证明“可以做”，不能证明“值得做”。

## 4. 新颖性逐项评分

| 候选 | 当前证据 | 架构新颖性潜力 | 审阅判断 |
|---|---:|---:|---|
| ZUI exact | 口号 | 1.0/5 | exact 是性质，不是架构 |
| Gate-Code Superscalar | 类比 | 1.0/5 | 实质是 multicast/SIMD |
| ISD/type system | descriptor | 1.0/5 | 无类型规则和检查器 |
| WAL/SSA/VC | 类比 | 0.5/5 | 不应进入贡献 |
| Gate-stationary | 数据流设想 | 2.0/5 | 需 loop/traffic/PPA，先例很多 |
| DCTF-2C | 完整 RTL 原型 | 2.0/5 | 工程质量高，机制常规 |
| PPDI | 叶 RTL | 2.0/5 | domain-specific 微结构 |
| RCSD | 公式 + 随机整数验证 | **3.5/5** | 最有希望的 score 架构机制 |
| MFEP | 重排证明 + 多重集方案 | **3.5/5** | 最有希望的数据流/存储机制 |
| STT | 容器设想 | 2.0/5 | TTB 的 Local5 基础设施 |
| direct/delta 单 substrate | 设想 | 3.0/5 | 需证明低稀疏开销和 dense 惩罚 |

RCSD/MFEP 的 `3.5/5` 是“通过 profile、RTL、PPA 后”的潜力，不是当前完成度。

## 5. 与关键工作的差分审阅

### Prosperity

Prosperity 已提出无损 exact/partial product reuse 和在线关系发现。RCSD 不得
宣称首次 exact reuse。可辩护差异是固定 stencil 给出天然 self anchor，
无 TCAM/detector，并通过 remainder carry 保持 Local5 Q7-RNE。

### Phi

Phi 已提出 pattern + residual 两级执行。RCSD 必须加入 Phi-like exact
codebook-residual 成本基线，否则审稿人会认为只是把 residual 从学习 pattern
换成 self K。

### Bishop

TTB 和 density stratifier 已被提出。STT 只能作为 Local5 容器；必须证明
halo、方向 delta 和 multiplicity metadata 在真实流量上有净收益。双核不是
必选项。

### FireFly-T

多 lane sparse decoder、weight dispatch、bank-conflict handling 和 binary
attention engine 都已有。RCSD 可以借其多 set-bit 提取思路，但 DCTF 的
bank-local/OOO 不能据此重复计新颖性。

### 复旦 ISSCC 2023

butterfly zero skipper、local-attention reuse 和 QK sharing 已有芯片结果。
固定 Local5 优先 line buffer + hardwired taps；直接使用蝶形网络既不新，
也大概率不节能。可变 span 邻域才值得重开 butterfly DSE。

### Sanger / FuseMax / StreamTensor / Canon

- stationary dataflow 已有；
- attention fusion 已有；
- iterative stream type 已有；
- data-driven orchestration 已有。

这些工作适合作为设计范式和基线，不能靠改名形成创新。Local5 的差异必须
落到“有向 delta + RNE”和“bounded multiset edge projection”上。

## 6. 对主报告的审阅修改要求

主报告已完成以下修正：

1. 把 `1.4486` 从“RTL-exact”改为“Python RTL-like”；
2. 增加边界、Shiftmax x2、score RNE 三个 P0；
3. 把 RCSD 改为严格 ties-to-even 余数规则；
4. 把随机公式检查扩展为 50 万组 Q7-RNE 零失配；
5. 明确 DCTF 不能原样复用 multiplicity term；
6. 增加 offset-separated 强基线；
7. 增加 head global lane、BN/bias/requant 和 Acc 位宽合同；
8. 把硬件切线改为 G0/G1 后的条件决策。

仍待后续实证：

- Local5 修复后的 valid825；
- Local5 ordered profile；
- RCSD/MFEP trace reduction；
- RTL 与 PPA。

## 7. 晋级为 DATE 可投稿工作的硬门槛

### Gate A：算法与 RTL 语义

- 三种边界合同统一；
- score RNE、Shiftmax 缩放修复；
- Python/SV score、gate、attn、projection 全链零失配；
- 修复后 valid825 仍优于 H67。

### Gate B：workload 证明

- 多 sample、全部 stage/block/head/window；
- delta density mean/p95/p99；
- multiplicity、gate reuse、fanout、fallback；
- source-K/weight/Acc SRAM traffic；
- ordered queue/stall p95/p99。

### Gate C：微架构收益

- RCSD 相对 Direct5-CSE 的 EDP 至少降低 `15%`；
- MFEP 相对 materialized 和 offset-separated 的 EDP 至少降低 `15%`；
- p99 latency 退化不超过 `5%`；
- 无数值近似。

### Gate D：物理与系统

- 同一 SDC/PVT/SRAM macro 的 DC/STA/SAIF；
- H67、Local5 naïve、RCSD、MFEP 公平对照；
- full encoder Amdahl 后端到端提升至少 `8%`；
- 达到目标 FPS/带宽或明确说明子系统 scope。

### Gate E：独立重审

完成每个 Gate 后做一次独立 DATE 审阅。任何 Gate 失败：

- RCSD/MFEP 降为负结果或附录；
- H67 继续作为硬件主线；
- 不用包装词掩盖未达到的 PPA。

## 8. 最终审稿意见

当前工作不能投稿为“Local5 硬件已完成”，但方向选择已经比继续包装 SCS、
term flow 和 DCTF 更有架构潜力。

最合理的论文核心是：

```text
规则 Local5 软件候选
  + RCSD 精确邻域差分 score
  + MFEP 有界多重集边项投影
  + 统一 encoder 后端
```

其中 TTB、DCTF、PPDI、line buffer、descriptor 和 exactness 都是支撑机制。
完成 Gate A/B 以前，不应开始大规模 RTL；完成 Gate C/D 以前，不应声称达到
DATE accept 标准。
