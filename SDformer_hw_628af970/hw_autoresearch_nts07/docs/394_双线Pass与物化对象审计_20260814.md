# 双线Pass与物化对象审计（2026-08-14）

## 1. 审计目的

本审计使用“算子cascade、mapping、format、binding”和“pass/物化对象”口径检查现有贡献是否真的改变架构边界。它不新增机制、不修改`docs/359`，也不把CSE、字段变窄、FIFO或编译器代码量重新包装成DATE贡献。

判定规则：

1. 只减少组合逻辑公共子式，不减少输入访问、迭代域或物化对象：实现支撑；
2. 改变同一对象的编码宽度但不改变生产/消费边界：格式优化；
3. 消除一次强制再访、一个完整中间对象或一个运行时调度对象：架构机制候选；
4. 所有“exact”仅相对冻结hardware-order定点语义成立。

## 2. Motion：MSSB5 + TESC/RQTB

### 2.1 当前cascade

```text
Q/K temporal pair
  -> Motion-XOR score sufficient statistics
  -> Fixed2S or RQTB slot descriptor
  -> 32-entry slot FIFO
  -> weighted score-class histogram + active descriptor directory
  -> class scan: row denominator
  -> active descriptor replay: gate + K-bank read
  -> ordered gated-K stream
```

### 2.2 pass与物化对象

| 阶段 | 访问/物化对象 | Fixed2S | RQTB2S | 架构判定 |
|---|---|---:|---:|---|
| score-front | 每对Q/K读一次并计算两个时间score | 相同 | 相同 | MSSB5只做充分统计CSE，不减少pass |
| slot issue | 16-bit slot descriptor | 每个时间实例一slot | equal-Q7 pair为一slot+2-bit mask/multiplicity | **改变归一化迭代对象** |
| K payload | 两个32-bit K bank | 写一次，活动时读回 | 写一次，活动时读回 | 当前不减少K payload字节 |
| class build | 163-class occupancy/histogram | 按slot更新 | 按quotient descriptor更新 | RQTB减少更新事务，不消除histogram |
| class scan | present class的exp与加权分母 | 一次 | 一次 | 高层pass数相同，工作量随active class变化 |
| active replay | pair id/score/mask目录 | 两个相等score可有两项 | temporal pair可合为一项 | **减少active descriptor物化与replay** |
| output | gated-K token stream | 恢复每个活动K | 恢复每个活动K | exact恢复，不删有效payload |

因此，Motion可以守住的架构主张不是“把3-pass Shiftmax变成1-pass”，而是：

> 在不改变class-scan与K恢复语义的前提下，将归一化迭代域从时间slot商化为带multiplicity的Q7 score等价类，并使active descriptor目录在投影边界前保持可逆。

RQTB改变了slot/active-directory的生产对象和replay次数，但没有消除K store、class denominator pass或最终每个有效K贡献。`112589→94891`小于slot降幅正是该边界的周期表现。

### 2.3 不应升级的主张

- MSSB5：五个充分统计替代冗余计数，是score-front CSE；相对强SSR5实现的增量不足以单列贡献。
- class-wise K folding：会丢token目的地址，已否决。
- equal-gate公共K多播：现有NMF/FCIP已经使用`{gate,lane}+destination bitmap`，不是新对象。
- 推迟除法：除非逐位证明hardware-order舍入/饱和完全一致，否则不采用。

## 3. Local5：QS + 有界转置 + TCFM5

### 3.1 当前cascade

```text
destination Q + five candidate K
  -> Local5 score / Shiftmax5 or exact Q-silent/ident-K path
  -> destination-major relation row
  -> three-row relation ring + last-consumer retirement
  -> source-major descriptor
  -> unique-gate x active-K-lane term stream
  -> resident weight row
  -> one product vector multicast to five colored Acc banks
  -> Acc32 readback
```

### 3.2 pass与物化对象

| 段 | 当前对象 | 避免的对象/工作 | 判定 |
|---|---|---|---|
| QS score段 | Q、五路K、五路gate | Q==0时跳过普通score/Shiftmax服务；ident-K走exact直达 | 代数early-out，不是近似剪枝 |
| relation段 | 三行K/gate ring | 不物化完整T450 destination×relation矩阵 | **存储对象改变** |
| retirement | 固定offset+raster的last-consumer event | 不维护全图per-source runtime consumer table | 拓扑特化控制合同 |
| descriptor/term | 一个source descriptor；term实时生成 | 不存完整term list；相同gate合并destination mask | source-major流式复用 |
| weight | 32行output-tile weight驻留 | 同一`{gate,lane}`产品只算一次并多播 | TCFM5生产对象 |
| Acc | `bank(x,y)=(x+2y) mod 5`的五个Acc bank | 五邻域同拍写冲突 | 拓扑绑定的执行映射 |

对生产cross-r1，垂直offset范围为`[-1,+1]`，reuse distance/live row span下界为：

```text
Dr = max(delta_y) - min(delta_y) + 1 = 3 rows
```

现行FCSR恰好使用三行ring。dilated cross-r2的`Dr=5`，本轮生成式合同验证了相同last-consumer规格可参数化到五行；非对称sidecar只证明规则生成与保序，不是训练网络或新数据流。

### 3.3 融合粒度负结果

在公平active-mask后，QS+Dynamic与QS+FCSR同为`155791`周期。该结果说明将score、transpose和projection“进一步全融合”并不会自动减少执行工作：

- FCSR的价值是把运行时consumer state替换为三行闭式退休合同；
- 在当前生产边界上，它没有额外吞吐收益；
- generated rules与手写FCSR等周期只证明规格化替换不偷吞吐；
- Query-Silent overlap仍是工程流水，不单列贡献。

## 4. 双线DATE贡献边界

| 线 | 真正改变的对象 | 不改变的对象 | 可写主张 |
|---|---|---|---|
| Motion | token-time slot/active descriptor → exact score quotient descriptor | K payload、class denominator pass、有效token输出 | 可逆定点score商数据流 |
| Local5 | full relation/consumer table → bounded relation ring + compile-time last-consumer；冲突Acc → topology-colored banks | 五邻域数学、最终Acc32贡献 | 固定拓扑编译的source-major投影数据流 |

结论：这份审计能加强贡献的可解释性，但不自动把创新评分提高到4/5。创新分继续受限于近邻的exact reuse、stencil line buffer、last-consumer与stationary dataflow；能提高接收概率的下一步仍是强基线、macro-aware PPA、多样本和full-encoder证据。
