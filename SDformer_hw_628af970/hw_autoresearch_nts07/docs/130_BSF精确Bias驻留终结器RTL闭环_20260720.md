# BSF 精确 Bias 驻留终结器 RTL 闭环

## 1. 本轮问题

同步 bias SRAM 合同修正后，baseline 在每个 output supertile 内仍为 162 个 token 分别请求同一组投影 bias。该行为数值正确，但重复读取相同 bias，并让 projection 尾部被 bias 请求/响应串行化。

BSF（Bias-Stationary Finalizer）在 `{tag, output_tile}` 生命周期内只读取一次完整 `OUT_TILE x ACC_W` bias，随后对 162 个 token 的最终累加结果复用驻留值。它不删除 token、不改变乘加顺序，也不改变最终 acc32 数值。

~~~text
tile/head projection done
          |
          v
bias req(token=0, tag, tile) --> synchronous bias SRAM
          |                         |
          +<-- matched response ----+
          |
          v
resident bias[OUT_TILE][ACC_W]
          |
          +--> token 0 ... token 161 final commit
          |
          +--> last token / tile done / reset: invalidate
~~~

## 2. RTL 合同

核心实现位于 `rtl_hitflow/gatestack_multihead_tile_projection_top.sv`：

- BSF 模式请求 token 固定为 0，并等待 tag/token 匹配响应；
- 匹配响应装入完整 `OUT_TILE x ACC_W` 驻留值；
- accumulator 每次只对当前 token 提交一次驻留 bias；
- token 161 完成后清除 resident-valid；新 tile 和 reset 也清除；
- 错 tag/token 的响应不形成 bias commit，置协议错误并重新发起请求；
- 参数 `BIAS_STATIONARY_ENABLE=0` 保留原 baseline 行为。

SVA 对请求反压稳定、响应反压稳定、单 outstanding、BSF token=0 和“bias commit 必须有匹配响应 credit”进行约束。一次匹配 BSF 响应产生恰好 `TOKENS` 个提交 credit，而 baseline 响应只产生一个。

## 3. 功能与协议验证

专用入口：

~~~bash
bash sim_hitflow/run_gatestack_bias_stationary_finalizer_checks.sh
~~~

验证覆盖：

1. 单头定向测试包含错误 tag/token 响应、至少一拍 SRAM 响应延迟和 final backpressure；
2. bias 使用 `+200000/-300000`，验证没有退化回 17-bit product 宽度；
3. HATF96 真实 S0-S3 逐元素比较；
4. Icarus 动态仿真、Verilator 动态 SVA、完整 S3 SVA elaboration/lint、Yosys check、Erie lint；
5. Erie runner 已显式识别 `[ERROR]`、`[MUST] ... ERROR` 和 `ERROR` 三类错误前缀。

最终 suite 为 PASS。四阶段比较元素数分别为 `15552/31104/62208/124416`，总计 `233280`，mismatch 为 0；各 stage checksum 与 baseline 一致。

## 4. 真实四阶段结果

| Stage | baseline周期 | BSF周期 | 减少 | baseline bias请求 | BSF bias请求 |
|---|---:|---:|---:|---:|---:|
| S0 | 2165 | 1830 | 335 | 162 | 1 |
| S1 | 2262 | 1592 | 670 | 324 | 2 |
| S2 | 11650 | 10310 | 1340 | 648 | 4 |
| S3 | 64146 | 61465 | 2681 | 1296 | 8 |
| 合计 | 80223 | 75197 | 5026 | 2430 | 15 |

因此在当前单窗口真实 RTL trace 上：

- 完整 Builder+projection 周期降低 `6.265%`；
- 加速 `1.067x`；
- bias 请求降低 `162x`；
- 外部 bias SRAM payload 从 `7464960 bit` 降至 `46080 bit`；
- 数值保持 exact。

这里必须区分外部与内部数据搬运：BSF 每个 supertile 驻留 `96 x 32 = 3072 bit`，162 个 token 仍需在本地读取或广播这些值。`162x` 是 SRAM transaction/payload 降幅，不是总 bias 能量降幅。

## 5. 面积代理与淘汰判断

在相同 HATF96 顶层、相同 RTL 集合和 Nangate45 开放库下，仅切换 BSF 参数：

| 模式 | logic area | cells | 未映射 `$mem_v2` | 面积归一吞吐 |
|---|---:|---:|---:|---:|
| baseline | 204042.748 | 148243 | 3 | 1.000x |
| BSF | 225972.852 | 160151 | 3 | 0.963x |

当前 BSF 把 `96 x 32 = 3072 bit` 驻留阵列映射为标准单元寄存器，导致开放逻辑面积增加 `10.748%`。其 `1.067x` 加速不足以抵消该面积，面积归一吞吐反而下降 `3.67%`。

据此作出克制结论：

1. BSF 的功能和周期收益成立；
2. 当前 flop-based 实现不能作为面积效率贡献；
3. BSF 暂时降级为条件微结构，只在 SRAM/register-file macro 与 SAIF 证明总能量净收益后晋级；
4. 论文当前可以报告 `162x` bias transaction reduction 和 exact 语义，但不能声称已降低功耗或 EDP；
5. 不应为保住创新点而隐藏面积归一吞吐低于 1 的结果。

## 6. 后续最小优化

不继续无约束堆寄存器。下一步只评估两种物理候选：

- 每个 32-lane bank 本地 `1024-bit` bias register-file/macro，与 DCTF bank-local finalizer 合并；
- 利用 AccTile 初始化/读改写阶段实现 bias-as-initial-state，前提是不增加 162 次全宽复制且保持加法顺序 exact。

晋级门槛：相对 HATF96 baseline，在同 SRAM macro、同 SDC、同频率下总能量至少下降 `10%`，或完整 projection EDP 至少改善 `15%`；否则 BSF 仅作为附属消融，不列 DATE 主贡献。
