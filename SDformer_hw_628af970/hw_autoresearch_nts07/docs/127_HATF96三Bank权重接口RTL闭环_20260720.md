# HATF96 三 Bank 权重接口 RTL 闭环

## 1. 为什么需要这个模块

此前 OUT_TILE=96 的真实 trace 仿真证明了跨三个 output tile 复用 replay/term 的周期价值，但外部权重接口仍表现为一条 96×8=768 bit 宽总线。若不进一步细化，评审人可以合理质疑它只是参数加宽，无法映射到现实 SRAM。

本轮新增 gatestack_hatf96_weight_coalescer，把 HATF96 冻结为一个明确的物理接口合同：

- 逻辑层每个 input channel 发出一次 96-lane supertile 请求；
- 物理层并行访问三个 32-lane 权重 bank；
- 三个 bank 各自支持 ready/valid 和不等返回延迟；
- 合并器分别缓存返回，三份齐全后才向 projection 原子提交；
- tag、input channel、physical output tile 任一错配都会随该逻辑响应报错。

## 2. 数据流

~~~text
Projection logical request
  {tag, input_channel, supertile}
                  |
                  v
       HATF96 weight coalescer
          /       |       \
       Bank0    Bank1    Bank2
       32lane   32lane   32lane
          \       |       /
       stagger-tolerant response buffers
                  |
                  v
      atomic {96 weights, identity, error}
~~~

physical_tile = supertile×3 + bank_id。因此 S0/S1/S2/S3 分别需要 1/2/4/8 个 supertile，且都没有尾部 padding。

## 3. 协议不变量

1. 一个 bank 请求握手后不得重复发射；
2. 未发射的 bank 不接收返回，已接收的 bank 不重复接收；
3. 输出反压期间 96-lane payload 与全部身份字段必须稳定；
4. 三个 bank 返回未齐全前不得暴露部分响应；
5. 任一返回身份错配时，完整 payload 仍原子隔离在响应中，同时 rsp_error 和 sticky protocol_error 置位；
6. 同拍三个 bank 握手的计数必须增加 3，而不是增加 1。

## 5. 架构意义与创新边界

该模块本身不是足够独立发表的架构创新。它的作用是把 HATF96 的核心主张从“把 SIMD 参数改成 96”推进为可审计的数据流和存储端口：

- 复用对象是 H67 typed final-gate term，不是权重零跳过；
- 共享边界在 replay/decoder/term，三个权重与 Acc bank 保持独立；
- 一致性边界是三 bank 原子 join，避免部分 bank 输出污染 projection；
- 物理边界是 3×32 bank，而不是假设单体 768-bit SRAM。

论文中应把它放在 HATF-Supertile 的 memory organization 子节，和 32/64/96/128 周期、面积代理及后续 SRAM PPA 共同构成证据。不能单独把“bank coalescer”包装成贡献。

HATF96 的三 bank 接口也明确暴露了代价：逻辑请求数约为 32-lane 路径的三分之一，但每次并行访问三个 32-lane bank，所以稠密权重 payload 总 bit 近似不变，峰值 SRAM 带宽约为三倍。当前证据支持 term/replay 控制复用和延迟下降，不支持“权重存储能量下降三倍”。

## 6. 下一步

1. 等同步 bias SRAM 接口完成后，把 coalescer 接到完整 Builder→projection 顶层；
2. 为 term 广播和三个 Acc bank 增加同样的独立 ready/原子完成合同；
3. 重跑 S0-S3 真实 trace，确认显式 bank 接口不改变 bit-exact，且周期没有隐藏串行化；
4. 加入 3×32 权重 SRAM 与 3×32×ACC bias/final 存储宏；
5. 进行同一 SDC 下的 HATF32/HATF96 DC、STA、SAIF、SRAM 能耗和布线对比。
