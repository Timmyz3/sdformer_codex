# 顶会机制迁移与 DATE Accept 硬件收口决策

日期：2026-08-27  
主线：Motion/H67  
目标：DATE accept 竞争力；不再以 Best Paper 完整度作为本轮硬门。

## 1. 结论

允许借鉴公开工作的机制，但必须满足三条：明确引用原机制；迁移到 H67 后有新的计算对象、协议或资源约束；用同资源 trace/VCS/新思证据证明变化不是只改名字。论文不把基础零跳过、polyphase decomposition、多 lane decode、AER 或 FIFO 单独宣称新颖。

本轮保留三个论文级组合贡献，其他模块作为实现支撑或完整性消融：

1. **Signed-source execution fabric**：把 binary-spike multi-NZ/temporal packing 迁移到 ATLIF 的 signed analog source，统一 Conv、FC2 和 decoder 的 K8 descriptor、Acc24 context 与边界语义。
2. **Exact parent/product capture path**：把 Prosperity/Phi 的 product/pattern reuse 迁移到 H67 source-owned parent、dual-destination update 与有限 scratch/commit 约束；主张 capture path 与 capture-gap，不主张首次 product sparsity。
3. **Phase-decoupled neuron service**：把 resident neuron/event service 迁移到 analog ATLIF 的 timestep/rank 状态与固定 T10 公平边界；是否成为主贡献由 M518 fixed-vs-candidate VCS/DC 决定。

RQTB attention 作为网络覆盖完整性和局部能量点，不作为系统加速主贡献。M523 decoder frontend 与 M519 registered-release FC2 endpoint 是贡献 1 的支撑模块，不各自拆成额外贡献。

## 3. M523 的合法论文位置

M523 不是新的 transposed-convolution decomposition。它的功能是：

- 对 H67 四个 `ConvTranspose2d(K3,S2,P1,OP1)` 输入事件精确生成边界相关的 4/6/9 个 tap descriptor；
- 以 18-entry atomic FIFO 解耦可变 fanout；
- 仅在 tag/time 相同且前一事件不是 stream-last 时跨事件补齐 K8 bundle；
- 每 lane 保留 event boundary，tag/time/stream-last/fault 强制 partial flush；
- 为后续接入既有 signed-source/Acc24 fabric提供 transport descriptor；当前版本尚未实现 C2/M218 要求的 8-bank weight-key 唯一性。

当前 M523 的 8 条 lane 是 transport lane，不是 C2 的 8 个 weight bank。同一事件的 taps 共享 `cin`，若没有 `(cin,kernel_index)` flatten、bank mapping、冲突延期与对应的 weight-store identity，不能直接满足 M218 的 one-source-per-bank 合同。C2 K8 每次返回 `8x16=128` 个 weights，而强 A1 是 96 product lanes；任何约 `128/96=1.333x` 的差值首先是资源宽度，不是 scheduler 创新。

因此 M523 r1 只准作为 descriptor-only 完整性模块。若后续另立 bank-aware 版本，必须在 M511/M513 精确 trace 上与**相同 128-product/cycle 峰值、相同 bank/port、相同 SRAM 延迟**的强 baseline 比较；只有同资源局部 `>=1.20x` 或 exposed descriptor/weight traffic 降低 `>=30%` 才进入主性能表。否则保留为完整网络支持模块。

## 4. DATE accept 的证据硬门

| 门 | 最低要求 | 失败处置 |
|---|---|---|
| 功能 | 最终引用 RTL 均有 exact-SHA VCS/SVA、数值/tuple/协议/故障覆盖和独立 hammer | 不引用该 RTL |
| 公平性 | K1/K8/K1x8、Fixed/Candidate、decoder A1/M523 使用相同算子、trace、lane、bank/port和频率标签 | 降为 component opportunity |
| 物理 | 核心贡献至少 logic-only DC/STA；最终表明确 0-macro，并给 SRAM 保守模型 | 不写 paper PPA ready |
| 性能 | 一个不重叠 full-network cycle table；局部倍率不相乘；external artifact 单独列 | 没有系统表则只报组件 |
| 能量 | 至少 logic/SRAM/DRAM 三项模型分解；PTPX 只覆盖其实际 activity window | 不推导 mJ/frame |
| 泛化 | 最少 3 条 DSEC sequence 或低/中/高 event-density 分层及最坏点 | 明确单序列 case study |
| 对标 | Fixed、bit-sparse、ours 为同 workload 主表；Prosperity/Phi 为公开 artifact/iso-resource 辅表 | 禁止跨网络直接算“ours X×” |

DATE accept 的现实目标是：共同资源下 full-network `>=1.10x`，最好 `>=1.15x`，并以 throughput/mm²、energy/frame、SRAM/DRAM traffic 补强。无需为追求 `2–4x` 系统数字伪造口径。

## 5. 四到八天收口窗口

1. 第 1–2 天：M518、M519、M522、M523 的 VCS/DC 准入；取得 M511/M513 exact decoder trace。
2. 第 2–4 天：decoder bundling fast-kill、统一 address-timed SRAM/DRAM schedule、完整 Fixed/bit/ours 周期表。
3. 第 4–6 天：matched SAIF/PTPX、SRAM/DRAM 能量、至少两条额外 sequence 或密度分层。
4. 第 6–8 天：最终独立 DATE 模拟评审、数字索引、可复跑 artifact 与论文表格冻结。

阻塞优先级：A800 精确 trace > M523/M519 VCS/DC > system memory model > 多序列 > 附加有损机制。任何 attention-only 或第四种 generic matcher 不占用收口窗口。

## 6. 红线

- 不把公开机制换名后宣称首次提出；差异必须落在对象、协议、资源或可证语义上。
- 不把 M472 官方 Prosperity `2.459487x` 写成 ours RTL/system speedup。
- 不把 M519 K8 对单 K1 的 4.89–6.32x 写成 equal-peak 稀疏收益；equal-bandwidth K1x8 差距只有约 1–4%。
- 不把 Chang & Chang/GANAX 已有的 transposed-conv decomposition 写成 M523 novelty。
