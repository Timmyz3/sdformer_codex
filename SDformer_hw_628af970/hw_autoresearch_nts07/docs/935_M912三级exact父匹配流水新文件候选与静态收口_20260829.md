## 2. F/G/R exact pipeline

### F｜current tuple

每拍接收一个 `bank,row,mask,popcount`。`popcount` 在 prep 接收该 row 时写入已存在的 `directory_q[27:23]`，因此没有新增 `64x5` popcount array，也不会在 G 的每个 candidate 重新展开 popcount tree。

### G｜8 组 × 8 candidate

64 个 candidate 保持冻结合法性：

1. candidate 非空；
2. `candidate_mask` 是 `current_mask` 的 exact subset；
3. 若 mask 相等，只允许 `candidate_id < current_id`；
4. current popcount 小于 2 时不选 parent。

每组 8 个 leaf 用 `8→4→2→1` 平衡树产生 local winner，并寄存八个 28-bit tuple `{valid,popcount,row_id,mask}`。

### R｜global winner + directory commit

八个 local winner 用 `8→4→2→1` 平衡树归并。比较规则与原 ascending scan 的 strict-greater 更新完全一致：优先最大 popcount，同 popcount 保留最低 row id。随后计算 exact residual XOR，写回冻结的 32-bit directory 格式，并更新 parent-live bitmap。

row 0–63 连续进入 F，静态结构的 row initiation interval 为 1。row63 进入 F 后继续排空 G/R；只有 row63 的 R 结果真正写入 directory 的同一 edge 才把 bank 从 `BANK_MATCH` 改为 `BANK_READY`。从最后一个 prep accept 到 execution ownership 的 cleanroom countdown 从 M912 的 65 拍变为 67 拍，即明确增加 2 cycle/task；这还不是测量的 RTL 性能结果。

## 3. 资源边界

新增 state 静态计数：

| 项 | bit |
|---|---:|
| issue-done | 1 |
| F valid+tuple | 29 |

`283 < 512 bit`。popcount cache 复用现有 directory bits；没有新增 1152-bit residual 或 1824-bit psum 寄存器。M912 的两项 1152-bit parent response slots 仍是唯一宽 queue。
