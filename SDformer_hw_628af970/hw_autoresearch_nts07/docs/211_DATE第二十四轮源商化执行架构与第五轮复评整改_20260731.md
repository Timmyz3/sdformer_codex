# DATE 第二十四轮：源商化执行架构与第五轮复评整改

> **2026-07-31勘误：** 本文将 `(source,lane,gate)` 视为product复用键的
> 表述不成立。`source`只决定destination集合，不决定
> `gate×W[lane,:]`数值。正确的值键为
> `(lane,gate,weight_epoch)`。本文相关旧表述仅保留为迭代记录，后续以
> `docs/213`和`docs/214`为准。

## 1. 本轮结论

本轮不再增加彼此松散的“创新点”，而是把 Local5 硬件收敛为一个可证明、
可实现、可做强基线的联合架构：

```text
query/destination-major Local5 score
  -> FCSR-RX 有界生命周期在线关系转置
  -> source-major descriptor
  -> (source, lane, gate) 等价类商化
  -> gate×W 向量只计算一次
  -> destination set 精确多播
  -> 拓扑编译的五色同步1R1W Acc
```

暂定总称为：

> **SQEF：Source-Quotient Exact Fabric，源商化精确执行织构**

SQEF 不是给原有模块换名字。它的核心架构原理是：

> 将 gated-K 投影中的重复工作按 `(source, lane, gate)` 等价关系取商，
> 把“每条 edge 做一次 product”改写为“每个等价类做一次 product，再向
> 该类的 destination set 精确多播”。

Local5 的固定五点图进一步允许把 destination set 的冲突关系在编译期固化
为最小五色 Acc 映射。Motion 没有这个固定图性质，因此只复用 source-
quotient term IR、共享 product 与动态 replay 后端，不能照搬 TCFM-5。

当前状态：

- 同步 1R1W Acc P0 已关闭；
- Local5 C1-C3 端到端整数 exact 回归通过；
- 5-bank 零 replay 与 2–5 bank Pareto 已穷举；
- 仍缺 post-G0 Local5 多样本 trace、强基线完整 RTL 和目标工艺 PPA。

## 3. 同步1R1W Acc整改

### 3.1 旧问题

旧版虽然在行为上分成五个数组，但每个 bank 同时存在：

- update 读；
- readback 读；
- clear 写；
- update writeback 写。

仅在输出端加寄存器不能证明它是同步 SRAM。第五轮 ASIC 复核因此判定旧版
仍可能形成两读两写 memory。

### 3.2 新端口合同

当前 `qfit_tcfm5_acc_bank.sv` 明确只有：

```text
read port:
  update read OR result readback

write port:
  clear OR RMW writeback
```

Yosys 在 `memory_dff` 后审计单个 bank：

| 参数 | 数值 |
|---|---:|
| RD_PORTS | 1 |
| WR_PORTS | 1 |
| RD_CLK_ENABLE | 1 |
| WR_CLK_ENABLE | 1 |
| WIDTH | 128 bit |
| DEPTH | 90 |

五个 bank 因而对应五个独立的 `128×90` 同步1R1W memory。

该结果只关闭 RTL 端口形态 P0，不代表目标工艺 SRAM macro 已完成映射。

### 3.3 RAW与相序

新增定向序列：

```text
A/A/A
A/B/A
```

同拍读写同址由显式 `collision_forward_data` 旁路，不依赖目标宏的
read-first、write-first 或 no-change 语义。

新增 SVA：

- update 与 readback 不得同拍占用唯一读口；
- clear 时不得存在 pending writeback；
- clear/update/read 相序互斥；
- 同址碰撞必须选择前递值；
- read 一拍有效；
- 所有地址不越界。

第六轮 ASIC 复核结论为：

> **GO，旧 Acc P0 关闭；可进入 SRAM wrapper/DC 试映射。**

## 4. Local5 bank/replay Pareto

穷举合同：

```text
bank(x,y) = (x + b*y) mod B
B in {2,3,4,5}
每 bank 每拍最多一条同步1R1W更新
冲突 destination 通过 exact replay 完成
```

部署窗口 `T=2×15×15` 的拓扑上界：

| bank数 | 最佳公式 | 最大replay | 平均replay | bank深度 | 槽利用率 |
|---:|---|---:|---:|---:|---:|
| 2 | `(x+0y)%2` | 3 | 2.8667 | 240 | 93.75% |
| 3 | `(x+y)%3` | 2 | 1.9911 | 150 | 100.00% |
| 4 | `(x+2y)%4` | 2 | 1.8667 | 120 | 93.75% |
| 5 | `(x+2y)%5` | 1 | 1.0000 | 90 | 100.00% |

结论：

1. 五银行是全五角色 term 的零 replay 最小点；
2. 四银行不是简单“少一个 SRAM 就更省”，其不均衡容量为
   `4×120=480` 槽，高于五银行的 `5×90=450` 槽；
3. 四银行可能节省一个宏的外围电路，但必须付出 replay；
4. 是否具有更优 EDP 只能由真实 gate mask 与目标宏结果决定。

当前 W6 exact 定向 term 流：

| 映射 | delivery周期 | 相对TCFM-5 |
|---|---:|---:|
| TCFM-5 | 1494 | 1.000x |
| Affine-4 exact replay | 1579 | 1.057x |
| Linear-5 exact replay | 1598 | 1.070x |
| Single-bank | 2335 | 1.563x |

Affine-4 只多 5.69% 周期，因此应保留为 PPA Pareto 基线，但当前不能替代
TCFM-5 主配置。

## 5. 可写进 DATE 的贡献重构

建议主文只列三项。

### C1：有界关系转置执行

Local5 的 score/gate 天然按 query 或 destination 产生，而 gated-K projection
需要按 K source 聚合复用。FCSR-RX 利用固定五点图的闭式最后消费者
frontier，在三行有界状态内在线完成：

```text
destination-major relation
  -> source-major descriptor
```

这不是通用 CSR 建表，也不是把整个窗口先写回再转置。

### C2：源商化精确投影

对同一 source 的 destination edge 按 `(lane, gate)` 分等价类：

```text
edge product:
  each destination computes gate×W

source quotient:
  each unique (source,lane,gate) computes gate×W once
  then multicasts to all equivalent destinations
```

结果保持整数逐位一致，不做 top-k、弱边删除或预测。

### C3：拓扑编译的最小无冲突多播

对 Local5 固定五点 destination set，编译：

```text
bank(x,y) = (x+2y) mod 5
```

内点五角色形成 K5 写冲突团，因此在“一 bank 一拍一更新、无 replay、
无复制归约”合同下至少需要五个 bank；TCFM-5 达到这个下界。

真正可辩护的贡献是 **C1+C2+C3 的联合数据流**，不是着色公式本身。

## 6. 从已有工作借鉴了什么

| 工作 | 实际借鉴 | 本土化后的硬件机制 | 是否单列创新 |
|---|---|---|---|
| Prosperity | exact reuse/skip | source gate-equivalence product reuse | 否，作为C2来源 |
| Phi | pattern与residual分层 | 固定五点 incidence 与 exact XOR residual | 否，作为C1前端范式 |
| Bishop | TTB与metadata-first | Motion的TTB/STT；Local5的frontier-complete descriptor | 否 |
| FireFly-T | 事件抽取 | K-bitmap next-set-bit iterator | 否 |
| stencil banking | graph coloring | K5下界约束下的五色Acc多播 | 不能单列 |
| sparse stream/dataflow | descriptor化 | 统一 source-quotient term IR | 作为C1-C3接口 |

本工作的本土化差异不是“把论文名字换掉”，而是：

1. reuse key 来自 all-binary gate 等价关系，不需要在线近似 matcher；
2. Local5 关系生命周期由固定图闭式给出，不需要全窗口 CSR；
3. destination 冲突图与 projection Acc banking 联合编译；
4. 全链路保持 hardware-order 整数 exact。

## 7. Motion与Local5的统一边界

统一 term IR：

```text
{
  source_id,
  lane_id,
  gate_code,
  destination_set,
  transaction_last
}
```

### Local5路径

```text
FCSR-RX
  -> 5-bit role mask
  -> static TCFM-5
  -> zero replay
```

### Motion路径

```text
TTB/STT + SCS
  -> dynamic destination stream/bitmap
  -> DCTF bank-local replay
  -> exact retirement
```

两条线可共享：

- weight SRAM；
- `gate×W` product vector；
- packed Acc bank；
- close/drain/readback；
- source-quotient term 协议。

不能共享或照搬：

- Local5 的三行 frontier；
- 五角色 mask；
- K5 五色零冲突保证。

因此双线不是两套完全独立 RTL，也不能假装同一静态拓扑机制对两者都有效。

## 11. Role-Sharded强基线下界

为避免只与弱 hash baseline 比较，本轮补充“按五个 stencil 角色分别存
partial Acc，读回时再归约”的强基线。该基线写入天然无冲突，delivery
也可做到一 product term 一拍。

采用对基线有利的边界压缩，即无效边界 edge 不分配 partial entry：

| 架构 | Acc entry | Acc bits | 读向量 | 最终128-bit向量加法 |
|---|---:|---:|---:|---:|
| TCFM-5 | 450 | 57600 | 450 | 0 |
| Role-sharded | 2130 | 272640 | 2130 | 1680 |

Role-sharded 的存储与读向量仍为 TCFM-5 的 4.733 倍，最终还需 6720 次
32-bit 标量加法。两者的核心差异为：

```text
Role-sharded:
  复制每条有效edge的destination partial state
  -> 无冲突写
  -> final reduction

TCFM-5:
  每个destination只保留一份Acc
  -> 拓扑着色无冲突写
  -> 无final reduction
```

这是结构下界模型，不是 SRAM 面积或能量结果；后续仍需同接口 RTL 与同宏
PPA。
