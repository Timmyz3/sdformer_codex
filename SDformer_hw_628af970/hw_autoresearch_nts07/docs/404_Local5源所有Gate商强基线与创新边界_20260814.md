# Local5 源所有 Gate 商强基线与创新边界

## 1. 本轮结论

- 裁决：`KEEP_INSIDE_UNIFIED_LOCAL5_CONTRIBUTION`。
- 当前创新评分仍为 `3.1/5`，没有因工作量或 term 数降低而上调。
- source-owned gate quotient 不是全局最少乘法，也不是首次 source-stationary。
- 可守的执行对象是：固定五邻域的完整 source-local edge-label 集合，在
  descriptor 退休边界形成 gate 等价类，并把 destination mask 直接映射为
  TCFM5 五色写使能。
- `docs/359_DATE终局冻结_20260813.md` 未修改。

## 2. 精确局部命题

对固定 source `s` 和活动 K lane `l`，定义非零 gate 集合：

```text
G(s,l) = { gate(d,s) | d consumes s, gate(d,s) != 0 }
```

在下列接口合同内：

```text
one issue = {one source, one active lane, one nonzero gate,
             arbitrary five-destination mask}
```

每个 destination 必须收到其原 Q1.7 gate 对应的独立 Acc32 更新，且不允许一个
issue 同时携带多个 gate/product，则最少 issue 数为 `|G(s,l)|`。生产 builder
恰好对每个 unique gate 发一次，因此达到这个 descriptor-local issue 下界。

这不是全局计算下界。以下机制均可进一步改变 product start 或周期：

- 跨 descriptor 的 `(lane,gate)` product cache；
- 一个命令携带多个 gate/product；
- 不同 gate 的代数派生；
- 跨 lane/weight 的偶然等值；
- 多 issue 并行；
- 权重为零或定点饱和导致的 product 等值。

因此论文只能写“达到该接口合同的局部最少 message issue”，不能写“全局最少
乘法/周期/能量”。

## 3. 同一 100-group 强基线 `[prof]`

证据：
`results/local5_source_owned_cache_strong_baseline_20260814/report.json`，SHA256
`b35d8c0b22a5e9be889b269c2868476b2b53b59df5e52cf351152fc8f984e09c`。

输入是 100 个 sample-disjoint、population-stage-weighted 真实 group；cache 在
每个 weight/head group 边界清空。

| 流 | message issue | 无 cache start | W4 start | W6 start |
|---|---:|---:|---:|---:|
| raw relation-lane | 222,649 | 不单列 | 与对应 key 首次相同 | 与对应 key 首次相同 |
| destination-local MFEP | 174,289 | 174,289 | 5,551 | 5,503 |
| source-owned multicast | 74,131 | 74,131 | 5,561 | 5,507 |

关键结论：

1. W4/W6 几乎完全覆盖两种流的跨 descriptor product reuse；source-owned 相对
   MFEP 没有 product-start 优势，W4 下反而多 10 次 miss。
2. source-owned 仍将 message issue 减少 `57.467%`，destination update
   `222,649` 不变。
3. W4 tag compare 从 MFEP 流的 `697,156` 降为 source-owned 流的 `296,524`；
   但这只是逻辑访问账本，不是 SAIF 能量。
4. OUT2 W4 logical state 为 `5,922 bit`，W6 为 `9,058 bit`；这些不是宏面积。

因此 W4 与 quotient 是“语义正交、物理竞争”：cache 减少 multiplier/weight
activity，quotient 减少 issue、路由、tag lookup 和重复 destination-side request。
最佳实现可能是二者组合，不能用其中一方的模型数字替代另一方。

## 4. 近邻边界

- GRIP/Gustavson 已覆盖 source/edge-centric scatter，不能声称 source-stationary。
- I-GCN 已覆盖 shared-neighbor aggregation reuse；本工作不同在于 edge 带独立
  Q1.7 gate，只能在 gate 精确相等时合并，且每个 destination Acc32 保留。
- Prosperity 已覆盖 exact product reuse；本工作不需要跨上下文 TCAM/排序发现，
  因为固定五邻域使 descriptor 退休时的 consumer/gate 集合完整可知。
- 现有 GAT accelerator 多按 edge 计算 attention coefficient 和 weighted message；
  当前未发现其把相同量化 edge gate 直接商化成 destination mask，但在完整检索
  前不写“首次”。

## 5. 唯一允许的下一项创新 go/no-go

不再新开名字。只做生产边界 `2x2` 消融：

| 配置 | descriptor-local equal-gate grouping | lane-local W4 cache |
|---|---:|---:|
| E | 关，逐 consumer one-hot mask | 关 |
| Q | 开，现行 source-owned builder | 关 |
| C | 关 | 开 |
| QC | 开 | 开 |

四者必须共享：

- inverse-stencil/frontier、合法 1RW Acc、TCFM5 写口和反压；
- 同一 100-group、OUT2、checkpoint 权重；
- 同乘法流水、product SRAM 端口、FIFO 深度和 SDC；
- Acc32 逐组 0 mismatch。

必须报告：issue、product start、cache read/write、tag compare、weight read、Acc
RMW、bank stall、busy cycle、逻辑/宏状态以及 matched SAIF。没有 Synopsys 时可先
做 RTL go/no-go，但不写能量/PPA。

晋级门槛：`Q` 或 `QC` 相对强基线 `C` 必须在相同端口/容量下形成稳定 Pareto；
若 `QC` 与 `C` 的周期、activity 和最终 EDP 接近，则 gate quotient 只保留为
bounded-multicast implementation，不提升创新分。
